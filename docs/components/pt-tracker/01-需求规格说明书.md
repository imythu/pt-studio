> pt-tracker **不是插件**，是独立进程、独立 Cargo workspace（`crates/pt-tracker`），许可证 **AGPL-3.0-only**（D16）。它与内核、插件之间只通过 Redis 数据结构通信，不链接任何主 workspace 代码（licensing.md §2）。文档缩写 `PTT`（未在 catalog/plugins.md 中登记，因为它不是插件；需求编号沿用 `FR-PTT-xxx` 格式）。

## 1. 引言

### 1.1 目的

定义 pt-tracker 的功能与非功能需求：PT 专用的 HTTP(S) BitTorrent tracker，负责 passkey 鉴权、准入控制、swarm 维护与 peer 交换、按 peer 会话计算流量增量，并把增量写入 Redis Streams 供 accounting 插件消费。它不包含任何站点业务规则（倍率、促销、H&R、作弊判定）。

### 1.2 范围

**包含**

- HTTP(S) announce（BEP 3、BEP 23 compact、BEP 7 IPv6 peers6）与单 hash scrape（BEP 48 子集）。
- passkey 路径鉴权、用户状态、种子白名单与状态（含 owner_only 与墓碑原因）、客户端规则、请求头与端口过滤。
- swarm（torrust `swarm-coordination-registry`，经适配层）与自有 peer 选择策略。
- peer 会话状态（键 `user_id + info_hash + peer_id`）的本地缓存与 Redis 写穿（CAS）。
- 增量计算、异步记账队列、背压、流量事件出口（`acct:<partition>`、`u:<uid>:live`）。
- 与 tracker-bridge 的同步：快照加载 + 变更流消费 + 缺口检测与全量重载。
- 节点重启 / 分片迁移后的懒加载 swarm 重建。
- 分片感知（与负载均衡一致的哈希环）、错误路由计数。
- 节点状态与被拒客户端统计（`trk:stats:*`）、Prometheus 指标、健康检查、AGPL 源码地址。
- 部署模板（负载均衡按 URL 解码后的 info_hash 一致性哈希、Redis ACL）与压测计划。

**不包含**

| 不包含 | 说明 / 归属 |
|---|---|
| UDP tracker、BEP 41 | D15 |
| 倍率、促销、免费、H&R、分享率限制 | accounting、promotion 等插件 |
| 作弊判定 | anticheat；pt-tracker 只输出信号位 |
| 窗口聚合与落库 | accounting |
| passkey / 白名单的维护 | tracker-bridge（唯一写入方） |
| 访问 PostgreSQL | 不访问任何数据库 |
| 多 hash scrape 汇总、全站统计 | 预留 `trk:stats:*`，P2 |
| 连通性探测（UNIT3D-Announce 的 connectable 检查） | 不做（需要主动出站连接，P2 再评估） |
| DHT、PEX | private 种子禁用 |

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| 累计值 | announce 中上报的 `uploaded` / `downloaded`（本会话总量） |
| 增量（Δ） | 两次 announce 之间累计值的差，以及做种 / 下载时长 |
| peer 会话 | 唯一键 `(user_id, info_hash, peer_id)` |
| swarm | 一个 info_hash 的 peer 集合（内存，torrust Registry） |
| 快照键 / 变更流 | `trk:*` 中的当前状态 / `trk:sync`（见 tracker-bridge 文档） |
| 墓碑 | 已删除 / 已替换的种子、已重置的 passkey 的快照键，带原因与过期时间 |
| 节点 | 一个 pt-tracker 进程 |
| N / K | 流量流分区数（全站固定，默认 64）/ 节点内记账 worker 数 |

- docs/design/03、09、10（方案对比、详细设计 §5、原型 §6、风险 §7）；`.spike/pt-tracker-proto/`（约 880 行原型，7 个单元测试，13 个 curl 场景）。

- 开源实现（只读克隆于 `.spike/refs/`，只借鉴思路，不复制代码）：
  - **UNIT3D-Announce**（Rust，AGPL）：全部用户 / 种子 / 黑名单在内存；主站经 HTTP API 推送变更；announce 先检查请求头（`Accept-Language`、`Referer`、`Accept-Charset`、`want-digest` → 拒绝）、UA 必填且 ≤ 64 字节、浏览器关键字拒绝、peer_id 黑名单、端口黑名单；种子非 Approved 拒绝；“下载槽位”限制；peer 与流量变更放入内存队列，定时批量写数据库；记录未注册 info_hash。
  - **Ocelot**（C++，Gazelle）：内存态 + 定时批量刷库；peer_id 前缀白名单；删除原因回显；按用户 / 种子统计；站点经 HTTP `update` 推送。
  - **XBT Tracker**（C++）：轮询数据库同步，批量写回。
  - **NexusPHP announce.php**（PHP）：每次 announce 读写数据库（带缓存），客户端允许列表（peer_id/UA 正则 + 最低版本），announce 过于频繁时拒绝，在 announce 中直接结算流量与促销。
  - **torrust-tracker**（Rust，AGPL）：本项目复用其 swarm、协议解析与编码、基础类型、事件四个包（D14）。

## 2. 总体描述

### 2.1 定位

| 项 | 内容 |
|---|---|
| 形态 | 独立二进制 `pt-tracker`，无状态可水平扩展（swarm 是可重建的软状态），按 info_hash 分片 |
| 许可证 | AGPL-3.0-only；对网络用户提供源码地址（`/source`） |
| torrust 依赖 | `swarm-coordination-registry`、`http-protocol`、`primitives`、`events`（git rev 锁定，只出现在 `swarm/`、`protocol/` 适配模块） |
| 输入 | BT 客户端 HTTP(S) 请求；Redis `trk:*`（只读，`trk:stats:*` 除外） |
| 输出 | HTTP bencode 响应；Redis `ps:*`、`acct:*`、`u:*:live`、`trk:stats:*` |

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| BT 客户端 | 开始下载 / 做种 / 完成 / 停止时 announce；周期 announce；scrape |
| 站点用户 | 通过客户端界面看到失败原因（封禁、种子已删除、客户端不允许等） |
| 运维 | 部署多个节点，配置负载均衡与 Redis；观察指标；滚动升级 |
| accounting 插件 | 消费 `acct:*` 流 |
| tracker-bridge 插件 | 写 `trk:*`；读节点状态、被拒客户端统计、`ps:*` |

### 2.3 现有开源 PT 程序的做法调研

| 主题 | 做法 | 优点 | 缺点 | 采纳 / 改进 |
|---|---|---|---|---|
| tracker 与主站分离 | UNIT3D 从 PHP announce（约 250 次/秒/核）改为 Rust 外挂 UNIT3D-Announce（约 5 万次/秒/核）；Ocelot、XBT 也独立 | 性能高几个数量级 | UNIT3D-Announce、Ocelot 为单进程内存态，无法水平扩展；重启丢失 swarm | **采纳**独立进程；**改进**：按 info_hash 分片多节点 + peer 会话写穿 Redis + 懒加载重建 |
| 流量统计 | NexusPHP 在 announce 内同步写库；Ocelot/UNIT3D-Announce/XBT 内存累积后定时批量写库 | 批量写大幅减轻数据库压力 | 进程崩溃丢失未刷数据；倍率等业务规则写在 tracker 里 | **改进**：增量即时写入 Redis Streams（持久、可重放、按用户分区），tracker 不含倍率；崩溃最多少记一个间隔且不重复记 |
| 增量依据 | Ocelot / UNIT3D-Announce 按 (用户, 种子, peer_id) 保存上次累计值 | 正确 | 状态只在内存 | **采纳**键设计（D17），并写穿 Redis（CAS） |
| 客户端过滤 | UNIT3D-Announce：黑名单 + 浏览器 UA + 可疑请求头 + 端口黑名单；Ocelot/NexusPHP：允许列表 | 请求头检查能挡住浏览器、下载工具与脚本 | 规则硬编码 | **采纳全部检查**，规则与开关由 tracker-bridge 下发（`trk:clients`、`trk:cfg`） |
| 删除原因 | Ocelot 删除原因回显 | 用户友好 | 重启丢失 | 墓碑键（持久） |
| 待审种子 | UNIT3D-Announce 拒绝非 Approved | 简单 | 发布者无法先做种 | `owner_only`：仅发布者可 announce |
| peer 选择 | torrust 按 SocketAddr 顺序取前 N，不随机、不区分做种者 | — | 大 swarm 中所有人拿到同一批 peer | 自写选择：排除自己、做种者不拿做种者、随机起点 |
| 频繁 announce | NexusPHP 拒绝间隔过短的 announce | 减少滥用 | 客户端行为差异导致误伤 | 只计数并以 `min interval` 引导，不拒绝（可配置限速） |

### 2.4 约束与假设

1. 负载均衡按 **URL 解码后的** `info_hash` 做一致性哈希（design/10 §5.7）；节点对错误路由的请求仍正确处理（CAS 保证）。
2. Redis 三种角色可分开部署：`tracker_sync`（读 `trk:*`，单分片）、`tracker_state`（`ps:*`，可 Cluster）、`acct`（`acct:*`、`u:*:live`）。
3. 规模：30 万用户、100 万种子、约 3000 万 peer；平均 1.7 万次/秒，峰值 5 万次/秒（design/03 §3）。
4. 客户端遵守 `interval`（1800 s）；`max_peer_timeout`（2700 s）必须大于 interval。
5. 原型已验证 torrust 包的可用性与增量算法；真实 Redis、异步队列、同步、重建、负载均衡、性能、真实客户端尚未验证（design/10 §6.4），本文把它们列为验证需求（§3.9）。

## 3. 功能需求

### 3.1 协议

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-PTT-001 | announce 入口 | `GET /announce/{passkey}`，参数 `info_hash`、`peer_id`、`port`、`uploaded`、`downloaded`、`left`、`event`、`compact`、`numwant`、`no_peer_id`、`key`；`ip` 参数默认忽略 | P0 | 原型 13 个场景 + 参数边界测试通过 |
| FR-PTT-002 | 响应格式 | compact（BEP 23，含 `peers6`，BEP 7）与非 compact；`interval`、`min interval` 取 `trk:cfg`；`complete`、`incomplete`、`downloaded` 来自 swarm 统计 | P0 | 与 qBittorrent、Transmission、Deluge、rTorrent 兼容 |
| FR-PTT-003 | 失败响应 | 业务失败一律 HTTP 200 + `d14:failure reason…e`，文案为固定表（LLD §2.2），不含内部错误、源码路径、passkey | P0 | 畸形参数响应中不含 `.rs:` 或路径片段 |
| FR-PTT-004 | 无 passkey | `/announce` 返回“passkey required”；UDP 不提供 | P0 | — |
| FR-PTT-005 | scrape | `GET /scrape/{passkey}?info_hash=…`：鉴权同 announce，只支持单个 hash（多个 hash 返回 failure “multi-hash scrape not supported”）；`trk:cfg.scrape_enabled = 0` 时返回 “scrape disabled” | P1 | — |
| FR-PTT-006 | 参数校验 | `info_hash`、`peer_id` 必须 20 字节；`port` 1～65535（`stopped` 允许 0）；数值非负且 ≤ 2^63−1；`numwant` 截断到 `max_numwant` | P0 | 边界用例 |

### 3.2 准入

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-PTT-007 | passkey 鉴权 | 32 位小写 hex；先查本地缓存；未命中时读 `trk:pk:<pk>` 一次并做负缓存（`negative_cache_ttl`，默认 60 s），回源总速率限制（`miss_lookup_rps`）；变更流中该键的消息会清除负缓存 | P0 | 刚注册用户 1 s 内可用；穷举 passkey 不会放大 Redis 读取 |
| FR-PTT-008 | 用户状态 | `st = 0` 放行；`1`（禁止下载）在 `left > 0` 且 `event ≠ stopped` 时拒绝；`2` 拒绝（“account disabled”）；`3` 拒绝（“passkey revoked”，`rsn = reset` 时提示重新下载种子）；墓碑 `exp` 已过视为未注册 | P0 | 原型场景 3、6 + 新增场景 |
| FR-PTT-009 | 种子状态 | `st = 0` 放行；`1` 仅 `uid == own` 放行，否则 “torrent pending moderation”；`2` “torrent disabled”；`3` “torrent deleted: <rsn>”；`4` “torrent replaced, please re-download”；未知 “torrent not registered” | P0 | 各状态用例 |
| FR-PTT-010 | 客户端规则 | 按 `trk:clients` 有序规则判定（算法与 tracker-bridge LLD §1.5 完全一致）；默认动作取规则集 `default` | P0 | 共享测试向量全部通过 |
| FR-PTT-011 | 请求头与端口 | `trk:cfg` 开关：`require_ua`（缺 UA 拒绝）、UA 长度 ≤ 128 字节、`deny_browser_ua`（UA 含 mozilla、chrome、safari、applewebkit、opera、lynx、bot 等关键字拒绝）、`deny_abnormal_headers`（含 `Accept-Language`、`Referer`、`Accept-Charset`、`Cookie`、`want-digest` 拒绝）、`port_blacklist` | P1 | 用 curl 带浏览器头被拒 |
| FR-PTT-012 | 被拒客户端统计 | 因客户端规则或 UA 被拒时，按 `<peer_id 前 8 字节>|<UA 前 32 字节>` 在本地计数，每 10 s 批量 `ZINCRBY trk:stats:denied:<yyyymmdd>` | P2 | tracker-bridge 能读到排行 |
| FR-PTT-013 | 单 passkey 限速 | 可选（默认关闭）：每个 passkey 每节点令牌桶（`per_passkey_rps`），超出返回 “rate limited” | P2 | — |

### 3.4 记账

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-PTT-018 | 增量算法 | 按 design/10 §5.3 表格：首见 started 计上报值、首见非 started 只建基线（`baseline_reset`）、正常相减、回退记 0 并重建基线、时长按上次角色计并截断到 `max_interval`、completed 首次标记、stopped 计入后删除会话；新增 `left_gt_size` 信号（`left` 大于种子体积） | P0 | 原型 7 个单元测试 + 新增属性测试 |
| FR-PTT-019 | 计账范围 | 只有 `trk:t.acct = 1` 的 hash 计账；`acct = 0`（hybrid 的 v2 截断 hash）只参与 swarm，不建会话、不产生流量事件 | P0 | hybrid 双 hash announce 只记一次 |
| FR-PTT-020 | 异步队列 | announce 响应不等待记账；事实按会话键哈希分到 K 个有界队列（保证同会话顺序）；队列满返回 “tracker busy”（该 announce 不被接受，客户端重试） | P0 | Redis 延迟注入时 announce p99 不受影响，直到队列满 |
| FR-PTT-021 | 会话状态存储 | 本地缓存（LRU）+ Redis `ps:<hash>` 写穿；写回使用 CAS（比较 `ver`）；冲突时用 Redis 中的值重新计算一次 | P0 | 两节点并发处理同一会话（迁移场景）无重复计数 |
| FR-PTT-022 | 流量事件 | 先写会话状态，再在同一 pipeline 中 `XADD acct:<uid % N> MAXLEN ~ <上限>` 与 `HINCRBY u:<uid>:live`；字段见 LLD §3.5；`emit_zero_delta = 0` 时全零且无 event、无 flags 的 announce 不输出 | P0 | 字段与 accounting 文档一致 |
| FR-PTT-023 | 事件去重标识 | 每个事件带 `eid = <node_id>:<boot_epoch>:<seq>`；XADD 超时重试使用同一 `eid`，下游可去重 | P0 | — |
| FR-PTT-024 | 崩溃语义 | 写状态后、XADD 前崩溃：最多少记一个间隔，不重复记 | P0 | 故障注入测试 |

### 3.7 运维

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-PTT-001 | 性能 | 单节点（8 vCPU，release 构建）announce 吞吐 | ≥ 25,000 次/秒，CPU ≤ 80% |
| NFR-PTT-002 | 性能 | 节点内 announce 处理延迟（不含网络） | p50 ≤ 1 ms，p99 ≤ 10 ms（在 25,000 次/秒负载下） |
| NFR-PTT-003 | 扩展 | 集群吞吐 | 3 节点 ≥ 50,000 次/秒（目标峰值），近线性扩展 |
| NFR-PTT-004 | 时效 | 记账延迟（响应到 XADD 完成） | p99 ≤ 2 s；accounting 侧窗口不受影响 |
| NFR-PTT-005 | 正确性 | 不重复计数 | 任何故障场景下 Σ Δ ≤ 客户端真实增量；正常场景误差 0 |
| NFR-PTT-006 | 可靠性 | Redis `acct` 不可用 | 已接受的 announce 流量不丢（队列容量内）；队列满后拒绝新 announce（busy），恢复后自动追上 |
| NFR-PTT-007 | 可靠性 | Redis `tracker_sync` 不可用 | 继续以本地缓存服务；恢复后从游标继续或全量重载 |
| NFR-PTT-008 | 可靠性 | Redis `tracker_state` 不可用 | announce 照常（会话以本地缓存为准）；CAS 写入排队重试；超过重试上限时只建基线（宁少记） |
| NFR-PTT-009 | 容量 | 单节点内存 | 1000 万 peer 的 swarm + 会话缓存 ≤ 6 GB；本地准入缓存（30 万 + 100 万）≤ 200 MB |
| NFR-PTT-010 | 容量 | Redis 写入量 | 每次 announce ≤ 1 次 CAS + 1 次 XADD + ≤ 3 次 HINCRBY（同一 pipeline） |
| NFR-PTT-011 | 安全 | passkey 不出现在日志、指标、错误文案；Redis ACL 最小权限 | 扫描与 ACL 测试 |
| NFR-PTT-012 | 安全 | 抗穷举：回源速率受限；负缓存 | 每节点回源 ≤ `miss_lookup_rps` |
| NFR-PTT-013 | 可观测 | design/10 §5.9 全部指标 + 本文新增指标 | — |
| NFR-PTT-014 | 可维护 | 升级 torrust rev 的改动只出现在适配模块；有回归测试 | 每次升级 PR 的 diff 只在 `swarm/`、`protocol/` 与 `Cargo.*` |
| NFR-PTT-015 | 许可证 | AGPL-3.0 合规：源码公开、`LICENSE`、`NOTICE`、SPDX 头、`/source` | 发布检查表 |

## 5. 可配置项

完整配置见 LLD §4。站点可变参数（interval、max_peers、过滤开关等）由 tracker-bridge 经 `trk:cfg` 下发，pt-tracker 配置文件中只放部署相关项与默认值。pt-tracker 没有站点术语；失败文案为英文固定文本（BT 客户端普遍只显示 ASCII）。
