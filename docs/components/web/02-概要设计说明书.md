## 1. 设计目标与原则

1. **API 优先**：前端只经生成的 SDK 访问后端；替换前端不需要改后端。
2. **外壳 + 插槽**：核心只提供框架页面与插槽，业务 UI 来自插件。
3. **插件运行时契约稳定**：`@pt-studio/slots` 的类型与宿主 API 按 semver 管理，与 `pt:plugin` WIT 版本同步。
4. **安全默认**：严格 CSP，用户内容只经专用组件渲染。

## 2. 总体结构

```
web/
├─ packages/
│  ├─ sdk/          # openapi-typescript 生成的类型 + fetch 封装（鉴权、CSRF、problem+json、幂等键）
│  ├─ ui-kit/       # 基础组件（基于 Radix UI 原语 + CSS 变量主题）
│  ├─ slots/        # @pt-studio/slots：Slot 组件、插件加载器、PluginApi、批量预取
│  ├─ schema-form/  # JSON Schema 表单与筛选面板
│  └─ terms/        # 术语与 i18n
├─ app/             # 外壳与框架页面、路由
├─ themes/          # 主题令牌
└─ tools/           # 构建脚本（SDK 生成、import map 生成、插件打包模板）
```

## 3. 技术选型

| 领域 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite（Rollup） | 快速开发服务器；原生 ESM 输出便于 import map 共享 |
| 路由 | TanStack Router | 类型安全、路由级数据加载、代码分割；支持运行时追加插件路由（通过通配路由 `/p/$plugin/*` 交给插件组件处理） |
| 数据 | TanStack Query | 缓存、重试、失效；与生成的 SDK 组合 |
| 表单 | React Hook Form + 自研 schema 映射（Ajv 2020 校验） | 控制渲染成本；schema 扩展需自研映射层 |
| 状态 | 以 Query 缓存为主；少量全局 UI 状态用 Zustand | 避免全局状态膨胀 |
| 组件原语 | Radix UI（MIT）+ 自有样式 | 无障碍原语成熟、样式可完全控制 |
| 样式 | CSS Modules + CSS 变量令牌 | 主题只替换令牌，不依赖运行时 CSS-in-JS（CSP 友好） |
| i18n | i18next（MIT）+ 术语层 | 生态成熟；术语与界面文案分层 |
| 净化 | DOMPurify（Apache-2.0 / MPL-2.0 双许可，选 Apache-2.0） | 二次净化服务端 HTML |
| 测试 | Vitest + Testing Library + Playwright | |

## 4. 插件前端加载（DD-WEB-1）

| 方案 | 评价 |
|---|---|
| Module Federation | 宿主与插件需使用兼容的打包器与运行时；版本协商复杂 |
| **原生 ESM + import map（采用）** | 宿主在 HTML 中注入 import map，把 `react`、`react-dom`、`@pt-studio/slots`、`@pt-studio/ui-kit`、`@tanstack/react-query` 映射到宿主提供的同一份模块；插件以 ESM 构建并把这些依赖标记为 external；与打包器无关 |

```html
<script type="importmap" nonce="…">
{ "imports": {
    "react": "/static/vendor/react.<hash>.js",
    "react/jsx-runtime": "/static/vendor/react-jsx-runtime.<hash>.js",
    "react-dom": "/static/vendor/react-dom.<hash>.js",
    "@pt-studio/slots": "/static/vendor/slots.<hash>.js",
    "@pt-studio/ui-kit": "/static/vendor/ui-kit.<hash>.js",
    "@tanstack/react-query": "/static/vendor/react-query.<hash>.js" } }
</script>
```

import map 本身是内联脚本：使用 CSP nonce（由内核在返回 `index.html` 时生成）。插件入口 URL 来自 manifest（`/static/plugins/<id>/<hash12>/index.js`），同源加载。

## 5. 插槽与插件 API（DD-WEB-2）

- `<Slot name ctx>` 根据 manifest 找到注册该插槽的插件，懒加载其入口模块，渲染对应组件；每个插件组件包在错误边界与 Suspense 中。
- `PluginApi`：`fetch`（只允许 `/api/` 前缀；自动带会话、CSRF、幂等键工具函数）、`t`、`useTerm`、`navigate`、`toast`、`user`（当前用户摘要）、`batch`（批量预取，见 03 §3）。插件拿不到原始 cookie、localStorage 中的宿主数据或其他插件的状态。
- 插件页面路由：`/p/<id>/*` 交给插件导出的 `routes` 组件渲染；后台 `/admin/p/<id>/*` 同理（未自定义时渲染 schema 设置页）。

## 6. 数据与鉴权

- 会话：HttpOnly cookie（identity）+ CSRF 令牌（`/api/kernel/v1/session` 返回，SDK 自动附加 `X-CSRF-Token`）。
- 错误：SDK 把 problem+json 转为 `ApiError{code, status, message, details}`；UI 层按 code 查本地化文案。
- 幂等：所有创建类 POST 由 SDK 生成 `Idempotency-Key`（同一次用户操作重试复用）。

## 7. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-WEB-1 | 插件加载方式 | 原生 ESM + import map（§4） |
| DD-WEB-2 | 插件隔离 | 同源同文档（受信任代码）+ 错误边界 + 受限 API；不用 iframe（性能与样式集成成本高）。高风险的第三方插件 UI 将来可选 iframe 沙箱模式 |
| DD-WEB-3 | SSR | 不做（§SRS 2.4）；登录页等做成静态轻量页 |
| DD-WEB-4 | 主题 | 设计令牌（CSS 变量），主题包只能替换令牌与少量图标，不能替换组件结构（结构替换走 `overrides`） |
| DD-WEB-5 | 页面覆盖 | `app/overrides.ts` 映射表：站点二开时用自定义组件替换某个框架页面或区块，而不修改核心源码 |

## 8. 对平台契约的新增

- 内核：返回 `index.html` 时生成 CSP nonce 并注入 import map；`/api/kernel/v1/frontend/manifest` 包含插件入口、插槽注册、路由、`settings_ui`、共享依赖版本；
- 插槽目录：新增 `user.name.decorations`（medals 02 §7 提议）、`auth.register.form_extra`、`auth.login.extra`（identity 提议）——前端实现时一并加入 slots 目录；
- 插件前端包版本约束：manifest 中声明依赖的 `@pt-studio/slots` 主版本，不匹配时不加载并在后台提示。
