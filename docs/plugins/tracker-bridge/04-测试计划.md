## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元测试 | 状态映射、规则校验与匹配（含版本提取）、`ps` 值解码、peer_id → 客户端名、`cfg` 校验 | `cargo nextest`、`proptest` |
| 脚本测试 | `trk_put` / `trk_del` / `trk_put_json` 的 ver 比较、TTL、流追加 | 真实 Redis 7.4（testcontainers） |
| 集成测试 | 内核 + tracker-bridge + `t-identity-stub`（可编程状态与 passkey）+ torrent（真实插件）+ Redis（tracker_sync、tracker_state、main 分开三个实例）+ PG 17 | `pt-testkit` |
| 联调测试 | 与 pt-tracker 原型 / 正式实现联调：写入后 announce 结果正确；共享测试向量 | docker compose |
| 契约测试 | `pt:tracker@0.1.0` WIT；Redis 格式与 pt-tracker 文档一致（测试向量 `docs/components/pt-tracker/vectors/*.json`）；OpenAPI | `xtask` |
| 并发与可靠性 | 重建与增量交错、事件重放、Redis 故障注入、NOSCRIPT | `toxiproxy`、自写交错调度器 |
| 性能测试 | 增量吞吐、全量重建耗时、抽样校验耗时 | 自写压测（批量发布事件） |
| 安全测试 | passkey 泄漏扫描、Redis ACL、IP 返回权限、正则 DoS | 专项 |

## 2. 测试环境与数据

- Redis：`tracker_sync`（单实例）、`tracker_state`（单实例；另做 3 主 Cluster 用于 TC-TRB-041）、`main`；均开启 ACL，使用 `deploy/redis/acl.conf` 模板。
- 数据：小规模 1000 用户 / 5000 种子（含 hybrid、纯 v2、已删除、已替换）；大规模 30 万用户 / 100 万种子（生成脚本）。
- 测试向量：`client-rules.json`（≥ 60 组 peer_id + UA + 规则集 → 期望动作与规则 ID）、`ps-values.json`（≥ 20 组字节 ↔ 字段）、`status-mapping.json`。

## 5. 通过准则

1. P0 需求全部通过；安全用例（048、049、064、065）任一失败为阻断。
2. 共享测试向量（`client-rules.json`、`ps-values.json`、`status-mapping.json`）在本插件与 pt-tracker 两侧全部通过。
3. 交错与重放用例（004、005、055～060、063）全部通过。
4. 性能用例达到 NFR 指标。
5. 行覆盖率：`writer`、`users`、`torrents`、`clients` ≥ 90%；整体 ≥ 80%。
