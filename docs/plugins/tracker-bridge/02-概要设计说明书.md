## 1. 设计目标与原则

1. **单一写入方**：`trk:*` 只由本插件写；pt-tracker 只读（节点状态键除外，见 §7）。
2. **快照为真、流为通知**：快照键保存完整当前状态；`trk:sync` 只说“哪个键变了”，pt-tracker 收到后重读快照键。丢一条流消息最多造成延迟，不会造成错误状态；流被修剪时 pt-tracker 全量重载。
3. **写入可重放**：每次写入都由“当前源状态”重新计算，不依赖事件载荷中的旧值；单调 `ver` + Lua 比较写入保证乱序与重放无害。
4. **先取 ver 再读源**：保证并发的重建任务不会用旧状态覆盖新状态（LLD §1.2 证明）。
5. **最小敏感暴露**：passkey 只在内存中短暂存在，数据库只存 HMAC 指纹；Redis 明文副本受 ACL 保护（security.md §4）。
6. **与 pt-tracker 零代码共享**：数据格式以文档为准（licensing.md §2），两边各自实现，并共享一组**测试向量文件**（数据，不是代码）。

## 2. 总体结构

### 2.1 位置

```
 identity ──user.*──┐                                   ┌──► trk:pk:<pk> / trk:u:<uid>
 torrent ──torrent.*┼──► 事件日志 ──► tracker-bridge ───┼──► trk:t:<hash>
 后台（规则/参数）───┘     (inbox)        │  │  │         ├──► trk:clients / trk:cfg
                                         │  │  │         └──► XADD trk:sync      （Redis tracker_sync）
          ctx.users.get_sensitive(passkey)┘  │  │                      │ XREAD
          视图 v_user_public / v_torrent_tracker  │                      ▼
                                             │  └── 读 trk:stats:node:*、trk:stats:denied:* ◄── pt-tracker 节点 × N
                                             └───── 读 ps:<hash>（Redis tracker_state）◄────────┘
```

### 2.2 模块

| 模块 | 职责 |
|---|---|
| `writer` | Redis 连接（`ctx.redis.global("tracker_sync")`）、Lua 脚本加载（`SCRIPT LOAD` + `EVALSHA`，NOSCRIPT 时重载）、批量 pipeline、版本号分配 |

| `cfg` | 设置 → `trk:cfg` |
| `rebuild` | 全量 / 单对象重建任务 |
| `checker` | 抽样与全量一致性校验、孤儿清理、告警 |
| `nodes` | 读取节点状态、延迟计算 |
| `peers` | 读取并解析 `ps:*`、peer_id → 客户端名 |
| `service` | `TrackerService` 实现 |
| `http` | 后台与用户 API |
| `subscriber` | 事件处理入口 |

## 5. 关键流程

### 5.1 用户封禁

```
identity: set_status(banned) → COMMIT → user.status_changed
tracker-bridge.on_user_status_changed（inbox 去重）:
  ver = nextval(sync_ver)                         ← 先取 ver
  u = SELECT status FROM identity.v_user_public WHERE id = $uid
  pk = ctx.users.get_sensitive(uid, "passkey")
  EVALSHA trk_put trk:pk:<pk> trk:sync  ver "pk" <pk> 0  uid <uid> st 2 rsn banned
  EVALSHA trk_put trk:u:<uid> -        ver ...（不追加流）
  UPSERT user_sync(uid, fp(pk), st=2, ver)
pt-tracker 节点: XREAD trk:sync → {kind: pk, key: <pk>, op: upsert, ver} → HGETALL trk:pk:<pk> → 本地缓存 st=2
  → 下一次 announce 返回 "account disabled"
```

### 5.2 种子删除

```
torrent.deleted{torrent_id, reason_code: dupe, info_hash_v1} →
  ver = nextval；row = SELECT … FROM torrent.v_torrent_tracker WHERE id = $tid
  row.status == deleted → trk_put trk:t:<v1> ver "t" <v1> ttl=7d  tid st=3 acct=1 size own rsn=dupe exp=<now+7d>
  hybrid 时对 v2 截断 hash 同样写墓碑
  pt-tracker: announce → "torrent deleted: dupe"；7 天后键过期 → "torrent not registered"
```

### 5.3 全量重建

```
POST /v1/admin/resyncs {scope: full} → jobs.schedule_once("rebuild", now, {scope: full}, dedupe "full") → 202
rebuild job（持有 p:tracker-bridge:rebuild_lock）:
  start_ver = nextval(sync_ver)
  for 用户批（1000，按 id 键集）: ver = nextval；rows = v_user_public；pks = ctx.users.get_sensitive_many(ids)
       pipeline trk_put × n；UPSERT user_sync；commit
  for 种子批（1000）: ver = nextval；rows = v_torrent_tracker（含已删除且墓碑未过期者）；pipeline；UPSERT torrent_sync；commit
  写 trk:clients、trk:cfg
  孤儿清理：SCAN trk:pk:* / trk:t:*，HGET ver < start_ver 的键 → 对照数据库确认后 trk_del（追加 op=delete）
  XADD trk:sync kind=all op=reload ver=<当前>
  publish tracker.resynced{scope: full, count}
```

### 5.4 一致性校验

```
check_sample: 随机抽样 N 个用户（user_sync 表随机起点 + 键集）与 N 个种子
  用户: v_user_public.status → 期望 st；trk:u:<uid>.pk → HMAC 与 user_sync.fp 比较；trk:pk:<pk>{uid, st}
        抽样的 1% 额外调用 get_sensitive_many 比较 identity 当前 passkey
  种子: v_torrent_tracker → 期望 {tid, st, acct, own}；HMGET trk:t:<hash>
  不一致 → 以新 ver 修复；check_runs 记录；≥ 阈值 → tracker.inconsistency_detected + 通知
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| DD-TRB-1 | 同步通道 | HTTP 推送（Ocelot、UNIT3D-Announce）/ 轮询数据库（XBT）/ Redis 快照 + 流 | Redis 快照 + 流（design/10 §5.5） | 推送会丢、轮询有延迟；快照可重放、多节点各自消费；pt-tracker 不接触 PG，许可证隔离清晰 |
| DD-TRB-2 | 快照与流的原子性 | 先写快照再 XADD 两步 / Lua 一步 | Lua 一步（`trk_put`） | 两步之间崩溃会导致节点不知道变更（只能等校验修复）；脚本同时实现 ver 比较 |
| DD-TRB-3 | ver 来源 | 事件时间 / Redis INCR / PG 序列 | PG 序列 `sync_ver` | 与读源状态在同一数据库，可在同一调用中先取后读；Redis 被清空后版本仍单调 |
| DD-TRB-4 | 旧 passkey 如何找到 | 事件携带（违反敏感规则）/ PG 存密文 / Redis 反向索引 | Redis `trk:u:<uid>`（新增键）+ PG 只存 HMAC 指纹 | 不在第二个数据库保存 passkey；`trk:*` 本就有明文副本与 ACL；指纹用于校验 Redis 是否被篡改 |
| DD-TRB-5 | 删除语义 | DEL 键 / 墓碑 | 墓碑（带 TTL 与 `exp`）；只有孤儿清理用 DEL | 墓碑让客户端看到原因（Ocelot 经验），也防止“旧的 upsert 在 DEL 后复活”（墓碑保留 ver） |
| DD-TRB-6 | 待审种子 announce | 拒绝 / 只允许发布者 / 放开 | 默认只允许发布者（`st = 1` + `own`），可配置 | 与 torrent DD-TOR-7 一致 |
| DD-TRB-7 | 客户端规则模型 | 只允许列表（Ocelot）/ 只拒绝列表（UNIT3D）/ 有序 allow+deny + 默认动作 | 有序规则 + 默认 deny + 最低版本（NexusPHP 思路） | 同一模型可以表达“允许 qB 4.3 以上但拒绝 4.6.0”这类例外 |
| DD-TRB-8 | 匹配算法放在哪 | 只在 pt-tracker / 两边都实现 | 两边各自实现同一规范 + 共享测试向量（JSON 数据文件） | 后台“规则测试”需要同样的结果；不能共享代码（D16） |
| DD-TRB-9 | 全量重建期间的增量 | 暂停订阅 / 并行 | 并行 | 先取 ver 再读源保证正确（LLD §1.2）；不中断线上生效 |
| DD-TRB-10 | 重建如何批量拿 passkey | 逐个 `get_sensitive`（30 万次调用）/ 敏感视图 / 批量方法 | 新增 `ctx.users.get_sensitive_many`（≤ 1000） | passkey 在 identity 中加密存储，视图无法解密；批量方法 300 次调用即可 |
| DD-TRB-11 | 种子批量读取 | `ctx.torrents` 分页 / 视图 | 视图 `v_torrent_tracker`（敏感，只授予本插件） | 100 万行键集扫描；需要匿名种子的真实发布者以实现 owner_only |
| DD-TRB-12 | `tracker_sync` 是否允许 Cluster | 允许（键加哈希标签）/ 不允许 | 要求单分片 | 数据量小（≈150 MB）；脚本跨快照键与流；pt-tracker 全量 SCAN 简单 |

## 7. 对平台契约的新增

| 类别 | 内容 | 说明 |
|---|---|---|
| Redis 键 | `trk:u:<user_id>` HASH `{pk, ver}`，tracker_sync，写入方 tracker-bridge，读取方 tracker-bridge（pt-tracker 不读），无 TTL（用户删除时删除） | redis-keys.md §3 |
| Redis 键 | `trk:stats:node:<node_id>` HASH（pt-tracker 写，TTL 30 s）、`trk:stats:denied:<yyyymmdd>` ZSET（pt-tracker 写，TTL 8 天） | 具体化 `trk:stats:*`；**ACL 调整**：pt-tracker 账号增加对 `trk:stats:*` 的写权限（其余 `trk:*` 仍只读） |
| Redis 键字段细化 | `trk:pk`：`st` 增加 `3 = revoked`（墓碑），增加 `rsn`、`exp`；`trk:t`：`st` 改为 `0 open / 1 owner_only / 2 disabled / 3 deleted / 4 replaced`，增加 `own`、`rsn`、`exp`；`trk:sync` 的 `kind` 增加 `all`、`op` 增加 `reload` | 修订 design/10 §5.5；pt-tracker 文档同步 |
| Redis 实例约束 | `tracker_sync` 必须单分片 | redis-keys.md §2 |
| 服务方法 | `ctx.tracker`：`status()`、`peers_of_user(user_id)`；`ctx.users.get_sensitive_many(ids, field) -> Vec<(id, Option<String>)>`（≤ 1000，同样检查 sensitive 授权并写一条汇总审计） | services.md |
| 视图授权 | 本插件消费 `torrent.v_torrent_tracker`（敏感）、`torrent.v_torrent_hash_history` | 见 torrent HLD §7 |
| 事件 | `tracker.inconsistency_detected` v1：`kind(users/torrents/clients/cfg/node_lag/node_lost/rebuild_failed), count, repaired, check_id?, node_id?` | events.md §4.3 |
| 事件字段 | `tracker.resynced` 增加 `run_id`、`mismatches`、`duration_ms` | 只增 |
| 权限点 | `tracker-bridge.peers.read_ip`（查看 peer IP，默认 admin） | permissions.md |
| MCP（建议，P2） | `admin_get_tracker_status`（只读，`tracker-bridge.peers.read`） | mcp-tools.md |
| 依赖方事件要求 | identity 必须在首次生成 passkey 时也发布 `user.passkey_reset`（或在 `user.registered` 前生成）；torrent 的 `torrent.deleted` 携带 hash | 与 identity、torrent 文档作者对齐 |
| 路由声明 | 建议清单 `[[http.routes]]` 增加 `reauth_secs`（要求 N 秒内重新验证过密码或 2FA，网关调用 identity 检查），用于重建、规则修改等高危后台操作 | plugin-api.md §4、kernel/03 §8.2 |
| 测试向量 | `docs/components/pt-tracker/vectors/`（客户端规则匹配、`ps` 值编解码）作为两边共同的数据契约 | 数据文件，不是代码 |
