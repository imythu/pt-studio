## 1. 模块详细设计

### 1.1 `writer`

**连接**：`ctx.redis.global("tracker_sync")`（写 `trk:*`）、`ctx.redis.global("tracker_state")`（只读 `ps:*`）。插件启动（`lifecycle.init`）时 `SCRIPT LOAD` 三个脚本并缓存 SHA；执行时 `EVALSHA`，收到 `NOSCRIPT`（Redis 重启）自动重新加载后重试一次。

> 平台对插件私有 Redis 禁止 `EVAL`；`global()` 返回的原生连接不受该白名单限制，Redis ACL 层限定本账号只能写 `trk:*`、读 `ps:*`（LLD §6）。

**脚本 `trk_put`**（写哈希快照键，可选追加变更流）：

```lua
-- KEYS[1] 快照键；KEYS[2] trk:sync
-- ARGV[1] ver；ARGV[2] kind（"" 表示不追加流）；ARGV[3] 流中的 key 字段；ARGV[4] ttl 秒（0 = 永久）
-- ARGV[5] maxlen；ARGV[6..] field, value, ...
local cur = redis.call('HGET', KEYS[1], 'ver')
if cur and tonumber(cur) >= tonumber(ARGV[1]) then return 0 end
redis.call('DEL', KEYS[1])
local f = {}
for i = 6, #ARGV do f[#f + 1] = ARGV[i] end
f[#f + 1] = 'ver'; f[#f + 1] = ARGV[1]
redis.call('HSET', KEYS[1], unpack(f))
if tonumber(ARGV[4]) > 0 then redis.call('EXPIRE', KEYS[1], ARGV[4]) end
if ARGV[2] ~= '' then
  redis.call('XADD', KEYS[2], 'MAXLEN', '~', ARGV[5], '*',
             'kind', ARGV[2], 'key', ARGV[3], 'op', 'upsert', 'ver', ARGV[1])
end
return 1
```

**脚本 `trk_del`**（只用于孤儿清理与用户反向索引删除）：

```lua
-- KEYS[1] 快照键；KEYS[2] trk:sync；ARGV[1] ver；ARGV[2] kind（"" 不追加）；ARGV[3] key 字段；ARGV[4] maxlen
local cur = redis.call('HGET', KEYS[1], 'ver')
if cur and tonumber(cur) >= tonumber(ARGV[1]) then return 0 end
redis.call('DEL', KEYS[1])
if ARGV[2] ~= '' then
  redis.call('XADD', KEYS[2], 'MAXLEN', '~', ARGV[4], '*', 'kind', ARGV[2], 'key', ARGV[3], 'op', 'delete', 'ver', ARGV[1])
end
return 1
```

**脚本 `trk_put_json`**（`trk:clients`）：

```lua
-- KEYS[1] trk:clients；KEYS[2] trk:sync；ARGV[1] ver；ARGV[2] JSON；ARGV[3] maxlen
local cur = redis.call('GET', KEYS[1])
if cur then
  local ok, obj = pcall(cjson.decode, cur)
  if ok and obj.ver and tonumber(obj.ver) >= tonumber(ARGV[1]) then return 0 end
end
redis.call('SET', KEYS[1], ARGV[2])
redis.call('XADD', KEYS[2], 'MAXLEN', '~', ARGV[3], '*', 'kind', 'clients', 'key', 'clients', 'op', 'upsert', 'ver', ARGV[1])
return 1
```

`trk:cfg` 用 `trk_put`（kind = `cfg`，key = `cfg`）。

**批量**：`pipeline(cmds, atomic = false)`，每批 ≤ 500 条 `EVALSHA`；返回 0 的条目计入 `stale_writes_total`（说明已有更新的写入，属正常）。

**失败处理**：Redis 错误 → 返回 `tracker-bridge.redis_unavailable`（retryable）；事件订阅因此失败并由内核退避重试；PG 中的 `user_sync`/`torrent_sync` 只在 Redis 成功后更新（同一工作单元，Redis 失败则整体回滚）。

### 1.2 版本号与“先取 ver 再读源”

```
fn next_ver(ctx) -> i64:  SELECT nextval('sync_ver')      -- 非事务性，回滚也不会复用
```

**正确性论证**（重建任务 R 与增量处理 W 并发作用于同一对象 X）：

1. 设 X 的状态在时刻 c 被修改并提交（事件 E 随之提交）。
2. W 在收到 E 之后才开始，故 W 取 ver 的时刻 `tW > c`。
3. 若 R 读到的是**旧**状态，则 R 读源的时刻 `rR < c`；而 R 取 ver 的时刻 `tR < rR`（先取后读），所以 `tR < c < tW`，即 `verR < verW`。
4. 脚本只接受更大的 ver，因此无论两者写 Redis 的先后，最终快照为 W 写入的新状态。
5. 若 R 读到的是新状态，两者内容相同，谁赢都正确。∎

同理适用于两个增量处理（例如事件重放）之间。

### 1.3 `users`

**状态映射**：

| identity `UserStatus` | `trk:pk.st` | `rsn` |
|---|---|---|
| `active` | 0 | — |
| `leech_disabled` | 1 | — |
| `pending` | 2 | `pending` |
| `banned` | 2 | `banned` |
| `deleted` / 视图中不存在 | 3（墓碑） | `deleted` |
| 旧 passkey（已重置） | 3（墓碑） | `reset` |

```
fn sync_user(ctx, uid) -> Result<SyncOutcome>:
    ver = next_ver()
    row = SELECT status FROM identity.v_user_public WHERE id = $uid
    if row is None: return revoke_user(ctx, uid, ver)
    pk = ctx.users.get_sensitive(uid, "passkey")?          // Option<String>
    prev = HGET trk:u:<uid> pk                              // 旧 passkey（可能为空）
    if pk is None:
        if prev: 墓碑 prev（rsn = reset）；trk_del trk:u:<uid>
        UPSERT user_sync(uid, fp = NULL, st, ver, synced_at)；return NoPasskey
    require pk ~ ^[0-9a-f]{32}$ ?: tracker-bridge.passkey_malformed（告警，不写）
    (st, rsn) = map(row.status)
    cmds = [ EVALSHA trk_put [trk:pk:<pk>, trk:sync] ver "pk" pk 0 maxlen  uid <uid> st <st> [rsn <rsn>],
             EVALSHA trk_put [trk:u:<uid>, trk:sync] ver "" "" 0 maxlen  pk <pk> ]
    if prev && prev != pk:
        exp = now + ttl
        cmds.push(EVALSHA trk_put [trk:pk:<prev>, trk:sync] ver "pk" prev ttl maxlen uid <uid> st 3 rsn reset exp <exp>)
    pipeline(cmds)?
    UPSERT user_sync(uid, fp = HMAC(fingerprint_key, pk), st, rsn, ver, synced_at = now())
    zeroize(pk, prev)

fn revoke_user(ctx, uid, ver):
    prev = HGET trk:u:<uid> pk
    if prev: trk_put trk:pk:<prev> st 3 rsn deleted exp ttl；trk_del trk:u:<uid>（不追加流）
    UPDATE user_sync SET st = 3, rsn = 'deleted', ver, fp = NULL
```

> 事件中的 `from/to` 不被使用：处理永远基于“当前”状态，因此乱序到达的旧事件只是一次无害的重写。

### 1.4 `torrents`

**状态映射**（`settings.pending_announce` / `rejected_announce` 可改 candidate/pending 与 rejected 两行）：

| torrent 状态 | `st` | `rsn` | TTL |
|---|---|---|---|
| `approved` | 0 open | — | 无 |
| `candidate`、`pending` | 1 owner_only（`open` → 0；`deny` → 2 `rsn = pending`） | `pending`（`st = 1` 时也写 `rsn`，pt-tracker 用它选择失败文案） | 无 |
| `rejected` | 1 owner_only（同上可改；`deny` → 2 `rsn = rejected`） | `rejected` | 无 |

> hybrid 种子：v2 截断 hash（`v2t`）的条目只在 v1 缺失时计账（`acct = 1`）；客户端用 v1 汇报时，`v2t` 下没有会话，`peers` 对它返回空列表属正常（评审 F-01）。
| `disabled` | 2 | `disabled` | 无 |
| `deleted` | 3 | 删除原因码（`dupe` 等） | `deleted_at + ttl` |
| 被替换的旧 hash | 4 | `replaced` | `replaced_at + ttl` |

```
fn sync_torrent(ctx, tid):
    ver = next_ver()
    row = SELECT id, info_hash_v1, info_hash_v2, size, status, uploader_id, deleted_at, delete_reason
          FROM torrent.v_torrent_tracker WHERE id = $tid
    if row is None: log warn；return
    hist = SELECT info_hash_v1, info_hash_v2, replaced_at FROM torrent.v_torrent_hash_history
           WHERE torrent_id = $tid AND replaced_at > now() - ttl
    entries = []
    v2t = row.info_hash_v2.map(|h| h[0..20])
    (st, rsn, exp) = map(row)
    if row.info_hash_v1: entries.push((v1, acct = 1))
    if v2t:              entries.push((v2t, acct = row.info_hash_v1.is_none() as u8))
    cmds = []
    for (h, acct) in entries:
        if exp.is_some() && exp <= now: cmds.push(trk_del trk:t:<hex h> ver "t" hex(h))   // 墓碑已过期
        else: cmds.push(trk_put trk:t:<hex h> ver "t" hex(h) ttl(exp) maxlen
                         tid <tid> st <st> acct <acct> size <size> own <uploader_id or 0> [rsn <rsn>] [exp <exp>])
    for old in hist: 同样为 old.v1 / old.v2t 写 st = 4、rsn = replaced、exp = replaced_at + ttl
                     （若该 hash 恰好等于当前 hash 则跳过）
    pipeline(cmds)?
    UPSERT torrent_sync(...) for each entry；DELETE torrent_sync WHERE torrent_id = $tid AND info_hash NOT IN (...)
```

`ttl(exp) = max(1, exp − now)` 秒；`exp` 来自 `deleted_at`/`replaced_at` 而不是“当前时间”，所以重复同步不会延长墓碑寿命。

### 1.5 `clients`：规则集与匹配规范

**规则字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | u64 | |
| `name` | string ≤ 64 | 显示用 |
| `action` | `allow` / `deny` | |
| `pid_prefix` | string ≤ 20 字节 | 字面字节，可用 `%XX` 表示任意字节（如 `-UT%32%32`） |
| `pid_regex` | string ≤ 256 | 作用于 peer_id 的 Latin-1 文本（每个字节 → U+00XX）；可含命名组 `ver` |
| `min_ver` / `max_ver` | `^\d+(\.\d+){0,3}$` | 需要 `pid_regex` 含 `ver` 组 |
| `ua_prefix` | string ≤ 64 | |
| `ua_regex` | string ≤ 256 | |
| `enabled` | bool | 停用的规则不导出 |
| `note` | string ≤ 500 | |

约束：每条规则至少有 `pid_prefix`、`pid_regex`、`ua_prefix`、`ua_regex` 之一；规则数 ≤ 500；正则用 Rust `regex`（线性时间），`RegexBuilder::size_limit(64 KiB)`。

**匹配算法**（pt-tracker 必须实现完全相同的语义）：

```
fn decide(rules, default, peer_id: [u8;20], ua: &str) -> (action, rule_id?):
    for r in rules（数组顺序）:
        if r.pid_prefix && !peer_id.starts_with(r.pid_prefix_bytes): continue
        if r.ua_prefix  && !ua.starts_with(r.ua_prefix): continue
        if r.ua_regex   && !r.ua_regex.is_match(ua): continue
        if r.pid_regex:
            m = r.pid_regex.captures(latin1(peer_id)) else continue
            if r.min_ver || r.max_ver:
                v = m["ver"] else continue
                digits = [base36(c) for c in v]          // '0'-'9' → 0-9，'A'-'Z'/'a'-'z' → 10-35，其他字符 → 规则不匹配
                if r.min_ver && cmp(digits, parse(r.min_ver)) < 0: continue
                if r.max_ver && cmp(digits, parse(r.max_ver)) > 0: continue
        return (r.action, r.id)
    return (default, None)
cmp(a, b): 右侧补 0 到同长后逐项比较
```

例：qBittorrent 4.6.3 的 peer_id 前缀 `-qB4630-`，规则 `pid_regex = "^-qB(?P<ver>[0-9A-Z]{4})-"`、`min_ver = "4.3"` → digits `[4,6,3,0]` ≥ `[4,3,0,0]` → 命中。

**导出格式**（`trk:clients` 的值）：

```json
{ "ver": 1287, "default": "deny",
  "rules": [
    { "id": 5, "name": "qBittorrent 4.6.0（有缺陷，拒绝）", "action": "deny", "pid_prefix": "-qB4600-" },
    { "id": 3, "name": "qBittorrent ≥ 4.3", "action": "allow",
      "pid_regex": "^-qB(?P<ver>[0-9A-Z]{4})-", "min_ver": "4.3", "ua_prefix": "qBittorrent/" },
    { "id": 4, "name": "Transmission ≥ 3.0", "action": "allow",
      "pid_regex": "^-TR(?P<ver>[0-9]{3})[0-9Z]-", "min_ver": "3.0" }
  ] }
```

`pid_prefix` 导出时为 `%XX` 编码后的 ASCII 字符串；未设置的字段省略。

**保存**：

```
fn set_rules(ctx, rules, expected_version, by):
    validate 每条（错误收集为 errors[{path: "/rules/3/pid_regex", code, message}]）→ tracker-bridge.rules_invalid
    UPDATE client_ruleset SET version = version + 1 … WHERE id = 1 AND version = $expected  → 0 行 → kernel.conflict
    DELETE client_rules；INSERT 新规则（position = 下标）
    ver = next_ver()；json = export(rules where enabled, default)
    EVALSHA trk_put_json [trk:clients, trk:sync] ver json maxlen
    audit("tracker-bridge.client_rules_set", target "global", {version, added, removed, changed})
    publish tracker.client_rules_changed {version, rule_count}
```

**预设模板**（`GET /client-rule-presets`，只读数据，随插件发布）：qBittorrent ≥ 4.3、Transmission ≥ 3.0、Deluge 2.x（libtorrent `-DE2…`）、rTorrent/libtorrent ≥ 0.13.8（`-lt0D8…`）、BiglyBT、libtorrent-rasterbar 通用、Flood（经 rTorrent）；以及常见拒绝项（迅雷 `-XL`、`-SD`，μTorrent 3.x 可选）。管理员一键加入后可编辑。

### 1.6 `cfg`

`trk:cfg` 字段（全部十进制字符串）：

| 字段 | 来源设置 | 校验 |
|---|---|---|
| `interval` | `announce_interval` | 300～7200 |
| `min_interval` | `announce_min_interval` | 60～interval |
| `max_peers` | `max_peers` | 1～200 |
| `max_numwant` | `max_numwant` | max_peers～500 |
| `emit_zero_delta` | | 0/1 |
| `require_ua` / `deny_browser_ua` / `deny_abnormal_headers` / `scrape_enabled` | | 0/1 |

### 1.7 `rebuild`

```
job rebuild(payload {scope, target_id?, run_id}):          // tx = manual
    if scope == full:
        SET p:tracker-bridge:rebuild_lock <run_id> NX EX 3600 失败 → 标记 run 为 skipped（另一个在跑）；return
    UPDATE rebuild_runs SET state = running, started_at = now(), start_ver = nextval
    match scope:
      user    → sync_user(target_id)
      torrent → sync_torrent(target_id)
      full    →
        cursor = 0
        loop users:
            ids/status = SELECT id, status FROM identity.v_user_public WHERE id > $cursor ORDER BY id LIMIT 1000
            if empty: break
            ver = next_ver()；pks = ctx.users.get_sensitive_many(ids, "passkey")
            按 §1.3 组装命令（每用户 2～3 条）→ pipeline；UPSERT user_sync（批量 UNNEST）
            processed += n；UPDATE rebuild_runs SET processed；sql.commit()；续约锁（EXPIRE）
        loop torrents（同理，视图键集；包含 deleted 且 deleted_at > now − ttl 的行；替换历史批量取）
        写 trk:clients（导出当前规则）与 trk:cfg
        sweep(start_ver)                                       // 孤儿清理
        XADD trk:sync MAXLEN ~ maxlen * kind all key all op reload ver <next_ver()>
    UPDATE rebuild_runs SET state = done, finished_at, counts
    publish tracker.resynced {scope, count, run_id, mismatches: orphans, duration_ms}
    DEL lock（值等于 run_id 时）
    异常：state = failed, error；publish tracker.inconsistency_detected{kind: rebuild_failed}

fn sweep(start_ver):
    for key in SCAN trk:pk:* COUNT 1000（tracker_sync）:
        (uid, st, ver) = HMGET key uid st ver
        if ver ≥ start_ver: continue                          // 本次重建或之后写过
        if st == 3: continue                                  // 墓碑，自行过期
        cur = HGET trk:u:<uid> pk
        if cur != passkey_of(key): trk_del key ver=next_ver() kind "pk"
    for key in SCAN trk:t:*:
        ver < start_ver 且 hash 不在 torrent_sync 中 → trk_del kind "t"
```

`kind = all, op = reload` 让 pt-tracker 节点做一次全量重载（覆盖“节点本地缓存里残留了被清理的键”的情况）。

### 1.8 `checker`

```
cron check_sample:
    run = INSERT check_runs(kind = sample)
    // 用户：随机起点
    r = random u64；ids = SELECT user_id FROM user_sync WHERE user_id >= $r ORDER BY user_id LIMIT N
         （不足 N 则从头补齐）；另加 v_user_public 中最近 1 小时内更新的用户（若视图有 updated_at，否则略）
    expected = v_user_public 状态 → (st)
    actual   = pipeline HGET trk:u:<uid> pk；再 HMGET trk:pk:<pk> uid st ver
    mismatch 类型：missing_reverse、missing_pk、wrong_uid、wrong_st、fp_mismatch（HMAC(pk) ≠ user_sync.fp）
    抽样 1%：get_sensitive_many 比较 identity 当前 passkey 与 trk:u 的 pk → passkey_drift
    // 种子
    rows = v_torrent_tracker 随机起点 N 行 → 期望 (tid, st, acct, own) vs HMGET trk:t:<hash>
    // 客户端与参数
    trk:clients.ver vs client_ruleset 导出时记录的 ver；trk:cfg.ver vs 设置版本
    // 节点
    nodes.refresh()
    修复：每个不一致对象调用 sync_user / sync_torrent（新 ver）
    UPDATE check_runs SET mismatches = {type: count}, repaired, samples（最多 50 条，不含 passkey，只含 uid/tid 与类型）
    if Σ mismatches ≥ threshold: publish tracker.inconsistency_detected；notify（可选）
    每 1000 个对象 sql.commit()

cron check_full: 同上但遍历全部（键集分页），最后 sweep(当前 ver − 0)（只清理确认的孤儿），并删除 90 天前的 check_runs
```

重复执行：校验只读 + 修复操作本身幂等（新 ver 重写当前状态）；同一 `scheduled_at` 被内核去重；即使重复运行也只多一次无害重写。

### 1.9 `nodes`

读取 `SCAN trk:stats:node:* COUNT 100` → `HGETALL`：

| 字段 | 含义 |
|---|---|
| `ver` | pt-tracker 版本 |
| `boot` | 启动时间（Unix 秒） |
| `sid` | 已应用的 `trk:sync` 最新 ID |
| `lag_ms` | 节点自报同步延迟（最新条目时间戳与应用时间之差） |
| `pk` / `t` | 本地缓存条目数 |
| `peers` / `torrents` | swarm 规模 |
| `mpt` | `max_peer_timeout` 秒 |
| `rps` | 最近 1 分钟 announce 速率 |
| `ts` | 写入时间 |

计算：本插件另取 `XINFO STREAM trk:sync` 的 `last-generated-id`，若节点 `sid` 落后且 `now − ts(sid 对应时间) > node_lag_alert_ms` → 告警 `node_lag`；记录过的节点 ID 在键过期后 2 分钟仍未出现 → `node_lost`（节点 ID 列表存 `kv` 的 `nodes_seen`，24 h 未出现则移除）。

### 1.10 `peers`

**`ps:<hash>` 值格式**（契约，见 pt-tracker LLD §3.4）：field = `<uid 十进制>:<peer_id 40 位小写 hex>`；value（大端）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | `fmt` = 1 |
| 1 | 1 | `flags`：bit0 completed、bit1 ipv6、bit2 seeder（left = 0） |
| 2 | 2 | `port` |
| 4 | 4 | `ver`（CAS 版本） |
| 8 | 8 | `uploaded` |
| 16 | 8 | `downloaded` |
| 24 | 8 | `left` |
| 32 | 4 | `last_ts`（Unix 秒） |
| 36 | 4 | `started_ts` |
| 40 | 4 / 16 | IP（v4 / v6） |

`fmt` 未知的条目跳过并计数。

```
fn peers(ctx, tid, want_ip) -> Vec<PeerInfo>:
    t = ctx.torrents.get(tid)? ?: kernel.not_found          // 以调用者 actor 做可见性检查
    hashes = [t.info_hash_v1, trunc(t.info_hash_v2)].flatten()
    entries = for h in hashes: HSCAN ps:<h> COUNT 500 直到结束或累计 2000 条（超过则 truncated = true）
    cutoff = now − mpt（节点状态中的最大值，缺省 2700）
    out = entries.filter(last_ts ≥ cutoff).map(decode)
    include_ip = want_ip && caller 有效敏感能力含 peer.ip && （HTTP 时）rbac(tracker-bridge.peers.read_ip)
    if include_ip: audit("tracker-bridge.peer_ip_read", "torrent:<tid>", {count})
    client = client_name(peer_id)   // 解析 Azureus 风格 -XXvvvv-，未知显示前 8 字节可打印部分
    sort: seeder 优先，再按 last_ts 降序
```

`peers_of_user(uid)`：`ctx.accounting.seeding_now(uid)`（可选依赖，缺失返回 `kernel.service_unavailable`）→ 前 200 个种子 → 对每个 hash `HSCAN ps:<h> MATCH <uid>:* COUNT 500`。本人查看时 IP 以掩码显示（IPv4 `a.b.*.*`，IPv6 前 32 位），不需要 `peer.ip` 授权以外的权限（数据属于本人），但仍要求本插件被授予 `peer.ip`，否则不显示。

### 1.11 事件处理入口

| 订阅 | 处理 | 幂等说明 |
|---|---|---|
| `on_user_registered`、`on_user_passkey_reset`、`on_user_status_changed` | `sync_user(payload.user_id)` | 基于当前状态重写；Redis 侧以 ver 判定；PG 侧 UPSERT |
| `on_user_deleted` | `revoke_user` | 同上 |
| `on_torrent_created`、`on_torrent_status_changed`、`on_torrent_deleted` | `sync_torrent(payload.torrent_id)` | 同上 |
| `on_torrent_updated` | `fields ∩ {info_hash, size} ≠ ∅` 时 `sync_torrent`，否则直接成功 | 同上 |
| `on_settings_changed` | `payload.plugin_id == "tracker-bridge"` 时写 `trk:cfg` | 同上 |

全部 `ordered = true`（同一用户 / 种子顺序处理），`max_attempts = 20`（Redis 短暂故障时多给重试机会），失败进入死信后由校验任务兜底修复。

**tracker_sync（契约，pt-tracker 读取）**：

| `trk:u:<user_id>` | HASH | `pk`、`ver` | 无（用户删除时删） | 本插件（pt-tracker 不读） |
| `trk:t:<info_hash 40 hex>` | HASH | `tid`、`st`（0 open / 1 owner_only / 2 disabled / 3 deleted / 4 replaced）、`acct`（0/1）、`size`、`own`（uid，0 = 无）、`ver`、`rsn?`、`exp?` | 墓碑：`exp − now`；其他无 | 本插件 |

| `trk:cfg` | HASH | §1.6 字段 + `ver` | 无 | 本插件 |

| `trk:stats:node:<node_id>` | HASH | §1.9 | 30 s | pt-tracker |
| `trk:stats:denied:<yyyymmdd>`（UTC 日期） | ZSET | member `<peer_id 前 8 字节>|<UA 前 32 字节>`：peer_id 中非 `[0-9A-Za-z._~-]` 的字节写成 `%XX`（大写十六进制），UA 中的 `|`、`%` 与控制字符同样写成 `%XX`；score 次数 | 8 天 | pt-tracker |

**tracker_state（只读）**：`ps:<info_hash 40 hex>`，格式见 §1.10。

**main（私有）**：

| 键（插件内写法） | 类型 | TTL | 说明 |
|---|---|---|---|
| `rebuild_lock` | STRING | 3600 s，续约 | 全量重建互斥，值为 run_id |

## 6. 安全设计

| 项 | 措施 |
|---|---|
| passkey | 只在 `sync_user`、重建、校验函数的局部变量中出现，用后 `zeroize`；PG 只存 HMAC 指纹；日志、错误、审计、指标中只出现 `uid`；`tracing` 字段过滤 `pk`、`passkey`；`check_runs.samples` 不含 passkey |
| Redis ACL（`deploy/redis/acl.conf` 模板） | `user pt-bridge on >… ~trk:* +@read +@write +@stream +evalsha +script|load -@dangerous`（tracker_sync）；`user pt-bridge-ro on >… ~ps:* +@read -@write`（tracker_state）；pt-tracker 账号以 components/pt-tracker 03 §6.2 为准：只读 `trk:pk:*`、`trk:t:*`、`trk:clients`、`trk:cfg`、`trk:sync`，读写 `trk:stats:*`，**不能读 `trk:u:*`** |
| 输入 | 规则字段长度、正则大小限制、线性时间引擎；规则测试接口的 peer_id 解码限制为 20 字节 |
| 权限 | 路由权限由网关检查；IP 返回需要双重条件（插件 `peer.ip` 授权 + 用户 `tracker-bridge.peers.read_ip`）；`peers` 服务先经 `ctx.torrents.get` 做可见性检查（候选种子的 peer 不会泄露给无权者） |
| 审计 | `tracker-bridge.client_rules_set`、`tracker-bridge.cfg_set`、`tracker-bridge.rebuild`、`tracker-bridge.repair`（校验修复汇总）、`tracker-bridge.peer_ip_read` |
| 重建 | 需要 `tracker-bridge.resync`（sysop）+ 近期重新验证（security.md §3；若平台尚无路由级“近期重新验证”声明，本插件在 HLD §7 中一并提出） |
