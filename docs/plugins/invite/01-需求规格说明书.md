## 1. 引言

### 1.1 目的

定义 `invite` 插件（WASM，提供 `ctx.invites`）的功能与非功能需求：邀请码的生成、发放、过期、撤销；邀请额度的来源与消耗；注册钩子中的邀请码预留与注册事件确认；邀请树与连坐；防倒卖；发邀统计。本文是概要设计（HLD-INV）、详细设计（LLD-INV）与测试计划（TP-INV）的依据。

### 1.2 范围

**包含**

- 个人邀请码（一次性）、管理员 / 系统邀请码（含面试通过后签发）、活动邀请码（多次使用，P2）。
- 邀请额度账户：永久额度与带有效期的临时额度（“额度批次”），来源包括等级晋升赠送、按等级周期发放、商城购买（shop 调用 `ctx.invites.grant_quota`）、管理员调整、新用户初始额度。
- `user.before_register` 钩子处理者：校验 + 带 TTL 预留；`user.registered` 订阅：确认兑换、建立邀请树边。
- `invite.before_issue` 钩子点（拥有者）：允许 levels / ratio-policy / hnr 等插件否决发邀。
- 邀请树查询、后台整树操作（参考 Gazelle）。
- 连坐规则（可配置）：被邀请人被封禁 / 作弊处置时对上游邀请人扣额度、暂停发邀、通知、标记复核等，可在解封时撤销。
- 防倒卖：128 位随机码、哈希存储、短有效期、未使用数量上限、可选邮箱绑定 / 用户名预定、连坐威慑、统计识别异常邀请人。
- 用户与站点级发邀统计。
- HTTP API、MCP 工具、前端页面与插槽注入。

**不包含**

- 是否允许“无邀请码注册”、注册窗口、名额、答题、验证码、邮箱域名规则——由 `registration-policy` 负责。
- 账号创建、邮箱验证、用户状态——由 `identity` 负责。
- 购买邀请的扣款与商品定义——由 `shop` 负责，本插件只提供 `grant_quota` / `deduct_quota`。
- 邀请邮件的投递——P2，依赖 `notify` 新增“发送到外部地址”能力（见 HLD §7）；本期默认由邀请人复制链接发送。
- 多号检测、邀请交易监控的机器学习——属于 anticheat。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 邀请码 | `INV-` + 26 位 Crockford Base32（128 位，由插件密钥对签发幂等键做 HMAC 派生，对外等价于随机，见 HLD DD-INV-1）；只在签发时明文返回，库中只存 SHA-256 |
| 码尾 | 邀请码最后 4 位，用于列表展示（`code_hint`） |
| 额度 / 名额 | 用户可发出的邀请数，站点叫法用术语键 `invite.quota` |
| 额度批次（lot） | 一次发放形成的额度记录，带来源、剩余数、可选到期时间；消耗时按“先到期先用”（FIFO by expires_at） |
| 临时额度 | 带到期时间的批次，NexusPHP 称“临时邀请” |
| 预留 | 注册钩子中对邀请码写入的带 TTL 记录（用户名 + 到期时间），由 `user.registered` 确认，过期自动释放 |
| 邀请树 / 边 | 被邀请人 → 邀请人的有向边；根为无邀请人用户 |
| 连坐 | 被邀请人违规时对其上游邀请人（1～N 级）施加的处置 |
| 发邀权暂停 | 本插件内部的限制，在期限内不能发邀请 |

## 2. 总体描述

### 2.1 插件定位

| 项 | 内容 |
|---|---|
| 类型 | WASM（站点规则，低频调用；热路径仅注册钩子） |
| 提供服务 | `ctx.invites`（single） |
| 依赖服务 | `ctx.users`（必需：查用户状态 / 等级）；`ctx.rbac`（必需：`invite.quota.bypass`、`invite.penalty.exempt` 权限判断）；`ctx.registration`（可选：绑定邮箱的域名预检）；`ctx.notify`（可选：连坐通知）；`ctx.users` 作用域 `write:status`（可选，仅当启用“限制邀请人下载”连坐动作） |
| 只读视图 | `identity.v_user_public`（批量按等级发放、邀请树展示）、`accounting.v_user_totals`（被邀请人分享率统计） |
| 钩子 | 处理 `user.before_register`（优先级 10）；拥有 `invite.before_issue` |
| 敏感能力 | `sensitive_optional = ["user.email"]`：仅用于邮箱绑定校验（需内核支持钩子输入按处理者裁剪，见 identity DD-IDN-12） |

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户（`invite.send`） | 查看额度与到期；生成邀请链接（可绑定邮箱）；撤销未使用邀请；查看自己邀请的人及其健康度；查看自己受到的连坐处置 |
| 未注册访客 | 打开邀请链接，注册页显示邀请有效性、邀请人（可配置）、是否绑定邮箱 |
| 版主（`invite.tree.read`） | 查看任意用户邀请树、发邀统计、“问题邀请人”排行；复核“标记复核”的连坐记录 |
| 管理员（`invite.manage`） | 调整额度、批量发放、签发系统 / 活动邀请码、撤销任意邀请、配置额度规则与连坐规则、整树操作 |
| shop 插件 | 用户购买“邀请名额”后调用 `grant_quota`（带幂等键）；退款时调用 `deduct_quota` |
| 外部面试系统 / registration-policy | 以系统身份签发邀请（`issue`，作用域 `write:issue`） |
| levels / ratio-policy / hnr | 作为 `invite.before_issue` 处理者否决不合格用户发邀 |

### 2.3 现有开源 PT 程序的做法调研

| 项目 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| NexusPHP | `users.invites` 计数 + `invites` 表（`hash`、`inviter`、`invitee` 邮箱、`valid`、`expired_at`）；邀请以邮件发送；后台“邀请过期天数”（默认 7 天，过期删除）、“初始邀请名额”；魔力值商城可购买**永久邀请**与**临时邀请**（临时 7 天有效，`TEMPORARY_INVITE_VALID_DAYS`）；可选“邀请预定邮箱与用户名”（`is_invite_pre_email_and_username`）；“最大用户数”达到后自由注册与邀请注册都关闭；按等级配置“发送邀请 / 查看邀请 / 购买邀请” | 永久 / 临时额度的区分很实用；预定邮箱用户名能有效防倒卖；配置项贴近国内站点习惯 | 邀请码由 `md5(mt_rand(1,10000).username.time.passhash)` 生成，熵低且可预测；码明文存储；兑换检查与插入之间没有锁 / 预留（并发可重复使用）；计数器与明细两套数据易不一致；没有邀请树与连坐 |
| UNIT3D | `invite-only` 开关；邀请 14 天过期；`max_unused_user_invites`（默认 1）；**发邀前须开启 2FA 满 24 小时**；可按用户组限制；邀请必须填写邮箱，且邮箱在 invites / users / applications 中唯一并经过一次性邮箱黑名单；UUID v4 作为码；邀请树页面；申请制（Application）：申请人提交邮箱、类型、推荐人、≥2 张证明截图与 ≥2 个链接，审核通过后系统向邮箱发邀请 | 未使用邀请数上限 + 强制邮箱 + 2FA 门槛，对“养号卖邀”有明显抑制；申请制作为第二通道 | 撤销邀请不返还名额；码明文存储；额度只有单一计数，不支持临时额度；规则硬编码在 config 中 |
| Gazelle / OPS | `users_main.inviter_user_id` 构成邀请树，用递归 CTE 一次取出整棵子树，并尊重被邀请人的“偏执”（paranoia）隐私设置；树页面给出各层统计（人数、上传下载、各等级分布）；**员工可对整棵子树执行操作**（封禁全树、收回全树发邀权、加备注）；撤销未用邀请返还名额；`site_send_unlimited_invites` 权限可无限发邀；`InviteSource` 记录招募来源（从哪个站招募）；IRC 面试系统通过 API `GenerateInvite` 以面试官为邀请人签发 3 天有效的邀请 | 邀请树 + 整树处置是“连坐”的事实标准；招募来源统计便于评估招募渠道；面试通过即签发邀请的流程清晰 | 连坐完全靠人工；树查询在大树上每次全量递归、结果靠缓存；邀请与用户主表强耦合 |
| TorrentPier | `config/auth.php` 中的静态邀请码表（码 → 到期时间，或 `permanent`），任何人可重复使用 | 适合活动期间“公开活动码” | 码共享、无用量上限、无归属，无法追责 |
| Luminance / Arcadia | Luminance 沿用 Gazelle 的邀请与邀请树模型；Arcadia 尚处早期，未见成型的邀请额度体系 | — | — |

**我们采纳**

1. NexusPHP 的“永久 + 临时额度”，抽象为**额度批次**：任何来源都可带到期时间，消耗时先用最早到期的批次。
2. NexusPHP 的“预定邮箱 / 用户名”与 UNIT3D 的“强制邮箱”合并为可配置的**绑定**（邮箱以 HMAC 存储，用户名可选预定），按等级可设为必需。
3. UNIT3D 的“未使用邀请上限”“发邀资格门槛”；门槛中与其他插件有关的（等级、分享率、H&R）一律通过 `invite.before_issue` 钩子由对应插件判定，本插件只管自己的数据（账号状态、注册天数、暂停、上限）。
4. Gazelle 的邀请树（递归 CTE）、整树操作、无限发邀权限、撤销返还、面试签发。
5. TorrentPier 的“活动码”作为 P2：只能由管理员创建，带用量上限、到期与归属（创建人），解决共享码无法追责的问题。

**我们改进**

1. **安全的码**：128 位 CSPRNG（`ctx.random`），库中只存 SHA-256，日志 / 事件 / 审计只出现码尾。
2. **并发正确**：兑换不在钩子中“一次写死”，而是“钩子中带 TTL 预留 + `user.registered` 确认”（平台 README 要点 4、identity §5.1），同一用户名重试可复用预留，其他用户名在预留有效期内被拒。
3. **单一事实来源**：额度余额 = 未过期批次剩余之和，所有变动写只追加的额度流水，可对账；不再维护易漂移的计数列。
4. **自动连坐，可配置、可撤销**：由事件驱动（`user.status_changed`、`anticheat.case_resolved`），每条处置幂等记录，解封时可自动撤销；默认动作温和（扣额度、暂停发邀、通知），强处置（限制下载）需站点授权并默认关闭。
5. **统计识别倒卖**：按邀请人统计被邀请人早期封禁率、存活率，后台给出“问题邀请人”排行，供版主复核。

### 2.4 约束与假设

1. WASM 插件每次调用新实例、无内存状态；每次调用一个事务；钩子写入独立提交（kernel/03 §5.2）。
2. 钩子中不能出站 HTTP；连坐通知等出站动作只在事件处理中进行，并带 `<event_id>:<子键>` 幂等键。
3. identity 在调用钩子前已完成用户名 / 邮箱唯一性预检（identity LLD §1.2），唯一冲突时依赖预留 TTL 释放。
4. identity 在 `user.registered` 中携带 `invite_code`、`inviter_id`、`registration_mode`、`username`；`username` 与钩子输入中的 `username` 为同一显示形式，可用于关联预留。
5. 钩子输入中的 `email` 只有在内核实现“按处理者裁剪”且站点授予 `user.email` 时才出现；否则邮箱绑定退化为域名校验（见 FR-INV-004）。
6. 用户等级 `class_id` 从 `ctx.users` / `identity.v_user_public` 读取；等级晋升事件 `level.promoted` 由 levels 发布。
7. 站点规模：用户 50 万，日均注册 ≤ 5,000，开放注册高峰 ≤ 200 次/秒（钩子调用）；邀请树最大子树 10 万节点。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-INV-001 | 生成个人邀请 | 拥有 `invite.send` 的用户提交生成请求（可选邮箱、有效天数、备注）；通过资格检查（FR-INV-002）与 `invite.before_issue` 钩子后，从额度中扣 1，生成 128 位邀请码，返回明文码与注册链接（仅此一次），发布 `invite.issued` | P0 | 余额减 1、流水 1 条、事件 1 条；响应含 `code`、`url`；之后任何接口都不再返回明文（FR-INV-036 开启时除外） |
| FR-INV-002 | 发邀资格检查 | 依次检查：邀请系统启用；账号状态 `active`；注册满 `min_account_days`；未处于发邀权暂停；未使用邀请数 < 本等级 `max_outstanding`；当日发邀数 < `daily_limit`；余额 ≥ 1（有 `invite.quota.bypass` 时跳过余额）；再运行 `invite.before_issue` 钩子 | P0 | 每条不满足时返回对应错误码（LLD §9），钩子拒绝时返回处理者错误码，均不扣额度 |
| FR-INV-003 | 有效期 | 个人邀请默认 `default_expiry_days`（7）天，用户可在 [1, `max_expiry_days`] 内选择；系统 / 面试邀请默认 3 天；到期后不可兑换 | P0 | 过期码在钩子与校验接口中返回 `invite.code_invalid`（`details.reason = expired`） |
| FR-INV-004 | 邮箱绑定（防倒卖） | 发邀时可填写被邀请人邮箱；可按等级配置为必填。存储 `HMAC(email_binding_key, 规范化邮箱)` 与邮箱域名；注册时钩子输入含 `email` 则比对 HMAC，只有 `email_domain` 时比对域名并计入降级指标 | P1 | 邮箱不符 → `invite.binding_invalid`；降级比对时 `pt_plugin_invite_binding_degraded_total` 增加；库中无明文邮箱 |
| FR-INV-005 | 用户名预定 | 发邀时可预定被邀请人用户名；注册用户名必须一致（大小写不敏感） | P2 | 不一致 → `invite.binding_invalid` |
| FR-INV-006 | 公开校验 | 匿名可提交邀请码（POST 体）查询：是否有效、到期时间、是否绑定邮箱 / 用户名、邀请人用户名（`show_inviter_on_check` 可关） | P0 | 有效码返回 200；无效 / 过期 / 撤销 / 已用返回 422 `invite.code_invalid` 及 `reason`；限流 `ip:10/m` |
| FR-INV-007 | 注册钩子预留 | 处理 `user.before_register`：无 `invite_code` 直接放行；有则校验状态、到期、绑定，在行锁下检查“已用次数 + 有效预留 < 最大次数”，写入 `(invite_id, username, reserved_until = now + reservation_ttl)` 预留；同一用户名已有有效预留时延长；返回 modify：`attributes.inviter_id`、`attributes.registration_mode = "invite"` | P0 | 同码两个不同用户名并发注册，只有一个得到预留，另一个返回 `invite.code_reserved`；同一用户名重试成功；钩子 p99 ≤ 30 ms |
| FR-INV-008 | 注册确认 | 订阅 `user.registered`：载荷含 `invite_code` 时按码哈希 + 用户名确认预留，`use_count + 1`，单次码置为 `exhausted`，写邀请树边与统计，发布 `invite.redeemed` | P0 | 同一事件重复投递只确认一次；预留已过期但码未被他人使用时仍确认；码已被他人用完时记录冲突（边照常建立，指标 + 告警） |
| FR-INV-009 | 预留释放 | 过期预留不再计入占用；cron 将过期预留标记为 `released` 便于统计 | P0 | 预留到期后另一用户名可预留成功 |
| FR-INV-010 | 撤销 | 邀请人可撤销自己未使用且无有效预留的邀请；管理员可撤销任意未用完邀请；按 `refund_on_revoke`（默认 true）返还额度到原批次（原批次已过期则不返还）；发布 `invite.revoked` | P0 | 已兑换的邀请撤销返回 `invite.already_redeemed`；返还时余额 +1 且流水记录 |
| FR-INV-011 | 过期处理 | cron 分批把到期未用邀请置为 `expired`，按 `refund_on_expire`（默认 false）决定是否返还，发布 `invite.revoked(reason = expired)` | P0 | 重复运行不重复返还；每批独立提交 |
| FR-INV-012 | 额度批次 | 额度以批次存储（来源、数量、剩余、到期）；余额 = 未过期批次剩余之和；消耗按到期时间升序（永久批次最后）；所有变动写只追加流水并发布 `invite.quota_changed` | P0 | 流水求和 = 余额；临时批次先于永久批次被消耗 |
| FR-INV-013 | 临时额度到期 | cron 把到期批次剩余清零、写流水、发布 `invite.quota_changed(delta < 0, reason = lot_expired)` | P0 | 到期后余额立即不含该批次（查询按时间过滤），cron 只负责落账 |
| FR-INV-014 | 等级晋升赠送 | 订阅 `level.promoted`：按 `class_grants[to_class].on_promotion` 发放（可带有效期）；同一用户同一等级只发一次（降级再升级不重复，可配置 `repeat_on_repromotion`） | P1 | 重复事件只发一次；同用户第二次晋升到同等级默认不发 |
| FR-INV-015 | 按等级周期发放 | cron（默认每月 1 日）按 `class_grants[*].periodic` 为该等级活跃用户发放，`max_balance` 封顶；按用户 ID 键集分批、断点续跑 | P1 | 同一周期重复触发不重复发放；50 万用户 ≤ 10 分钟完成 |
| FR-INV-016 | 商城购买 | shop 调用 `ctx.invites.grant_quota{user, amount, reason = "shop.<order_id>", expires_at?, idempotency_key}`（作用域 `write:quota`）；订单退款调用 `deduct_quota` | P0 | 相同幂等键重复调用返回相同结果、不重复发放；未授权调用方返回 `kernel.capability_denied` |
| FR-INV-017 | 管理员调整 | 管理员对单个用户增减额度（可带有效期与原因），写审计 | P0 | 审计记录含调整前后余额 |
| FR-INV-018 | 批量发放 | 管理员按筛选条件（等级集合、账号状态、注册早于）批量发放，异步分批执行，可查询进度 | P1 | 返回 202 + 任务 ID；中途失败可续跑且不重复发放 |
| FR-INV-019 | 新用户初始额度 | 订阅 `user.registered`，按 `initial_quota`（数量与有效天数）发放 | P2 | 重复事件只发一次 |
| FR-INV-020 | 邀请树 | 维护边表；查询某用户的上游链（≤ 10 级）与下游子树（深度、分页）；返回每个节点的用户名、等级、状态、注册时间、直接下级数 | P0 | 10 万节点子树按深度 3 分页查询 p99 ≤ 300 ms |
| FR-INV-021 | 被邀请人可见性 | 邀请人可查看直接下级的用户名、状态、等级、注册时间；`show_invitee_stats = true` 时还可看上传 / 下载 / 分享率；版主可看整树 | P1 | 无 `invite.tree.read` 的用户查看他人树返回 403 |
| FR-INV-022 | 整树操作 | 版主 / 管理员可对某用户的子树（深度可选）执行：暂停发邀（期限）、撤销全部未用邀请、写备注；异步分批执行并审计 | P1 | 1 万节点子树 ≤ 2 分钟完成，可查看进度 |
| FR-INV-023 | 连坐规则 | 站点配置多条规则：触发（`invitee_banned`、`invitee_cheating`）、条件（被邀请人注册后 `within_days` 天内；向上 `max_depth` 级；被邀请人状态变化来源不是 invite 自身）、动作（`deduct_quota`、`suspend_invite`、`revoke_outstanding`、`notify`、`flag_review`、`restrict_inviter`）、每级动作可不同 | P1 | 对每个（触发事件, 规则, 目标）恰好一条处置记录；发布 `invite.penalty_applied` |
| FR-INV-024 | 连坐撤销 | 被邀请人从封禁恢复（`user.status_changed` from banned）时，对 `reverse_on_lift = true` 的规则撤销处置：返还扣除的额度、解除暂停、解除限制 | P1 | 撤销后余额与暂停状态恢复；重复事件不重复返还 |
| FR-INV-025 | 连坐复核 | `flag_review` 动作产生待复核记录；版主可确认或撤销，撤销等同 FR-INV-024 | P1 | 复核操作写审计 |
| FR-INV-026 | 发邀权暂停 | 本插件维护暂停记录（来源：连坐 / 管理员，带到期）；暂停期间发邀返回 `invite.privilege_suspended`（含到期时间） | P1 | 到期后自动恢复（按时间判断，无需任务） |
| FR-INV-027 | 用户发邀统计 | 用户可查看：已发、已兑换、过期、撤销、当前未用；被邀请人按状态计数；被邀请人平均分享率（可关） | P1 | 统计与明细一致 |
| FR-INV-028 | 站点发邀统计 | 每日汇总：发放、兑换、过期、撤销、额度发放 / 消耗、连坐次数；邀请人排行（兑换数、被邀请人 30 天内封禁率） | P1 | 日汇总 cron 重复执行结果相同 |
| FR-INV-029 | 系统 / 面试邀请 | 拥有作用域 `write:issue` 的插件或 `invite.manage` 的管理员可签发系统邀请（`inviter` 可为空或指定面试官），不消耗额度，`source` 记录渠道（admin / interview / application / api） | P1 | 系统邀请在树中以 `inviter_id` 为空或面试官为父节点 |
| FR-INV-030 | 活动邀请码 | 管理员创建多次使用的活动码（最大次数、到期、备注），兑换者的邀请人为空（或创建人，可配置）；可随时停用 | P2 | 超过最大次数后返回 `invite.code_invalid(reason = exhausted)` |
| FR-INV-031 | 用户删除 | 订阅 `user.deleted`：`soft` 时撤销其未用邀请（不返还）；`purge` 时另外删除其额度批次与流水中的备注、预留中的用户名，邀请树边保留 ID（伪匿名）但标记 `invitee_purged` | P0 | purge 后本插件中无该用户的用户名文本 |
| FR-INV-032 | `ctx.invites` 服务 | 提供 `validate`、`reserve`、`issue`、`revoke`、`quota`、`grant_quota`、`deduct_quota`、`tree`、`inviter_of`、`ancestors`、`stats` | P0 | 契约测试通过；写方法带幂等键 |
| FR-INV-033 | MCP 工具 | `get_my_invites`（只读）、`admin_get_invite_tree`（只读）、`admin_adjust_invite_quota`（写，需确认） | P1 | 输出不含明文邀请码 |
| FR-INV-034 | 前端 | 我的邀请页、个人资料统计、邀请树标签页、后台用户标签页、后台管理页、注册页邀请信息组件 | P1 | 插槽按目录注入；无权限时不渲染 |
| FR-INV-035 | 邀请邮件发送 | 发邀时可选择由站点发送邀请邮件（依赖 notify 新能力，见 HLD §7） | P2 | notify 不可用时界面隐藏该选项 |
| FR-INV-036 | 链接再显示 | `redisplay_link = true` 时邀请人可再次查看自己未使用邀请的链接（服务端由密钥重新派生，库中仍无明文） | P2 | 关闭时接口返回 `invite.redisplay_disabled`；已用 / 撤销 / 过期的邀请不可再显示 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-INV-001 | 性能 | `user.before_register` 处理（含预留写入） | p99 ≤ 30 ms（单实例 PG），超时上限 500 ms 内 |
| NFR-INV-002 | 性能 | 公开校验接口 | p99 ≤ 20 ms；支持 200 次/秒 |
| NFR-INV-003 | 性能 | 邀请树查询 | 10 万节点子树、深度 3、每页 100：p99 ≤ 300 ms |
| NFR-INV-004 | 性能 | 周期发放 | 50 万用户 ≤ 10 分钟；每批 ≤ 1,000 用户且独立提交，单事务 ≤ 2 s |
| NFR-INV-005 | 安全 | 邀请码熵与存储 | 128 位（密钥 HMAC 派生，密钥 256 位，计算上不可与随机区分）；库中只存 SHA-256；明文只在签发响应中出现一次；日志 / 事件 / 审计 / MCP 只出现码尾 |
| NFR-INV-006 | 安全 | 防枚举 | 公开校验 `ip:10/m`；钩子失败计数指标；无效码与有效码的响应耗时差 < 5 ms（统一走索引查找） |
| NFR-INV-007 | 隐私 | 邮箱绑定 | 不存储明文邮箱，只存 HMAC（密钥来自静态配置 `x-pt-secret`）与域名；`user.deleted(purge)` 后删除 |
| NFR-INV-008 | 可靠性 | 幂等 | 所有事件订阅基于 inbox 恰好一次；对外服务调用使用 `<event_id>:<子键>`；`grant_quota`/`deduct_quota`/`issue`/`revoke` 以幂等键去重，重复调用返回首次结果 |
| NFR-INV-009 | 一致性 | 额度 | 任意时刻：每个批次 `0 ≤ remaining ≤ amount`；流水累计 = 当前剩余之和；每日对账任务差异为 0 |
| NFR-INV-010 | 一致性 | 兑换 | 单次码最多兑换一次；多次码兑换数 ≤ `max_uses`（冲突只可能来自事件延迟超过 TTL，必须计数并告警） |
| NFR-INV-011 | 可观测性 | 指标与告警 | 发放 / 兑换 / 预留冲突 / 降级绑定 / 连坐 / 钩子耗时指标；冲突 > 0、钩子 p99 > 100 ms 告警 |
| NFR-INV-012 | 可配置性 | 规则 | 额度规则、连坐规则、有效期、上限均为运行时设置，修改即时生效（下次调用读取） |
| NFR-INV-013 | 可扩展性 | 多副本 | 无内存状态；cron 由内核保证单副本；批处理以游标断点续跑 |

## 6. 外部接口需求概述

- **用户界面**：`/p/invite/`（我的邀请：额度、生成、列表、我邀请的人）、个人资料统计与“邀请树”标签页、后台 `/admin/p/invite/*`（总览统计、邀请检索、额度规则、连坐规则、批量发放、连坐复核）、注册页邀请信息组件（插槽 `auth.register.form_extra`，identity 申请中）。
- **HTTP API**：`/api/p/invite/v1/…`（用户、公开校验、后台），见 LLD §2.4。
- **服务**：`ctx.invites`（LLD §2.1 WIT）。
- **事件**：发布 `invite.issued`、`invite.redeemed`、`invite.revoked`、`invite.quota_changed`、`invite.penalty_applied`（新增）；订阅 `user.registered`、`user.status_changed`、`user.deleted`、`level.promoted`、`anticheat.case_resolved`。
- **钩子**：处理 `user.before_register`；拥有 `invite.before_issue`。
- **MCP**：`get_my_invites`、`admin_get_invite_tree`、`admin_adjust_invite_quota`（新增，见 HLD §7）。
