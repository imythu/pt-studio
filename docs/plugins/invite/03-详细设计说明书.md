## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/invite/`（Rust，`wit-bindgen`），清单 `kind = "wasm"`。每次调用新实例；状态全部在 PG（schema `invite`）与 kv。
- 时间一律 `time.now()`；随机一律 `random.bytes()`。所有 SQL 参数化；排序字段经白名单映射。
- **持有者规范化** `holder(username) = lowercase(nfc(trim(username)))`。identity 在钩子输入与 `user.registered` 中给出同一显示形用户名（SRS §2.4 假设 4），因此两处计算结果一致。
- **密钥**：静态配置 `secret`（`x-pt-secret`，32 字节 base64）。子密钥 `HKDF-SHA256(ikm = secret, salt = "pt-studio/invite", info)`：`code`（码派生）、`email-binding`（邮箱 HMAC）。crate：`hmac`、`sha2`、`hkdf`（MIT/Apache）。
- **幂等**：服务写方法以 `<caller_plugin>:<idempotency_key>` 为键写 `idempotency` 表（同事务），重复调用返回首次结果；事件订阅依赖内核 inbox，对外调用使用 `<event_id>:<子键>`。
- **用户串行化**：任何改变某用户额度或发邀状态的操作先 `lock_account(uid)`：

```sql
INSERT INTO accounts (user_id) VALUES ($1) ON CONFLICT (user_id) DO NOTHING;
SELECT user_id, promo_classes FROM accounts WHERE user_id = $1 FOR UPDATE;
```

  多个用户同时加锁时按 user_id 升序，避免死锁。

### 1.1 codes：码派生与格式

```
fn derive_code(scope: &str, key: &str) -> String:          // scope 如 "user:10086"、"svc:registration-policy"、"admin:7"
    mac = HMAC_SHA256(subkey("code"), "issue:" + scope + ":" + key)
    body = crockford_base32(mac[0..16])                     // 128 位 → 26 字符（末字符只用 3 位）
    return "INV-" + body
fn normalize(input) -> Option<String>:
    s = uppercase(remove_all(input, [' ', '-', '\t']))      // 允许用户粘贴时带空格/连字符
    s = s.strip_prefix("INV")?                               // 必须有前缀
    s = s.map(|c| match c { 'O' => '0', 'I' | 'L' => '1', _ => c })   // Crockford 容错
    require len(s) == 26 && all(c in CROCKFORD_ALPHABET)
    return Some("INV-" + s)
fn code_hash(code) = SHA256(code)                           // bytea(32)
fn code_hint(code) = last4(code)
```

- 无幂等键的签发（HTTP 未带 `request_id`）：`key = random.uuid_v7()`，结果不可重放。
- `issue_key_hash = SHA256(scope + ":" + key)` 唯一，用于去重；重放时 `derive_code(scope, key)` 得到同一码。
- 校验接口与钩子对不合格式的输入直接按 `not_found` 处理，同样执行一次索引查找（对随机哈希）以对齐耗时（NFR-INV-006）。

### 1.2 issue：发邀

**资格检查**（`check_eligibility(uid, kind, now) -> Result<Eligibility>`，返回第一个不满足项）：

| 顺序 | 检查 | 错误码 | 说明 |
|---|---|---|---|
| 1 | `settings.enabled` | `invite.disabled` | |
| 2 | 用户状态 = active（`identity.v_user_public`） | `invite.account_inactive` | pending / leech_disabled / banned 都不能发邀 |
| 3 | `created_at + min_account_days ≤ now`（等级规则 `can_bypass_min_age` 可豁免） | `invite.account_too_new` | `details.available_at` |
| 4 | 无生效暂停（`lifted_at IS NULL AND (until IS NULL OR until > now)`） | `invite.privilege_suspended` | `details.until?` |
| 5 | `outstanding < class_rules[class].max_outstanding`（bypass 跳过） | `invite.outstanding_limit_reached` | outstanding = 本人 active 邀请数 |
| 6 | 今日（站点时区）已发 < `daily_limit`（bypass 跳过） | `invite.daily_limit_reached` | |
| 7 | 余额 ≥ 1（bypass 跳过） | `invite.quota_exhausted` | |
| 8 | 等级规则 `require_email_binding` 且未提供邮箱 | `kernel.validation_failed`（`errors[].path=/email`） | |
| 9 | `ctx.registration.check_email_domain`★ 可用且返回 deny | `invite.binding_domain_not_allowed` | 仅提示性校验，失败不阻断（`registration` 不可用时跳过） |
| 10 | `invite.before_issue` 钩子 | 处理者错误码 | |

bypass = `ctx.rbac.check(uid, "invite.quota.bypass")`★。`GET /users/me/eligibility` 执行 1～7 并返回每项结果（不触发钩子），供前端提示。

**签发算法**：

```
fn issue_personal(uid, req) -> IssuedInvite:          // req: email?, username?, expires_days?, note?, request_id?
    scope = "user:" + uid; key = req.request_id ?? uuid_v7()
    tx:
      lock_account(uid)
      if row = SELECT … FROM invites WHERE issue_key_hash = sha256(scope:key):
          return replay(row, derive_code(scope, key))      // 200，同一结果
      elig = check_eligibility(uid, personal, now)?
      days = clamp(req.expires_days ?? default_expiry_days, 1, max_expiry_days)
      binding = bind(req.email, req.username)             // email → (HMAC(subkey("email-binding"), canon_email), domain)
      outcome = hooks.run("invite.before_issue", {version:1, actor, inviter_id: uid, kind: "personal", source: "user",
                         class_id, outstanding: elig.outstanding, email_domain: binding.domain?, email_bound: binding.email?})
      if Denied(d): return Err(d.code)
      lot_id = elig.bypass ? NULL : consume_one(uid, reason = "issue", ref = "invite")   // §1.5
      code = derive_code(scope, key)
      id = INSERT invites(kind='personal', source='user', code_hash, code_hint, inviter_id=uid, issued_by=uid,
                          status='active', max_uses=1, use_count=0, expires_at=now+days, email_hmac, email_domain,
                          username_binding, note, issue_key_hash, lot_id) RETURNING id
      publish invite.issued{invite_id: id, inviter_id: uid, expires_at, kind, source, max_uses: 1, email_bound, username_bound, code_hint}
      metrics invite_issued_total{kind=personal}
    return {invite_id, code, url: base_url_path + urlencode(code), expires_at}
```

- 系统 / 面试 / 申请邀请（`issue` 服务或 `POST /admin/invites`，`kind = system`）：不检查资格、不触发 `invite.before_issue`（调用方已授权，管理员 / 面试官即为把关人）、不消耗额度（除非 `consume_quota = true` 且指定 `inviter`，此时执行资格 1～7）；`expires_at` 默认 `system_expiry_days`；`inviter` 可为空或为面试官。
- 活动码（`kind = campaign`，P2）：`max_uses` ∈ [2, 100000]；仅管理员；`inviter_id = NULL`，`issued_by` = 创建人；`campaign_inviter = creator` 时兑换者的邀请人为创建人。
- `username_binding` 存规范化用户名（holder 形式）。

### 1.3 redeem：钩子处理（`user.before_register`）

```
fn on_before_register(input) -> HookDecision:
    code = input.invite_code
    if code is None or code == "": return Allow
    t0 = now()
    norm = normalize(code)
    h = norm.map(code_hash).unwrap_or(sha256("INV-invalid:" + code))   // 格式不合也走一次查找
    holder = holder(input.username)
    row = SELECT i.id, i.kind, i.status, i.expires_at, i.max_uses, i.use_count, i.inviter_id, i.issued_by,
                 i.email_hmac, i.email_domain, i.username_binding, u.status AS inviter_status
          FROM invites i LEFT JOIN identity.v_user_public u ON u.id = i.inviter_id
          WHERE i.code_hash = $h FOR UPDATE OF i
    reason = match:
        row is None                                         => not_found
        !settings.enabled and !settings.redeem_when_disabled => disabled
        row.status == revoked                               => revoked
        row.status == exhausted                             => exhausted
        row.status == expired or row.expires_at <= now      => expired
        row.inviter_id is Some and row.inviter_status ∉ {active, leech_disabled} and !redeem_if_inviter_unavailable
                                                            => inviter_unavailable
        _ => ok
    if reason != ok: metrics(hook_denied{reason}); return Deny(invite.code_invalid, details{reason})
    // 绑定
    if row.username_binding is Some and row.username_binding != holder: return Deny(invite.binding_invalid, {field: "username"})
    if row.email_hmac is Some:
        if input.email is Some:
            if HMAC(email-binding, canon_email(input.email)) != row.email_hmac: return Deny(invite.binding_invalid, {field: "email"})
        else:
            metrics(binding_degraded_total)
            if input.email_domain != row.email_domain: return Deny(invite.binding_invalid, {field: "email"})
    // 占用检查
    others = SELECT count(*) FROM reservations
             WHERE invite_id = $id AND state = 'active' AND reserved_until > now() AND holder <> $holder
    if row.use_count + others >= row.max_uses: return Deny(invite.code_reserved, details{retry_after_secs})
    INSERT INTO reservations (invite_id, holder, reserved_until, state)
         VALUES ($id, $holder, now() + make_interval(secs => $ttl), 'active')
    ON CONFLICT (invite_id, holder) WHERE state = 'active'
         DO UPDATE SET reserved_until = EXCLUDED.reserved_until, updated_at = now()
    inviter = match row.kind { campaign => (campaign_inviter == creator ? row.issued_by : None), _ => row.inviter_id }
    histogram(hook_ms, now() - t0)
    return Modify({"attributes": {"invite_id": row.id, "inviter_id": inviter?}})   // 评审 R1：事件不再携带明文邀请码，确认阶段按 invite_id 查找
```

- `retry_after_secs` = 他人预留中最早到期的剩余秒数（提示“该邀请码正被使用，请稍后再试”）。
- 预留只在邀请 active 时写；同一持有者重复提交只延长到期（可重入）。
- 钩子工作单元独立提交：后续处理者拒绝或 identity 因唯一冲突放弃建号时，预留在 `reservation_ttl_secs` 后失效。

### 1.4 redeem：确认（订阅 `user.registered`）

```
fn on_user_registered(evt):
    p = evt.payload                          // user_id, username, inviter_id?, registration_mode, attributes{invite_id?}, …
    if p.attributes.invite_id is Some:
        confirm(evt.id, p)
    grant_initial_quota(evt.id, p.user_id)   // initial_quota.amount > 0 时

fn confirm(event_id, p):
    inv = SELECT … FROM invites WHERE id = p.attributes.invite_id FOR UPDATE
    if inv is None: metrics(redeem_unknown_code); return
    if exists(redemptions WHERE invitee_id = p.user_id): return          // 回放 / 重复（inbox 之外的保险）
    holder = holder(p.username)
    r = UPDATE reservations SET state='consumed', user_id=$uid, updated_at=now()
        WHERE invite_id=$id AND holder=$holder AND state IN ('active','released') RETURNING id
    if r is None: metrics(redeem_without_reservation)                  // 例如管理员建号带码
    over = inv.use_count >= inv.max_uses or inv.status ∈ {revoked, expired}
    UPDATE invites SET use_count = use_count + 1,
                       status = CASE WHEN status='active' AND use_count + 1 >= max_uses THEN 'exhausted' ELSE status END,
                       updated_at = now() WHERE id = $id
    if over: metrics(over_redeemed_total); log warn {invite_id, user_id}
    inviter = p.inviter_id ?? effective_inviter(inv)
    INSERT redemptions(invite_id, invitee_id, inviter_id, event_id, over_redeemed = over)
    if inviter is Some: add_edge(p.user_id, inviter, inv.id, registered_at = evt.occurred_at)   // §1.6
    publish invite.redeemed{invite_id, inviter_id: inviter?, invitee_id: p.user_id, kind, over_redeemed: over}
```

- 预留过期（`released`）但码仍可用时照常确认（SRS FR-INV-008）。
- 码在钩子与事件之间被撤销：仍确认（账号已建立），`over_redeemed = true`，供人工复核。
- `p.inviter_id` 与本地计算不一致时以 `p.inviter_id` 为准（identity 已写入用户记录），并计指标 `inviter_mismatch_total`。

### 1.5 quota：批次、消耗、发放、扣减

**余额**：

```sql
SELECT COALESCE(sum(remaining), 0) AS balance,
       COALESCE(sum(remaining) FILTER (WHERE expires_at IS NULL), 0) AS permanent,
       min(expires_at) FILTER (WHERE expires_at IS NOT NULL) AS next_expiry
FROM quota_lots
WHERE user_id = $1 AND remaining > 0 AND (expires_at IS NULL OR expires_at > now());
```

**消耗一个（FIFO）**：

```
fn consume_one(uid, reason, ref) -> LotId:      // 调用前已 lock_account(uid)
    lot = SELECT id FROM quota_lots
          WHERE user_id=$1 AND remaining > 0 AND (expires_at IS NULL OR expires_at > now())
          ORDER BY expires_at ASC NULLS LAST, id ASC LIMIT 1 FOR UPDATE
    if lot is None: Err(invite.quota_exhausted)
    UPDATE quota_lots SET remaining = remaining - 1, updated_at = now() WHERE id = $lot
    ledger(uid, lot, -1, reason, ref)
    return lot

fn ledger(uid, lot, delta, reason, ref, actor?):
    bal = balance(uid)                               // 已包含本次变化
    INSERT quota_ledger(user_id, lot_id, delta, reason, ref, balance_after = bal, actor_id)
    publish invite.quota_changed{user_id: uid, delta, balance: bal, reason, lot_id, expires_at?}
```

**发放**：

```
fn grant(uid, amount, source, source_ref, expires_at?, reason, actor?, idem?) -> GrantResult:
    if idem and r = SELECT result FROM idempotency WHERE key = idem: return r
    lock_account(uid)
    if max_balance_applies(source): amount = min(amount, max_balance - balance(uid)); if amount <= 0: return {lot: None, balance, granted: 0}
    lot = INSERT quota_lots(user_id, source, source_ref, amount, remaining = amount, expires_at)
          ON CONFLICT (source, source_ref, user_id) DO NOTHING RETURNING id
    if lot is None: return existing(source, source_ref, uid)       // 自然键去重（周期、晋升、事件）
    ledger(uid, lot, +amount, reason, source_ref, actor)
    if idem: INSERT idempotency(key = idem, op = 'grant', result)
    return {lot_id, granted: amount, balance}
```

- `source` ∈ `level_promotion | periodic | shop | admin | initial | batch | penalty_refund | migration`；`source_ref` 唯一（同用户）：`periodic:<period>:<class_id>`、`<event_id>`、`shop:<caller>:<idempotency_key>`、`admin:<request_uuid>`、`batch:<job_id>`。
- `expires_at` 必须在未来且 ≤ now + 3650 天；`amount` ∈ [1, 1000]（管理员 ≤ 100000）。

**扣减**（`deduct_quota`）：

```
fn deduct(uid, amount, reason, ref_idem?, idem) -> DeductResult:
    idempotency check
    lock_account(uid)
    left = amount; deducted = 0
    if ref_idem: lots = [lot by source_ref = "shop:<caller>:<ref_idem>"]   // 先扣原批次
    lots += 其他有效批次 ORDER BY expires_at ASC NULLS LAST            // FIFO
    for lot in lots FOR UPDATE while left > 0:
        d = min(lot.remaining, left); UPDATE remaining -= d; ledger(uid, lot, -d, reason, ref); left -= d; deducted += d
    return {deducted, shortfall: amount - deducted, balance}            // 不产生负余额，由调用方决定补偿
```

**到期落账**（cron `expire_lots`）：

```
loop:
    rows = SELECT id, user_id, remaining FROM quota_lots
           WHERE remaining > 0 AND expires_at <= now() ORDER BY expires_at LIMIT 500 FOR UPDATE SKIP LOCKED
    if empty: break
    for r: UPDATE quota_lots SET remaining = 0 WHERE id = r.id; ledger(r.user_id, r.id, -r.remaining, "lot_expired", "lot:<id>")
    sql.commit()
```

查询余额时已按时间过滤，因此 cron 延迟只影响流水落账时间，不影响可用额度（FR-INV-013）。

**晋升赠送**（订阅 `level.promoted`）：

```
fn on_level_promoted(evt): p = {user_id, from_class, to_class}
    rule = settings.class_grants.find(class_id = to_class)?.on_promotion; if None: return

```

**周期发放**（cron `periodic_grants`，`tx = manual`）：

```
period = match settings.periodic_schedule { monthly => if day(today)==1 {"YYYY-MM"} , weekly => if weekday==Mon {"YYYY-Www"} }
if period is None: return                         // 非边界日
rules = class_grants.filter(periodic is Some); classes = rules.class_ids
cursor = kv.get("periodic:<period>:cursor") ?? 0
loop:
    users = SELECT id, class_id FROM identity.v_user_public
            WHERE status = 'active' AND class_id = ANY($classes) AND id > $cursor ORDER BY id LIMIT 1000
    if empty: kv.set("periodic:<period>:done", now); break
    balances = 批量余额（同 §余额 SQL，GROUP BY user_id，WHERE user_id = ANY($ids)）
    for u: g = rule[u.class].periodic; amt = min(g.amount, g.max_balance - balances[u])；amt > 0 时
          INSERT quota_lots … ON CONFLICT (source, source_ref, user_id) DO NOTHING（source_ref = "periodic:<period>:<class>"）
          插入成功才写流水与事件
    kv.set(cursor_key, last_id); sql.commit()
```

- 同一周期重复触发（手动运行、补跑）因自然键去重不会重复发放；`done` 标记存在时直接返回。
- 50 万用户 / 1000 每批 = 500 批，每批 ≤ 2 s（NFR-INV-004）；超时（`timeout_secs = 1800`）后下次触发从游标续跑。

**批量发放**（`POST /admin/quota-grants` → `batch_jobs` + 延迟任务链）：


### 1.6 tree：边与闭包表

```
fn add_edge(invitee, inviter, invite_id, registered_at):
    INSERT INTO tree_edges(invitee_id, inviter_id, invite_id, invitee_registered_at)
         VALUES ($1,$2,$3,$4) ON CONFLICT (invitee_id) DO NOTHING
    if 0 rows: return                                        // 已存在（回放）
    INSERT INTO tree_closure(ancestor_id, descendant_id, depth) VALUES ($inviter, $inviter, 0) ON CONFLICT DO NOTHING
    INSERT INTO tree_closure(ancestor_id, descendant_id, depth) VALUES ($invitee, $invitee, 0) ON CONFLICT DO NOTHING
    INSERT INTO tree_closure(ancestor_id, descendant_id, depth)
         SELECT ancestor_id, $invitee, depth + 1 FROM tree_closure WHERE descendant_id = $inviter
    ON CONFLICT DO NOTHING
```

被邀请人是新注册用户，不可能已有后代，所以只需复制邀请人的祖先行。

**下游子树分页**（`tree(user, depth, cursor, limit)`）：

```sql
SELECT c.depth, c.descendant_id, e.inviter_id, e.invitee_registered_at,
       u.username, u.class_id, u.status,
       (SELECT count(*) FROM tree_edges e2 WHERE e2.inviter_id = c.descendant_id) AS direct_count
FROM tree_closure c
JOIN tree_edges e ON e.invitee_id = c.descendant_id
LEFT JOIN identity.v_user_public u ON u.id = c.descendant_id
WHERE c.ancestor_id = $1 AND c.depth BETWEEN 1 AND $2
  AND (c.depth, c.descendant_id) > ($3, $4)          -- 游标
ORDER BY c.depth, c.descendant_id
LIMIT $5;
```

- 主键 `(ancestor_id, depth, descendant_id)` 使上式为索引范围扫描（NFR-INV-003）。
- 总数：`SELECT depth, count(*) FROM tree_closure WHERE ancestor_id=$1 AND depth BETWEEN 1 AND $2 GROUP BY depth`（树页头部各层计数）。
- `show_invitee_stats` 时另行 `SELECT … FROM accounting.v_user_totals WHERE user_id = ANY($ids)`（本页 ≤ 100 个）。
- 已清除（purge）的被邀请人：`username` 返回空，`purged = true`。

**上游链**：`SELECT ancestor_id, depth FROM tree_closure WHERE descendant_id=$1 AND depth BETWEEN 1 AND $2 ORDER BY depth`。

**整树操作**（`POST /admin/users/{id}/tree-actions`，`batch_jobs.kind = tree_action`）：

| action | 每个节点执行 |
|---|---|
| `suspend_invite` | INSERT suspensions(source = 'tree_action', ref = job_id, until)（同 ref 去重） |
| `revoke_outstanding` | 撤销其全部 active 邀请（reason = tree_action，不返还） |
| `add_note` | INSERT user_notes |

参数 `depth`（1～10，默认全部 ≤ 10）、`include_root`。按 `(depth, descendant_id)` 游标每步 500 个节点，延迟任务链执行，进度可查；全部操作写审计 `invite.tree_action`（只写一条汇总 + 节点数，不逐个写）。

```json
                               {"type": "suspend_invite", "days": 30},
                               {"type": "notify"} ] },
    { "depth": 2, "actions": [ {"type": "flag_review"} ] }
  ],
  "reverse_on_lift": true
}
```

- `trigger`：`invitee_banned`（`user.status_changed.to = banned`）或 `invitee_cheating`（`anticheat.case_resolved.action ∈ cheating_actions`）。
- `actions[].type`：`deduct_quota{amount}`、`suspend_invite{days?}`（无 days = 直到撤销）、`revoke_outstanding`、`notify`、`flag_review`、`restrict_inviter{days}`（需站点授予 `ctx.users` 作用域 `write:status`，默认规则中不出现）。
- `flag_review` 与其他动作同时出现时：其他动作**延后到复核确认后**才执行（`state = pending_review`）；单独出现时只产生复核记录。

**执行**：

```
fn on_trigger(event_id, trigger, invitee, occurred_at, source):
    if trigger == invitee_banned and source == "invite": return       // 不由自己的限制引发连锁
    edge = SELECT … FROM tree_edges WHERE invitee_id = $invitee; if None: return
    for r in rules where r.enabled and r.trigger == trigger:
        if edge.invitee_registered_at + r.within_days < occurred_at: continue
        for (depth, target) in ancestors(invitee, r.max_depth):
            lv = r.levels.find(depth); if None: continue
            if exists(penalties WHERE invitee_id=$invitee AND target_user_id=$target AND rule_group=r.group
                      AND state IN ('applied','pending_review','confirmed') AND created_at > now - dedupe_window_days): continue
            exempt = rbac.check(target, "invite.penalty.exempt")
            state = exempt ? 'exempt' : (lv has flag_review ? 'pending_review' : 'applied')
            pid = INSERT penalties(rule_id, rule_group, trigger, trigger_event_id = event_id, invitee_id, target_user_id = target,
                                   depth, actions = lv.actions, state) ON CONFLICT (trigger_event_id, rule_id, target_user_id) DO NOTHING
            if pid is None: continue                                      // 重复
            if state == 'applied': execute(pid, event_id)
            publish invite.penalty_applied{penalty_id: pid, rule_id, trigger, invitee_id, target_user_id, depth, actions: types, state}

fn execute(pid, event_id):
    p = penalties[pid]; applied = {}
    lock_account(p.target)
    for a in p.actions:
        match a.type:
            deduct_quota    => applied.deducted = deduct(p.target, a.amount, "penalty", None, idem = "pen:<pid>").deducted
            suspend_invite  => applied.suspension_id = INSERT suspensions(user_id, source='penalty', ref=pid, until = a.days.map(now+d))
            revoke_outstanding => applied.revoked = revoke_all_active(p.target, reason='penalty', refund=false)
            notify          => jobs.schedule_once("penalty_notify", now, {penalty_id: pid}, dedupe = "pn:<pid>")
            restrict_inviter=> applied.restriction_id = ctx.users.apply_restriction★{user: p.target, kind: leech_disabled,
                                    reason_code: "invite.penalty", until: now + a.days, idempotency_key: "<event_id>:<pid>:restrict"}
                               // 未合入时：ctx.users.set_status(target, leech_disabled, "invite.penalty") + schedule_once("penalty_unrestrict", until, {pid})
            flag_review     => （无动作）
    UPDATE penalties SET applied = $applied, state = 'applied', updated_at = now() WHERE id = $pid
```

- `ancestors` 使用闭包表；`apply_restriction` 返回 `identity.target_protected`（目标为员工）时记入 `applied.errors[]`，不使整个事件失败。
- 服务调用失败且 `retryable = true` → 返回错误，整个事件回滚重试（`ctx.users` 调用带幂等键，重复安全）；不可重试错误 → 记入 `applied.errors[]` 继续。

**撤销**（订阅 `user.status_changed{from: banned, to ∉ {banned, deleted}}`、复核撤销、管理员撤销）：

```
fn reverse(pid, reason, event_id?):
    p = SELECT … FOR UPDATE; if p.state ∉ {applied, confirmed, pending_review}: return
    if p.state != pending_review:
        if p.applied.deducted > 0: grant(p.target, p.applied.deducted, "penalty_refund", source_ref = "pen:<pid>", None, "penalty_refund")
        if p.applied.suspension_id: UPDATE suspensions SET lifted_at = now(), lifted_reason = reason WHERE id = $sid AND lifted_at IS NULL
        if p.applied.restriction_id: ctx.users.lift_restriction★(p.target, leech_disabled, "invite.penalty_reversed", idem = "<pid>:lift")
        // 已撤销的邀请不恢复（文档化）
    UPDATE penalties SET state = 'reversed', reversed_at = now(), reverse_reason = reason
    publish invite.penalty_reversed{penalty_id, target_user_id, reason}
```

`user.status_changed` 恢复时只撤销该被邀请人触发、规则 `reverse_on_lift = true` 的处置。

**复核**（`POST /admin/penalties/{id}/reviews {decision: confirm|reverse, note}`，权限 `invite.penalties.moderate`★）：`confirm` → 执行延后的动作（`execute`），`state = confirmed`；`reverse` → `reverse(pid, "review")`。乐观锁：请求带 `version`。

**连坐通知**（延迟任务 `penalty_notify`）：读 penalty → `ctx.notify.send(target, "invite.penalty_applied", {invitee_username, rule_id, actions, until?})` → `UPDATE penalties SET notified_at = now() WHERE id=$1 AND notified_at IS NULL`；已有 `notified_at` 直接返回。

### 1.8 lifecycle：撤销、过期、预留释放、用户删除

```
fn revoke(invite_id, by, reason, refund_opt, idem?):
    inv = SELECT … FOR UPDATE
    if inv.status != active: return inv.use_count > 0 ? Err(invite.already_redeemed) : Ok(false)   // 幂等：已撤销/过期返回 false
    if by is user (非管理员) and exists active reservation (reserved_until > now): Err(invite.invite_reserved)
    UPDATE invites SET status='revoked', revoked_at, revoked_by, revoke_reason
    refund = refund_opt ?? settings.refund_on_revoke
    if refund and inv.lot_id and inv.kind == personal: refund_to_lot(inv)    // 原批次未过期才返还（DD-INV-11）
    publish invite.revoked{invite_id, inviter_id, reason, refunded, by_user_id}
fn refund_to_lot(inv):
    n = UPDATE quota_lots SET remaining = remaining + 1 WHERE id = inv.lot_id AND remaining < amount
        AND (expires_at IS NULL OR expires_at > now())
    if n == 1: ledger(inv.inviter_id, inv.lot_id, +1, reason, "invite:<id>"); UPDATE invites SET refunded = true
```

- 多次使用的码（活动码、`max_uses > 1` 的系统码）部分兑换后撤销：只停止后续兑换，不返还。
- cron `expire_invites`：见 HLD §5.5；返还逻辑同 `refund_to_lot`（`refund_on_expire`）。
- cron `release_reservations`：`UPDATE reservations SET state='released' WHERE state='active' AND reserved_until < now() - interval '1 minute'`，每批 1000 行（ctid 子查询）后提交。

**用户删除**（订阅 `user.deleted`）：

| mode | 动作 |
|---|---|
| `soft` | 撤销其 active 邀请（reason = user_deleted，不返还）；解除其进行中的复核（不改变已执行动作） |
| `purge` | 上述 + `DELETE quota_ledger / quota_lots / accounts / suspensions / user_notes WHERE user_id`；`UPDATE invites SET note = NULL, email_hmac = NULL, email_domain = NULL, username_binding = NULL WHERE inviter_id = $uid`；`UPDATE reservations SET holder = 'purged:' || id WHERE user_id = $uid`；`UPDATE tree_edges SET purged = true WHERE invitee_id = $uid`（边与闭包保留 ID，维持树结构）；`penalties` 保留 ID 与动作，`applied.errors` 中的文字清空 |

### 1.9 stats：统计与问题邀请人

**用户统计**（`stats(user)`、`GET /users/me/stats`）：

**日汇总**（cron `daily_stats`，统计站点时区昨日 `D`，`INSERT … ON CONFLICT (day, metric) DO UPDATE SET value = EXCLUDED.value`，重复执行结果相同）：`issued`、`issued_system`、`redeemed`、`expired`、`revoked`、`quota_granted`、`quota_consumed`、`quota_expired`、`penalties`、`over_redeemed`。

**问题邀请人评分**（同一 cron，第二阶段，分批 1000 个邀请人）：对近 `score_window_days`（180）内兑换数 ≥ `score_min_redeemed`（3）的邀请人：
`early_ban_rate = 被邀请人中“注册后 30 天内被封禁”的人数 / 兑换数`（“30 天内封禁”= 当前状态 banned 且 `penalties` 或封禁触发记录中的触发时间 − 注册时间 ≤ 30 天；为避免依赖事件历史，本插件在 `on_user_status_changed` 中对 `to = banned` 的被邀请人写 `invitee_bans(invitee_id, banned_at)` 小表）。
`flagged = early_ban_rate ≥ score_flag_threshold（0.3）`；写 `inviter_scores`（覆盖）。后台排行按 `early_ban_rate DESC, redeemed DESC`。

### 2.3 钩子

#### 处理 `user.before_register`

- 清单：`[[hooks]] hook = "user.before_register"`, `priority = 10`, `timeout_ms = 200`。
- 读取：`username`、`invite_code?`、`email_domain`、`email?`（仅在内核裁剪合入且授权时）、`attributes.registration_mode`。
- 返回：`allow`；`deny(invite.code_invalid | invite.code_reserved | invite.binding_invalid)`，`details` 见 §1.3；`modify {"attributes": {"inviter_id": <u64>}}`。
- 不修改 `registration_mode`（identity 在 `invite_code` 非空时已推导为 `invite`）、`tags`（避免与其他处理者的数组覆盖冲突）。
- 失败（超时 / trap）由 identity 管线按 deny（锁定）处理 → `503 kernel.hook_failed`。

#### 拥有 `invite.before_issue`

```sql
CREATE TABLE accounts (
    user_id        bigint PRIMARY KEY,
    promo_classes  integer[] NOT NULL DEFAULT '{}',
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE quota_lots (

CREATE TABLE quota_ledger (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id        bigint NOT NULL,

    reason         text NOT NULL CHECK (char_length(reason) <= 64),
    ref            text CHECK (char_length(ref) <= 200),
    balance_after  integer NOT NULL CHECK (balance_after >= 0),
    actor_id       bigint,
    note           text CHECK (char_length(note) <= 500),
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX quota_ledger_user_idx ON quota_ledger (user_id, id DESC);
CREATE INDEX quota_ledger_created_idx ON quota_ledger (created_at);

CREATE TABLE invites (
    id                bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    kind              text NOT NULL CHECK (kind IN ('personal','system','campaign')),
    source            text NOT NULL CHECK (source IN ('user','admin','interview','application','api','campaign')),
    code_hash         bytea NOT NULL CHECK (octet_length(code_hash) = 32),
    code_hint         text NOT NULL CHECK (char_length(code_hint) = 4),
    issue_key_hash    bytea NOT NULL CHECK (octet_length(issue_key_hash) = 32),
    inviter_id        bigint,
    issued_by         bigint,
    issued_by_plugin  text,
    status            text NOT NULL DEFAULT 'active' CHECK (status IN ('active','exhausted','revoked','expired')),
    max_uses          integer NOT NULL DEFAULT 1 CHECK (max_uses BETWEEN 1 AND 100000),
    use_count         integer NOT NULL DEFAULT 0 CHECK (use_count >= 0),
    expires_at        timestamptz NOT NULL,
    email_hmac        bytea CHECK (email_hmac IS NULL OR octet_length(email_hmac) = 32),
    email_domain      text CHECK (char_length(email_domain) <= 253),
    username_binding  text CHECK (char_length(username_binding) <= 64),
    note              text CHECK (char_length(note) <= 200),
    lot_id            bigint REFERENCES quota_lots (id) ON DELETE SET NULL,
    refunded          boolean NOT NULL DEFAULT false,
    revoked_at        timestamptz,
    revoked_by        bigint,
    revoke_reason     text CHECK (revoke_reason IN ('user','admin','expired','user_deleted','tree_action','penalty','service')),
    created_at        timestamptz NOT NULL DEFAULT now(),
    updated_at        timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT invites_personal_check CHECK (kind <> 'personal' OR (inviter_id IS NOT NULL AND max_uses = 1))

CREATE UNIQUE INDEX invites_code_hash_key ON invites (code_hash);
CREATE UNIQUE INDEX invites_issue_key_hash_key ON invites (issue_key_hash);
CREATE INDEX invites_inviter_idx ON invites (inviter_id, created_at DESC) WHERE inviter_id IS NOT NULL;
CREATE INDEX invites_inviter_active_idx ON invites (inviter_id) WHERE status = 'active';
CREATE INDEX invites_expiring_idx ON invites (expires_at) WHERE status = 'active';
CREATE INDEX invites_admin_list_idx ON invites (created_at DESC, id DESC);

CREATE TABLE reservations (
    id              bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    invite_id       bigint NOT NULL REFERENCES invites (id) ON DELETE CASCADE,
    holder          text NOT NULL CHECK (char_length(holder) <= 80),
    state           text NOT NULL DEFAULT 'active' CHECK (state IN ('active','consumed','released')),
    reserved_until  timestamptz NOT NULL,
    user_id         bigint,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX reservations_active_key ON reservations (invite_id, holder) WHERE state = 'active';
CREATE INDEX reservations_invite_idx ON reservations (invite_id, state, reserved_until);

CREATE TABLE redemptions (

    event_id       uuid NOT NULL,
    over_redeemed  boolean NOT NULL DEFAULT false,
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX redemptions_invitee_key ON redemptions (invitee_id);
CREATE INDEX redemptions_invite_idx ON redemptions (invite_id);
CREATE INDEX redemptions_inviter_idx ON redemptions (inviter_id, created_at DESC);

CREATE TABLE tree_edges (
    invitee_id             bigint PRIMARY KEY,
    inviter_id             bigint NOT NULL,
    invite_id              bigint REFERENCES invites (id) ON DELETE SET NULL,
    invitee_registered_at  timestamptz NOT NULL,
    purged                 boolean NOT NULL DEFAULT false,

    source         text NOT NULL CHECK (source IN ('penalty','admin','tree_action')),
    ref            text NOT NULL CHECK (char_length(ref) <= 100),
    reason         text CHECK (char_length(reason) <= 500),
    until          timestamptz,
    created_by     bigint,
    created_at     timestamptz NOT NULL DEFAULT now(),
    lifted_at      timestamptz,
    lifted_by      bigint,
    lifted_reason  text CHECK (char_length(lifted_reason) <= 200)
);
CREATE UNIQUE INDEX suspensions_ref_key ON suspensions (user_id, source, ref);
CREATE INDEX suspensions_active_idx ON suspensions (user_id) WHERE lifted_at IS NULL;

CREATE TABLE penalties (
    id                bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    rule_id           text NOT NULL CHECK (char_length(rule_id) <= 64),
    rule_group        text NOT NULL CHECK (char_length(rule_group) <= 64),
    trigger           text NOT NULL CHECK (trigger IN ('invitee_banned','invitee_cheating')),
    trigger_event_id  uuid NOT NULL,
    invitee_id        bigint NOT NULL,
    target_user_id    bigint NOT NULL,
    depth             smallint NOT NULL CHECK (depth BETWEEN 1 AND 10),
    actions           jsonb NOT NULL,
    applied           jsonb NOT NULL DEFAULT '{}',
    state             text NOT NULL CHECK (state IN ('applied','pending_review','confirmed','reversed','exempt')),
    notified_at       timestamptz,
    reviewed_by       bigint,
    reviewed_at       timestamptz,
    review_note       text CHECK (char_length(review_note) <= 1000),
    reversed_at       timestamptz,
    reverse_reason    text CHECK (reverse_reason IN ('invitee_restored','review','admin')),
    version           integer NOT NULL DEFAULT 1,
    created_at        timestamptz NOT NULL DEFAULT now(),
    updated_at        timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX penalties_trigger_key ON penalties (trigger_event_id, rule_id, target_user_id);

CREATE INDEX penalties_target_idx ON penalties (target_user_id, created_at DESC);
CREATE INDEX penalties_review_idx ON penalties (created_at) WHERE state = 'pending_review';

CREATE TABLE invitee_bans (
    invitee_id  bigint NOT NULL,
    banned_at   timestamptz NOT NULL,
    event_id    uuid NOT NULL,
    PRIMARY KEY (invitee_id, banned_at)
);

CREATE TABLE user_notes (
    id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
```

**数据量估算**（50 万用户、3 年）：invites ≈ 150 万行（≈ 300 MB 含索引）；quota_lots ≈ 600 万（周期发放每月每活跃高等级用户一行）；quota_ledger ≈ 1500 万（≈ 2 GB）——超过阈值时在 0002 迁移中改为按月分区（`[[database.partitions]] table = "quota_ledger", by = "range_month", retention_months = 36`，主键改为 `(id, created_at)`）；tree_edges ≈ 50 万；tree_closure ≈ 500 万（平均深度 10，≈ 400 MB）；penalties ≪ 10 万。idempotency 保留 30 天（`reconcile` cron 清理）。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 码 | 128 位（HMAC 派生）；只存 SHA-256；明文仅在签发响应（`no-store`）中出现；日志 / 事件 / 审计 / MCP 只出现码尾；码在请求体而非 URL 中校验（注册链接中的 `?invite=` 由前端读取后放入请求体，页面设置 `Referrer-Policy` 由内核统一下发） |
| 枚举 | 公开校验 `ip:10/m`；格式非法也执行一次索引查找；对外不区分 `inviter_unavailable`；钩子拒绝计数指标按 reason 告警 |
| 越权 | 本人接口按 `actor.user_id` 过滤（`DELETE /users/me/invites/{id}` 校验 `inviter_id`）；他人树需 `invite.tree.read`；服务写方法检查 `caller-scopes`；`revoke` 服务只能撤销本调用方签发的邀请（`issued_by_plugin`） |
| 邮箱 | 只存 HMAC（独立子密钥）+ 域名；`user.email` 为 optional 敏感能力，仅用于钩子内比对，不落库、不入日志 |
| 审计 | `invite.quota_adjust`（前后余额、原因）、`invite.issue_system`、`invite.revoke_admin`、`invite.tree_action`、`invite.penalty_review`、`invite.suspension_add/lift`；details 不含码与邮箱 |
| 输入校验 | 所有字符串长度限制、NFC、拒绝控制字符；`note` 为纯文本（前端不渲染 HTML）；`expires_days`、`amount`、`depth` 范围校验 |
| 防倒卖 | 未用上限、每日上限、注册天数门槛、邮箱 / 用户名绑定、连坐、问题邀请人排行；绑定邮箱的码在注册页提示“只有该邮箱可以使用” |

## 7. 性能设计

| 路径 | 设计 | 估算 |
|---|---|---|
| 注册钩子 | 1 次按唯一索引查邀请（JOIN 视图主键）+ 1 次预留计数（`reservations_invite_idx`）+ 1 次 UPSERT；行锁只锁该邀请 | p99 ≤ 30 ms；不同码完全并行，同一码串行 |
| 确认 | 同上 + 闭包表插入（≤ 祖先数行） | 每事件 < 10 ms |
| 发邀 | `lock_account` + 余额查询 + 计数（部分索引）+ 钩子 | p99 ≤ 80 ms（含 `invite.before_issue` 处理者） |
| 树查询 | 闭包表主键范围扫描 + 视图主键 JOIN | 10 万子树、深度 3、每页 100：≈ 20 ms |
| 周期发放 | 视图按 id 键集分批 1000 + 批量余额查询 + `execute_batch` 插入 | 500 批 × ≤ 1 s |
| 日汇总 | 按 `created_at` 索引范围聚合；评分按邀请人分批 | < 2 min |

WASM 实例：`max_concurrency = 64`（注册高峰钩子并发）；实例内存 64 MiB。
