## 1. 模块详细设计

### 1.1 expr：安全表达式语言

#### 1.1.1 语法（EBNF）

```
expr      = ternary ;
ternary   = or_expr [ "?" expr ":" expr ] ;
or_expr   = and_expr { ("or" | "||") and_expr } ;
and_expr  = not_expr { ("and" | "&&") not_expr } ;
not_expr  = ("not" | "!") not_expr | cmp ;
cmp       = add [ ("==" | "!=" | "<" | "<=" | ">" | ">=") add ] ;      (* 不允许链式比较 *)
add       = mul { ("+" | "-") mul } ;
mul       = unary { ("*" | "/" | "%") unary } ;
unary     = "-" unary | power ;
power     = primary [ "^" unary ] ;                                     (* 右结合 *)
primary   = number | ident | call | "(" expr ")" ;
call      = ident "(" [ arg { "," arg } ] ")" ;
arg       = expr | string ;                                             (* 字符串只能作为特定函数的字面量参数 *)
number    = digit { digit } [ "." digit { digit } ] [ ("e"|"E") ["+"|"-"] digit { digit } ] ;
string    = '"' { 字母 | 数字 | "_" | "-" | ":" | "." } '"' ;           (* ≤ 64 字符 *)
ident     = 字母 { 字母 | 数字 | "_" } ;                                 (* ASCII，≤ 32 字符 *)
```

- 只有一种值类型 `f64`；布尔以 1.0 / 0.0 表示（比较、逻辑运算结果为 0 或 1；条件判断 `≠ 0` 为真）。
- 无赋值、无循环、无用户函数、无字符串运算、无属性访问。
- 词法拒绝：非 ASCII（字符串字面量除外仍限 ASCII）、控制字符、`;`、反引号。

#### 1.1.2 运算语义

| 运算 | 语义 |
|---|---|
| `a / b`、`a % b` | `b == 0` 时结果为 0（不产生 ∞/NaN）；`%` 为截断取余 |
| `a ^ b` | `pow(a, b)`；`|b| > 64` 时求值错误 |
| 任意运算产生 NaN 或 ±∞ | 该表达式本次求值结果视为 0，计数 `expr_nonfinite_total{expr}`，用户小时记录 `flags.nonfinite = true` |
| `and`/`or` | 短路求值 |
| `c ? a : b`、`if(c, a, b)` | 只求值被选中的分支 |

#### 1.1.3 函数白名单

| 函数 | 说明 |
|---|---|
| `min(a, b, …)`、`max(a, b, …)` | 2～16 个参数 |
| `clamp(x, lo, hi)` | |
| `abs`、`floor`、`ceil`、`round`（四舍五入，远离零）、`trunc` | |
| `sqrt`（负数 → 0）、`ln`、`log10`、`log2`（≤ 0 → 0）、`exp`（参数 > 700 → 错误）、`pow(a, b)`、`atan`、`tanh` | 实现使用纯 Rust `libm` crate（MIT），保证确定性 |
| `if(c, a, b)` | 同三元 |
| `safe_div(a, b, d)` | `b == 0` 时返回 `d` |
| `between(x, lo, hi)` | `lo ≤ x < hi` → 1 |
| `tag("<tag>")` | 种子级：种子是否有该标签（`torrent.tags_changed` 镜像） |
| `type("<type_id>")` | 种子级：资源类型是否为该值 |
| `has_role("<role>")` | 用户级：用户是否有该角色（`ctx.rbac.roles_of`，按需获取） |

常量：`pi`、`e`、`KiB`=1024、`MiB`、`GiB`、`TiB`、`HOUR`=3600、`DAY`=86400、`WEEK`=604800、`YEAR`=31536000。规则集 `params` 中定义的参数（`^[A-Z][A-Z0-9_]{0,31}$`）可作为标识符使用。

#### 1.1.4 变量

**种子级**（在 `torrent_terms` 中可用）：

| 变量 | 来源 | 易变 |
|---|---|---|
| `size` | 快照 `torrents[].size`；为 0 时取 `torrent_facts.size` | 否 |
| `gib` | `size / GiB` | 否 |
| `seed_secs` | 快照，`0..3600` | 否 |
| `seed_hours` | `seed_secs / 3600` | 否 |
| `seeders` | 快照 `seeders`（快照时刻） | 否 |
| `age_secs`、`age_days`、`age_weeks` | `period_start − torrent_facts.created_at`（≥ 0） | 否 |
| `is_uploader` | `torrent_facts.uploader_id == user_id` | 否 |
| `leechers`、`completed` | `torrent_facts`（来自 `traffic.swarm_stats_updated` 的最新值） | **是** |
| `snatch_seed_secs` | `accounting.v_snatch.seed_secs`（该用户该种子累计） | **是** |
| `tag(...)`、`type(...)` | 镜像 | 否（标签变化视为易变，见 DD-BONUS-11 说明） |

**用户级**（在 `user_formulas` 中可用）：

| 变量 | 说明 | 获取 |
|---|---|---|
| `<项名>` | 种子级项按用户求和 | 计算 |
| `count` | 计入的种子数（`seed_secs > 0` 且通过过滤） | 计算 |
| `total_gib` | 计入种子体积之和 / GiB | 计算 |
| `seed_hours_total` | Σ seed_hours | 计算 |
| `class_id` | `ctx.users.get` | 总是获取（同时用于资格判断） |
| `has_role("…")` | `ctx.rbac.roles_of` | 仅当引用时 |
| `medal_factor` | `ctx.medals.bonus_factor(u) / 1000`（返回 ‰，评审 R1 已合入；服务缺失时为 0） | 仅当引用时（易变） |
| `invitee_seed_points` | 被邀请人上一小时 `seed_points` 之和（P2，本插件 `user_hours` 汇总 + `ctx.invites.tree(depth=1)`） | 仅当引用时（易变） |

静态分析在编译时为每个表达式计算 `deps = {torrent_vars, user_vars, volatile: bool, needs_snatch: bool, needs_roles: bool, needs_medals: bool}`，求值时只获取需要的数据。

#### 1.1.5 编译与求值

```
compile(src, scope: Torrent|User, params, term_names) -> Result<Compiled, Vec<ExprIssue>>:
    require len(src) ≤ 4000                                         ?: bonus.expression_too_complex
    tokens = lex(src)                                               ?: bonus.expression_syntax(pos)
    ast = pratt_parse(tokens, max_depth=32)                         ?: syntax / too_complex
    require node_count(ast) ≤ 512
    resolve identifiers：变量（按 scope）、params、常量、term_names（仅 User）  ?: bonus.expression_unknown_identifier(name, pos)
    resolve calls：函数白名单、参数个数、字符串参数位置与格式               ?: bonus.expression_unknown_function / bad_arguments
    constant folding（只折叠纯常量子树）
    deps = analyze(ast)
    return Compiled{ast（扁平数组 + 下标引用，无递归求值栈溢出风险）, deps}

eval(c: &Compiled, env) -> f64:
    栈式解释（显式栈，容量 = 节点数），每节点 O(1)；函数调用查表
    结果非有限 → 0（并置 nonfinite 标志）
```

规则集编译结果（全部表达式 + 依赖并集）序列化为 `bincode` 存 kv `rules:compiled:<version>`；每次调用按需反序列化（约 10～50 µs），同一调用内复用。

### 1.2 rules：规则集与版本

**规则集定义 JSON**（`rule_sets.draft`、`rule_versions.definition`）：

```json
{
  "mode": "expression",
  "params": { "T0": 4, "N0": 7, "B0": 100, "L": 300, "P": 1, "MAX": 7, "DONOR": 2, "OFFICIAL": 0.5, "ZERO_FACTOR": 0 },
  "filters": { "min_size": 0, "min_seed_secs": 60 },
  "torrent_terms": [
    { "name": "A",  "expr": "(1 - exp(ln(0.1) / T0 * age_weeks)) * if(tag(\"zero_bonus\"), gib * ZERO_FACTOR, gib) * (1 + sqrt(2) * exp(ln(0.1) * (seeders - 1) / (N0 - 1)))" },
    { "name": "AW", "expr": "A_i * seed_hours" },
    { "name": "OA", "expr": "if(tag(\"official\"), A_i, 0)" }
  ],
  "user_formulas": {
    "seed_points": "(B0 * 2 / pi * atan(A / L) + P * min(count, MAX)) * safe_div(AW, A, 0)",
    "bonus": "((B0 * 2 / pi * atan(A / L) + P * min(count, MAX)) * if(has_role(\"levels:vip\"), DONOR, 1) + B0 * 2 / pi * atan(OA / L) * OFFICIAL) * safe_div(AW, A, 0)"
  },
  "caps": { "bonus": 100000, "seed_points": 100000 },
  "tiers": null
}
```

- 种子级项内可引用**前面**已定义项的本种子值，写作 `<名>_i`（如 `A_i`）；用户级引用项名得到用户总和。
- `user_formulas` 的键必须是本插件币种；值为显示单位（如魔力值 12.5 点）；求值后 `floor(v × 10^scale)`，再 `clamp(0, caps[c])`（`caps` 为最小单位）。
- 上例即 NexusPHP 形状，乘以 `safe_div(AW, A, 0)`（“按做种时长覆盖率折算”）：用户整小时做种全部种子时与 NexusPHP 一致，部分时间做种时按 A 加权折算（改进点：NexusPHP 按 cleanup 时刻的瞬时 peers 计算）。

**分档模式**（`mode = "tiers"`，UNIT3D 风格）：

```json
{
  "mode": "tiers",
  "params": {},
  "tiers": [
    { "key": "dying",      "when": "seeders == 1 and completed >= 3",       "op": "add", "value": "2" },
    { "key": "legendary",  "when": "age_days >= 365",                        "op": "add", "value": "1.5" },
    { "key": "old",        "when": "between(age_days, 182, 365)",            "op": "add", "value": "1" },
    { "key": "huge",       "when": "size >= 100 * GiB",                      "op": "add", "value": "0.75" },
    { "key": "large",      "when": "between(size, 25 * GiB, 100 * GiB)",     "op": "add", "value": "0.5" },
    { "key": "everyday",   "when": "between(size, 1 * GiB, 25 * GiB)",       "op": "add", "value": "0.25" },
    { "key": "legend",     "when": "snatch_seed_secs >= YEAR",               "op": "add", "value": "2" },
    { "key": "internal",   "when": "tag(\"official\")",                       "op": "multiply", "value": "1.5" }
  ],
  "tier_output": { "bonus": 1.0, "seed_points": 1.0 }
}
```

编译：`T_i = (((0 + if(w1, v1, 0)) + if(w2, v2, 0)) … ) * if(wk, vk, 1) …` 按列表顺序；再 `TW_i = T_i * seed_hours`；用户级公式 `c: TW * tier_output[c]`。编译后的表达式在编辑器中只读展示。分档名称术语键 `bonus.tier.<rule_set_id>.<key>`，保存时以 `ctx.terms.define` 定义（默认值取编辑器中填写的各语言名称，幂等键 `ruleset:<id>:rev:<draft_rev>`）。

**预设**：`nexusphp`（上例）、`unit3d_tiers`（上例）、`gazelle_like`（`A_i = gib_capped * (0.0433 + 0.0233 * ... )`，以 `type()` 系数缩放；文档中给出参数，不复制源码）、`flat`（`bonus: count * 1`）。迁移 `0002` 插入预设为规则集草案；首次 `init` 若 `rule_versions` 为空，则发布 `nexusphp` 为 v1，`effective_from = 1970-01-01`。

**发布**：

```
publish(rule_set_id, effective_from?, note, key):
    rs = SELECT … FOR UPDATE；compile 全部表达式（失败 → 422，issues）
    ef = effective_from ?: next_hour(now)；require ef ≥ next_hour(now) 且 ef 为整点        ?: bonus.effective_time_invalid
    require 不存在 effective_from ≥ ef 的版本（时间线只追加）                             ?: bonus.effective_time_conflict
    v = INSERT rule_versions(rule_set_id, definition = rs.draft, compiled_hash, effective_from = ef, …) RETURNING version
    kv.set("rules:compiled:<v>", bincode(compiled))
    audit.write("bonus.rules_publish", "rule_version:<v>", {rule_set_id, effective_from, diff_summary})
version_at(t): SELECT version FROM rule_versions WHERE effective_from <= t AND NOT revoked ORDER BY effective_from DESC LIMIT 1
```

撤销未生效的版本：`effective_from > now` 时可 `revoked = true`；已生效的版本不可撤销，只能发布新版本并重算。

### 1.3 facts：种子镜像

| 事件 | 处理 |
|---|---|
| `torrent.created` | `INSERT torrent_facts(torrent_id, size, type_id, uploader_id, is_anonymous, created_at_src = envelope.occurred_at, status) ON CONFLICT DO UPDATE`（只覆盖为空的列） |
| `torrent.status_changed` | `UPDATE status`；`to = approved` 且首次 → 行为奖励 `torrent_approved`（§1.5） |
| `torrent.tags_changed` | `DELETE torrent_tags WHERE torrent_id`；`INSERT` 新标签集合 |
| `torrent.deleted` | `is_deleted = true`；行为奖励回收 |
| `traffic.swarm_stats_updated` | 批量 `UPDATE torrent_facts SET leechers, completed, swarm_updated_at FROM (VALUES …)`（≤ 1000 项，只更新已存在的行） |

`facts_backfill`（cron）：`SELECT id, size, type_id, uploader_id, status, created_at FROM torrent.v_torrent_public WHERE id > $last ORDER BY id LIMIT 5000`，upsert；游标存 kv `facts:backfill_cursor`；每轮最多 10 批并 commit。视图中匿名种子 `uploader_id` 为 NULL，此时 `is_uploader` 以 `torrent.created` 镜像中的值为准（事件只在服务端流转，含真实上传者）。

`load_facts(ids)`：`SELECT … FROM torrent_facts WHERE torrent_id = ANY($1)`；缺失 id → `SELECT … FROM torrent.v_torrent_public WHERE id = ANY($missing)` 并 upsert；仍缺失 → 使用快照字段（`created_at` 未知时 `age_secs = 0`，`flags.facts_missing = true`）。

### 1.4 hourly：小时结算

```
on_seeding_snapshot(evt, delivery):                     -- tx auto；内核已写 inbox
    p = parse(evt.payload)                              -- schema v1
    P = p.period_start
    if delivery.replay:
        job = SELECT … FROM recalc_jobs WHERE state IN ('awaiting_replay','replaying') AND P >= from AND P < to
              ORDER BY id DESC LIMIT 1
        if job: return recalc_collect(job, p)            -- §1.7
    if not settings.hourly.enabled:
        INSERT user_hours(…, skipped_reason='paused') ON CONFLICT DO NOTHING; return
    -- 多部分合并
    agg_part = partial_aggregate(p)                      -- 需要规则版本：ver = version_at(P)
    if p.parts > 1:
        INSERT snapshot_parts(user, P, batch_id, part, parts, rule_version, partial) ON CONFLICT DO NOTHING
        n = SELECT count(*) FROM snapshot_parts WHERE user_id=$u AND period_start=$P AND batch_id=$b
        if n < p.parts: return
        agg = merge(SELECT partial FROM snapshot_parts WHERE …)；DELETE snapshot_parts WHERE …
    else: agg = agg_part
    if EXISTS user_hours(P, u): metric(dup_hour); return  -- 防御（理论上不会发生）
    finalize(u, P, ver, agg, source = delivery.replay ? 'replay' : 'live')

partial_aggregate(p, ver):
    c = compiled(ver)
    rows = [t for t in p.torrents if t.seed_secs ≥ c.filters.min_seed_secs]
    facts = load_facts(rows.ids)
    snatch = c.deps.needs_snatch ? SELECT torrent_id, seed_secs FROM accounting.v_snatch
                                     WHERE user_id = $u AND torrent_id = ANY($ids) : {}
    sums = {term: 0.0}；count = 0；total_size = 0；hours = 0
    for t in rows:
        f = facts[t.id]；size = t.size > 0 ? t.size : f.size
        if size < max(settings.min_torrent_size, c.filters.min_size) or f.is_deleted: continue
        env = TorrentEnv{size, seed_secs, seeders, age_secs = max(0, P − f.created_at), …}
        for term in c.torrent_terms（按顺序，前项本种子值写入 env 作为 <名>_i）:
            v = eval(term, env)；env[term.name + "_i"] = v；sums[term.name] += v
        count += 1；total_size += size；hours += seed_secs / 3600
    return Partial{sums, count, total_size, hours, flags}

finalize(u, P, ver, agg, source):
    user = ctx.users.get(u)
    if user is None or user.status ∈ {banned, deleted}: reason = 'user_' + status
    elif user.status == leech_disabled and not settings.pay_leech_disabled: reason = 'leech_disabled'
    elif user.status == pending: reason = 'user_pending'
    env = UserEnv{sums, count, total_gib, seed_hours_total, class_id}
    if c.deps.needs_roles: env.roles = ctx.rbac.roles_of(u)（服务缺失 → 空集）
    if c.deps.needs_medals: env.medal_factor = ctx.medals.bonus_factor(u)（缺失 → 0）
    amounts = {}
    if reason is None:
        for (cur, f) in c.user_formulas:
            v = eval(f, env)；m = floor(v × 10^scale(cur))（v ≤ 0 → 0；超过 2^53 → cap）
            amounts[cur] = min(m, c.caps[cur] ?: +∞)
    INSERT user_hours(period_start=P, user_id=u, rule_version=ver, torrent_count=count, total_size,
                      terms=sums, amounts, skipped_reason=reason, flags, source)
    INSERT accruals(user_id, currency, period_start, amount) SELECT … WHERE amount > 0
    if settings.publish_events and any(amounts > 0):
        events.publish(bonus.hourly_settled v1, key "user:<u>", {user_id, period_start, amount: amounts.bonus ?: 0,
                       currency: "bonus", amounts, rule_version: ver, torrent_count: count,
                       terms: sums, breakdown: {count, total_gib, seed_hours: hours}})
```

**并发与幂等**：订阅 `ordered = true`，同一用户的事件串行；inbox 保证同一事件只处理一次；`user_hours` 主键 `(period_start, user_id)` 再兜底。不同部分属于不同事件（不同 event_id），`snapshot_parts` 主键 `(user_id, period_start, part)` 防止部分重复累加。部分合并所需的规则版本在首个部分时记录，后续部分使用同一版本。

**错误处理**：`ctx.users.get` 失败（retryable）→ 返回 err，内核重试；表达式求值错误（如 `exp` 溢出）→ 该表达式结果 0，记录 `flags.eval_errors`，不阻塞；快照载荷校验失败 → 返回非 retryable 错误进入死信（`bonus.snapshot_invalid`）。

### 1.5 actions：行为奖励

**支持的触发**（`action_rules.trigger`）：

| trigger | 事件 | 受益人 | 对象引用 ref | 可用条件变量 | 回收事件 |
|---|---|---|---|---|---|
| `torrent_approved` | `torrent.status_changed`（`to = approved`） | 上传者（`torrent_facts.uploader_id`，缺失则 `ctx.torrents.get`） | `torrent:<id>` | `size`、`gib`、`type("…")`、`is_anonymous` | `torrent.deleted` |
| `comment_created` | `comment.created` | `author_id` | `comment:<id>` | `target_is("torrent")`（目标类型） | `comment.deleted` |
| `topic_created` | `forum.topic_created` | `author_id` | `forum_topic:<id>` | — | —（主题删除事件未登记） |
| `post_created` | `forum.post_created` | `author_id` | `forum_post:<id>` | — | `forum.post_deleted` |
| `request_filled` | `request.filled` | `filler_id` | `request:<id>` | — | — |
| `subtitle_uploaded` | `subtitle.uploaded` | `uploader_id` | `subtitle:<id>` | — | `subtitle.deleted` |
| `invite_redeemed` | `invite.redeemed` | `inviter_id` | `user:<invitee_id>` | — | — |

条件表达式使用 §1.1 语言，变量集为上表；另有 `today_count`（该用户该规则今日已发次数）。

```
on_action_event(evt, trigger):
    rules = SELECT … FROM action_rules WHERE trigger = $t AND enabled
    for r in rules:
        (uid, ref, vars) = extract(trigger, evt)       -- torrent_approved 需 load_facts
        if uid is None: continue
        if r.condition and eval(r.condition, vars) == 0: continue
        day = local_date(evt.occurred_at, site_timezone)
        ok = INSERT INTO action_daily(user_id, rule_id, day, count, amount) VALUES ($u,$r,$d,1,$a)
             ON CONFLICT (user_id, rule_id, day) DO UPDATE SET count = action_daily.count + 1, amount = action_daily.amount + $a
             WHERE ($cl = 0 OR action_daily.count + 1 <= $cl) AND ($al = 0 OR action_daily.amount + $a <= $al)
             RETURNING 1
        if not ok: metric(action_capped); continue
        ins = INSERT action_awards(rule_id, user_id, ref, event_id, currency, amount, state='pending',
                                   clawback_until = r.clawback ? occurred_at + r.clawback_days : NULL)
              ON CONFLICT (rule_id, ref) DO NOTHING RETURNING id
        if not ins: 回滚本规则的 action_daily 增量（UPDATE … − 1）; continue   -- 同一对象已奖励过（如重复审核通过）
        res = ctx.ledger.transfer({currency, from: None, to: uid, amount, reason: "bonus.action_" + r.code,
                                   memo: "", idempotency_key: "act:" + evt.id + ":" + r.id})
        UPDATE action_awards SET state='awarded', entry_id = res.entry_id
        events.publish(bonus.awarded{award_id, user_id, currency, amount, reason, source: "action", ref})
```

ledger 调用失败（retryable）→ 返回 err，整个事件工作单元回滚（`action_daily`、`action_awards` 一并回滚），内核重投时以相同幂等键调用 ledger，不会重复发放。ledger 非 retryable 错误（如 `ledger.currency_disabled`）→ 记录 `state='failed'` 与错误码并提交（不再重试）。

**回收**：

```
on_delete_event(evt, ref):
    awards = SELECT … FROM action_awards WHERE ref = $ref AND state = 'awarded' AND clawback_until >= evt.occurred_at
    for a in awards:
        r = ctx.ledger.reverse(a.entry_id, "bonus.clawback", "claw:" + evt.id + ":" + a.id, false)
        ok → state='clawed'；ledger.insufficient_balance → state='clawback_pending', next_retry_at = now()+1d
        ledger.already_reversed → state='clawed'（幂等）
retry_clawbacks（cron 每日）：分批 500 条 clawback_pending 且 next_retry_at ≤ now：
    同上（幂等键 "claw:retry:<award_id>"——同一 award 的不同重试复用一个键：ledger 对失败的调用不登记结果，见 ledger LLD §1.4 第 1 步在事务内回滚）
    created_at + clawback.retry_days < now → state='clawback_expired'
```

### 1.6 posting：批量入账

```
post_accruals(job):                                     -- cron "40 * * * *"，tx manual，timeout 3000 s
    -- 0 续跑
    for P in SELECT id FROM postings WHERE state IN ('open','submitting') ORDER BY id: submit(P)
    -- 1 新建
    iv = settings.posting.interval_hours
    cutoff = floor(now_hour − 1h, iv)                   -- 只入账已完整结束的周期；按站点时区对齐
    for cur in currencies:
        if EXISTS postings WHERE currency=cur AND cutoff = $cutoff: continue
        if not EXISTS accruals WHERE currency=cur AND posting_id IS NULL AND period_start < cutoff: continue
        P = INSERT postings(currency, cutoff, state='open') RETURNING id；commit
        loop:                                            -- 分批标记，避免长事务
            n = UPDATE accruals SET posting_id = $P
                WHERE (user_id, currency, period_start) IN (SELECT … WHERE currency=$c AND posting_id IS NULL
                       AND period_start < $cutoff ORDER BY user_id LIMIT 50000)
            commit；until n == 0
        INSERT posting_items(posting_id, user_id, amount, hours)
            SELECT $P, user_id, sum(amount), count(*) FROM accruals WHERE posting_id = $P GROUP BY user_id
        UPDATE postings SET state='submitting', item_count, total_amount；commit
        submit(P)

submit(P):
    loop:
        items = SELECT user_id, amount FROM posting_items WHERE posting_id=$P AND state='pending'
                ORDER BY user_id LIMIT settings.posting.batch_size
        if empty: break
        results = ctx.ledger.transfer_batch([{currency, from_user: None, to_user: i.user_id, amount: i.amount,
                     reason: "bonus.seeding", memo: period_label(P), idempotency_key: "post:" + P + ":" + i.user_id}])
        Err(retryable) → 退避 2 s、5 s、15 s 后重试本批；仍失败 → 退出本次 cron（下次续跑）
        逐笔：ok → state='done', entry_id；err → attempts += 1，attempts ≥ 5 → state='failed', error_code
        commit
    if 无 pending: UPDATE postings SET state = (any failed ? 'done_with_failures' : 'done')；commit
```

- `period_label`：如 `"2026-10-05 08:00–09:00 (Asia/Shanghai)"`；ledger memo ≤ 200 字符。
- 入账批创建后，迟到的用户小时（`period_start < cutoff`）留在 `posting_id IS NULL`，在下一周期的批中入账（`cutoff` 更大，包含它们）。
- `failed` 的条目在后台可“重新提交”（同一幂等键）或“作废”（写审计）。

### 1.7 recalc：回放重算

```
create_recalc(from, to, target_version, currencies, note, key):
    require from < to，均为整点；to − from ≤ 31 天；target_version 存在
    require 无其他 state ∈ (awaiting_replay, replaying, previewed, applying) 的任务与之时间重叠  ?: bonus.recalc_overlap
    INSERT recalc_jobs(state='awaiting_replay', …)；audit

recalc_collect(job, p):                                 -- 回放投递，tx auto
    若 job.state == 'awaiting_replay'：UPDATE state='replaying'
    多部分：与 §1.4 相同，但写入 snapshot_parts 时 batch 维度加 job（列 recalc_job_id），避免与实时合并混淆
    agg = partial_aggregate(p, job.target_version)
    new = compute_amounts(u, agg, job.target_version)  -- 同 finalize，但不写 user_hours/accruals、不发事件
    old = SELECT amounts FROM user_hours WHERE period_start=$P AND user_id=$u（无行 → 全 0）
    for cur in job.currencies:
        UPSERT recalc_items(job_id, user_id, period_start, currency, old_amount, new_amount)

GET /admin/recalcs/{id}：汇总 recalc_items：hours、users、Σold、Σnew、Σ(new−old)>0、Σ(new−old)<0、前 20 个变化最大的用户

apply(job, key)：require state ∈ (replaying, previewed)；UPDATE state='applying'；
    INSERT recalc_user_results(job_id, user_id, currency, delta) SELECT … GROUP BY user_id, currency HAVING sum(new−old) <> 0
    jobs.schedule_once("recalc_apply_step", now, {job_id}, dedupe "recalc:<id>")
recalc_apply_step（延迟任务，tx manual）：
    loop 每 500 个 state='pending'：
        delta > 0 → ledger.transfer({from: None, to: u, amount: delta, reason: "bonus.recalc", key: "recalc:<job>:<u>:<cur>"})
        delta < 0 → ledger.transfer({from: u, to: None, amount: −delta, reason: "bonus.recalc", key 同上})
              ledger.insufficient_balance(details.available) → available > 0 时以 amount = available、
              key "recalc:<job>:<u>:<cur>:partial" 回收，shortfall = −delta − available；state='partial'
              ledger.account_locked → state='blocked'（管理员处理）
        ok → state='done', entry_id；commit
    剩余 > 0 → schedule_once 自身（dedupe 同键，run_at = now + 1 s）；否则 state='applied'；audit
```

被回放的事件同时记录 inbox，不影响后续实时事件。重算**不修改** `user_hours` 原记录（审计保留当时结果），差额在 `recalc_user_results` 与 ledger 流水中体现。

```
estimate(u):

### 1.9 currencies：币种初始化

```

### 1.10 service：`award`

```
award_ex(req{user, currency, amount, reason, memo, idempotency_key}):
    caller = invocation.caller_plugin；require "award" ∈ caller_scopes        ?: bonus.scope_required
    require currencies[currency].external_award（默认：bonus 是，seed_points 否）  ?: bonus.currency_not_awardable
    require 1 ≤ amount ≤ settings.award.max_amount                              ?: bonus.award_amount_invalid
    require reason ~ ^<caller>\.[a-z][a-z0-9_]*$                                ?: kernel.validation_failed
    ins = INSERT service_awards(caller_plugin, idempotency_key, user_id, currency, amount, reason, request_hash)
          ON CONFLICT DO NOTHING RETURNING 1
    if not ins: hit = SELECT …；hash 不同 → kernel.idempotency_key_reused；hit.entry_id → return {entry_id, duplicate: true}
    res = ctx.ledger.transfer({currency, from: None, to: user, amount, reason: "bonus.award",
                               memo: truncate(reason + " " + memo, 200), idempotency_key: "svc:" + caller + ":" + key})
    UPDATE service_awards SET entry_id；publish bonus.awarded{source: "service", reason}
    return {entry_id, duplicate: res.duplicate}
```

ledger 要求 `reason` 前缀为调用方（bonus），因此 ledger 侧统一为 `bonus.award`，真实来源原因码进入 memo 与本插件 `service_awards`。若本工作单元在 ledger 成功后回滚（极少），调用方重试时 `service_awards` 无行 → 再次调用 ledger，ledger 以相同幂等键返回首次结果，不重复发放。

### 1.11 用户删除

`purge_user`（`user.deleted`，tx manual）：`mode = purge`：分批删除 `user_hours`（各分区）、`accruals WHERE posting_id IS NULL`、`snapshot_parts`、`action_daily`、`recalc_items`、`recalc_user_results`；`action_awards`、`service_awards`、`posting_items` 的 `user_id` 置 0（保留金额用于对账）；`DEL est:<u>`（Redis，幂等）。`mode = soft`：只删未入账 `accruals`（不再发放）。

**GET `/v1/admin/postings?state=&currency=`** → 入账批列表（id、cutoff、条目数、金额、完成数、失败数）。

错误统一为 problem+json（conventions/api.md §7）。

分区：`user_hours` `range_day`、`premake = 3`、保留 `hourly.retention_days`（依赖 accounting N-4 的 `retention_days`；未合入前用 `range_month`、`retention_months = 3`）。

**数据量**：`user_hours` 25 万/小时 × 24 = 600 万行/天 × ~250 B ≈ 1.5 GB/天（含索引约 2.5 GB），保留 90 天 ≈ 220 GB——**偏大**：站点可把 `hourly.retention_days` 调为 14（≈ 35 GB），重算范围同时受快照事件日志保留期限制（B-8），两者取较小者。`accruals` 已入账行在 `cleanup` 中删除（posting done 后 7 天），常驻约 1 个周期 × 25 万 × 币种数。`torrent_facts` ≈ 种子数（百万级，~100 B/行）。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 表达式 | 自研解释器；无 I/O、无反射、无动态代码；限额（长度、节点、深度、函数参数数、`pow`/`exp` 边界）；显式栈求值；单次规则集求值时间由 WASM 调用截止时间兜底；仅 `bonus.rules.manage` 可提交 |
| 权限 | 后台路由经内核网关；重算单独权限 `bonus.recalc.manage` 且执行时要求近期重新验证；内核回放需 `kernel.events.replay`（sysop） |
| 作用域 | ledger 只申请本插件币种 + `read`；`award` 作用域由站点授予（`[grants.<plugin>.scopes]`）；reason 前缀校验防伪造来源；单笔上限 |
| 输入 | 规则 JSON 经 schema 校验；名称 NFC、≤ 64 字符、去控制字符；描述 Markdown 服务端转受限 HTML |
| 隐私 | 无敏感能力；事件不含用户文字；匿名种子：明细与 MCP 中只给 `torrent_id`，标题由 torrent 插件按可见性返回 |
| 审计 | `bonus.rules_publish`、`bonus.rules_revoke`、`bonus.action_rule_change`、`bonus.recalc_create`、`bonus.recalc_apply`、`bonus.posting_void`、`bonus.service_award`（来源插件、金额） |
| 资金安全 | 发放只走 ledger；本插件不保存余额；入账批与 ledger 每日对账（`reconcile`）：Σ posting_items(done) 与 ledger `history` 抽样比对，差异告警 |

## 7. 性能设计

|---|---|---|
| 快照事件 | 1 次 `torrent_facts` 批量查询（主键 ANY，80 行）+ 可选 1 次 `v_snatch` 查询 + 1 次 `ctx.users.get` + 80 × 项数次求值 + 2～3 条 INSERT | p50 8 ms，p99 30 ms |
