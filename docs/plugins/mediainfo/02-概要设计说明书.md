## 1. 设计目标

纯函数解析（可在钩子调用链中安全使用，type-* 的同步快速检查也可调用 `parse`）；异步解析结果供展示与校验；脱敏默认开启。

## 2. 结构与接口

| 类别 | 内容 |
|---|---|
| 模块 | `detect`（格式识别：文本 / JSON / BDInfo）、`text`、`json`、`bdinfo`、`labels`（多语言标签表）、`sanitize`（路径脱敏）、`summary`、`compare`、`nfo` |
| 服务 | `ctx.mediainfo`：`parse(text) -> MediaInfo`、`parse_nfo(bytes_b64) -> Nfo`（已登记）、⊕ `compare(summary, fields) -> Vec<Diff>` |
| 依赖 | 只读视图 `torrent.v_torrent_fields`（异步解析时读取 mediainfo 字段与规格字段） |
| 事件 | 发布 `mediainfo.parsed`；订阅 `torrent.created`、`torrent.updated` |
| HTTP | `POST /v1/parse`、`POST /v1/parse-nfo`（user，`mediainfo.use`，限流 `user:60/m`）；`GET /v1/torrents/{id}`（解析结果） |
| 插槽 | `torrent.detail.info`、`torrent.upload.extra` |

## 3. 关键流程

```
parse(text):
  len ≤ max → detect：以 "{" 开头且可解析 JSON → json；含 "DISC INFO:" / "PLAYLIST REPORT:" → bdinfo；否则 text
  text：按空行分段，段首行为段名（General / Video / Audio #1 / Text #2 / 菜单 …，经 labels 归一化）；
        每行 "key<空白>: value"，key 经 labels 归一化为英文键
  sanitize：Complete name / 完整名称 / Unique ID 以外的路径类字段 → basename
  summary：从归一化段中计算规格摘要
on torrent.created(evt): f = v_torrent_fields[evt.torrent_id]；f.fields.mediainfo 非空 → parse → UPSERT results → publish mediainfo.parsed{summary}
```

## 4. 设计决策

| 编号 | 问题 | 结论 |
|---|---|---|
| DD-MINFO-1 | 脱敏后是否回写种子字段 | 不回写（torrent 拥有字段）；展示使用本插件的脱敏结果；请 torrent 在上传时调用 `ctx.mediainfo.parse` 并保存脱敏文本（§5） |
| DD-MINFO-2 | 钩子中使用 | `parse` 为纯函数、无出站，可在钩子中调用；但 type-* 只做快速检查（性能预算） |

## 5. 对平台契约的新增

服务 `compare`；建议 torrent 上传时把 `fields.mediainfo` 替换为 `ctx.mediainfo.parse(text).sanitized_text`（防止原始路径进入存储与事件），见 torrent 设计确认。

## 6. 需求追溯

FR-001～004 → detect、text、json、bdinfo、labels；FR-005 → sanitize；FR-006 → summary；FR-007 → compare；FR-008 → nfo；FR-009 → 订阅；FR-010、011 → HTTP。

## 7. 实现说明（2026-10-17，v0.1.0）

- DD-MINFO-1 调整：资源类型插件拒绝未知字段，`fields.mediainfo` 不可用，改为本插件自存脱敏结果（表 `results`，每种子一行），发种者或 `mediainfo.manage` 经 `PUT /v1/torrents/{id}` 保存；发布页通过插槽 `torrent.upload.extra` 的 `afterUpload(cb)` 在发布成功后提交粘贴的报告。原始文本不进入存储与事件。
- 未实现：`parse_nfo` / `POST /v1/parse-nfo`（NFO 解码）、发布时强制要求或差异阻止发布。
