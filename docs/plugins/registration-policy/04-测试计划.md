## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元 | 周期时段（跨午夜、DST）、下一次开放时间、域名后缀键生成、IP 规范化与网段、CIDR 豁免、PoW 前导零位、表单令牌、选项洗牌与判分、状态 `mode` 推导、关卡排序 | `cargo test`（wasm32-wasip2 + 原生）、`proptest` |
| 插件集成 | 内核 testkit 加载 registration-policy.wasm + 真实 PG / Redis；stub identity（运行 `user.before_register` 管线、发布 `user.registered` / `user.deleted`、实现 `ctx.users.create` 并回调钩子）、stub invite（priority 10 处理者）、模拟第三方 siteverify（testkit HTTP mock） | `pt-testkit`、testcontainers |
| 契约 | `pt:registration` WIT；事件载荷、MCP 输入输出 JSON Schema；OpenAPI → TS SDK、`oasdiff` | `wasm-tools`、`jsonschema`、`openapi-typescript` |
| 组合 | 通道 × 关卡矩阵（§3.3），随机组合与预演对照 | 表驱动 + `proptest` |
| 前端 | 注册页插槽（PoW Worker、蜜罐、答题弹窗）、申请页、后台设置矩阵；可访问性 | Vitest、Playwright、axe-core |
| 性能 | 钩子、状态接口、开放窗口高峰 | k6 |
| 安全 / 隐私 | 敏感扫描（IP、邮箱、票据、令牌）、刷题、票据转用、令牌枚举、越权 | 自动化 + 扫描器 |

**通用断言**：敏感扫描器收集事件、日志、审计、指标标签、MCP 输出、错误响应、PG 全表转储（申请表 `email_enc` 列除外），对测试用的原始 IP、邮箱、票据、状态令牌做子串搜索，必须 0 命中。

## 2. 测试环境与数据

- PostgreSQL 17、Redis 7.4；`time` 可冻结 / 快进，站点时区 `Asia/Shanghai`（DST 用例另用 `Europe/Berlin`）；`random` 可设种子。
- stub identity 选项：是否在钩子输入中提供 `ip`（模拟内核裁剪 + 授权）、`ip_hmac`、`device_hmac`；在 registration-policy 之后由 stub invite 或另一 stub 拒绝；`create` 可配置返回成功 / `identity.username_taken` / retryable 错误。
- 题库：分类 `rules`（30 题）、`bt`（20 题），zh-CN 与 en。
- 用户：M（moderator，`registration-policy.applications.moderate`）、AD（admin，`registration-policy.manage` + `identity.users.read_sensitive`）、M2（第二个版主）。
- 性能数据：50 万用户；域名名单 20 万条。

## 5. 通过准则

1. P0 用例 100% 通过；P1 ≥ 95% 且无安全 / 隐私 / 并发类失败；P2 不阻断发布但需登记。

5. 契约测试通过；业务逻辑行覆盖率 ≥ 80%（`pipeline`、`claims`、`applications` ≥ 90%）。
6. 依赖 HLD §7 新增契约（★：钩子输入裁剪 `ip`、`ip_hmac`、`device_hmac`、`pending_source`、`write:create`）的用例：合入前按退化方案执行（IP 关卡按 `on_unavailable`），合入后复测。
