## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/registration-policy/`（Rust，`wit-bindgen`）。PG schema `registration_policy`；Redis 私有前缀 `p:registration-policy:`（下文写插件代码中的键）。
- **持有者** `holder(username) = lowercase(nfc(trim(username)))`（与 invite 相同）。
- **密钥**：静态配置 `secret`（32 字节）。`HKDF-SHA256(salt = "pt-studio/registration-policy", info)`：`ip-mac`（IP / 网段 / 设备摘要）、`email-enc`（AES-256-GCM）、`email-mac`（邮箱 HMAC）、`form-token`（表单令牌签名）、`token-mac`（状态令牌哈希加盐）。crate：`hmac`、`sha2`、`hkdf`、`aes-gcm`、`ipnet`（均 MIT/Apache）。
- **随机**：票据 / 挑战 / 会话 ID = `base64url(random.bytes(16))`；状态令牌 = `"rpa_" + base64url(random.bytes(24))`。
- **时间**：`time.now()`；周期时段按 `time.site_timezone()`（`chrono-tz` 内置时区库）。
- **设置读取**：每次调用 `config.get-settings()`（内核缓存）；紧急开关、窗口来自 PG，状态汇总缓存于 Redis `st:v1`（5 s）。

### 1.1 availability：可用性

```
fn channel_available(ch, now) -> Result<(), Closed{reason, next_open_at?}>:
    ov = SELECT state, channels, until FROM overrides WHERE id = 1      // 单行，主键查找
    if ov and (ov.until is None or ov.until > now) and ch ∈ ov.channels:
        return ov.state == 'closed' ? Err(forced_closed) : Ok          // 强制开放仍执行关卡
    c = settings.channels[ch]
    if !c.enabled: Err(channel_disabled)
    match c.availability:
        always   => Ok
        never    => Err(channel_disabled)
        windows  => w = active_window(ch, now)
                    w ? Ok : Err(window_closed, next = next_window_start(ch, now))
        schedule => in_schedule(settings.schedule, now) ? Ok : Err(outside_schedule, next = next_schedule_start(now))

fn active_window(ch, now) =
    SELECT id, slots, ends_at FROM windows
    WHERE $ch = ANY(channels) AND cancelled_at IS NULL AND starts_at <= $now AND ends_at > $now
    LIMIT 1                                                           // 同通道不重叠（写入时校验）

fn in_schedule(rules, now):
    local = now.in(site_tz); d = weekday(local) (0 = 周日); t = local.time()
    for r in rules:
        if r.from <= r.to: hit = d ∈ r.days and r.from <= t < r.to
        else:              hit = (d ∈ r.days and t >= r.from) or (prev_day(d) ∈ r.days and t < r.to)   // 跨午夜
        if hit: return true
    false
```

`next_schedule_start` 在未来 8 天内按分钟边界扫描规则端点（最多 7 × 规则数个候选），取最小值。DST 切换时按本地时间解释（不存在的本地时间顺延到下一个有效时刻）。

### 1.2 pipeline：钩子编排

```
const GATE_ORDER = [username_hold, email_domain, captcha, quiz, ip_limit, device_limit, window_slots, user_cap]
const CAPACITY = {ip_limit, device_limit, window_slots, user_cap}

fn on_before_register(input, dry_run = false) -> (HookDecision, Trace):
    ch = input.attributes.registration_mode ?? "open"
    gates = settings.channels[ch].gates ∩ GATE_ORDER（按 GATE_ORDER 排序）
    trace = []
    if ch ∉ {admin, import}:
        r = channel_available(ch, now)
        if r is Err(e):
            if ch == open and channel_available(invite, now).is_ok() and settings.channels.invite.enabled:
                return deny(invite_required)
            return deny(closed, {reason: e.reason, next_open_at: e.next})
        if ch == invite and kv.get("env:invite_present") != "1": return deny(invite_unavailable)
    holder = holder(input.username)
    ns = input.form["registration-policy"] ?? {}
    // ② 只读关卡
    for g in gates where g ∉ CAPACITY:
        v = match g:
            username_hold => ch != application and settings.application.username_hold and
                             exists(SELECT 1 FROM applications WHERE username_key = $holder AND status IN ('submitted','approved'))
                             ? Deny(username_held) : Pass
            email_domain  => domain_verdict(input.email_domain, ch).into()
            captcha       => check_captcha(ns, holder, dry_run)
            quiz          => check_ticket(ns.quiz_ticket, kind = quiz, holder, dry_run)
        trace.push((g, v)); if v is Deny: stats(ch, g, deny); return deny(v)
    // ③ 容量关卡
    pools = []
    if ip_limit ∈ gates:     pools += ip_pools(input)?          // 可能返回 Deny(ip_unavailable) 或 Skip
    if device_limit ∈ gates: pools += device_pool(input)?
    if window_slots ∈ gates: w = active_window(ch, now); if w and w.slots: pools += {key: "window:<w.id>", cap: w.slots}
    if user_cap ∈ gates and settings.user_cap.enabled: pools += {key: "cap", cap: settings.user_cap.max_users}
    if pools non-empty:
        v = claim_all(pools, holder, now + ttl, dry_run)        // §1.3
        trace.push(v); if v is Deny: stats(ch, v.gate, deny); return deny(v)
    stats(ch, "all", pass)
    if ch == open and settings.channels.open.review:
        return modify({attributes: {initial_status: "pending", pending_reason: "registration-policy.review",
                                    pending_source: "registration-policy"}})        // ★ 字段未合入时只发 initial_status
    return allow
```

- `admin`、`import` 通道跳过可用性；其 `gates` 默认为空。
- 预演（`POST /admin/evaluations`）以 `dry_run = true` 调用同一函数：票据只读不绑定；`claim_all` 只计数不写；返回 `trace`。
- 钩子中所有 Redis 操作失败 → 返回 `err(kernel.service_unavailable)` → 管线 fail-closed（NFR-REGP-009）；仅在启用了 captcha / quiz 关卡时才访问 Redis（统计计数失败忽略）。

### 1.3 claims：名额池与占位

**池**：

| 池键 | 容量 | 计数口径 |
|---|---|---|
| `cap` | `user_cap.max_users` | `pools.confirmed`（= 用户数）+ 他人有效占位 |
| `window:<id>` | `windows.slots` | `pools.confirmed`（本窗口确认数）+ 他人有效占位 |
| `ip:<hex>` | `ip_limit.per_ip.max` | 窗口内 confirmed 占位 + 他人有效占位 |
| `pfx:<hex>` | `ip_limit.per_prefix.max` | 同上 |
| `dev:<hex>` | `device_limit.max` | 同上 |

```
fn claim_all(pools, holder, until, dry_run) -> Verdict:
    pools.sort_by(key)                                                  // 固定加锁顺序，避免死锁
    for p in pools:
        INSERT INTO claim_locks(pool) VALUES ($k) ON CONFLICT (pool) DO UPDATE SET touched_at = now()   // 取行锁
    for p in pools:
        used = match p.kind:
            cap | window => (SELECT confirmed FROM pools WHERE pool = $k) +
                            (SELECT count(*) FROM claims WHERE pool=$k AND state='reserved' AND reserved_until > now() AND holder <> $h)
            ip | pfx | dev => SELECT count(*) FROM claims WHERE pool = $k AND (
                                (state = 'confirmed' AND confirmed_at > now() - make_interval(hours => $w)) OR
                                (state = 'reserved' AND reserved_until > now() AND holder <> $h))
        if used >= p.cap: return Deny(gate_of(p), details{scope})
    if dry_run: return Pass
    for p in pools:
        INSERT INTO claims(pool, holder, state, reserved_until) VALUES ($k, $h, 'reserved', $until)
        ON CONFLICT (pool, holder) WHERE state = 'reserved' DO UPDATE SET reserved_until = EXCLUDED.reserved_until
    return Pass
```

- 同一持有者重复提交：自己的占位不计入，`ON CONFLICT` 只延长（可重入）。
- 拒绝时不写占位；锁随工作单元提交释放（钩子工作单元很短）。
- 拒绝映射：`cap` → `closed{reason: cap_reached}`；`window` → `closed{reason: slots_exhausted}`；`ip`/`pfx` → `ip_limit_reached{scope: ip|prefix}`；`dev` → `device_limit_reached`。

**确认**（订阅 `user.registered`）：

```
fn on_user_registered(evt):
    p = evt.payload; h = holder(p.username)
    rows = UPDATE claims SET state = 'confirmed', confirmed_at = now(),
                  user_id = CASE WHEN pool LIKE 'ip:%' OR pool LIKE 'pfx:%' OR pool LIKE 'dev:%' THEN NULL ELSE $uid END,
                  holder  = CASE WHEN pool LIKE 'ip:%' OR pool LIKE 'pfx:%' OR pool LIKE 'dev:%' THEN NULL ELSE holder END
           WHERE holder = $h AND state IN ('reserved','released') RETURNING pool
    if rows 为空 and p.registration_mode ∉ {admin, import}: metrics(confirm_without_claim)
    INSERT INTO pools(pool, confirmed) VALUES ('cap', 1) ON CONFLICT (pool) DO UPDATE SET confirmed = pools.confirmed + 1, updated_at = now()
    for r in rows where r.pool starts_with "window:":
        UPDATE pools SET confirmed = confirmed + 1 WHERE pool = r.pool
        if confirmed > windows.slots: metrics(slots_overcommitted_total)        // 仅事件延迟 > TTL 时可能
    if p.registration_mode == application: 校验 applications.user_id = p.user_id（记录 created_seen_at）
```

- 确认后 IP 类占位的 `holder` 与 `user_id` 置空——摘要不再能关联到账号（FR-REGP-034）。
- 内核 inbox 保证上述写入对同一事件恰好一次。
- `on_user_deleted`：`INSERT INTO deleted_users(user_id) … ON CONFLICT DO NOTHING`，插入成功时 `UPDATE pools SET confirmed = greatest(confirmed - 1, 0) WHERE pool = 'cap'`；`purge` 时另执行 §1.7 清理。

**清理**：`claims_sweep` 每批 1000 行：`UPDATE … SET state='released' WHERE state='reserved' AND reserved_until < now()`；`DELETE … WHERE state='released' AND pool NOT LIKE 'ip:%' … AND updated_at < now() - interval '1 day'`；`ip_retention`：`DELETE FROM claims WHERE (pool LIKE 'ip:%' OR pool LIKE 'pfx:%' OR pool LIKE 'dev:%') AND created_at < now() - make_interval(days => $retention)`，以及 30 天未触达的 `claim_locks` 行。

### 1.4 gates：邮箱域名、IP、设备

**域名判定**：

```
fn domain_verdict(domain, ch) -> DomainVerdict:      // domain 已由 identity 规范化为 IDNA ASCII 小写
    labels = domain.split('.'); keys = [domain] + [ "." + labels[i..].join(".") for i in 1..len ]   // a.b.edu.cn → [a.b.edu.cn, .b.edu.cn, .edu.cn, .cn]
    rows = SELECT list, pattern FROM domain_rules WHERE pattern = ANY($keys)
    if rows.any(list == deny):       return {allowed: false, reason: denylisted, rule}
    if settings.email_domain.use_disposable and rows.any(list == disposable): return {allowed: false, reason: disposable}
    if settings.email_domain.allowlist_only and !rows.any(list == allow):     return {allowed: false, reason: not_in_allowlist}
    return {allowed: true}
```

- 名单项 `pattern`：精确 `example.com` 或后缀 `.edu.cn`（输入 `*.edu.cn` 规范化为 `.edu.cn`）。精确项不匹配子域。
- `check_email_domain(domain, ch)` 服务与钩子共用此函数（ch 决定是否启用该关卡：未启用则 `allowed: true, reason: gate_disabled`）。

**IP 池**：

```
fn ip_pools(input) -> Result<Vec<Pool>, Verdict>:
    if input.ip is Some(raw):                                   // 内核裁剪 + user.ip 授权
        ip = parse(raw)?; if exempt(ip, settings.ip_limit.exempt_cidrs): return Ok([])
        h  = HMAC(ip-mac, canonical(ip)); pfx = network(ip, v4_prefix | v6_prefix)
        hp = HMAC(ip-mac, "pfx:" + pfx)
    else if input.ip_hmac★ is Some:                              // identity 盲化摘要（不支持豁免）
        h = SHA256("idn:" + input.ip_hmac); hp = SHA256("idn:" + input.ip_prefix_hmac)
    else:
        metrics(ip_unavailable_total)
        return settings.ip_limit.on_unavailable == deny ? Err(Deny(ip_unavailable)) : Ok([])
    pools = []
    if per_ip.max > 0:     pools += {key: "ip:" + hex(h[0..16]),  cap: per_ip.max,     window: per_ip.window_hours}
    if per_prefix.max > 0: pools += {key: "pfx:" + hex(hp[0..16]), cap: per_prefix.max, window: per_prefix.window_hours}
    return Ok(pools)
```

- 原始 IP 只存在于本次调用的内存中，不写日志、不写库。
- `device_pool`：`input.device_hmac★` 存在时 `{key: "dev:" + hex(SHA256("idn:" + device_hmac)[0..16])}`；否则同 `on_unavailable`。

### 1.5 captcha：提供方、表单令牌、票据

**提供方接口**（插件内部 trait）：

```rust
trait CaptchaProvider {
    fn id(&self) -> &'static str;
    /// 签发挑战；第三方提供方返回 None（前端直接渲染组件）
    fn challenge(&self, ctx: &Ctx) -> PResult<Option<Challenge>>;
    /// 校验用户提交；HTTP 处理器中调用，可出站
    fn verify(&self, ctx: &Ctx, sub: &Submission) -> PResult<VerifyOutcome>;
}
enum VerifyOutcome { Pass, Fail(&'static str /* reason */), Unavailable }
```

| 提供方 | challenge | verify |
|---|---|---|
| `pow` | `salt = random(16)`；Redis `HSET pc:<id> s <salt> d <difficulty>` + `EXPIRE 300` | `HGETALL pc:<id>` → `DEL pc:<id>` 返回 1 → `leading_zero_bits(SHA256(salt ‖ nonce_bytes)) ≥ d`；nonce ≤ 32 字节 |
| `hcaptcha` | 无 | `POST https://api.hcaptcha.com/siteverify`（form：`secret`、`response`、`sitekey`），超时 3 s；`success && hostname == site_host` |
| `turnstile` | 无 | `POST https://challenges.cloudflare.com/turnstile/v0/siteverify`（`secret`、`response`、`idempotency_key = <challenge uuid>`） |
| `recaptcha` | 无 | `POST https://www.google.com/recaptcha/api/siteverify`；v3 时 `score ≥ recaptcha.min_score` |
| `image`（P2） | WASM 内绘制 5 字符图片（PNG data URL），答案 `SHA256` 存 `ic:<id>`（300 s，`n` 次数） | 比较哈希，错 3 次 `DEL` |
| `none` / `external` | 无 | 不签发票据；钩子中 captcha 关卡直接 Pass |

均不向第三方发送 `remoteip`。第三方返回 `Unavailable`（网络错误、5xx、超时）且 `fallback_to_pow` → 响应 `409 registration-policy.captcha_fallback` + PoW 挑战。

**表单令牌**（蜜罐的时间维度）：`form_token = base64url(ts_ms(8B) ‖ HMAC(form-token, ts)[0..16])`，随 `GET /status` 下发。

**票据**：

```
fn issue_ticket(kind, holder?, score?) -> (id, expires_at):
    id = random_id(); ttl = kind == captcha ? captcha.ticket_ttl_secs : quiz.ticket_ttl_secs
    pipeline(atomic): HSET tk:<id> k <kind> [h <holder>] [s <score>] t <now>; EXPIRE tk:<id> ttl
fn check_ticket(id?, kind, holder, dry_run) -> Verdict:
    if id is None: return Deny(kind == captcha ? captcha_required : quiz_required)
    t = HGETALL tk:<id>; if t is empty or t.k != kind: return Deny(ticket_invalid, {kind})
    if t.h is None: if !dry_run: HSETNX tk:<id> h <holder>; t.h = HGET tk:<id> h      // 首次绑定（并发安全）
    return t.h == holder ? Pass : Deny(ticket_invalid, {kind, reason: holder_mismatch})
fn check_captcha(ns, holder, dry_run):
    if provider ∈ {none, external}: return Pass
    if settings.captcha.honeypot:
        if ns.hp non-empty: return Deny(captcha_invalid, {reason: honeypot})
        ts = verify_form_token(ns.form_token)?: Deny(captcha_invalid, {reason: form_token})
        if now - ts < min_fill_secs: Deny(captcha_invalid, {reason: too_fast}); if now - ts > 2h: Deny(form_token)
    return check_ticket(ns.captcha_ticket, captcha, holder, dry_run)
```

### 1.6 quiz：题库、会话、判分

**抽题**：

```
fn start_session(locale, captcha_ticket?) -> Session:
    if quiz.require_captcha: check_ticket(captcha_ticket, captcha, holder = None → 只校验存在与类型)
    picked = []
    for d in settings.quiz.draw:
        ids = SELECT id FROM questions WHERE category=$1 AND enabled AND locale = $2 ORDER BY random() LIMIT $3
        if len(ids) < d.count: ids += 同分类 site.default_locale 的题（排除已选）

    qs = SELECT id, kind, body, options FROM questions WHERE id = ANY($picked)
    for q: perm = shuffle(0..len(q.options), random); labels = ['a','b',…]
    sid = random_id(); exp = now + time_limit_secs
    HSET qs:<sid> q <json [{qid, version, perm}]> e <exp>; EXPIRE qs:<sid> time_limit + 60
    UPDATE questions SET shown_count = shown_count + 1 WHERE id = ANY($picked)

```

**判分**：

```
fn submit(sid, answers: map<n, [label]>, username?) -> Result:
    s = HGETALL qs:<sid>; if empty: Err(quiz_session_invalid)
    if DEL qs:<sid> == 0: Err(quiz_session_invalid)          // 并发重复提交只有一个成功
    if now > s.e: Err(quiz_session_invalid, {reason: expired})
    keys = SELECT id, version, answer_keys, kind FROM questions WHERE id = ANY($qids)
    correct = 0
    for (n, item) in s.q:
        chosen = answers[n].map(label → original option index via item.perm).map(index → option key)
        ok = match settings.quiz.multi_scoring { all_or_nothing => set(chosen) == set(answer_keys) }
        correct += ok; stat_rows.push((qid, ok))
    execute_batch("UPDATE questions SET correct_count = correct_count + $2 WHERE id = $1", stat_rows)
    score = round(100 * correct / len)
    stats INCR quiz:<pass|fail>
    if score >= pass_percent: (tid, exp) = issue_ticket(quiz, username.map(holder), score); return {passed: true, score, ticket: tid, expires_at: exp}
    return {passed: false, score}
```

题目在会话期间被修改：判分以当前版本为准，`version` 不一致的题目按正确计分（避免因管理员改题误伤），并计指标。

### 1.7 applications：申请制

**状态机**：

```
submitted ──approve──► approved ──create ok──► created
    │                      └──create 失败（不可重试）──► create_failed ──retry──► approved
    ├──reject──► rejected
    ├──withdraw──► withdrawn
    └──expire──► expired
```

**提交**：

```
fn submit_application(req) -> (id, token):
    channel_available(application, now)?                         // closed / channel_disabled
    for g in settings.channels.application.submit_gates:          // email_domain、captcha（holder = 申请用户名）
        run gate（同 §1.2 只读关卡；captcha 票据绑定申请用户名）
    validate_username_format(req.username)                        // 与 identity 规则一致的子集：长度、字符集；最终以 create 为准
    if ctx.users.find_by_username(req.username)? is Some: Err(identity.username_taken)
    validate_fields(req.fields, settings.application.fields); validate_urls(req.proof_urls)   // https/http，≤ 2048，数量
    referrer_id = req.referrer.map(ctx.users.find_by_username).flatten().map(.id)            // 找不到 → 422 referrer_not_found
    email = canon_email(req.email); mac = HMAC(email-mac, email); key = holder(req.username)
    tx:
        if exists(applications WHERE username_key = key AND status IN ('submitted','approved')): Err(application_duplicate{field: username})
        if exists(applications WHERE email_hmac = mac AND status IN ('submitted','approved')): Err(application_duplicate{field: email})
        if c = SELECT until FROM application_cooldowns WHERE email_hmac = mac AND until > now(): Err(application_cooldown{until})
        token = "rpa_" + random; th = HMAC(token-mac, token)
        id = INSERT applications(username, username_key = key, email_enc = aes_gcm(email-enc, email, aad = "app:email"),
                                 email_hmac = mac, email_domain, locale, fields, proof_urls, referrer_id, status = 'submitted',
                                 token_hash = th, expires_at = now + expire_days) RETURNING id
        publish registration.application_submitted{application_id: id, username}
    return (id, token)
```

`email_enc` 的 AAD 在插入后无法包含 id，因此使用固定 AAD `"app:email"` + 随机 96 位 nonce；密文格式 `ver(1) ‖ nonce(12) ‖ ct ‖ tag(16)`。

**状态查询**：`POST /application-status-queries {token}` → `SELECT … WHERE token_hash = HMAC(token-mac, token)`；未命中统一 404 `kernel.not_found`；返回 `{status, submitted_at, decided_at?, reason_code?, next_steps}`（`created` 时 `next_steps = "check_email"`）。

**建号任务**（延迟任务 `create_account`）：

```
fn create_account(job):
    a = SELECT … FROM applications WHERE id = $1 FOR UPDATE
    if a.status != 'approved' or a.attempt != job.payload.attempt: return ok              // 已处理 / 已被新一轮替代
    email = aes_gcm_decrypt(email-enc, a.email_enc)
    r = ctx.users.create({username: a.username, password: None, email, locale: a.locale, invite_code: None,
                          form: "{}", origin_ref: "registration-policy:application:<id>",
                          skip_email_verification: false, idempotency_key: "regp:app:<id>:<attempt>"})
    match r:
        Ok(uid) => UPDATE applications SET status='created', user_id=uid, purge_after = now + retention_days
                   publish registration.application_completed{application_id, outcome: created, user_id: uid}
        Err(e) if !e.retryable =>
                   UPDATE applications SET status='create_failed', failure_code = e.code
                   publish registration.application_completed{application_id, outcome: failed, failure_code: e.code}
        Err(e) => return Err(e)                                                          // 内核重试（30 s、2 min、10 min）
```

- `ctx.users.create` 触发 `user.before_register`，通道为 `application`：本插件只执行 `channels.application.gates`（默认 `user_cap`），不执行 `username_hold`（申请本身占用该名）。
- `application_maintenance`：`status = 'approved' AND decided_at < now() - 10 min AND user_id IS NULL` 且无待执行任务 → 以同一 attempt 重新调度（dedupe 键加 `:r<n>`，幂等键不变，identity 返回同一用户）。

**过期与清除**（`application_maintenance`，每批 500，分批提交）：
1. `submitted AND expires_at < now()` → `expired`，`purge_after = now + retention_days`。
2. `purge_after < now()` → `email_enc = NULL, fields = '{}', proof_urls = '{}', review_note = NULL, token_hash = NULL, email_domain` 保留（统计）、`purged_at = now()`。
3. `DELETE FROM application_cooldowns WHERE until < now()`。

**purge**（`user.deleted{mode: purge}`）：`UPDATE applications SET username = 'purged:' || id, username_key = 'purged:' || id, email_enc = NULL, email_hmac = NULL, fields = '{}', proof_urls = '{}' WHERE user_id = $uid`。

### 1.8 stats：统计

- 钩子 / 接口中：`INCR st:<yyyymmdd>:<channel>:<metric>` + `EXPIRE … 40 天`（pipeline，非原子，失败忽略）。`metric` ∈ `hook_calls`、`deny:<gate>`、`deny:closed:<reason>`、`allow`、`captcha_issued`、`captcha_passed`、`captcha_failed`、`quiz_started`、`quiz_passed`、`quiz_failed`。
- PG 侧（事件中计）：`registered:<channel>`（`on_user_registered` 中 `INSERT … ON CONFLICT DO UPDATE value = value + 1`），`applications_*` 由申请状态表聚合。
- `stats_rollup`：读取昨日全部键（已知集合：channel × metric 组合，逐个 `GET`，不使用 `SCAN`/`KEYS`），`INSERT INTO daily_stats … ON CONFLICT (day, channel, metric) DO UPDATE SET value = EXCLUDED.value`——重复执行结果相同。

### 1.9 service：`ctx.registration`

```
fn status() -> RegistrationStatus:
    if c = GET st:v1: return parse(c)
    for ch in [open, invite, application]:
        avail = channel_available(ch, now); w = active_window(ch, now)
        remaining = min( cap 剩余（若该通道 gates 含 user_cap 且启用）, window 剩余（若有名额） )
        cs.push({channel: ch, enabled, open_now: avail.ok, reason?, window_ends_at?, next_open_at?, remaining_slots?,
                 requires_captcha: captcha ∈ gates && provider ∉ {none, external}, requires_quiz: quiz ∈ gates, requires_review})
    mode = derive_mode(cs)        // closed | open | invite_only | open_and_invite | application_only | mixed
    s = {mode, open: cs[open].open_now, remaining_slots: cs[open].remaining_slots, requires_invite: !cs[open].open_now && cs[invite].open_now,
         requires_exam: cs[open].requires_quiz, channels: cs, captcha: {provider, site_key?}, next_open_at, user_cap?}
    SET st:v1 <json> EX 5
    return s
```

`derive_mode`：open 开 + invite 开 → `open_and_invite`；只有 open → `open`；只有 invite → `invite_only`；只有 application → `application_only`；全部关闭 → `closed`；其他组合 → `mixed`。`show_remaining_slots = false` 时公开接口不返回 `remaining_slots`（服务仍返回）。

### 1.10 init

`lifecycle.init`：`plugins = ctx.plugins.list()`；`kv.set("env:invite_present", any(p.id == "invite" && p.enabled))`；校验设置一致性（`channels.*.availability = windows` 但无未来窗口 → 告警日志；`captcha.provider` 为第三方但缺 secret → 启动告警，钩子按 `fallback_to_pow`）。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 票据 | 128 位随机；Redis TTL；首次使用绑定用户名（`HSETNX`）；类型校验；不出现在日志与事件中 |
| PoW 挑战 | 单次使用（`DEL` 返回值判定）；5 分钟有效；难度可调；`/captcha-challenges` 限流 |
| 第三方验证码 | secret 为 `x-pt-secret` 加密存储、API 不回显；只连接清单白名单主机；不发送用户 IP；校验 hostname；超时 3 s |
| 表单令牌 | HMAC 签名时间戳，防止伪造“填写时间” |
| 答题 | 不返回题目 ID 与答案；会话单次提交；选项会话内重新标签；开始前可要求验证码；内核按 IP 限流 |
| 申请 | 邮箱 AES-256-GCM；HMAC 去重；状态令牌只存 HMAC；查询失败统一 404；完整邮箱查看需 `identity.users.read_sensitive` 并审计 `registration-policy.email_reveal`；证明链接仅允许 http/https，前端以纯文本 + 外链展示，不预取（避免 SSRF / 跟踪） |
| IP | 原始值不落盘；摘要使用插件密钥；确认后断开关联；保留期删除；豁免 CIDR 由管理员配置 |
| 输入校验 | 全部字段长度、NFC、控制字符；`fields` 按配置 schema 校验；题干受限 Markdown 由前端 `<RichText>` 渲染 |
| 越权 | 后台路由权限由内核检查；`admin_reveal_email` handler 内二次检查；审核乐观锁 |
| 审计 | `registration-policy.override_set/clear`、`window_create/update/cancel`、`domain_rules_import`、`question_change`、`application_decide`、`application_retry`、`email_reveal`；details 不含邮箱与 IP |
| 隐私合规 | 目的限定（防滥用）、最小化（摘要）、期限（≤ 90 天）、告知（注册页文案）、删除（purge 与保留期任务）；符合《个人信息保护法》与 GDPR 的“必要性”原则；站点可完全关闭 IP / 设备关卡 |

## 7. 性能设计

| 路径 | 设计 | 估算 |
|---|---|---|
| 注册钩子 | 1 次 overrides 主键查询 + 0～1 次窗口索引查询 + 1 次 `applications_open_username_key` 查找 + 1 次 `domain_rules` `= ANY` 查找（≤ 6 个键）+ 2 次 Redis HGETALL + 容量锁（≤ 4 行）与计数（部分索引）+ ≤ 4 次 UPSERT | p99 ≤ 20 ms |
| 热点 | `claim_locks('cap')` 与 `pools('cap')` 每次注册都被锁定；锁持有时间 = 钩子剩余部分（< 3 ms）+ 提交 | 单行 ≥ 300 次/秒；若实测不足，把 `cap` 拆为 `cap:0..cap:7`（按 holder 哈希选择，容量按比例分配 + 每次检查汇总确认数缓存），作为 0002 迁移预案 |
| 状态接口 | Redis 5 s 缓存；未命中时 3 个通道 × 少量主键查询 | 命中 < 5 ms |
| 答题 | 抽题 `ORDER BY random()` 在 ≤ 1 万题的分类内 | < 10 ms |
| cron | 全部分批 500～1000 行并提交 | 单批 < 1 s |

WASM：`max_concurrency = 128`（开放窗口高峰：钩子 + 状态 + 验证码接口）。
