## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/medals/`（Rust + `wit-bindgen`），`kind = "wasm"`；状态在 PG schema `medals`、Redis `p:medals:`、blob `plugins/medals/`。
- 时间戳：PG `timestamptz`；接口 RFC 3339 / WIT 毫秒。
- 幂等：服务写方法以 `(caller_plugin, idempotency_key)` 写 `idempotency` 表；授予另有 `grants.source_ref` 唯一约束兜底。
- 谓词：使用 `pt-predicate` 共享 crate（与 anticheat 03 §1.2 的谓词格式相同：`{field, op, value}`，op ∈ `eq ne gt gte lt lte in nin exists`）；在共享 crate 落地前，本插件内置同语义实现。

### 1.1 catalog（物品定义）

```
create_item(req, actor):
  校验：kind ∈ {medal, badge, title}；slug ^[a-z0-9_]{2,40}$ 唯一；rarity ∈ {common, rare, epic, legendary}
        default_days ∈ [1, 3650] 或 null（永久）；limit ∈ [1, 10^7] 或 null；on_regrant ∈ {extend, latest, reject}
        wearable 仅对 medal 有意义（badge/title 强制 false）
  INSERT items … RETURNING id
  terms.define([{ key: "medals.item."+id, defaults: { zh-CN: {name: req.name_zh}, en: {name: req.name_en ?? req.name_zh} } }],
               idempotency_key = "item:"+id+":"+revision)
  audit.write(…)
update_item：可改除 kind 外的字段；改名称默认值时再次 define（revision+1）
deactivate_item：active=false；不影响已有授予；不可再授予；terms 不退役（历史仍需显示）
delete_item：仅当无任何授予记录时允许；terms.retire(["medals.item."+id])
```

**图标**：`POST /admin/items/{id}/icon`，multipart，≤ 256 KiB；类型由内容嗅探（PNG / WebP / SVG）；SVG 用 `ammonia` 风格的白名单净化（只保留 `svg, g, path, circle, rect, ellipse, line, polyline, polygon, defs, linearGradient, radialGradient, stop, title`，去掉所有 `on*` 属性、`href` 外链、`<script>`、`<foreignObject>`、`style` 中的 `url()`）；存 `blob.put("icons/<id>-<sha256前12位>.<ext>")`，旧图标保留 7 天后删除（`cleanup` 由 `expire_grants` 顺带执行）。

### 1.2 grants（授予、续期、限量、收回、过期）

```
grant(req, caller, actor) -> GrantResult:
  if idem = idempotency.get(caller, req.idempotency_key): return idem
  item = SELECT … FROM items WHERE id = req.medal_id AND active          // 不存在 → medals.item_not_found
  user = users.get(req.user_id)；status = deleted → medals.user_invalid
  if item.limit is not null: SELECT … FROM items WHERE id = … FOR UPDATE   // 限量串行化
  SELECT … FROM grants WHERE user_id=$u AND medal_id=$m AND state='active' FOR UPDATE → cur
  expires = req.expires_at ?? (item.default_days ? now + days : null)
  if cur:
     match item.on_regrant:
       reject → err(medals.already_held)
       extend → new_exp = (cur.expires_at is null or expires is null) ? null : cur.expires_at + (expires - now)
       latest → new_exp = max_nullable(cur.expires_at, expires)          // null 表示永久，为最大
     UPDATE grants SET expires_at = new_exp, renewed_count+1, updated_at=now WHERE id = cur.id
     result = {grant_id: cur.id, renewed: true, expires_at: new_exp}
  else:
     if item.limit: active_count = item.active_holders；if active_count >= limit → err(medals.limit_reached)
     INSERT grants(user_id, medal_id, state='active', source, source_ref, reason, granted_by, expires_at)
            ON CONFLICT (source_ref) DO NOTHING RETURNING id
     无行 → 返回已有 source_ref 对应记录（视为幂等成功）
     UPDATE items SET active_holders = active_holders + 1, total_granted = total_granted + 1
     if item.kind == title && settings.auto_activate_title && 用户无激活头衔: wear::activate_title(uid, grant_id)
  publish medal.granted；cache::invalidate(uid)；if notify_on_grant: notify.send(uid, "medals.granted", {item}, None)
  idempotency.put；return result
```

**source / source_ref 规则**：

| source | source_ref |
|---|---|
| `admin` | `admin:<request_uuid>:<user_id>`（批量授予时每个用户一条） |
| `achievement` | `ach:<rule_id>:<user_id>`；规则 `repeatable = true` 时 `ach:<rule_id>:<user_id>:<n>` |
| `shop` | `shop:<caller_key>`（caller_key = shop 传入的幂等键） |
| `plugin` | `plugin:<caller_plugin>:<idempotency_key>` |

**收回**：

```
revoke(uid, medal_id, reason, cause, idem):
  g = SELECT … FROM grants WHERE user_id AND medal_id AND state='active' FOR UPDATE；无 → 幂等成功（返回 revoked=false）
  UPDATE grants SET state='revoked', ended_at=now, end_reason=reason
  UPDATE items SET active_holders = active_holders - 1
  wear::on_grant_ended(uid, g)        // 取消佩戴；若为激活头衔则清除并 users.set_title(uid, None)
  publish medal.revoked{cause}；cache::invalidate(uid)
```

**过期**（cron `expire_grants`，tx manual，每批 1000）：

```
loop:
  rows = SELECT id, user_id, medal_id FROM grants WHERE state='active' AND expires_at <= now
         ORDER BY expires_at LIMIT 1000 FOR UPDATE SKIP LOCKED
  for g in rows: 同 revoke 但 state='expired'，cause='expired'
  commit；rows 为空则结束
```

### 1.3 wear（佩戴与头衔）

```
set_worn(uid, grant_ids: Vec<u64>):
  len ≤ settings.max_worn，否则 medals.too_many_worn；不得重复
  每个 grant：属于 uid、state=active、item.kind=medal 且 wearable，否则 medals.not_wearable
  DELETE FROM worn WHERE user_id = uid；INSERT worn(user_id, position, grant_id) …
  cache::invalidate(uid)

activate_title(uid, grant_id | None):
  None → DELETE titles；users.set_title(uid, None)
  grant 属于 uid、state=active、kind=title，否则 medals.not_a_title
  UPSERT titles(user_id, grant_id, custom_text = null)
  name = terms.get("medals.item."+medal_id, site.default_locale).name
  users.set_title(uid, Some(name))              // identity 保存显示文本
  publish medal.title_changed{user_id, medal_id, custom:false}

set_custom_title(uid, text, idem):
  text = nfc(trim(text))；去控制字符与双向控制符（U+202A–U+202E、U+2066–U+2069）
  1 ≤ grapheme_len(text) ≤ settings.custom_title.max_len，否则 medals.title_invalid
  （钩子 user.before_title_change 合入后：hooks.run，deny → 返回处理者错误码）
  UPSERT titles(user_id, grant_id = null, custom_text = text)；users.set_title(uid, Some(text))
  publish medal.title_changed{custom:true}
```

说明：头衔物品的显示名在激活时按站点默认语言渲染后写入 identity；管理员在术语后台改名后，`terms.updated` 不触发批量回写（量大且非必要），用户重新激活或下一次 `eval_stat_achievements` 顺带刷新（§1.5 末尾）。

### 1.4 display（展示快照）

```
show_many(user_ids ≤ 100) -> Vec<UserDisplay{user_id, title?, worn:[{medal_id, icon_url, rarity, name_key}]}>:
  vals = redis.pipeline(HGETALL disp:<uid> for uid)
  miss = 未命中的 uid
  if miss: SELECT w.user_id, w.position, g.medal_id, i.icon_path, i.rarity
           FROM worn w JOIN grants g ON g.id = w.grant_id AND g.state='active'
           JOIN items i ON i.id = g.medal_id
           WHERE w.user_id = ANY($1) ORDER BY w.user_id, w.position
           + SELECT user_id, grant_id, custom_text FROM titles WHERE user_id = ANY($1)
     回写 disp:<uid>（TTL 3600 s；无佩戴也写空标记，防穿透）
  名称不在快照中渲染，只返回术语键，由前端 t() 渲染（随语言变化）
```

`cache::invalidate(uid)` = `DEL disp:<uid>`，在授予、收回、过期、佩戴、头衔变化时调用。

### 1.5 achievements（成就）

**规则定义**（`rules.definition`，JSON，`schemas/achievement.v1.json`）：

```json
{
  "schema": 1,
  "kind": "event",
  "medal_id": 12,
  "visible": true,
  "trigger": {
    "event": "torrent.created",
    "user_field": "uploader_id",
    "where": [ { "field": "anonymous", "op": "eq", "value": false },
               { "field": "size", "op": "gte", "value": 1073741824 } ]
  },
  "counter": { "measure": "count", "gte": 100 },
  "decrement_on": null,
  "repeatable": false
}
```

```json
{
  "schema": 1,
  "kind": "stat",
  "medal_id": 13,
  "visible": true,
  "stat": { "source": "accounting.v_user_totals", "field": "uploaded", "op": "gte", "value": 10995116277760 },
  "revoke_on_loss": false
}
```

| 字段 | 约束 |
|---|---|
| `kind` | `event` / `stat` |
| `trigger.event` | 必须是 §1.5.1 白名单中的事件 |
| `trigger.user_field` | 必须是该事件白名单中的用户字段 |
| `trigger.where` | ≤ 10 个谓词，字段必须在该事件的可用字段内 |
| `counter.measure` | `count` 或 `sum:<field>`（数值字段） |
| `counter.gte` | 1～10^15 |
| `decrement_on` | null 或 `torrent.deleted`（仅 `trigger.event = torrent.created` 时允许） |
| `repeatable` | true 时达到阈值后计数器清零并可再次授予（如“每签到 100 天得一枚”） |
| `stat.source` / `stat.field` | 只能是 §1.5.2 白名单中的视图字段 |

语义校验：`medal_id` 存在且 active；同一 `medal_id` 最多 5 条规则；全部规则 ≤ 200 条。

#### 1.5.1 事件白名单

| 事件 | user_field | 可用字段 |
|---|---|---|
| `torrent.created` | `uploader_id` | `size`、`type_id`、`anonymous`、`status` |
| `traffic.snatch_completed` | `user_id` | `torrent_id` |
| `checkin.checked_in` | `user_id` | `streak`、`reward` |
| `request.filled` | `filler_id` | `request_id` |
| `level.promoted` | `user_id` | `to_class`、`from_class` |
| `comment.created` | `author_id` | `target` |
| `forum.post_created` | `author_id` | `topic_id` |
| `subtitle.uploaded` | `uploader_id` | `language` |
| `invite.redeemed` | `inviter_id` | — |
| `exam.passed` | `user_id` | `exam_id` |

#### 1.5.2 统计视图白名单

| 视图 | 字段 |
|---|---|
| `accounting.v_user_totals` | `uploaded`、`downloaded`、`seed_secs`、`leech_secs` |
| `ledger.v_balance` | `balance`（需额外条件 `currency = '<code>'`，定义中 `stat.currency` 必填） |
| `identity.v_user_public` | `account_age_days`（由 `now() - created_at` 计算） |

#### 1.5.3 事件处理

```
on_event(evt):                                   // 所有 ach_* 订阅共用
  rules = 缓存的 active event 规则（kv "rules:ver" + PG 读取；每次调用读 PG：规则 ≤ 200，命中索引 rules_event_idx）
  for r in rules where r.trigger.event == evt.type:
     uid = evt.payload[r.trigger.user_field]；缺失或 null（匿名发布的 uploader 仍有值，但 where 可排除）→ continue
     if !predicate::eval(r.trigger.where, evt.payload): continue
     inc = r.counter.measure == count ? 1 : evt.payload[field] as i64（缺失视为 0）
     row = INSERT INTO counters(rule_id, user_id, value, cycle) VALUES (r.id, uid, inc, 0)
           ON CONFLICT (rule_id, user_id) DO UPDATE SET value = counters.value + EXCLUDED.value, updated_at = now()
           RETURNING value, cycle
     if row.value >= r.counter.gte:
        source_ref = r.repeatable ? "ach:"+r.id+":"+uid+":"+row.cycle : "ach:"+r.id+":"+uid
        grants::grant({source: achievement, source_ref, idempotency_key: source_ref, …})
          // limit_reached / already_held(reject) 时记录 counters.blocked_reason，不重试
        if r.repeatable: UPDATE counters SET value = value - r.counter.gte, cycle = cycle + 1
on torrent.deleted（decrement_on 规则）：
  需要知道被删种子的 uploader：事件载荷只有 torrent_id → 查 torrent.v_torrent_public（已删种子不可见）
  ⇒ 本插件在 ach_torrent_created 中把 (torrent_id → uploader_id, rule_ids) 记入 counted_torrents 表；删除时据此扣减（不低于 0）
```

内核 inbox 保证同一事件对本插件只产生一次数据库副作用（计数器与授予在同一事务）。

#### 1.5.4 统计评估（cron `eval_stat_achievements`，tx manual）

```
for r in active stat rules:
  cursor = 0
  loop:
    rows = SELECT v.user_id FROM <view> v
           WHERE v.<field> <op> $value [AND v.currency = $cur] AND v.user_id > $cursor
             AND NOT EXISTS (SELECT 1 FROM grants g WHERE g.source_ref = 'ach:'||$rid||':'||v.user_id)
           ORDER BY v.user_id LIMIT 2000
    for uid in rows: grant(…)
    commit；cursor = last；rows 为空则 break
  if r.revoke_on_loss:
    同样分批：持有 source_ref 'ach:<rid>:%' 且 active 的用户中，视图不再满足条件者 → revoke(cause = condition_lost)
顺带：刷新头衔显示文本（激活的头衔物品，名称术语覆盖值变化时 users.set_title），每次最多 5000 个
```

视图字段名映射在代码中写死（白名单），用户输入只决定白名单内的选项与数值参数，SQL 始终参数化。

#### 1.5.5 回填（延迟任务 `backfill`）

- `stat` 规则：立即调度一次只针对该规则的 `eval_stat_achievements` 逻辑。
- `event` 规则：调用内核回放（`kernel.events.replay` 权限，由管理员在内核后台发起，订阅名 `ach_*`），本插件只提供“规则创建时间之前的事件是否计入”的选项 `count_history`；默认 false（只对新事件生效）。理由：回放会重复投递所有成就订阅的历史事件，计数器会对**已有规则**重复累加——因此回放前必须由本插件把目标订阅切换为“仅对 backfill 规则生效”模式（kv `backfill:<subscription>` = rule_id），回放结束后清除。

### 1.6 lifecycle

- `on_user_deleted`：purge → 删除 `grants`、`worn`、`titles`、`counters`、`counted_torrents`，相应物品 `active_holders` 减少；soft → `DEL disp:<uid>`。
- `expire_grants` 同时清理 7 天前替换下来的旧图标（blob 删除）与 7 天前的幂等记录。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:medals@0.1.0`）

```wit
package pt:medals@0.1.0;

interface medals {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  enum item-kind { medal, badge, title }
  enum rarity { common, rare, epic, legendary }

  record item-def {
    id: u64, kind: item-kind, slug: string, name-key: string, icon-url: option<string>,
    rarity: rarity, default-days: option<u32>, limit: option<u64>, active-holders: u64,
    wearable: bool, hidden: bool, active: bool,
  }
  record item-filter { kind: option<item-kind>, active-only: bool }

  record holding {
    grant-id: u64, item: item-def, granted-at: timestamp-ms, expires-at: option<timestamp-ms>,
    source: string, worn-position: option<u8>, is-title: bool,
  }
  record worn-item { medal-id: u64, name-key: string, icon-url: option<string>, rarity: rarity }
  record user-display { user-id: user-id, title: option<string>, worn: list<worn-item> }

  record grant-request {
    user-id: user-id, medal-id: u64, reason: string,
    expires-at: option<timestamp-ms>, idempotency-key: string,
  }
  record grant-result { grant-id: u64, renewed: bool, expires-at: option<timestamp-ms> }

  of-user: func(user: user-id, include-hidden: bool) -> result<list<holding>, plugin-error>;
  worn-many: func(users: list<user-id>) -> result<list<user-display>, plugin-error>;
  definitions: func(filter: item-filter) -> result<list<item-def>, plugin-error>;
  grant: func(req: grant-request) -> result<grant-result, plugin-error>;
  revoke: func(user: user-id, medal-id: u64, reason: string, idempotency-key: string) -> result<bool, plugin-error>;
  set-title: func(user: user-id, medal-id: option<u64>) -> result<_, plugin-error>;
  set-custom-title: func(user: user-id, text: string, idempotency-key: string) -> result<_, plugin-error>;
  /// 评审 R1 F-06：用户当前有效（未过期、未撤销）物品的 bonus_factor_permille 之和，截断到 settings.bonus_factor_cap_permille（默认 500）；
  /// 结果缓存在 p:medals:bf:<uid>（TTL 300 s，grant / revoke / 过期时删除）；bonus 结算时批量调用 bonus-factor-many
  bonus-factor: func(user: user-id) -> result<u32, plugin-error>;
  bonus-factor-many: func(users: list<user-id>) -> result<list<tuple<user-id, u32>>, plugin-error>;
}
```

| 方法 | 作用域 | 错误码 |
|---|---|---|
| `of-user`、`worn-many`、`definitions` | — | `medals.too_many_ids`（> 100） |
| `grant` | `grant` | `medals.item_not_found`、`medals.item_inactive`、`medals.user_invalid`、`medals.limit_reached`、`medals.already_held`、`kernel.idempotency_key_reused` |
| `revoke` | `grant` | — |
| `set-title` | `grant` | `medals.not_a_title`、`medals.grant_not_found` |
| `set-custom-title` | `grant` | `medals.title_invalid`、钩子处理者错误码 |

### 2.4 HTTP API

**GET `/v1/me`** →

```json
{ "holdings": [ { "grant_id": 881, "medal_id": 12, "kind": "medal", "name_key": "medals.item.12",
                  "icon_url": "/blob/plugins/medals/icons/12-9f2c1a.png", "rarity": "rare",
                  "granted_at": "2026-09-01T10:00:00Z", "expires_at": null, "source": "achievement",
                  "worn_position": 0 } ],
  "title": { "medal_id": 30, "custom_text": null },
  "max_worn": 3 }
```

**GET `/v1/users/{user_id}`**：同上，但不含 `hidden` 物品（查看者有 `medals.grant` 且 `show_hidden_to_staff` 时包含）。

**GET `/v1/show?user_ids=1,2,3`**（≤ 100）→ `{ "items": [ { "user_id": 1, "title": "种子大师", "worn": [ { "medal_id": 12, "name_key": "medals.item.12", "icon_url": "…", "rarity": "rare" } ] } ] }`；响应带 `Cache-Control: private, max-age=60`。

**PUT `/v1/me/worn`** 请求 `{ "grant_ids": [881, 902] }` → 204。错误：422 `medals.too_many_worn` / `medals.not_wearable`。

**PUT `/v1/me/title`** 请求 `{ "grant_id": 905 }` 或 `{ "grant_id": null }` → 204。

**GET `/v1/achievements`** → `{ "items": [ { "rule_id": 3, "medal_id": 12, "name_key": "medals.item.12", "kind": "event", "progress": 37, "target": 100, "achieved": false } ] }`（`visible = false` 的规则不返回；stat 类 progress 取视图当前值）。

**POST `/v1/admin/items`** 请求：

```json
{ "kind": "medal", "slug": "hundred_uploads", "name_zh": "百种勋章", "name_en": "Centurion",
  "description": "发布 100 个种子", "rarity": "rare", "default_days": null, "limit": null,
  "on_regrant": "reject", "wearable": true, "hidden": false, "sort": 10 }
```

→ 201 `{ "id": 12 }`。

**POST `/v1/admin/grants`**（`Idempotency-Key` 必填）请求 `{ "medal_id": 12, "user_ids": [1, 2], "days": 30, "reason": "活动奖励" }` → `{ "results": [ { "user_id": 1, "grant_id": 990, "renewed": false }, { "user_id": 2, "error": "medals.already_held" } ] }`（≤ 1000 个用户）。

**POST `/v1/admin/grants/{grant_id}/revoke`** 请求 `{ "reason": "违规" }` → 204。

**POST `/v1/admin/achievements`** 请求为 §1.5 规则 JSON → 201；校验失败 422 `kernel.validation_failed`，`details.errors[]` 为 `{path, code, message}`。

**POST `/v1/admin/achievements/{id}/backfill`** 请求 `{ "count_history": false }` → 202 `{ "job_id": "…" }`。

### 2.5 MCP 工具

`list_my_medals`：入参 `{}`；出参 `{ holdings: [{name, kind, rarity, granted_at, expires_at, worn}] , title }`（名称已按站点术语渲染）；write = false。

## 3. 数据库设计

### 3.1 PostgreSQL（schema `medals`）

```sql
CREATE TABLE medals.items (
    id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind             text NOT NULL CHECK (kind IN ('medal', 'badge', 'title')),
    slug             text NOT NULL UNIQUE,
    description      text NOT NULL DEFAULT '',
    icon_path        text,
    rarity           text NOT NULL DEFAULT 'common' CHECK (rarity IN ('common','rare','epic','legendary')),
    default_days     integer CHECK (default_days BETWEEN 1 AND 3650),
    item_limit       bigint CHECK (item_limit >= 1),
    on_regrant       text NOT NULL DEFAULT 'reject' CHECK (on_regrant IN ('extend','latest','reject')),
    wearable         boolean NOT NULL DEFAULT false,
    hidden           boolean NOT NULL DEFAULT false,
    sort             integer NOT NULL DEFAULT 100,
    active           boolean NOT NULL DEFAULT true,
    active_holders   bigint NOT NULL DEFAULT 0 CHECK (active_holders >= 0),
    total_granted    bigint NOT NULL DEFAULT 0,
    name_revision    integer NOT NULL DEFAULT 1,
    bonus_factor_permille integer NOT NULL DEFAULT 0 CHECK (bonus_factor_permille BETWEEN 0 AND 1000),  -- 评审 R1 F-06：持有期间的魔力加成（‰）
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT items_wearable_medal_only CHECK (NOT wearable OR kind = 'medal')
);

CREATE TABLE medals.grants (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id         bigint NOT NULL,
    medal_id        bigint NOT NULL REFERENCES medals.items (id),
    state           text NOT NULL CHECK (state IN ('active', 'expired', 'revoked')),
    source          text NOT NULL CHECK (source IN ('admin', 'achievement', 'shop', 'plugin')),
    source_ref      text NOT NULL UNIQUE,
    reason          text NOT NULL DEFAULT '',
    granted_by      text NOT NULL,            -- 'user:<id>' / 'plugin:<id>' / 'system'
    expires_at      timestamptz,
    renewed_count   integer NOT NULL DEFAULT 0,
    ended_at        timestamptz,
    end_reason      text,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX grants_one_active_idx ON medals.grants (user_id, medal_id) WHERE state = 'active';
CREATE INDEX grants_user_idx ON medals.grants (user_id, state);
CREATE INDEX grants_expiry_idx ON medals.grants (expires_at) WHERE state = 'active' AND expires_at IS NOT NULL;
CREATE INDEX grants_medal_idx ON medals.grants (medal_id, state, created_at DESC);

CREATE TABLE medals.worn (
    user_id   bigint NOT NULL,
    position  smallint NOT NULL CHECK (position BETWEEN 0 AND 9),
    grant_id  bigint NOT NULL REFERENCES medals.grants (id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, position),
    UNIQUE (grant_id)
);

CREATE TABLE medals.titles (
    user_id      bigint PRIMARY KEY,
    grant_id     bigint REFERENCES medals.grants (id) ON DELETE SET NULL,
    custom_text  text,
    updated_at   timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT titles_one_kind CHECK ((grant_id IS NULL) <> (custom_text IS NULL))
);

CREATE TABLE medals.rules (
    id           bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind         text NOT NULL CHECK (kind IN ('event', 'stat')),
    medal_id     bigint NOT NULL REFERENCES medals.items (id),
    trigger_event text,                       -- kind = event 时为白名单事件名
    definition   jsonb NOT NULL,
    active       boolean NOT NULL DEFAULT true,
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX rules_event_idx ON medals.rules (trigger_event) WHERE active AND kind = 'event';

CREATE TABLE medals.counters (
    rule_id         bigint NOT NULL REFERENCES medals.rules (id) ON DELETE CASCADE,
    user_id         bigint NOT NULL,
    value           bigint NOT NULL DEFAULT 0,
    cycle           integer NOT NULL DEFAULT 0,
    blocked_reason  text,
    updated_at      timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (rule_id, user_id)
);
CREATE INDEX counters_user_idx ON medals.counters (user_id);

CREATE TABLE medals.counted_torrents (
    torrent_id  bigint NOT NULL,
    rule_id     bigint NOT NULL REFERENCES medals.rules (id) ON DELETE CASCADE,
    user_id     bigint NOT NULL,
    PRIMARY KEY (torrent_id, rule_id)
);

CREATE TABLE medals.idempotency (
    caller       text NOT NULL,
    key          text NOT NULL,
    request_hash bytea NOT NULL,
    response     jsonb NOT NULL,
    created_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (caller, key)
);
```

数据量：`grants` ≤ 500 万行；`counters` ≤ 规则数 × 活跃用户（200 × 30 万上限，实际远小，按 600 万行估算）；`counted_torrents` 只为带 `decrement_on` 的规则写入。

### 3.2 Redis（前缀 `p:medals:`）

| 键 | 类型 | TTL | 说明 |
|---|---|---|---|
| `disp:<uid>` | HASH | 3600 s | 展示快照：`title`、`worn`（JSON）；空值写 `_empty=1` |
| `rules:ver` | STRING | 无 | 规则版本号（规则变更时 INCR）；WASM 实例不跨调用缓存规则，此键只用于前端成就列表的缓存失效 |

## 6. 安全设计

| 点 | 措施 |
|---|---|
| SVG XSS | 白名单净化；前端以 `<img>` 加载（不内联），`Content-Type: image/svg+xml` 且 blob 服务带 `Content-Security-Policy: sandbox` |
| 头衔注入 | 长度、字符清洗；前端按纯文本渲染；钩子留给 moderation |
| 越权授予 | 服务 `grant` 需作用域；HTTP 需 `medals.grant`；批量授予写审计 |
| 隐藏物品 | 非本人、非管理员不可见 |
| SQL | 视图与字段只来自白名单映射；参数化 |

## 7. 性能设计

- `show_many`：Redis pipeline 一次往返；缓存未命中时两条 `ANY($1)` 查询。
- 事件计数：每事件只读取该事件类型的规则（索引），一次 upsert；平均 < 5 ms。
- 统计评估：每规则按 user_id 键集分页，2000/批；视图上的条件依赖提供方索引（`accounting.v_user_totals` 基表需 `uploaded` 等字段索引——若无，对 30 万行全扫描也在秒级，可接受）。
