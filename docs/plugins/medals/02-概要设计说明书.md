## 1. 设计目标与原则

1. **授予与售卖分离**：本插件只管“谁持有什么”；价格、扣款、库存展示由 shop 负责（NexusPHP 耦合在一起的改进）。
2. **名称走术语**：每个物品登记动态术语键 `medals.item.<id>`，站点在术语后台改名，不在本插件重复维护名称。
3. **成就数据驱动**：成就规则用与 anticheat 相同的谓词格式（`{field, op, value}`），后台可视化编辑，无需发版本。
4. **展示快**：列表页批量查询走 Redis 缓存的“展示快照”（佩戴勋章 + 头衔），授予/收回/佩戴变化时失效。
5. **幂等**：每次授予有确定性的来源键（`source_ref`），重复事件、重复服务调用不会重复授予。

## 2. 总体结构

### 2.1 在整体架构中的位置

```
shop / newbie-exam / 管理员 ──ctx.medals.grant──►┐
事件（torrent.created、checkin.checked_in …）──►  medals (WASM) ──ctx.users.set_title──► identity
cron（统计阈值评估）── 只读视图 ──────────────►┘    │ ctx.terms.define / retire
                                                     │ events: medal.granted / revoked / title_changed
                                                     ▼
                                       PG schema medals / Redis p:medals:*
前端插槽（个人页、论坛）──GET /show?user_ids=…──► 展示快照缓存
```

## 5. 关键流程

### 5.1 授予

```
grant(req{user_id, medal_id, reason, source, source_ref, expires_at?, idempotency_key}):
  幂等命中 → 返回首次结果
  item = items[medal_id]（active）
  锁 item 行（限量时）→ 有效持有数 < limit
  已有有效授予？→ 按 item.on_regrant：extend（延长）/ latest（取较晚到期）/ reject
  INSERT grants（source_ref 唯一，冲突 → 返回已有）
  title 类且用户当前无头衔 → 自动激活（设置 auto_activate_title）
  publish medal.granted；DEL disp:<uid>；可选 notify
```

### 5.2 事件计数成就

```
on ach_torrent_created(evt):
  for rule in rules where trigger.event == evt.type and active:
     uid = rule.trigger.user_field 取值
     if !predicate::eval(rule.trigger.where, evt.payload): continue
     inc = rule.counter.measure（count=1 / sum:<path>）
     UPDATE counters SET value = value + inc … RETURNING value      // inbox 保证事件只处理一次
     if value >= rule.counter.gte:
        grant(source = achievement, source_ref = "ach:<rule_id>:<uid>[:<cycle>]")
```

### 5.3 统计阈值成就

```
cron eval_stat_achievements（tx manual）:
  for rule in rules where kind == stat:
     按 user_id 分批 5000：
        SELECT user_id FROM <view> WHERE <field> >= <threshold> AND user_id > $cursor ORDER BY user_id LIMIT 5000
        排除已持有（source_ref 存在）→ 批量 grant；commit
     revoke_on_loss 开启时：对持有者中不再满足的用户收回
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论与理由 |
|---|---|---|---|
| DD-MEDAL-1 | 购买在哪里实现 | medals 自带价格 / shop | shop：避免两个插件各自实现扣款与退款；medals 的 `definitions` 提供可售物品 |
| DD-MEDAL-2 | 成就规则表达 | 代码写死 / CEL / 谓词 JSON | 谓词 JSON，与 anticheat DD-ACH-3 一致：可校验、可视化、执行有界 |
| DD-MEDAL-3 | 统计类成就 | 订阅高频事件（`traffic.seeding_snapshot_taken` 每小时 30 万条）实时累计 / 每日批量用视图评估 | 每日批量：避免高频事件负载；“达到上传量”类成就晚一天授予可以接受 |
| DD-MEDAL-4 | 头衔存储 | 只在 medals / 同步到 identity | 同步到 identity（`set_title`）：用户名渲染只依赖 identity 的 `UserSummary.title`，不必每个列表都查 medals |
| DD-MEDAL-5 | 幂等键 | 随机 / 确定性 `source_ref` | 确定性：成就 `ach:<rule>:<uid>`、shop `shop:<order_id>`、管理员 `admin:<request_id>:<uid>`；`grants.source_ref` 唯一索引兜底 |
| DD-MEDAL-6 | 计数器与事件重复 | 计数器自己去重 / 依赖内核 inbox | 依赖 inbox：订阅方数据库副作用对同一事件只发生一次（平台约定），计数更新与 inbox 同事务 |
| DD-MEDAL-7 | 删除种子是否扣减发种计数 | 不扣 / 可选扣 | 规则可选 `decrement_on: "torrent.deleted"`，默认不扣（已授予的不收回） |

## 实现说明（2026-10-17，v0.1.0，开站计划 M4.2）

- 物品两类：`medal`（可佩戴多枚，`max_worn` 设置，默认 5）与 `title`（同时激活一个）；可限量（`max_holders`，按有效持有人数）、设有效天数、隐藏（不在他人勋章墙展示）、停用。名称直接存于 `items.name`，未登记动态术语键。徽章（badge）未单独建类型。
- 授予：`grants.source_ref` 唯一（成就 `ach:<rule>:<uid>`、管理员 `admin:<actor>:<ms>:<uid>`、插件 `<caller>:<idempotency_key>`），重复授予返回首次结果。已持有时再次授予新增一条授予记录，到期时间按物品有效期从当前到期时间顺延（永久持有不变）；持有判定为“任一授予未收回且未到期”，到期无需扫描任务。
- 头衔只在 medals 内保存并由前端插槽展示，未同步到 identity（`ctx.users.set_title` 与 `user.before_title_change` 钩子尚不存在）；用户在个人资料中自填的 `title` 仍独立存在。
- 成就规则只支持两类：`event`（订阅白名单事件，计量 `count` / `sum:<字段>` / `max:<字段>`，达到阈值授予；匿名发布不计入）与 `stat`（`accounting.v_user_totals` 的 uploaded / downloaded / seed_secs / completed_count / seeding_count，每日 03:30 评估、后台可立即评估一批 5000 人）。未实现谓词过滤、`revoke_on_loss`、回填任务、周期性成就。预置 5 枚成就勋章及规则。
- 服务 `ctx.medals`：`of_user`、`worn_many`、`definitions`、`grant`（作用域 `grant`，需 `idempotency_key`）、`revoke`（作用域 `grant`，按用户 + 物品收回全部有效授予）。`set_title` / `set_custom_title` 未实现。
- 获得新勋章时经 `ctx.notify` 通知（类别 `account`，可在设置关闭）；用户删除时收回全部授予并清理展示与计数。
- 前端：个人页 `user.profile.header`（头衔 + 佩戴勋章）、`user.profile.badges`（完整勋章墙，折叠）、用户菜单“我的勋章”、`/p/medals/`（佩戴设置、成就进度）、`/admin/p/medals/`（物品与图标、持有者与收回、批量授予、成就规则）。`user.name.decorations` 与 `forum.post.footer` 插槽前端尚未渲染，暂不提供。
