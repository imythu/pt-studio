## 1. 引言

### 1.1 目的

定义勋章插件 `medals` 的需求。勋章、徽章、头衔是 PT 站重要的荣誉与消费体系，本插件统一管理它们的定义、授予、佩戴、展示与成就自动授予。

### 1.2 范围

包含：

- 三类荣誉物品：**勋章**（medal，可佩戴展示在用户名旁）、**徽章**（badge，展示在个人页，不占佩戴位）、**头衔**（title，同一时刻最多一个，显示为用户称号）；
- 定义管理（名称走动态术语键、图标、稀有度、有效期、限量、是否可佩戴、是否隐藏）；
- 授予来源：管理员手动、成就自动、商城购买（shop 调用）、其他插件调用（活动、考核）；
- 有效期与过期回收；收回；
- 佩戴与展示（个人页、用户名旁、论坛帖子签名档）；
- 成就规则（数据驱动）：事件计数类、统计阈值类；
- 自定义头衔（由商城售卖“改头衔卡”后调用）。

不包含：

- 商城售卖流程与扣款（shop）；
- 等级（levels）；等级名不是头衔。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 物品 | 勋章、徽章、头衔的统称（item） |
| 授予记录 | 某用户持有某物品的一条记录（grant），有来源、有效期、状态 |
| 佩戴 | 用户选择在用户名旁展示的勋章（最多 N 个） |
| 成就 | 满足条件自动授予物品的规则 |

### 1.4 参考资料

- docs/platform/、docs/plugins/terms/、docs/plugins/anticheat/03 §1.2（谓词格式）
- NexusPHP 1.7+ 勋章（medal）功能：后台定义勋章、魔力值购买、有效期、佩戴展示
- UNIT3D：achievements（基于 `gstvo/laravel-achievements` 思路的进度型成就）、badges
- Gazelle/OPS：用户徽章（badges，如捐赠、贡献者）、自定义头衔（需特权）

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM，ID `medals`，缩写 `MEDAL`。
- 提供：`ctx.medals`（single）。
- 依赖：`ctx.users`（设置头衔）、`ctx.terms`（动态术语键 define/retire）；可选 `ctx.notify`（获得勋章通知）。
- 只读视图：`identity.v_user_public`、`accounting.v_user_totals`、`ledger.v_balance`（统计阈值类成就）。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 查看自己的勋章墙；选择佩戴；查看成就进度；在商城购买勋章（shop） |
| 访客（已登录用户看他人） | 在他人个人页、论坛帖子旁看到佩戴的勋章与头衔 |
| 管理员 | 定义物品；手动授予 / 收回；配置成就规则；查看持有统计 |
| 其他插件 | shop 购买履约；newbie-exam 通过考核授予徽章；活动插件授予限时勋章 |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP（medal） | 勋章表定义名称、图片、价格、有效期（天）、库存；用户用魔力值购买；`user_medals` 记录过期时间与是否佩戴；个人页与用户名旁显示 | 简单直观，带动魔力值消费 | 购买逻辑与勋章耦合在一起；名称写死不支持多语言；没有自动成就 | **采纳**定义字段（价格交给 shop）、有效期、库存（限量）、佩戴；**改进**：购买交给 shop，本插件只负责授予；名称走术语键；增加成就自动授予 |
| UNIT3D（achievements） | 预定义成就类（上传 N 个种子、发表 N 条评论等），按进度累计，达成后通知 | 进度可视化，激励明确 | 成就写死在代码中，新增要发版本；计数器逐条事件 +1，回填困难 | **采纳**进度型成就与进度展示；**改进**：成就规则数据驱动；提供“统计阈值”类型，用视图批量计算，便于回填 |
| Gazelle/OPS（badges、custom title） | 徽章由站方授予（捐赠者、贡献者等）；自定义头衔需要特权或购买 | 头衔与徽章分离 | 头衔无审核易出现违规内容 | **采纳**头衔与徽章分离；**改进**：自定义头衔有长度限制、敏感词过滤钩子（交给 moderation），可由管理员一键清除 |

### 2.4 约束与假设

1. WASM 插件只能订阅清单中静态声明的事件，因此成就规则只能基于清单中列出的事件（见详细设计 §1.5 的事件白名单）；新增事件来源需要发插件新版本。
2. 头衔最终存储在 identity（`ctx.users.set_title`），本插件负责“哪个头衔物品处于激活状态”。
3. 规模：30 万用户；授予记录预计 ≤ 500 万行；佩戴展示在论坛、种子列表等列表页需要批量查询。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-MEDAL-001 | 物品定义 | 管理员创建 / 编辑 / 停用物品：类型（medal/badge/title）、名称（术语键 `medals.item.<id>`）、描述、图标、稀有度、默认有效期、限量、可佩戴、隐藏、排序 | P0 | 创建后可在后台列表看到；名称在术语管理中可改 |
| FR-MEDAL-002 | 图标上传 | 图标上传到对象存储（PNG/WebP/SVG ≤ 256 KiB；SVG 须净化） | P1 | 上传含脚本的 SVG 被拒绝或净化 |
| FR-MEDAL-003 | 手动授予 | 管理员向一个或多个用户授予物品，可指定有效期与原因 | P0 | 授予后用户勋章墙可见；事件 `medal.granted` |
| FR-MEDAL-004 | 服务授予 | `grant(user_id, medal_id, reason, expires_at?, idempotency_key)` 供 shop、newbie-exam 等调用 | P0 | 同一幂等键只授予一次 |
| FR-MEDAL-005 | 重复授予 | 已持有未过期的同一物品时再授予：延长有效期（可配置为“叠加”或“取较晚者”）或拒绝 | P1 | 按物品配置的 `on_regrant` 行为执行 |
| FR-MEDAL-006 | 限量 | 物品设置限量 N 时，当前有效持有数达到 N 后拒绝授予 | P1 | 并发授予不超过 N |
| FR-MEDAL-007 | 收回 | 管理员或服务收回某用户的物品，记录原因；收回后取消佩戴、头衔恢复为空或前一个头衔 | P0 | 事件 `medal.revoked`；佩戴列表不再包含 |
| FR-MEDAL-008 | 过期 | 到期自动失效，取消佩戴，头衔失效 | P0 | 到期后 1 小时内处理 |
| FR-MEDAL-009 | 佩戴 | 用户选择最多 `max_worn`（默认 3）个可佩戴勋章并排序 | P0 | 超过上限返回 `medals.too_many_worn` |
| FR-MEDAL-010 | 头衔激活 | 用户从持有的头衔物品中选择一个激活；激活后通过 `ctx.users.set_title` 更新显示 | P0 | 用户名旁显示所选头衔（渲染后的术语名） |
| FR-MEDAL-011 | 自定义头衔 | `set_custom_title(user_id, text, idempotency_key)`（shop 改头衔卡调用）：长度 1～20 字符、去控制字符、经 moderation 钩子检查 | P1 | 违规内容被拒；管理员可清除 |
| FR-MEDAL-012 | 勋章墙 | 用户个人页展示持有的勋章与徽章（隐藏物品仅本人可见），含获得时间、到期时间 | P0 | 他人查看时不显示隐藏物品 |
| FR-MEDAL-013 | 批量展示 | 列表页（论坛、种子评论）批量查询多个用户的佩戴勋章与头衔 | P0 | 一次查询 100 个用户 p99 < 30 ms |
| FR-MEDAL-014 | 事件计数成就 | 规则：在指定事件发生时对用户计数（或累加字段），满足谓词时计入，达到阈值授予物品 | P1 | 上传第 100 个种子时获得“百种”勋章 |
| FR-MEDAL-015 | 统计阈值成就 | 规则：周期性用只读视图评估（上传量、做种时间、注册天数、余额等），达到阈值授予 | P1 | 上传量达到 10 TiB 后下一次评估时授予 |
| FR-MEDAL-016 | 成就进度 | 用户查看成就进度（当前值 / 目标值） | P2 | 进度与计数器一致 |
| FR-MEDAL-017 | 成就回填 | 管理员新建成就后可触发回填：对统计阈值类全量评估；事件计数类从历史事件回放（经内核回放）或标记“仅对新事件生效” | P2 | 回填后满足条件的用户获得物品，且只获得一次 |
| FR-MEDAL-018 | 成就撤回条件 | 可选：统计条件不再满足时自动收回（默认不收回） | P2 | 开启后条件不满足时下次评估收回 |
| FR-MEDAL-019 | 获得通知 | 获得物品时通过 notify 通知（可在设置中关闭） | P2 | 收到通知，模板使用术语 |
| FR-MEDAL-020 | 用户删除 | 订阅 `user.deleted`，purge 时删除数据 | P1 | purge 后无记录 |
| FR-MEDAL-021 | 统计 | 管理员查看每个物品的有效持有数、累计授予数 | P2 | 与数据库一致 |
| FR-MEDAL-022 | MCP | `list_my_medals`（读） | P2 | 返回持有物品，名称为站点术语 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-MEDAL-001 | 性能 | 批量展示查询 | 100 个用户 p99 < 30 ms（缓存命中） |
| NFR-MEDAL-002 | 性能 | 事件计数成就处理 | 单事件处理 p99 < 20 ms；规则数 ≤ 200 |
| NFR-MEDAL-003 | 可靠性 | 授予幂等 | 同一成就同一用户只授予一次；事件重复投递不重复计数 |
| NFR-MEDAL-004 | 一致性 | 限量 | 并发授予下有效持有数 ≤ 限量 |
| NFR-MEDAL-005 | 安全 | 图标与头衔 | SVG 净化；头衔文本转义、长度限制、敏感词钩子 |
| NFR-MEDAL-006 | 可扩展 | 统计阈值评估 | 30 万用户全量评估 ≤ 10 分钟，分批提交 |
| NFR-MEDAL-007 | 可观测 | 指标 | 授予/收回次数、成就命中次数、评估耗时 |

## 5. 可配置项与站点术语

运行时设置：

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `max_worn` | integer | 3 | 最多佩戴数（1～10） |
| `notify_on_grant` | bool | true | 获得时通知 |
| `custom_title.max_len` | integer | 20 | 自定义头衔最大长度 |
| `stat_eval_schedule` | string | `"30 3 * * *"` | 仅展示，实际计划在清单中固定，见详细设计 |
| `show_hidden_to_staff` | bool | true | 管理员可见隐藏物品 |

术语：`medals.medal`、`medals.badge`、`medals.title`、`medals.item.<medal_id>`（动态，define/retire）、`medals.achievement`（成就）、`medals.wall`（勋章墙）。

## 6. 外部接口需求概述

- 服务 `ctx.medals`：`of_user`、`worn_many`、`grant`、`revoke`、`set_title`、`set_custom_title`、`definitions`。
- 事件：发布 `medal.granted`、`medal.revoked`、`medal.title_changed`；订阅成就白名单事件与 `user.deleted`。
- HTTP：`/api/p/medals/v1/*`；前端插槽 `user.profile.badges`、`user.profile.header`、`forum.post.footer`；页面 `/p/medals/`。
- MCP：`list_my_medals`。
