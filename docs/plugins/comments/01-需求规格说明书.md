## 1. 引言

### 1.1 目的

定义通用评论插件 `comments` 的需求，以及全站共用的用户内容渲染器 `pt-markup`（Markdown + BBCode 安全渲染）。

### 1.2 范围

包含：对种子、作品（Group）、求种、字幕等目标的评论；楼中楼（单层回复）；引用；编辑与编辑历史；删除（软删）；@提醒；感谢 / 点赞；表情；反垃圾（频率限制、重复内容、新用户限制）；审核钩子；AI 审核（异步）；统一渲染器；分页与排序；评论计数；用户评论历史。

不包含：论坛（forum）、站内信（messages）。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 目标（target） | 被评论的对象，`TargetRef` 字符串 `"<kind>:<id>"` |
| 楼中楼 | 对某条评论的回复，只支持一层（回复的回复挂在同一楼层下，带 @） |
| 源文本 / 渲染结果 | 存储用户输入的原文与渲染后的安全 HTML |

### 1.4 参考资料

- docs/platform/conventions/security.md（XSS、CSP）、catalog/hooks.md（`comment.before_create`）
- Gazelle：comments 表按 Page（torrents、artist、collages、requests）区分，BBCode 渲染（Text 类），引用、编辑历史
- UNIT3D：polymorphic comments（commentable），Markdown + BBCode（`Joypixels` 表情），感谢（thanks）
- NexusPHP：种子评论、BBCode、编辑记录，“感谢”与“说谢谢”

## 2. 总体描述

WASM，ID `comments`，缩写 `CMT`；提供 `ctx.comments`；拥有钩子 `comment.before_create`；提供共享 crate `pt-markup`（不是插件，是 Rust 库，供 comments、forum、messages、requests、promotion 横幅等使用）。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle | 每种页面一张评论表或 Page 字段；BBCode 自研解析器 | 功能成熟 | 自研解析器历史上多次出现 XSS；多张表 | **采纳**统一表 + 目标类型；**改进**：解析后统一经白名单 HTML 净化（ammonia） |
| UNIT3D | 多态关联；Markdown + BBCode 混合 | 灵活 | 混合语法在边界情况下难以预测 | **采纳**两种语法；**改进**：每条内容只选一种语法（`markup` 字段），不混合 |
| NexusPHP | BBCode；感谢；评论楼层号 | 用户熟悉 | 渲染时拼接 HTML，CVE 中有多起 XSS | 安全渲染 + CSP |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-CMT-001 | 发表评论 | 对允许的目标发表评论（≤ 20000 字符），选择 markdown 或 bbcode | P0 | |
| FR-CMT-002 | 目标类型 | 支持 `torrent`、`group`、`request`、`subtitle`；站点可停用某类型 | P0 | |
| FR-CMT-003 | 目标校验 | 目标存在且对评论者可见；目标被锁定（由目标拥有者通过钩子拒绝）时不能评论 | P0 | |
| FR-CMT-004 | 回复 | 对评论回复（单层），回复计入楼层 | P1 | |
| FR-CMT-005 | 引用 | 引用某条评论（插入引用块，引用原文快照） | P1 | |
| FR-CMT-006 | 编辑 | 作者在 `edit_window_minutes`（默认 60，0 = 不限）内编辑；版主随时编辑；保留编辑历史 | P0 | |
| FR-CMT-007 | 删除 | 作者删除自己的评论（软删，显示“已删除”）；版主删除（记录原因） | P0 | |
| FR-CMT-008 | @提醒 | `@username` 通知被提及者（经 notify，每条评论最多提醒 10 人） | P1 | |
| FR-CMT-009 | 感谢 | 对评论点“感谢”（每人每条一次），计数 | P2 | |
| FR-CMT-010 | 表情 | 短代码（`:smile:`）与站点自定义表情包（图片） | P2 | |
| FR-CMT-011 | 安全渲染 | 渲染器白名单输出；外链 `rel="nofollow noopener ugc"`；图片只允许站内 blob 或白名单主机（或经图片代理） | P0 | XSS 测试集全部无效 |
| FR-CMT-012 | 反垃圾 | 发言频率（默认每用户 30 秒 1 条、每小时 60 条）、重复内容检测、注册不足 N 天的用户每日上限、链接数量上限 | P0 | |
| FR-CMT-013 | 审核钩子 | 发表前触发 `comment.before_create`（处理者可拒绝或修改正文） | P0 | |
| FR-CMT-014 | AI 审核 | 发表后异步交给 ai-moderation（订阅 `comment.created`），结果为建议 | P2 | |
| FR-CMT-015 | 列表 | 按楼层正序 / 倒序、按感谢数排序；游标分页 | P0 | |
| FR-CMT-016 | 计数 | `count(target)` | P0 | |
| FR-CMT-017 | 用户历史 | 用户的评论列表（他人可见，已删除的不显示） | P1 | |
| FR-CMT-018 | 管理 | 版主按用户 / 目标 / 关键词检索评论、批量删除 | P1 | |
| FR-CMT-019 | 举报入口 | 每条评论有举报按钮（reports 插件） | P1 | |
| FR-CMT-020 | 用户删除 | purge 时删除其评论正文（保留“已删除”占位以维持楼层） | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-CMT-001 | 列表性能 | 50 条/页 p99 < 50 ms（渲染结果已缓存于表中） |
| NFR-CMT-002 | 发表性能 | p99 < 200 ms（含钩子） |
| NFR-CMT-003 | 安全 | 渲染器通过 OWASP XSS 测试集与自建模糊测试 |
| NFR-CMT-004 | 容量 | 评论表 ≤ 1 亿行，按目标类型 + 时间索引 |

## 5. 可配置项与站点术语

`enabled_targets`、`edit_window_minutes`（60）、`max_length`（20000）、`rate.per_30s`（1）、`rate.per_hour`（60）、`new_user_days`（7）、`new_user_daily_limit`（20）、`max_links`（10）、`image_hosts`（[]）、`default_markup`（markdown）、`thanks_enabled`（true）。术语：`comments.name`（已登记）、`comments.thanks`（感谢）。

## 6. 外部接口需求概述

服务 `ctx.comments`（`count`、`list`、`create`、`delete`）；事件 `comment.created` / `updated` / `deleted`；钩子 `comment.before_create`；HTTP `/api/p/comments/v1/*`；插槽 `torrent.detail.tabs`、`group.detail.tabs`、`request.detail.sidebar`、`user.profile.tabs`；共享 crate `pt-markup`。
