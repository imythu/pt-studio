## 1. 模块详细设计

### 1.1 `pt-markup`（共享 crate，`crates/pt-markup`，MIT OR Apache-2.0）

```rust
pub enum Markup { Markdown, BbCode }
pub struct RenderOptions {
    pub image_hosts: Vec<String>,       // 允许的外部图片主机（https）
    pub blob_prefix: String,            // 站内图片前缀，如 "/blob/"
    pub link_base: String,              // 站点 URL，用于判断站内链接
    pub mention_resolver: Option<&dyn Fn(&str) -> Option<u64>>,   // 用户名 → user_id（存在才渲染为链接）
    pub emoji: &EmojiTable,
    pub max_quote_depth: u8,            // 默认 3
}
pub struct Rendered { pub html: String, pub text: String /* 纯文本，供搜索与摘要 */, pub mentions: Vec<u64>, pub links: u32, pub images: u32 }
pub fn render(src: &str, markup: Markup, opt: &RenderOptions) -> Rendered;
pub const RENDER_VERSION: u32 = 1;
```

**Markdown**：`pulldown-cmark`（MIT），启用表格、删除线、任务列表；**禁用原始 HTML**（`Event::Html` / `InlineHtml` 一律转义为文本）。

**BBCode**（兼容 NexusPHP / Gazelle 常用标签）：`[b] [i] [u] [s] [url] [url=] [img] [img=WxH] [quote] [quote=name] [code] [pre] [spoiler] [spoiler=title] [color=#hex|名称] [size=1-7] [list] [*] [center] [hr] [mediainfo]`；自研有界解析器：标签栈深度 ≤ 32、输入 ≤ 64 KiB、未闭合标签按文本输出；属性值只接受白名单格式（颜色 `^#[0-9a-fA-F]{3,6}$` 或 CSS 颜色名白名单，尺寸整数 1～7，URL 见下）。

**净化**（两种语法都经过）：`ammonia`（MIT / Apache）白名单：

| 允许的元素 | 允许的属性 |
|---|---|
| `p br hr strong em del u code pre blockquote ul ol li table thead tbody tr th td h3 h4 h5 h6 span a img details summary div` | `a[href rel]`、`img[src alt width height loading]`、`span[class style(仅 color / font-size)]`、`div[class]`、`th/td[align]` |

- 链接：只允许 `https:`、`http:`（转为 https 不强制）、站内相对路径与 `magnet:`（可配置，默认禁止）；一律加 `rel="nofollow noopener ugc"`，站外链接加 `target` 不设置（避免 tabnabbing）。
- 图片：`src` 必须以 `blob_prefix` 开头或主机 ∈ `image_hosts` 且为 https；否则替换为链接文本；加 `loading="lazy"`；宽高限制在 1～4096。
- `style` 只保留 `color` 与 `font-size`（`em` / 预设值），由 BBCode 渲染器生成，用户无法直接输入。
- 输出前对所有文本节点 HTML 转义（由 ammonia 保证）。

**@提醒**：`(?<![\w@])@([A-Za-z0-9_\-\.]{2,32})` → `mention_resolver` 存在则渲染为 `<a href="/users/<id>">@name</a>`；代码块内不解析。
**表情**：`:name:` → `<img src="/blob/emoji/<name>.png" alt=":name:" class="emoji">`（只在表情表中存在时替换）。

### 1.2 targets

| kind | 存在与可见性判断 | 可评论条件 |
|---|---|---|
| `torrent` | `torrent.v_torrent_public` 中存在且 `status ∈ {approved, candidate, pending}`；`pending` 只对发布者与审核员可见 | approved 或 candidate（候选区可评论，可配置） |
| `group` | `torrent.v_group_public` 存在 | 是 |
| `request` | `requests.v_request_public` 存在且未删除 | 由 requests 作为钩子处理者决定（已关闭的求种可设为不可评论） |
| `subtitle` | `subtitles.v_subtitle_public` 存在 | 是 |

审核员 / 发布者身份判断：`ctx.rbac.check(user, "moderation.queue.read")` 或视图中的 `uploader_id = user`（匿名种子时视图中为 NULL → 发布者无法从视图识别，使用 `ctx.torrents.get` 的服务调用（会做权限过滤）——comments `requires ctx.torrents`；torrent 不依赖 comments，无环）。

### 1.3 antispam

```
check(uid, body_text, target):
  INCR rl:30s:<uid>（EX 30）> rate.per_30s → comments.rate_limited
  INCR rl:1h:<uid>（EX 3600）> rate.per_hour → comments.rate_limited
  account_age < new_user_days → INCR rl:day:<uid>（EX 86400）> new_user_daily_limit → comments.rate_limited
  fp = simhash64(normalize(body_text))；最近 1 小时同一用户的指纹列表（Redis LIST，最多 20）中海明距离 ≤ 3 → comments.duplicate
  rendered.links > max_links → comments.too_many_links
```

### 1.4 posting

```
create(author, target, body, markup, reply_to?, quote_of?, idem):
  幂等（author, idem）
  targets::check(author, target)；antispam::check
  if reply_to: 父评论属于同一目标且未删除，且父评论本身不是回复（单层）→ 否则 comments.reply_invalid
  if quote_of: 插入引用前缀（markdown："> @name 写道：\n> …" 截断 500 字；bbcode："[quote=name]…[/quote]"）
  outcome = hooks.run("comment.before_create", {author_id, target, body, markup, reply_to, mentions})
     modify.body → 使用修改后的正文
  r = pt_markup::render(body, markup, opts)
  floor = UPDATE target_counters SET next_floor = next_floor + 1, comment_count = comment_count + 1
          WHERE target = $1 RETURNING next_floor - 1（不存在则 INSERT … ON CONFLICT DO UPDATE）
  INSERT comments(...)；publish comment.created{comment_id, target, author_id, reply_to, mentions}
  mentions：去重、排除作者、≤ 10 → notify.send(uid, "comments.mentioned", {comment_id, target}, None)（幂等键 "<comment_id>:m:<uid>"）
edit(id, editor, body)：作者在窗口内或版主；INSERT edits(old source)；重新渲染；publish comment.updated
delete(id, by, reason)：state = deleted_by_author / deleted_by_moderator；source / rendered 保留（版主可见）但列表中显示占位；comment_count − 1；publish comment.deleted
```

### 1.5 query

- 列表：`WHERE target = $1 AND (state = 'visible' OR (deleted 占位))`，按 `floor` 排序，键集分页（游标 = floor）；回复按父楼层聚合：一次查询取本页楼层的全部回复（`reply_to = ANY($floors)`，每楼最多返回 5 条，其余“展开”接口）。
- 排序 `thanks`：`ORDER BY thanks_count DESC, floor`（偏移分页，限 20 页）。
- 用户历史：`WHERE author_id = $1 AND state = 'visible' ORDER BY id DESC`，并过滤目标可见性（目标不可见的条目隐藏）。

### 1.6 lifecycle

- `user.deleted{purge}`：`UPDATE comments SET source = '', rendered = '', state = 'purged' WHERE author_id = $1`（分批）。
- `torrent.deleted` / `group.deleted`：`UPDATE target_counters SET hidden = true`（评论随目标不可见，不删除）。
- `rerender`（`RENDER_VERSION` 变化后由管理员触发或启动时检测）：按 id 分批 1000 重新渲染。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:comments@0.1.0`）

```wit
package pt:comments@0.1.0;

interface comments {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms};

  enum markup { markdown, bbcode }
  record comment {
    id: u64, target: string, floor: u32, author-id: option<user-id>, reply-to: option<u64>,
    html: string, created-at: timestamp-ms, edited-at: option<timestamp-ms>, thanks: u32, deleted: bool,
  }
  record comment-page { items: list<comment>, next-cursor: option<string> }
  record create-request { author-id: user-id, target: string, body: string, markup: markup, reply-to: option<u64>, idempotency-key: string }

  count: func(target: string) -> result<u64, plugin-error>;
  count-many: func(targets: list<string>) -> result<list<u64>, plugin-error>;
  list: func(target: string, cursor: option<string>) -> result<comment-page, plugin-error>;
  create: func(req: create-request) -> result<u64, plugin-error>;
  delete: func(id: u64, reason: string) -> result<_, plugin-error>;
}
```

`create`、`delete` 需作用域 `write`（如 requests 插件以系统身份发布“已应求”评论）。

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `comment.created` | `comment_id, target, author_id, reply_to?, mentions[], length` |
| `comment.updated` | `comment_id, target, editor_id` |
| `comment.deleted` | `comment_id, target, by, reason, by_moderator` |

正文不进事件；需要正文的订阅方（ai-moderation）通过 `GET /v1/comments/{id}?raw=1`（需 `comments.moderate` 或插件作用域）获取。

### 2.3 钩子 `comment.before_create`

输入：`version, actor, author_id, target, body, markup, reply_to?, mentions[]`；决策 allow / deny / modify(`body`)；300 ms；失败策略 allow。

### 2.4 HTTP API（摘要）

**POST `/v1/targets/torrent:5501/comments`**（`Idempotency-Key`）`{ "body": "感谢分享 :smile:", "markup": "markdown", "reply_to": null, "quote_of": null }` → 201 `{ "id": 9001, "floor": 37 }`；错误：403 `comments.target_locked`（钩子）、429 `comments.rate_limited`、422 `comments.duplicate` / `comments.too_many_links` / `comments.too_long`、404 目标不存在。

**GET `/v1/targets/torrent:5501/comments?cursor=&order=asc`** → `{ "items": [ { "id": 9001, "floor": 37, "author": { "id": 1, "username": "alice" }, "html": "<p>感谢分享 <img …></p>", "replies": [ … ], "reply_count": 2, "thanks": 3, "thanked_by_me": false, "created_at": "…", "edited_at": null, "can_edit": true } ], "next_cursor": "37" }`

**POST `/v1/preview`** `{ "body": "…", "markup": "bbcode" }` → `{ "html": "…" }`（限流 `user:60/m`）。

**POST `/v1/images`**（multipart，≤ 5 MiB，PNG/JPEG/WebP/GIF，内容嗅探，重新编码去除 EXIF）→ `{ "url": "/blob/plugins/comments/img/<sha256>.webp" }`（限流 `user:20/h`）。

无独立工具。

## 3. 数据库设计（schema `comments`）

```sql
CREATE TABLE comments.target_counters (
    target         text PRIMARY KEY,
    next_floor     integer NOT NULL DEFAULT 1,
    comment_count  integer NOT NULL DEFAULT 0,
    hidden         boolean NOT NULL DEFAULT false
);

CREATE TABLE comments.comments (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    target          text NOT NULL,
    floor           integer NOT NULL,
    author_id       bigint,
    reply_to        bigint REFERENCES comments.comments (id),
    markup          text NOT NULL CHECK (markup IN ('markdown', 'bbcode')),
    source          text NOT NULL,
    rendered        text NOT NULL,
    plain           text NOT NULL,                 -- 纯文本（摘要、AI 审核）
    render_version  integer NOT NULL,
    state           text NOT NULL DEFAULT 'visible' CHECK (state IN ('visible','deleted_by_author','deleted_by_moderator','purged')),
    deleted_reason  text,
    thanks_count    integer NOT NULL DEFAULT 0,
    created_at      timestamptz NOT NULL DEFAULT now(),
    edited_at       timestamptz,
    UNIQUE (target, floor)
);
CREATE INDEX comments_target_idx ON comments.comments (target, floor);
CREATE INDEX comments_reply_idx ON comments.comments (reply_to) WHERE reply_to IS NOT NULL;
CREATE INDEX comments_author_idx ON comments.comments (author_id, id DESC);

CREATE TABLE comments.edits (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    comment_id  bigint NOT NULL REFERENCES comments.comments (id),
    editor_id   bigint NOT NULL,
    old_source  text NOT NULL,
    edited_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX edits_comment_idx ON comments.edits (comment_id, id DESC);

CREATE TABLE comments.thanks (
    comment_id  bigint NOT NULL REFERENCES comments.comments (id),
    user_id     bigint NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (comment_id, user_id)
);

CREATE TABLE comments.emoji (
    name     text PRIMARY KEY CHECK (name ~ '^[a-z0-9_]{2,32}$'),
    path     text NOT NULL,
    pack     text NOT NULL DEFAULT 'default',
    active   boolean NOT NULL DEFAULT true
);
```

数据量：1 亿行时 `comments` 约 60 GB（含 rendered）；v0.2 按 `id` 范围分区。

### 3.1 Redis（`p:comments:`）

`rl:30s:<uid>`、`rl:1h:<uid>`、`rl:day:<uid>`（计数）、`fp:<uid>`（LIST，TTL 1 h）、`emoji`（表情表缓存，60 s）。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.users@^0.1", "ctx.torrents@^0.1"]`、`optional_requires = ["ctx.notify@^0.1", "ctx.rbac@^0.1"]`；`[capabilities] sql, redis, blob, views = [...]`；`[[hook_points]] comment.before_create`；订阅 `user.deleted`、`torrent.deleted`、`group.deleted`；cron `rerender`（手动触发为主，计划 `0 5 * * *` 检查版本）、`cleanup`。

## 5. 前端设计

评论区组件（编辑器：Markdown / BBCode 切换、工具栏、表情面板、图片上传、实时预览）；楼层、回复折叠、引用按钮、感谢按钮、编辑历史（版主）、举报按钮（reports 插槽）。

## 6. 安全设计

渲染器（§1.1）；CSP：`img-src 'self' <image_hosts>`、`script-src 'self'`（无内联脚本）；图片上传重新编码；频率限制；正文不进事件与日志。

## 7. 性能设计

读路径只查询表中缓存的 HTML；楼层号单行锁（同一目标并发发表串行化，单目标 > 100 条/秒才会成为瓶颈）。

## 8. 可观测性

`pt_plugin_comments_created_total{target_kind}`、`pt_plugin_comments_rejected_total{reason}`、`pt_plugin_comments_render_seconds`。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `comments.target_not_found` | 404 | 目标不存在或不可见 |
| `comments.target_disabled` | 403 | 该目标类型未启用评论 |
| `comments.target_locked` | 403 | 目标不允许评论（由目标拥有者的钩子返回，拥有者也可用自己的错误码） |
| `comments.rate_limited` | 429 | 发言过快 |
| `comments.duplicate` | 422 | 重复内容 |
| `comments.too_many_links` | 422 | 链接过多 |
| `comments.too_long` | 422 | 超长 |
| `comments.reply_invalid` | 422 | 回复对象不合法 |
| `comments.edit_window_expired` | 403 | 超过编辑时限 |
| `comments.not_found` | 404 | |
| `comments.image_invalid` | 422 | 图片格式或大小不合法 |
