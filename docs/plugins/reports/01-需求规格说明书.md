## 1. 引言

### 1.1 目的

定义举报插件 `reports` 的需求：用户举报任意内容（种子、评论、帖子、用户、站内信、求种、字幕等），员工处理并反馈结果。

### 1.2 范围

包含：举报创建（目标、理由分类、说明、可选快照）、理由目录（按目标类型）、去重与合并（同一目标的多份举报合并为一个工单）、处理队列、认领、处理结论（无效 / 有效并执行动作 / 升级）、动作（调用目标拥有者的服务：删除评论、下架种子等）、通知举报者结果、滥用防护（频率、恶意举报计数）、统计、MCP。

不包含：作弊案件（anticheat）、审核队列（moderation）。

### 1.3 参考资料

- Gazelle/OPS：reports（按类型的理由、认领、处理、处理后通知）与 reportsv2（种子报告：trump、坏文件、格式错误，附带证据与处理动作）
- UNIT3D：reports（torrent / request / user，`solved`、`verdict`、员工评论）
- NexusPHP：举报（reports 表，处理后标记）

## 2. 总体描述

WASM，ID `reports`，缩写 `RPT`；提供 `ctx.reports`；不拥有钩子（创建举报不需要拦截链；滥用防护在插件内）。

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle reportsv2 | 种子报告带结构化理由与可执行动作（如“下架并警告上传者”），处理一步完成 | 处理效率高 | 动作硬编码 | **采纳**理由 → 推荐动作；动作调用拥有者服务（插件化） |
| UNIT3D | 简单举报 + 员工结论 | 简洁 | 同一目标多份举报分散 | **改进**：按目标合并为工单 |
| NexusPHP | 举报列表 | — | 无结果反馈 | 增加举报者通知 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-RPT-001 | 创建 | 对目标（`TargetRef`）提交举报：理由码、说明（≤ 2000）、可选证据链接 / 快照（由目标拥有者插件提供，如站内信快照） | P0 | |
| FR-RPT-002 | 理由目录 | 每种目标类型的理由列表（术语键 `reports.reason.<kind>.<code>`），含推荐动作与默认优先级 | P0 | |
| FR-RPT-003 | 合并 | 同一目标未结的举报合并为一个工单，计数与举报人列表累加 | P0 | |
| FR-RPT-004 | 去重 | 同一用户对同一目标在工单未结期间只能举报一次 | P0 | |
| FR-RPT-005 | 队列 | 按优先级、举报数、等待时间排序；筛选目标类型与理由 | P0 | |
| FR-RPT-006 | 认领 | 员工认领工单（30 分钟锁） | P1 | |
| FR-RPT-007 | 结论 | `invalid`（无效）/ `resolved`（有效）/ `escalated`（升级给管理员）；必填处理说明 | P0 | |
| FR-RPT-008 | 动作 | 有效时可执行动作：删除评论 / 帖子（comments / forum 服务）、下架种子（torrents.set_status disabled）、删除字幕、对用户施加限制（identity，需权限）、发送警告（notify 模板）；动作结果记录 | P1 | |
| FR-RPT-009 | 举报者反馈 | 结案后通知举报者（结论 + 可公开说明） | P1 | |
| FR-RPT-010 | 滥用防护 | 频率（每小时 10 份）；无效举报计数，超过阈值（30 天内 5 次无效）禁止举报 7 天 | P1 | |
| FR-RPT-011 | 被举报者隐私 | 举报者身份对被举报者不可见；工单只对员工可见 | P0 | |
| FR-RPT-012 | 快照 | 支持目标拥有者提交的快照（站内信等不可由员工直接查看的内容） | P1 | |
| FR-RPT-013 | 统计 | 工单量、处理时长、按理由分布 | P2 | |
| FR-RPT-014 | MCP | `admin_list_reports`、`admin_resolve_report`（已登记） | P2 | |
| FR-RPT-015 | 用户删除 | 举报者被删除：工单保留，举报人显示为已删除；被举报用户被删除：工单自动结案（target_gone） | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-RPT-001 | 创建 | p99 < 100 ms |
| NFR-RPT-002 | 审计 | 结论与动作写审计 |
| NFR-RPT-003 | 依赖 | 动作调用均为 optional 服务，缺失时对应动作不可用 |

## 5. 可配置项与站点术语

`rate_per_hour`（10）、`abuse.invalid_threshold`（5）、`abuse.window_days`（30）、`abuse.ban_days`（7）、`claim_minutes`（30）、`notify_reporter`（true）、`reasons`（理由目录，可编辑）。术语：`reports.name`（已登记）、`reports.reason.<kind>.<code>`、`reports.resolution.<code>`。

## 6. 外部接口需求概述

服务 `ctx.reports`（`create`、`resolve`；⊕ `create` 增加 `snapshot`）；事件 `report.created`、`report.resolved`（已登记）；HTTP `/api/p/reports/v1/*`；插槽 `torrent.detail.actions`、`forum.post.footer`、`admin.dashboard.widgets`；MCP 两项。
