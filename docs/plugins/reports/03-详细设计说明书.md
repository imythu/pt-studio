## 1. 模块详细设计

### 1.1 reasons（默认目录）

| kind | code | 推荐动作 | 优先级 |
|---|---|---|---|
| torrent | `dupe`、`trump`（有更好版本）、`bad_file`（文件损坏 / 错误）、`wrong_info`（信息错误）、`spam`、`illegal`、`other` | `disable_torrent`（bad_file、illegal）、`notify_uploader`（wrong_info） | illegal 100、bad_file 50、其他 20 |
| comment / forum_post | `spam`、`abuse`（辱骂）、`off_topic`、`illegal`、`other` | `delete_content` | abuse 50 |
| user | `spam`、`abuse`、`impersonation`、`cheating`、`other` | `restrict_user`（需 `identity.users.ban`） | cheating 60 |
| message | `spam`、`abuse`、`scam`、`other` | `restrict_user` | scam 80 |
| request / subtitle | `invalid`、`spam`、`other` | `delete_content` | 20 |

管理员可增删改；理由带 `requires_note`（是否必须填写说明）。

### 1.2 intake

```
create(u, target, reason_code, note, snapshot?, idem):
  rbac reports.create；abuse.banned_until(u) > now → reports.temporarily_banned
  INCR rl:<u>（EX 3600）> rate_per_hour → reports.rate_limited
  kind = target.kind；reason ∈ reasons[kind]，否则 reports.reason_invalid
  目标存在：torrent → torrent.v_torrent_public；comment → comments 视图（⊕ 请 comments 提供 v_comment_public）；
            forum_post → forum 视图（⊕）；user → identity.v_user_public；message → snapshot 必须存在（由 messages 调用）
  不得举报自己（target = user:<u>）→ reports.self_report
  c = SELECT … FROM cases WHERE target = $1 AND state IN ('open', 'claimed') FOR UPDATE
      无 → INSERT cases(target, kind, state = 'open', priority = reason.priority)
  INSERT reports(case_id, reporter_id, reason_code, note, snapshot) ON CONFLICT (case_id, reporter_id) DO NOTHING
      → 冲突：reports.already_reported
  UPDATE cases SET report_count + 1, priority = max(priority, reason.priority), last_report_at = now
  publish report.created{report_id, case_id, target, reporter_id, reason_code}
```

快照：只接受服务调用（作用域 `write`）提交的 `snapshot`（HTTP 用户提交的 `snapshot` 字段被忽略），防止伪造。

### 1.3 cases

```
list：WHERE state IN ('open', 'claimed', 'escalated'[管理员]) ORDER BY priority DESC, report_count DESC, created_at
claim：同 moderation（claim_minutes）
resolve(staff, case, {code ∈ invalid|resolved|escalated, note_internal, note_public, actions[]}, idem):
  rbac reports.moderate；escalated 的工单只能由管理员（`identity.users.ban` 或 `kernel.settings.manage`）处理
  for (i, a) in actions: r = actions::run(a, case, key = "rpt:<case>:<i>")；记录 results[i]
  任一失败 → UPDATE cases SET action_results；返回 207（部分成功），state 不变
  全部成功 → state = 'closed'（或 escalated）、resolution、resolved_by、resolved_at
  code == invalid → for reporter in reports: abuse::record_invalid(reporter)
  publish report.resolved{report_id: 首份, case_id, resolution, by}；feedback（notify_reporter）
```

### 1.4 actions

| 动作 | 适配 | 所需依赖 / 作用域 |
|---|---|---|
| `delete_content` | comment → `comments.delete(id, reason)`；forum_post → `forum.delete_post`（⊕）；subtitle → `subtitles.delete`（⊕）；request → `requests`（不提供删除：改为 `moderate` 关闭，⊕ 暂不支持） | `ctx.comments` `write` 等 |
| `disable_torrent` | `torrents.set_status(id, disabled, reason)` | `ctx.torrents` `write:status` |
| `restrict_user` | `users.apply_restriction({kind: leech_disabled | banned, reason_code: "reports.<code>", until?, idempotency_key})`；员工自身需 `identity.users.ban`（原始 actor 权限由 identity 检查） | `ctx.users` `write:status` |
| `notify_user` | `notify.send(target_user, "reports.warning", {note_public})` | `ctx.notify` `send` |
| `none` | — | — |

动作不可用（依赖插件未启用）时，前端不显示该动作；服务端返回 `reports.action_unavailable`。

### 1.5 abuse

`abuse(user_id, invalid_count, window_start, banned_until)`；`record_invalid`：窗口过期则重置；`invalid_count ≥ threshold` → `banned_until = now + ban_days`；`abuse_decay`（每日）清理过期窗口。

### 1.6 lifecycle

订阅目标删除事件：对应工单若仍 open → `state = closed, resolution = target_gone`（不通知举报者“无效”，而是“目标已被处理”）。`user.deleted{purge}`：举报者 → `reports.reporter_id = NULL`。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:reports@0.1.0`）

```wit
package pt:reports@0.1.0;

interface reports {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, json};

  record resolution { code: string, note-internal: string, note-public: string }

  create: func(reporter: user-id, target: string, reason-code: string, note: string, snapshot: option<json>, idempotency-key: string) -> result<u64, plugin-error>;
  resolve: func(case-id: u64, resolution: resolution) -> result<_, plugin-error>;
}
```

`create` 由插件代用户调用时需作用域 `write`；`resolve`（不带动作）需 `write` 且原始 actor 有 `reports.moderate`。

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `report.created` | `report_id, case_id, target, reporter_id, reason_code` |
| `report.resolved` | `report_id, case_id, target, resolution, by` |

`reporter_id` 在事件中保留（服务端流转），但不得通过 webhook、通知等外发给被举报者（webhook 插件需过滤此字段，见 webhook 设计）。

### 2.3 HTTP API（前缀 `/api/p/reports/v1`）

**POST `/reports`** `{ "target": "comment:9001", "reason_code": "abuse", "note": "…" }` → 201 `{ "report_id": 31, "case_id": 12 }`；错误：409 `reports.already_reported`、429 `reports.rate_limited`、403 `reports.temporarily_banned`、422 `reports.reason_invalid` / `reports.self_report`、404 目标不存在。

**GET `/cases/{id}`**（员工）→ `{ "id": 12, "target": "comment:9001", "target_preview": {...（来自视图或快照）}, "reports": [ { "reporter": {"id": 3, "username": "x"}, "reason_code": "abuse", "note": "…", "snapshot": null, "created_at": "…" } ], "available_actions": ["delete_content", "restrict_user", "notify_user"], "state": "open" }`

**POST `/cases/{id}/resolve`** `{ "code": "resolved", "note_internal": "…", "note_public": "已处理，感谢举报", "actions": [ { "kind": "delete_content" }, { "kind": "restrict_user", "restriction": "leech_disabled", "days": 7 } ] }` → 200 或 207 `{ "results": [ {"kind": "delete_content", "ok": true}, {"kind": "restrict_user", "ok": false, "error": "kernel.forbidden"} ] }`。

**GET `/my-reports`** → 我的举报与结论（不含内部说明）。

### 2.4 MCP

`admin_list_reports`（入参 `{kind?, state?}`）；`admin_resolve_report`（入参 `{case_id, code, note_public, actions?}`；write，confirm；含 `restrict_user` 时不可关闭确认）。

## 3. 数据库设计（schema `reports`）

```sql
CREATE TABLE reports.cases (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    target          text NOT NULL,
    kind            text NOT NULL,
    state           text NOT NULL CHECK (state IN ('open','claimed','escalated','closed')),
    priority        integer NOT NULL DEFAULT 0,
    report_count    integer NOT NULL DEFAULT 0,
    claimed_by      bigint,
    claim_until     timestamptz,
    resolution      text,
    note_internal   text,
    note_public     text,
    action_results  jsonb,
    resolved_by     bigint,
    resolved_at     timestamptz,
    created_at      timestamptz NOT NULL DEFAULT now(),
    last_report_at  timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX cases_open_target_idx ON reports.cases (target) WHERE state IN ('open', 'claimed', 'escalated');
CREATE INDEX cases_queue_idx ON reports.cases (state, priority DESC, report_count DESC, created_at);

CREATE TABLE reports.reports (
    id           bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    case_id      bigint NOT NULL REFERENCES reports.cases (id),
    reporter_id  bigint,
    reason_code  text NOT NULL,
    note         text NOT NULL DEFAULT '',
    snapshot     jsonb,
    created_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (case_id, reporter_id)
);
CREATE INDEX reports_reporter_idx ON reports.reports (reporter_id, id DESC);

CREATE TABLE reports.reasons (
    kind           text NOT NULL,
    code           text NOT NULL,
    priority       integer NOT NULL DEFAULT 20,
    recommended    text[] NOT NULL DEFAULT '{}',
    requires_note  boolean NOT NULL DEFAULT false,
    active         boolean NOT NULL DEFAULT true,
    PRIMARY KEY (kind, code)
);

CREATE TABLE reports.abuse (
    user_id        bigint PRIMARY KEY,
    invalid_count  integer NOT NULL DEFAULT 0,
    window_start   timestamptz NOT NULL DEFAULT now(),
    banned_until   timestamptz
);
CREATE TABLE reports.idempotency (owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (owner, key));
```

快照最大 64 KiB；保留期 365 天（结案后，`cleanup` 清除 snapshot 字段）。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.users@^0.1", "ctx.rbac@^0.1"]`、`optional_requires = ["ctx.notify@^0.1", "ctx.comments@^0.1", "ctx.forum@^0.1", "ctx.torrents@^0.1", "ctx.subtitles@^0.1"]`；scopes：`ctx.users = ["write:status"]`、`ctx.torrents = ["write:status"]`、`ctx.comments = ["write"]`、`ctx.forum = ["write"]`、`ctx.notify = ["send"]`；views：`torrent.v_torrent_public`、`identity.v_user_public` 等；订阅四项；cron 三项（含 `cleanup`）。

## 5. 前端设计

举报对话框（理由按目标类型列出、说明）；员工工单列表与详情（目标预览、举报列表、推荐动作勾选、内外部说明）；“我的举报”页。

## 6. 安全设计

举报者身份只对员工可见；快照只接受服务调用；动作需相应权限；审计全部结论与动作；滥用防护。

## 7. 性能设计

创建为单事务少量 SQL；队列走部分索引。

## 8. 可观测性

`pt_plugin_reports_cases{state}`、`pt_plugin_reports_resolution_seconds`、`pt_plugin_reports_invalid_total`。
