## 1. 设计目标与原则

1. **工单 = 目标**：同一目标的未结举报合并；举报（report）与工单（case）两层。
2. **动作插件化**：动作通过目标拥有者的服务执行；reports 只声明 optional 依赖，缺失则动作不可用。
3. **避免依赖环**：messages 依赖 reports（提交快照），因此 reports **不依赖** messages；给用户的通知统一经 `ctx.notify`。

## 2. 总体结构

| 模块 | 职责 |
|---|---|
| `intake` | 创建举报、去重、合并、频率与滥用检查 |
| `reasons` | 理由目录 |
| `cases` | 工单队列、认领、结论 |
| `actions` | 动作适配器（comments、forum、torrents、subtitles、users） |
| `feedback` | 举报者通知 |
| `abuse` | 无效举报计数与禁止期 |

## 3. 对外接口清单

| 类别 | 内容 |
|---|---|
| 服务 | `create(reporter_id, target, reason_code, note) -> id`、`resolve(id, resolution)`（已登记）；⊕ `create` 增加 `snapshot: Option<Json>`、`idempotency_key` |
| 依赖 | `ctx.users`、`ctx.rbac`；optional：`ctx.notify`、`ctx.comments`（`delete`）、`ctx.forum`（删除帖子 ⊕ 需 forum 提供 `delete_post`）、`ctx.torrents`（`set_status`）、`ctx.subtitles`（删除 ⊕ 需 subtitles 提供 `delete`）、`ctx.users.apply_restriction` |
| 事件 | 发布 `report.created`、`report.resolved`；订阅 `user.deleted`、`torrent.deleted`、`comment.deleted`、`forum.post_deleted`（目标已被删除 → 工单可自动结案 target_gone） |
| HTTP | `POST /v1/reports`、`GET /v1/reasons?kind=`、`GET /v1/my-reports`；员工：`GET /v1/cases`、`GET /v1/cases/{id}`、`POST /v1/cases/{id}/claim`、`POST /v1/cases/{id}/resolve`、`GET /v1/admin/stats`、`GET/PUT /v1/admin/reasons` |
| 插槽 | `torrent.detail.actions`、`forum.post.footer`（举报按钮）、`admin.dashboard.widgets`（待处理数）；评论、站内信的举报按钮由 comments / messages 自己渲染并调用本插件接口 |
| cron | `claim_expire`（`* * * * *`）、`abuse_decay`（`0 3 * * *`） |
| 权限点 | `reports.create`、`reports.moderate`（已登记） |

## 4. 数据设计概要

`cases`（目标、状态、优先级、举报数、认领、结论、动作结果）、`reports`（每份举报：举报者、理由、说明、快照）、`reasons`、`abuse`（用户无效计数、禁止期）。

## 5. 关键流程

```
create：频率 / 禁止期检查 → 理由属于目标类型 → 目标存在（视图或由快照提供方保证）→ 找未结工单（target）→ 无则新建 → 去重（同举报者）→ INSERT reports → cases.report_count+1、priority = max(理由优先级) → publish report.created
resolve(case, resolution{code, note_internal, note_public, actions[]})：
  执行 actions（逐个调用服务，幂等键 "rpt:<case>:<i>"），记录结果；任一失败 → 工单保持 open，返回部分结果
  结论写入；invalid → 每个举报者 abuse.invalid += 1（超过阈值设置禁止期）
  publish report.resolved；notify 举报者（note_public）
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-RPT-1 | 合并粒度 | 按目标合并：员工一次处理即可回复所有举报者 |
| DD-RPT-2 | 动作失败 | 不回滚已执行的动作（各自独立提交），工单保持 open 并显示失败项，员工重试（幂等键保证不重复） |
| DD-RPT-3 | 站内信举报 | 员工无法读取站内信，只能看到 messages 提交的快照（举报者同意后） |

## 7. 对平台契约的新增

`ctx.reports.create` 增加 `snapshot`、`idempotency_key`；请 forum 提供 `delete_post(id, reason)` 服务方法、subtitles 提供 `delete(id, reason)`；术语 `reports.reason.<kind>.<code>`、`reports.resolution.<code>`；依赖方向约束：reports 不得依赖 messages。
