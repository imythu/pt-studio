## 1. 设计目标与原则

1. **复式、只追加**：每笔流水的分录合计为 0（系统发行/回收也以系统分录体现）；更正只能冲正。
2. **余额是缓存，流水是事实**：`accounts.balance` 由流水驱动并在同事务更新；任何时刻可由“月度结余 + 之后的分录”重建。
3. **条件更新防负**：不用“先读后写”；扣减语句自带可用余额与锁定条件，影响行数为 0 即失败。
4. **无热点**：系统账户不设余额行，发行/回收按分片计数；用户账户按 user_id 升序加锁。
5. **幂等是接口的一部分**：每个写方法必须带幂等键，键与结果在同一事务持久化。
6. **币种是数据，规则在外**：ledger 不知道“魔力值怎么赚”，只保证记账正确。

## 2. 总体结构

```
 bonus/shop/checkin/lottery/requests/…（WASM） ──ctx.ledger──┐
 anticheat ──lock_account / 处理 ledger.before_transfer ─────┤
 用户浏览器 ──/api/p/ledger/v1/…────────────────────────────┤
                                                              ▼
 ┌──────────────────────────── ledger（Native）──────────────────────────────┐
 │ service ─► guard（作用域、币种状态、幂等预检）─► hook（before_transfer）      │
 │        ─► posting（单事务：幂等登记 → 账户条件更新 → 分录 → 供给分片 → 事件） │
 │ holds（冻结/释放/结算/过期） locks（锁定计数） currencies（注册、设置缓存）    │
 │ reconcile（日对账、月结余） archive  http  mcp  ui                             │
 └───────────────────────────────────────┬────────────────────────────────────┘
                                         ▼ PostgreSQL schema ledger
        currencies / accounts / entries / lines / holds / account_locks / idempotency / supply_shards / checkpoints
```

| 模块 | 职责 |
|---|---|
| `currencies` | 注册、查询、设置（transferable、fee、限额）合并；进程内缓存 |
| `guard` | 作用域检查、金额范围、币种停用、幂等预检（命中直接返回首次结果，不触发钩子） |
| `hook` | 对用户转出触发 `ledger.before_transfer` |
| `posting` | 记账核心：一个事务内完成全部写入 |
| `holds` | 冻结生命周期 |
| `locks` | 账户锁定与 `accounts.lock_count` 维护 |
| `reconcile` | 对账、月结余快照 |
| `archive` | 分区归档 |
| `service` / `http` / `mcp` / `ui` | 接口层 |

## 5. 关键流程

### 5.1 用户间转账

```
HTTP POST /transfers ─► 内核网关（鉴权、权限、限流、Idempotency-Key）─► ledger.http
  解析收款人（ctx.users.find_by_username）→ 币种可转账？→ 限额/2FA
  service.transfer(req{from=u1, to=u2, key="http:<principal>:<Idempotency-Key>"})
    guard：作用域（HTTP 路径以 ledger 自身身份，视为拥有全部币种作用域）、幂等预检（命中 → 返回）
    hook：ctx.hooks.run("ledger.before_transfer", …) → deny → 返回处理者错误码
    posting（事务）：
       INSERT idempotency … ON CONFLICT DO NOTHING RETURNING → 0 行：读已有结果返回（并发同键）
       按 user_id 升序：UPDATE accounts（付款方：条件扣减 amount+fee；收款方：增加，必要时 INSERT）
       INSERT entries；INSERT lines（u1: −(amount+fee)，u2: +amount，system: +fee）
       UPDATE supply_shards（fee → burned）
       UPDATE daily_outflow
       events.publish(entry_posted × 2)
       UPDATE idempotency SET entry_id, result
     COMMIT
```

### 5.2 冻结与结算（lottery 下注）

```
lottery ─hold(bonus, u, 100, key="<event>:hold")─► 条件 held += 100（可用 ≥ 100 且未锁定）→ holds(active)
开奖：lottery ─capture_hold(hold_id, to=None, amount=100, key)─►
        held −= 100；balance −= 100（流水：u −100，system +100 burned）；hold → captured
未中奖退还：release_hold(hold_id) → held −= 100；hold → released
过期：cron expire_holds → 同 release
```

### 5.3 锁定

```
anticheat ─lock_account(u, None, reason="anticheat.case", ref="case:812", key)─►
   INSERT account_locks；UPDATE accounts SET lock_count = lock_count + 1 WHERE user_id = u（全部币种）
   之后：扣减类 UPDATE 带条件 lock_count = 0 → 0 行 → ledger.account_locked
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| DD-LED-1 | 记账模型 | A 单式（余额 + 日志）；B 复式 | B | 分录合计为 0 是最强的自校验；系统发行/回收显式记录，供给可对账 |
| DD-LED-2 | 金额类型 | A numeric；B bigint 最小单位 + scale | B | database.md §4 规定；整数运算快且无舍入歧义；scale 不可变，避免 NexusPHP 改列 |
| DD-LED-3 | 防负余额 | A SELECT FOR UPDATE 后判断；B 条件 UPDATE | B | 单语句原子，锁持有时间最短；A 也正确但多一次往返 |
| DD-LED-4 | 系统账户 | A 一行系统账户；B 按 16 分片计数 | B | 发行量大（时薪）时单行成为全站热点；分片后对账按币种汇总 |
| DD-LED-5 | 幂等存储 | A entries 上唯一索引；B 独立表 | B | 分区表唯一索引必须包含分区键，无法跨月保证唯一；独立表可设保留期 |
| DD-LED-6 | 流水 ID | A bigint 自增；B UUIDv7 | B（entries.id），分录用 (entry_id, line_no) | 对外不可枚举、跨副本生成、带时间序便于分区定位 |
| DD-LED-7 | 锁定实现 | A 每次扣减查询锁表；B `accounts.lock_count` 计数 | B | 扣减语句条件内完成判断，无额外查询；锁表保留明细与审计 |
| DD-LED-8 | 高频小额发放（时薪） | A 每用户每小时一笔；B 消费方按日/6 小时合并；C ledger 提供“累计入账” | B 为建议，同时提供批量接口 | 保持只追加语义；A 在 25 万用户下每天 600 万笔仍在容量内，但事件与存储成本高，建议 bonus 评估 |
| DD-LED-9 | 钩子触发位置 | A 事务内；B 事务前 | B | 钩子处理者在自己的工作单元中执行（kernel/03 §5.2），不能参与 ledger 事务；钩子只读判断，不需要回滚 |
| DD-LED-10 | 手续费处理 | A 进入系统收入账户；B 回收（burned） | B | 无站务“收入账户”需求；需要时可由插件再发行 |
| DD-LED-11 | 余额缓存 | A Redis 缓存余额；B 不缓存 | B | PG 主键查询已足够快（< 1 ms）；缓存引入一致性问题 |
| DD-LED-12 | 对账粒度 | A 每日全量从头求和；B 月结余快照 + 增量 | B | 历史分录可达数十亿行，全量求和不可行 |

## 7. 对平台契约的新增

| # | 类别 | 内容 | 理由 |
|---|---|---|---|
| L-1 | 服务方法（services.md `ctx.ledger`） | 新增 `currencies()`、`transfer_batch(reqs)`、`hold(req)`、`release_hold(hold_id, key)`、`capture_hold(req)`、`lock_account(req)`、`unlock_account(lock_id, key)`、`supply(currency)`；`reverse` 增加 `idempotency_key` 与 `allow_negative` 参数；`register_currency` 增加 `options` | 冻结/锁定是悬赏、彩票、反作弊必需；冲正需要幂等 |
| L-2 | 服务作用域 | `ctx.ledger` 新增作用域 `lock`（锁定/解锁账户，供 anticheat） | 锁定影响所有币种，不应由币种作用域授予 |
| L-3 | 事件载荷 | `ledger.entry_posted` 增加字段 `kind(issue/burn/transfer/hold_capture/reversal/adjust)`、`caller_plugin`；`balance_after` 为总额；不含 memo | 消费方区分来源 |
| L-4 | 钩子输入（hooks.md `ledger.before_transfer`） | 增加 `operation: "transfer"|"burn"|"hold"`；说明新建冻结也会触发 | 冻结同样是用户资金转出 |
| L-5 | 权限点 | `ledger.currencies.manage`（币种设置，默认 admin） | |
| L-6 | MCP 工具 | `get_my_balances`（user，无权限点）、`admin_get_user_ledger`（admin，`ledger.balance.read`） | 用户与管理员查询 |
| L-7 | 术语键 | `ledger.wallet`、`ledger.transfer` | 站点叫法 |
| L-8 | 错误码（error-codes.md §3 补充） | `ledger.account_locked`、`ledger.currency_disabled`、`ledger.hold_not_active` 等（全表见 LLD §9） | 跨插件常用 |
| L-9 | 事件日志保留 | 同 accounting N-2：`ledger.entry_posted` 体量大（每日可达千万条），需要按类型设置保留期（建议 90 天；流水本身由 ledger 永久保存） | |
