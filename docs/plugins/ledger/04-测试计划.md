## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元 | 分录生成（各操作的分录表，LLD §1.4）、手续费计算（u128 中间值、向下取整）、金额范围检查、`request_hash` 规范化、原因码校验、游标编解码、`diagnose` 错误分类、对账检查函数 | `cargo nextest`、`proptest` |
| 性质测试 | 任意操作序列（发行、回收、转账、冻结、结算、释放、冲正、锁定）下：① 每笔流水分录合计 = 0；② `balance − held ≥ min_balance`（未授权负余额时）；③ Σ用户余额 = 已发行 − 已回收；④ `held` = Σ活动 hold；⑤ 余额 = 月结余 + 分录合计 | `proptest`（状态机模型 `tests/model.rs`） |
| 集成 | 真实 PG 17 + pt-testkit 内核宿主（事件 outbox、钩子管线、延迟任务、cron、设置、审计）；WASM 测试插件 `t-bonus`、`t-shop`、`t-lottery`、`t-anticheat`（stub）作为调用方与钩子处理者 | `pt-testkit`、testcontainers |
| 并发 | 同账户多连接并发扣款、双向互转、同幂等键并发、冻结与扣款竞争 | `tokio` 多任务 + 独立连接池；检查 PG 日志无 `40P01`（死锁） |
| 契约 | WIT（`pt:ledger@0.1.0`）可被 `wasm-tools` 解析，WASM 调用方链接成功；事件载荷符合 `schemas/events/ledger.*.v1.json`；钩子输入符合 `schemas/hooks/ledger.before_transfer.json`；OpenAPI 与清单路由一致、`oasdiff` 无破坏性变更；MCP 输入输出 schema | `jsonschema`、`wasm-tools`、`oasdiff` |
| 性能 | 单笔延迟、持续吞吐、批量发行、10 亿分录下的流水查询、日对账耗时 | `criterion`、`xtask loadgen-ledger`、Prometheus |
| 安全 | 作用域越权、原因码伪造、管理员接口权限与近期重新验证、输入注入、信息泄露（memo 不进事件/日志） | 集成 + 静态扫描 |
| 前端 | 钱包页、转账表单（十进制字符串换算、幂等键复用）、后台标签页 | Vitest、Playwright |

参考模型：`tests/model.rs` 以最朴素的内存账本（逐笔执行、无并发）计算期望余额、冻结、供给与事件，集成与性质测试的“预期结果”以它为准。

## 2. 测试环境与数据

| 环境 | 配置 |
|---|---|
| CI 集成 | PG 17 单实例；1～3 个 pt-server 副本（同进程多实例模拟）；`hold_max_ttl_secs = 3600`；`pt-testkit` 冻结 `ctx.time` |
| 并发 | PG 17（8 vCPU）；`database.pool_size = 64`；200 个并发任务 |
| 性能 | PG 17（16 vCPU / 64 GB / NVMe）；3 个 pt-server 副本（8 vCPU）；预灌 30 万用户 × 3 币种账户、10 亿条分录（36 个月分区，按 LLD §3.1 估算分布） |

测试币种（由 `t-bonus` 注册）：

| 代码 | scale | 设置 |
|---|---|---|
| `bonus` | 1 | transferable = true，fee_bps = 500，min_transfer = 100，daily_out_limit = 100000，require_2fa = false |
| `seedpt` | 0 | transferable = false |
| `credit` | 2 | min_balance = −10000（允许透支，用于 FR-LED-008 边界） |

测试插件作用域（`site.toml [grants.<id>.scopes]`）：`t-bonus`：`currency:bonus`、`currency:seedpt`；`t-shop`：`currency:bonus`；`t-lottery`：`currency:bonus`；`t-anticheat`：`lock`；`t-admin-tool`：`read`、`reverse`；`t-noscope`：无。
