## 1. 引言

### 1.1 目的

定义 `ledger` 插件（Native，提供 `ctx.ledger`）的需求。ledger 是全站唯一的虚拟货币账本（决策 D13）：币种由其他插件注册（bonus 注册魔力值、做种积分等），所有余额变动都以只追加的复式流水记录，提供转账、冻结（预留）/解冻、账户锁定、冲正、幂等、对账，保证定点精度与“不出现未经许可的负余额”。

### 1.2 范围

| 包含 | 不包含 |
|---|---|
| 币种注册与元数据（精度 scale、术语键、是否允许用户间转账、手续费等站点设置） | 币种的“赚取规则”（bonus、checkin、lottery 等决定何时发多少） |
| 账户、余额、冻结额（holds）、账户锁定 | 商品、订单（shop） |
| 转账：系统发行（from=None）、系统回收（to=None）、用户间转账（含手续费）、批量发行 | 流量（上传/下载量属于 accounting） |
| 只追加流水（复式）、冲正、幂等键 | 汇率与币种兑换（P2 可在此基础上由插件以“回收 + 发行”实现） |
| `ledger.before_transfer` 钩子点 | 反作弊判定（anticheat 通过钩子与锁定接口介入） |
| 对账（账户、币种总量、流水平衡、冻结额）、月度结余快照、归档 | |
| 用户界面：余额与流水、用户间转账；后台：查看、手工调整、冲正、锁定 | |

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| 币种（currency） | 由插件注册的虚拟货币，代码 `^[a-z][a-z0-9_]{1,15}$`，如 `bonus` |
| scale | 小数位数（0～6）。金额以最小单位整数存储：显示值 = 金额 / 10^scale |
| 账户 | (user_id, currency) 唯一；系统账户不存余额行，以“发行/回收计数”表示 |
| 流水（entry） | 一次记账操作，ID 为 UUIDv7（对外称 `entry_id`），含 ≥ 2 条分录 |
| 分录（line） | 一个账户（或系统）在一笔流水中的金额变动，复式：一笔流水内全部分录金额之和为 0 |
| 冻结（hold） | 对用户可用余额的预留，冻结期间不可动用；之后释放或结算（capture） |
| 可用余额 | `balance − held` |
| 锁定（lock） | 禁止账户转出（含冻结），由 anticheat 或管理员施加，可叠加 |
| 冲正（reversal） | 以一笔方向相反的新流水抵消原流水，原流水不修改 |
| 幂等键 | 调用方在本插件范围内唯一的字符串；以 (调用方插件, 键) 去重，重复请求返回首次结果 |
| 发行 / 回收 | 系统账户 → 用户（from=None）/ 用户 → 系统（to=None） |

## 2. 总体描述

### 2.1 插件定位

| 项 | 内容 |
|---|---|
| 类型 | Native（高频写入、并发控制、为全部经济类插件服务） |
| 提供服务 | `ctx.ledger@0.1.0` |
| 依赖服务 | `ctx.users`（转账时按用户名查找收款人、校验用户状态）；`ctx.rbac`（HTTP 内细粒度检查）；`ctx.terms`（MCP 输出渲染） |
| 钩子点（拥有者） | `ledger.before_transfer` |
| 对外视图 | `ledger.v_balance`（已登记） |
| 消费方 | bonus、shop、checkin、lottery、requests（悬赏）、medals（购买）、invite（如以货币购买邀请）、anticheat（锁定） |

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 查看各币种余额与收支明细；在站点开放时向其他用户赠送（转账），可附言 |
| 经济类插件 | 注册币种；发放（时薪、签到奖励、彩票中奖）；扣款（购买、下注）；冻结后结算（悬赏、竞猜）；批量发放 |
| anticheat | 在 `ledger.before_transfer` 中拦截可疑转出；对作弊账户施加锁定 |
| 版主 | 查看他人余额与流水 |
| 管理员 | 手工发放/扣除、冲正错误流水、锁定/解锁账户、配置币种（是否可转账、手续费、单日上限） |
| 运维 | 对账报告、币种总量监控 |

### 2.3 现有开源 PT 程序的做法调研

| 项目 | 做法 | 优点 | 缺点 | 采纳 | 改进 |
|---|---|---|---|---|---|
| NexusPHP | 余额是 `users` 表的 decimal 列；`bonus_logs` 记录旧值、变动、新值；时薪批量 UPDATE 不记日志；赠送有手续费 | 简单；`old/new_total_value` 便于核对 | 余额与用户表耦合；时薪不入账无法对账；并发下“先读后写”易超卖；decimal(10,1) 曾溢出被迫改列 | 每条分录记录 `balance_after`；赠送手续费作为站点设置 | 独立账本 schema；所有变动都入账；条件 UPDATE 防负；整数最小单位 + 每币种 scale，避免改列 |
| UNIT3D | `seedbonus` 列 + `bon_transactions`（`cost double`，发送者/接收者） | 记录赠送与打赏的双方 | 金额用浮点（`double`），存在精度误差；交易记录不覆盖全部来源（时薪、管理员调整） | 交易同时记录双方 | 定点整数；复式分录覆盖全部来源 |
| Gazelle / OPS | `user_bonus` + `bonus_history`；定时任务批量加分；Gift 赠送 | 批量加分高效 | 历史只覆盖购买，无法从流水重建余额 | 批量发放接口 | 批量发放也逐用户入账（一个事务内多条），并提供月度结余快照控制体量 |
| Luminance / TorrentPier | 类似：用户表余额列 + 简单日志 | — | 同上 | — | — |
| 通用金融系统 | 复式记账、幂等键、冲正而非修改、按期结账（checkpoint） | 可审计、可对账 | 实现复杂度 | 全部采纳 | 按 PT 场景简化：系统账户以分片计数代替单行（避免热点） |

### 2.4 约束与假设

1. 金额为 `i64` 最小单位；单笔绝对值 ≤ 2^53 − 1（JSON 安全整数），账户余额范围同此。
2. 平台约束：每次调用一个事务；服务调用在被调方自己的事务中执行；ledger 是 Native，同进程直接调用。
3. 体量假设：如 bonus 每小时给 25 万用户发放并逐笔入账，每天约 600 万笔流水、1200 万分录；设计容量目标 ≤ 1000 万流水/天。建议 bonus 按日或按 6 小时合并发放（见 HLD §6 DD-LED-8）。
4. 币种注册在提供方插件 `init` 中调用，必须幂等。
5. 不做多租户（D6），一个站点一套账本。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-LED-001 | 币种注册 | `register_currency(code, scale, name_term, options)`：调用方须持有 `currency:<code>` 作用域；相同参数重复注册成功（幂等）；已由其他插件注册的代码 → 冲突；已注册币种不可修改 scale | P0 | bonus 重复注册返回成功；shop 注册 `bonus` 返回 `ledger.currency_owned_by_other`；改 scale 返回 `ledger.currency_immutable` |
| FR-LED-002 | 币种查询 | 列出币种：代码、scale、术语键、所属插件、是否可转账、手续费、状态 | P0 | 前端与 MCP 能正确格式化金额 |
| FR-LED-003 | 发行 | `transfer(from=None, to=user)`：增加用户余额与币种已发行量 | P0 | 余额增加、`ledger.entry_posted` 1 条、supply.issued 增加 |
| FR-LED-004 | 回收 | `transfer(from=user, to=None)`：校验可用余额与锁定后扣减，增加已回收量 | P0 | 余额不足返回 `ledger.insufficient_balance`；锁定账户返回 `ledger.account_locked` |
| FR-LED-005 | 用户间转账 | `transfer(from=u1, to=u2)`：原子扣减与增加；按币种设置收取手续费（回收），手续费向下取整；不允许自转账 | P0 | 两边余额与手续费正确；任一步失败整体回滚 |
| FR-LED-006 | 作用域控制 | 写操作要求调用方持有 `currency:<code>`；读他人余额/流水要求 `read` 或该币种作用域 | P0 | 无作用域调用返回 `ledger.currency_not_allowed` |
| FR-LED-007 | 幂等 | 所有写方法必带 `idempotency_key`；同一 (调用方, 键) 同参数重复调用返回首次结果（`duplicate=true`），不同参数返回 `kernel.idempotency_key_reused`；并发同键只执行一次 | P0 | 并发 50 次同键转账只扣一次 |
| FR-LED-008 | 防负余额 | 默认任何操作后 `balance − held ≥ min_balance`（币种设置，默认 0）；以条件更新保证并发正确 | P0 | 1000 个并发扣款压测后无负余额、总扣款不超过初始余额 |
| FR-LED-009 | 并发与死锁 | 多账户操作按 (user_id) 升序加锁；系统账户不形成热点 | P0 | 双向互转压测无死锁、无超时 |
| FR-LED-010 | 精度 | 金额整数最小单位；scale 0～6；手续费、拆分等计算使用整数与向下取整；溢出检测 | P0 | 极值测试（2^53−1）返回 `ledger.amount_out_of_range` 而非溢出 |
| FR-LED-011 | 冻结（hold） | `hold(currency, user, amount, reason, expires_at?, key) -> hold_id`：从可用余额中预留；`release_hold` 释放；`capture_hold(hold_id, to?, amount≤冻结额, key)` 结算（剩余自动释放）；过期自动释放 | P0 | lottery 下注冻结、开奖时 capture；过期 hold 1 分钟内释放 |
| FR-LED-012 | 账户锁定 | `lock_account(user, currency?, reason, ref, key) -> lock_id`、`unlock_account(lock_id, key)`：锁定期间禁止转出与新建冻结（发行、收款仍允许）；多个锁叠加 | P0 | anticheat 锁定后用户转账被拒；解除最后一个锁后恢复 |
| FR-LED-013 | 钩子 `ledger.before_transfer` | 对 from 为用户的转出（含用户间转账、回收、新建冻结）在记账前触发钩子；deny 时返回处理者错误码；fail-closed | P0 | anticheat deny 时转账未发生，返回其错误码 |
| FR-LED-014 | 批量发行 | `transfer_batch(reqs)`：一次 ≤ 1000 笔，只允许 from=None；单事务；逐笔幂等；返回逐笔结果 | P0 | 1000 笔批量 1 秒内完成；重放同批不重复发放 |
| FR-LED-015 | 余额查询 | `balance`、`balances`（全部币种：余额、冻结、可用）；视图 `v_balance` | P0 | 数值与账户表一致 |
| FR-LED-016 | 流水查询 | `history(currency?, user, cursor, limit)`：按时间倒序的分录（金额、余额后值、原因、对方、备注），游标分页 | P0 | 翻页无重复、无遗漏 |
| FR-LED-017 | 冲正 | `reverse(entry_id, reason, key, allow_negative)`：生成相反流水；已冲正的流水不可再冲正；冲正导致余额不足时默认失败，管理员可显式允许形成负余额（欠款） | P0 | 冲正后余额恢复；重复冲正返回 `ledger.already_reversed` |
| FR-LED-018 | 事件 | 发布 `ledger.currency_registered`、`ledger.entry_posted`（每个用户分录一条）、`ledger.entry_reversed` | P0 | 事件与流水一致，载荷符合 schema |
| FR-LED-019 | 用户转账 API | `POST /transfers`：权限 `ledger.transfer.use`、币种可转账、收款人存在且状态正常、单笔最小值、单日转出上限、可选要求 2FA、附言 ≤ 200 字符 | P1 | 各限制分别返回对应错误码 |
| FR-LED-020 | 后台调整 | 管理员发放/扣除（`ledger.balance.adjust`），必填原因；写审计 | P0 | 审计含前后余额 |
| FR-LED-021 | 后台查询 | 查看任意用户余额、流水、冻结、锁定（`ledger.balance.read`） | P0 | |
| FR-LED-022 | 对账 | 每日：① 每个账户 余额 = 上月结余 + 本月分录合计；② 每笔流水分录合计 = 0；③ 每币种 Σ用户余额 = 已发行 − 已回收；④ 每账户冻结额 = Σ活动 hold。差异写报告并告警 | P0 | 篡改一行余额后次日报告指出该账户 |
| FR-LED-023 | 月度结余快照 | 每月初为上月有变动的账户写结余快照，供对账与归档后的余额证明 | P1 | 快照与当时余额一致 |
| FR-LED-024 | 归档 | 分录与流水按月分区；超过保留期（默认永久，可配 ≥ 24 个月）的分区先导出到对象存储再删除 | P2 | 归档文件可校验、可导入 |
| FR-LED-025 | 用户删除 | `user.deleted{purge}`：清空该用户相关流水的备注；余额视图隐藏；流水金额保留（财务记录不删除） | P1 | purge 后流水无备注、视图无该用户 |
| FR-LED-026 | MCP | `get_my_balances`（用户，本人余额与最近流水）、`admin_get_user_ledger`（管理员）——需在 MCP 目录新增 | P2 | 输出经术语渲染、含正确小数位 |
| FR-LED-027 | 前端 | 用户“我的钱包”页、转账表单；`admin.user.tabs` 账本标签页；`nav.user_menu` 入口 | P1 | |
| FR-LED-028 | 币种设置 | 管理员设置币种是否允许用户间转账、手续费（基点）、最小转账额、每日转出上限、是否要求 2FA、币种停用（停用后只读） | P1 | 修改后立即生效 |
| FR-LED-029 | 冻结过期 | cron 每分钟释放过期 hold | P0 | 见 FR-LED-011 |
| FR-LED-030 | 批量发放 | 管理员（`ledger.balance.adjust`）给一批用户各发同一数量的货币：对象按用户状态（正常 / 禁止下载 / 待验证，默认只含正常；封禁与已删除永远不发）与等级筛选，或按用户名名单（≤ 5000，不区分大小写）；必填原因（≤ 200 字符，写入每笔流水备注）；提交前预览人数、总额、名单中找不到的用户名；单批 ≤ 200 000 人、总额 ≤ 2^53−1；创建时快照收款人，后台分块记账（每人一笔 `ledger.admin_grant`，幂等），单人失败只记在该人；可查看列表、进度与失败名单，任务重试耗尽后可“继续”；创建写审计 `ledger.grant` | P1 | 1 万人的批 1 分钟内到账；中途杀进程后续跑，每人恰好一笔；同一幂等键重复提交只建一批 |
| FR-LED-031 | 发放通知 | 批量发放可选给每个收款人发一封系统站内信（`ctx.messages.send_system`，未安装站内信插件时不可选 / 跳过）；标题与正文为模板，变量 `{username}` `{amount}` `{currency}` `{balance}` `{memo}`；站内信暂不可用时稍后重试，连续失败 5 次后放弃剩余并记为通知失败 | P1 | 每个收款人收到 1 封，金额按小数位格式化、货币用站点术语名 |
| FR-LED-032 | 批量扣除 | 同一功能的另一方向：给一批用户各扣同一数量（每人一笔 `ledger.admin_deduct`，kind = adjust，不检查账户锁定）；不形成负余额：可用余额（余额 − 冻结 − 最低余额）不足时按管理员选择跳过此人（默认，记 `ledger.insufficient_balance`）或扣到可用余额为 0；预览给出余额不足人数与预计实际扣除总额；只通知实际被扣的人，`{amount}` 为此人实际扣除数量；默认通知模板为扣除措辞；审计 `ledger.deduct` | P1 | 余额不足者 skip 时余额不变、无站内信；partial 时余额为 0、通知数量为原可用余额；任何情况下无负余额 |

## 5. 可配置项与站点术语

## 6. 外部接口需求概述

- **服务**：`ctx.ledger`（LLD §2.1 WIT）。
- **钩子点**：`ledger.before_transfer`。
- **事件**：发布 `ledger.currency_registered`、`ledger.entry_posted`、`ledger.entry_reversed`；订阅 `user.deleted`。
- **HTTP**：`/api/p/ledger/v1/…`。
- **MCP**：`get_my_balances`、`admin_get_user_ledger`（新增，见 HLD §7）。
- **前端**：`nav.user_menu`、`admin.user.tabs`、`/p/ledger/*`、`/admin/p/ledger/*`。
- **视图**：`ledger.v_balance`。
