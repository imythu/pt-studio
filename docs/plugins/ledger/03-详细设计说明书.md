## 1. 模块详细设计

### 1.1 currencies

**数据**：`currencies` 表保存不可变定义（code、scale、name_term、owner_plugin、registered_at）；可变设置（transferable、fee_bps、min_transfer、daily_out_limit、require_2fa、min_balance、disabled）保存在插件运行时设置 `currencies.<code>.*`（后台可改，经 settings schema 校验）。进程内缓存 `ArcSwap<HashMap<code, CurrencyView>>`，在 `kernel.settings_changed` 回调与每 30 s 刷新。

**注册算法**：

```
register_currency(def{code, scale, name_term, options}):
    require "currency:"+code ∈ invocation.caller_scopes            ?: ledger.currency_not_allowed
    validate code ^[a-z][a-z0-9_]{1,15}$, scale 0..=6, name_term 以 "<caller>." 或 "ledger.currency." 开头
    row = INSERT INTO currencies(code, scale, name_term, owner_plugin) VALUES (…) ON CONFLICT (code) DO NOTHING RETURNING *
    if row: events.publish(ledger.currency_registered{currency, scale, name_term, owner_plugin}); 刷新缓存; return
    existing = SELECT … WHERE code = $1
    if existing.owner_plugin != caller: err ledger.currency_owned_by_other
    if existing.scale != scale or existing.name_term != name_term: err ledger.currency_immutable
    return ok                                                       -- 幂等
```

`options`（初始设置建议值：`transferable`、`fee_bps` 等）只在首次注册时写入设置的默认值（不覆盖管理员已改的值）。

### 1.2 guard

```
guard_write(currency, caller, key):
    cur = cache[currency] ?: ledger.currency_not_found
    cur.disabled → ledger.currency_disabled
    caller != "ledger" and "currency:"+currency ∉ caller_scopes → ledger.currency_not_allowed
    key 1..=128 字符，^[\x21-\x7e]+$ → 否则 kernel.validation_failed
    amount ∈ [1, 2^53-1] → 否则 ledger.amount_out_of_range（发行/转账/冻结金额必须为正）
    hit = SELECT entry_id, hold_id, lock_id, request_hash, result FROM idempotency WHERE caller_plugin=$1 AND key=$2
    if hit:
        hit.request_hash != hash(req) → kernel.idempotency_key_reused
        hit.result IS NULL → ledger.idempotency_in_progress（retryable，罕见：并发同键且首个事务未提交）
        return Replay(hit.result)                                   -- duplicate = true，不触发钩子
```

`request_hash = sha256(canonical_json(请求去掉 idempotency_key))`。

### 1.3 hook

对以下操作且 `from_user` 为用户时，在记账事务开始前调用：

```
outcome = ctx.hooks.run("ledger.before_transfer", {
    version: 1, actor: 当前 actor, operation: "transfer"|"burn"|"hold",
    currency, from_user, to_user?, amount, reason })
Denied{code, message, by_plugin} → 返回 PluginError{code, message, retryable=false}
Err(kernel.hook_failed)         → 原样返回（503，retryable）
```

`ledger.before_transfer` 失败策略 deny（钩子目录），超时 100 ms。批量发行、系统回收（from=None 的情况不存在）、capture（冻结时已检查）、冲正、管理员调整不触发钩子。

### 1.4 posting：记账核心

**分录约定**：

| 操作 | 分录（user_id: amount） | supply |
|---|---|---|
| 发行 to=u | u: +A；system: −A | issued += A |
| 回收 from=u | u: −A；system: +A | burned += A |
| 转账 u1→u2，手续费 F | u1: −(A+F)；u2: +A；system: +F | burned += F |
| capture hold（u，to=None） | u: −C；system: +C | burned += C |
| capture hold（u，to=v） | u: −C；v: +C | — |
| 冲正 | 原流水每条分录取反 | issued/burned 反向调整（发行冲正 → issued −= A；回收冲正 → burned −= A） |

`F = A × fee_bps / 10000`（u128 中间值，向下取整）。

**事务算法**（`posting.post(op)`，在一个工作单元内）：

```
post(op):
    -- 1 幂等登记（并发同键串行化于唯一约束）
    ins = INSERT INTO idempotency(caller_plugin, key, request_hash, created_at)
          VALUES ($caller, $key, $hash, now()) ON CONFLICT DO NOTHING RETURNING 1
    if ins 为空:
        hit = SELECT request_hash, result FROM idempotency WHERE … FOR SHARE   -- 等待并发事务提交
        hash 不同 → kernel.idempotency_key_reused；result 存在 → return Replay(result)
    -- 2 账户变动（按 user_id 升序）
    for (uid, delta, kind) in op.account_changes.sorted_by(uid):
        if delta < 0:   -- 扣减
            r = UPDATE accounts SET balance = balance + $delta, version = version + 1, updated_at = now()
                WHERE user_id = $uid AND currency = $cur
                  AND lock_count = 0                                  -- 冲正与管理员扣减时省略此条件
                  AND balance + $delta - held >= $min_balance         -- allow_negative 时省略
                RETURNING balance
            if r 为空: diagnose(uid) → ledger.account_locked | ledger.insufficient_balance(details{available, required})
        else:           -- 增加（账户不存在则创建）
            r = INSERT INTO accounts(user_id, currency, balance, lock_count)
                VALUES ($uid, $cur, $delta, (SELECT count(*) FROM account_locks WHERE user_id=$uid AND currency IS NULL AND released_at IS NULL))
                ON CONFLICT (user_id, currency) DO UPDATE
                  SET balance = accounts.balance + EXCLUDED.balance, version = accounts.version + 1, updated_at = now()
                RETURNING balance
            checked：balance ≤ 2^53-1，否则 ledger.amount_out_of_range（回滚）
        balance_after[uid] = r.balance
    -- 3 流水与分录
    entry_id = uuid_v7()
    INSERT INTO entries(id, created_at, currency, kind, reason, memo, caller_plugin, actor_kind, actor_user_id, reversal_of, hold_id)
    INSERT INTO lines(entry_id, created_at, line_no, currency, user_id, amount, balance_after, counterparty_user_id)  -- 多行一条语句
    -- 4 供给分片
    UPDATE supply_shards SET issued = issued + $i, burned = burned + $b WHERE currency = $cur AND shard = ($uid % 16)
    -- 5 附加
    用户间转账：INSERT INTO daily_outflow … ON CONFLICT DO UPDATE SET amount = amount + $a
        WHERE daily_outflow.amount + $a <= $limit（limit=0 不限）→ 0 行 → ledger.daily_limit_exceeded
    -- 6 事件（每个用户分录一条）
    events.publish(ledger.entry_posted{entry_id, currency, user_id, amount, balance_after, reason, kind,
                   caller_plugin, counterparty_user_id?})
    -- 7 记录幂等结果
    UPDATE idempotency SET entry_id = $entry_id, result = $result_json WHERE caller_plugin=$1 AND key=$2
    return result
```

`diagnose(uid)`：`SELECT balance, held, lock_count FROM accounts WHERE …`（无行视为余额 0）。

**一致性说明**：

- 并发扣同一账户：条件 UPDATE 行锁串行化，后到者看到新余额并重新判断条件，不会超扣。
- 两账户转账按 user_id 升序更新，所有路径顺序一致，无死锁。
- 供给分片按收款/付款用户取模，16 个分片把系统热点分散；分片行在迁移中预建（每注册一个币种插入 16 行）。

**批量发行** `transfer_batch`：所有请求同一币种、`from_user = None`；按 `to_user` 升序；每笔单独幂等登记；每笔单独流水（便于逐笔冲正）；整个批次一个事务；返回逐笔 `result<transfer-result, plugin-error>`——单笔业务错误（如幂等键冲突）不回滚其他笔，基础设施错误回滚全批（调用方以相同幂等键重试安全）。为此每笔使用 `SAVEPOINT`？——运行期语句检查禁止 SAVEPOINT（kernel/03 §6.3），因此改为：先对全批做幂等预检与参数校验，把有错的笔剔除并直接返回错误；剩余笔（全部为增加操作，不会因余额失败）在同一事务中执行。

### 1.5 holds

```
hold(req{currency, user, amount, reason, expires_at?, idempotency_key}):
    guard_write; hook(operation="hold")
    事务：幂等登记 →
       r = UPDATE accounts SET held = held + $a, version = version + 1, updated_at = now()
           WHERE user_id=$u AND currency=$c AND lock_count = 0 AND balance - held - $a >= $min_balance
           RETURNING held
       空 → diagnose → 错误
       INSERT holds(id=uuid_v7, currency, user_id, amount, remaining=amount, state='active', reason,
                    caller_plugin, expires_at = min(expires_at, now()+max_ttl))
       记录幂等结果 hold_id
release_hold(hold_id, key):
    事务：幂等登记 → h = SELECT … FROM holds WHERE id=$1 FOR UPDATE
       h.caller_plugin != caller 且 caller 无 reverse 作用域 → ledger.hold_not_found
       h.state != 'active' → 若同键重放已处理；否则 ledger.hold_not_active
       UPDATE accounts SET held = held - h.remaining …；UPDATE holds SET state='released', remaining=0, closed_at=now()
capture_hold(req{hold_id, to_user?, amount, reason, memo, idempotency_key}) -> transfer-result:
    事务：幂等登记 → h FOR UPDATE（同上校验）→ amount ≤ h.remaining 否则 ledger.hold_amount_exceeded
       UPDATE accounts SET held = held - h.remaining, balance = balance - $amount WHERE …（不检查 lock_count：资金已预留）
       若 to_user：收款方增加（同 posting 第 2 步）
       写 entries(kind='hold_capture', hold_id) / lines / supply
       UPDATE holds SET state='captured', captured_amount=$amount, remaining=0, closed_at=now()
       （剩余部分随之释放）
expire_holds（cron，每分钟，tx manual）：
    loop: ids = SELECT id FROM holds WHERE state='active' AND expires_at <= now() ORDER BY expires_at LIMIT 500 FOR UPDATE SKIP LOCKED
          对每个：同 release（幂等键 "expire:<hold_id>"，caller=ledger）；commit
```

### 1.6 locks

```
lock_account(req{user, currency?, reason, ref, idempotency_key}) -> lock_id:
    require "lock" ∈ caller_scopes 或 caller == "ledger"（管理员 HTTP）  ?: ledger.scope_required
    事务：幂等登记 → INSERT account_locks(id, user_id, currency, reason, ref, caller_plugin, actor) RETURNING id
       UPDATE accounts SET lock_count = lock_count + 1, updated_at = now()
           WHERE user_id = $u AND ($currency IS NULL OR currency = $currency)
       ctx.audit.write("ledger.lock", "user:<u>", {lock_id, currency, reason, ref})
unlock_account(lock_id, key):
    事务：幂等登记 → l = SELECT … FOR UPDATE；released_at 非空 → 成功（幂等）
       l.caller_plugin != caller 且 caller != "ledger" → ledger.lock_not_found
       UPDATE account_locks SET released_at = now(), released_by …
       UPDATE accounts SET lock_count = lock_count - 1 WHERE user_id = $u AND (l.currency IS NULL OR currency = l.currency) AND lock_count > 0
```

新建账户时 `lock_count` 初始化为该用户全币种锁的数量（§1.4 第 2 步）；指定币种的锁在该币种账户不存在时先插入一个余额 0 的账户再加锁。

### 1.7 reverse

```
reverse(entry_id, reason, key, allow_negative) -> entry_id':
    e = SELECT … FROM entries WHERE id = $1（created_at 从 UUIDv7 时间推出分区，加速定位）  ?: ledger.entry_not_found
    权限：caller 有 "reverse" 作用域；或 caller == e.caller_plugin 且有 "currency:"+e.currency；或 caller == "ledger"（管理员）
    allow_negative 只允许 caller == "ledger"（管理员 HTTP，且需 ledger.balance.adjust）  ?: ledger.negative_not_allowed
    e.kind == 'reversal' → ledger.cannot_reverse_reversal
    事务：幂等登记 → INSERT entry_reversals(entry_id) ON CONFLICT DO NOTHING RETURNING → 空 → ledger.already_reversed
       lines = SELECT user_id, amount FROM lines WHERE entry_id = $1
       对每条用户分录取反执行账户变动（扣减方向的条件含余额检查，除非 allow_negative；不检查 lock_count）
       写 entries(kind='reversal', reversal_of = e.id)、lines、supply 反向
       events.publish(ledger.entry_reversed{entry_id: e.id, reversal_entry_id, reason}) 每个用户一条
       events.publish(ledger.entry_posted …) 每个用户一条（kind=reversal）
```

### 1.8 reconcile

**日对账**（cron `reconcile_daily`，tx manual，结果写 `reconcile_reports`）：

| 检查 | SQL 要点 | 范围 |
|---|---|---|
| C1 账户余额 | `a.balance = coalesce(cp.balance_end, 0) + Σ lines.amount WHERE created_at >= cp 月末` | 平日：昨日有分录的账户（`lines` 昨日分区 DISTINCT user_id, currency）；每月 `full_balance_check_day`：全部账户（分批 5000） |
| C2 流水平衡 | `SELECT entry_id FROM lines WHERE created_at ∈ 昨日 GROUP BY entry_id HAVING sum(amount) <> 0` | 昨日 |
| C3 币种总量 | `Σ accounts.balance = Σ supply.issued − Σ supply.burned`，并与 `Σ lines(user_id IS NULL)` 的相反数一致 | 每币种 |
| C4 冻结额 | `a.held = Σ holds.remaining WHERE state='active'` | 昨日有 hold 变动的账户；每月全量 |
| C5 锁计数 | `a.lock_count = count(active locks matching)` | 同 C4 |

差异写 `reconcile_reports(day, check, subject, expected, actual)`，指标 `pt_plugin_ledger_reconcile_mismatches_total{check}`，> 0 告警。**不自动修复**（资金类差异必须人工确认；修复方式为管理员调整或冲正）。

**月结余快照**（cron `monthly_checkpoint`，每月 1 日）：对上月有分录的账户：`balance_end = 上一快照 + Σ 上月分录`，写 `checkpoints(month, user_id, currency, balance_end, line_count)`；并与当前余额减去本月已发生分录后的值比对（即时校验）。

### 1.9 archive

`retention_months > 0` 时，cron `archive` 对即将到期的月分区（`entries`、`lines`）导出 `archive/<table>/<yyyymm>.csv.gz` + manifest（行数、sha256、该月 Σamount 按币种），校验后标记 `archived_partitions`；内核分区维护在保留期后删除（依赖 accounting HLD §7 N-4 的 `archive_hook`，未合入前本任务在到期前 7 天完成导出，内核删除时不再回调）。`checkpoints` 永久保留，保证归档后余额仍可证明。

### 1.10 用户删除

订阅 `purge_user`（`user.deleted`，tx manual）：

- `purge`：`UPDATE entries SET memo = NULL WHERE id IN (SELECT entry_id FROM lines WHERE user_id = $u)`（分批）；`UPDATE accounts SET is_hidden = true`；释放全部活动 hold（幂等键 `purge:<event_id>:<hold_id>`）。分录金额、余额不删除（财务记录，database.md §6）。
- `soft`：`is_hidden = true`。

### 1.11 HTTP 用户转账细节

```
POST /v1/transfers {currency, to_username | to_user_id, amount, memo?, otp?}
  cur.transferable 否 → ledger.transfer_disabled
  amount < cur.min_transfer → ledger.amount_below_minimum
  to = ctx.users.find_by_username / get；不存在或 status ∈ {banned, deleted} → ledger.recipient_invalid（不区分原因）

```

### 1.12 grants：批量发放与扣除（FR-LED-030～032）

实现：`src/grants.rs`；表 `grant_batches`、`grant_recipients`（§3.1，迁移 0002、0003）；延迟任务 `grant_batch`。

一批有方向 `direction`：`grant`（发放，默认）或 `deduct`（扣除）。扣除另有 `shortfall`：`skip`（默认，余额不足跳过此人）或 `partial`（扣到可用余额为 0）。可用余额 = `balance − held − min_balance`，与 `core::post` 中 `Check::IgnoreLock` 的条件一致；扣除不检查账户锁定（与单人管理员回收相同），也从不形成负余额（要形成欠款用单笔冲正的 `allow_negative`）。下文“发放”在扣除时即“扣除”。

**发放对象**（`target`，JSON 标签联合）：

| kind | 字段 | 解析（`identity.v_user_public`） |
|---|---|---|
| `filter` | `statuses`（⊆ `active` / `leech_disabled` / `pending`，非空，默认 `["active"]`）、`class_ids`（空 = 所有等级） | `status = ANY(statuses) AND (class_ids 为空 OR class_id = ANY(class_ids))` |
| `users` | `usernames`（1～5000） | `lower(username) = ANY(小写名单) AND status NOT IN ('banned','deleted')` |

封禁与已删除用户在任何模式下都不发。预览与创建用同一条解析 SQL。

**预览** `POST /v1/admin/grants/preview`：返回人数、总额（发放为 `amount × count`，超过 2^53−1 时为 null；扣除为按当前可用余额估算的实际扣除总额）、余额不足人数（扣除时）、币种 scale、名单中找不到或已封禁的用户名（≤ 50 个）、人数上限、站内信是否可用（以 `ctx.messages.unread_count` 试探）、默认通知模板。只读。

**创建** `POST /v1/admin/grants`（idempotent）—— 单个工作单元事务内：

```
校验 target、amount ∈ [1, 2^53−1]、memo（clean_memo，1～200 字符）、模板（标题 ≤ 120、正文 ≤ 5000，空则用默认）
request_key = "http:<credential_id>:<Idempotency-Key>" 已存在 → 200 返回该批（网关 Redis 幂等之外的第二道保险）
币种已停用 → ledger.currency_disabled
INSERT grant_batches(state = 'granting')
INSERT INTO grant_recipients SELECT <批>, id FROM (<解析 SQL>)      -- 收款人快照
  0 人 → ledger.grant_no_recipients；> 200 000 → ledger.grant_too_many（422）；amount × 人数 > 2^53−1 → ledger.amount_out_of_range
  （返回错误时整个事务回滚，不留空批）
schedule_once("grant_batch", now, {batch_id})
审计 ledger.grant {currency, amount, memo, target, recipients, notify}
```

**任务** `grant_batch {batch_id}`：每次执行一块，一块一个事务（延迟任务的工作单元）；`SELECT … FOR UPDATE` 锁批行使同一批的块串行。

```
state = granting：
  取 ≤ 500 个 entry_id IS NULL AND error IS NULL 的收款人（按 user_id）
  扣除时先一次查出本块各人可用余额，算出此人实际数量 a：够 → amount；不够且 partial → max(可用, 0)；否则 0
    a = 0 → 不记账，error = ledger.insufficient_balance
  逐人 core::transfer({from: None, to: u（扣除时 from: u, to: None）, amount: a,
                       reason: "ledger.admin_grant" / "ledger.admin_deduct", memo,
                       idempotency_key: "grant:<批>:<u>"}, adjust = true)       -- kind = adjust，与单人调整一致
    （余额在预查与记账之间变少时 post 返回 ledger.insufficient_balance，同样只记在此人上）
    业务错误（ledger.* / kernel.validation_failed / kernel.idempotency_key_reused）→ 只记 error = 错误码
    其他错误 → 整块回滚，内核按 30 s / 2 min / 10 min 重试
  批量回写 entry_id、balance_after、amount（实际数量）、error（unnest）；granted / failed / moved（实际总额）累加
  本块不足 500 人 → 发完：notify 且站内信可用 → notifying；notify 但不可用 → done（last_error = messages_unavailable，
                    notify_failed = granted）；不通知 → done
  未完成 → 排队下一块（立即）
state = notifying：
  取 ≤ 100 个已发放、未通知、无通知错误的收款人
  逐人 ctx.messages.send_system({user_id, subject, body})，模板变量见下
    kernel.capability_denied / kernel.service_unavailable → 站内信不可用：剩余全部记通知失败，done
    retryable 错误 → 本块停下；notify_retries + 1，≥ 5 时剩余全部记通知失败并 done，否则 60 s 后再排队
    其他错误 → 只记该人 notify_error
  成功的记 notified_at；本块成功推进时 notify_retries 清零；不足 100 人且未停下 → done
```

站内信由 messages 插件在自己的工作单元里提交，与本块事务不是原子的：本块事务若在发信后失败，重试会给这一块已收到的人再发一次（极少见；发放本身由幂等键保证恰好一次）。暂时失败时不返回错误而是记录进度后延迟重排，正是为了避免这种重复。

**模板变量**：`{username}`、`{amount}`（此人实际数量，按 scale 格式化、去掉末尾 0）、`{currency}`（币种 `name_term` 的站点术语名，取不到时为代码）、`{balance}`（此人记账后余额）、`{memo}`。默认标题：发放 `你收到了 {amount} {currency}`，扣除 `你被扣除了 {amount} {currency}`；默认正文含用户名、数量、原因、当前余额。只通知记账成功的人（扣除时被跳过的人不通知）。审计动作：发放 `ledger.grant`，扣除 `ledger.deduct`。

**继续** `POST /v1/admin/grants/{id}/resume`：清零 `notify_retries` 与 `last_error`、重新排队；已完成的批 → `ledger.grant_finished`。用于任务重试耗尽（如数据库长时间故障）后的人工恢复；块逻辑只处理未完成的收款人，重复排队无副作用。

**容量**：每人一笔分录，与单人调整同成本；1 万人 = 20 块，延迟任务轮询间隔 1 s，约十几秒到账。通知每块 100 人（每封一次 WASM 调用）。

## 2. 接口详细设计

### 2.1 服务接口（WIT）

文件 `plugins/native/ledger/wit/ledger.wit`：

```wit
package pt:ledger@0.1.0;

interface ledger {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  record currency-options {
    transferable: option<bool>,
    fee-bps: option<u32>,
    min-transfer: option<s64>,
    daily-out-limit: option<s64>,
  }
  record currency-def {
    code: string,            // ^[a-z][a-z0-9_]{1,15}$
    scale: u8,               // 0..=6
    name-term: string,       // 如 "bonus.currency"
    options: currency-options,
  }
  record currency-info {
    code: string, scale: u8, name-term: string, owner-plugin: string,
    transferable: bool, fee-bps: u32, min-transfer: s64, daily-out-limit: s64, disabled: bool,
  }

  record transfer-request {
    currency: string,
    from-user: option<user-id>,   // none = 系统发行
    to-user: option<user-id>,     // none = 系统回收
    amount: s64,                  // > 0，最小单位
    reason: string,               // 原因码 <plugin>.<code>，如 "bonus.hourly"
    memo: string,                 // ≤ 200 字符，可为空
    idempotency-key: string,      // 1..=128 可见 ASCII
  }
  record transfer-result {
    entry-id: string,             // UUIDv7
    from-balance-after: option<s64>,
    to-balance-after: option<s64>,
    fee: s64,
    duplicate: bool,
  }

  record balance-info { currency: string, balance: s64, held: s64, available: s64, locked: bool, updated-at: timestamp-ms }

  enum entry-kind { issue, burn, transfer, hold-capture, reversal, adjust }
  record history-item {
    entry-id: string, currency: string, kind: entry-kind, amount: s64, balance-after: s64,
    reason: string, memo: option<string>, counterparty-user-id: option<user-id>,
    caller-plugin: string, reversed: bool, created-at: timestamp-ms,
  }
  record history-page { items: list<history-item>, next-cursor: option<string> }

  record hold-request {
    currency: string, user: user-id, amount: s64, reason: string,
    expires-at: option<timestamp-ms>, idempotency-key: string,
  }
  record capture-request {
    hold-id: string, to-user: option<user-id>, amount: s64, reason: string, memo: string, idempotency-key: string,
  }
  record lock-request {
    user: user-id, currency: option<string>, reason: string, ref: string, idempotency-key: string,
  }
  record supply-info { currency: string, issued: s64, burned: s64, circulating: s64, held: s64 }

  register-currency: func(def: currency-def) -> result<_, plugin-error>;
  currencies: func() -> list<currency-info>;
  transfer: func(req: transfer-request) -> result<transfer-result, plugin-error>;
  transfer-batch: func(reqs: list<transfer-request>) -> result<list<result<transfer-result, plugin-error>>, plugin-error>;
  balance: func(currency: string, user: user-id) -> result<s64, plugin-error>;
  balances: func(user: user-id) -> result<list<balance-info>, plugin-error>;
  history: func(currency: option<string>, user: user-id, cursor: option<string>, limit: u32) -> result<history-page, plugin-error>;
  reverse: func(entry-id: string, reason: string, idempotency-key: string, allow-negative: bool) -> result<string, plugin-error>;
  hold: func(req: hold-request) -> result<string, plugin-error>;
  release-hold: func(hold-id: string, idempotency-key: string) -> result<_, plugin-error>;
  capture-hold: func(req: capture-request) -> result<transfer-result, plugin-error>;
  lock-account: func(req: lock-request) -> result<string, plugin-error>;
  unlock-account: func(lock-id: string, idempotency-key: string) -> result<_, plugin-error>;
  supply: func(currency: string) -> result<supply-info, plugin-error>;
}
```

| 方法 | 作用域 | 错误码 |
|---|---|---|
| `register-currency` | `currency:<code>` | `ledger.currency_not_allowed`、`ledger.currency_owned_by_other`、`ledger.currency_immutable`、`kernel.validation_failed` |
| `currencies` | — | — |
| `transfer` | `currency:<code>` | `ledger.currency_not_found`、`ledger.currency_disabled`、`ledger.currency_not_allowed`、`ledger.amount_out_of_range`、`ledger.insufficient_balance`、`ledger.account_locked`、`ledger.self_transfer`、`ledger.daily_limit_exceeded`、`kernel.idempotency_key_reused`、`ledger.idempotency_in_progress`、钩子处理者错误码、`kernel.hook_failed` |
| `transfer-batch` | `currency:<code>` | 整体：`ledger.batch_too_large`（> 1000）、`ledger.batch_mixed`（币种不同或含 from-user）；逐笔：同 transfer |
| `balance` | `read` 或 `currency:<code>` | `ledger.currency_not_found`、`ledger.currency_not_allowed` |
| `balances` | `read` | `ledger.scope_required` |
| `history` | `read`；或仅 `currency:<code>` 且 currency 必填 | `ledger.currency_not_allowed`、`kernel.bad_request`（游标） |

### 2.4 HTTP API（前缀 `/api/p/ledger`）

**GET `/v1/currencies`**

```json
{ "items": [ { "code": "bonus", "scale": 1, "name_term": "bonus.currency", "transferable": true,
               "fee_bps": 500, "min_transfer": 100, "disabled": false } ] }
```

**GET `/v1/users/me/balances`**

```json
{ "items": [ { "currency": "bonus", "scale": 1, "balance": 900000, "held": 1000, "available": 899000, "locked": false } ] }
```

（`900000` 在 scale=1 时显示为 90000.0。）

**GET `/v1/users/me/entries?currency=bonus&limit=50&cursor=…`**

```json
{ "items": [ { "entry_id": "01928c3e-…", "currency": "bonus", "kind": "transfer", "amount": -10500,
               "balance_after": 889500, "reason": "ledger.user_gift", "memo": "谢谢补种",
               "counterparty": { "user_id": 20001 }, "reversed": false, "created_at": "2026-10-05T08:00:00.000Z" } ],
  "next_cursor": "…", "has_more": true }
```

游标 = base64url(`{"t":created_at,"e":entry_id,"l":line_no}`)，排序 `created_at DESC, entry_id DESC, line_no DESC`。

**POST `/v1/transfers`**（idempotent；`Idempotency-Key` 必填，缺失 400 `kernel.bad_request`）

请求：

```json
{ "currency": "bonus", "to_username": "alice", "amount": 10000, "memo": "谢谢补种" }
```

响应 201：

```json
{ "entry_id": "01928c3e-…", "amount": 10000, "fee": 500, "balance_after": 889500, "duplicate": false }
```

错误：403 `ledger.transfer_disabled` / `ledger.account_locked` / anticheat 拒绝码；422 `ledger.insufficient_balance`（`details: {available, required}`）、`ledger.amount_below_minimum`、`ledger.recipient_invalid`、`ledger.self_transfer`、`ledger.daily_limit_exceeded`；401 `kernel.two_factor_required`。

**POST `/v1/admin/adjustments`**（`ledger.balance.adjust`，idempotent；要求近期重新验证）

```json
{ "user_id": 10086, "currency": "bonus", "amount": -50000, "reason_note": "违规刷魔力值回收" }
```

正数为发行、负数为回收（`reason = "ledger.admin_adjust"`，`kind = adjust`，扣减时检查余额，不检查锁定）；响应 201 同转账。审计 `ledger.adjust`（前后余额、note）。

**POST `/v1/admin/entries/{id}/reversals`** `{ "reason_note": "…", "allow_negative": false }` → 201 `{ "reversal_entry_id": "…" }`。

**GET `/v1/admin/users/{id}/entries?currency=&cursor=&limit=`**（`ledger.balance.read`）→ 与 `/users/me/entries` 相同的分页结构；后台据此列出流水并对单笔冲正。

**POST `/v1/admin/users/{id}/locks`** `{ "currency": null, "reason_note": "…" }` → 201 `{ "lock_id": "…" }`；**DELETE `/v1/admin/locks/{lock_id}`** → 204。

**PATCH `/v1/admin/currencies/{code}`**（merge-patch）`{ "transferable": true, "fee_bps": 500 }` → 200 当前设置；写审计 `ledger.currency_settings`。

**GET `/v1/admin/currencies/{code}/supply`** → `{issued, burned, circulating, held}`；**GET `/v1/admin/reconcile-reports?day=&check=`**。

**POST `/v1/admin/grants/preview`**（`ledger.balance.adjust`）

```json
{ "currency": "bonus", "amount": 1000, "target": { "kind": "filter", "statuses": ["active"], "class_ids": [] },
  "direction": "grant", "shortfall": "skip" }
```

`direction`、`shortfall` 可省略（默认 `grant`、`skip`）。响应 200：

```json
{ "count": 3120, "insufficient": 0, "total_amount": 3120000, "scale": 1, "missing": [], "max_recipients": 200000,
  "notify_available": true, "default_subject": "你收到了 {amount} {currency}", "default_body": "…" }
```

**POST `/v1/admin/grants`**（`ledger.balance.adjust`，idempotent）

```json
{ "currency": "bonus", "amount": 1000, "memo": "国庆福利",
  "target": { "kind": "users", "usernames": ["alice", "bob"] },
  "notify": { "subject": "福利：{amount} {currency}", "body": "{username}，……当前余额 {balance}" } }
```

另可带 `direction`、`shortfall`（同预览）。`notify` 省略或为 null 表示不通知；`notify` 中标题 / 正文为空时用该方向的默认模板。响应 201 为批对象：`{id, currency, amount, direction, shortfall, moved, memo, target, notify, subject, body, state, total, granted, failed, notified, notify_failed, last_error, created_by, created_by_name, created_at, finished_at, scale}`（时间为毫秒时间戳；`moved` 为实际总额）。错误：422 `ledger.grant_no_recipients`、`ledger.grant_too_many`（`details: {max, count}`）、`ledger.amount_out_of_range`、`kernel.validation_failed`；403 `ledger.currency_disabled`。

**GET `/v1/admin/grants?before=&limit=`** → `{items: [批对象], next_before}`（按 id 倒序，limit 1～100，默认 20）。

**GET `/v1/admin/grants/{id}`** → 批对象 + `failures: [{user_id, username, error, notify_error, amount}]`：记账失败 / 跳过、只扣了一部分（`amount` ≠ 每人数量）、通知失败的人，最多 200 条。

**POST `/v1/admin/grants/{id}/resume`** → 200 批对象；已完成 → 422 `ledger.grant_finished`。

```sql
    user_id     bigint NOT NULL,
    currency    text NOT NULL REFERENCES currencies (code),
    balance     bigint NOT NULL DEFAULT 0,
    held        bigint NOT NULL DEFAULT 0 CHECK (held >= 0),
```

```sql
-- 0003_grant_deduct.sql
ALTER TABLE grant_batches
    ADD COLUMN direction  text NOT NULL DEFAULT 'grant' CHECK (direction IN ('grant','deduct')),
    ADD COLUMN shortfall  text NOT NULL DEFAULT 'skip' CHECK (shortfall IN ('skip','partial')),
    ADD COLUMN moved      bigint NOT NULL DEFAULT 0;   -- 实际总额
ALTER TABLE grant_recipients ADD COLUMN amount bigint;   -- 此人实际数量
```

分区声明：`entries`、`lines`：`range_month`，`premake = 3`，`retention_months = 0`（站点可设 ≥ 24 并开启归档）；`checkpoints`：`range_month`，永久。`supply_shards` 的 16 行在 `register_currency` 首次插入时一并插入（`INSERT … SELECT generate_series(0,15)`）。

**数据量估算**（设计容量 1000 万流水/天、平均 2.1 条分录）：`entries` 每月 3 亿行 × ~120 B ≈ 36 GB；`lines` 每月 6.3 亿行 × ~80 B（含索引约 2 倍）≈ 100 GB。以 bonus 每日合并发放为例（25 万用户/天）实际体量约为上述的 1/20。`accounts` ≈ 用户数 × 币种数（30 万 × 3 = 90 万行）。

### 3.2 Redis

不使用 Redis（DD-LED-11）。限流由内核网关处理（`k:rl:*`）。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 作用域 | 币种写操作需 `currency:<code>`（站点在 `[grants.<plugin>.scopes]` 授权）；锁定需 `lock`；读他人需 `read`；冲正跨插件需 `reverse` |
| 原因码前缀 | `reason` 必须以调用方插件 ID 开头，防止伪造他人来源 |
| 用户转账防滥用 | 路由限流 `user:10/m`；每日上限；最小金额；可选 2FA；收款人状态检查；钩子供 anticheat 拦截（如新号、被调查账户） |
| 管理员操作 | 调整、冲正、锁定要求近期重新验证（security.md §3）；全部写审计：`ledger.adjust`、`ledger.reverse`、`ledger.lock`、`ledger.unlock`、`ledger.currency_settings` |
| 输入 | 金额整数范围；memo NFC + 去控制字符 + ≤ 200；用户名经 identity 解析 |
| 信息泄露 | `recipient_invalid` 不区分“不存在/被封”；事件不含 memo；MCP 不返回 memo 原文以外的他人信息（memo 作为用户内容字段标注） |
| 数据完整性 | 只追加；运行期不执行 `UPDATE lines`/`DELETE entries`（除 purge 清 memo）；对账每日校验 |

## 7. 性能设计

| 路径 | 设计 | 预期 |
|---|---|---|
| `transfer`（用户间） | 1 次幂等 INSERT + 2 次条件 UPDATE + 2 INSERT + 1 UPDATE 分片 + 1 UPDATE 幂等；单事务 7 条语句 | p99 < 10 ms |
| 发行 | 同上少 1 次 UPDATE | < 6 ms |
| `transfer_batch` 1000 笔 | 幂等批量 INSERT（UNNEST）、账户批量 upsert（UNNEST，按 user_id 排序）、entries/lines 批量 INSERT、分片批量 UPDATE、事件 1000 条 | < 300 ms |
| `balance(s)` | 主键 / 前缀查询 | < 1 ms |
| `history` 首页 | `lines_user_currency_idx` 键集分页，只扫最近分区 | < 5 ms |
| 热点账户（如某用户同时收到大量打赏） | 行锁串行，每笔 ms 级；可接受 | |
| 对账 | 增量（昨日分区）+ 月度全量分批 | 日对账 < 10 分钟 |
