## 1. 设计目标与原则

1. **基线增量**：进度 = 当前值 − 分配时的值（NexusPHP 绝对值的改进）。
2. **指标复用**：与 levels 共用指标定义与计算 SQL（建议抽为共享 crate `pt-metrics`，见 §7）。
3. **处置可逆**：默认 restrict（可补救），封禁需显式配置。
4. **只评估进行中的考核**。

## 2. 总体结构

```
user.registered ─► auto_assign ─► assignments(active, baseline)
traffic.settled ─► dirty
cron evaluate（*/20 min：脏用户 + 临期）、evaluate_all（hourly）─► 判定阶段 ─► passed / failed ─► 处置（identity 限制）
```

| 模块 | 职责 |
|---|---|
| `exams` | 考核定义 |
| `assign` | 自动 / 手动分配、基线 |
| `metrics` | 指标计算（同 levels） |
| `evaluator` | 阶段判定、提醒、处置、补救 |
| `rewards` | 通过奖励 |
| `hooks` | `invite.before_issue` |

## 4. 数据设计概要

`exams`（定义 JSON）、`assignments`（user_id、exam_id、state、assigned_at、baseline JSON、stage_index、stage_deadline、prewarned、restricted、result_at）、`dirty_users`、`rewards_given`。

## 5. 关键流程

```
auto_assign(evt user.registered):
  for rule in auto_assign_rules: if predicate(rule.when, {registration_mode, inviter_class_id, …}): assign(uid, rule.exam_id)；break
assign(uid, exam):
  if 已有 active 考核: 返回 newbie-exam.already_assigned（幂等键相同则返回首次结果）
  if 等级豁免: exempted
  baseline = metrics(uid)；INSERT assignments(state=active, stage 0, stage_deadline = assigned_at + stage[0].days)
evaluate(a):
  cur = metrics(uid)；delta = cur − baseline（ratio 用绝对值）
  stage 全部目标达成 → stage_passed；有下一阶段 → stage_index+1（截止时间按考核开始计算）；否则 passed（奖励）
  now ≥ stage_deadline 且未达成 → failed（处置）
  失败且 restrict 且 remedy_days > 0：补救期内达成全部阶段目标 → lift_restriction，state = remedied
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-EXAM-1 | 阶段截止时间基准 | 从分配时间起算的累计天数（第 1 阶段 7 天、第 2 阶段 30 天），而非每阶段重新计时，便于公告 |
| DD-EXAM-2 | 默认处置 | restrict（禁止下载）：用户可联系管理员或补救；封禁不可逆，需显式配置 |
| DD-EXAM-3 | 指标实现 | 与 levels 共用（共享 crate），避免两套口径 |

## 7. 对平台契约的新增

服务 `assign` / `exempt` 补幂等键；事件 `exam.exempted`、`exam.stage_passed`、`exam.remedied`；共享 crate `pt-metrics`（levels 与 newbie-exam 共用的指标计算，读同一组视图）；术语 `newbie-exam.exam.<id>`。
