## 1. 引言

### 1.1 目的

定义新手考核插件 `newbie-exam` 的需求：新注册用户必须在限定时间内达到上传量、做种时长、魔力值等目标，未通过的按配置处置。

### 1.2 范围

包含：考核定义（多指标、多阶段、期限）、自动分配（注册时）与手动分配、基线与增量计算、进度展示、通过 / 失败判定与处置、豁免、通过奖励（可选，经 medals / ledger）、状态查询、MCP。

不包含：等级（levels）、分享率（ratio-policy）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 考核（exam） | 一组目标 + 期限；可分为多个阶段（stage） |
| 基线 | 分配考核时记录的指标值；进度 = 当前值 − 基线 |
| 处置 | 未通过时的动作：none / restrict（禁止下载）/ ban |

### 1.4 参考资料

- docs/platform/、docs/plugins/levels/（指标定义）、docs/plugins/identity/（限制机制）
- NexusPHP 1.7+ 考核（exam）：新手考核、指标（上传量、做种时间、魔力值、做种积分、下载量），考核期满未完成封禁；多个考核可按等级分配
- 国内 PT 站常见做法：新人 7～30 天内上传 N GB、做种 M 小时，否则封号

## 2. 总体描述

### 2.1 插件定位

- WASM，ID `newbie-exam`，缩写 `EXAM`；提供 `ctx.exams`。
- 依赖：`ctx.users`（限制）；可选 `ctx.medals`（通过奖励）、`ctx.notify`。
- 视图：`accounting.v_user_totals`、`ledger.v_balance`、`identity.v_user_public`、`torrent.v_torrent_public`。
- 订阅：`user.registered`、`traffic.settled`（脏用户）、`user.deleted`。
- 处理钩子：`invite.before_issue`（考核中不能发邀，可配置）。

### 2.2 用户角色与使用场景

新用户：首页看到考核卡片（剩余时间、各指标进度）。管理员：定义考核、按注册方式分配、手动分配 / 豁免 / 延期、查看通过率。

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP 考核 | 后台定义考核（指标、目标、期限、适用等级 / 注册时间范围），定时任务检查；未通过封禁 | 指标多样、可按条件批量分配 | 进度用绝对值（老用户转入考核时不公平）；处置只有封禁；检查任务全量扫描 | **采纳**多指标、按条件分配；**改进**：基线增量计算；处置可选（默认禁止下载而非封禁）；只评估进行中的考核 |

### 2.4 约束与假设

指标与 levels 相同（同一白名单与计算方式）；规模：日新注册 ≤ 2000，同时进行中的考核 ≤ 6 万。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-EXAM-001 | 考核定义 | 名称、描述、期限（天）、阶段列表（每阶段：截止天数 + 目标列表）、处置、通过奖励、适用条件 | P0 | 后台可配置 |
| FR-EXAM-002 | 指标 | 目标可用指标：`uploaded`、`downloaded`、`seed_secs`、`uploads_count`、`balance:<currency>`（均为增量），以及 `ratio`（绝对值） | P0 | |
| FR-EXAM-003 | 自动分配 | 订阅 `user.registered`，按规则（注册方式：邀请 / 开放 / 申请；邀请人等级等）分配考核 | P0 | 新用户注册后获得考核 |
| FR-EXAM-004 | 手动分配 | 管理员为一批用户分配考核；服务 `assign(user_id, exam_id)` | P1 | |
| FR-EXAM-005 | 基线 | 分配时记录各指标当前值作为基线 | P0 | 进度从 0 开始 |
| FR-EXAM-006 | 进度 | `status(user)` 返回各阶段、各目标的当前增量、目标值、截止时间 | P0 | |
| FR-EXAM-007 | 阶段判定 | 每阶段截止前全部目标达成 → 阶段通过；最后阶段通过 → 考核通过 | P0 | 发布 `exam.passed` |
| FR-EXAM-008 | 失败处置 | 任一阶段截止时未达成 → 失败，执行处置：none / restrict（leech_disabled）/ ban；发布 `exam.failed` | P0 | 默认 restrict |
| FR-EXAM-009 | 失败后补救 | restrict 处置后，用户补齐目标（在 `remedy_days` 内）可自动解除并视为通过 | P2 | |
| FR-EXAM-010 | 豁免 | 服务 `exempt(user, reason)`、管理员豁免；等级豁免 | P1 | 发布 `exam.exempted` |
| FR-EXAM-011 | 延期 | 管理员为用户延长期限 | P2 | |
| FR-EXAM-012 | 通过奖励 | 可选：授予勋章（`medals.grant`）或币种奖励（`ledger.transfer` 系统发行） | P2 | 只奖励一次 |
| FR-EXAM-013 | 考核期限制 | 可选：考核中不能发邀 | P1 | |
| FR-EXAM-014 | 临期提醒 | 阶段截止前 `prewarn_hours` 未达成时提醒 | P2 | |
| FR-EXAM-015 | 统计 | 每个考核的分配数、通过率、失败数 | P2 | |
| FR-EXAM-016 | MCP | `get_my_exam`（已登记） | P2 | |
| FR-EXAM-017 | 用户删除 | 清理 | P1 | |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-EXAM-001 | 性能 | 评估 | 6 万进行中考核每小时全量评估 ≤ 3 分钟 |
| NFR-EXAM-002 | 可靠性 | 幂等 | 重复事件不重复分配；重复评估不重复处置 |
| NFR-EXAM-003 | 公平性 | 基线 | 进度只计算分配后的增量 |

## 5. 可配置项与站点术语

运行时设置：`auto_assign_rules`（`[{when: 谓词（registration_mode、inviter_class_id）, exam_id}]`）、`prewarn_hours`（48）、`block_invite_during_exam`（true）、`exempt_class_ids`（[]）、`remedy_days`（0）。

术语：`newbie-exam.name`（已登记）；新增 `newbie-exam.exam.<id>`（考核名，动态）。

## 6. 外部接口需求概述

服务 `ctx.exams`（`status`、`assign`、`exempt`）；事件 `exam.assigned`、`exam.passed`、`exam.failed`（已登记），新增 `exam.exempted`、`exam.stage_passed`；HTTP `/api/p/newbie-exam/v1/*`；插槽 `home.widgets`、`user.profile.stats`；MCP `get_my_exam`。
