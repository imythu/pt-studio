## 1. 模块详细设计

### 1.1 考核定义（`exams.definition`，`schemas/exam.v1.json`）

```json
{
  "schema": 1,
  "name_zh": "新手考核", "name_en": "Newbie Exam",
  "description_md": "注册后 30 天内完成以下目标……",
  "stages": [
    { "days": 7,  "goals": [ { "metric": "uploaded", "gte": 10737418240 } ] },
    { "days": 30, "goals": [ { "metric": "uploaded", "gte": 53687091200 },
                             { "metric": "seed_secs", "gte": 1080000 },
                             { "metric": "balance:bonus", "gte": 5000 } ] }
  ],
  "on_fail": "restrict",
  "reward": { "medal_id": 21, "currency": null, "amount": 0 }
}
```

校验：阶段 1～5 个，`days` 严格递增且 ≤ 365；每阶段目标 1～8 个；指标白名单同 levels 03 §1.2（`uploaded`、`downloaded`、`seed_secs`、`uploads_count`、`balance:<currency>`、`ratio`）；`on_fail ∈ {none, restrict, ban}`；`ban` 需要设置 `allow_ban = true` 才能保存。

### 1.2 assign

```
assign(uid, exam_id, by, idem):
  幂等（caller, idem）命中 → 返回
  SELECT … FROM assignments WHERE user_id=$1 AND state IN ('active','failed_restricted') FOR UPDATE → 存在 → newbie-exam.already_assigned
  u = users.get(uid)；u.class_id ∈ exempt_class_ids → INSERT state='exempted'；publish exam.exempted；return
  baseline = metrics::snapshot(uid, metrics_used(exam))   // 只取考核引用的指标
  INSERT assignments(user_id, exam_id, state='active', assigned_at=now, baseline, stage_index=0,
                     stage_deadline = now + stages[0].days)
  publish exam.assigned{user_id, exam_id, deadline = 最后阶段截止}
on_registered(evt)：遍历 auto_assign_rules（谓词字段：registration_mode、inviter_class_id、has_invite），命中第一条即分配（幂等键 "<event_id>:assign"）
```

### 1.3 evaluator

```
evaluate_one(a):
  exam = exams[a.exam_id]；cur = metrics::snapshot(uid, used)
  d(metric) = metric == ratio ? cur.ratio : cur[metric] − a.baseline[metric]（下限 0）
  stage = exam.stages[a.stage_index]
  done = all(d(g.metric) ≥ g.gte for g in stage.goals)
  if a.state == 'active':
     if done:
        publish exam.stage_passed；if 有下一阶段: stage_index+1；stage_deadline = assigned_at + stages[i+1].days；prewarned=false
        else: state='passed'；rewards::give(a)；publish exam.passed
     elif now ≥ a.stage_deadline:
        match exam.on_fail:
          none     → state='failed'
          restrict → users.apply_restriction({kind: leech_disabled, reason_code: "newbie-exam.failed",
                                               until: None, idempotency_key: "exam:r:<assignment_id>"}) → state='failed_restricted'
          ban      → apply_restriction(kind: banned, …) → state='failed_banned'
        publish exam.failed{action}
     elif !a.prewarned && a.stage_deadline − now ≤ prewarn_hours: prewarned=true；notify
  elif a.state == 'failed_restricted' && remedy_days > 0 && now ≤ result_at + remedy_days:
     若最后阶段全部目标 done（以最后阶段目标为准）→ users.lift_restriction(uid, leech_disabled, "newbie-exam.remedied", "exam:l:<id>")；
        state='remedied'；publish exam.remedied
```

调度：`evaluate`（每 20 分钟）处理 `dirty_users`（来自 `traffic.settled`）∪ `stage_deadline < now + 1h` 的考核；`evaluate_all`（每小时）键集分页处理所有 `active` 与补救期内的 `failed_restricted`。

### 1.4 rewards

`rewards_given(assignment_id)` 唯一；`medals.grant({user, medal_id, reason: "newbie-exam.passed", idempotency_key: "exam:m:<id>"})`；币种奖励 `ledger.transfer({from: None, to: uid, amount, reason: "newbie-exam.reward", idempotency_key: "exam:c:<id>"})`。失败保留 `pending`，`evaluate_all` 重试。

### 1.5 hooks

`invite.before_issue`：`block_invite_during_exam` 且 inviter 有 `active` 或 `failed_*` 考核 → deny(`newbie-exam.restricted`)。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:exams@0.1.0`）

```wit
package pt:exams@0.1.0;

interface exams {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms};

  record goal-progress { metric: string, target: string, current: string, met: bool }
  record stage-progress { index: u8, deadline: timestamp-ms, goals: list<goal-progress>, passed: bool }
  record exam-progress {
    assignment-id: u64, exam-id: u64, name-key: string, state: string,
    current-stage: u8, stages: list<stage-progress>, action-on-fail: string,
  }

  status: func(user: user-id) -> result<option<exam-progress>, plugin-error>;
  assign: func(user: user-id, exam-id: u64, idempotency-key: string) -> result<u64, plugin-error>;
  exempt: func(user: user-id, reason: string, idempotency-key: string) -> result<_, plugin-error>;
}
```

`assign` / `exempt` 需作用域 `write`。

### 2.2 事件载荷（版本 1）

| 事件 | 字段 |
|---|---|
| `exam.assigned` | `user_id, exam_id, assignment_id, deadline` |
| `exam.stage_passed` | `user_id, exam_id, assignment_id, stage` |
| `exam.passed` | `user_id, exam_id, assignment_id` |
| `exam.failed` | `user_id, exam_id, assignment_id, stage, action(none/restrict/ban)` |
| `exam.exempted` | `user_id, exam_id?, reason` |
| `exam.remedied` | `user_id, exam_id, assignment_id` |

### 2.3 HTTP API

**GET `/v1/me`** →

```json
{ "assignment_id": 77, "exam": "新手考核", "state": "active", "current_stage": 0, "action_on_fail": "restrict",
  "stages": [ { "index": 0, "deadline": "2026-10-12T08:00:00Z", "passed": false,
                "goals": [ { "metric": "uploaded", "target": "10737418240", "current": "3221225472", "met": false } ] } ] }
```

无考核时 `204`。

**POST `/v1/admin/assign`** `{ "exam_id": 3, "user_ids": [ … ≤ 1000 ], "reason": "…" }` → `{ "results": [ { "user_id": 1, "assignment_id": 90 }, { "user_id": 2, "error": "newbie-exam.already_assigned" } ] }`。

**POST `/v1/admin/users/{id}/exempt`** `{ "reason": "…" }`；**POST `/extend`** `{ "days": 7 }`（顺延当前及后续阶段截止时间）。

### 2.4 MCP 工具

`get_my_exam`：出参同 GET /me。

## 3. 数据库设计（schema `newbie_exam`）

```sql
CREATE TABLE newbie_exam.exams (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    definition  jsonb NOT NULL,
    active      boolean NOT NULL DEFAULT true,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE newbie_exam.assignments (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id         bigint NOT NULL,
    exam_id         bigint REFERENCES newbie_exam.exams (id),
    state           text NOT NULL CHECK (state IN ('active','passed','failed','failed_restricted','failed_banned',
                                                   'remedied','exempted')),
    assigned_at     timestamptz NOT NULL,
    baseline        jsonb NOT NULL DEFAULT '{}',
    definition_snapshot jsonb NOT NULL,          -- 分配时的考核定义（之后修改考核不影响进行中的考核）
    stage_index     smallint NOT NULL DEFAULT 0,
    stage_deadline  timestamptz,
    prewarned       boolean NOT NULL DEFAULT false,
    result_at       timestamptz,
    assigned_by     text NOT NULL,
    reason          text NOT NULL DEFAULT ''
);
CREATE UNIQUE INDEX assignments_one_open_idx ON newbie_exam.assignments (user_id)
    WHERE state IN ('active', 'failed_restricted');
CREATE INDEX assignments_deadline_idx ON newbie_exam.assignments (stage_deadline) WHERE state = 'active';

CREATE TABLE newbie_exam.dirty_users (user_id bigint PRIMARY KEY, since timestamptz NOT NULL);

CREATE TABLE newbie_exam.rewards_given (
    assignment_id bigint PRIMARY KEY, state text NOT NULL CHECK (state IN ('pending','done'))
);

CREATE TABLE newbie_exam.idempotency (
    caller text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (caller, key)
);
```

`evaluate_one` 使用 `definition_snapshot` 而非 `exams.definition`。

## 4. 配置项

见 SRS §5，另加 `allow_ban`（false）。清单：`requires = ["ctx.users@^0.1"]`；`optional_requires = ["ctx.medals@^0.1", "ctx.ledger@^0.1", "ctx.notify@^0.1"]`；scopes：`ctx.users = ["write:status"]`、`ctx.medals = ["grant"]`、`ctx.ledger = ["currency:bonus"]`；订阅三项；钩子 `invite.before_issue`；cron 两项。

## 5. 前端设计

首页考核卡片（阶段进度条、倒计时、未达成目标高亮）；个人页统计；后台考核编辑器（阶段与目标表格）、分配规则编辑、统计（分配 / 通过 / 失败 / 补救）。

## 6. 安全设计

封禁需显式开关；处置写审计；只解除本插件来源的限制；员工被 identity 拒绝限制时记录跳过。

## 7. 性能设计

进行中考核 ≤ 6 万；每小时全量 30 批 × 2000；指标查询复用 levels 的批量 SQL。

## 8. 可观测性

`pt_plugin_newbie_exam_assignments{state}`（gauge）、`pt_plugin_newbie_exam_results_total{result}`、`pt_plugin_newbie_exam_evaluate_seconds`。
