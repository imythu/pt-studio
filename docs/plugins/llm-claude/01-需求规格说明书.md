## 1. 引言

### 1.1 目的

定义 `ctx.llm` 的 Anthropic Claude 提供方插件 `llm-claude` 的需求。接口见 [../_shared/llm-interface-common.md](../_shared/llm-interface-common.md)。

### 1.2 范围

包含：Messages API（`POST https://api.anthropic.com/v1/messages`）调用、模型与 profile 配置、工具调用、结构化输出（`output_config.format` JSON Schema）、思考深度（`output_config.effort`）、提示缓存（`cache_control`）、token 计数（`POST /v1/messages/count_tokens`，用于配额预估）、refusal 处理与服务端回退（`fallbacks: "default"`）、重试、计量与配额、敏感模式兜底脱敏。

不包含：流式输出（v0.1 不提供）、批处理 API、Files API、Managed Agents、服务端工具（网页搜索等）。**嵌入（embed）**：Anthropic 不提供嵌入接口（官方建议使用第三方嵌入服务），本插件的 `embed` 返回 `llm-claude.unsupported`；站点需要语义搜索时，嵌入由 Meilisearch 内置 embedder 或 `llm-openai-compat`（本地嵌入模型）提供。

### 1.3 参考资料

- Claude API 文档（Messages、Tool use、Structured outputs、Prompt caching、Token counting、Errors）；本设计中的模型 ID 与参数以 2026-10 的官方文档为准，部署前核对
- docs/platform/catalog/services.md §2.1（profiles）

## 2. 总体描述

Native 插件（Rust），ID `llm-claude`，缩写 `LLMC`；提供 `ctx.llm`（single 候选）。Anthropic 没有官方 Rust SDK，本插件以原始 HTTPS 调用 API（`reqwest` 经内核 `ctx.http`）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-LLMC-001 | complete | 实现 `complete`：把接口请求映射为 Messages API 请求，响应映射回接口 | P0 | |
| FR-LLMC-002 | 模型与 profile | `site.toml [plugin.llm-claude.profiles]`：每个 profile 指定 `model`、`max_tokens`、`effort`；默认 profile 使用 `claude-opus-5-5`；建议的低成本 profile `cheap` 使用 `claude-haiku-4-5` | P0 | |
| FR-LLMC-003 | 工具 | 工具定义映射为 `tools[]`（`input_schema`、`strict`）；`tool_mode = auto` → `tool_choice: {type: "auto"}`；`none` → `{type: "none"}`；不发送 `any` / `tool`（当前 Opus 5.5、Sonnet 5.5 等模型会返回 400） | P0 | |
| FR-LLMC-004 | 结构化输出 | `output_schema` → `output_config.format = {type: "json_schema", schema}`；发送前把 API 不支持的约束（minimum / maximum / minLength / maxLength 等）从 schema 中移除，并在收到结果后用完整 schema 本地校验 | P0 | |
| FR-LLMC-005 | 思考深度 | `effort`（low / medium / high）→ `output_config.effort`；未指定时使用 profile 配置（Opus 5.5 的 API 默认值为 medium，插件显式发送） | P0 | |
| FR-LLMC-006 | 提示缓存 | `system` 块与前 `cache_prefix_messages` 条消息之后放置 `cache_control: {type: "ephemeral"}`；记录 `cache_read_input_tokens` | P1 | 重复请求缓存命中 |
| FR-LLMC-007 | refusal | `stop_reason = "refusal"` → `stop = refusal`；默认启用服务端回退 `fallbacks: "default"`（请求头 `anthropic-beta: server-side-fallback-2026-07-01`），可在配置中关闭 | P0 | |
| FR-LLMC-008 | 重试 | 429 / 500 / 529 / 网络错误重试 2 次，尊重 `retry-after`；400 / 401 / 403 / 404 / 413 不重试 | P0 | |
| FR-LLMC-009 | 计量与配额 | 每次调用发布 `llm.usage_recorded`；插件 / 用户每日 token 配额；调用前用 `count_tokens`（可选）预估大请求 | P0 | |
| FR-LLMC-010 | 敏感兜底 | 发送前扫描 32 位十六进制 passkey 模式、邮箱、IP 地址，替换为占位符并计数告警 | P1 | |
| FR-LLMC-011 | 不可信内容 | `untrusted` 内容包裹为 `<user_content>` 并在系统提示末尾附加固定说明 | P0 | |
| FR-LLMC-012 | models | `models()` 返回各 profile 的模型与能力（`supports_embed = false`） | P1 | |
| FR-LLMC-013 | 配置校验 | 启动时校验 API key 存在；可选调用 `GET /v1/models/{id}` 校验模型可用 | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-LLMC-001 | 插件开销 | 除上游耗时外 < 5 ms |
| NFR-LLMC-002 | 安全 | API key 只在静态配置，不进日志；不记录提示词与输出 |
| NFR-LLMC-003 | 可观测 | 请求数、错误码分布、token 用量、缓存命中、refusal 次数 |

## 5. 可配置项

静态：`api_key`（secret）、`api_base`（`https://api.anthropic.com`）、`profiles`、`fallbacks_enabled`（true）。运行时：`quota.per_plugin_daily_tokens`、`quota.per_user_daily_tokens`、`debug_logging`（false，24 小时自动关闭）。

## 6. 外部接口需求概述

服务 `ctx.llm`；事件 `llm.usage_recorded`（已登记）；HTTP `/api/p/llm-claude/v1/admin/usage`、`/admin/test`（sysop）；无前端插槽（后台设置页由 schema 生成）。
