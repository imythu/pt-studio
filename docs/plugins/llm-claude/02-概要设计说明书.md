| 类别 | 内容 |
|---|---|
| 原则 | 接口与提供方解耦（共用设计）；HTTP 直连（无官方 Rust SDK）；默认安全（不记录内容、敏感兜底、不可信内容标记） |
| 模块 | `mapper`（接口 ↔ Messages API）、`schema`（结构化输出 schema 降级与本地校验，`jsonschema` crate）、`client`（HTTP、头、重试、超时）、`quota`（Redis 计数）、`scrub`（敏感模式）、`idem`（幂等缓存）、`usage`（计量事件） |
| 服务 | `ctx.llm`：`complete`、`embed`（返回 unsupported）、`models` |
| 依赖 | 内核 `ctx.http`（出站 `api.anthropic.com`）、`ctx.redis`（配额）、`ctx.kv`（幂等缓存）、`ctx.events` |
| 事件 | 发布 `llm.usage_recorded` |
| HTTP | `GET /api/p/llm-claude/v1/admin/usage?from&to&group_by=plugin|model`、`POST /v1/admin/test`（`llm-claude.manage`） |
| 关键流程 | 配额预检 → scrub → mapper 构造请求 → client（重试）→ 解析响应（refusal、tool_use、结构化 JSON 本地校验）→ 计量事件 → 幂等缓存 → 返回 |
| 设计决策 | DD-LLMC-1：不暴露强制工具调用（当前模型拒绝 `any` / `tool`），调用方用 `auto` + 提示词或结构化输出；DD-LLMC-2：结构化输出 schema 先降级（移除 API 不支持的数值 / 长度约束）再本地完整校验；DD-LLMC-3：默认启用 `fallbacks: "default"` 服务端回退，refusal 时 API 在同一次调用内由回退模型重试（可关闭）；DD-LLMC-4：v0.1 不使用流式，`max_tokens` 默认 16000（非流式请求的建议上限），调用方可调低；DD-LLMC-5：不支持 embed（Anthropic 无嵌入接口） |
| 平台契约新增 | `ctx.llm` 的 WIT 以共用设计为准（`pt:llm@0.1.0`）；`llm.usage_recorded` 增加字段 `cached_input_tokens`、`end_user_id?`、`stop`；错误码见共用设计 §4 |
| 权限点 | `llm-claude.manage`（已登记） |

需求追溯：FR-001～007、011 → mapper、schema；FR-008、013 → client；FR-009 → quota、usage；FR-010 → scrub；FR-012 → models。
