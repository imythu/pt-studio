## 1. 模块详细设计

### 1.1 rules

设置 `exempt_rules`（谓词规则列表，任一成立即豁免）：

```json
[
  { "id": "small",       "when": [ { "field": "size", "op": "lt", "value": 524288000 } ] },
  { "id": "own_upload",  "when": [ { "field": "is_uploader", "op": "eq", "value": true } ] },
  { "id": "freeleech",   "when": [ { "field": "promotion_kind", "op": "in", "value": ["free", "double_up_free"] } ] },
  { "id": "partial",     "when": [ { "field": "downloaded_pct", "op": "lt", "value": 0.1 } ] },
  { "id": "seedbox",     "when": [ { "field": "is_seedbox", "op": "eq", "value": true } ] }
]
```

可用字段：`size`、`type_id`、`tags`、`promotion_kind`、`class_id`、`is_uploader`、`is_seedbox`、`downloaded_pct`、`account_age_days`。默认规则：`small`（500 MiB）、`own_upload`、`partial`。

### 1.2 records：创建


### 1.3 evaluator

**分层**：

| 任务 | 选择条件 | 批大小 |
|---|---|---|
| `evaluate_hot` | `state = 'active' AND deadline < now + 48h`（含已过期但未判定的） | 5000 |
| `evaluate_cold` | `state = 'active' AND deadline ≥ now + 48h AND hashtext(user_id::text) % 6 = (hour % 6)` | 5000 |

```
evaluate_batch(rows)（tx manual，每批提交）:
  snaps = SELECT user_id, torrent_id, uploaded, downloaded, seed_secs FROM accounting.v_snatch
          WHERE (user_id, torrent_id) IN (SELECT * FROM unnest($1::bigint[], $2::bigint[]))
  sizes = torrent.v_torrent_public（只在 min_torrent_ratio > 0 时）
  for r in rows:
    sn = snaps[(r.user_id, r.torrent_id)]（缺失视为 0）
    ok = sn.seed_secs >= min_seed_hours*3600 ||
         (min_torrent_ratio > 0 && sn.uploaded as f64 >= min_torrent_ratio * max(sn.downloaded, size) as f64)
    UPDATE records SET seed_secs_snapshot = sn.seed_secs, ratio_snapshot = …
    if ok: state='satisfied', resolved_at=now；user_counts.active−1；publish hnr.satisfied
    elif now >= deadline + grace_hours: state='failed', failed_at=now；user_counts.active−1, failed+1；publish hnr.failed；penalty::recount(uid)
    elif deadline − now <= prewarn_hours && !prewarned: prewarned=true；publish hnr.prewarned；notify（幂等键 "hnr:pw:<record_id>"）
```

### 1.4 penalty

```
recount(uid):
  n = SELECT count(*) FROM records WHERE user_id=$1 AND state='failed' AND failed_at > now − expire_days
  UPDATE user_counts SET failed_effective = n
  if n >= max_hnr && !restricted:
     users.apply_restriction({user: uid, kind: leech_disabled, reason_code: "hnr.too_many",
                              idempotency_key: "hnr:r:<uid>:<seq+1>"}) → restricted = true, seq+1
  elif n < max_hnr && restricted:
     users.lift_restriction(uid, Some(leech_disabled), "hnr.below_limit", "hnr:l:<uid>:<seq>") → restricted = false
```

`expire_counts`（每日）：对 `user_counts.failed_effective > 0` 的用户分批 `recount`（处理过期）。员工（identity 返回 forbidden）记录 `restricted_skipped`。

### 1.5 forgive

```
forgive(record_id, reason, idem, actor):
  r = FOR UPDATE；state ∈ {failed, active}，否则 hnr.not_forgivable
  幂等（caller, idem）
  prev = r.state；state='forgiven', forgiven_by, forgive_reason
  user_counts：prev == failed → failed−1；prev == active → active−1
  publish hnr.forgiven；if prev == failed: recount(uid)
```

批量免除（管理员）：按条件（用户、种子、时间段）选出记录，分批执行。

### 1.6 订阅

- `on_torrent_deleted` / `on_torrent_status`（to ∈ {deleted, disabled}）：`UPDATE records SET state='exempted', exempt_rule='torrent_removed' WHERE torrent_id=$1 AND state='active'`（分批），更新计数；**已 failed 的记录不自动豁免**（配置 `forgive_failed_on_removal`，默认 false）。
- `on_user_deleted`（purge）：逐分区删除；`user_counts` 删除。

### 1.7 hooks

```
torrent.before_download(input{user_id, torrent_id}):
  c = user_counts[user_id]；if c.failed_effective >= max_hnr: deny("hnr.download_restricted", …)   // 与 identity 限制双保险，限制生效前的空窗
  allow
invite.before_issue(input{inviter_id}): c.failed_effective >= invite_block_at → deny("hnr.restricted", "有未处理的 H&R，不能发送邀请")
```

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:hnr@0.1.0`）

```wit
package pt:hnr@0.1.0;

interface hnr {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  enum record-state { active, satisfied, failed, forgiven, exempted }
  record hnr-status { active: u32, failed: u32, can-download: bool, max: u32 }
  record hnr-record {
    id: u64, torrent-id: u64, state: record-state, completed-at: timestamp-ms, deadline: timestamp-ms,
    seed-secs: u64, required-seed-secs: u64, ratio: option<f64>, required-ratio: option<f64>,
    exempt-rule: option<string>,
  }
  record record-filter { state: option<record-state> }
  record record-page { items: list<hnr-record>, next-cursor: option<string> }

  status: func(user: user-id) -> result<hnr-status, plugin-error>;
  records: func(user: user-id, filter: record-filter, cursor: option<string>) -> result<record-page, plugin-error>;
  forgive: func(record-id: u64, reason: string, idempotency-key: string) -> result<_, plugin-error>;
}
```

`forgive` 需作用域 `forgive`；调用方为 shop 时，shop 自行校验记录属于购买者（shop 03 §1.3）。

### 2.2 事件载荷（版本 1）

| 事件 | 字段 |
|---|---|
| `hnr.recorded` | `record_id, user_id, torrent_id, deadline` |
| `hnr.exempted` | `record_id, user_id, torrent_id, rule` |
| `hnr.prewarned` | `record_id, user_id, torrent_id, deadline, seed_secs, required_seed_secs` |
| `hnr.satisfied` | `record_id, user_id, torrent_id` |
| `hnr.failed` | `record_id, user_id, torrent_id, failed_effective` |
| `hnr.forgiven` | `record_id, user_id, by, reason` |

### 2.3 HTTP API

**GET `/v1/me`** → `{ "active": 12, "failed": 1, "max": 5, "can_download": true, "rules": { "window_days": 14, "min_seed_hours": 72, "min_torrent_ratio": 1.0 } }`

**GET `/v1/me/records?state=active&cursor=`** → `{ "items": [ { "id": 8812, "torrent_id": 5501, "title": "Some.Movie.2023.1080p", "state": "active", "deadline": "…", "seed_secs": 90000, "required_seed_secs": 259200, "ratio": 0.32, "required_ratio": 1.0 } ], "next_cursor": "…" }`

**POST `/v1/records/{id}/forgive`** `{ "reason": "…" }` → 204（`hnr.forgive`）。

**GET `/v1/torrents/{id}/requirement`** → `{ "required": true, "exempt_rule": null, "min_seed_hours": 72, "window_days": 14 }`（对当前用户预判豁免，促销以当前状态为准）。

**PUT `/v1/admin/rules`**：全部设置与豁免规则；校验谓词字段白名单 → 422 `hnr.rule_invalid`。

### 2.4 MCP 工具

`list_my_hnr`（出参同 `/me/records`，默认 state = active + failed）；`admin_forgive_hnr`（入参 `{record_id, reason}`，write，确认）。

## 3. 数据库设计（schema `hnr`）

```sql
CREATE TABLE hnr.records (
    id                  bigint GENERATED ALWAYS AS IDENTITY,
    user_id             bigint NOT NULL,
    torrent_id          bigint NOT NULL,
    completed_at        timestamptz NOT NULL,
    deadline            timestamptz NOT NULL,
    state               text NOT NULL CHECK (state IN ('active','satisfied','failed','forgiven','exempted')),
    exempt_rule         text,
    prewarned           boolean NOT NULL DEFAULT false,
    seed_secs_snapshot  bigint NOT NULL DEFAULT 0,
    ratio_snapshot      double precision,
    resolved_at         timestamptz,
    failed_at           timestamptz,
    forgiven_by         text,
    forgive_reason      text,
    PRIMARY KEY (completed_at, id),
    UNIQUE (user_id, torrent_id, completed_at)
) PARTITION BY RANGE (completed_at);
CREATE INDEX records_active_deadline_idx ON hnr.records (deadline) WHERE state = 'active';
CREATE INDEX records_user_idx ON hnr.records (user_id, completed_at DESC);
CREATE INDEX records_torrent_active_idx ON hnr.records (torrent_id) WHERE state = 'active';
CREATE INDEX records_failed_idx ON hnr.records (user_id, failed_at) WHERE state = 'failed';

CREATE TABLE hnr.user_counts (
    user_id           bigint PRIMARY KEY,
    active            integer NOT NULL DEFAULT 0,
    failed_effective  integer NOT NULL DEFAULT 0,
    restricted        boolean NOT NULL DEFAULT false,
    restricted_seq    integer NOT NULL DEFAULT 0,
    restricted_skipped boolean NOT NULL DEFAULT false,
    updated_at        timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE hnr.idempotency (
    caller text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (caller, key)
);
```

分区按月、保留 13 个月（`expire_days` ≤ 365，否则校验拒绝）。`records` 的 `(user_id, torrent_id)` 查找走 `records_user_idx` + 过滤（每用户记录数有限）。

## 4. 配置项

见 SRS §5；校验：`window_days` 1～60、`min_seed_hours` 0～720、`expire_days` 1～365、`max_hnr` 1～1000。清单：`requires = ["ctx.users@^0.1"]`、`optional_requires = ["ctx.promotions@^0.1", "ctx.seedbox@^0.1", "ctx.notify@^0.1"]`；订阅四项（`on_snatch_completed` ordered = true）；钩子两项；cron 三项；`records` 分区。

## 5. 前端设计

个人页统计（考核中 / 已计入 / 上限）；“H&R”标签页（列表、进度条、剩余时间、违规记录可跳转商城“消除 H&R”）；种子列表徽标（我在考核中的种子显示剩余时间，按页批量查询 `GET /me/records?torrent_ids=`）；种子页提示是否需要考核。

## 6. 安全设计

用户只能看自己的记录；查看他人需 `hnr.read`；免除写审计；限制来源隔离。

## 7. 性能设计

- 创建：每事件 3～4 次主键 / 索引查询；日 50 万次，平均 6 次/秒。
- 评估：hot 层预计每 10 分钟 ≤ 50 万条；cold 层每小时约 100 万条；每批 5000 一次 `v_snatch` 批量查询。
- 钩子：`user_counts` 主键查询。

## 8. 可观测性

`pt_plugin_hnr_records_total{state}`、`pt_plugin_hnr_active`（gauge）、`pt_plugin_hnr_evaluate_seconds{tier}`、`pt_plugin_hnr_restrictions_total{op}`。
