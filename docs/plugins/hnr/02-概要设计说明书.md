## 1. 设计目标与原则

1. **只评估在考核中的记录**，按期限分层（临期的评估更频繁），避免全表扫描（UNIT3D / NexusPHP 的改进）。
2. **数据来自 accounting**：做种时长与单种上传下载从 `v_snatch` 读取，不自行累计。
3. **限制来源隔离**：处罚用 identity 带来源限制。
4. **豁免数据驱动**：谓词规则（字段：体积、标签、促销、等级、本人发布、盒子、下载占比）。

## 2. 总体结构

```
traffic.snatch_completed ─► create（豁免判定）─► records(active)
cron evaluate_hot（*/10 min：期限 < 48h）/ evaluate_cold（hourly：其余 active，分 6 片轮转）
  └─► 读 v_snatch（批量 user_id,torrent_id）─► satisfied / failed / prewarn
failed 变化 ─► recount(user) ─► users.apply/lift_restriction
torrent.deleted / status_changed ─► 豁免该种子 active 记录
```

| 模块 | 职责 |
|---|---|
| `rules` | 豁免规则与达标参数 |
| `records` | 创建、状态迁移 |
| `evaluator` | 分层评估 |
| `penalty` | 有效计数、限制施加与解除 |
| `forgive` | 免除 |
| `hooks` | 钩子处理 |

## 4. 数据设计概要

`records`（按月分区：user_id、torrent_id、completed_at、deadline、state、seed_secs_snapshot、ratio_snapshot、prewarned、reason）、`user_counts`（每用户有效 failed 数、active 数、是否已施加限制）、`active_index`（(deadline, user_id, torrent_id) 便于分层评估——实现为 records 上的部分索引）。

## 5. 关键流程

```
create(evt{user_id, torrent_id, completed_at}):
  existing = records(user, torrent) 最新一条
  if existing.state ∈ {active, satisfied, exempted, forgiven}: return            // 幂等 / 已处理
  if existing.state == failed && redownload_mode == ignore: return
  t = torrent.v_torrent_public[torrent_id]；snap = v_snatch[(user, torrent)]
  ctx = {size, tags（由 on_torrent_status 维护的镜像，或无）, promotion_kind（promotions.current）, class_id, is_uploader, is_seedbox, downloaded_pct = snap.downloaded / size}
  if 任一 exempt_rule 成立: INSERT state=exempted, reason=rule_id；publish hnr.exempted；return
  INSERT state=active, deadline = completed_at + window；publish hnr.recorded

evaluate(batch of active):
  snaps = v_snatch WHERE (user_id, torrent_id) IN batch
  for r: ok = snap.seed_secs ≥ min_seed_hours×3600 || (min_ratio > 0 && snap.uploaded ≥ min_ratio × snap.downloaded_base)
     ok → satisfied（publish）
     !ok && now ≥ deadline + grace → failed（publish）；recount(user)
     !ok && 剩余 < prewarn && !prewarned → prewarned（publish + notify）
recount(uid): n = count(failed AND failed_at > now − expire_days)；
     n ≥ max_hnr 且未限制 → apply_restriction；n < max 且已限制 → lift_restriction
```

`downloaded_base`：单种分享率的分母取 `max(snap.downloaded, size)`，避免只下载部分文件的用户以小分母轻易达标（与 NexusPHP 一致）。

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-HNR-1 | 评估方式 | 分层：期限 48 小时内每 10 分钟；其余每小时评估 1/6（按 user_id 哈希分片），每条记录约 6 小时评估一次；达标是单调的（做种时长只增），延迟评估不影响结果 |
| DD-HNR-2 | 是否需要 `traffic.settled` | 不需要：达标可延迟判定；只在完成下载时创建记录 |
| DD-HNR-3 | 豁免判定时机 | 创建时判定（促销状态以下载完成时为准）；之后促销变化不影响 |
| DD-HNR-4 | 部分下载 | 下载量 < `min_download_pct`（默认 10%）× 体积 视为未下载，不创建记录（豁免规则默认包含） |
| DD-HNR-5 | 依赖 promotion | optional：避免强依赖；不可用时“促销豁免”规则不生效 |
