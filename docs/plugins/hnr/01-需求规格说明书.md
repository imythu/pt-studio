## 1. 引言

### 1.1 目的

定义 H&R（Hit and Run，下完就跑）考核插件 `hnr` 的需求：用户完成下载后必须在规定期限内做种达到时长或分享率要求，否则记为 H&R；H&R 过多时限制下载。

### 1.2 范围

包含：考核记录的创建（完成下载时）、达标条件（做种时长 / 单种分享率）、考核期限、豁免规则（数据驱动）、到期判定、H&R 计数与有效期、处罚（限制下载）、免除（版主、商城）、临期提醒、种子删除时自动免除、状态查询、MCP。

不包含：全局分享率（ratio-policy）、作弊判定（anticheat）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 考核记录 | 用户完成某种子下载后产生的一条记录，状态 `active / satisfied / failed / forgiven / exempted` |
| 达标 | 期限内该种子做种时长 ≥ `min_seed_hours`，或该种子分享率 ≥ `min_torrent_ratio` |
| 有效 H&R | 状态为 failed 且未过有效期（默认 90 天）的记录 |

### 1.4 参考资料

- docs/platform/、docs/plugins/accounting/（`traffic.snatch_completed`、`v_snatch`）、docs/plugins/identity/（限制机制）、docs/plugins/promotion/（促销状态）
- NexusPHP H&R 插件（`hit_and_runs` 表：完成后 N 天内做种 M 小时，未达标计入，超过上限禁止下载，魔力值消除）
- UNIT3D：`history` 表 + `prewarned` / `hitrun` 标志，`hitrun_settings`（grace_period、seedtime、buffer、expire、max_warnings），自动警告、超过 `max_warnings` 禁止下载

## 2. 总体描述

### 2.1 插件定位

- WASM，ID `hnr`，缩写 `HNR`；提供 `ctx.hnr`。
- 依赖：`ctx.users`（限制）、`ctx.promotions`（optional，判断免费种子豁免）、`ctx.seedbox`（optional）、`ctx.notify`（optional）。
- 视图：`accounting.v_snatch`、`torrent.v_torrent_public`、`identity.v_user_public`。
- 订阅：`traffic.snatch_completed`、`torrent.deleted`、`torrent.status_changed`、`user.deleted`。
- 处理钩子：`torrent.before_download`、`invite.before_issue`。

### 2.2 用户角色与使用场景

普通用户：查看自己的考核列表（剩余时间、已做种时长、达标进度）、有效 H&R 数、被限制原因；在商城购买“消除 H&R”。版主：查看他人 H&R、免除。管理员：配置规则。

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP H&R 插件 | 下载完成后在 `hit_and_runs` 记录，考核期内做种时长或分享率达标即通过；超时未达标计入；H&R 数超上限禁止下载；可用魔力值消除 | 运营成熟 | 规则字段写在设置表中，豁免条件有限；定时任务全量扫描 | **采纳**达标条件（时长或分享率）、计数上限、魔力值消除（经商城）；**改进**：豁免规则数据驱动；只评估 active 记录 |
| UNIT3D | `grace_period`（宽限）、`buffer`（提前预警）、`expire`（H&R 有效期）、`max_warnings`；prewarn 通知 | 有预警与有效期 | 依赖 `history` 表全表扫描 | **采纳**预警、有效期、上限；评估只扫描 active 记录 |

### 2.4 约束与假设

做种时长来自 accounting 的 snatch 记录（分钟级最终一致）。规模：日完成下载约 50 万次（30 万用户），active 记录峰值约 700 万（14 天窗口）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-HNR-001 | 创建记录 | 订阅 `traffic.snatch_completed`，为（用户，种子）创建考核记录，期限 = 完成时间 + `window_days`（默认 14） | P0 | 完成下载后出现记录 |
| FR-HNR-002 | 豁免规则 | 数据驱动的豁免：种子体积 < X、本人发布、促销类型（如免费）、种子标签、用户等级、盒子、下载量 < 种子体积的 Y%（未真正下完） | P0 | 满足任一豁免时记录为 exempted 或不创建 |
| FR-HNR-003 | 达标判定 | 做种时长 ≥ `min_seed_hours`（默认 72）或单种分享率 ≥ `min_torrent_ratio`（默认 1.0） | P0 | 达标后状态 satisfied，发布 `hnr.satisfied` |
| FR-HNR-004 | 到期判定 | 期限到时未达标 → failed，发布 `hnr.failed` | P0 | |
| FR-HNR-005 | 宽限 | 到期后宽限 `grace_hours`（默认 0）内达标仍可通过 | P2 | |
| FR-HNR-006 | 临期提醒 | 剩余 `prewarn_hours`（默认 48）且未达标时提醒一次 | P1 | 只提醒一次 |
| FR-HNR-007 | 有效期 | failed 记录在 `expire_days`（默认 90）后不再计入有效 H&R | P1 | 计数下降 |
| FR-HNR-008 | 处罚 | 有效 H&R ≥ `max_hnr`（默认 5）→ `apply_restriction(leech_disabled, "hnr.too_many")`；低于上限时自动解除 | P0 | 只解除本插件来源 |
| FR-HNR-009 | 发邀限制 | 有效 H&R ≥ `invite_block_at`（默认 1）时拒绝发邀 | P1 | |
| FR-HNR-010 | 免除 | 版主免除记录（原因）；服务 `forgive(record_id, reason, idempotency_key)`（shop 使用） | P0 | 状态 forgiven；计数下降；发布 `hnr.forgiven` |
| FR-HNR-011 | 种子删除 | 种子被删除或下架 → 该种子的 active 记录自动 exempted（原因 torrent_removed） | P1 | |
| FR-HNR-012 | 考核状态查询 | `status(user)`、`records(user, filter)`：每条记录的期限、已做种时长、分享率、进度 | P0 | |
| FR-HNR-013 | 种子页提示 | 下载前提示该种子是否需要考核（`torrent.detail.header`） | P2 | |
| FR-HNR-014 | 重新下载 | 已 failed 的种子再次下载并完成：按配置新建记录或忽略（默认忽略，当前 failed 保留） | P2 | |
| FR-HNR-015 | 管理 | 规则配置、按用户 / 种子查询、批量免除 | P1 | |
| FR-HNR-016 | MCP | `list_my_hnr`（已登记）、`admin_forgive_hnr`（已登记） | P2 | |
| FR-HNR-017 | 用户删除 | 清理 | P1 | |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-HNR-001 | 性能 | 创建记录 | 单事件 p99 < 20 ms |
| NFR-HNR-002 | 性能 | 评估 | 每小时评估全部 active 记录（≤ 700 万）≤ 20 分钟，或按期限临近分层评估 |
| NFR-HNR-003 | 性能 | 钩子 | p99 < 10 ms |
| NFR-HNR-004 | 可靠性 | 幂等 | 重复事件不重复创建记录；重复评估不重复发事件 |
| NFR-HNR-005 | 容量 | 记录表 | 每年约 1.8 亿行，按月分区，保留 13 个月 |

## 5. 可配置项与站点术语

`window_days`（14）、`min_seed_hours`（72）、`min_torrent_ratio`（1.0，0 = 不使用）、`grace_hours`（0）、`prewarn_hours`（48）、`expire_days`（90）、`max_hnr`（5）、`invite_block_at`（1）、`exempt_rules`（谓词规则列表，见详细设计）、`redownload_mode`（ignore / new_record）、`notify`（true）。

术语：`hnr.name`、`hnr.rule_summary`（已登记）；新增 `hnr.active`（考核中）、`hnr.failed`（已计入）。

## 6. 外部接口需求概述

服务 `ctx.hnr`（`status`、`records`、`forgive`）；事件 `hnr.recorded`、`hnr.satisfied`、`hnr.failed`、`hnr.forgiven`（已登记）及新增 `hnr.exempted`、`hnr.prewarned`；HTTP `/api/p/hnr/v1/*`；插槽 `user.profile.stats`、`user.profile.tabs`、`torrent.list.row_badges`（我在考核中的种子）、`torrent.detail.header`；MCP 两项。
