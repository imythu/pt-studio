## 1. 引言

### 1.1 目的

定义审核插件 `moderation` 的需求：发种审核队列、候选区、审核决定与模板、自动通过规则、敏感词过滤、可见性控制、审核日志与统计。种子状态机由 torrent 插件定义（[torrent 03 §1.5](../torrent/03-详细设计说明书.md)），本插件负责“谁、何时、依据什么”推动状态迁移。

### 1.2 范围

包含：

- 初始状态决定（`torrent.before_upload` 处理者：信任的发布者直接通过、普通发布者待审、可选进入候选区）；
- 审核队列（种子、字幕等目标）、认领（锁定，防止多人同时审核）、决定（通过 / 拒绝 / 要求修改）、理由模板、批量操作；
- 候选区：用户投票（支持 / 反对），达到阈值后进入待审或自动通过；
- AI 预审结果展示（ai-upload-review 的报告）；
- 可见性：候选与待审种子对普通用户在搜索与列表中隐藏（`search.before_query`）；
- 敏感词过滤（评论、帖子、站内信标题、头衔）；
- 审核日志、审核员统计、队列积压告警；MCP 工具。

不包含：举报处理（reports）；作弊处置（anticheat）。

### 1.3 参考资料

- docs/plugins/torrent/（状态机、`set_status`、`torrent.before_upload` 的 `initial_status`）
- NexusPHP 1.7+：候选区（offers：投票通过后可发布）、种子审核（approval）功能、审核员后台
- UNIT3D：moderation 队列（pending / postponed / rejected，`moderated_by`、`moderated_at`），Trusted uploaders 自动通过
- Gazelle：无发种审核（事后报告制）

## 2. 总体描述

WASM，ID `moderation`，缩写 `MOD`；提供 `ctx.moderation`；处理钩子 `torrent.before_upload`、`torrent.before_status_change`、`search.before_query`、`comment.before_create`、`forum.before_post`、`message.before_send`、`user.before_rename`、`subtitle.before_upload`。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| UNIT3D | 种子待审 → 审核员通过 / 搁置 / 拒绝；可信发布者自动通过 | 简单有效 | 无认领，多人同时审核同一种子；拒绝理由自由文本 | **采纳**三种决定与可信发布者；**改进**：认领锁、理由模板 |
| NexusPHP | 候选区由用户投票，达标后上传者可发布 | 社区参与 | 候选与正式发布是两套流程 | **改进**：候选区是种子的一个状态（candidate），投票达标自动迁移，无需重新上传 |
| Gazelle | 无审核，依靠报告 | 低人力成本 | 违规内容先上线 | 站点可配置 `default_initial_status = approved` 达到同样效果 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-MOD-001 | 初始状态规则 | 数据驱动：按发布者等级、角色、历史通过数、资源类型、AI 风险等决定 `approved` / `pending` / `candidate`；默认：uploader 角色或已通过 ≥ 20 → approved，其余 pending | P0 | |
| FR-MOD-002 | 审核队列 | 列出待审目标（种子、字幕），按等待时间、类型、AI 风险排序筛选 | P0 | |
| FR-MOD-003 | 认领 | 审核员认领目标（10 分钟锁，可续期）；他人看到“正在审核” | P1 | |
| FR-MOD-004 | 决定 | 通过 / 拒绝（理由模板 + 补充说明）/ 要求修改（needs_edit：种子保持 pending，通知上传者修改后重新提交） | P0 | |
| FR-MOD-005 | 理由模板 | 管理员维护模板（术语键 + 默认文案），决定时选择 | P1 | |
| FR-MOD-006 | 批量 | 批量通过 / 拒绝 | P2 | |
| FR-MOD-007 | 候选区 | candidate 种子：用户投支持 / 反对；支持 − 反对 ≥ `approve_votes`（默认 10）→ 迁移为 pending（或 approved，可配）；≤ −`reject_votes` → rejected；超过 `candidate_days`（默认 7）未达标 → 按配置处理 | P1 | |
| FR-MOD-008 | AI 预审 | 队列与审核页展示 ai-upload-review 报告（只读）；AI 不自动做决定 | P2 | |
| FR-MOD-009 | 可见性 | `search.before_query`：对无 `moderation.queue.read` 的用户追加过滤 `vis_status = approved`（候选区页面例外：`vis_status = candidate` 只在候选区入口可搜） | P0 | |
| FR-MOD-010 | 敏感词 | 词表（精确 / 通配 / 正则受限），动作 block（拒绝）/ mask（替换为 *）/ review（允许但入队复核）；作用于评论、帖子、站内信标题、改名、字幕文件名 | P1 | |
| FR-MOD-011 | 审核日志 | 每个决定记录审核员、时间、理由、目标快照（标题、上传者） | P0 | |
| FR-MOD-012 | 统计 | 每个审核员的审核数、平均耗时；队列积压 | P2 | |
| FR-MOD-013 | 积压告警 | 待审超过 N 个或最老待审超过 M 小时 → 指标告警与员工通知 | P2 | |
| FR-MOD-014 | 服务 | `submit(target, reason)`（其他插件把目标送审，如字幕）、`decide(target, decision, note)`、`queue_stats()` | P0 | |
| FR-MOD-015 | MCP | `admin_list_moderation_queue`、`admin_decide_moderation`（已登记） | P2 | |
| FR-MOD-016 | 撤回审核 | 已通过的种子可被版主撤回到 pending（复审） | P2 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-MOD-001 | 钩子性能 | `torrent.before_upload` p99 < 50 ms；`search.before_query` p99 < 5 ms；敏感词检查 20000 字 p99 < 5 ms（Aho-Corasick） |
| NFR-MOD-002 | 一致性 | 决定与 torrent 状态一致（set_status 失败时决定不生效） |
| NFR-MOD-003 | 审计 | 全部决定写审计 |

## 5. 可配置项与站点术语

`initial_rules`（谓词规则列表）、`candidate.enabled`（false）、`candidate.approve_votes`（10）、`candidate.reject_votes`（10）、`candidate.days`（7）、`candidate.on_timeout`（pending / reject）、`candidate.on_approve`（pending / approved）、`claim_minutes`（10）、`backlog.max_items`（200）、`backlog.max_age_hours`（24）。术语：`moderation.candidate_area`（已登记）、`moderation.reason.<id>`（理由模板，动态）、`moderation.decision.<decision>`。

## 6. 外部接口需求概述

服务 `ctx.moderation`；事件 `moderation.decided`（已登记），新增 `moderation.submitted`、`moderation.candidate_voted`；HTTP `/api/p/moderation/v1/*`；插槽 `admin.dashboard.widgets`（待审数）、`torrent.detail.header`（审核状态与候选投票）、`admin.torrent.tabs`（审核历史）、`nav.main`（候选区入口，启用时）；MCP 两项。
