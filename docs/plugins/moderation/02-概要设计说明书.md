## 1. 设计目标与原则

1. **状态机属于 torrent，流程属于 moderation**：决定通过 `ctx.torrents.set_status` 落地（作用域 `write:status`）；非种子目标（字幕等）通过发布 `moderation.decided` 由目标拥有者订阅处理。
2. **钩子只读、极快**：初始状态规则、可见性过滤、敏感词都只读本插件的缓存数据（规则与词表在 kv / 本地表，自动机在每次调用时从 kv 中的序列化结构加载——见 03 §1.5）。
3. **队列由事件驱动**：订阅 `torrent.created`、`torrent.status_changed`、`moderation.submitted`，维护本插件的 `queue` 表；不依赖扫描 torrent 表。

## 2. 总体结构

```
torrent.before_upload ──► initial_rules ──► modify.initial_status
torrent.created / status_changed ──► queue（pending / candidate）
审核员 ─HTTP─► claim / decide ──► ctx.torrents.set_status ─► torrent.status_changed ─► queue 出队
                              └► publish moderation.decided（所有目标）
用户 ─HTTP─► candidate vote ──► 达到阈值 ──► set_status
search.before_query ──► 可见性过滤
comment / forum / message / rename / subtitle 钩子 ──► 敏感词
```

| 模块 | 职责 |
|---|---|
| `rules` | 初始状态规则（谓词） |
| `queue` | 队列维护、认领、筛选 |
| `decisions` | 决定、理由模板、批量、撤回 |
| `candidates` | 候选投票与阈值 |
| `visibility` | `search.before_query` |
| `wordfilter` | 敏感词（Aho-Corasick） |
| `stats` | 统计与积压告警 |

## 4. 数据设计概要

`queue`（目标、状态、提交时间、认领者、认领到期、AI 风险、优先级）、`decisions`（日志）、`reasons`（模板）、`initial_rules`（规则版本）、`candidate_votes`、`candidate_tally`、`words`（敏感词）、`word_hits`（review 动作的复核项）。

## 5. 关键流程

```
初始状态（钩子）：
  ctx = {uploader class / roles / approved_uploads（本插件统计表）/ type_id / size / ai_risk（不可得：钩子时 AI 尚未审）/ tags}
  for rule in initial_rules（按顺序）：predicate 成立 → modify initial_status = rule.status；break
  默认 → pending（或 candidate，若 candidate.enabled 且规则指定）
决定：
  decide(target torrent:<id>, approve, note) → torrents.set_status(id, approved, note)
       → 成功：INSERT decisions；queue 删除；publish moderation.decided；notify 上传者（拒绝 / 要求修改时）
  needs_edit：set_status 不变（保持 pending）；queue.state = awaiting_uploader；上传者编辑（torrent.updated 事件）→ 回到 pending 队列
  非种子目标：publish moderation.decided；拥有者订阅后处理
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-MOD-1 | 初始状态由谁决定 | moderation 作为 `torrent.before_upload` 处理者 modify `initial_status`；未安装 moderation 时 torrent 使用 `default_initial_status` |
| DD-MOD-2 | 候选区 | 作为 torrent 的 `candidate` 状态（无需二次上传），投票阈值迁移 |
| DD-MOD-3 | AI 结论 | 只展示，不自动决定；规则中可引用 ai_risk 作为排序依据（队列中），不用于初始状态 |
| DD-MOD-4 | 防绕过 | `torrent.before_status_change` 中只有审核员（或本插件自身）能把 candidate / pending 改为 approved |
| DD-MOD-5 | 敏感词实现 | 词表编译为 Aho-Corasick 自动机（`aho-corasick` crate），序列化后存 kv（≤ 2 MiB），每次调用反序列化（WASM 无跨调用内存）；10 万词以内反序列化 < 2 ms |

## 7. 对平台契约的新增

服务参数补幂等键；事件 `moderation.submitted`、`moderation.candidate_voted`；权限点 `moderation.candidates.vote`；钩子目录中各钩子的预期处理者加入 moderation（已大多列出）；术语 `moderation.reason.<id>`、`moderation.decision.<decision>`；依赖 `user.before_title_change`（medals 02 §7 提议的钩子）以过滤头衔。
