## 1. 模块详细设计

### 1.1 rules（`torrent.before_upload` 处理）

规则（设置 `initial_rules`，按顺序匹配第一条）：

```json
[
  { "id": "trusted_role", "when": [ { "field": "roles", "op": "in", "value": ["uploader"] } ], "status": "approved" },
  { "id": "veteran",      "when": [ { "field": "approved_uploads", "op": "gte", "value": 20 },
                                    { "field": "rejected_ratio", "op": "lt", "value": 0.1 } ], "status": "approved" },
  { "id": "new_uploader", "when": [ { "field": "approved_uploads", "op": "lt", "value": 3 } ], "status": "candidate" }
]
```

可用字段：`class_id`、`class_rank`、`roles`、`approved_uploads`、`rejected_uploads`、`rejected_ratio`、`account_age_days`、`type_id`、`size`、`tags`、`anonymous`。默认（无规则命中）：`pending`。`candidate` 只在 `candidate.enabled` 时有效，否则视为 `pending`。

`approved_uploads` / `rejected_uploads` 来自本插件表 `uploader_stats`（订阅 `torrent.status_changed` 维护）。钩子只读本插件表与 `ctx.users`（请求上下文已有）。

**输入中已有 `initial_status` 修改**（type-* 可能已设为 pending，如 spec_mismatch）：本插件只能把状态“变严”（approved → pending → candidate 视为同级，approved 不能覆盖其他处理者给出的 pending）。

### 1.2 queue

```
on torrent.created(evt): evt.status ∈ {pending, candidate} → INSERT queue(target = "torrent:<id>", kind, submitted_at, uploader_id, type_id, priority)
on torrent.status_changed(evt): to ∈ {pending, candidate} → UPSERT queue；to ∉ → DELETE queue（并结束认领）
on moderation.submitted（本插件服务 submit 写入）：INSERT queue
on ai.upload_reviewed(evt): UPDATE queue SET ai_verdict = evt.verdict, ai_findings_count
priority = 基础分（等待小时数）+ ai_verdict 权重（fail +50、warn +20）+ 资源类型权重（设置）
列表：WHERE state IN ('pending', 'candidate', 'awaiting_uploader') [AND kind / type_id / ai_verdict] ORDER BY priority DESC, submitted_at
claim(target, mod)：UPDATE queue SET claimed_by = mod, claim_until = now + claim_minutes
                    WHERE target = $1 AND (claimed_by IS NULL OR claim_until < now OR claimed_by = mod)
                    → 0 行：moderation.claimed_by_other{by}
```

### 1.3 decisions

```
decide(mod, target, decision ∈ {approve, reject, needs_edit}, reason_id?, note, idem):
  rbac moderation.decide；幂等
  q = queue[target]；q 被他人认领且未过期 → moderation.claimed_by_other（可强制：moderation.manage）
  match target.kind:
    torrent:
      approve    → torrents.set_status(id, approved, note)
      reject     → torrents.set_status(id, rejected, reason_text)
      needs_edit → 状态不变；queue.state = 'awaiting_uploader'；notify 上传者（模板 + 说明）
      set_status 返回 torrent.invalid_status_transition → moderation.stale（种子状态已变化）
    其他（subtitle 等）：不调用服务
  INSERT decisions(target, decision, reason_id, note, moderator_id, snapshot{title, uploader_id, status_before})
  publish moderation.decided{target, decision, moderator_id, by_ai: false, note}
  queue：approve / reject → DELETE；needs_edit → 保留
  通知：reject / needs_edit → notify 上传者（`moderation.decision.<decision>` 模板，含理由文本）
on torrent.updated(evt): queue[torrent:<id>].state == awaiting_uploader → state = 'pending'（上传者已修改）
revoke_approval(mod, torrent)：torrents.set_status(id, pending, "moderation.recheck")
batch(mod, targets ≤ 100, decision, reason)：逐个 decide，汇总结果
```

### 1.4 candidates

```
vote(u, torrent_id, +1 | −1)：rbac moderation.candidates.vote；种子 status == candidate；u ≠ uploader；账号年龄 ≥ 7 天
  UPSERT candidate_votes(torrent_id, user_id, value)（可改票）
  UPDATE candidate_tally SET up = …, down = …（重新计数该种子的票，≤ 数百行）
  publish moderation.candidate_voted
  if up − down ≥ approve_votes 或 down − up ≥ reject_votes：
     jobs.schedule_once("candidate_resolve", now, {torrent_id}, dedupe = torrent_id)
candidate_resolve（延迟任务，actor = plugin:moderation）：
  重新读取 tally 与种子状态（仍为 candidate）→ set_status(id, on_approve | rejected, "moderation.candidate_votes")
candidate_timeout（cron）：candidate 且 submitted_at < now − candidate.days → 调度 candidate_resolve（按 on_timeout）
```

在延迟任务中执行迁移，保证 `torrent.before_status_change` 中的 actor 为本插件（§1.6）。

### 1.5 wordfilter

```
words(id, pattern, kind ∈ {exact, wildcard}, action ∈ {block, mask, review}, scopes[comment, forum, message_subject, rename, title, subtitle_filename])
compile：exact → 小写 + NFKC + 去除零宽字符；wildcard（* 匹配 0～3 个任意字符）展开为多个模式或在匹配后校验
自动机：aho_corasick::AhoCorasick（LeftmostLongest），序列化（serde + bincode）存 kv "ac:<scope>"（版本号 "ac_ver"）；词表变更时重建
check(scope, text)：规范化 text → 查找 → 取命中词中最严重的动作（block > review > mask）
  block → deny("moderation.blocked_word", details{count})（不回显具体词，避免探测）
  mask  → modify body：命中片段替换为 "*"（按字符数）
  review → allow；INSERT word_hits(scope, target_ref?, author_id, excerpt)（后台复核）
```

钩子映射：`comment.before_create`（body）、`forum.before_post`（title、body）、`message.before_send`（subject——正文不在输入中）、`user.before_rename`（new_username，scope rename）、`subtitle.before_upload`（filename）。

### 1.6 `torrent.before_status_change` 处理

```
input{torrent_id, from, to, reason, actor}
if to == approved && from ∈ {pending, candidate, rejected}:
   allow iff actor 有 moderation.decide，或 actor = plugin:moderation，或 actor 有 torrent.update 且站点设置 allow_editor_approve = true
   否则 deny("moderation.approval_required")
allow
```

### 1.7 visibility（`search.before_query` 处理）

```
input{index, filters, user_id?, class_id?}
index ∉ {torrents, groups} → allow
if user 有 moderation.queue.read → allow
if 请求来自候选区（filters 中已含 vis_status = candidate 的标记——由前端候选区页面传入 `x_scope = candidates` 参数，search 将其放入钩子输入 ⊕）且 candidate.enabled → modify filters += ["vis_status = candidate"]
else modify filters += ["vis_status = approved"]
```

`vis_status` 字段由 search 的拥有者字段提供（search 03 §1.2 保留前缀 `vis_`）。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:moderation@0.1.0`）

```wit
package pt:moderation@0.1.0;

interface moderation {
  use pt:plugin/types@0.1.0.{plugin-error, user-id};

  enum decision { approve, reject, needs-edit }
  record queue-stats { pending: u32, candidate: u32, awaiting-uploader: u32, oldest-age-secs: u64 }

  submit: func(target: string, reason: string, idempotency-key: string) -> result<_, plugin-error>;
  decide: func(target: string, decision: decision, note: string, idempotency-key: string) -> result<_, plugin-error>;
  queue-stats: func() -> result<queue-stats, plugin-error>;
}
```

`submit` 需作用域 `write`（subtitles 等使用）；`decide` 需 `write` 且原始 actor 有 `moderation.decide`。

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `moderation.decided` | `target, decision(approve/reject/needs_edit), moderator_id?, by_ai: false, reason_id?, note` |
| `moderation.submitted` | `target, submitted_by_plugin, reason` |
| `moderation.candidate_voted` | `torrent_id, up, down` |

### 2.3 HTTP API（前缀 `/api/p/moderation/v1`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/queue?kind=&type_id=&ai=&cursor=` | `moderation.queue.read` | 队列 |
| POST | `/queue/{target}/claim`、DELETE 同路径 | `moderation.decide` | 认领 / 释放 |
| POST | `/queue/{target}/decision` | `moderation.decide` | `{decision, reason_id?, note}` |
| POST | `/queue/batch` | `moderation.decide` | 批量 |
| POST | `/torrents/{id}/recheck` | `moderation.decide` | 撤回审核 |
| GET | `/history?target=&moderator_id=` | `moderation.queue.read` | 决定日志 |
| GET | `/candidates?cursor=` | user | 候选列表（启用时） |
| POST | `/candidates/{torrent_id}/vote` | `moderation.candidates.vote` | `{value: 1 | -1}` |
| GET/POST/PATCH/DELETE | `/admin/reasons`、`/admin/rules`、`/admin/words` | `moderation.manage` | 模板、规则、词表 |
| GET | `/admin/word-hits` | `moderation.queue.read` | 敏感词复核 |
| GET | `/admin/stats` | `moderation.manage` | 统计 |

### 2.4 MCP

`admin_list_moderation_queue`（入参 `{kind?, limit?}`；出参：目标、标题、上传者、等待时长、AI 结论）；`admin_decide_moderation`（入参 `{target, decision, reason_id?, note}`；write，confirm 不可关闭）。

## 3. 数据库设计（schema `moderation`）

```sql
CREATE TABLE moderation.queue (
    target         text PRIMARY KEY,
    kind           text NOT NULL,
    state          text NOT NULL CHECK (state IN ('pending','candidate','awaiting_uploader')),
    type_id        text,
    uploader_id    bigint,
    submitted_at   timestamptz NOT NULL,
    priority       integer NOT NULL DEFAULT 0,
    ai_verdict     text,
    ai_findings    integer,
    claimed_by     bigint,
    claim_until    timestamptz
);
CREATE INDEX queue_order_idx ON moderation.queue (state, priority DESC, submitted_at);

CREATE TABLE moderation.decisions (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    target        text NOT NULL,
    decision      text NOT NULL,
    reason_id     bigint,
    note          text NOT NULL DEFAULT '',
    moderator_id  bigint,
    actor         text NOT NULL,
    snapshot      jsonb NOT NULL,
    created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX decisions_target_idx ON moderation.decisions (target, id DESC);
CREATE INDEX decisions_moderator_idx ON moderation.decisions (moderator_id, id DESC);

CREATE TABLE moderation.reasons (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, decision text NOT NULL, active boolean NOT NULL DEFAULT true, sort integer NOT NULL DEFAULT 100);
CREATE TABLE moderation.uploader_stats (user_id bigint PRIMARY KEY, approved integer NOT NULL DEFAULT 0, rejected integer NOT NULL DEFAULT 0);
CREATE TABLE moderation.candidate_votes (torrent_id bigint NOT NULL, user_id bigint NOT NULL, value smallint NOT NULL CHECK (value IN (-1, 1)), created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (torrent_id, user_id));
CREATE TABLE moderation.candidate_tally (torrent_id bigint PRIMARY KEY, up integer NOT NULL DEFAULT 0, down integer NOT NULL DEFAULT 0);
CREATE TABLE moderation.words (
    id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    pattern  text NOT NULL,
    kind     text NOT NULL CHECK (kind IN ('exact', 'wildcard')),
    action   text NOT NULL CHECK (action IN ('block', 'mask', 'review')),
    scopes   text[] NOT NULL,
    active   boolean NOT NULL DEFAULT true
);
CREATE TABLE moderation.word_hits (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, scope text NOT NULL, author_id bigint, excerpt text NOT NULL, state text NOT NULL DEFAULT 'open', created_at timestamptz NOT NULL DEFAULT now());
CREATE TABLE moderation.idempotency (owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (owner, key));
```

## 4. 配置项

见 SRS §5，另加 `allow_editor_approve`（false）。清单：`requires = ["ctx.torrents@^0.1", "ctx.users@^0.1", "ctx.rbac@^0.1"]`、`optional_requires = ["ctx.notify@^0.1", "ctx.ai_upload_review@^0.1"]`（ai-upload-review 不得反向依赖本插件）；scopes `ctx.torrents = ["write:status"]`；`[[hooks]]` 八项（见 02 §3）；订阅五项；cron 三项；`[[jobs]] candidate_resolve`。

## 5. 前端设计

审核台：队列列表（AI 结论徽标、等待时长、认领状态）、审核页（种子详情 + 文件列表 + MediaInfo 差异 + AI 报告 + 决定面板与理由模板下拉）；候选区页面（投票按钮、进度条）；后台：规则编辑器（谓词构建器）、敏感词管理（批量导入、测试文本框）、统计。

## 6. 安全设计

决定权限与审计；认领防冲突；敏感词拒绝时不回显命中词；候选投票限制账号年龄与上传者本人；防绕过钩子（§1.6）。

## 7. 性能设计

钩子只读本插件表与 kv；自动机反序列化 < 2 ms；队列由事件维护。

## 8. 可观测性

`pt_plugin_moderation_queue_size{state}`、`pt_plugin_moderation_oldest_age_seconds`、`pt_plugin_moderation_decisions_total{decision}`、`pt_plugin_moderation_word_hits_total{action,scope}`。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `moderation.not_in_queue` | 404 | 目标不在队列 |
| `moderation.claimed_by_other` | 409 | 已被他人认领 |
| `moderation.stale` | 409 | 目标状态已变化 |
| `moderation.approval_required` | 403 | 只有审核员能通过（钩子返回） |
| `moderation.blocked_word` | 422 | 含禁止词 |
| `moderation.vote_not_allowed` | 403 | 不能对该种子投票 |
| `moderation.rule_invalid` | 422 | 规则校验失败 |
