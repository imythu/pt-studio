| 类别 | 内容 |
|---|---|
| 原则 | 只读、批量、按指纹索引查询；可见性与下载权限由 torrent 与 rss 保证；本插件不存种子数据 |
| 模块 | `auth`（token 鉴权与配额）、`lookup`（指纹 / hash 批量查询）、`links`（下载链接生成：需要用户的 feed key——由用户在请求中额外提供 `feed_key`，或在设置中授权本插件代为签发 ⊕）、`compat`（IYUU 兼容层） |
| 依赖 | `ctx.auth`（`authenticate(api_token)`、`issue_token(kind = feed)`）、`ctx.torrents`（`get_many`，按 principal 可见性过滤）；视图 ⊕ `torrent.v_torrent_fingerprint(torrent_id, content_fp, info_hash_v1, info_hash_v2, status)`（需在 `content_fp` 上建索引）、`torrent.v_torrent_hash_history` |
| 关键流程 | 鉴权 → 配额（Redis 计数）→ 规范化 hex → `SELECT torrent_id, content_fp FROM torrent.v_torrent_fingerprint WHERE content_fp = ANY($1) AND status = 'approved'` → `torrents.get_many(ids)`（以用户 principal 调用，过滤不可见与不可下载）→ 生成链接 → 返回（未命中的指纹返回空数组，不区分“不存在”与“不可见”） |
| 设计决策 | DD-XSEED-1：下载链接复用 rss（feed key），不另造下载接口；DD-XSEED-2：feed key 不能由 API token 换取（避免一个泄露的 token 拿到下载能力的同时也拿到 RSS 访问）——用户需在请求中提供自己的 feed key，或在设置页显式开启“辅种接口可代我生成下载链接”（本插件保存一个专用的 feed key，作用域仅 `download`） |
| 平台契约新增 | 视图 `torrent.v_torrent_fingerprint`（索引 `content_fp`）；identity：token kind `feed` 的作用域可单独为 `download`；内核“以 principal 调用”（同 rss 02） |
| 权限点 | `crossseed-api.use`、`crossseed-api.manage`（已登记） |

需求追溯：FR-001、002 → lookup；FR-003、006、007、009 → auth；FR-004 → links；FR-005 → lookup（principal 过滤）；FR-008 → compat。
