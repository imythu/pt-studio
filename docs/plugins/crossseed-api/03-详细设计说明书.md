## 1. 模块详细设计

### 1.1 auth

```
p = auth.authenticate(Bearer token | ?token=)；scope 必须含 crossseed；rbac(p.user, crossseed-api.use)
INCR rl:<token_id>:<minute>（EX 120）> rate_per_min → 429
INCRBY q:<token_id>:<yyyymmdd> n（EX 2 天）> daily_quota → 429（details.reset_at）
记录：HINCRBY usage:<yyyymmdd> <user_id> n（只记数量）
```

### 1.2 lookup

**POST `/v1/lookup`**

```json
{ "pieces_sha1": ["3f786850e387550fdab836ed7e6dc881de23001b", "…"],
  "info_hash_v1": [], "info_hash_v2": [],
  "feed_key": "ptf_…（可选）" }
```

```
校验：总数 ≤ max_batch；每项 40 位（v1 / pieces）或 64 位（v2）hex，转小写
rows = 视图查询（pieces → content_fp；v1 / v2 → info_hash 与 hash_history）
visible = torrents.get_many(ids)（principal = 请求者）→ 只保留 status = approved 且 can_download
（can_download 来自 torrent 的 get_many 结果中的下载权限标志 ⊕；或调用 torrent.before_download 钩子的“预检”模式——不在本期）
links：feed_key 提供且有效 → dl 链接；或用户开启代签 → 使用保存的专用 key；否则 link = null
```

响应：

```json
{ "results": {
    "3f786850e387550fdab836ed7e6dc881de23001b": [
      { "torrent_id": 5501, "title": "…", "size": 53687091200, "info_hash_v1": "…",
        "details_url": "https://site/torrents/5501",
        "download_url": "https://site/api/p/rss/v1/dl/5501?k=ptf_…" } ] },
  "quota_remaining": 49500 }
```

未命中的键返回空数组。

### 1.3 links 与代签

设置页开关“允许辅种接口为我生成下载链接”：开启时 `auth.issue_token(user, kind = feed, scopes = ["download"], name = "crossseed")`，密文保存在本插件 kv（`dk:<uid>`，内核 kv 对插件私有；明文在内存中使用，不记录）；关闭时吊销该 token 并删除 kv。

### 1.4 compat（IYUU 兼容层）

IYUU 的站点对接方式（接口路径、签名、返回字段）以 IYUU 官方对接文档为准，**本设计不臆造其格式**。实现约束：

- 兼容层只能是 `lookup` 的格式转换（请求参数 → `pieces_sha1[]`，结果 → IYUU 要求的结构），不得增加新的数据暴露；
- 鉴权仍使用本站个人 API token（或 IYUU 规范要求的用户绑定方式，经 identity 的 token 实现）；
- 默认关闭（`iyuu_compat = false`），由站点在核实规范后开启；
- 兼容层路由 `/api/p/crossseed-api/v1/iyuu/*`，在部署文档中给出配置说明。

此项列入 docs/design/09-roadmap.md 的待核实项（评审时合入）。

## 2. 接口详细设计

无服务、事件、钩子。HTTP：`POST /v1/lookup`（`auth = public`，本插件自行用 token 鉴权）；`GET/PUT /v1/me/settings`（user，代签开关）；`GET /v1/admin/usage?date=`（`crossseed-api.manage`）。

## 3. 数据库设计

无表（只用 kv 与 Redis）。Redis（`p:crossseed-api:`）：`rl:*`、`q:*`、`usage:<date>`（HASH，保留 30 天）。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.auth@^0.1", "ctx.torrents@^0.1"]`；`views = ["torrent.v_torrent_fingerprint", "torrent.v_torrent_hash_history"]`；scopes `ctx.auth = ["tokens:issue"]`；`[http] max_body_kb = 64`。

## 5. 前端设计

设置页“辅种”：说明如何在辅种工具中配置（API 地址、个人 token）、代签开关、今日用量。

## 6. 安全设计

token 作用域限定；配额与限流；不区分不存在与不可见；下载链接通过可吊销的专用 key；不记录查询的具体指纹（避免形成用户本地文件清单）。

## 7. 性能设计

视图在 `content_fp`、`info_hash_v1`、`info_hash_v2` 上有索引；500 个指纹一次 `= ANY` 查询。
