|---|---|

外部渠道使用 HTTP 桩（Mailgun / SendGrid / Postmark / SES / relay / Telegram / Discord 的请求与响应录制）。

| 编号 | 关联需求 | 步骤 | 预期结果 |
|---|---|---|---|
| TC-NOTIFY-001 | FR-001 | send（center + email） | inbox 一条；outbox 一条并投递；`notify.delivered` |
| TC-NOTIFY-002 | FR-001 | 同一幂等键 send 两次 | duplicate = true；只投递一次 |
| TC-NOTIFY-003 | FR-002 | 清单登记模板；运行时登记他人前缀模板 | 前者成功；后者拒绝 |
| TC-NOTIFY-004 | FR-002 | args 不符合 schema | 422 `notify.args_invalid` |
| TC-NOTIFY-005 | FR-003 | 用户关闭 social 邮件 | 只投递站内；security 类仍发邮件 |
| TC-NOTIFY-006 | FR-004 | 列表、未读、全部已读 | 正确；Redis 与 SQL 一致 |
| TC-NOTIFY-007 | FR-005 | 五种提供方桩 | 请求格式正确（含 List-Unsubscribe 头、SES SigV4 签名） |
| TC-NOTIFY-008 | FR-005 | 未授权 user.email | 插件启动失败（sensitive 必需） |
| TC-NOTIFY-009 | FR-006 | 绑定码流程；错误 / 过期码；webhook secret 错误 | 绑定成功；422；401 |
| TC-NOTIFY-010 | FR-006 | Telegram 403（被屏蔽） | 绑定停用；`notify.failed{permanent: true}` |
| TC-NOTIFY-011 | FR-007 | Discord OAuth（state 校验）与私信 | 正确 |
| TC-NOTIFY-012 | FR-008 | user.challenge_issued 投递两次 | challenge_delivery 同幂等键；令牌不出现在 outbox、日志 |
| TC-NOTIFY-013 | FR-009 | new_device 登录 | security 通知 |
| TC-NOTIFY-014 | FR-010 | digest 10 分钟内 5 次 | 一条合并通知；digest_flush 重复执行不重复 |
| TC-NOTIFY-015 | FR-011 | 邮件第 21 封 / security 类超限 | skipped / 仍发送 |
| TC-NOTIFY-016 | FR-012 | 一键退订（POST）、篡改令牌 | 偏好更新；422 |
| TC-NOTIFY-017 | FR-013 | 提供方 503 三次后成功；400 永久失败 | 重试成功；failed 不重试 |
| TC-NOTIFY-018 | FR-014 | 投递记录 | 30 天后 cleanup 删除；重复执行无副作用 |
| TC-NOTIFY-019 | FR-015 | send_to_address 无作用域 / 有作用域 / 超限 | 拒绝 / 成功 / 429 |
| TC-NOTIFY-020 | FR-016 | 模板参数引用匿名发布者 | 渲染为“匿名” |
| TC-NOTIFY-021 | FR-017 | `user.deleted{purge}` 两次 | 数据删除 |
| TC-NOTIFY-022 | 安全 | 参数含 `</a><script>`、Telegram Markdown 特殊字符 | 转义正确 |
| TC-NOTIFY-023 | 隐私 | 日志、事件扫描 | 无邮箱、chat_id |
| TC-NOTIFY-024 | 依赖 | 依赖图检查 | notify 不依赖 messages、reports |
| TC-NOTIFY-025 | NFR-001 | send 1000 次/秒 | 受理 p99 < 30 ms |
| TC-NOTIFY-026 | NFR-002 | 站内与外部渠道延迟 | 站内 < 2 s；外部 p95 < 30 s（桩） |

覆盖：FR-001～017 对应 001～021；NFR 对应 023、025、026。通过准则：隐私与安全用例（012、022、023）必须通过。
