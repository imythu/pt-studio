## 1. 模块详细设计

### 1.1 templates

| 字段 | 说明 |
|---|---|
| `key` | `<plugin_id>.<name>`，前缀必须等于登记插件 ID |
| `category` | security / account / social / content / economy / system |
| `default_channels` | `center`、`email`、`telegram`、`discord` 的子集 |
| `title_term`、`body_term` | 术语键（模板文本，MessageFormat 子集，见 terms 03）；可选 `email_html_term`（邮件 HTML 版本，经 `pt-markup` markdown 渲染） |
| `link` | 站内相对链接模板，如 `/torrents/{torrent_id}#comment-{comment_id}` |
| `unsubscribable` | security 类强制 false |
| `digest_minutes` | 合并窗口 |
| `params_schema` | 参数 JSON Schema（校验 `args`，防止模板注入） |

渲染：`terms.render(body_term, args, locale)`；参数值中的字符串在渲染后再做 HTML 转义（邮件 HTML 版）或 Telegram MarkdownV2 转义；渲染结果**不再作为模板**（防止二次展开）。

内置模板（本插件）：`notify.challenge.email_verify`、`notify.challenge.password_reset`、`notify.challenge.email_change`、`notify.security.new_device_login`、`notify.binding.telegram_bound`。

### 1.2 intake

```
send(uid, key, args, channels?, idem):
  owner = caller_plugin；幂等键作用域 (owner, idem)，记录 → 返回首次 {notification_id, channels}
  t = templates[key]；schema 校验 args → notify.args_invalid
  u = users.get(uid)；status ∈ {deleted} → skipped
  chs = (channels ?? t.default_channels) ∩ enabled_channels
  if t.category != security: chs = chs.filter(prefs(uid, t.category, ch))；rl(uid, ch) 超限 → 移除并记 skipped
  外部渠道还需：email → users.get_sensitive(uid, "email") 存在且已验证；telegram / discord → 绑定有效
  digest：t.digest_minutes > 0 → RPUSH dg:<uid>:<key> args；SET dg_due:<uid>:<key> (now + digest) NX；return
  n = INSERT notifications(uid, key, args, category, created_at)
  center ∈ chs → INSERT inbox(n, uid)；INCR unread:<uid>
  for ch in chs − {center}: INSERT outbox(n, uid, ch, state = pending)；jobs.schedule_once("deliver", now, {outbox_id}, dedupe = outbox_id)
send_many：同一事务批量（≤ 1000），共享模板解析与偏好批量查询
send_to_address(address, key, args, locale, idem)：作用域 send:address；仅 email 渠道；地址格式校验；按地址哈希限流（每小时 5）
```

`digest_flush`（每分钟）：扫描到期的 `dg_due:*`（用 Redis ZSET `dg_due` 按到期时间存储，避免 SCAN）→ 取出参数列表 → 以 `args = {items: [...], count}` 调用一次 send（模板需支持列表参数，由模板作者负责）。

### 1.3 center

```
GET /v1/inbox?cursor=&unread_only=：SELECT … FROM inbox JOIN notifications … WHERE user_id = $1 ORDER BY id DESC
  展示时渲染标题与正文（按请求语言），附 link
POST /v1/inbox/read {ids[] | all: true}：UPDATE inbox SET read_at = now …；DECRBY unread（校正：未读计数以 SQL 为准，每小时 reconcile）
未读数：GET unread:<uid>（缺失时 SELECT count(*) … WHERE read_at IS NULL 并回填）
```

### 1.4 adapters

**email**（`EmailProvider` trait，按配置选择）：

| 提供方 | 请求 |
|---|---|
| mailgun | `POST https://api.mailgun.net/v3/<domain>/messages`（Basic auth `api:<key>`，form 字段 from / to / subject / text / html / `h:List-Unsubscribe`） |
| sendgrid | `POST https://api.sendgrid.com/v3/mail/send`（Bearer，JSON） |
| postmark | `POST https://api.postmarkapp.com/email`（`X-Postmark-Server-Token`） |
| ses | `POST https://email.<region>.amazonaws.com/v2/email/outbound-emails`（SigV4 签名，`aws-sigv4` crate） |
| http_relay | `POST <endpoint>`，JSON `{from, to, subject, text, html, headers}`，`Authorization: Bearer <token>`——站点自建的 HTTP→SMTP 中继（参考实现放在 `deploy/smtp-relay/`，非插件） |

错误归类：4xx（地址被拒、退订列表）→ 永久失败；429 / 5xx / 超时 → 临时失败。

**telegram**：`POST https://api.telegram.org/bot<token>/sendMessage`（`chat_id`、`text`（MarkdownV2 转义）、`disable_web_page_preview = true`）；403（用户屏蔽 Bot）→ 永久失败并停用绑定；429 → 按 `retry_after` 重试。

**discord**：用 Bot 创建 DM 频道 `POST /api/v10/users/@me/channels {recipient_id}` 后 `POST /api/v10/channels/{id}/messages`；403 → 停用绑定。

### 1.5 bindings

```
Telegram：
  POST /v1/bindings/telegram → code = random(16 字节 base32)，SET bind:<code> uid EX 600；返回 deep link https://t.me/<bot>?start=<code>
  Telegram webhook（POST /v1/telegram/webhook，校验 X-Telegram-Bot-Api-Secret-Token = webhook_secret）：
    message.text == "/start <code>" → uid = GETDEL bind:<code> → UPSERT bindings(uid, telegram, chat_id) → 回复确认
  解绑：DELETE /v1/bindings/telegram
Discord：OAuth2（scope identify）→ 回调保存 discord user id；state 参数防 CSRF
```

Webhook 路由 `auth = public`，以 secret 头鉴权；只处理 `/start` 与 `/stop` 命令，其余忽略。

### 1.6 security

```
on user.challenge_issued(evt{challenge_id, purpose, locale}):
  d = auth.challenge_delivery(challenge_id, idempotency_key = evt.id + ":deliver")   // 返回 {to, purpose, url, code?, expires_at, template_key, locale}
  直接调用 email 适配器（不经 outbox，避免令牌落库）；失败 → 抛出错误让内核重试订阅（至少一次投递）；
  幂等：challenge_delivery 同一幂等键返回同一结果；邮件提供方侧可能重复发送一次（可接受）
on user.logged_in(evt{new_device, risk_flags, region}): new_device || risk_flags 非空 → send(uid, "notify.security.new_device_login", {region, time})
```

### 1.7 unsubscribe

链接 `https://<site>/api/p/notify/v1/unsubscribe?t=<token>`；`token = base64url(uid ‖ category ‖ exp ‖ HMAC(unsubscribe_secret, …))`；GET 显示确认页（前端路由），POST 执行；邮件头 `List-Unsubscribe: <https://…>`、`List-Unsubscribe-Post: List-Unsubscribe=One-Click`（RFC 8058）。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:notify@0.1.0`）

```wit
package pt:notify@0.1.0;

interface notify {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, json};

  record send-result { notification-id: option<u64>, channels: list<string>, skipped: list<string>, duplicate: bool }
  record template-def {
    key: string, category: string, default-channels: list<string>, title-term: string, body-term: string,
    email-html-term: option<string>, link: option<string>, unsubscribable: bool, digest-minutes: u32, params-schema: json,
  }

  send: func(user: user-id, template-key: string, args: json, channels: option<list<string>>, idempotency-key: string) -> result<send-result, plugin-error>;
  send-many: func(users: list<user-id>, template-key: string, args: json, channels: option<list<string>>, idempotency-key: string) -> result<u32, plugin-error>;
  channels-of: func(user: user-id) -> result<list<string>, plugin-error>;
  register-templates: func(defs: list<template-def>) -> result<_, plugin-error>;
  send-to-address: func(address: string, template-key: string, args: json, locale: string, idempotency-key: string) -> result<send-result, plugin-error>;
}
```

| 方法 | 作用域 |
|---|---|
| `send`、`send-many` | `send` |
| `send-to-address` | `send:address` |
| `register-templates` | 内核启动时调用（caller = kernel）；插件运行时调用只能登记自己前缀的模板 |

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `notify.delivered` | `notification_id, user_id, channel, template_key` |
| `notify.failed` | `notification_id, user_id, channel, error_code, permanent` |

## 3. 数据库设计（schema `notify`）

```sql
CREATE TABLE notify.templates (
    key             text PRIMARY KEY,
    owner_plugin    text NOT NULL,
    category        text NOT NULL,
    default_channels text[] NOT NULL,
    title_term      text NOT NULL,
    body_term       text NOT NULL,
    email_html_term text,
    link            text,
    unsubscribable  boolean NOT NULL,
    digest_minutes  integer NOT NULL DEFAULT 0,
    params_schema   jsonb NOT NULL,
    updated_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE notify.prefs (
    user_id   bigint NOT NULL,
    category  text NOT NULL,
    channel   text NOT NULL,
    enabled   boolean NOT NULL,
    PRIMARY KEY (user_id, category, channel)
);

CREATE TABLE notify.notifications (
    id          bigint GENERATED ALWAYS AS IDENTITY,
    user_id     bigint NOT NULL,
    template_key text NOT NULL,
    args        jsonb NOT NULL,
    category    text NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (created_at, id)
) PARTITION BY RANGE (created_at);

CREATE TABLE notify.inbox (
    notification_id  bigint NOT NULL,
    created_at       timestamptz NOT NULL,
    user_id          bigint NOT NULL,
    read_at          timestamptz,
    PRIMARY KEY (created_at, notification_id)
) PARTITION BY RANGE (created_at);
CREATE INDEX inbox_user_idx ON notify.inbox (user_id, created_at DESC);
CREATE INDEX inbox_unread_idx ON notify.inbox (user_id) WHERE read_at IS NULL;

CREATE TABLE notify.outbox (
    id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    notification_id  bigint NOT NULL,
    user_id          bigint NOT NULL,
    channel          text NOT NULL,
    state            text NOT NULL CHECK (state IN ('pending','delivered','failed','skipped')),
    attempts         integer NOT NULL DEFAULT 0,
    error_code       text,
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX outbox_pending_idx ON notify.outbox (created_at) WHERE state = 'pending';

CREATE TABLE notify.bindings (
    user_id     bigint NOT NULL,
    channel     text NOT NULL CHECK (channel IN ('telegram', 'discord')),
    external_id text NOT NULL,          -- chat_id / discord user id（不进日志与事件）
    active      boolean NOT NULL DEFAULT true,
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, channel)
);

CREATE TABLE notify.idempotency (owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (owner, key));
```

分区：`notifications`、`inbox` 按月，保留 3 个月；`outbox` 30 天后 `cleanup` 删除。

Redis（`p:notify:`）：`unread:<uid>`、`rl:<uid>:<ch>:<hour>`、`dg:<uid>:<key>`（LIST）、`dg_due`（ZSET）、`bind:<code>`（10 分钟）。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.users@^0.1", "ctx.auth@^0.1", "ctx.terms@^0.1"]`；`[capabilities] sql, redis, kv, sensitive = ["user.email"], http_outbound = [...]`；scopes `ctx.auth = ["challenges:deliver"]`；订阅四项；cron 两项；`[[jobs]] deliver`；分区声明。

## 5. 前端设计

铃铛（未读徽标、下拉列表、全部已读）；通知中心页；设置页：类别 × 渠道开关矩阵（security 类锁定）、Telegram 绑定按钮（打开 deep link）、Discord 绑定；退订确认页。

## 6. 安全设计

邮箱需 `user.email` 授权且只在投递时读取；挑战令牌不落库；Telegram webhook secret 校验；退订令牌签名与过期；模板参数 schema 校验与渲染后转义；邮箱、chat_id 不进日志与事件；后台投递记录中邮箱脱敏（`a***@example.com`）。

## 7. 性能设计

受理只写库与调度；外部投递异步；站内未读走 Redis；send_many 批量。

## 8. 可观测性

`pt_plugin_notify_sent_total{channel,category,result}`、`pt_plugin_notify_delivery_seconds{channel}`、`pt_plugin_notify_pending{channel}`、`pt_plugin_notify_bindings_deactivated_total{channel}`。告警：邮件提供方连续失败 > 20。
