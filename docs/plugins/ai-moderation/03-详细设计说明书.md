## 1. 模块详细设计

### 1.1 intake

```
on comment.created(evt{comment_id, target, author_id}) / forum.post_created(evt{post_id, …}):
  source 未启用 → return
  新用户（注册 < new_user_days，经 ctx.users.get）→ 必审；否则按 sample_rate 抽样（hash(id) % 1000 < rate × 1000）
  jobs.schedule_once("classify_item", now, {kind, id}, dedupe = kind + ":" + id)
```

### 1.2 local（本地规则）

| 规则 | 结果 |
|---|---|
| 链接数 ≥ 5 且账号 < 7 天 | spam 0.95 |
| 包含 `spam_domains` 中的域名 | spam 0.99 |
| 同一字符或词重复 ≥ 30 次 | spam 0.8 |
| 文本含 32 位十六进制（疑似 passkey）或完整邮箱 / 手机号 | personal_info 0.9 |

本地规则命中 ≥ report_threshold → 不调用模型，直接动作。

### 1.3 classifier

系统提示（固定）：说明类别定义与评分口径（0 = 无，1 = 明确违规；讨论影视内容中的暴力情节不算 harassment 等站点特定说明，可在设置中追加）。用户消息：`untrusted(plain_text 前 4000 字)` + `text(context：内容类型、所在版块名称)`。

结构化输出 schema：

```json
{ "type": "object", "additionalProperties": false, "required": ["categories"],
  "properties": { "categories": { "type": "array", "items": { "type": "object", "additionalProperties": false,
      "required": ["category", "score", "rationale"],
      "properties": { "category": { "type": "string", "enum": ["spam","harassment","hate","sexual","illegal","self_harm","personal_info","other"] },
                      "score": { "type": "number" }, "rationale": { "type": "string" } } } } } }
```

`ctx.llm.complete({profile: "cheap", effort: "low", max_output_tokens: 600, idempotency_key: "aimod:<kind>:<id>"})`；refusal → 记录 `model_refused`（视为需人工抽查，分数 0.5 的 other）。

### 1.4 actions

```
max = 最高分类别
max.score ≥ threshold(category)（默认 report_threshold，可按类别覆盖）:
   case = reports.create({reporter: None（系统）, target: "comment:<id>" | "forum_post:<id>",
                          reason_code: map(category) → spam | abuse | illegal | other,
                          note: "AI 判定：<category> <score>；<rationale>", idempotency_key: "aimod:<kind>:<id>"})
   publish ai.content_flagged{target, categories[{category, score}], score: max.score, report_case_id: case}
max.score ≥ review_threshold → INSERT flags(state = 'review')（后台抽查列表）
```

### 1.5 feedback

订阅 `report.resolved`：若工单由本插件创建（kv 记录 case → flag 映射）→ 更新 flags.outcome（resolved = 真阳性、invalid = 误报）→ 按类别统计 precision。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:ai-moderation@0.1.0`）

```wit
package pt:ai-moderation@0.1.0;

interface ai-moderation {
  use pt:plugin/types@0.1.0.{plugin-error};
  record category-score { category: string, score: f64, rationale: string }
  record moderation-verdict { categories: list<category-score>, max-category: string, max-score: f64, model-used: bool }
  classify: func(text: string, context: string) -> result<moderation-verdict, plugin-error>;
}
```

调用方需作用域 `use`；在钩子调用链中调用会因出站被拒而失败（返回 `ai-moderation.unavailable_in_hook`，只给出本地规则结果）。

### 2.2 事件

`ai.content_flagged`：`target, categories[{category, score}], score, report_case_id?`。

## 3. 数据库设计（schema `ai_moderation`）

```sql
CREATE TABLE ai_moderation.flags (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    target          text NOT NULL UNIQUE,
    categories      jsonb NOT NULL,
    max_category    text NOT NULL,
    max_score       double precision NOT NULL,
    source          text NOT NULL CHECK (source IN ('local', 'model')),
    state           text NOT NULL CHECK (state IN ('reported', 'review', 'dismissed')),
    report_case_id  bigint,
    outcome         text CHECK (outcome IN ('true_positive', 'false_positive')),
    created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX flags_review_idx ON ai_moderation.flags (created_at DESC) WHERE state = 'review';
```

保留 180 天。不存正文。

## 4. 配置项

见 SRS §4，另 `category_thresholds`（按类别覆盖）、`extra_guidelines`（追加到系统提示的站点说明，≤ 2000 字）。清单：`requires = ["ctx.llm@^0.1", "ctx.reports@^0.1", "ctx.users@^0.1"]`、`optional_requires = ["ctx.comments@^0.1", "ctx.forum@^0.1"]`；scopes：`ctx.llm = ["use", "profile:cheap"]`、`ctx.reports = ["write"]`、`ctx.comments = ["read:raw"]`、`ctx.forum = ["read:raw"]`；订阅三项；钩子一项（默认关闭由设置控制，钩子内检查 `hook_enabled`）；`[[jobs]] classify_item`。
