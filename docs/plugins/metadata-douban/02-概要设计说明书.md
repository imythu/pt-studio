## 1. 设计目标

只做“代理客户端 + 归一化 + 缓存”；不内置爬取；默认关闭。

## 2. 总体结构

模块：`client`（代理 HTTP、限速、熔断）、`mapper`（代理约定格式 → 统一模型）、`cache`、`images`、`consent`（风险确认）。

## 3. 对外接口清单

| 类别 | 内容 |
|---|---|
| 导出 | `metadata-provider` |
| 能力 | `sql`、`redis`、`blob`；`http_outbound` 为空，由 site.toml 覆盖为代理主机与图片主机（清单中声明 `http_outbound = ["${proxy_host}"]` 占位，内核在启动时用静态配置替换——见 §7） |
| HTTP | `GET /v1/lookup`、`GET /v1/search`（user）；`POST /v1/admin/enable`、`POST /v1/admin/disable`（`metadata-douban.manage`） |
| 事件 | `metadata.fetched` |
| cron | `refresh_stale` |

## 4. 数据设计概要

`cache`（同 metadata-tmdb）；kv `consent`（确认人、时间、声明版本）。

## 5. 关键流程

```
lookup(id): enabled && consent 存在，否则 not_enabled
  GET {proxy_base_url}/subject/{id}（Authorization: Bearer proxy_token）→ 约定 JSON（详细设计 §2）→ mapper → cache
search(q, type): GET {proxy_base_url}/search?q=&type=
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-MDDOUBAN-1 | 是否内置爬虫 | 否：法律与条款风险由站点在自己的代理中承担；本插件代码不包含针对豆瓣的爬取逻辑 |
| DD-MDDOUBAN-2 | 代理接口 | 定义一份最小 JSON 约定，便于站点用任意实现对接 |

## 7. 对平台契约的新增

内核需要支持“出站主机由静态配置决定”的声明方式：清单 `http_outbound = ["config:proxy_base_url", "config:image_hosts"]`，内核启动时从 `[plugin.metadata-douban]` 读取并校验为 https 主机（同样适用于各 metadata 插件的代理覆盖，共用设计 §6）。

## 8. 需求追溯

FR-001 → consent；FR-002～004 → client、mapper；FR-005 → cache、client；FR-006 → images；FR-007 → 前端。
