## 1. 引言

### 1.1 目的

定义用户等级插件 `levels` 的需求：等级体系、数据驱动的升降级规则、等级与权限（RBAC 角色）的绑定、保号、VIP 与荣誉等级、不活跃账号处理。

### 1.2 范围

包含：

- 等级定义：名称（术语键）、排序、类型（普通 / VIP / 荣誉）、升级条件、保级条件、对应 RBAC 角色、升级奖励（邀请名额等）、是否保号；
- 两套预设：NexusPHP 风格、Gazelle 风格；
- 升降级评估：每日全量 + 流量变化触发的增量评估；降级前警告期；升级后保护期；
- 手动设置等级与锁定（管理员）；
- 保号（`is_protected`）：等级自带或管理员单独设置；
- 不活跃账号策略（可选）；
- VIP：由角色（如 shop 售卖的 `shop:vip`）或管理员授予，覆盖普通等级显示与权限；
- 进度查询、MCP 工具、钩子处理（`invite.before_issue`）。

不包含：

- 用户状态（封禁、禁止下载）——由 ratio-policy、hnr、anticheat 通过 identity 的限制机制处理；
- 员工职务（版主、管理员）——由 identity 的内置角色管理，与等级无关。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 等级（class） | 用户的成长等级，对应 `UserSummary.class_id` |
| 升级条件 | 满足后升到该等级的一组谓词（全部成立） |
| 保级条件 | 已在该等级的用户必须持续满足的一组谓词；不满足进入警告期 |
| 保护期 | 升级后一段时间内不评估降级 |
| 保号 | 不活跃账号策略对其不生效 |
| 指标（metric） | 规则可引用的用户数据：注册天数、上传量、下载量、分享率、做种时间、魔力值余额等 |

### 1.4 参考资料

- docs/platform/、docs/plugins/identity/（`set_class`、`set_class_roles`、限制机制）、docs/plugins/accounting/（`v_user_totals`）、docs/plugins/anticheat/03 §1.2（谓词格式）
- NexusPHP：`UC_PEASANT` … `UC_NEXUS_MASTER` 等级常量、`autopromotion`（按注册周数、上传量、分享率自动升级）、降级到 Peasant、“保号”等级（Veteran User 及以上）
- Gazelle/OPS：User → Member → Power User → Elite → Torrent Master → Power TM → Elite TM 的升级条件（上传量、分享率、发种数、注册时长）、`Required Ratio`
- UNIT3D：`groups` 表的 `autogroup` 与 `min_uploaded`、`min_ratio`、`min_age`、`min_avg_seedtime`、`min_seedsize`，定时任务 `AutoGroup`

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM，ID `levels`，缩写 `LVL`。
- 提供：`ctx.levels`（single）。
- 依赖：`ctx.users`（`set_class`、`restrictions`）、`ctx.rbac`（`set_class_roles`、`roles_of`）、`ctx.terms`；可选 `ctx.invites`（升级奖励）、`ctx.notify`。
- 只读视图：`identity.v_user_public`、`accounting.v_user_totals`、`ledger.v_balance`、`accounting.v_snatch`（发种数 / 做种量等聚合需求见详细设计）。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 查看当前等级、下一级条件与进度；收到升级 / 降级警告通知 |
| 管理员 | 配置等级与规则、选择预设、手动设置等级、锁定等级、设置保号、配置不活跃策略 |
| 其他插件 | invite 发邀前检查等级；shop 读取等级名；medals 订阅 `level.promoted` |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP | 等级为整数常量，权限用 `class >= UC_X` 比较；`cleanup.php` 中硬编码各级升级条件（注册周数、上传 GB、分享率），并在分享率过低时降为 Peasant；Veteran 及以上保号 | 运营成熟、用户熟悉 | 等级与权限耦合在整数比较中，改条件要改代码；清理脚本全表扫描锁表；降级无预警 | **采纳**等级层次与条件维度、保号；**改进**：条件数据驱动；等级 → 角色映射（权限点由 RBAC 决定）；降级前警告期；分批评估 |
| Gazelle/OPS | 每级有上传量、分享率、发种数、注册时长要求；不满足时降级；页面显示下一级要求 | 条件透明 | 同样硬编码 | **采纳**“下一级要求与进度”展示 |
| UNIT3D | `groups` 表字段配置自动升级条件，`AutoGroup` 命令定时执行 | 后台可配 | 条件维度固定为表字段，新增维度需改表 | **采纳**后台配置；**改进**：用谓词列表，指标集合可扩展 |

### 2.4 约束与假设

1. 等级 ID（`class_id`）为 `u32`，由本插件分配；identity 只存储 `class_id`，不理解其含义。
2. 规模 30 万用户；全量评估每日一次，≤ 15 分钟。
3. 流量指标来自 accounting 视图，按窗口最终一致（分钟级延迟）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-LVL-001 | 等级定义 | 管理员创建 / 编辑 / 停用等级：排序（rank）、类型（normal / vip / honor）、名称术语键、图标、颜色、升级条件、保级条件、角色、升级奖励、保号 | P0 | 后台可编辑；名称在术语后台可改 |
| FR-LVL-002 | 预设 | 首次启用时可选择 NexusPHP 或 Gazelle 预设（含中英文名称与默认条件），之后可修改 | P0 | 选择预设后生成对应等级与规则 |
| FR-LVL-003 | 默认等级 | 新注册用户进入 `default_class`（订阅 `user.registered`，若 identity 未设定初始等级） | P0 | 新用户 class = 默认等级 |
| FR-LVL-004 | 等级 → 角色 | 每个等级绑定一组 RBAC 角色（`levels:class_<id>` 动态角色 + 可选内置角色），通过 `ctx.rbac.set_class_roles` 同步 | P0 | 用户等级变化后权限随之变化 |
| FR-LVL-005 | 指标 | 规则可用指标：`account_age_days`、`uploaded`、`downloaded`、`ratio`、`seed_secs`、`avg_seed_secs`、`uploads_count`、`seeding_size`、`balance:<currency>`、`days_since_login` | P0 | 每个指标有单元测试 |
| FR-LVL-006 | 升级 | 用户满足某个更高普通等级的升级条件时升到满足条件的最高等级（可配置为每次只升一级） | P0 | 条件满足后下一次评估升级；发布 `level.promoted` |
| FR-LVL-007 | 保级与警告 | 用户不满足当前等级保级条件时进入警告期（默认 7 天），通知用户；期满仍不满足则降到满足保级条件的最高等级 | P0 | 警告期内恢复则取消警告；期满降级并发布 `level.demoted` |
| FR-LVL-008 | 保护期 | 升级后 `protect_days`（默认 3 天）内不评估降级 | P1 | 升级次日不满足保级也不进入警告 |
| FR-LVL-009 | 评估调度 | 每日全量评估；订阅 `traffic.settled` 标记“脏用户”，每 15 分钟增量评估脏用户的升级（降级只在每日评估中进行） | P0 | 上传量达标后 15 分钟内升级 |
| FR-LVL-010 | 手动设置 | 管理员为用户设置等级，可选“锁定”（自动评估不再改变其等级）与锁定期限 | P0 | 锁定期间评估跳过 |
| FR-LVL-011 | 保号 | `is_protected(user)`：当前等级 `protected = true`，或管理员单独设置保号（可设期限） | P0 | 服务返回正确 |
| FR-LVL-012 | 不活跃策略 | 可选：`days_since_login` ≥ N 且未保号的用户，执行动作（none / notify / restrict），restrict 通过 identity 施加 `banned` 限制（原因 `levels.inactive`），用户联系管理员解除 | P2 | 默认 none；开启后仅影响未保号用户 |
| FR-LVL-013 | VIP | VIP 等级（type = vip）不参与自动升降级；用户持有指定角色（默认 `shop:vip`）或管理员授予时进入 VIP 等级，角色到期后恢复为评估结果 | P1 | 购买 VIP 后等级显示为 VIP，到期后恢复 |
| FR-LVL-014 | 荣誉等级 | 荣誉等级（type = honor）只能手动授予，可设期限，不参与自动评估 | P2 | 到期后恢复 |
| FR-LVL-015 | 升级奖励 | 等级可配置首次升到该等级时的奖励：邀请名额（`invites.grant_quota`），每个用户每个等级只奖励一次 | P1 | 首次升级获得邀请；降级再升级不重复 |
| FR-LVL-016 | 进度 | `level_of(user)` 返回当前等级、下一等级、各条件当前值与目标值 | P0 | 与指标一致 |
| FR-LVL-017 | 发邀限制 | 处理 `invite.before_issue`：当前等级 `can_invite = false` 时拒绝 | P1 | 低等级发邀被拒，错误码 `levels.class_required` |
| FR-LVL-018 | 历史 | 记录每次等级变化（原因、规则、操作者） | P1 | 用户与管理员可查看 |
| FR-LVL-019 | 通知 | 升级、警告、降级通知（可关闭） | P2 | 模板使用术语 |
| FR-LVL-020 | 模拟 | 管理员修改规则前可预览“将有多少用户升级 / 降级” | P2 | 预览结果与实际评估一致 |
| FR-LVL-021 | MCP | `get_my_level`（已登记） | P2 | 返回等级与进度 |
| FR-LVL-022 | 用户删除 | 订阅 `user.deleted`，purge 时删除数据 | P1 | |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-LVL-001 | 性能 | 全量评估 | 30 万用户 ≤ 15 分钟，分批提交，单事务 < 5 s |
| NFR-LVL-002 | 性能 | 增量评估 | 每 15 分钟处理 ≤ 5 万脏用户 |
| NFR-LVL-003 | 性能 | `level_of` | p99 < 30 ms |
| NFR-LVL-004 | 可靠性 | 幂等 | 评估重复执行不重复发事件、不重复发奖励 |
| NFR-LVL-005 | 一致性 | 等级与角色 | identity 中的 class_id 与本插件记录一致；巡检修复偏差 |
| NFR-LVL-006 | 可配置 | 规则修改即时生效（下一次评估） | |
| NFR-LVL-007 | 可观测 | 升级 / 降级 / 警告次数、评估耗时 | |

## 5. 可配置项与站点术语

运行时设置：`default_class`、`promote_mode`（`highest` / `one_step`）、`warning_days`（7）、`protect_days`（3）、`notify`（true）、`vip_role`（`shop:vip`）、`inactivity.enabled`（false）、`inactivity.days`（180）、`inactivity.action`（none / notify / restrict）。

术语：`levels.class.<class_id>.name`、`levels.class.<class_id>.short`（动态，define）、`levels.protected`、`levels.vip`、`levels.honor.<honor_id>`（已登记）；新增 `levels.warning`（降级警告）、`levels.metric.<metric>`（指标显示名）。

## 6. 外部接口需求概述

- 服务 `ctx.levels`：`level_of`、`classes`、`evaluate`、`is_protected`、`set_class`（管理员语义）、`protect`。
- 事件：发布 `level.promoted`、`level.demoted`、`level.warned`、`level.warning_cleared`；订阅 `user.registered`、`user.roles_changed`、`traffic.settled`、`user.logged_in`（活跃时间）、`user.deleted`。
- 钩子：处理 `invite.before_issue`。
- HTTP：`/api/p/levels/v1/*`；插槽 `user.profile.header`、`user.profile.stats`；页面 `/p/levels/`（等级说明）。
- MCP：`get_my_level`。
