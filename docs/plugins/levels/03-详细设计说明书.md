## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/levels/`；状态在 PG schema `levels`。
- 谓词格式与 `pt-predicate` 一致（`{field, op, value}`，见 anticheat 03 §1.2），字段为本插件指标名。
- 字节数指标单位为字节；比率指标为 `f64`（下载量为 0 时 `ratio = +∞`，JSON 中以 `null` 表示“无限”，比较时视为大于任何数）。

### 1.1 classes

**等级定义**：

| 字段 | 说明 |
|---|---|
| `id` | `u32`，1～65535；预设从 10 开始，间隔 10，便于插入 |
| `slug` | `^[a-z0-9_]{2,32}$` |
| `rank` | 整数，越大越高；普通等级的 rank 唯一 |
| `type` | `normal` / `vip` / `honor` |
| `promote` | 谓词列表（normal 必填，最低等级可为空列表 = 默认等级） |
| `keep` | 谓词列表或 null（null = 与 promote 相同；空列表 = 永不降级） |
| `roles` | 额外内置角色（如 `uploader`），动态角色 `levels:class_<id>` 自动包含 |
| `can_invite` | bool |
| `reward_invites` | 首次到达奖励的邀请名额（0 = 无） |
| `protected` | bool，保号 |
| `icon`、`color` | 展示 |
| `active` | 停用后不再作为评估目标；已在该等级的用户在下一次每日评估中按保级失败处理（无警告直接重新评估） |

**角色同步**（等级创建 / 修改 / 启动时）：

```
for c in classes:
  rbac.define_role("levels:class_"+c.id, permissions = []（权限由管理员在 identity 后台为该角色配置）)   // 已存在则不变
  rbac.set_class_roles(c.id, ["levels:class_"+c.id] ++ c.roles)
terms.define([{key: "levels.class.<id>.name", …}, {key: "levels.class.<id>.short", …}], key = "class:<id>:<rev>")
```

**预设**（`POST /admin/preset {preset: "nexus" | "gazelle"}`，仅当 `classes` 为空或全部为预设生成且无手动修改时允许）：

NexusPHP 风格（节选，GiB = 2^30 字节）：

| id | slug | 中文名 | promote | keep | 保号 |
|---|---|---|---|---|---|
| 10 | peasant | 农民 | — | `ratio < 0.5`（仅作为降级落点） | 否 |
| 20 | user | 用户 | `[]`（默认） | `[]` | 否 |
| 30 | power_user | 精英用户 | `age ≥ 28d, uploaded ≥ 50 GiB, ratio ≥ 1.05` | `ratio ≥ 0.95` | 否 |
| 40 | elite_user | 爱好者 | `age ≥ 56d, uploaded ≥ 120 GiB, ratio ≥ 1.55` | `ratio ≥ 1.45` | 否 |
| 50 | crazy_user | 狂热者 | `age ≥ 84d, uploaded ≥ 300 GiB, ratio ≥ 2.05` | `ratio ≥ 1.95` | 否 |
| 60 | insane_user | 疯狂者 | `age ≥ 112d, uploaded ≥ 500 GiB, ratio ≥ 2.55` | `ratio ≥ 2.45` | 否 |
| 70 | veteran_user | 府丞 | `age ≥ 168d, uploaded ≥ 750 GiB, ratio ≥ 3.05` | `ratio ≥ 2.95` | 是 |
| 80 | extreme_user | 府尹 | `age ≥ 224d, uploaded ≥ 1 TiB, ratio ≥ 3.55` | `ratio ≥ 3.45` | 是 |
| 90 | ultimate_user | 极限玩家 | `age ≥ 280d, uploaded ≥ 1.5 TiB, ratio ≥ 4.05` | `ratio ≥ 3.95` | 是 |
| 100 | nexus_master | 大师 | `age ≥ 364d, uploaded ≥ 3 TiB, ratio ≥ 4.55` | `ratio ≥ 4.45` | 是 |
| 200 | vip | 贵宾 | type = vip | — | 是 |

“农民”的处理：rank 低于“用户”；`user` 的 keep 为 `ratio ≥ 0.5`（预设中改写），不满足时降到 peasant；peasant 的 promote = `ratio ≥ 0.6`（滞回）。这对应 NexusPHP 的分享率过低降级。下载限制由 ratio-policy 处理，不在等级中。

Gazelle 风格：User（默认）→ Member（`age ≥ 7d, uploaded ≥ 10 GiB, ratio ≥ 0.7`）→ Power User（`age ≥ 14d, uploaded ≥ 25 GiB, uploads_count ≥ 5, ratio ≥ 1.05`）→ Elite（`age ≥ 28d, uploaded ≥ 100 GiB, uploads_count ≥ 50, ratio ≥ 1.05`）→ Torrent Master（`age ≥ 56d, uploaded ≥ 500 GiB, uploads_count ≥ 500, ratio ≥ 1.05`）→ Power TM（`uploads_count ≥ 500, …`）→ Elite TM（`uploads_count ≥ 500, uploaded ≥ 1 TiB, ratio ≥ 1.05`）；各级 keep = 同 promote 的 ratio 条件。

### 1.2 metrics

| 指标 | 定义 | 来源 |
|---|---|---|
| `account_age_days` | `floor((now − created_at) / 86400)` | `identity.v_user_public` |
| `uploaded` / `downloaded` | 字节 | `accounting.v_user_totals` |
| `ratio` | `uploaded / downloaded`（downloaded = 0 → ∞） | 同上 |
| `seed_secs` | 累计做种秒数 | 同上 |
| `avg_seed_secs` | `seed_secs / max(1, 完成数)`；完成数来自 `v_snatch`（`completed_at IS NOT NULL` 计数） | `accounting.v_snatch` |
| `uploads_count` | 本人发布且 `status = approved` 的种子数（不含匿名过滤：匿名发布仍计入，用于本人等级） | `torrent.v_torrent_public` 的 `uploader_id` 为 NULL（匿名）时无法计数 → 见 §5 说明 |
| `seeding_size` | 当前做种体积 | 优先 `accounting.v_user_totals.seeding_size`（§7 申请）；否则不可用（规则校验拒绝） |
| `balance:<currency>` | 余额 | `ledger.v_balance` |
| `days_since_login` | `now − last_active_day` | 本插件 `user_levels.last_active_day` |

**批量计算**（评估批次 2000 个用户）：

```sql
SELECT u.id, u.class_id, u.created_at, t.uploaded, t.downloaded, t.seed_secs
FROM identity.v_user_public u
LEFT JOIN accounting.v_user_totals t ON t.user_id = u.id
WHERE u.id = ANY($1) AND u.status NOT IN ('deleted');
-- uploads_count（只在规则引用时执行）
SELECT uploader_id, count(*) FROM torrent.v_torrent_public
WHERE uploader_id = ANY($1) AND status = 'approved' GROUP BY uploader_id;
-- 完成数（只在引用 avg_seed_secs 时执行）
SELECT user_id, count(*) FROM accounting.v_snatch WHERE user_id = ANY($1) AND completed_at IS NOT NULL GROUP BY user_id;
-- 余额（只在引用 balance:* 时执行）
SELECT user_id, currency, balance FROM ledger.v_balance WHERE user_id = ANY($1) AND currency = ANY($2);
```

规则引用的指标集合在规则保存时计算并缓存（kv `metrics_used`），评估时只执行需要的查询。

### 1.3 evaluator

见 HLD §5.1 的算法，补充细节：

- **覆盖层**（`overrides` 表，取 `priority` 最高的生效项）：`manual`（priority 300，可无期限）、`honor`（200）、`vip`（100，来自角色）。存在生效覆盖时，`user_levels.class_id = override.class_id`；覆盖到期后立即用 full 模式评估一次。
- **评估时普通等级基线**：`base_class_id` 字段保存“不考虑覆盖时”的普通等级，覆盖期间也继续评估 base（升级、警告），覆盖到期后直接回到 base。
- **警告**：`warning_class_id`、`warning_deadline`、`warning_failed[]`（失败的谓词描述）；用户在警告期内升级或满足 keep → 清除。
- **one_step**：只考虑 rank 紧邻的下一级。
- **并发**：每个用户评估前 `SELECT … FROM user_levels WHERE user_id = $1 FOR UPDATE`；批次内按 user_id 排序获取锁。

### 1.4 scheduler

```
on_traffic_settled(evt): INSERT INTO dirty_users(user_id, since) VALUES (evt.user_id, now) ON CONFLICT DO NOTHING
incr_evaluate（tx manual）:
  loop: ids = DELETE FROM dirty_users WHERE user_id IN (SELECT user_id FROM dirty_users ORDER BY since LIMIT 2000 FOR UPDATE SKIP LOCKED) RETURNING user_id
        if empty: break
        metrics = batch(ids)；for u: eval(u, m, promote_only)；commit
daily_evaluate（tx manual）:
  cursor = kv "daily_cursor"（中断后续跑），按 user_id 键集分页 2000；每批 eval(full)；commit；更新 cursor
  完成后清除 cursor，记录耗时
```

`traffic.settled` 每用户每窗口一条（约每分钟），`dirty_users` 只做去重插入，单条事件处理 < 1 ms。

### 1.5 rewards、protection、inactivity

- 奖励：`INSERT INTO rewards_given(user_id, class_id) ON CONFLICT DO NOTHING RETURNING`；有行才调用 `invites.grant_quota({user, amount: reward_invites, reason: "levels.promotion", idempotency_key: "lvl:reward:<uid>:<cid>"})`；调用失败记录 `pending`，`expire_overrides` 顺带重试。
- 保号：`is_protected(uid) = user_levels.protected_until > now || class(user_levels.class_id).protected`。
- 不活跃：`on_logged_in` 更新 `last_active_day`（同一天只写一次：`UPDATE … WHERE last_active_day < $today`）；`daily_evaluate` 中对 `days_since_login ≥ inactivity.days` 且未保号的用户执行动作：`notify`（每 30 天最多一次）或 `restrict` → `users.apply_restriction({kind: banned, reason_code: "levels.inactive", idempotency_key: "lvl:inactive:<uid>:<yyyymm>"})`。identity 规定插件不能限制版主及以上员工，返回 `kernel.forbidden` 时跳过并记录。

### 1.6 钩子处理 `invite.before_issue`

```
on invite.before_issue(input{inviter_id, …}):
  ul = user_levels[inviter_id]；c = classes[ul.class_id]
  if !c.can_invite: deny("levels.class_required", "当前等级不能发送邀请")
  allow
```

只读本插件表（一次主键查询），满足 200 ms 超时。

### 1.7 reconcile

`reconcile` 分批比较 `identity.v_user_public.class_id` 与 `user_levels.class_id`；不一致时以 identity 为准更新本地并记为 `manual` 覆盖（与 `on_class_changed` 相同逻辑），指标 `reconcile_mismatch_total`。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:levels@0.1.0`）

```wit
package pt:levels@0.1.0;

interface levels {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  enum class-type { normal, vip, honor }
  record class-def {
    id: u32, slug: string, rank: s32, class-type: class-type, name-key: string,
    can-invite: bool, protected: bool, icon: option<string>, color: option<string>,
  }
  record condition-progress { metric: string, op: string, target: string, current: string, met: bool }
  record level-info {
    class-id: u32, name-key: string, source: string,
    next-class-id: option<u32>, progress: list<condition-progress>,
    warning-deadline: option<timestamp-ms>, protected: bool,
  }

  level-of: func(user: user-id) -> result<level-info, plugin-error>;
  classes: func() -> result<list<class-def>, plugin-error>;
  evaluate: func(user: user-id) -> result<level-info, plugin-error>;
  is-protected: func(user: user-id) -> result<bool, plugin-error>;
  grant-honor: func(user: user-id, class-id: u32, until: option<timestamp-ms>, reason: string, idempotency-key: string) -> result<_, plugin-error>;
}
```

| 方法 | 作用域 | 错误码 |
|---|---|---|
| `level-of`、`classes`、`is-protected` | — | `kernel.not_found` |
| `evaluate` | `evaluate` | |
| `grant-honor` | `grant` | `levels.class_not_found`、`levels.class_type_invalid`（只能授予 vip / honor） |

`target` 与 `current` 以字符串返回（字节数为十进制字符串，比率保留 2 位，∞ 为 `"inf"`），前端按 `metric` 格式化。

**POST `/v1/admin/users/{id}/protect`** `{ "until": "2027-01-01T00:00:00Z" }` → 204。

## 3. 数据库设计

### 3.1 PostgreSQL（schema `levels`）

```sql
CREATE TABLE levels.classes (
    id              integer PRIMARY KEY CHECK (id BETWEEN 1 AND 65535),
    slug            text NOT NULL UNIQUE,
    rank            integer NOT NULL,
    type            text NOT NULL CHECK (type IN ('normal', 'vip', 'honor')),
    promote         jsonb NOT NULL DEFAULT '[]',
    keep            jsonb,
    roles           text[] NOT NULL DEFAULT '{}',
    can_invite      boolean NOT NULL DEFAULT true,
    reward_invites  integer NOT NULL DEFAULT 0 CHECK (reward_invites BETWEEN 0 AND 100),
    protected       boolean NOT NULL DEFAULT false,
    icon            text,
    color           text,
    active          boolean NOT NULL DEFAULT true,
    preset          text,
    revision        integer NOT NULL DEFAULT 1,
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX classes_normal_rank_idx ON levels.classes (rank) WHERE type = 'normal' AND active;

CREATE TABLE levels.user_levels (
    user_id            bigint PRIMARY KEY,
    class_id           integer NOT NULL,
    base_class_id      integer NOT NULL,
    source             text NOT NULL CHECK (source IN ('auto', 'manual', 'vip', 'honor', 'default')),
    protect_until      timestamptz,             -- 升级保护期
    protected_until    timestamptz,             -- 管理员保号
    warning_class_id   integer,
    warning_deadline   timestamptz,
    warning_failed     jsonb,
    last_active_day    date,
    last_inactive_notice date,
    evaluated_at       timestamptz,
    updated_at         timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX user_levels_warning_idx ON levels.user_levels (warning_deadline) WHERE warning_deadline IS NOT NULL;
CREATE INDEX user_levels_active_idx ON levels.user_levels (last_active_day);

CREATE TABLE levels.overrides (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id     bigint NOT NULL,
    kind        text NOT NULL CHECK (kind IN ('manual', 'honor', 'vip')),
    class_id    integer NOT NULL REFERENCES levels.classes (id),
    until       timestamptz,
    reason      text NOT NULL DEFAULT '',
    created_by  text NOT NULL,
    source_ref  text UNIQUE,
    ended_at    timestamptz,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX overrides_user_idx ON levels.overrides (user_id) WHERE ended_at IS NULL;
CREATE INDEX overrides_until_idx ON levels.overrides (until) WHERE ended_at IS NULL AND until IS NOT NULL;

CREATE TABLE levels.dirty_users (
    user_id  bigint PRIMARY KEY,
    since    timestamptz NOT NULL
);

CREATE TABLE levels.rewards_given (
    user_id   bigint NOT NULL,
    class_id  integer NOT NULL,
    state     text NOT NULL DEFAULT 'pending' CHECK (state IN ('pending', 'done', 'skipped')),
    PRIMARY KEY (user_id, class_id)
);

CREATE TABLE levels.history (
    id          bigint GENERATED ALWAYS AS IDENTITY,
    at          timestamptz NOT NULL DEFAULT now(),
    user_id     bigint NOT NULL,
    from_class  integer,
    to_class    integer NOT NULL,
    cause       text NOT NULL,
    actor       text NOT NULL,
    detail      jsonb,
    PRIMARY KEY (at, id)
) PARTITION BY RANGE (at);
CREATE INDEX history_user_idx ON levels.history (user_id, at DESC);
```

## 5. 前端设计

- 个人页：等级徽标（颜色、图标、名称）；进度条按条件逐项显示（已满足打勾）；警告期显示倒计时与失败条件。
- `/p/levels/`：等级说明表（各级条件、权益描述——权益文案由管理员在等级描述中填写）。
- 后台：等级列表（拖拽调整 rank）、条件编辑器（谓词构建器，指标下拉）、预设向导、模拟结果对比。

匿名发布对 `uploads_count` 的影响：`torrent.v_torrent_public` 对匿名种子 `uploader_id` 为 NULL，导致匿名发布不计入发种数。站点若依赖发种数，应请 torrent 提供只含计数的视图 `v_uploader_counts(user_id, approved_count)`（§7 已在 02 中提出的视图申请里补充）。

## 6. 安全设计

| 点 | 措施 |
|---|---|
| 规则注入 | 谓词字段白名单；数值类型校验；SQL 只来自固定模板 |
| 越权 | 管理接口权限点；服务作用域 |
| 员工保护 | identity 拒绝插件限制员工；本插件不对员工执行不活跃限制 |

## 7. 性能设计

- 每日全量：150 批 × 2000 用户；每批 2～5 条视图查询（索引走 `user_id = ANY`）+ 逐用户 eval（内存计算）+ 变化用户的 `set_class`（通常 < 1%）。
- 增量：每 15 分钟 ≤ 5 万脏用户，只升级。
- `level_of`：主键读取 + 一次指标批量查询（单用户），p99 < 30 ms。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `levels.class_required` | 403 | 等级不足（已登记，钩子返回） |
| `levels.class_not_found` | 404 | 等级不存在 |
| `levels.class_type_invalid` | 422 | 等级类型不允许该操作 |
| `levels.rule_invalid` | 422 | 条件校验失败（未知指标、类型错误、不可用指标） |
| `levels.rank_conflict` | 409 | 普通等级 rank 重复 |
| `levels.class_in_use` | 409 | 删除仍有用户的等级 |
| `levels.preset_not_allowed` | 409 | 已有自定义等级时不能应用预设 |
