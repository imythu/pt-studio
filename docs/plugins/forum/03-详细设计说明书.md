## 1. 模块详细设计

### 1.1 acl

版块权限（`boards.acl`）：

```json
{ "read":   { "min_class": null, "roles": [] },
  "reply":  { "min_class": 20,   "roles": [] },
  "create": { "min_class": 30,   "roles": ["uploader"] },
  "hidden": false }
```

`allowed(u, board, action)`：`u` 有 `forum.manage` → true；`action = read` 时还要求 `forum.read`；`action ∈ {reply, create}` 时要求 `forum.post`；然后 `min_class` 为空或 `levels.level_of(u).rank ≥ rank(min_class)`（等级按 rank 比较，需要 `ctx.levels.classes()` 的 rank）**或** `u` 拥有 `roles` 中任一角色。版块版主对其版块的 read / reply / create 一律允许。

可见版块集合：`visible_boards(u)` 计算后缓存在 Redis `vb:<uid>`（60 s，用户等级 / 角色变化时由 `user.class_changed`、`user.roles_changed` 订阅删除）。

### 1.2 topics 与 posts

```
create_topic(u, board, title, body, markup, poll?, idem):
  allowed(u, board, create)；antispam；hooks.run(forum.before_post, {is_topic: true, …})
  INSERT topics(board_id, title, author_id, created_at, last_post_at, …)
  INSERT posts(topic_id, author_id, floor = 1, …)；UPDATE topics.first_post_id、last_post_id、post_count = 1
  UPDATE boards SET topic_count+1, post_count+1, last_topic_id, last_post_at
  poll → INSERT polls
  自动订阅作者；publish forum.topic_created、forum.post_created
reply(u, topic, body, quote_of?, idem):
  t 未锁定（版主除外）；allowed(u, t.board, reply)；antispam；钩子
  floor = UPDATE topics SET post_count = post_count + 1, last_post_id = …, last_post_at = now RETURNING post_count
  INSERT posts；UPDATE boards；publish forum.post_created；subs::mark_dirty(topic)
move(topic, to_board)：更新 topics.board_id；两个版块计数调整（重新计算该主题的帖子数）；publish forum.topic_moved
merge(from, into)：posts 按时间重排 floor（into 中按 created_at 合并，floor 重新编号——只在合并时整体重写，帖子数 ≤ 10 万），from 标记 merged_into；publish forum.topic_merged
split(topic, from_floor, new_title)：floor ≥ from_floor 的帖子移到新主题并重新编号
```

全局公告：`topics.announcement = true` 的主题出现在所有可见版块的列表顶部与 `home.announcements` 插槽（最多 5 条）。

### 1.3 polls

`polls(topic_id, question, options[], multi, max_choices, closes_at, public_voters)`；投票 `poll_votes(poll_id, user_id, option_idx)` 主键 `(poll_id, user_id, option_idx)`；单选时先删除再插入（同一事务）；结果计数 `poll_counts` 冗余（`UPDATE … SET counts[idx] = counts[idx] + 1`）；`closes_at` 后不能投票；`public_voters = false` 时只显示计数。

### 1.4 reads

见 HLD §5。版块页一次性计算：

```sql
SELECT t.id, t.last_post_id, t.last_post_at, r.last_read_post_id
FROM forum.topics t
LEFT JOIN forum.topic_reads r ON r.topic_id = t.id AND r.user_id = $uid
WHERE t.board_id = $board AND t.state = 'visible'
ORDER BY t.sticky DESC, t.last_post_at DESC
LIMIT $n OFFSET $o;
```

`base` 在应用层比较。版块列表的未读标记：对每个可见版块执行 `EXISTS (SELECT 1 FROM topics t LEFT JOIN topic_reads r … WHERE t.board_id = b AND t.last_post_at > base AND (r.topic_id IS NULL OR t.last_post_id > r.last_read_post_id) LIMIT 1)`，借助 `topics(board_id, last_post_at DESC)` 索引；版块数 ≤ 100。

`topic_reads` 清理：超过 180 天未更新且 `last_post_at < 用户 catchup` 的行可删除（每日任务，按 user 分批）。

### 1.5 subs

```
mark_dirty(topic)：INSERT subs_dirty(topic_id, since) ON CONFLICT DO NOTHING
subs_digest（每 10 分钟）：取 since < now − digest_minutes 的 dirty 主题；
  for 订阅者（排除最后发帖者、无 read 权限者）：notify.send(uid, "forum.topic_updated", {topic_id, new_posts}, None)
  幂等键 "forum:sub:<topic>:<last_post_id>:<uid>"；删除 dirty
```

### 1.6 search 贡献

`index-schemas()` → `forum` 索引：`forum_board_id`（int，filterable）、`forum_topic_id`（int）、`forum_post_id`（id 即 post_id）、`forum_title`（searchable，rank 1）、`forum_body`（searchable，rank 2，取 `plain` 前 10000 字）、`forum_author_id`（filterable）、`forum_created_at`（sortable）。订阅事件后 search 调用 `to-document("forum", post_id)`。

`search.before_query` 处理（index = forum）：`modify.filters += ["forum_board_id IN [<visible boards>]"]`。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:forum@0.1.0`）

```wit
package pt:forum@0.1.0;

interface forum {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms};

  record topic-info { id: u64, board-id: u64, title: string, author-id: option<user-id>, post-count: u32,
                      locked: bool, last-post-at: timestamp-ms, url: string }
  record create-topic-request { board-id: u64, author-id: user-id, title: string, body: string,
                                markup: string, idempotency-key: string }

  create-topic: func(req: create-topic-request) -> result<u64, plugin-error>;
  get-topic: func(id: u64) -> result<option<topic-info>, plugin-error>;
  link-topic: func(target: string, topic-id: u64) -> result<_, plugin-error>;
  topic-for: func(target: string) -> result<option<topic-info>, plugin-error>;
}
```

`create-topic`、`link-topic` 需作用域 `write`。

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `forum.topic_created` | `topic_id, forum_id, author_id, title_length` |
| `forum.post_created` | `post_id, topic_id, forum_id, author_id, mentions[]` |
| `forum.post_updated` | `post_id, topic_id, editor_id` |
| `forum.post_deleted` | `post_id, topic_id, by, by_moderator` |
| `forum.topic_moved` | `topic_id, from_forum_id, to_forum_id, by` |
| `forum.topic_locked` | `topic_id, locked, by` |
| `forum.topic_merged` | `from_topic_id, into_topic_id, by` |

### 2.3 钩子 `forum.before_post`

输入：`version, actor, author_id, forum_id, topic_id?, title?, body, markup, is_topic`；allow / deny / modify(`title`、`body`)；300 ms；失败策略 allow。

### 2.4 HTTP API（前缀 `/api/p/forum/v1`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/boards` | 可见分区与版块（含未读、计数、最后帖子） |
| GET | `/boards/{id}/topics?page=` | 主题列表（置顶在前，未读标记） |
| POST | `/boards/{id}/topics` | 发主题（Idempotency-Key）`{title, body, markup, poll?}` |
| GET | `/topics/{id}?page=` / `?post={post_id}`（跳转到某帖所在页） | 主题与帖子 |
| POST | `/topics/{id}/posts` | 回复 `{body, markup, quote_of?}` |
| PATCH / DELETE | `/posts/{id}` | 编辑 / 删除 |
| GET | `/posts/{id}/history` | 编辑历史（版主） |
| POST / DELETE | `/posts/{id}/thanks` | 感谢 |
| POST | `/topics/{id}/vote` | 投票 `{options: [0, 2]}` |
| POST / DELETE | `/topics/{id}/subscription` | 订阅 |
| POST | `/boards/{id}/catchup`、`/catchup` | 标为已读 |
| POST | `/topics/{id}/moderate` | `{action: sticky|unsticky|feature|lock|unlock|announce|move|merge|split, …}`（版主） |
| GET/POST/PATCH/DELETE | `/admin/categories`、`/admin/boards` | 管理（`forum.manage`） |

### 2.5 MCP

无独立工具（`search_torrents` 不覆盖论坛；后续可加 `search_forum`）。

## 3. 数据库设计（schema `forum`）

```sql
CREATE TABLE forum.categories (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, sort integer NOT NULL DEFAULT 100);

CREATE TABLE forum.boards (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    category_id     bigint NOT NULL REFERENCES forum.categories (id),
    sort            integer NOT NULL DEFAULT 100,
    icon            text,
    acl             jsonb NOT NULL,
    topic_count     integer NOT NULL DEFAULT 0,
    post_count      integer NOT NULL DEFAULT 0,
    last_topic_id   bigint,
    last_post_at    timestamptz,
    active          boolean NOT NULL DEFAULT true
);

CREATE TABLE forum.board_moderators (board_id bigint NOT NULL REFERENCES forum.boards (id), user_id bigint NOT NULL, PRIMARY KEY (board_id, user_id));

CREATE TABLE forum.topics (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    board_id        bigint NOT NULL REFERENCES forum.boards (id),
    title           text NOT NULL,
    author_id       bigint,
    first_post_id   bigint,
    last_post_id    bigint,
    last_post_at    timestamptz NOT NULL,
    last_poster_id  bigint,
    post_count      integer NOT NULL DEFAULT 0,
    sticky          boolean NOT NULL DEFAULT false,
    announcement    boolean NOT NULL DEFAULT false,
    featured        boolean NOT NULL DEFAULT false,
    locked          boolean NOT NULL DEFAULT false,
    state           text NOT NULL DEFAULT 'visible' CHECK (state IN ('visible', 'deleted', 'merged')),
    merged_into     bigint,
    created_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX topics_board_idx ON forum.topics (board_id, sticky DESC, last_post_at DESC) WHERE state = 'visible';
CREATE INDEX topics_announce_idx ON forum.topics (last_post_at DESC) WHERE announcement AND state = 'visible';

CREATE TABLE forum.posts (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    topic_id        bigint NOT NULL REFERENCES forum.topics (id),
    floor           integer NOT NULL,
    author_id       bigint,
    markup          text NOT NULL,
    source          text NOT NULL,
    rendered        text NOT NULL,
    plain           text NOT NULL,
    render_version  integer NOT NULL,
    state           text NOT NULL DEFAULT 'visible' CHECK (state IN ('visible','deleted_by_author','deleted_by_moderator','purged')),
    thanks_count    integer NOT NULL DEFAULT 0,
    created_at      timestamptz NOT NULL DEFAULT now(),
    edited_at       timestamptz,
    UNIQUE (topic_id, floor)
);
CREATE INDEX posts_author_idx ON forum.posts (author_id, id DESC);

CREATE TABLE forum.post_edits (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, post_id bigint NOT NULL REFERENCES forum.posts (id), editor_id bigint NOT NULL, old_source text NOT NULL, edited_at timestamptz NOT NULL DEFAULT now());

CREATE TABLE forum.polls (
    topic_id       bigint PRIMARY KEY REFERENCES forum.topics (id),
    question       text NOT NULL,
    options        text[] NOT NULL CHECK (array_length(options, 1) BETWEEN 2 AND 20),
    counts         integer[] NOT NULL,
    multi          boolean NOT NULL DEFAULT false,
    max_choices    integer NOT NULL DEFAULT 1,
    public_voters  boolean NOT NULL DEFAULT false,
    closes_at      timestamptz
);
CREATE TABLE forum.poll_votes (topic_id bigint NOT NULL, user_id bigint NOT NULL, option_idx smallint NOT NULL, PRIMARY KEY (topic_id, user_id, option_idx));

CREATE TABLE forum.topic_reads (user_id bigint NOT NULL, topic_id bigint NOT NULL, last_read_post_id bigint NOT NULL, updated_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (user_id, topic_id));
CREATE TABLE forum.board_catchup (user_id bigint NOT NULL, board_id bigint NOT NULL, at timestamptz NOT NULL, PRIMARY KEY (user_id, board_id));
CREATE TABLE forum.user_catchup (user_id bigint PRIMARY KEY, at timestamptz NOT NULL);

CREATE TABLE forum.subscriptions (user_id bigint NOT NULL, topic_id bigint NOT NULL, PRIMARY KEY (user_id, topic_id));
CREATE INDEX subscriptions_topic_idx ON forum.subscriptions (topic_id);
CREATE TABLE forum.subs_dirty (topic_id bigint PRIMARY KEY, since timestamptz NOT NULL);

CREATE TABLE forum.thanks (post_id bigint NOT NULL, user_id bigint NOT NULL, PRIMARY KEY (post_id, user_id));
CREATE TABLE forum.topic_links (target text PRIMARY KEY, topic_id bigint NOT NULL REFERENCES forum.topics (id));
```

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.users@^0.1", "ctx.rbac@^0.1"]`、`optional_requires = ["ctx.levels@^0.1", "ctx.notify@^0.1"]`；`search_contributor = true`；`[[hook_points]] forum.before_post`；`[[hooks]] search.before_query priority 20`；订阅 `user.deleted`、`user.class_changed`、`user.roles_changed`；cron `subs_digest`、`poll_close`、`reads_cleanup`（`0 6 * * *`）。

## 5. 前端设计

版块首页（分区折叠、未读标记、最后发帖）；主题列表（置顶 / 公告 / 精华徽标）；主题页（楼层、引用、感谢、`forum.post.footer` 插槽中的勋章）；编辑器复用 comments 组件；版主工具栏。

## 6. 安全设计

ACL 在每个读写接口检查；隐藏版块对无权者返回 404；渲染与反垃圾同 comments；投票防重复（主键）；版主操作审计。

## 7. 性能设计

版块与主题列表依赖冗余计数与索引；可见版块集合缓存；`topic_reads` 只为打开过的主题写行。

## 8. 可观测性

`pt_plugin_forum_posts_total`、`pt_plugin_forum_rejected_total{reason}`、`pt_plugin_forum_board_list_seconds`。
