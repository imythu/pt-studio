## 1. 设计目标与原则

1. **权限集中计算**：每个请求计算一次“用户可见版块集合”（缓存 60 秒），所有查询以此过滤。
2. **未读高效**：`topic_reads(user, topic, last_read_post_id)` 只在用户打开主题时写入；版块级 `board_catchup(user, board, at)` 与全站级 `catchup_at` 表示“此前全部已读”。
3. **计数冗余**：版块与主题的计数、最后帖子冗余存储，事务内更新。
4. **渲染与反垃圾复用 comments 的 `pt-markup` 与规则实现**（代码复用，不是服务依赖）。

## 2. 总体结构

| 模块 | 职责 |
|---|---|
| `boards` | 分区、版块、权限、版块版主 |
| `acl` | 可见 / 回帖 / 发主题判定（等级经 `ctx.levels`，角色经 `ctx.rbac`） |
| `topics` | 主题 CRUD、置顶、精华、锁定、移动、合并、拆分 |
| `posts` | 帖子发表、编辑、删除、引用、@、感谢 |
| `polls` | 投票 |
| `reads` | 未读追踪 |
| `subs` | 订阅与通知 |
| `search` | forum 索引贡献 |

## 4. 数据设计概要

`categories`、`boards`（含权限 JSON、计数、最后帖子）、`board_moderators`、`topics`、`posts`、`post_edits`、`polls`、`poll_votes`、`topic_reads`、`board_catchup`、`user_catchup`、`subscriptions`、`thanks`、`topic_links`（target → topic）。

## 5. 关键流程

```
未读判定（主题 t、用户 u）：
  r = topic_reads[(u, t)]
  base = max(user_catchup[u], board_catchup[(u, t.board)])
  unread = t.last_post_at > base AND (r is None OR t.last_post_id > r.last_read_post_id)
版块未读：存在任一满足条件的主题（查询：board 的主题按 last_post_at 倒序取 last_post_at > base 的前 50 条，与 topic_reads 左连接）
打开主题第 N 页：UPSERT topic_reads SET last_read_post_id = max(旧值, 本页最后一帖 ID)
全部标为已读：UPDATE user_catchup / board_catchup SET at = now()（单行）
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-FORUM-1 | 权限模型 | 最低等级 + 角色白名单（OR）：覆盖 Gazelle（class）与 UNIT3D（group）两种习惯，且不随组数膨胀 |
| DD-FORUM-2 | 未读 | 主题级行 + 版块 / 全站追赶时间戳（Gazelle 改进） |
| DD-FORUM-3 | 搜索可见性 | 处理 `search.before_query`（只能追加过滤，符合钩子约束） |

## 7. 对平台契约的新增

服务 `topic_for(target)`；事件 `forum.topic_moved` / `topic_locked` / `topic_merged`；本插件作为 `search.before_query` 的处理者（钩子目录预期处理者中需加入 forum）；术语 `forum.category.<id>`、`forum.sticky`、`forum.featured`、`forum.announcement`；共享 crate：反垃圾逻辑从 comments 抽出为 `pt-antispam`（与 `pt-markup` 并列）。
