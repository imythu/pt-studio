## 1. 设计目标与原则

1. **种子实体的唯一拥有者**：info_hash、文件、状态、Group 关联只在本插件中写；其他插件通过服务、事件、钩子、视图访问。
2. **核心提供机制，插件决定策略**：状态机的合法迁移由本插件保证；“谁能通过审核、候选区规则、等级限制下载”由 moderation、levels、ratio-policy 等通过钩子与服务决定。
3. **info 字典字节不可变**：规范化后存储的 info 字节就是最终 hash 的依据，下载时只改根字典的 announce 等键，用“根字典拼接”保证 hash 不变。
4. **不依赖 tracker-bridge**：tracker 同步由 tracker-bridge 订阅本插件事件完成，避免依赖环（tracker-bridge requires `ctx.torrents`）。
5. **passkey 最小暴露**：只在下载响应体中出现；签名下载链接不含 passkey。
6. **热路径缓存不可变数据**：规范化种子按内容寻址，进程内 LRU 缓存不存在失效问题。

## 2. 总体结构

### 2.1 位置

```
 浏览器 / RSS / MCP ──HTTP──► 内核网关 ──► torrent（Native）──► PostgreSQL schema torrent
                                             │  │  │            对象存储 plugins/torrent/
                       ctx.content_types ◄───┘  │  └──► ctx.users（passkey，需 user.passkey 授权）
                       （内核聚合 → type-*）    │
                                    ctx.hooks.run(torrent.before_*) ──► moderation / levels / ratio-policy / hnr …
                                             │
                                  事件（outbox）──► tracker-bridge ──► Redis trk:t:* ──► pt-tracker
                                             ├──► search-meilisearch（索引）
                                             └──► moderation、requests、mediainfo、ai-upload-review、rss …
```

### 2.2 模块划分

| 模块 | 职责 |
|---|---|
| `bencode` | 有界解码（保留原始字节切片）、规范编码、根字典拼接 |
| `parser` | v1/v2/hybrid 结构校验、路径安全、文件列表提取、hash 计算 |
| `normalizer` | 键白名单、private/source、hybrid 策略、生成规范化种子字节 |
| `store` | 种子、文件列表、修订、Group、标签、分类、制作组的数据库访问 |
| `blob_cache` | 对象存储读写 + 进程内 LRU（键为内容哈希） |
| `upload` | 上传编排：解析 → 类型规范化 → 去重 → 钩子 → 落库 → 事件 |
| `lifecycle` | 状态机、编辑、文件替换、删除、恢复、清除 |
| `groups` | Group 查找或创建、编辑、合并 |
| `download` | 权限与状态检查、钩子、passkey 注入、签名链接、批量 zip、下载历史 |
| `visibility` | 统一的可见性与匿名裁剪（API、服务、MCP、搜索共用） |
| `service` | `TorrentsService` 实现（`ctx.torrents`） |
| `http` | axum 路由 |
| `search` | `SearchContributor` 实现 |
| `mcp` | `McpTool` 实现 |
| `jobs` | 定时任务：对象存储 GC、清除、Group 计数校正 |

## 5. 关键流程

### 5.1 上传

```
客户端 ─POST /v1/torrents (multipart, Idempotency-Key)─► 网关（鉴权、torrent.upload、限流、幂等）
torrent.upload:
  1 读取文件（≤ max_torrent_kb）→ bencode 有界解码 → parser 校验（v1/v2/hybrid、路径）
  2 normalizer：白名单、private、source、hybrid 策略 → 规范 info 字节 → hash
  3 ctx.content_types.normalize / group_key / canonical_title
  4 预检查重复（SELECT by hash，未删除）→ 命中则 409
  5 ctx.hooks.run("torrent.before_upload", input) → deny 则返回
  6 blob.put("torrents/<hash>.torrent")（内容寻址，幂等；失败返回 503）
  7 事务：upsert group → INSERT torrents（唯一约束兜底并发重复）→ 文件版本、文件列表、修订、标签
           → publish torrent.created（+ group.created）→ COMMIT
  8 201 {id, status, need_redownload: true, download_url}
异步：tracker-bridge 写 trk:t:<hash>（约 1 秒）；search 建索引；moderation 入队。
```

### 5.2 下载

```
GET /v1/torrents/{id}/download
  1 load torrent（含可见性：状态 + 发布者 + 权限）→ 不可见 404，不可下载 403 torrent.not_downloadable
  2 用户状态（ctx.users.get，5 s 进程内缓存）→ banned/pending/leech_disabled 规则
  3 promotion = ctx.promotions.current(id)（可选，失败置空）
  4 ctx.hooks.run("torrent.before_download", {user_id, torrent_id, uploader_id, size, status, promotion})
  5 passkey = ctx.users.get_sensitive(user_id, "passkey")（不缓存）
  6 bytes = blob_cache.get(hash) → splice_root(announce=<base>/<passkey>, announce-list, comment, created by, creation date)
  7 事务：upsert user_downloads；publish torrent.downloaded → COMMIT
  8 200 application/x-bittorrent; Content-Disposition 附件名；Cache-Control: private, no-store
```

### 5.3 状态迁移

```
moderation.decide → ctx.torrents.set_status(id, approved, note)
  torrent: 校验迁移合法 → hooks.run(torrent.before_status_change) → UPDATE … WHERE version = $v
           → revision → publish torrent.status_changed{from,to,reason,by_user_id} → COMMIT
  tracker-bridge（订阅）：按状态映射写 trk:t:<hash>.st（approved → open）
  search（订阅）：更新可见性 / 删除
```

### 5.4 删除与 tracker 墓碑

```
DELETE /v1/torrents/{id} {reason: "trumped", replaced_by: 5502}
  hooks.run(torrent.before_delete) → UPDATE status=deleted, prev_status, deleted_* → revision
  → publish torrent.deleted{reason, replaced_by?} → COMMIT → ctx.search.remove（尽力）
  tracker-bridge：trk:t:<hash> 写墓碑 st=deleted, rsn="trumped"（TTL 可配）→ 客户端看到 “torrent deleted: trumped”
```

## 6. 设计决策

| 编号 | 问题 | 备选方案 | 结论 | 理由 |
|---|---|---|---|---|
| DD-TOR-1 | hybrid 种子如何处理 | ① 拒绝（UNIT3D）② 去 v2 化（NexusPHP）③ 保留双 hash | 默认②，可配置①③ | 去 v2 化后 tracker 只有一个 hash，记账无重复风险，客户端兼容性最好；③留给需要 v2 的站点，tracker 侧 v2 截断 hash `acct=0`（design/10 §5.3） |
| DD-TOR-2 | 是否加入随机 entropy | 加（UNIT3D）/ 不加 | 不加 | source 已保证跨站不同 hash；不加才能用 hash 做站内去重，也便于辅种工具匹配 |
| DD-TOR-3 | 存储与生成下载文件 | ① 每次重新编码整个字典 ② 存 info 原始字节 + 根字典拼接 | ② | 保证 info 字节逐字节不变（hash 不变）；生成成本 O(文件大小) 的内存拷贝 |
| DD-TOR-4 | 对象存储键 | 按 torrent_id / 按内容哈希 | 内容哈希 `torrents/<hash>.torrent` | 上传在事务前 put，失败重试幂等；不可变数据可安全缓存；孤儿由 GC 清理 |
| DD-TOR-5 | “禁转”放在哪里 | 状态 / 标签 | 标签 `no_repost`；状态 `disabled` 表示“下架” | 禁转是转载许可，与能否下载无关；catalog 中 `TorrentStatus.disabled` 的注释“禁转/下架”应改为“下架”（§7） |
| DD-TOR-6 | 审核分工 | torrent 内置审核 / moderation 插件 | torrent 只有状态机与钩子；队列、审核员 UI、候选投票、自动通过规则在 moderation | 原则 1；未安装 moderation 时可设 `default_initial_status = approved` |
| DD-TOR-7 | 待审种子能否 announce | 拒绝（UNIT3D）/ 只允许发布者 | 只允许发布者（tracker `owner_only`），由 tracker-bridge 按设置映射 | 发布者可先做种，审核通过后立即有种源 |
| DD-TOR-8 | tracker 同步方向 | torrent 调 `ctx.tracker.sync_torrent` / tracker-bridge 订阅事件 | 订阅事件 | tracker-bridge 依赖 `ctx.torrents`，反向调用会成环；事件 + inbox 天然可重放、可全量重建 |
| DD-TOR-9 | tracker-bridge 如何批量读取 hash 与真实发布者 | 服务分页 / 只读视图 | 新增敏感视图 `v_torrent_tracker`（只授予 tracker-bridge） | 全量重建与一致性校验要扫 100 万行，视图键集分页最高效；含匿名种子的真实发布者，故标为需授权 |
| DD-TOR-10 | 文件列表存储 | 行表 / 压缩块 | 每个文件版本一行 zstd 压缩 JSON | 100 万种子 × 平均 20 文件，行表 2000 万行且只按种子整体读取；压缩块读一次即可 |
| DD-TOR-11 | 自动化下载凭据 | URL 带 passkey（NexusPHP）/ 签名链接 | 签名链接（HMAC，含 tid、uid、exp、file_version） | passkey 不出现在 URL；链接可短期、可失效（检查用户当前状态） |
| DD-TOR-12 | 替换文件 | 只允许新种子取代 / 同种子文件版本 | 两者都支持 | 待审期修正错误不应丢失评论与审核记录；发布后的质量升级仍用“取代”保留两条记录 |
| DD-TOR-13 | Group 并发创建 | 应用锁 / 唯一约束 + upsert | `INSERT … ON CONFLICT (type_id, group_key) WHERE … DO UPDATE SET updated_at = groups.updated_at RETURNING id` | 无锁、单语句 |
