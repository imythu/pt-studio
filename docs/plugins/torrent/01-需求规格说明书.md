## 1. 引言

### 1.1 目的

定义 `torrent` 插件（Native，提供 `ctx.torrents`）的功能与非功能需求。torrent 是站点中“种子”这一实体的唯一拥有者：解析与规范化 .torrent 文件、计算 info_hash 与去重、保存文件列表与对象存储中的种子文件、维护 Group 关联、维护审核状态机、在下载时注入用户的 tracker passkey，并向搜索贡献公共字段。

### 1.2 范围

**包含**

- .torrent 解析：BEP 3（v1）、BEP 52（v2）、hybrid（v1+v2），BEP 47 填充文件识别；有界解析与严格校验。
- 规范化：强制 `private=1`、写入站点 `source`、去掉无关键、重写 announce；info_hash（v1 SHA-1、v2 SHA-256 及其 20 字节截断）计算与去重。
- 文件列表的存储与分页读取；种子文件存入对象存储。
- Group 关联：调用 `ctx.content_types` 规范化字段、计算分组键与规范标题；Group 的创建、编辑、合并、删除。
- 审核状态机：`candidate` / `pending` / `approved` / `rejected` / `disabled` / `deleted` 的合法迁移、钩子与事件；与 moderation 插件的分工。
- 标签（官方 / 原创 / 置顶 / 禁转及自定义）、分类、制作组。
- 下载：单个下载、限时签名下载链接、批量下载；`torrent.before_download` 钩子；注入 passkey。
- 匿名发布；种子编辑与修订历史；种子文件替换（文件版本）；软删除、恢复与清除。
- 搜索文档贡献（`torrents`、`groups` 两个索引的公共字段）。
- HTTP API、MCP 工具（`get_torrent`、`get_download_link`）、前端页面与插槽。

**不包含**

| 不包含 | 归属 |
|---|---|
| 向 pt-tracker 同步种子白名单 | tracker-bridge（订阅本插件事件，读取本插件提供的视图） |
| 审核队列、审核员界面、候选区投票、审核规则 | moderation |
| 类型字段 schema、分组规则、标题规范、元数据抓取 | `type-*`、`metadata-*` |
| 促销、倍率 | promotion、accounting |
| 做种数 / 下载数 / 完成数 | accounting（`traffic.swarm_stats_updated`），search 部分更新 |
| 搜索查询与可见性过滤执行 | search-meilisearch（本插件只贡献文档字段） |
| 分享率 / H&R / 新手考核对下载的限制 | 各规则插件作为 `torrent.before_download` 的处理者 |
| 评论、字幕、举报、求种应求 | comments、subtitles、reports、requests |
| MediaInfo 解析 | mediainfo（本插件只保存原文） |
| 种子“做种者连通性检测”、UDP | 不做（D15） |

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| v1 / v2 / hybrid | BEP 3 种子、BEP 52 种子、同时包含 v1 与 v2 信息的混合种子 |
| info dict | .torrent 根字典中的 `info` 字典，其 bencode 字节的哈希即 info_hash |
| info_hash_v1 | `SHA-1(bencode(info))`，20 字节 |
| info_hash_v2 | `SHA-256(bencode(info))`，32 字节；tracker 协议中使用其前 20 字节（截断哈希） |
| 规范化种子 | 经本插件改写（private、source、删除无关键、去掉 announce）后的种子，存于对象存储 |
| 文件版本 | 同一个种子替换 .torrent 文件后的序号，从 1 开始 |
| passkey | tracker passkey（32 位小写十六进制），见 conventions/security.md §4 |
| Group | 作品，由资源类型插件定义其字段与分组键（design/05） |
| 禁转 | 标签 `no_repost`（不得转载到其他站点），**不是**状态；“下架”对应状态 `disabled` |

### 1.4 参考资料

- docs/design/01、03、04、05、08、10；docs/platform 全部契约。
- BEP 3（The BitTorrent Protocol Specification）、BEP 27（Private Torrents）、BEP 47（Padding files and extended file attributes）、BEP 52（The BitTorrent Protocol Specification v2）、BEP 12（Multitracker Metadata Extension，announce-list）。
- 开源 PT 程序（只读克隆于 `.spike/refs/`，仅阅读思路，未复制代码）：
  - NexusPHP（`public/takeupload.php`、`public/download.php`）：上传时清理根字段、设置 private 与 `source = "[站点URL] 站点名"`、把 hybrid 种子“去 v2 化”（unhybridize）；下载时把 `?passkey=` 拼进 announce；可选用 passkey 参数直接下载（供 IYUU 等工具）。
  - UNIT3D（`app/Helpers/TorrentTools.php`、`StoreTorrentRequest.php`）：根字典与 info 字典按白名单保留键；写入 `source`、`private=1`，并加入随机 `entropy` 使每次上传 info_hash 唯一；**拒绝 v2/hybrid**；审核状态 Pending / Approved / Rejected / Postponed，tracker 对非 Approved 拒绝 announce。
  - Gazelle（OPS/RED）：音乐 Group → Edition → Torrent 层级；source 标记（`OPS`/`RED`）防止跨站重复；“Trump”替换与删除原因记录；日志评分。
  - Ocelot（Gazelle 的 tracker）：删除种子时记录原因码，客户端 announce 时返回“Unregistered torrent: <原因>”，原因保留一段时间。
  - UNIT3D-Announce：种子删除后 announce 返回“Torrent has been deleted”，并记录用户对未注册 info_hash 的访问。
  - Luminance、Arcadia、TorrentPier：Arcadia 的“内容无关”目标与本项目相同；TorrentPier 论坛帖 = 种子。

## 2. 总体描述

### 2.1 插件定位

| 项 | 内容 |
|---|---|
| 类型 | Native（热路径之一：下载 .torrent 与批量下载；需要高效 bencode 处理与对象存储缓存） |
| 提供 | `ctx.torrents@0.1.0`；只读视图 `torrent.v_torrent_public`、`torrent.v_group_public`、`torrent.v_torrent_tracker`（新增，见概要设计 §7） |
| 依赖（requires） | `ctx.users`（取 passkey、用户状态）、`ctx.rbac`、`ctx.content_types`（内核聚合）、`ctx.terms` |
| 可选依赖 | `ctx.promotions`（下载钩子输入中的促销）、`ctx.search`（删除时高优先级移除） |
| 钩子点（拥有者） | `torrent.before_upload`、`torrent.before_update`、`torrent.before_status_change`、`torrent.before_delete`、`torrent.before_download` |
| 发布事件 | `torrent.created/updated/status_changed/tags_changed/deleted/downloaded`、`group.created/updated/merged/deleted` |

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户（user） | 浏览种子与 Group、下载 .torrent、批量下载、获取限时下载链接（RSS 客户端、AI 客户端） |
| 发布者（user / uploader） | 上传种子（可匿名）、编辑自己的种子、在待审期间替换文件、重新提交被拒绝的种子 |
| 审核员（moderator） | 修改任意种子、设置状态（经 moderation 或直接）、设置标签、编辑与合并 Group、删除与恢复 |
| 管理员（admin） | 查看匿名发布者、配置分类 / 制作组 / 标签 / 上传策略 |
| 其他插件 | moderation 改状态；requests 关联应求；search 拉取文档；tracker-bridge 读取 info_hash；rss / crossseed-api 生成下载链接；ai-upload-review 读取详情 |

### 2.3 现有开源 PT 程序的做法调研

| 主题 | 做法 | 优点 | 缺点 | 我们采纳 / 改进 |
|---|---|---|---|---|
| 强制 private 与 source | NexusPHP、UNIT3D、Gazelle 都在上传时改写 info 字典：`private=1`、`source=站点标记`，上传者必须重新下载 | 防止 DHT/PEX 泄漏；source 让同一内容在不同站点有不同 info_hash，客户端不会混用 tracker | 上传者常忘记重新下载导致“未注册种子” | **采纳**；上传成功响应中明确提示重新下载，并直接给出下载按钮；tracker 对上传者旧 hash 不做特殊兼容 |
| info 字典白名单 | UNIT3D 只保留 `files/length/name/piece length/pieces`；NexusPHP 清理根字段 | 去掉 `x_cross_seed`、自定义键、制作工具标记，减少指纹与体积 | UNIT3D 白名单丢掉了 v2 键，因此只能拒绝 v2 | **采纳并扩展**：白名单含 BEP 52 键（`meta version`、`file tree`）与 BEP 47 文件属性 |
| 随机 entropy | UNIT3D 在 info 中加入 64 字节随机 `entropy` | 每次上传 hash 唯一，杜绝“同 hash 跨站” | **重复上传同一种子无法用 hash 发现**；辅种工具无法匹配 | **不采纳**：source 已保证跨站唯一；规范化后的 hash 用于站内去重 |
| v2 / hybrid | UNIT3D 直接拒绝；NexusPHP 把 hybrid 去 v2 化为纯 v1 | 简单，避免一个种子两个 hash 的记账问题 | 拒绝会挡住新版客户端制作的种子；去 v2 化丢失 v2 能力 | **采纳 NexusPHP 的默认去 v2 化**（`hybrid_policy = "strip_v2"`），同时支持 `keep_hybrid`（tracker 侧 v2 截断 hash 只参与 swarm 不计账，design/10 §5.3）；纯 v2 默认拒绝，可配置接受 |
| announce 注入 | NexusPHP 在 download.php 中把 `?passkey=` 拼到 announce；可用 URL 中的 passkey 直接下载 | 实现简单，支持自动化工具 | passkey 出现在下载 URL、浏览器历史、代理日志中 | **改进**：passkey 只出现在 .torrent 内容里；网页下载走会话；自动化工具使用短期签名链接（不含 passkey）；announce 路径式 `/announce/<passkey>`（design/10） |
| 删除原因回显 | Ocelot：删除时带原因码，announce 返回“Unregistered torrent: <原因>” | 用户知道为什么种子失效（被替换 / 重复 / 违规） | 原因只在 tracker 内存中，重启丢失 | **采纳**：本插件保存删除原因码与替换关系；tracker-bridge 把原因写进 tracker 墓碑键（保留期可配） |
| 审核状态 | UNIT3D：Pending/Approved/Rejected/Postponed，非 Approved 不能 announce；NexusPHP：候选区 + 管理员审核 | 状态清晰；tracker 侧强制 | 发布者在待审期间无法做种验证；UNIT3D 把审核写死在核心 | **改进**：状态机在 torrent，审核策略在 moderation 插件；待审 / 候选期间只允许发布者本人 announce（tracker `owner_only`，由 tracker-bridge 映射） |
| Group | Gazelle 以音乐 Group/Edition 为核心；UNIT3D 按 TMDB ID 隐式分组；NexusPHP 无分组 | Gazelle 浏览体验好 | 模型绑定内容类型 | **改进**：Group 字段与分组键由资源类型插件定义（`ctx.content_types.group_key`），torrent 只存 `(type_id, group_key)` 与 JSON 字段 |
| 编辑历史 | Gazelle 有编辑日志；NexusPHP 几乎没有 | 便于追责 | — | **采纳**：修订表记录每次编辑前后值与原因 |
| 替换文件 | Gazelle 用“trump”上传新种子删除旧种子；UNIT3D 不允许替换文件 | trump 语义清楚 | 下载记录、评论分散到两个种子 | **两种都支持**：同一种子的文件版本（待审期内发布者可替换，之后需审核员）；跨种子“取代”用删除原因 `trumped` + `replaced_by` |
| SQL 与 XSS | NexusPHP 的 SQL 拼接与输出未转义（design/08） | — | 19 个 CVE | 全部参数化；简介服务端转受限 HTML；文件名不进入 HTML 属性 |

### 2.4 约束与假设

1. 平台约束：跨插件只经服务 / 事件 / 钩子 / 视图；钩子处理者独立提交；钩子中不能出站 HTTP；每次调用一个事务；Native 插件可以使用进程内缓存，但缓存内容必须是不可变或可容忍短暂过期的。
2. tracker 侧只认 info_hash（v1 或截断 v2）；hash 到 torrent_id 的映射由 tracker-bridge 写入 Redis，torrent 不直接访问 `trk:*`。
3. passkey 由 identity 生成与保存；本插件通过 `ctx.users.get_sensitive(user_id, "passkey")` 读取，需要站点授权 `user.passkey`。
4. 规模假设：100 万种子、30 万用户、每日新增 2000 种子、每日下载 .torrent 50 万次（峰值 50 次/秒，批量下载另计）。
5. 对象存储为 S3 兼容（MinIO）。
6. 资源类型插件至少启用一个（通常 `type-generic`）。

## 3. 功能需求

### 3.1 解析与规范化

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-001 | 有界 bencode 解析 | 解析 .torrent，限制：文件 ≤ `max_torrent_kb`（默认 10240）、嵌套深度 ≤ 64、整数 ≤ 2^63−1 且无前导零、字典键严格递增、字符串长度不超过剩余字节；末尾不得有多余字节 | P0 | 畸形、超大、深嵌套、重复键样本均返回 `torrent.invalid_file`，不 panic、不超 100 ms |
| FR-TOR-002 | v1 校验 | `info` 含 `name`、`piece length`（2 的幂，16 KiB～64 MiB）、`pieces`（长度为 20 的倍数且等于 `20 × ceil(总大小 / piece length)`）、`length` 与 `files` 二选一；文件数 ≤ `max_files`（默认 100000） | P0 | 各类违规样本被拒，错误 `details.reason` 指明原因 |
| FR-TOR-003 | v2 / hybrid 识别与校验 | `meta version = 2` 时校验 `file tree`、`piece layers`（大于 piece length 的文件必须有对应层）；hybrid 额外校验 v1 文件列表与 v2 文件树一致（忽略 BEP 47 填充文件） | P0 | BEP 52 官方测试种子（v2、hybrid）通过；篡改样本被拒 |
| FR-TOR-004 | 混合种子策略 | 配置 `hybrid_policy`：`strip_v2`（默认，删除 `meta version`、`file tree`、根 `piece layers`，保留 v1 部分含填充文件）、`keep_hybrid`、`reject`；`v2_only_policy`：`reject`（默认）、`accept` | P0 | 三种策略下行为与 hash 结果符合预期 |
| FR-TOR-005 | 路径安全 | 拒绝路径分量为空、`.`、`..`、含 `/`、`\`、NUL 或控制字符、超过 255 字节、总路径超过 4096 字节；名称必须是合法 UTF-8（或存在 `name.utf-8` / `path.utf-8` 时取之）；NFC 规范化后在同一目录下不得重名 | P0 | 路径穿越样本被拒，返回 `torrent.invalid_path` |
| FR-TOR-006 | 强制 private 与 source | 规范化时设置 `info.private = 1`、`info.source = <source_tag>`；`reject_non_private = true` 时原始种子未设置 private 则拒绝（`torrent.not_private`） | P0 | 下载得到的种子 info 中 private=1、source 为站点值 |
| FR-TOR-007 | 键白名单 | 根字典只保留 `info`、`piece layers`（hybrid/v2）；`comment`、`created by`、`creation date` 由站点重写；info 只保留 BEP 3/27/47/52 定义的键与 `source`；文件条目只保留 `length`、`path`、`attr`、`symlink path`、`sha1` | P0 | 带 `x_cross_seed`、`unique`、`entropy` 等键的种子，规范化后不含这些键 |
| FR-TOR-008 | info_hash 计算 | 对规范化后的 info 字典按规范 bencode 编码计算 v1 SHA-1、v2 SHA-256；v2 另存截断 20 字节 | P0 | 与 libtorrent 计算结果一致（测试向量） |
| FR-TOR-009 | 去重 | 同一 info_hash（v1 或 v2）在未删除种子中唯一；冲突返回 `torrent.duplicate` 并在调用者可见时给出已存在种子 ID；另计算内容指纹 `content_fp = SHA-1(pieces)`，命中时不阻止，但写入钩子输入 `similar_torrent_ids` 供审核 | P0 | 并发上传同一种子只有一个成功 |
| FR-TOR-010 | 文件列表 | 保存完整文件列表（路径、大小、是否填充文件），分页读取；体积与文件数不计填充文件 | P0 | 10 万文件种子可分页读取，每页 ≤ 500 |

### 3.2 上传、Group 与类型字段

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-011 | 上传 | multipart 上传 .torrent + 元数据（type_id、fields、title 可选、subtitle、description、mediainfo、nfo 文件、category、release_group、anonymous、group_id 可选），需 `torrent.upload`，支持 `Idempotency-Key` | P0 | 成功返回 201 + 种子 ID、状态与“请重新下载”提示 |
| FR-TOR-012 | 类型字段规范化 | 调用 `ctx.content_types.normalize(type_id, fields)` 校验并规范化；未知 type_id → `torrent.type_unknown` | P0 | 类型插件返回的错误码透传（422） |
| FR-TOR-013 | 规范标题 | 未提交 title 时使用 `canonical_title`；提交了则按站点设置 `title_mode`（`canonical_only` / `allow_custom`）处理 | P1 | 两种模式均可验证 |
| FR-TOR-014 | Group 关联 | `group_key` 非空时按 `(type_id, group_key)` 查找或创建 Group（并发安全）；上传者显式指定 group_id 时校验类型一致；类型不分组时 group_id 为空 | P0 | 并发上传同一作品只产生一个 Group |
| FR-TOR-015 | `torrent.before_upload` 钩子 | 解析完成后、落库前触发；处理者可拒绝，或修改 `title`、`fields`、`initial_status`、`tags[]` | P0 | deny 时无任何数据写入，对象存储无残留（或由 GC 清理） |
| FR-TOR-016 | 初始状态 | 默认取设置 `default_initial_status`（默认 `pending`），钩子可改为 `candidate`/`pending`/`approved` | P0 | 未安装 moderation 时可设置为 `approved` |
| FR-TOR-017 | 存储 | 规范化种子（不含 announce）按内容寻址存入对象存储 `torrents/<v1或v2 hex>.torrent`；NFO 存 `nfo/<torrent_id>.nfo` | P0 | 对象存储中的文件与下载文件除 announce 等根字段外逐字节一致 |
| FR-TOR-018 | Group 管理 | 查看、编辑（按类型插件 `group_schema` 校验）、合并（种子全部移入目标 Group，来源 Group 标记为已合并）、删除空 Group；需 `torrent.groups.manage` | P1 | 合并后两边事件正确，旧 Group 详情 301 指向新 Group |
| FR-TOR-019 | 内容类型列表 | 提供 HTTP 接口列出已启用资源类型及字段 schema（WASM 插件和前端经此读取） | P0 | 与 `ctx.content_types.list()` 一致 |
| FR-TOR-020 | 分类与制作组 | 管理员维护分类（按类型）与制作组；上传时可选；名称用术语键 `torrent.category.<key>`、`torrent.release_group.<key>` | P1 | 停用的分类不能再被选择 |

### 3.3 审核状态与标签

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-021 | 状态机 | 合法迁移见 LLD §1.5；非法迁移返回 `torrent.invalid_status_transition` | P0 | 状态迁移表全覆盖测试 |
| FR-TOR-022 | `torrent.before_status_change` | 每次状态变更前触发，可拒绝 | P0 | 处理者拒绝时状态不变 |
| FR-TOR-023 | 状态服务 | `ctx.torrents.set_status(id, status, reason)` 需作用域 `write:status`（moderation 使用）；HTTP 侧需 `torrent.update` | P0 | 无作用域调用返回 `kernel.capability_denied` |
| FR-TOR-024 | 发布者重新提交 | `rejected` 的种子在发布者编辑后可重新提交为 `pending` | P1 | 只有发布者本人或有 `torrent.update` 的用户可操作 |
| FR-TOR-025 | 状态可见性 | `approved`、`disabled` 对所有有权用户可见（`disabled` 不可下载）；`candidate`、`pending`、`rejected` 只对发布者与有 `moderation.queue.read` 或 `torrent.update` 的用户可见；`deleted` 只对有 `torrent.delete` 的用户可见 | P0 | 无权用户 GET 返回 404 |
| FR-TOR-026 | 标签 | 设置 / 取消标签（`torrent.tags.manage`，或服务作用域 `write:tags`）；标签定义可由管理员增加；发布 `torrent.tags_changed` | P1 | `no_repost` 等内置标签不可删除 |

### 3.4 下载

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-027 | 单个下载 | `GET …/torrents/{id}/download`，需登录与 `torrent.download`；检查可见性与可下载状态（`approved`；发布者本人可下载自己的 `candidate`/`pending`） | P0 | 返回 `application/x-bittorrent`，`Cache-Control: private, no-store` |
| FR-TOR-028 | 下载钩子 | 生成文件前触发 `torrent.before_download`（输入含促销状态）；拒绝时返回处理者错误码 | P0 | ratio-policy 等拒绝时返回 403 与对应错误码 |
| FR-TOR-029 | 注入 passkey | 生成文件时 announce 为 `<announce_base_url>/<passkey>`；可选 `announce-list`（多个 tracker 域名，同一层级）；info 字典字节不变 | P0 | 下载文件的 info_hash 与库中一致；文件中 passkey 为当前用户的 |
| FR-TOR-030 | 用户状态检查 | `banned` / `pending` 用户不能下载；`leech_disabled` 用户只能下载自己发布的种子（可配置） | P0 | 对应错误码 `identity.account_banned`、`identity.download_disabled` |
| FR-TOR-031 | 限时下载链接 | 生成不含 passkey 的签名链接（默认 TTL 600 秒，最大 86400），链接访问时重新执行全部检查与钩子；用于 MCP、RSS、辅种工具 | P0 | 过期、篡改、用户被封禁后链接均失效 |
| FR-TOR-032 | 批量下载 | 一次最多 `batch_max`（默认 50）个种子，打包为 zip；每个种子独立检查与触发钩子；未通过的在 `manifest.json` 中列出原因 | P1 | 混合可下载 / 不可下载的批量请求返回部分结果 |
| FR-TOR-033 | 下载事件 | 每次成功下载发布 `torrent.downloaded`；本插件记录用户下载历史（首次、最近、次数） | P0 | 同一用户重复下载只更新计数 |
| FR-TOR-034 | passkey 不可用 | identity 返回无 passkey 时（未生成）调用 `reset_passkey` 生成一次后重试，仍失败返回 `torrent.passkey_unavailable` | P1 | — |

### 3.5 匿名、编辑、版本、删除

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-035 | 匿名发布 | `anonymous = true`（受设置 `allow_anonymous` 控制）；对无 `torrent.anonymous.reveal` 的调用者，API、服务、视图、搜索文档、MCP 中都不出现发布者；事件中保留 `uploader_id` 与 `anonymous` | P0 | 普通用户在所有出口都看不到发布者；查看匿名发布者写审计 |
| FR-TOR-036 | 编辑元数据 | 发布者在 `edit_window_hours` 内（默认不限）或有 `torrent.update` 的用户可编辑标题、副标题、简介、MediaInfo、fields、分类、制作组、匿名；触发 `torrent.before_update`；乐观锁（`If-Match`） | P0 | 并发编辑一方得到 412 `kernel.conflict` |
| FR-TOR-037 | 修订历史 | 每次编辑、状态变更、标签变更、文件替换、Group 变更写修订记录（变更前后值、原因、操作者）；可查看 | P1 | 修订记录完整、只追加 |
| FR-TOR-038 | 替换种子文件 | 发布者在 `candidate`/`pending`/`rejected` 状态下，或 `torrent.update` 用户任意状态下，可上传新 .torrent；文件版本 +1，旧 hash 失效并在 tracker 显示“已替换” | P1 | 替换后旧 hash 不在 `v_torrent_tracker` 有效集合中，新 hash 去重仍生效 |
| FR-TOR-039 | 删除 | 软删除（HTTP 需 `torrent.delete`，发布者本人在 `candidate`/`pending`/`rejected` 状态下可删除自己的种子；服务 `delete` 方法需作用域 `write:status`），记录原因码（`dupe`、`trumped`、`rules`、`copyright`、`uploader_request`、`other`）与可选 `replaced_by`；触发 `torrent.before_delete`；发布 `torrent.deleted` | P0 | 删除后搜索、列表、下载均不可见 |
| FR-TOR-040 | 恢复 | 有 `torrent.delete` 的用户可恢复到删除前状态；hash 已被其他种子占用时返回 `torrent.restore_conflict` | P1 | 恢复后 tracker 重新放行 |
| FR-TOR-041 | 清除 | 删除超过 `purge_after_days`（默认 0 = 不清除）的种子，由定时任务删除对象存储文件与文件列表，行保留（状态仍为 deleted，不能再恢复） | P2 | 定时任务重复执行无副作用 |
| FR-TOR-042 | 用户清除 | 订阅 `user.deleted{mode: purge}`：该用户发布的种子 `uploader_id` 置空并标记 `uploader_purged`；下载历史删除 | P1 | 重复投递结果相同 |

### 3.6 查询、搜索、MCP

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TOR-043 | 服务读取 | `get`、`get_many`（≤ 500）、`by_info_hash`（v1、v2 或截断 v2）、`list_by_uploader`、`get_group`、`get_detail` | P0 | 匿名规则对服务调用同样生效（按调用者 actor 判断） |
| FR-TOR-044 | 列表 API | 按 uploader、group、status、type、category、tag、时间过滤，游标分页（全文搜索走 ctx.search） | P1 | — |
| FR-TOR-045 | 搜索贡献 | 实现 `search-contributor`：`torrents`、`groups` 两个索引的公共字段；匿名种子不输出发布者 | P0 | 文档字段与 LLD §3.3 一致 |
| FR-TOR-046 | 删除优先 | 删除、下架、拒绝时若启用了 `ctx.search`，同步调用 `ctx.search.remove` 高优先级移除（失败不影响删除，靠事件兜底） | P1 | 删除后 2 秒内搜不到 |
| FR-TOR-047 | MCP `get_torrent` | 返回种子与 Group 详情（不含 passkey、发布者对匿名种子隐藏），用户生成内容放在独立字段并注明 | P1 | 输出通过 schema 与敏感字段检查 |
| FR-TOR-048 | MCP `get_download_link` | 返回限时签名链接 | P1 | 链接不含 passkey |
| FR-TOR-049 | 视图 | 提供 `v_torrent_public`、`v_group_public`（catalog 已登记）与 `v_torrent_tracker`（新增，供 tracker-bridge） | P0 | 视图列与 LLD 一致 |

|---|---|---|---|

## 6. 外部接口需求概述

- **用户界面**：浏览（经搜索）、种子详情、Group 详情、上传（类型表单由 schema 生成）、编辑、修订历史、我的发布、后台（分类、制作组、标签、上传策略）。
- **HTTP API**：`/api/p/torrent/v1/…`，详见 LLD §2.4。
- **服务**：`ctx.torrents`（LLD §2.1）。
- **MCP**：`get_torrent`、`get_download_link`。
- **事件**：发布 10 种（HLD §3.3）；订阅 `user.deleted`、`kernel.settings_changed`（HLD §3.4）。
- **钩子**：拥有 5 个钩子点（HLD §3.5）。
- **视图**：`v_torrent_public`、`v_group_public`、`v_torrent_tracker`。
