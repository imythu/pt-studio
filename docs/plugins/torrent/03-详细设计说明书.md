## 1. 模块详细设计

### 1.1 `bencode`

**数据结构**（借用输入缓冲区，零拷贝）：

```rust
pub enum BValue<'a> {
    Int(i64),
    Bytes(&'a [u8]),
    List(Vec<BValue<'a>>),
    /// 键按出现顺序；raw 为整个字典（含 d…e）的原始字节
    Dict { entries: Vec<(&'a [u8], BValue<'a>)>, raw: &'a [u8] },
}
pub struct Limits { pub max_depth: u32 /*64*/, pub max_items: u32 /*2_000_000*/, pub max_bytes: usize }
pub fn decode<'a>(buf: &'a [u8], lim: &Limits) -> Result<BValue<'a>, BError>;
pub fn encode(v: &BValue, out: &mut Vec<u8>);          // 规范编码：字典键按字节序
pub fn splice_root(root_raw: &[u8], set: &[(&[u8], Vec<u8>)], remove: &[&[u8]]) -> Result<Vec<u8>, BError>;
```

**解码规则**（任一违反 → `BError`，映射为 `torrent.invalid_file`，`details.reason` 为下列代号）：

| 代号 | 规则 |
|---|---|
| `depth` | 嵌套深度 > 64 |
| `items` | 元素总数 > 2,000,000 |
| `int_format` | `i-0e`、前导零、空整数、超出 i64 |
| `str_len` | 长度前缀有前导零或超过剩余字节 |
| `dict_order` | 键未严格递增（含重复键）。**说明**：BEP 3 要求键排序；不排序的种子在不同实现中 hash 不一致，直接拒绝 |
| `trailing` | 根值之后还有字节 |
| `root_type` | 根不是字典 |

迭代实现（显式栈），不递归，避免栈溢出。

**`splice_root`**：解析根字典的顶层条目（只取每个值的原始字节切片，不展开），用 `set` 覆盖或插入、`remove` 删除，按键字节序输出 `d` + `<len>:<key><raw value>`… + `e`。`info` 的原始字节原样拷贝，因此 hash 不变。

### 1.2 `parser`

输入：`BValue` 根。输出：

```rust
pub struct Parsed<'a> {
    pub meta: MetaVersion,                 // V1 | V2 | Hybrid
    pub info: &'a BValue<'a>,
    pub name: String,                      // NFC
    pub piece_length: u64,
    pub files: Vec<FileEntry>,             // v1 视角（hybrid/v1）或 v2 file tree 展开（纯 v2）
    pub total_size: u64,                   // 不含填充文件
    pub pieces_sha1: Option<[u8; 20]>,     // SHA-1(pieces)，内容指纹
    pub was_private: bool,
    pub piece_layers: Option<&'a BValue<'a>>,
}
pub struct FileEntry { pub path: Vec<String>, pub size: u64, pub padding: bool, pub attr: Option<String> }
```

算法（伪代码）：

```
fn parse(root):
    info = root["info"] as Dict ?: invalid("no_info")
    mv = info.get("meta version")
    has_v1 = info has "pieces"; has_v2 = mv == 2
    meta = match (has_v1, has_v2): (t,f)→V1, (f,t)→V2, (t,t)→Hybrid, _→invalid("no_pieces")
    name = utf8_field(info, "name.utf-8") or utf8_field(info, "name") ?: invalid("name_encoding")
    check_component(name)
    pl = info["piece length"] as int; require pl 是 2 的幂 且 16384 ≤ pl ≤ 67108864  ?: invalid("piece_length")
    if has_v1:
        files_v1 = if "length" in info: [single(name, length)]
                   elif "files" in info: for f in info.files:
                        path = f["path.utf-8"] or f["path"]; 每段 check_component；require len(path) ≥ 1
                        padding = f.attr 包含 'p'
                        size = f.length ≥ 0
                   else invalid("no_files")
        require 'length' 与 'files' 不同时存在 ?: invalid("length_and_files")
        total_v1 = Σ size（含填充）
        require len(pieces) == 20 × ceil(total_v1 / pl) ?: invalid("pieces_len")
    if has_v2:
        tree = info["file tree"] as Dict ?: invalid("no_file_tree")
        files_v2 = walk(tree)：叶子为键 "" 的字典 {length, pieces root?}；深度受全局限制
        for f in files_v2 where f.length > pl: require root["piece layers"][f.pieces_root] 存在，
             且长度 == 32 × ceil(f.length / pl) ?: invalid("piece_layers")
    if Hybrid: require 非填充的 files_v1 与 files_v2 按顺序路径、大小一致 ?: invalid("hybrid_mismatch")
    files = files_v1 if has_v1 else files_v2
    require count(files) ≤ max_files ?: torrent.too_many_files
    require 同一目录下 NFC 后无重名、文件与目录不同名 ?: invalid_path("duplicate_path")
    require 总路径（"/" 连接）≤ 4096 字节 ?: invalid_path("path_too_long")
    return Parsed{…, total_size = Σ 非填充 size, pieces_sha1 = has_v1 ? sha1(pieces) : None,
                  was_private = info.private == 1}

fn check_component(s):  // → torrent.invalid_path
    s 非空；s ∉ {".", ".."}；不含 '/', '\\', NUL, U+0000–U+001F, U+007F；≤ 255 字节；
    不以空格结尾；Windows 保留名（CON、PRN、AUX、NUL、COM1–9、LPT1–9，忽略大小写与扩展名）拒绝
```

### 1.3 `normalizer`

```
fn normalize(parsed, root, settings) -> Normalized:
    match (parsed.meta, settings.hybrid_policy, settings.v2_only_policy):
        (Hybrid, reject, _)    → torrent.hybrid_not_supported
        (V2, _, reject)        → torrent.v2_not_supported
        (Hybrid, strip_v2, _)  → target = V1
        其他                    → target = parsed.meta
    if settings.reject_non_private && !parsed.was_private → torrent.not_private
    info' = 新字典，按白名单从原 info 拷贝：
        V1 相关：name、name.utf-8、piece length、pieces、length、files（逐条只保留 length、path、path.utf-8、attr、symlink path、sha1）、md5sum
        V2 相关（target ∈ {V2, Hybrid}）：meta version、file tree
    info'.private = 1；info'.source = settings.source_tag（UTF-8，≤ 128 字节）
    info_raw = encode(info')                      // 规范编码
    ih_v1 = target 含 v1 ? sha1(info_raw) : None
    ih_v2 = target 含 v2 ? sha256(info_raw) : None
    root' = { "info": info_raw,
              "piece layers": target 含 v2 ? 原值 : 删除 }
    // announce / announce-list / comment / created by / creation date 在下载时拼接，不存储
    stored = encode(root')
    require len(stored) ≤ max_torrent_kb × 1024 × 1.1
    return Normalized{ stored, ih_v1, ih_v2, meta: target, info_raw_len }
```

> 去 v2 化后 info 字节变化，hash 与上传者手中的原文件不同——与强制 private/source 一样，上传者必须重新下载（FR-TOR-011 响应中提示）。

### 1.4 `upload`

```
fn upload(ctx, req: UploadRequest, file: Bytes, nfo: Option<Bytes>) -> Result<UploadResult>:
    settings = ctx.settings()
    require file.len() ≤ settings.max_torrent_kb×1024           ?: torrent.too_large
    require magic: file[0] == b'd'                               ?: torrent.invalid_file
    root = bencode::decode(&file, limits)?; parsed = parser::parse(&root)?
    norm = normalizer::normalize(&parsed, &root, &settings)?
    ti = ctx.content_types.get(req.type_id) ?: torrent.type_unknown
    fields = ctx.content_types.normalize(req.type_id, req.fields)?      // 类型插件错误码透传
    gkey   = ctx.content_types.group_key(req.type_id, &fields)?
    title  = if settings.title_mode == canonical_only || req.title is None
                 { ctx.content_types.canonical_title(req.type_id, &fields)? } else { sanitize_title(req.title) }
    category / release_group 存在且启用、category.type_id == type_id  ?: kernel.validation_failed
    if req.group_id: g = store.group(req.group_id) ?: kernel.not_found; require g.type_id == type_id ?: torrent.group_type_mismatch
    if req.anonymous && !settings.allow_anonymous → kernel.validation_failed
    dup = store.find_live_by_hash(norm.ih_v1, norm.ih_v2)        // 预检查，减少无效 blob 写入
    if dup → torrent.duplicate {details.torrent_id: 可见时给出}
    similar = store.find_by_content_fp(parsed.pieces_sha1, limit 5)
    input = {version:1, actor, uploader_id, type_id, title, size, file_count, files_sample: 前 200,
             info_hash_v1, info_hash_v2, fields, anonymous, group_id, nfo_present, content_fp, similar_torrent_ids,
             meta_version, category_id, release_group_id}
    outcome = ctx.hooks.run("torrent.before_upload", input)?
    Denied(d) → 返回 d.code（403/422）
    Allowed(final) → title = final.title; fields = final.fields; tags = final.tags ?: []
                     status = final.initial_status ?: settings.default_initial_status
    key = "torrents/" + hex(ih_v1 or ih_v2) + ".torrent"
    blob.put(key, "application/x-bittorrent", norm.stored)?        // 幂等；失败 → kernel.service_unavailable
    nfo 存在：限制 ≤ 1 MiB、文本（拒绝含 NUL）→ 稍后以 torrent_id 为键写入（事务后，失败只告警）
    // —— 工作单元事务 ——
    gid = req.group_id or (gkey ? groups::find_or_create(type_id, gkey, fields, title) : None)
    id = INSERT torrents (...) RETURNING id
         唯一冲突（torrents_info_hash_v1_live_key / v2）→ ROLLBACK → torrent.duplicate
    INSERT torrent_file_versions (id, 1, ih_v1, ih_v2, key, size)
    INSERT torrent_files (id, 1, count, total, zstd(json(files)))
    INSERT torrent_tags (过滤为已定义的 tag)
    INSERT revisions (kind = 'create')
    UPDATE groups SET torrent_count = torrent_count + 1, last_upload_at = now() WHERE id = gid
    publish torrent.created；若新建 Group 则 publish group.created
    COMMIT
    nfo → blob.put("nfo/<id>.nfo")；UPDATE torrents SET has_nfo = true（独立小事务）
    metrics; return {id, status, need_redownload: true}
```

并发：同一种子两次并发上传，两者都可能通过预检查并各自 `blob.put` 同一键（内容相同，无害），数据库部分唯一索引保证只有一个插入成功。钩子处理者在失败一方的副作用（如 moderation 的预留）由处理者自行以 `torrent.created` 确认，见 hooks.md 规则。

### 1.5 `lifecycle`：状态机

| from \ to | candidate | pending | approved | rejected | disabled | deleted |
|---|---|---|---|---|---|---|
| candidate | — | ✔ | ✔ | ✔ | — | ✔ |
| pending | ✔ | — | ✔ | ✔ | — | ✔ |
| approved | — | ✔（撤回审核） | — | — | ✔ | ✔ |
| rejected | — | ✔（重新提交） | ✔ | — | — | ✔ |
| disabled | — | — | ✔ | — | — | ✔ |
| deleted | 仅 `restore`：回到 `prev_status` | | | | | — |

谁能触发：

| 迁移 | HTTP 权限 / 服务作用域 |
|---|---|
| `rejected → pending`（重新提交） | 发布者本人，或 `torrent.update` |
| 其他非删除迁移 | `torrent.update`，或服务作用域 `write:status`（moderation） |
| `* → deleted` | `torrent.delete`；发布者本人仅限 candidate / pending / rejected；服务 `delete` 需 `write:status` |
| `deleted → prev` | `torrent.delete`；服务 `restore` 需 `write:status` |

```
fn set_status(ctx, id, to, reason, by) -> Result<()>:
    t = SELECT … FROM torrents WHERE id = $1 FOR UPDATE ?: kernel.not_found
    if t.status == to: return Ok(())                         // 幂等
    require allowed(t.status, to)                           ?: torrent.invalid_status_transition
    hooks.run("torrent.before_status_change", {torrent_id, from, to, reason})  // deny → 返回
    UPDATE torrents SET status=$to, status_reason=$reason, status_changed_at=now(), status_changed_by=$by,
                        version=version+1, updated_at=now() WHERE id=$id
    INSERT revisions(kind='status', changes={from,to}, reason)
    publish torrent.status_changed {torrent_id, from, to, reason, by_user_id}
    if to ∈ {rejected, disabled} && ctx.search 可用: 提交后 ctx.search.remove("torrents", id)（尽力）
```

`FOR UPDATE` 行锁保证同一种子状态迁移串行。

### 1.6 编辑与文件替换

```
fn update(ctx, id, patch, if_match_version, editor):
    t = load FOR UPDATE；require t.version == if_match_version ?: kernel.conflict(412)
    require 权限：editor == t.uploader_id && has(torrent.update_own) && 在 edit_window 内 && t.status != deleted
             或 has(torrent.update)                                 ?: kernel.forbidden
    允许字段：title, subtitle, description, mediainfo, fields, category_id, release_group_id, anonymous, group_id
    fields 变化 → ctx.content_types.normalize；group_key 变化 → 重新 find_or_create（发布者不能改 group_id，审核员可以）
    hooks.run("torrent.before_update", {torrent_id, editor_id, changes}) → modify 只能改 changes
    UPDATE …；revisions(kind='edit', changes={field: {before, after}})；旧/新 Group 计数调整
    publish torrent.updated {torrent_id, fields[]}；Group 变化另发 group.updated（双方）

fn replace_file(ctx, id, file, reason, editor):
    权限：发布者且 status ∈ {candidate, pending, rejected}，或 torrent.update
    解析、规范化同上传；新 hash 去重（排除自身）
    hooks.run("torrent.before_update", {changes: {info_hash: {before, after}}})
    blob.put；事务：INSERT torrent_file_versions(file_version+1)；torrent_files；
         UPDATE torrents SET info_hash_v1/v2, size, file_count, file_version = file_version+1, blob_key, version+1
    publish torrent.updated {fields: ["info_hash","size","files"], file_version, old_info_hash_v1, old_info_hash_v2}
```

### 1.7 删除、恢复、清除

```
fn delete(ctx, id, reason_code, note, replaced_by, by):
    t = load FOR UPDATE；if t.status == deleted: return Ok    // 幂等
    reason_code ∈ settings.delete_reasons ?: kernel.validation_failed
    replaced_by 存在且未删除 ?: kernel.validation_failed
    hooks.run("torrent.before_delete", {torrent_id, reason})
    UPDATE torrents SET prev_status=status, status='deleted', deleted_at=now(), deleted_by=$by,
           delete_reason=$code, delete_note=$note, replaced_by=$rb, version+1
    groups.torrent_count -= 1；revisions(kind='delete')
    publish torrent.deleted {torrent_id, reason, reason_code, replaced_by?, by_user_id}
    提交后：ctx.search.remove("torrents", id)（尽力）

fn restore(ctx, id, reason, by):
    t = load FOR UPDATE；require t.status == deleted && t.purged_at IS NULL ?: torrent.not_restorable
    冲突检查：同 hash 是否存在未删除种子 → torrent.restore_conflict
    hooks.run("torrent.before_status_change", {from: deleted, to: prev_status, reason: "restore"})
    UPDATE status=prev_status, deleted_*=NULL；计数 +1；revisions(kind='restore')
    publish torrent.status_changed {from: "deleted", to: prev, reason: "restore"}
```

`purge_deleted`（cron，tx manual）：`SELECT id FROM torrents WHERE status='deleted' AND purged_at IS NULL AND deleted_at < now() - $days LIMIT 500` → 对每个：删除 `torrent_files`、`blob.delete(nfo)`；规范化种子文件由 `blob_gc` 在无引用后删除；`UPDATE purged_at = now()`；每批 commit。重复执行时已清除行不再被选中。

### 1.8 `groups`

```
fn find_or_create(type_id, gkey, fields, torrent_title) -> group_id:
    gfields = 按 type_info.group_schema 的顶层属性从 fields 中挑选
    title = content_types.canonical_group_title(type_id, fields)（若提供方实现）
            否则 gfields.title ?: torrent_title；year = gfields.year
    INSERT INTO groups (type_id, group_key, title, year, fields) VALUES (…)
    ON CONFLICT (type_id, group_key) WHERE deleted_at IS NULL AND merged_into IS NULL
    DO UPDATE SET updated_at = groups.updated_at          -- 不修改，仅为 RETURNING
    RETURNING id, (xmax = 0) AS inserted                  -- inserted → 发布 group.created

fn merge(from, into, by):
    require from != into，二者类型相同、均未删除      ?: torrent.group_type_mismatch / kernel.validation_failed
    锁两行（按 id 升序 FOR UPDATE，避免死锁）
    UPDATE torrents SET group_id = into, version+1 WHERE group_id = from   （分批 1000，单事务内；单 Group 种子数通常 < 1000）
    UPDATE groups SET merged_into = into, deleted_at = now() WHERE id = from
    重新计算 into 的计数
    publish group.merged {from_group_id, into_group_id}；对每个移动的种子 publish torrent.updated{fields:["group_id"]}
```

`update_group(id, patch)`：merge-patch 后整体按 `group_schema` 用 `jsonschema` 校验；`title`/`year` 同步到列；发布 `group.updated`。

### 1.9 `download`

**可见性与可下载判定**（`visibility` 模块，所有出口共用）：

```
fn can_view(actor, t): match t.status:
    approved | disabled → has(torrent.download) 或 actor 为插件/系统
    candidate | pending | rejected → actor.user_id == t.uploader_id || has(moderation.queue.read) || has(torrent.update)
    deleted → has(torrent.delete)
fn can_download(actor, t): t.status == approved
    || (t.status ∈ {candidate, pending} && actor.user_id == t.uploader_id)
fn reveal_uploader(actor, t): !t.is_anonymous || actor.user_id == t.uploader_id || has(torrent.anonymous.reveal)
```

`has()` 为 `ctx.rbac.check`，同一请求内结果缓存。

**单个下载**：

```
fn build(ctx, id, user_id, via) -> Result<(Vec<u8>, filename)>:
    t = store.get(id) ?: kernel.not_found；require can_view ?: kernel.not_found；require can_download ?: torrent.not_downloadable
    u = ctx.users.get(user_id)  (进程内缓存 5 s)
    match u.status: banned → identity.account_banned; pending → identity.account_pending; deleted → kernel.forbidden
                    leech_disabled → 除非 settings.leech_disabled_can_download_own && t.uploader_id == user_id → identity.download_disabled
    promo = ctx.promotions?.current(id).ok().flatten()
    out = ctx.hooks.run("torrent.before_download", {version:1, actor, user_id, torrent_id:id, uploader_id,
                         size, status, promotion: promo.map(|p| {up_rate, down_rate}), via})?
    Denied(d) → Err(d)
    pk = ctx.users.get_sensitive(user_id, "passkey")?
    if pk is None: ctx.users.reset_passkey(user_id)?; pk = get_sensitive(...)? ?: torrent.passkey_unavailable
    require pk 匹配 ^[0-9a-f]{32}$ ?: torrent.passkey_unavailable
    stored = blob_cache.get(t.blob_key)? ?: torrent.file_missing（告警）
    set = [("announce", benc_str(base[0] + "/" + pk)),
           ("announce-list", base.len()>1 ? benc_list([[b + "/" + pk for b in base]]) : 跳过),
           ("comment", benc_str(render(comment_template, id))),
           ("created by", benc_str(settings.created_by)),
           ("creation date", benc_int(t.created_at_unix))]
    bytes = bencode::splice_root(stored, set, remove = [])
    filename = sanitize_filename("[" + site_short + "]." + t.title) + ".torrent"   // 仅 [A-Za-z0-9._-] 与 CJK，≤ 180 字节
    事务：INSERT user_downloads … ON CONFLICT (user_id, torrent_id) DO UPDATE SET last_at = now(), times = times + 1
         publish torrent.downloaded {torrent_id, user_id, via}
    zeroize(pk)；return (bytes, filename)
```

HTTP 响应头：`Content-Type: application/x-bittorrent`、`Content-Disposition: attachment; filename="<ascii>"; filename*=UTF-8''<pct>`、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`。

**签名下载链接**：

```
token = base64url( payload ) + "." + base64url( HMAC-SHA256(secret, payload)[0..16] )
payload = 二进制 v1：ver(u8=1) | tid(u64) | uid(u64) | file_version(u32) | exp(u32 unix秒) | nonce(u32)
URL = <site.base_url>/api/p/torrent/v1/dl/<token>
```

- `GET /v1/dl/{token}`（auth = public，`rate_limit = "ip:60/m"`）：常量时间比较签名 → 检查 `exp` → 以 `actor = {kind: user, user_id: uid, credential_id: "dl:<nonce>"}` 调用 `build(…, via = "link")`。`file_version` 不等于当前版本 → `torrent.download_link_expired`（文件已替换）。
- 链接不可撤销单条；用户 passkey 重置或被封禁时由 `build` 中的状态检查拒绝。密钥轮换：设置 `download_link_secret_previous` 在过渡期同时接受。

**批量下载**：

```
POST /v1/downloads:batch {torrent_ids: [≤ batch_max]}
    SET p:torrent:batch:<uid> 1 NX EX 120 失败 → kernel.rate_limited（同一用户同时只允许一个批量）
    并发度 8 地对每个 id 调用 build(via="batch")，收集 Ok / Err(code)
    zip（Stored，不压缩；总大小 ≤ 64 MiB，超出的计入 skipped: torrent.batch_too_large）
       每个文件 <id>-<filename>.torrent；manifest.json {included:[id], skipped:[{id, code}]}
    DEL p:torrent:batch:<uid>；返回 application/zip（全部失败时返回 422 + skipped 列表）
```

### 1.10 `blob_cache`

- moka `Cache<String /*blob_key*/, Bytes>`，按字节权重，容量 `cache_mb`；TTL 无（内容不可变），TTI 1 h。
- 未命中：`blob.get`，同键并发由 moka `get_with` 合并（single-flight）。
- 指标：命中率、对象存储耗时。

| 订阅 | 处理（幂等说明） |
|---|---|
| `on_user_deleted`（`ordered = false`） | `mode = purge`：`UPDATE torrents SET uploader_id = NULL, uploader_purged = true WHERE uploader_id = $1`（分批）；`DELETE FROM user_downloads WHERE user_id = $1`。只有数据库副作用，inbox 保证恰好一次；重放时语句本身也幂等 |
| `on_settings_changed` | 若 `plugin_id == "torrent"`：清空进程内设置快照（Native 进程内副作用，重复执行无害） |

### 1.12 定时任务

| 任务 | 算法 | 幂等 |
|---|---|---|
| `blob_gc` | 用 `kv` 保存游标；分页列出 `plugins/torrent/torrents/` 对象（需要内核 `blob.list`，见 HLD §7 附注；未提供前改为：遍历 `blob_gc_candidates` 表——上传失败与文件替换时写入的候选键）；对每个候选：数据库中无 `torrent_file_versions.blob_key` 引用且记录超过 24 h → `blob.delete`，删除候选行 | 重复删除不存在的对象无害 |
| `purge_deleted` | 见 §1.7 | 已清除不再选中 |
| `group_stats_fix` | `UPDATE groups g SET torrent_count = s.c, last_upload_at = s.m FROM (SELECT group_id, count(*) c, max(created_at) m FROM torrents WHERE status NOT IN ('deleted') AND group_id = ANY($ids) GROUP BY group_id) s WHERE …`，每批 1000 个 Group | 计算覆盖写 |

> 平台 blob 接口没有 `list`；本设计采用“候选表”方案，不需要新增接口。

## 2. 接口详细设计

### 2.1 服务接口（`plugins/native/torrent/wit/torrents.wit`）

```wit
package pt:torrents@0.1.0;

interface torrents {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms, json};

  enum torrent-status { candidate, pending, approved, rejected, disabled, deleted }

  record torrent-summary {
    id: u64,
    group-id: option<u64>,
    type-id: string,
    title: string,
    size: u64,
    status: torrent-status,
    /// 匿名且调用者无权查看时为 none
    uploader-id: option<user-id>,
    info-hash-v1: option<string>,   // 40 hex
    info-hash-v2: option<string>,   // 64 hex
    created-at: timestamp-ms,
    category-id: option<u32>,
    file-version: u32,
  }

  record torrent-detail {
    summary: torrent-summary,
    subtitle: option<string>,
    /// 用户生成内容（源文本，BBCode/Markdown）
    description: string,
    mediainfo: option<string>,
    fields: json,
    tags: list<string>,
    release-group-id: option<u32>,
    file-count: u32,
    meta-version: u8,              // 1 = v1, 2 = v2, 3 = hybrid
    anonymous: bool,
    has-nfo: bool,
    updated-at: timestamp-ms,
    /// 评审 R1 F-05：invocation.actor 为用户时，按 can_download 与用户状态预判（不执行 before_download 钩子）；system / plugin actor 恒为 status == approved
    can-download: bool,
  }

  record file-item { path: string, size: u64 }
  record file-page { items: list<file-item>, next-cursor: option<string> }
  record torrent-page { items: list<torrent-summary>, next-cursor: option<string> }

  record group-info {
    id: u64, type-id: string, title: string, year: option<u32>, fields: json,
    torrent-count: u32, merged-into: option<u64>, created-at: timestamp-ms, updated-at: timestamp-ms,
  }

  get: func(id: u64) -> result<option<torrent-summary>, plugin-error>;
  /// 最多 500 个；不可见的 ID 不出现在结果中
  get-many: func(ids: list<u64>) -> result<list<torrent-summary>, plugin-error>;
  /// 40 或 64 位小写 hex
  by-info-hash: func(hex: string) -> result<option<torrent-summary>, plugin-error>;
  list-by-uploader: func(user: user-id, cursor: option<string>) -> result<torrent-page, plugin-error>;
  /// 作用域 write:status
  set-status: func(id: u64, status: torrent-status, reason: string) -> result<_, plugin-error>;
  /// 作用域 write:tags；整体替换
  set-tags: func(id: u64, tags: list<string>) -> result<_, plugin-error>;
  /// 作用域 write:status；reason 为删除原因码（delete_reasons 之一），可写成 "trumped:5502" 指定取代者
  delete: func(id: u64, reason: string) -> result<_, plugin-error>;
  get-group: func(id: u64) -> result<option<group-info>, plugin-error>;
  /// 作用域 write:group；patch 为 JSON Merge Patch
  update-group: func(id: u64, patch: json) -> result<group-info, plugin-error>;
  /// 作用域 write:group
  merge-groups: func(%from: u64, into: u64) -> result<_, plugin-error>;
  /// 作用域 download；执行全部检查与 torrent.before_download；via 由调用方给出（`service`、`rss`、`crossseed`、`mcp`，其他值按 `service` 记录）
  build-download: func(id: u64, user: user-id, via: string) -> result<list<u8>, plugin-error>;

  // ---- 新增（HLD §7）----
  get-detail: func(id: u64) -> result<option<torrent-detail>, plugin-error>;
  list-files: func(id: u64, cursor: option<string>, limit: u32) -> result<file-page, plugin-error>;
  /// 作用域 download；ttl-secs 截断到 [60, 86400]
  download-link: func(id: u64, user: user-id, ttl-secs: u32) -> result<string, plugin-error>;
  /// 作用域 write:status
  restore: func(id: u64, reason: string) -> result<_, plugin-error>;
}
```

| 方法 | 错误码 | 说明 |
|---|---|---|
| `get` / `get-many` / `get-detail` | `kernel.validation_failed`（超过 500） | 可见性按 `invocation.actor`：actor 为 user 时按该用户权限；actor 为 system/plugin 时可见全部非删除种子，但匿名发布者一律隐藏（需要真实发布者的 tracker-bridge 使用敏感视图 `v_torrent_tracker`） |
| `set-status` | `kernel.not_found`、`torrent.invalid_status_transition`、`kernel.hook_denied` 或处理者错误码、`kernel.capability_denied` | 同状态重复调用直接成功 |
| `set-tags` | `torrent.tag_unknown` | |
| `delete` / `restore` | `torrent.not_restorable`、`torrent.restore_conflict` | 已删除再删除成功 |
| `merge-groups` | `torrent.group_type_mismatch` | |
| `build-download` | 同 HTTP 下载 | 返回字节 ≤ 4 MiB（WIT 上限）；更大的种子返回 `torrent.too_large_for_service`，调用方改用 `download-link` |

### 2.4 HTTP API

公共：JSON snake_case；错误 problem+json；列表游标分页。

**上传** `POST /api/p/torrent/v1/torrents`（`multipart/form-data`，`max_body_kb = 12288`，`rate_limit = "user:20/h"`，`idempotent = true`）

部件：`torrent`（文件，必填）、`nfo`（文件，可选，≤ 1 MiB）、`meta`（JSON，必填）：

```json
{ "type_id": "movie",
  "fields": { "imdb_id": "tt0133093", "resolution": "2160p", "source": "UHD Blu-ray" },
  "title": null, "subtitle": "黑客帝国 4K 原盘",
  "description": "[b]简介[/b] …", "mediainfo": "General\nComplete name …",
  "category_id": 3, "release_group_id": 12, "anonymous": false, "group_id": null }
```

响应 201，`Location: /api/p/torrent/v1/torrents/5501`：

```json
{ "id": 5501, "group_id": 301, "status": "pending", "info_hash_v1": "3b24…1bc0",
  "need_redownload": true, "download_url": "/api/p/torrent/v1/torrents/5501/download" }
```

错误：413 `torrent.too_large`；422 `torrent.invalid_file`（`details.reason`）、`torrent.invalid_path`、`torrent.not_private`、`torrent.v2_not_supported`、`torrent.hybrid_not_supported`、`torrent.too_many_files`、`torrent.type_unknown`、类型插件错误码；409 `torrent.duplicate`（`details.torrent_id` 仅可见时）；403 钩子拒绝码。

**详情** `GET /v1/torrents/{id}`：

```json
{ "id": 5501, "group_id": 301, "type_id": "movie", "title": "The.Matrix.1999.2160p.UHD.BluRay.x265-ABC",
  "subtitle": "黑客帝国 4K 原盘", "size": 53687091200, "file_count": 3, "status": "approved",
  "uploader": { "id": 10086 },                 // 匿名且无权时为 {"anonymous": true}
  "info_hash_v1": "3b24…1bc0", "meta_version": 1, "file_version": 1,
  "tags": ["official"], "category_id": 3, "release_group_id": 12,
  "description_html": "<p><strong>简介</strong> …</p>",   // 服务端渲染并净化
  "mediainfo": "General …", "has_nfo": true, "fields": { … },
  "created_at": "2026-10-05T08:00:00.000Z", "updated_at": "…", "version": 4 }
```

响应带 `ETag: "4"`；`PATCH` 需 `If-Match`。

**编辑** `PATCH /v1/torrents/{id}`（`application/merge-patch+json`，`rate_limit = "user:60/h"`）：`{"subtitle": "…", "fields": {…}}` → 200 详情。412 `kernel.conflict`、403 `torrent.edit_locked`（超过编辑窗口）。

**状态** `POST /v1/torrents/{id}/status-changes`：`{"to": "approved", "reason": "符合规则"}` → 200 `{"status":"approved"}`。

**删除** `DELETE /v1/torrents/{id}`，请求体 `{"reason_code":"trumped","note":"…","replaced_by":5502}` → 204。

**恢复** `POST /v1/torrents/{id}/restorations` `{"reason":"误删"}` → 200。

**替换文件** `PUT /v1/torrents/{id}/file`（multipart：`torrent`、`reason`）→ 200 `{"file_version":2,"info_hash_v1":"…","need_redownload":true}`。

**文件列表** `GET /v1/torrents/{id}/files?limit=200&cursor=…` → `{"items":[{"path":"Movie/movie.mkv","size":53687000000}],"next_cursor":null,"has_more":false}`（填充文件不返回）。

**下载** `GET /v1/torrents/{id}/download`（`rate_limit = "user:120/m"`）→ 200 二进制；403 `torrent.not_downloadable`、`identity.*`、钩子错误码。

**签名链接** `POST /v1/torrents/{id}/download-links` `{"ttl_secs":600}` → 201 `{"url":"https://pt.example.com/api/p/torrent/v1/dl/AQAAAA…Zg.k3J…","expires_at":"…"}`。

**批量** `POST /v1/downloads:batch` `{"torrent_ids":[5501,5502]}`（`rate_limit = "user:10/h"`）→ 200 `application/zip`。

**Group** `GET /v1/groups/{id}` → `{"id":301,"type_id":"movie","title":"The Matrix","year":1999,"fields":{…},"torrents":[TorrentSummary…]}`；已合并 → 301 `Location` 指向目标；`POST /v1/groups/{id}/merges` `{"into":300}` → 200。

**查看匿名发布者** `GET /v1/torrents/{id}/uploader` → `{"user_id":10086}`，写审计 `torrent.reveal_uploader`。

**内容类型** `GET /v1/content-types` → `{"items":[{"type_id":"movie","name_term":"type-movie.name","field_schema":{…},"group_schema":{…}}]}`，`ETag` 为插件集合哈希。

```sql
CREATE INDEX torrent_tags_tag_key_idx ON torrent_tags (tag_key, torrent_id);

CREATE TABLE revisions (
    id          bigint GENERATED BY DEFAULT AS IDENTITY,
    torrent_id  bigint,
    group_id    bigint,
    kind        text NOT NULL CHECK (kind IN ('create','edit','file','status','tags','group','delete','restore','merge')),
    editor_id   bigint,
    actor_kind  text NOT NULL,
    changes     jsonb NOT NULL CHECK (pg_column_size(changes) <= 131072),
    reason      text CHECK (char_length(reason) <= 500),
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);
CREATE INDEX revisions_torrent_id_idx ON revisions (torrent_id, created_at DESC);
CREATE INDEX revisions_group_id_idx ON revisions (group_id, created_at DESC);

CREATE TABLE user_downloads (
    user_id     bigint NOT NULL,
    torrent_id  bigint NOT NULL,
    first_at    timestamptz NOT NULL DEFAULT now(),
    last_at     timestamptz NOT NULL DEFAULT now(),
    times       integer NOT NULL DEFAULT 1,
    PRIMARY KEY (user_id, torrent_id)
) PARTITION BY HASH (user_id);
-- 16 个分区在迁移中一次建好
CREATE TABLE user_downloads_p00 PARTITION OF user_downloads FOR VALUES WITH (MODULUS 16, REMAINDER 0);
-- … p01 ～ p15 同理
CREATE INDEX user_downloads_user_id_last_at_idx ON user_downloads (user_id, last_at DESC);

CREATE TABLE blob_gc_candidates (
    blob_key    text PRIMARY KEY,
    created_at  timestamptz NOT NULL DEFAULT now()
);

-- 视图（[database].views）
CREATE VIEW v_torrent_public WITH (security_barrier = true) AS
SELECT id, group_id, type_id, title, size, status, created_at,
       CASE WHEN is_anonymous THEN NULL ELSE uploader_id END AS uploader_id
FROM torrents WHERE deleted_at IS NULL;

CREATE VIEW v_group_public WITH (security_barrier = true) AS
SELECT id, type_id, title, year, created_at FROM groups WHERE deleted_at IS NULL AND merged_into IS NULL;

-- 敏感：只授予 tracker-bridge（含已删除行，供写墓碑与一致性校验）
CREATE VIEW v_torrent_tracker WITH (security_barrier = true) AS
SELECT id, info_hash_v1, info_hash_v2, size, status, uploader_id, file_version,
       deleted_at, delete_reason, updated_at
FROM torrents;

-- 评审 R1 F-05：供 type-*、search-meilisearch、requests、levels 只读访问
CREATE VIEW v_torrent_fields WITH (security_barrier = true) AS
SELECT id, group_id, type_id, category_id, fields, release_group_id, updated_at
FROM torrents WHERE deleted_at IS NULL;

CREATE VIEW v_group_fields WITH (security_barrier = true) AS
SELECT id, type_id, title, year, fields, updated_at
FROM groups WHERE deleted_at IS NULL AND merged_into IS NULL;

-- 内容指纹（同内容重复检测，crossseed-api 与 type-* 使用）；索引 torrents_content_fp_idx
CREATE VIEW v_torrent_fingerprint WITH (security_barrier = true) AS
SELECT id, content_fp, size, status FROM torrents WHERE deleted_at IS NULL AND content_fp IS NOT NULL;

-- 发布者统计（levels、newbie-exam 的指标）；匿名发布照常计入本人
CREATE VIEW v_uploader_counts WITH (security_barrier = true) AS
SELECT uploader_id AS user_id,
       count(*) FILTER (WHERE status = 'approved') AS approved_count,
       count(*) AS total_count,
       coalesce(sum(size) FILTER (WHERE status = 'approved'), 0) AS approved_size
FROM torrents WHERE deleted_at IS NULL GROUP BY uploader_id;

CREATE VIEW v_torrent_hash_history WITH (security_barrier = true) AS
SELECT torrent_id, file_version, info_hash_v1, info_hash_v2, replaced_at
FROM torrent_file_versions WHERE replaced_at IS NOT NULL;
```

数据量估算：`torrents` 100 万行 × 约 3 KB（含 description、mediainfo，TOAST）≈ 3 GB；`torrent_files` 100 万 × 平均 2 KB ≈ 2 GB；`user_downloads` 30 万用户 × 平均 300 ≈ 9000 万行 × 50 B ≈ 4.5 GB（哈希分区）；`revisions` 每月约 10 万行。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 解析器 | 有界、迭代、无 `unsafe`；`cargo fuzz` 目标 `decode`、`parse`、`normalize`、`splice_root`；单请求内存上限（输入 ≤ 10 MiB，结构元素 ≤ 200 万） |
| 路径 | §1.2 `check_component`；文件名不在 HTML 属性中拼接，前端只以文本节点显示 |
| 简介 | 服务端 BBCode/Markdown → 受限 HTML（ammonia 白名单：`p, br, strong, em, u, s, a[href http/https/站内], img[src https], ul, ol, li, blockquote, pre, code, table…`）；图片外链可在设置中改为经图片代理 |
| passkey | 只在 `build` 内局部变量中存在，使用后 `zeroize`；不写日志（`tracing` 字段过滤器屏蔽 `passkey`）；响应 `no-store`、`Referrer-Policy: no-referrer`；错误信息不含 announce URL |
| 签名链接 | HMAC-SHA256 截断 128 位，常量时间比较；不含 passkey；短 TTL；按 IP 限流；访问仍执行全部检查 |
| 匿名 | `visibility::reveal_uploader` 统一出口；搜索文档、MCP、视图、列表接口均经过；查看真实发布者写审计 `torrent.reveal_uploader` |
| 权限 | 路由级权限由网关检查；对象级（本人、状态）由本插件检查；服务作用域检查 `invocation.caller_scopes` |
| 审计 | `torrent.status_change`、`torrent.delete`、`torrent.restore`、`torrent.replace_file`、`torrent.group_merge`、`torrent.tags_set`、`torrent.reveal_uploader`；details 不含 passkey |
| 限流 | 上传 `user:20/h`、编辑 `user:60/h`、下载 `user:120/m`、批量 `user:10/h`、签名链接下载 `ip:60/m` |
| 拒绝服务 | 上传解析在 `spawn_blocking` 中执行，并发上限 4/副本（信号量），超出返回 `kernel.rate_limited` |

## 7. 性能设计

| 热点 | 设计 | 容量估算 |
|---|---|---|
| 下载 | 规范化种子进程内 LRU（256 MiB，平均种子 40 KB → 约 6500 个热种子）；拼接只做一次线性拷贝；`ctx.users.get` 5 s 缓存；passkey 不缓存（每次一次服务调用，Native→Native 进程内调用） | 峰值 50 次/秒，单副本能力 ≥ 500 次/秒 |
| 上传 | 解析放到阻塞线程池；对象存储 put 一次；单事务 | 日 2000 次，可忽略 |
| `get_many` | 单条 `WHERE id = ANY($1)` + 标签聚合 | 500 个 ≤ 50 ms |
| 搜索 `to_document` | 索引 worker 批量拉取时 Native 接口逐个调用；`file_names` 需解压文件列表（平均 2 KB），可接受 | 全量重建 100 万文档约 10 分钟（单线程），由 search 控制并发 |
| tracker-bridge 全量扫描 | 走视图键集分页（主键索引） | 100 万行，1000 行/批 |
