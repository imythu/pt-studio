## 1. 引言

### 1.1 目的

定义抽奖插件 `lottery` 的需求。它为魔力值提供娱乐性消耗：用户消耗魔力值转动幸运转盘，按管理员设定的概率获得奖品。

### 1.2 范围

包含：

- **幸运转盘**：转盘展示全部可中奖品与“谢谢参与”，点击抽奖后转盘转动并停在结果上；
- **奖品类型**：魔力值、上传量、VIP 天数（顺延）、永久 VIP；
- **后台设置**：开关、每次消耗的魔力值（可为 0）、每人每日次数（可不限）、注册天数门槛；奖品列表（类型、数量、显示名称、概率、库存、启用）；
- **公示**：每个奖品的中奖概率与“谢谢参与”概率对用户可见；最近中奖名单；个人抽奖记录；
- **统计**：今日抽奖次数、参与人数、消耗魔力值、中奖次数；近 30 天各类奖品发放量。

不包含：期次制彩票、竞猜（0.1 的期次制已移除）；现金或站外奖品。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 奖品 | 转盘上的一个扇区，带类型、数量、概率与可选库存 |
| 概率 | 以百万分之一（ppm）存储，后台按百分比填写（最多 4 位小数） |
| 谢谢参与 | 未中奖；概率 = 100% − 启用奖品概率之和 |
| 库存 | 奖品剩余数量；为空表示不限，为 0 时不再出现在转盘上 |

## 2. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| LOT-F01 | 默认关闭；关闭时不能抽奖，转盘页提示“暂未开放”，首页小组件不显示 | 高 |
| LOT-F02 | 注册未满门槛天数的账号不能抽奖 | 高 |
| LOT-F03 | 每次抽奖扣除设定的魔力值；余额不足时拒绝且不留记录 | 高 |
| LOT-F04 | 每人每日（UTC）次数达到上限后拒绝；上限为 0 表示不限 | 高 |
| LOT-F05 | 按启用、有库存奖品的概率抽取；落在概率之外为谢谢参与 | 高 |
| LOT-F06 | 中奖即时发放：魔力值入账、上传量加到用户流量、VIP 顺延天数、永久 VIP | 高 |
| LOT-F07 | 发放失败时退回本次消耗并提示，不扣库存、不留记录 | 高 |
| LOT-F08 | 抽中有库存的奖品后库存减一；库存为 0 的奖品从转盘移除 | 中 |
| LOT-F09 | 管理员整表保存奖品：校验类型与数量范围、启用奖品概率之和 ≤ 100%、启用奖品 ≤ 16 个 | 高 |
| LOT-F10 | 删除的奖品保留在历史记录中（软删除） | 中 |
| LOT-F11 | 转盘页公示概率、最近 20 条中奖、本人最近 10 条记录 | 中 |
| LOT-F12 | 管理员修改奖品写审计日志 | 中 |

数量范围：魔力值 1–10 亿；上传量 1 字节–1 PiB；VIP 天数 1–3650；永久 VIP 无数量。

## 3. 非功能需求

- 同一用户的并发抽奖串行化，保证每日次数准确；
- 随机数来自宿主（`random` 接口），取模偏差可忽略；
- 扣费、发奖、退款都带幂等键，重试不会重复扣款或重复发奖；
- 转盘动画约 4.6 秒；移动端可用。

## 4. 依赖

- 必需：`ctx.ledger`（魔力值扣费与发放，scope `currency:bonus`）；
- 可选：`ctx.accounting`（上传量，scope `write:adjust`）、`ctx.levels`（VIP，scope `grant`）。缺失时对应奖品发放失败并退款。
