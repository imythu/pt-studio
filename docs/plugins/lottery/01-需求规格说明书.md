## 1. 引言

### 1.1 目的

定义彩票 / 竞猜插件 `lottery` 的需求。它为站内虚拟货币提供娱乐性消耗：定期开奖的彩票，以及管理员发起的竞猜（如赛事预测）。

### 1.2 范围

包含：

- **彩票**：期次（round）、票价、每人限购、奖池（销售额 × 返奖比例 + 保底奖金）、奖级（一等奖 1 名、二等奖 N 名……或按比例）、到时开奖；
- **可验证的随机开奖**：commit-reveal（开售前公布种子哈希，开奖后公开种子），任何人可复算；可选叠加公开随机信标；
- **竞猜**：管理员创建题目与选项，用户投注；按彩池（parimutuel）分配；管理员公布结果后结算；可取消并全额退还；
- 币种可配置，经 `ctx.ledger` 扣款与派奖；
- **合规开关**：插件默认关闭；开启时站点须在后台确认合规声明；可按等级限制参与；
- 历史、统计、MCP 查询。

不包含：

- 真实货币；
- 赠送彩票。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 期次 | 一轮彩票，从开售到开奖 |
| 奖池 | 本期可分配奖金 = 销售额 × `payout_ratio` + `guaranteed_pool` |
| 抽水 | 销售额 × (1 − `payout_ratio`)，从流通中回收（系统回收），用于抑制通胀 |
| commit-reveal | 开售前公布 `H = SHA-256(seed)`，开奖后公布 `seed`，随机结果由 `seed` 与本期全部票据确定性派生 |
| 彩池分配 | 竞猜中，获胜选项的投注者按投注额比例分配（总投注 × 返奖比例） |

### 1.4 参考资料

- docs/platform/、docs/plugins/ledger/03（transfer、hold、reverse）
- NexusPHP：博彩（bet）功能与第三方彩票插件（期次、奖池、到期开奖，随机数使用 `mt_rand`）
- UNIT3D：无原生彩票；社区常用“竞猜（gambling）”类扩展
- drand 公开随机信标（League of Entropy）

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM，ID `lottery`，缩写 `LOT`。
- 提供：`ctx.lottery`（single）。
- 依赖：`ctx.ledger`、`ctx.users`、`ctx.terms`；可选 `ctx.notify`。
- 出站 HTTP（可选）：`api.drand.sh`（公开随机信标），只在 cron 中使用。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 购买彩票、查看我的票号与开奖结果、验证开奖；参与竞猜、查看赔率估算 |
| 管理员 | 配置彩票期次模板；创建 / 结算 / 取消竞猜；查看统计；开启合规开关 |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP 博彩 / 彩票插件 | 用户下注魔力值；开奖用 PHP `mt_rand`；奖金直接加到用户字段 | 简单、活跃度高 | 随机数不可验证，站方可操纵或被质疑；开奖与派奖非原子，开奖脚本中断导致漏派；无合规开关 | **采纳**期次、奖池、竞猜玩法；**改进**：commit-reveal 可验证随机；派奖经 ledger 幂等；默认关闭并需合规确认 |
| 社区竞猜扩展（UNIT3D 等） | 管理员发题、用户投注、管理员定结果 | 适合赛事活动 | 固定赔率由管理员拍脑袋，可能被套利 | 采用彩池分配（parimutuel），站方不承担风险，只按比例抽水 |

### 2.4 约束与假设

1. WASM 每次调用新实例，开奖为 cron + 延迟任务分批执行；
2. 随机数：`ctx.random`（宿主 CSPRNG）生成 commit 种子；开奖不依赖开奖时刻的随机源，只依赖已承诺的种子与票据数据（可复算）；
3. 规模：每期票数 ≤ 100 万张；同时进行的竞猜 ≤ 50 个。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-LOT-001 | 合规开关 | 插件默认关闭（`enabled = false`）；管理员开启时须勾选合规声明并记录审计 | P0 | 未开启时所有用户接口返回 `lottery.disabled` |
| FR-LOT-002 | 期次模板 | 管理员配置模板：周期（cron 表达式）、开售时长、票价、币种、每人每期限购、返奖比例、保底奖池、奖级结构、最低参与等级 | P0 | 按模板自动开期 |
| FR-LOT-003 | 开期与承诺 | 新期开售时生成 32 字节种子，保存密文（静态密钥加密）并公布 `commit = SHA-256(seed)` | P0 | 开售时即可查到 commit |
| FR-LOT-004 | 购票 | 用户在开售期间购买 1～N 张；扣款经 ledger（转入系统，流水原因 `lottery.ticket`）；分配连续票号 | P0 | 余额减少；票号唯一连续 |
| FR-LOT-005 | 限购 | 每人每期限购；全期总票数上限（可选） | P1 | 超限 `lottery.limit_reached` |
| FR-LOT-006 | 停售 | 到达停售时间后禁止购票，计算“票据摘要”`tickets_root`（全部票据的哈希链） | P0 | 停售后购买返回 `lottery.round_closed` |
| FR-LOT-007 | 开奖 | 停售后开奖：`rand = HMAC-SHA256(seed, round_id ‖ tickets_root ‖ beacon?)`，按 §详细设计算法抽出各奖级票号；公开 seed | P0 | 任何人用公开数据复算得到相同中奖票号 |
| FR-LOT-008 | 信标（可选） | 开启时使用停售后第一轮 drand 随机值作为 `beacon` 参与派生；信标不可用时等待最多 30 分钟后不带信标开奖并标注 | P2 | 结果页显示信标轮次 |
| FR-LOT-009 | 派奖 | 中奖金额经 ledger 发行给中奖者（原因 `lottery.prize`，幂等键按 期次+票号）；抽水部分不发行（购票时已从流通回收） | P0 | 派奖总额 = 奖池（扣除未中出部分） |
| FR-LOT-010 | 奖池滚存 | 奖级无人中（票数不足）时，未派出金额滚入下一期（可配置为滚存或回收） | P1 | 下一期奖池包含滚存 |
| FR-LOT-011 | 最少票数 | 期内票数少于 `min_tickets` 时取消本期并全额退款 | P1 | 退款经 ledger 冲正 / 发行 |
| FR-LOT-012 | 验证页 | 展示 commit、seed、tickets_root、beacon、算法说明，并提供票据清单下载（票号 → 用户 ID 的哈希或用户名，按隐私设置） | P1 | 下载数据可复算结果 |
| FR-LOT-013 | 竞猜创建 | 管理员创建竞猜：题目、选项（2～16 个）、投注截止时间、最小 / 最大投注、币种、返奖比例 | P1 | 创建后用户可见 |
| FR-LOT-014 | 竞猜投注 | 用户在截止前对一个选项投注（可多次追加同一选项；是否允许投多个选项可配置） | P1 | 投注扣款；实时显示各选项总额与估算赔率 |
| FR-LOT-015 | 竞猜结算 | 管理员公布结果选项：获胜者按投注占比分配 `总投注 × 返奖比例`；无人投中获胜选项时全额退款 | P1 | 派奖金额之和 ≤ 总投注 × 比例，误差 < 1 最小单位 × 获胜人数 |
| FR-LOT-016 | 竞猜取消 | 管理员取消竞猜：全部投注退回 | P1 | 余额恢复 |
| FR-LOT-017 | 四眼结算 | 可选：结算需第二位管理员确认 | P2 | 未确认前不派奖 |
| FR-LOT-018 | 我的记录 | 用户查看自己的票、投注、中奖记录 | P0 | 与数据库一致 |
| FR-LOT-019 | 事件 | 发布 `lottery.ticket_bought`、`lottery.round_drawn`、`lottery.bet_placed`、`lottery.market_settled` | P0 | 订阅方收到 |
| FR-LOT-020 | 通知 | 中奖通知（可关闭） | P2 | 中奖者收到通知 |
| FR-LOT-021 | 等级限制 | 期次 / 竞猜可设最低等级；新用户（注册 < N 天）不可参与（默认 7 天） | P1 | 不满足返回 `lottery.not_eligible` |
| FR-LOT-022 | 用户删除 | 订阅 `user.deleted`：未开奖的票全额退款不适用（用户已删除），票据保留参与开奖但奖金不发放（回收）；purge 时匿名化 | P2 | 删除用户的中奖记录为“已回收” |
| FR-LOT-023 | MCP | `list_lottery_rounds`（读） | P2 | 返回当前期次与开奖结果 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-LOT-001 | 公平性 | 开奖结果可由公开数据独立复算 | 提供独立的验证脚本（Python，≤ 100 行）与测试向量 |
| NFR-LOT-002 | 公平性 | 站方无法在开售后改变结果 | seed 在开售时承诺；票据摘要在停售时固定；开奖不读取任何开奖时刻的随机源 |
| NFR-LOT-003 | 可靠性 | 派奖幂等、可恢复 | 开奖任务中断后重跑不重复派奖、不漏派 |
| NFR-LOT-004 | 性能 | 购票 | p99 < 200 ms |
| NFR-LOT-005 | 性能 | 开奖 | 100 万张票开奖（含派奖）≤ 10 分钟，分批提交 |
| NFR-LOT-006 | 安全 | seed 保密 | 开奖前 seed 只以密文存储；密钥来自静态配置；日志与事件不含 seed |
| NFR-LOT-007 | 合规 | 默认关闭、可审计 | 开关变更、结算、取消全部写审计 |

## 5. 可配置项与站点术语

运行时设置：`enabled`（false）、`compliance_ack`（只读展示，由开启操作写入）、`min_account_age_days`（7）、`notify_winners`（true）、`beacon.enabled`（false）、`ticket_list_privacy`（`hash` / `username`，默认 hash）。
静态配置：`seed_key`（32 字节 base64，必填，加密 seed 用）、`beacon_url`（默认 `https://api.drand.sh`）。

术语：`lottery.name`、`lottery.betting`（已登记）；新增 `lottery.round`（期）、`lottery.ticket`（彩票）、`lottery.prize_tier.<n>`（奖级名）、`lottery.market.<id>`（竞猜题目，动态）。

## 6. 外部接口需求概述

- 服务 `ctx.lottery`：`rounds`、`buy`、`markets`、`bet`。
- 事件：发布 `lottery.ticket_bought`、`lottery.round_drawn`、`lottery.round_cancelled`、`lottery.bet_placed`、`lottery.market_settled`、`lottery.market_cancelled`；订阅 `user.deleted`。
- HTTP：`/api/p/lottery/v1/*`；插槽 `nav.main`、`home.widgets`；页面 `/p/lottery/`。
- MCP：`list_lottery_rounds`。
