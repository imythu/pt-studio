## 2. 端到端（`crates/server/tests/e2e_lottery.rs`）

用 100% 概率的单一奖品使结果确定：

| 编号 | 用例 | 期望 |
|---|---|---|
| LOT-E01 | 迁移后的默认奖品 | 7 个；用户接口不含库存；有谢谢参与概率 |
| LOT-E02 | 默认关闭 / 注册天数 | `lottery.disabled` → 开启后 `lottery.not_eligible` |
| LOT-E03 | 奖品校验 | 概率之和 > 100%、VIP 天数 0 → 422；普通用户保存 → 403 |
| LOT-E04 | 魔力值奖品 | 余额 −50 +300 |
| LOT-E05 | 上传量奖品 | `accounting.user_totals.uploaded_adjust` 增加 1 GiB |
| LOT-E06 | VIP 天数 | VIP 覆盖约 7 天后到期 |
| LOT-E07 | 永久 VIP（库存 1） | 有时限的 VIP 被永久 VIP 取代；库存变为 0 |
| LOT-E08 | 库存用完 | 转盘无奖品、谢谢参与 100%；抽奖仍扣费、未中奖 |
| LOT-E09 | 每日次数 | 达到上限 → `lottery.limit_reached` |
| LOT-E10 | 余额不足 | `lottery.insufficient_funds`，不留记录 |
| LOT-E11 | 记录与删除 | 我的记录 5 条、最近中奖 4 条；保存空表后奖品软删除；审计 ≥ 5 条 |
| LOT-E12 | 十连抽（库存 3） | 10 条结果、前 3 条中奖其余谢谢参与；扣 500 得 900；今日 15 次；再十连 → `lottery.limit_reached`；`count` 11 → 422 |

相关回归：`e2e_shop`、`e2e_donations`、`e2e_levels`（`grant_vip` 改动）。

## 3. 手工 / 浏览器

- 桌面与手机宽度下转盘、概率公示、最近中奖、我的记录布局；
- 抽奖动画停在返回的奖品扇区，结果文字与记录刷新；顶栏魔力值同步更新；
- 十连抽：转盘停在第一个中奖奖品上，下方逐条列出 10 次结果；剩余次数不足 10 次时按钮禁用；
- 后台：开关与参数保存、奖品增删改、概率合计提示、超过 100% 时禁止保存。
