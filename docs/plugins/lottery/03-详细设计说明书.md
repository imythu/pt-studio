## 1. 数据库（`migrations/0002_wheel.sql`）

```sql
CREATE TABLE wheel_prizes (
    id          bigserial PRIMARY KEY,
    kind        text NOT NULL CHECK (kind IN ('bonus', 'upload', 'vip_days', 'vip_permanent')),
    amount      bigint NOT NULL DEFAULT 0 CHECK (amount >= 0),
    label       text NOT NULL DEFAULT '' CHECK (char_length(label) <= 40),
    chance_ppm  integer NOT NULL CHECK (chance_ppm BETWEEN 0 AND 1000000),
    stock       integer CHECK (stock >= 0),          -- NULL = 不限
    sort        integer NOT NULL DEFAULT 100,
    active      boolean NOT NULL DEFAULT true,
    deleted_at  timestamptz,                         -- 软删除：历史记录仍引用
    created_at, updated_at timestamptz
);
CREATE TABLE spins (id bigserial PK, user_id, cost, prize_id → wheel_prizes, kind, amount, created_at);
CREATE TABLE spin_locks (user_id bigint PRIMARY KEY);
```

`amount` 的含义：`bonus` 为魔力值、`upload` 为字节、`vip_days` 为天数、`vip_permanent` 恒为 0。

## 2. 抽奖流程（`spin`）

请求体 `{count}`，1–10，缺省 1（单抽）；10 为十连抽。

1. 读设置；未开启 → `lottery.disabled`（403）；注册天数不足 → `lottery.not_eligible`（403）；
2. `INSERT INTO spin_locks … ON CONFLICT DO UPDATE` 取得本用户行锁（插件 SQL 网关禁止 advisory lock）；
3. 今日（UTC）次数 + `count` > 上限 → `lottery.limit_reached`（409，整批拒绝）；
4. `SELECT … FROM wheel_prizes WHERE active AND deleted_at IS NULL AND (stock IS NULL OR stock > 0) ORDER BY sort, id FOR UPDATE`；
5. 取 `count` 个 `spins` 序列值作为抽奖 ID；消耗 > 0 时一次扣清 `消耗 × count`（`ctx.ledger.transfer(from=user)`，幂等键 `lot:s:<首个抽奖 ID>`），余额不足映射为 `lottery.insufficient_funds`（402），不扣费、无记录；
6. 以下每次抽奖重复；本批次内库存用完的奖品概率置 0；
7. `roll = be64(random(8)) mod 1 000 000`；按顺序累加 `chance_ppm`，第一个使 `roll < 累计` 的奖品中奖，否则未中奖；
8. 中奖时按类型发奖（见概要设计）；失败则退回该次消耗（`lot:rf:<抽奖 ID>`）：单抽返回 `lottery.grant_failed`（503），插件事务回滚（不扣库存、不写记录）；连抽中该次记为 `failed`、不写记录，其余照常（已发出的奖品由各服务提交，不能整批回滚）；
9. 有库存的奖品 `stock - 1`；写 `spins`；发布 `lottery.spun`；
10. 返回 `{cost, spins_today, results[{spin_id, prize_id, kind, amount, failed?}]}`，`cost` 为实际扣除（已扣除退款）；单抽时 `spin_id, prize_id, kind, amount` 也放在顶层（兼容旧客户端）。

扣费与发奖由各自服务提交。若进程在扣费后、写记录前中断，用户损失一次消耗；账本中有 `lottery.spin` 记录可供补偿。

## 3. 奖品保存（`save_prizes`）

请求 `PUT /v1/admin/wheel/prizes`，`{ prizes: [{id?, kind, amount, label, chance_ppm, stock, active}] }`：

- 校验：类型合法；数量范围（`check_amount`）；`chance_ppm` 0–1 000 000；库存 ≥ 0；名称 ≤ 40 字；启用奖品概率之和 ≤ 1 000 000；启用奖品 ≤ 16；
- 带 `id` 的更新（不存在或已删除 → 404），不带 `id` 的插入；`sort` 按提交顺序；
- 未出现在列表中的奖品标记 `deleted_at` 并停用；
- 写审计 `lottery.prizes_update`；返回与 `GET /v1/admin/wheel` 相同的结构。

## 5. levels 的永久 VIP

`ctx.levels.grant_vip` 增加 `permanent: true`：

- 以 `source_ref` 幂等；
- 已有永久 VIP（`kind = 'vip' AND until IS NULL AND ended_at IS NULL`）时直接返回 `{permanent: true, already_permanent: true}`，按天授予也不再生效；
- 授予永久 VIP 时结束当前有时限的 VIP 覆盖，插入 `until = NULL` 的覆盖；
- `vip_until` 返回 `{until_ms, permanent}`，永久时 `until_ms` 为 null。

## 6. 前端要点

- 转盘扇区等分；目标角度 `360 − (idx × seg + seg/2) + 抖动(±0.3 seg)`，在当前角度基础上多转 6 圈；
- 扇区文字最多两行，优先在空格处断开；上传量整数 GiB/TiB 去掉小数；
- 后台概率以 % 输入（`ppm = round(% × 10000)`），上传量以 GiB 输入（`bytes = round(GiB × 2^30)`）。
