## 1. 设计目标与原则

1. **可验证**：commit-reveal + 票据哈希链；开奖是 seed 与已固定数据的纯函数（NexusPHP `mt_rand` 不可验证的改进）。
2. **站方零风险**：彩票奖池来自销售额，竞猜采用彩池分配；抽水从流通中回收。
3. **记账清晰**：购票 / 投注 = 用户 → 系统（回收）；派奖 / 退款 = 系统 → 用户（发行）；全部带确定性幂等键。
4. **默认关闭**：合规开关；新号与低等级限制。
5. **分批可恢复**：开奖、派奖、退款都是状态机 + 分批任务。

## 2. 总体结构

### 2.1 在整体架构中的位置

```
用户 ──► lottery (WASM) ──ledger.transfer──► ledger
             │ cron: open_rounds / close_rounds / draw（可选出站 drand）
             │ jobs: payout_batch / refund_batch
             │ events: lottery.*
             ▼
       PG schema lottery
```

## 5. 关键流程

### 5.1 彩票生命周期

```
scheduled ─(开售时间)→ open ─(停售时间)→ closed ─→ drawing ─→ paying ─→ finished
                            └─(票数 < min_tickets 或 管理员取消)→ cancelling ─→ cancelled
open：购票 → ledger.transfer(user → 回收, key "lot:t:<batch_id>") → INSERT tickets(链哈希)
closed：tickets_root = 最后一个批次的链哈希；可选等待信标
drawing：rand 派生 → 抽中票号 → INSERT prizes；UPDATE rounds SET seed_plain（公开）
paying：分批 ledger.transfer(None → winner, key "lot:p:<round>:<ticket_no>")
```

### 5.2 竞猜生命周期

```
open ─(截止)→ locked ─(管理员结算提议[+确认])→ settling ─→ settled
  └─(取消)→ cancelling ─→ cancelled
投注：ledger.transfer(user → 回收, key "lot:b:<bet_id>")
结算：pool = Σ bets；win = Σ bets(winning option)；payout_i = floor(pool × ratio × bet_i / win)
     win == 0 → 全额退款
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论与理由 |
|---|---|---|---|
| DD-LOT-1 | 随机源 | 开奖时 CSPRNG / commit-reveal / 纯外部信标 | commit-reveal 为主、信标可选：站方无法事后选择种子；信标进一步排除“站方在开售前预知票据”之外的操纵空间（站方可在知道 seed 的情况下自己买票——见 DD-LOT-2） |
| DD-LOT-2 | 站方知道 seed 可自己买中奖票 | 无法完全防止 / 引入信标 / 票号由用户购买顺序决定 | 结果由 `tickets_root`（含全部票据）派生，任何后来的购买都会改变结果，站方无法预知最终 root；开启信标后连 root 确定后的结果也不可预知 |
| DD-LOT-3 | 扣款方式 | hold 到开奖 / 直接回收 | 直接回收：彩票不可退（取消期次除外），简化记账；取消时从系统发行退款 |
| DD-LOT-4 | 竞猜赔率 | 固定赔率 / 彩池 | 彩池：站方无风险，不需管理员定赔率 |
| DD-LOT-5 | 尾差 | 四舍五入 / 向下取整，余数回收 | 向下取整，余数回收（不发行），可审计 |

## 实现说明（2026-10-17，v0.1.0，开站计划 M4.2）

- 只实现彩票期次，竞猜（markets / bets）、期次模板、外部信标（drand）、MCP 工具留待后续。期次由管理员直接创建：票价、每人限购、最少票数、抽水（0～50%）、奖级（1～10 级，每级中奖数与奖池占比，合计 ≤ 100%）、停售时间（1 分钟～90 天后）。
- commit-reveal：创建时 `random.bytes(32)` 生成 seed，公开 `seed_commit = sha256(seed)`；seed 明文存于插件库（未加密），开奖后经 `/verify` 公开。
- 票据链：`chain_i = sha256(chain_{i-1} ‖ be64(batch_id) ‖ be64(user_id) ‖ be64(first_no) ‖ be64(count))`，`chain_0` 为空；批次 ID 先取序列值再参与哈希。开奖 `rand = sha256(seed ‖ tickets_root)`，第 t 级第 k 注：`n = be64(sha256(rand ‖ be32(t) ‖ be64(k) ‖ be32(attempt))[0..8]) mod total + 1`，跳过已抽中的号；中奖数超过票数时截断。前端“在浏览器中复算”用 WebCrypto 按同一算法核对 commit、票据链和中奖号码。
- 记账：购票 = 用户 → 回收（`lottery.ticket`，幂等键 `lot:t:<批次>`）；派奖 = 发行 → 用户（`lottery.prize`，`lot:p:<期>:<票号>`）；退款 = 发行 → 用户（`lottery.refund`，`lot:r:<批次>`）。奖金 = ⌊销售额 × (1 − 抽水) × 占比 / 中奖数⌋，尾差与抽水不发行。直接回收、不冻结（DD-LOT-3）。
- 开奖：`tick` 每分钟处理已停售的期次（每期一个事务提交，失败时本期回滚、下一分钟重试，派奖幂等）；票数少于最少票数时取消并全额退款。管理员可“立即开奖”（提前停售）或取消（填写理由，全额退款）。
- 合规与资格：设置 `enabled` 默认关闭（关闭时不能买票，已开的期次照常开奖）、`min_account_days`（默认 7）、`max_tickets_per_buy`（默认 100）。未接入用户等级限制。
- 中奖经 `ctx.notify` 通知（类别 `economy`）。前端：主导航“抽奖”、首页小组件（进行中的一期）、`/p/lottery/`（列表与我的中奖）、`/p/lottery/<id>`（购票、我的票、中奖名单、验证）、`/admin/p/lottery/`（开期、立即开奖、取消）。
