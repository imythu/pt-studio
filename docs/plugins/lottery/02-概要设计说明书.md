## 1. 总体结构

`lottery` 是 WASM 插件（`plugins/wasm/lottery`），前端在 `web/plugins/lottery`。

```
用户 ──GET /v1/wheel──────────────▶ 转盘配置 + 概率 + 最近中奖 + 本人记录
     ──POST /v1/wheel/spin─────────▶ 校验 → ledger 扣费 → 抽取 → 发奖 → 写记录 → lottery.spun
管理员 ─GET /v1/admin/wheel─────────▶ 奖品（含库存、停用）+ 今日统计 + 近 30 天发放
      ─PUT /v1/admin/wheel/prizes──▶ 整表保存奖品
      ─PUT /api/kernel/v1/admin/plugins/lottery/settings ▶ 开关与参数（内核插件设置）
```

发奖经服务调用：

| 奖品 | 服务 | 方法 | 幂等键 |
|---|---|---|---|
| 魔力值 | `ctx.ledger` | `transfer`（系统发行到用户，reason `lottery.prize`） | `lot:w:<抽奖 ID>` |
| 上传量 | `ctx.accounting` | `adjust`（`d_up`，reason `lottery.prize`） | `lot:w:<抽奖 ID>` |
| VIP 天数 | `ctx.levels` | `grant_vip`（`days`） | `source_ref = lot:w:<抽奖 ID>` |
| 永久 VIP | `ctx.levels` | `grant_vip`（`permanent: true`） | 同上 |

扣费：`ctx.ledger.transfer` 从用户回收（reason `lottery.spin`，键 `lot:s:<抽奖 ID>`）；发奖失败时退款（reason `lottery.refund`，键 `lot:rf:<抽奖 ID>`）。

## 2. 数据

| 表 | 说明 |
|---|---|
| `wheel_prizes` | 奖品：类型、数量、显示名称、概率（ppm）、库存（可空）、排序、启用、软删除时间 |
| `spins` | 抽奖记录：用户、消耗、奖品 ID（未中奖为空）、类型与数量快照、时间 |
| `spin_locks` | 每用户一行，抽奖时行锁串行化同一用户的请求 |

迁移 `0002_wheel.sql` 删除 0.1 的 `rounds / tickets / prizes`，并写入一组默认奖品（总概率 38.21%）。

## 3. 设置

内核插件设置（`settings_schema`）：`enabled`（默认 false）、`spin_cost`（默认 50）、`daily_limit`（默认 10，0 不限）、`min_account_days`（默认 7）。抽奖管理页直接读写这份设置，也可在“插件设置”中修改。

## 4. 前端

- `/p/lottery/`：SVG 转盘（扇区等分，“谢谢参与”插在中间），中心按钮抽奖；按返回的奖品计算目标角度，CSS 过渡转动 4.6 秒后显示结果；右侧为概率公示、最近中奖、我的记录；
- `/admin/p/lottery/`：开关与参数、奖品表格编辑（上传量以 GiB 填写，概率以 % 填写，实时显示已分配与谢谢参与比例）、今日统计、近 30 天发放；
- 插槽：`nav.main`（“抽奖”）、`home.widgets`（开启时显示消耗与今日次数）；
- 样式在 `web/app/src/app.css` 的 `.lw-*`（CSP 不允许插件内联 `<style>`）。

## 5. 事件与审计

- 事件 `lottery.spun`（键 `user:<id>`）：`spin_id, user_id, cost, currency, prize_id, kind, amount`；
- 审计 `lottery.prizes_update`：每次保存奖品，详情为提交的整表。
