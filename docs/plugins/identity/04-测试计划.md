## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元 | 用户名规范化与混淆检测、邮箱规范化、密码策略、旧哈希验证、TOTP（RFC 6238 附录测试向量）、token 格式与 CRC、有效状态合成、有效权限计算（位图）、rank 比较、挑战令牌派生、IP 截断 | `cargo nextest`、`proptest` |
| 插件集成 | 真实 PG + Redis（testcontainers），内核 testkit 宿主：服务调用、钩子点、事件 outbox、cron / 延迟任务、多副本模拟（两个内核实例共享 PG/Redis） | `pt-testkit` |
| 契约 | 3 个服务 WIT 兼容检查；全部事件载荷、钩子输入、MCP 输入输出按 JSON Schema 校验；OpenAPI 生成 TS SDK 可编译、`oasdiff` 无破坏性变更 | `wasm-tools`、`jsonschema`、`openapi-typescript` |
| 跨插件 | 与 stub 插件（invite / registration-policy 钩子处理者、notify 订阅 `user.challenge_issued` 并拉取、tracker-bridge 订阅 passkey/状态事件、levels 调用 set_class/set_class_roles、mcp 签发 token） | testkit stub |
| 前端 | 登录 / 2FA / 注册 / 设置页组件测试；Playwright：注册 → 验证 → 登录 → 开启 TOTP → 重新登录 → 重置 passkey | Vitest、Playwright、虚拟 WebAuthn 认证器（Chrome DevTools Protocol） |
| 性能 | authenticate、check、登录、注册基准与压测 | criterion、k6 |
| 安全 | 枚举、时序、暴力破解、CSRF、会话固定、敏感数据泄漏扫描、越权（rank / 作用域 / 来源） | 自动化测试 + 日志 / 事件扫描器 |

**通用断言**：每个产生事件的用例都断言事件载荷通过 schema 校验，且序列化后的 JSON 中**不出现**：明文 passkey、邮箱、IP、会话令牌、token、挑战令牌、TOTP 密钥（“敏感扫描器”：在测试中收集事件、日志、审计、指标标签、MCP 输出、错误响应，用已知敏感值做子串搜索）。

## 2. 测试环境与数据

- PostgreSQL 17、Redis 7.4（testcontainers）；内核 testkit 以 Native 方式加载 identity 与 stub 插件；`ctx.time` 可冻结 / 快进。
- `PT_SECRET_KEY` 使用固定测试密钥；GeoIP 使用 MaxMind 官方测试 mmdb（`GeoIP2-City-Test.mmdb` 等，含已知 IP → 国家映射）。
- 种子数据：内置角色；权限点集合（模拟 30 个插件 200 个权限点）；用户 A（user）、B（uploader）、M（moderator，已开 TOTP）、AD（admin）、S（sysop）、P（pending）、X（banned）。
- 性能数据：100 万用户、200 万会话（其中 30 万热会话）、5 万角色授予。
- stub 插件：`t-invite`（钩子：可配置 allow/deny/modify、记录预留）、`t-regpolicy`（作用域 `write:create`）、`t-notify`（`challenges:deliver` + `user.email` 授权）、`t-bridge`（`user.passkey` 授权，订阅 passkey/状态事件并写模拟 `trk:pk`）、`t-levels`（`write:class`、`write:roles`）、`t-ratio`（`write:status`）、`t-mcp`（`tokens:issue`）、`t-noscope`（无任何作用域与授权）。
