## 1. 模块详细设计

### 1.0 公共约定

- crate `pt-plugin-identity`，`pub fn plugin() -> NativePlugin`。所有服务方法第一个参数 `&Ctx`。
- 每次服务调用 / HTTP 请求为一个工作单元（PG 事务）。**缓存删除放在提交之后**：工作单元提供 `after_commit` 回调队列（Native 插件可在 handler 中先 `ctx.sql.commit()` 再执行 Redis 删除；若删除失败则记录指标，缓存最长 TTL 1 h 兜底——对撤销类操作，另将 `users.auth_version` 加 1，缓存条目带版本号，读取时比对，见 §1.3）。
- 时间一律 `ctx.time.now()`；随机一律 `ctx.random.bytes()`（底层 OS CSPRNG）。
- 用户名、邮箱、IP 进入日志前经 `redact::*`：用户名可记录（公开），邮箱、IP、passkey 不记录或打码。

### 1.1 crypto（密钥环）

**输入**：`PT_SECRET_KEY`（内核 `kernel.secret_key`，≥ 32 字节）；静态配置 `crypto.key_versions`（可选，旧主密钥列表，用于轮换）。

**子密钥派生**：`HKDF-SHA256(ikm = master_v, salt = "pt-studio/identity", info = <用途>)`，用途：

| info | 用途 | 算法 |
|---|---|---|
| `passkey-enc` | passkey 加密 | AES-256-GCM，96 位随机 nonce |
| `passkey-mac` | passkey 查找 | HMAC-SHA256 |
| `totp-enc` | TOTP 密钥加密 | AES-256-GCM |
| `challenge` | 挑战令牌派生 | HMAC-SHA256 |
| `ip-mac` | IP 盲化（限流键、同 IP 统计） | HMAC-SHA256 |
| `username-mac` | 失败计数键 | HMAC-SHA256 |
| `email-mac` | 对外邮箱哈希 | HMAC-SHA256 |
| `device-mac` | 设备 cookie 哈希 | HMAC-SHA256 |

**密文格式**：`bytea` = `key_ver(1 B) ‖ nonce(12 B) ‖ ciphertext ‖ tag(16 B)`；AAD = `"<table>:<column>:<user_id>"`（防密文在行间搬移）。

**MAC 列**不带版本（查找需要稳定）：轮换主密钥时 MAC 子密钥保持由 `crypto.mac_master`（默认等于首个主密钥）派生，单独轮换需离线重算（文档化，极少需要）。

**轮换**：新主密钥放在 `key_versions[0]`；新写入使用最新版本；手动任务 `rekey` 分批（1000 行/批，`sql.commit()`）重加密 `key_ver` 较旧的行。

### 1.2 accounts：注册

**用户名规范化**（`canon_username`）：

```
fn canon_username(raw) -> Result<(display, canonical)>:
    s = nfc(raw).trim()
    reject if len_chars(s) ∉ [min_len, max_len]
    reject if any control/format char (Cc, Cf, Zl, Zp), any whitespace inside
    allowed = ASCII [A-Za-z0-9_.-] ∪ (allow_cjk ? Han/Hiragana/Katakana/Hangul : ∅)
    reject if any char ∉ allowed
    reject if starts/ends with [_.-] or contains "..", "__", "--"
    reject if mixed-script ∉ {Latin+Common, Han+Latin+Common, Japanese, Korean}   // UTS #39 restriction level "moderately restrictive"
    canonical = lowercase(confusable_skeleton(s))   // UTS #39 skeleton，crate unicode-security
    reject if canonical ∈ reserved_canonicals
    return (s, canonical)
```

唯一性：`users.username_canonical` 唯一（含软删除用户，见 DDL），另查 `username_history` 中 `hold_until > now()` 的旧名规范形。

**邮箱规范化**：`trim → NFC → 域名 IDNA to ASCII 并小写 → 本地部分按配置 lowercase_local（默认 true）`；格式按 RFC 5321 简化正则 + 长度 ≤ 254；`email_domain` = 规范化后的域名。

**注册算法**：

```
fn register(ctx, req: RegisterRequest, origin: Http|Service{caller}|Admin|Import) -> Result<UserId>:
    (display, canon) = canon_username(req.username)?
    email = canon_email(req.email)?
    password_policy(req.password, display)?                     // §1.5
    if exists(users.username_canonical = canon) or held(canon): Err(identity.username_taken)
    if exists(user_emails.email_canonical = email): Err(identity.email_taken)   // 可配置统一提示，见 §6
    input = {version:1, actor, username: display, email_domain, email: email?, ip: req.ip?,
             invite_code: req.invite_code?, locale: req.locale, form: req.form,
             attributes: {registration_mode: derive_mode(origin, req)} }
    outcome = ctx.hooks.run("user.before_register", input)?
    match outcome:
        Denied(d) => publish? no; metrics(register_denied{by}); return Err(d.code)
        Allowed(final) => attrs = final.attributes
    hash = argon2_hash(req.password)                             // spawn_blocking + 信号量
    passkey = random_hex(16)
    tx:
        uid = INSERT users(username, username_canonical, class_id = attrs.initial_class_id ?? cfg.default_class_id,
                           status = 'active', locale, …) RETURNING id
        INSERT user_emails(uid, email, email_canonical, verified_at = NULL)
        INSERT user_passwords(uid, phc = hash, algo = 'argon2id')
        INSERT passkeys(uid, enc(passkey), mac(passkey), version = 1)
        if attrs.initial_status == 'pending': apply_restriction_tx(uid, pending, source = 'identity:review', reason = attrs.pending_reason ?? 'review')   // 审核通过由 registration-policy/管理员解除（lift-all 或 admin 解除该来源）
        if cfg.require_email_verification and origin != Admin{skip_verify} and origin != Import:
            apply_restriction_tx(uid, pending, source = 'identity', reason = 'email_unverified')
            issue_challenge_tx(uid, email_verify, target = email)
        recompute_status_tx(uid)         // 初始状态，不发 status_changed（由 registered 表达）
        publish user.registered{user_id: uid, username, status, inviter_id: attrs.inviter_id?,
                                registration_mode: attrs.registration_mode, attributes: attrs_public(attrs)}
        security_event(uid, 'registered')
        on unique_violation(users_username_canonical_key | user_emails_email_canonical_key) → Err(taken)
    return uid
```

- `derive_mode`：Import → `import`；Admin → `admin`；Service（registration-policy）→ `application`；Http 且 `invite_code` 非空 → `invite`；否则 `open`。处理者可 modify（★）。
- 钩子处理者的副作用独立提交：invite 在钩子中写的预留若最终因唯一冲突未创建用户，依赖其 TTL 释放（kernel/03 §5.2）。
- `attrs_public` 只保留钩子目录登记的字段（`invite_id`、`inviter_id`、`initial_status`、`initial_class_id`、`tags`、`registration_mode`），丢弃未知字段。

**幂等**：HTTP 注册不声明 `idempotent`（重复提交由唯一约束拒绝）；`ctx.users.create` 带 `idempotency_key`，存 `create_requests(idempotency_key PK, caller, user_id)`，重复调用返回已建 `user_id`。

### 1.3 auth：登录、会话、鉴权

**会话令牌**：32 字节随机 → base64url（43 字符）；`token_hash = SHA-256(token)`。会话公开 ID：`sessions.id`（UUIDv7），用于列表与撤销，也作为 `Principal.credential_id`。

**登录编排**：

```
fn login_password(ctx, username_or_email, password, remember, client) -> LoginResult:
    k_u = mac(username-mac, canon(username_or_email)); k_ip = mac(ip-mac, client.ip)
    throttle_check(k_u, k_ip, client.device_known)?           // §1.9，可能 Err(login_throttled{retry_after})
    user = find_login_target(username_or_email)               // 软删除/purged → None
    ok = match user:
        None => { argon2_verify(DUMMY_PHC, password); false } // 对齐耗时
        Some(u) => verify_password(u, password)               // 可能触发旧哈希迁移 / 参数升级（同事务 UPDATE）
    if !ok: throttle_fail(k_u, k_ip); publish user.login_failed{stage: password}; Err(invalid_credentials)
    if u.status == banned: publish login_failed{stage: status}; Err(account_banned{until?, reason_public?})
    if u.has_2fa:
        ticket = new_2fa_ticket(u.id, method = password, remember, client)    // Redis，5 min，attempts 5
        return NeedSecondFactor{ticket, methods: u.factor_methods}
    finish_login(ctx, u, method = password, two_factor = false, remember, client)

fn finish_login(ctx, u, method, two_factor, remember, client):
    risk = assess(u, client)                                   // new_device / new_region / new_asn
    out = ctx.hooks.run("user.before_login", {user_id, username, method, ip?, new_device★, risk_flags★})
    if Denied(d): publish login_failed{stage: hook}; Err(d.code)
    tx:
        sid = uuid_v7(); token = random(32)
        INSERT sessions(id = sid, user_id, token_hash, created_at, last_seen_at, idle_expires_at, absolute_expires_at,
                        two_factor_at = two_factor ? now : NULL, reauth_at = now, remember, device_id, ua_summary, ip_mac, country)
        upsert_device(u.id, client.device_cookie) → device_id（新设备时生成 cookie）
        ip_log_upsert(u.id, client.ip, source = 'login')
        security_event(u.id, 'login', {method, country, new_device})
        publish user.logged_in{user_id, method, two_factor, session_id: sid, new_device★, risk_flags★, region★?}
    throttle_success(k_u)                                      // 只清用户名维度
    cache_put_session(token_hash, …)
    return Session{token, sid, csrf = random(32), device_cookie?}
```

- `pending` 用户：允许登录，Principal 角色只有 `guest`，额外允许路由白名单（验证、重发、登出、读本人状态）——实现方式：`check_principal` 对 pending 用户只放行 `status.pending_allowed_permissions`（默认 `identity.profile.update_own` 之外不放行；验证/重发路由为 `auth = user` 且无 permission，handler 内部按状态判断）。
- 2FA 第二步 `POST /sessions/two-factor`：取票据（`GETDEL` 原子取出后若失败且 attempts<5 则写回 attempts+1、保持原 TTL），校验 TOTP / 恢复码 / WebAuthn 断言，成功后 `finish_login(two_factor = true)`。

**authenticate**：

```
fn authenticate(ctx, cred) -> Option<Principal>:
    match cred:
      Session{token}:
        h = sha256(token)
        s = redis HGETALL sess:<hex(h)> or { s = pg_load_session(h)?; cache_put(s); s }
        if s.revoked or now > s.idle_expires_at or now > s.absolute_expires_at: return None
        u = user_auth_state(s.user_id)          // Redis uas:<uid>（status, auth_version, roles_ver），缺失 PG 回填
        if u.auth_version != s.auth_version_seen: (重新从 PG 校验会话仍有效；刷新缓存)
        if u.status ∈ {banned, deleted}: return None
        touch(s)                                // 节流：now - s.last_seen_at > 15min 才写；滑动 idle_expires_at
        return Principal{user_id, roles: effective_roles(u), scopes: ["session"], credential: session,
                         credential_id: s.id, two_factor_passed: s.two_factor_at.is_some(), reauth_at★: s.reauth_at}
      Token{secret}:
        parse prefix ∈ {pts_, ptm_}；校验 CRC32；h = sha256(secret)
        t = redis tok:<hex(h)> or pg；检查 revoked/expired/kind 与前缀一致
        u = user_auth_state(t.user_id)；banned/deleted → None；pending → None（token 不给 pending 用户）
        touch_token(t)（节流 5 min）
        return Principal{…, scopes: t.scopes, credential: api_token|mcp_token, credential_id: t.id,
                         two_factor_passed: t.kind == mcp && "admin" ∈ t.scopes}
      FeedKey★{plugin, key}: 同 Token，额外要求 t.kind == feed 且 t.audience_plugin == plugin == invocation.caller_plugin
```

- `touch`：`HSET sess:<h> last_seen_at` 每次都写 Redis（廉价）；PG `UPDATE sessions SET last_seen_at, idle_expires_at` 仅当 `now - pg_last_seen > 15 min`（Redis 字段 `pg_seen_at` 记录），避免每请求写库。IP 变化（`ip_mac` 不同）时同样写 `ip_log` 与会话 `ip_mac`。
- `auth_version`：`users.auth_version` 在“改密码、封禁、重置 2FA、强制下线、删除”时 +1；会话缓存记录加载时的版本，不一致则回 PG 重查（被批量撤销的会话在 PG 中已标记）。

**撤销**：`UPDATE sessions SET revoked_at = now(), revoked_reason` → 提交后 `DEL sess:<h>`。批量撤销（改密码等）：`UPDATE … WHERE user_id = $1 AND id <> $current RETURNING token_hash` → 提交后 pipeline 删除各缓存键，并 `auth_version+1` 兜底。

**近期重新验证**：`POST /sessions/current/reauth {password | totp | webauthn}` → 验证成功 `UPDATE sessions SET reauth_at = now()`（2FA 成功同时设 `two_factor_at`）。需要 reauth 的 handler 调 `require_reauth(principal)`：`principal.credential == session && now - reauth_at ≤ reauth_window`，否则 `identity.reauth_required`（`details.methods`）。token 凭据一律不能执行需要 reauth 的操作。

### 1.4 credentials：TOTP、恢复码、WebAuthn

**TOTP 开启**：`POST /users/me/totp` → 生成 20 字节密钥，`totp_secrets(user_id, enc_secret, confirmed_at = NULL, last_step)` upsert（未确认的覆盖）→ 返回 `otpauth://totp/<site>:<username>?secret=<base32>&issuer=<site>&algorithm=SHA1&digits=6&period=30`。`POST /users/me/totp/confirm {code}` → 校验 → `confirmed_at = now`、生成恢复码 → 发布 `user.two_factor_changed{kind: totp, enabled: true}`、撤销其他会话（可配置，默认否）。

**TOTP 校验**（防重放）：

```
fn verify_totp(uid, code) -> bool:
    row = SELECT enc_secret, last_step FROM totp_secrets WHERE user_id = $1 AND confirmed_at IS NOT NULL FOR UPDATE
    secret = decrypt(row.enc_secret)
    now_step = floor(now / 30)
    for step in [now_step - 1, now_step, now_step + 1]:
        if step > row.last_step and ct_eq(hotp(secret, step), code):
            UPDATE totp_secrets SET last_step = step WHERE user_id = $1
            return true
    return false
```

`FOR UPDATE` + `last_step` 单调保证同一码并发提交只成功一次。

**恢复码**：10 个，格式 `xxxxx-xxxxx`（base32 去歧义字母表，50 位熵）；存 `recovery_codes(user_id, code_hash = SHA-256(salt‖code), salt, used_at)`；使用：`UPDATE … SET used_at = now() WHERE user_id = $1 AND code_hash = … AND used_at IS NULL`（逐个盐比较：最多 10 行，常数时间比较）。

**WebAuthn**（`webauthn-rs`）：

- RP：`rp_id` = 配置或 `site.base_url` 的主机名；`origins` = `[site.base_url]`。
- 登记：`POST /users/me/webauthn/registration-options`（reauth）→ `start_passkey_registration`（或 `start_securitykey_registration`，按“是否允许无密码”）→ 状态序列化写 Redis `wa:reg:<uuid>`（TTL 300 s）→ 返回 `{ceremony_id, public_key: CreationChallengeResponse}`；`POST /users/me/webauthn-credentials {ceremony_id, name, credential}` → `GETDEL` 状态 → `finish_*` → 插入 `webauthn_credentials`（`credential_id` 唯一、`public_key`（序列化的 Passkey/SecurityKey 对象）、`sign_count`、`transports`、`aaguid`、`passwordless`）。
- 断言（2FA）：票据中记录 `wa:auth:<ticket>`；无密码：`POST /webauthn/assertion-options` 生成 discoverable 挑战（Redis `wa:disc:<uuid>`）→ `POST /sessions/webauthn` → 按 `user_handle` 找用户与凭据 → 校验 → 更新 `sign_count`（若认证器返回计数器且未递增 → 拒绝并记安全事件 `webauthn_counter_regression`）→ `finish_login(method = passwordless★, two_factor = true)`。
- 上限 `webauthn.max_credentials`（默认 10）。

**密码校验与迁移**：

```
fn verify_password(u, pw) -> bool:
    row = user_passwords[u.id]
    match row.algo:
      'argon2id' => ok = argon2_verify(row.phc, pw); if ok && params_outdated(row.phc): rehash
      'legacy_nexus_sha256' => ok = ct_eq(sha256_hex(salt ‖ sha256_hex(pw)), row.legacy_hash); if ok: rehash
      'legacy_nexus_md5'    => ok = ct_eq(md5_hex(salt ‖ pw ‖ salt), row.legacy_hash); if ok: rehash
      'legacy_bcrypt'       => ok = bcrypt_verify(row.legacy_hash, pw); if ok: rehash
    rehash: UPDATE user_passwords SET algo='argon2id', phc=argon2_hash(pw), legacy_hash=NULL, salt=NULL, changed_at=changed_at
```

**Argon2 信号量**：每副本 `tokio::sync::Semaphore(cfg.password.max_concurrent_hashes)`（默认 CPU 核数）；`acquire` 超时 2 s → `kernel.service_unavailable`（retryable）。哈希在 `spawn_blocking` 中执行。

**密码策略**：长度（按 Unicode 字符计 ≥ min_length，按字节 ≤ 256）；不得包含用户名（不区分大小写，用户名 ≥ 4 字符时）；泄漏表：构建时把 top 10 万弱密码编译为 `fst::Set`（随 crate 打包，~1 MB），对小写形式查找。

### 1.5 tokens

**格式**：`<prefix><base62(32 字节随机)><base62(CRC32(prefix‖random), 6 位)>`，prefix ∈ `pts_`（api）、`ptm_`（mcp）、`ptf_`（feed）。

**签发**：

```
fn issue(ctx, user_id, kind, scopes, ttl, name, audience_plugin?, issued_by) -> (token_id, secret):
    validate scopes ⊆ allowed_scopes(kind)
        api : {"read","write"} ∪ {"perm:<permission>" …}   // perm: 前缀表示白名单
        mcp : {"read","write","admin"}
        feed: {"feed"}
    if kind == mcp && "admin" ∈ scopes: require rbac.check(user_id, "mcp.admin_tools.use")
    count(active tokens of user, kind) < max_per_user else Err(identity.token_limit_exceeded)
    ttl ≤ max_ttl (feed: 不过期，除非配置)
    secret = format(prefix(kind), random(32)); id = uuid_v7()
    INSERT tokens(id, user_id, kind, name, scopes, token_hash = sha256(secret), audience_plugin, expires_at, issued_by)
    security_event(user_id, 'token_issued', {kind, name}); audit identity.token_issue
    return (id, secret)
```

`feed` 每个 `audience_plugin` 一把：重新生成即撤销旧的（同事务）。

**有效权限**：见 §1.10 `check_principal`。

### 1.6 status：限制与有效状态

**严重度**：`active(0) < leech_disabled(1) < pending(2) < banned(3) < deleted(4)`。

```
fn apply_restriction_tx(uid, kind, source, reason_code, note?, until?, by_user?, idem?) -> RestrictionId:
    if idem and exists(restriction_requests.idempotency_key = idem): return that id
    cur = SELECT … FROM restrictions WHERE user_id=$1 AND kind=$2 AND source=$3 AND lifted_at IS NULL FOR UPDATE
    if cur: UPDATE restrictions SET reason_code, note, until, updated_at, updated_by …; op = updated
    else:   INSERT restrictions(...) RETURNING id; op = applied
    if until: ctx.jobs.schedule_once("restriction_expire", until, {restriction_id}, dedupe = "rx:<id>:<until_ms>")
    publish user.restriction_changed★{…, op}
    recompute_status_tx(uid, trigger_source = source, reason = reason_code)

fn lift_restriction_tx(uid, kind?, source, reason, by_user?, all_sources = false):
    rows = UPDATE restrictions SET lifted_at = now(), lifted_by, lift_reason
           WHERE user_id=$1 AND lifted_at IS NULL AND (all_sources OR source=$src) AND ($kind IS NULL OR kind=$kind)
           RETURNING id, kind, source
    for r in rows: publish user.restriction_changed★{op: lifted}
    recompute_status_tx(uid, trigger_source = source, reason)

fn recompute_status_tx(uid, trigger_source, reason):
    u = SELECT status, status_version FROM users WHERE id = $1 FOR UPDATE
    if u.status == 'deleted': return
    eff = max_severity(SELECT kind FROM restrictions WHERE user_id=$1 AND lifted_at IS NULL AND (until IS NULL OR until > now())) ?? active
    if eff != u.status:
        UPDATE users SET status = eff, status_version = status_version + 1, auth_version = auth_version + (eff == banned ? 1 : 0), updated_at = now()
        publish user.status_changed{user_id, from: u.status, to: eff, reason, until: max_until_of(eff)?, restriction_source★: trigger_source}
        if eff == banned: revoke_all_sessions_tx(uid, 'banned')
        audit identity.status_change {from, to, source, reason}
    after_commit: DEL uas:<uid>, ur:<uid>
```

- `set_status(id, status, reason)`（catalog 方法）语义：`banned|leech_disabled|pending` → `apply_restriction(kind = status, source = caller_plugin)`；`active` → `lift_restriction(kind = None, source = caller_plugin)`；`deleted` → 拒绝（`identity.scope_denied`，删除只能由管理员）。幂等键：`<caller>:<id>:<status>:<reason>` 的哈希（catalog 签名无幂等键参数，重复调用天然幂等：同来源同类型 upsert）。
- 管理员来源记为 `admin`，`created_by` 记录具体管理员；“解除全部来源”需 `identity.users.update` + 原因，审计中列出被解除的每条来源。
- **rank 检查**（管理员操作）：`max_builtin_rank(actor) > max_builtin_rank(target)` 或 actor 有 `sysop`，否则 `identity.insufficient_rank`。插件来源不做 rank 检查（由作用域授权），但**插件不能封禁拥有 `moderator` 及以上角色的用户**（防插件规则误伤员工；配置 `status.plugin_protected_min_role`，默认 moderator），返回 `identity.target_protected`。
- 到期：延迟任务 `restriction_expire{restriction_id}` → `UPDATE restrictions SET lifted_at = until, lift_reason = 'expired' WHERE id=$1 AND lifted_at IS NULL AND until <= now()`；0 行则无操作（幂等）；否则发布 `restriction_changed{op: expired}` + `recompute`。cron `restriction_sweep` 处理遗漏者（每批 500 行，分批提交）。

确认动作：

- `email_verify`：`lift_restriction(kind = pending, source = identity, reason = email_unverified)`（只解除这一条），`user_emails.verified_at = now()`，发布 `user.verified{method: email}`。identity 自身的 pending 限制用两个来源名区分（唯一索引为 user+kind+source）：`identity` = 邮箱未验证，`identity:review` = 注册钩子要求的待审核（registration-policy 以 `ctx.users.create` 建号时一般已审核过，不再产生；管理员可在后台解除）。
- `password_reset`：设置新密码（策略校验）、撤销全部会话与 `auth_version+1`、发布 `user.password_changed`；若用户此前未验证邮箱，同时视为验证成功（拥有邮箱的证明）。
- `email_change`：`user_emails` 更新为 `target_email`（再次检查唯一）、`verified_at = now()`；发布 `user.email_changed`；签发 `email_change_notice_old` 挑战（只通知、无链接动作，投递时 `to` 为旧邮箱，旧邮箱保存在挑战行的 `target_email` 中，投递后 30 天清除）。

### 1.9 risk：限流、设备、IP、GeoIP

**失败计数**（Redis，私有前缀）：

| 键 | 类型 | 说明 |
|---|---|---|
| `lf:u:<hex(mac(username))>` | STRING 计数 | TTL 15 min（首次失败设置） |
| `lf:ip:<hex(mac(ip))>` | STRING 计数 | TTL 1 h |
| `lock:u:<…>` | STRING | 软锁，TTL 15 min |
| `lock:ip:<…>` | STRING | IP 封锁，TTL 1 h |

```
fn throttle_check(ku, kip, device_known):
    if EXISTS lock:ip:<kip>: Err(login_throttled{retry_after = TTL})
    if !device_known and EXISTS lock:u:<ku>: Err(login_throttled{retry_after = TTL})
    n = max(GET lf:u:<ku>, 0)
    if n >= 3: delay = min(2^(n-3), 30) s → 若上次失败时间 + delay > now: Err(login_throttled{retry_after})
        （上次失败时间存在 lf:u 的伴随键 lft:u:<ku>）
fn throttle_fail(ku, kip):
    pipeline: INCR lf:u, EXPIRE lf:u 900 NX, SET lft:u now EX 900, INCR lf:ip, EXPIRE lf:ip 3600 NX
    if lf:u ≥ 10: SET lock:u 1 EX 900; publish login_failed{stage: throttled}（每次上锁一次）
    if lf:ip ≥ 50: SET lock:ip 1 EX 3600
```

Redis 不可用：`throttle_check` 退化为固定 1 s 延迟后继续（fail-safe，不阻断登录），指标 `pt_plugin_identity_throttle_degraded_total`。

**设备**：cookie `__Host-pt_dev`（32 字节随机，HttpOnly、Secure、SameSite=Lax、Max-Age 400 天）；`devices(id, user_id, device_mac, first_seen_at, last_seen_at, ua_summary)`，`(user_id, device_mac)` 唯一。`device_known` = cookie 存在且 `(user_id 候选, device_mac)` 存在——登录前尚不知用户：先按用户名查用户 ID（同一次查询）再判断。

**风险评估**：`new_device` = 设备不存在；`new_region` = 国家码 ∉ 该用户 90 天内 `ip_log.country` 集合（集合为空时为 false，首次登录不提醒）；`new_asn` 同理；`after_reset` = 24 h 内发生过密码找回。

**GeoIP**：`geoip.mmdb_path`（City/Country）与 `geoip.asn_mmdb_path`，启动时加载（`maxminddb` crate，内存映射）；未配置时 country/asn 为空，`new_region`/`new_asn` 不产生。

**IP 记录**：

```
fn ip_log_upsert(uid, ip, source):
    INSERT INTO ip_log(user_id, ip, ip_mac, source, country, asn, first_seen_at, last_seen_at, hits)
    VALUES (...) ON CONFLICT (user_id, ip_mac, source, first_seen_month) DO UPDATE SET last_seen_at = now(), hits = ip_log.hits + 1
```

`ip_log` 按 `first_seen_month`（date，月初）范围分区；唯一键含分区键，同一 IP 跨月会产生新行（可接受，便于按月删除）。

**保留期任务** `ip_retention`：

```
batch loop (1000 rows, commit each):
  UPDATE ip_log SET ip = network(set_masklen(ip, CASE family(ip) WHEN 4 THEN 24 ELSE 48 END)), truncated = true
  WHERE NOT truncated AND last_seen_at < now() - truncate_after
  （ip_mac 保留不变，仍可做“同 IP”统计直至删除；如配置 strict_privacy = true 则 ip_mac 一并置空）
分区：delete_after_days 由 [[database.partitions]] retention 处理（retention_months = ceil(365/30)+1）
```

### 1.10 rbac

**数据**：`permissions`（名、插件、说明术语键、default_roles、orphan）、`roles`（名、kind = builtin/plugin/custom、owner_plugin、rank（仅内置：guest 0 … sysop 5）、name_term）、`role_permissions`、`user_roles(user_id, role, expires_at, granted_by)`、`class_roles(class_id, role, owner_plugin)`、`permission_overrides(user_id, permission, effect, expires_at)`。

**进程内快照**（每副本一份，`ArcSwap<RbacSnapshot>`）：

```rust
struct RbacSnapshot {
    version: u64,
    role_perms: HashMap<RoleId, RoaringBitmap>,   // 权限点编号位图，内置角色已展开继承
    perm_index: HashMap<String, u32>,            // 权限名 → 编号
    class_roles: HashMap<u32, Vec<RoleId>>,
    status_mask: HashMap<UserStatus, RoaringBitmap>,
    two_factor_roles: HashSet<RoleId>,           // two_factor.required_roles 及以上
    all_perms: RoaringBitmap,                     // sysop

```

刷新：每次调用前若 `now - last_check > 1 s`：`GET rbac:ver`（Redis）≠ 本地 → 从 PG 重建（< 50 ms，单飞锁）。任何 RBAC 定义写入：提交后 `INCR rbac:ver`。

**用户有效角色**（Redis `ur:<uid>` HASH：`roles`（逗号分隔）、`class_id`、`status`、`overrides`（JSON，可空）、`ver`），缺失时：

```
roles = base_roles(status)                               // pending→guest；active/leech_disabled→user；banned/deleted→∅
      ∪ { r FROM user_roles WHERE user_id = $1 AND (expires_at IS NULL OR expires_at > now()) }
      ∪ class_roles[users.class_id]
```

TTL 10 min；`set_class`、角色授予 / 撤销、覆盖变更、状态变化后提交即 `DEL ur:<uid>`。

**检查**：

```
fn check_principal(p, perm, safe_method) -> bool:
    if p.user_id is None: roles = {guest} else ur = load_user_roles(p.user_id)
    snap = snapshot()
    if "sysop" ∈ roles: base = snap.all_perms
    else: base = ⋃ snap.role_perms[r] for r in roles
    // 2FA 强制：会话未通过 2FA 时，剔除需要 2FA 的角色的贡献
    if p.credential == session && !p.two_factor_passed && roles ∩ snap.two_factor_roles ≠ ∅:
        base = ⋃ role_perms[r] for r in roles \ two_factor_roles
    bits = base ∪ overrides.allow − overrides.deny − snap.status_mask[status]
    if perm is empty: ok = true else ok = perm ∈ snap.perm_index && bits.contains(idx(perm))
    // token scope
    match p.credential:
      api_token: if !safe_method && "write" ∉ p.scopes: ok = false
                 if any "perm:*" in scopes: ok = ok && ("perm:" + perm) ∈ p.scopes
      mcp_token: 由 mcp 网关按 read/write/admin 约束工具；此处：!safe_method && "write" ∉ scopes → false
      feed:      ok = ok && safe_method
    return ok
fn check(user_id, perm) = check_principal(session_principal_of(user_id, two_factor_passed = true), perm, true)
```

> 未合入 ★`check_principal` 前，内核网关调用 `check(user_id, perm)`：token 的只读约束无法生效，token scope 只支持 `read`/`write` 不生效的退化——上线前必须合入，见 HLD Q-IDN-2。

**未知权限点**：`check` 返回 false 并计数 `pt_plugin_identity_unknown_permission_total{permission}`（插件拼错权限名可被发现）。

**register_permissions**：

```
fn register_permissions(ctx, defs):
    require invocation.caller_plugin == "kernel"
    tx:
      for d in defs: INSERT permissions(name, plugin_id, description_term, default_roles, orphan=false, last_seen_at=now())
                     ON CONFLICT (name) DO UPDATE SET description_term = EXCLUDED.description_term, orphan = false, last_seen_at = now()
                     RETURNING (xmax = 0) AS inserted
                     if inserted: for r in d.default_roles: INSERT role_permissions(r, name) ON CONFLICT DO NOTHING
      UPDATE permissions SET orphan = true WHERE last_seen_at < now() - interval '1 minute' AND NOT orphan  // 本次未出现
    INCR rbac:ver
```

多副本同时启动时并发执行：`INSERT … ON CONFLICT` 保证只有一个副本看到 `inserted = true`，默认授权只发生一次。孤立判定改为“本次 defs 中不存在的名字”（用 `name <> ALL($names)`），避免依赖时钟。

**define_role / grant_role / set_class_roles**：

- `define_role(role, permissions)`：`role` 必须匹配 `^<caller_plugin>:[a-z0-9_]{1,48}$`；`permissions` 必须全部已登记；整体替换 `role_permissions`（事务内 DELETE + INSERT）；结果相同则不改版本号。
- `grant_role(user_id, role, expires_at)`：插件只能授予自己前缀的角色；管理员经 HTTP（`identity.roles.assign` 只能授予 rank < 自己最高 rank 的内置角色及非内置角色；`identity.roles.manage` 无限制，但授予 `sysop` 需要 sysop）；`user_roles` upsert；提交后 `DEL ur:<uid>`；有 `expires_at` 时调度 `grant_expire`；发布 `user.roles_changed{added: [role]}`（已有同角色且到期时间不同只更新，不发事件）。
- `set_class_roles(class_id, roles)`：调用方须同时持有 `write:roles` 与 `write:class`；`roles` 只能是调用方前缀的角色或内置 `uploader` 以下角色（不能借等级给出 moderator 及以上）；整体替换该 class 的绑定；`INCR rbac:ver`（快照包含 class_roles）。

**rank**：`max_rank(user) = max(roles ∩ builtin).rank`；被比较用户包含其 class 绑定的内置角色。

### 1.12 jobs 与 cron（幂等说明）

| 任务 | 幂等方式 |
|---|---|
| `restriction_expire`（延迟） | `UPDATE … WHERE lifted_at IS NULL AND until <= now()`，二次执行 0 行 |
| `grant_expire` / `override_expire` | `DELETE … WHERE id = $1 AND expires_at <= now()`，0 行即结束；发布事件仅在删除成功时 |
| `restriction_sweep` / `grant_sweep` | 同上条件批量 `FOR UPDATE SKIP LOCKED LIMIT 500`，与延迟任务并发也不重复 |
| `session_gc` | `DELETE … WHERE (absolute_expires_at < now() - 30d) OR (revoked_at < now() - 30d)` 批量 |
| `challenge_gc` | 删除 `expires_at < now() - 7d` |
| `ip_retention` | 条件 `NOT truncated` |
| `passkey_history_scrub` | 条件 `passkey_enc IS NOT NULL` |
| `account_purge` / `account_purge_due` | 条件 `executed_at IS NULL AND due_at <= now() AND cancelled_at IS NULL`，执行后写 `executed_at` |
| `token_expiry_notice` | `tokens.expiry_notified_at IS NULL` 条件 + 设置 |

全部 cron `tx = "manual"`、分批提交、`catch_up = "once"`（gc 类为 none）。

### 1.13 并发与一致性要点

- 用户名 / 邮箱唯一：数据库唯一约束为最终裁决。
- 限制与状态：`recompute` 前 `SELECT users … FOR UPDATE` 串行化同一用户的状态变更。
- passkey：`passkeys` 行锁；bridge 端按 `passkey_version` 单调覆盖。
- TOTP 防重放：行锁 + `last_step`。
- 2FA 票据：`GETDEL` + 写回，单票据并发尝试最多一个成功。
- WebAuthn 仪式状态：`GETDEL`，只能完成一次。
- 事件：全部在业务事务中发布（outbox），回滚则不发。

### 2.3 钩子

#### `user.before_register`（拥有者）

输入 schema `schemas/hooks/user.before_register.json`：

```json
{
  "version": 1,
  "actor": { "kind": "anonymous" },
  "username": "Alice_01",
  "email_domain": "example.com",
  "email": "alice@example.com",
  "ip": "203.0.113.7",
  "invite_code": "INV-7F3K-92QX",
  "locale": "zh-CN",
  "form": { "answers": { "q1": "b" }, "captcha": { "id": "…", "answer": "…" } },
  "attributes": { "registration_mode": "invite" }
}
```

- `email`、`ip`：内核按处理者授权裁剪（评审 R1 B-05 已接受）；identity 总是放入，另放入非敏感的 `ip_hmac`（HMAC(ip)）、`ip_prefix_hmac`（IPv4 /24、IPv6 /48 的 HMAC）、`device_hmac`（设备 cookie 的 HMAC，无则缺省），供 invite、registration-policy、anticheat 做关联而不接触原始 IP。
- 可修改：`attributes.invite_id`、`attributes.inviter_id`、`attributes.initial_status`、`attributes.initial_class_id`、`attributes.tags`、★`attributes.registration_mode`、★`attributes.pending_reason`、★`attributes.pending_source`（合入后 pending 限制的来源取该值，否则为 `identity:review`）。
- 超时 500 ms，失败策略 deny（锁定）；管线总预算 1500 ms。deny → 使用错误码在 error-codes 目录登记的状态，未登记时按后缀规则（评审 R1）。

#### `user.before_login`

输入：`{version, actor, user_id, username, method, ip?, new_device★, risk_flags★[]}`；只允许 allow / deny；200 ms；fail-open。

#### `user.before_rename`

输入：`{version, actor, user_id, old_username, new_username}`；allow / deny；200 ms；deny（失败即拒绝）。

#### `user.before_title_change`（评审 R1 新增）

触发：`set_title` 与用户自助修改头衔（若站点开启）在写入前。输入：`{version, actor, user_id, old_title?, new_title}`；allow / deny / modify `new_title`（修改后仍按 ≤ 32 字符、禁止控制字符校验）；200 ms；deny。清除头衔（`new_title = null`）不触发。预期处理者：shop（头衔卡）、moderation（敏感词）、levels（等级限制）。

```sql
  ('guest','builtin',0,'identity.role.guest'), ('user','builtin',1,'identity.role.user'),
  ('uploader','builtin',2,'identity.role.uploader'), ('moderator','builtin',3,'identity.role.moderator'),
  ('admin','builtin',4,'identity.role.admin'), ('sysop','builtin',5,'identity.role.sysop')
ON CONFLICT DO NOTHING;

-- ========== 对外只读视图 ==========
CREATE VIEW v_user_public WITH (security_barrier = true) AS
SELECT id, username, class_id, status, created_at
FROM users WHERE deleted_at IS NULL;

CREATE VIEW v_user_email WITH (security_barrier = true) AS
SELECT u.id, e.email
FROM users u JOIN user_emails e ON e.user_id = u.id
WHERE u.deleted_at IS NULL;
```

## 6. 安全设计

| 方面 | 措施 |
|---|---|
| 权限校验点 | 路由级由网关检查 permission；handler 内再做：本人资源归属、rank、reauth、凭据类型（passkey 展示只接受会话）、作用域（服务调用 `caller_scopes`）、敏感能力（`ctx.plugins.has_sensitive(caller, cap)`） |
| 输入校验 | OpenAPI schema + 业务校验；用户名 / 邮箱规范化；`avatar_url` 只允许 https 且主机在 `site.toml` 图片白名单（或对象存储公共域）；`next` 跳转只允许 `/` 开头且不以 `//` 开头 |
| 枚举防护 | 登录统一错误 + 假哈希对齐耗时；找回永远 202；验证 / 找回确认统一 `challenge_invalid`；`GET /users?username=` 需登录且限流 |
| 会话安全 | `__Host-` cookie；登录后新令牌；CSRF 双提交（内核检查）；改密码 / 封禁 / 2FA 重置撤销会话；会话 ID 与令牌分离（列表、日志只见 ID） |
| 敏感数据处理 | 见下表；序列化结构体中敏感字段使用 `Secret<String>` 包装（`Debug` 打码、`Serialize` 禁止，除非显式 `expose()`），事件载荷类型不含任何 `Secret` 字段（编译期保证） |
| 审计 | 动作：`identity.status_change`、`identity.restriction_apply/lift`、`identity.class_change`、`identity.role_grant/revoke`、`identity.role_define`、`identity.override_set`、`identity.rename`、`identity.passkey_reset`、`identity.two_factor_reset`、`identity.sessions_revoke`、`identity.token_issue/revoke`、`identity.sensitive_read`、`identity.user_delete`、`identity.user_create`、`identity.verify`；details 只含 ID、原因码、前后值（非敏感） |
| 防暴力 | 登录、2FA 票据 5 次、恢复码、挑战确认均限流；TOTP 防重放 |
| 依赖安全 | Argon2 / AES-GCM / HMAC 使用 RustCrypto；WebAuthn 使用 webauthn-rs；常数时间比较 `subtle` |
| 内部攻击面 | 插件即使获得 `write:status` 也不能封员工（`target_protected`）；`define_role` 不能给出别人前缀的角色；`set_class_roles` 不能绑定 moderator 及以上 |

敏感数据一览：

| 数据 | 存储 | 对外 |
|---|---|---|
| 密码 | Argon2id PHC | 永不 |
| 会话令牌 / token / 挑战令牌 / 恢复码 / 设备 cookie | SHA-256 或 HMAC | 只在创建时返回一次（挑战令牌经 `challenge_delivery`） |
| passkey | AES-GCM + HMAC | 本人会话、`get_sensitive`/`passkey_material`（授权 + 审计） |
| TOTP 密钥 | AES-GCM | 只在开启时返回一次 |
| WebAuthn 凭据对象 | jsonb（公钥，非秘密但按 `user.webauthn` 处理） | 不对外 |
| 邮箱 | 明文（独立表） | 本人、`identity.users.read_sensitive`、`v_user_email`（授权） |
| IP | inet，90 天后截断 | 本人（截断形式）、read_sensitive、`user.ip` 授权插件 |

## 7. 性能设计

| 热点 | 设计 | 目标 |
|---|---|---|
| `authenticate`（每请求） | Redis 1 次 `HGETALL sess:*` + 1 次 `HGETALL uas:*`（pipeline 合并为 1 次往返）；PG 写节流 15 min；内核 principal 缓存 5 s 进一步削减 | p99 < 1 ms；5 万 rps 全站 → Redis ~1 万 ops/s（考虑 5 s 缓存命中） |
| `check_principal` | 进程内位图；`ur:<uid>` Redis 读取与 authenticate 合并（Principal 中带 roles，check 时复用；仅 `check(user_id)` 服务调用需额外读取） | p99 < 0.2 ms |
| 登录 | Argon2 ~25 ms（19 MiB, t=2）；信号量 = 核数；8 核单副本 ~300 次/s | 峰值 50 次/s 全站，单副本即可 |
| 注册 | Argon2 + 钩子（≤ 500 ms）+ 单事务 | p99 < 800 ms |
| `get_many` | `WHERE id = ANY($1)`，≤ 500 | p99 < 10 ms |
| 批量撤销 | 单条 UPDATE … RETURNING + Redis pipeline | |
| cron | 每批 500～1000 行并提交；`FOR UPDATE SKIP LOCKED` | 不持有长事务 |
| RBAC 重建 | 单飞（`tokio::sync::OnceCell` 风格），全表 < 1 万行 | < 50 ms |
