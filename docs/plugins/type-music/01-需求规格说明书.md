## 1. 引言

### 1.1 目的

定义音乐资源类型插件 `type-music` 的需求。共用部分见 [../_shared/content-types-common.md](../_shared/content-types-common.md)。

### 1.2 范围

包含：专辑 Group（艺人 + 发行组）、版本（Edition：介质、年份、厂牌、目录号、版本名，即 Gazelle 的 remaster）、种子格式字段（格式、码率 / 编码、介质、log / cue、log 分数）、发行类型（专辑、EP、单曲、合辑、原声、现场等）、艺人（多艺人与角色）、标题规范、文件校验（音频文件、log、cue）、基础 log 检查、去重与替代、搜索字段、元数据（MusicBrainz）。

不包含：完整的 EAC / XLD 日志核验（基础检查在本插件，深度核验留给可选的 `log-checker` 扩展）；有声书（归 type-generic）。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 发行组（release group） | 同一作品的所有发行，MusicBrainz 概念 |
| 版本（edition / remaster） | 具体的一次发行：介质 + 年份 + 厂牌 + 目录号 + 版本名 |
| log | CD 抓轨软件（EAC、XLD 等）生成的日志，用于证明抓轨质量 |
| 编码 | Lossless、24bit Lossless、320、V0（VBR）、V2、256、192 等 |

### 1.4 参考资料

- 共用设计
- Gazelle / OPS / RED：torrent group（艺人 + 专辑）、remaster（年份、厂牌、目录号、标题）、format / encoding / media、log score、trump 规则（只借鉴思路，不复制代码）
- MusicBrainz：release group、release、artist credit
- NexusPHP 系音乐站：中文艺人名、专辑分类

## 2. 总体描述

WASM，ID `type-music`，`type_id = "music"`；导出 `content-type`、`search-contributor`；钩子与订阅同 type-movie。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle（OPS / RED） | 艺人 → 专辑 Group → remaster 版本 → 格式种子；log 分数与 trump 规则；艺人页 | 音乐站事实标准，冗余极少 | 模型硬编码在核心中，其他资源类型难以复用 | **采纳**整套层级、log 分数、trump；**改进**：作为插件实现，核心只有 Group / 种子两层，版本用 `edition_key` 表示 |
| NexusPHP | 音乐作为普通分类，平铺 | 简单 | 无专辑聚合 | 不采用 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TMUS-001 | 类型信息 | `info()` | P0 | |
| FR-TMUS-002 | 艺人 | Group 有一个或多个艺人（角色：main、guest、composer、conductor、producer、remixer、dj），可带 MusicBrainz artist MBID | P0 | |
| FR-TMUS-003 | 发行类型 | album、ep、single、compilation、soundtrack、live、remix、anthology、mixtape、bootleg、interview、other | P0 | |
| FR-TMUS-004 | 分组 | `music:mbrg:<release-group MBID>`；无 MBID 时 `music:title:<主艺人规范名>:<专辑规范名>:<原始年份>` | P0 | |
| FR-TMUS-005 | 版本 | 种子字段 `edition_year`、`edition_label`、`edition_catalog`、`edition_title`、`media`；`edition_key` 由这些字段规范化后计算 | P0 | 同一版本的不同格式归为一组 |
| FR-TMUS-006 | 格式字段 | `format`（FLAC、MP3、AAC、ALAC、DSD、Opus、AC3、DTS、WavPack、APE……）、`encoding`、`has_log`、`log_score`、`has_cue`、`scene` | P0 | |
| FR-TMUS-007 | 文件校验 | 至少一个与 format 对应扩展名的音频文件；有 log 时存在 `.log`；有 cue 时存在 `.cue`；禁止可执行文件 | P0 | |
| FR-TMUS-008 | log 基础检查 | 上传时可附 log 文本（字段 `logs[]`，≤ 5 个、各 ≤ 512 KiB）：识别软件（EAC / XLD / whipper / CUERipper）、读取偏移、精确模式、AccurateRip 结果等关键行，给出 0～100 的估算分数与问题列表 | P1 | 典型 log 得分与参考值一致（测试向量） |
| FR-TMUS-009 | 标题规范 | `{artists} - {album} [{original_year}] [{media} {format} {encoding}]` 等 | P0 | |
| FR-TMUS-010 | 去重 | 同 Group、同 edition_key、同 format+encoding 重复 | P1 | |
| FR-TMUS-011 | 替代 | 同版本内：有 log 且分数高 > 无 log；100 分 log + cue > 100 分无 cue；Lossless 与 24bit Lossless 各自独立；MP3 V0 与 320 并存，无法与 Lossless 比较 | P2 | |
| FR-TMUS-012 | 搜索字段 | `music_artists`、`music_release_type`、`music_format`、`music_encoding`、`music_media`、`music_has_log`、`music_log_score`、`music_label`、`music_catalog` | P0 | 可按“FLAC + CD + log 100”筛选 |
| FR-TMUS-013 | 艺人检索 | 按艺人查询所有 Group（经 search groups 索引的 `music_artists` 字段） | P1 | 艺人页列出作品 |
| FR-TMUS-014 | 元数据 | MusicBrainz：发行组标题、艺人、原始年份、发行类型、封面（Cover Art Archive） | P1 | |
| FR-TMUS-015 | 管理配置 | 格式与编码枚举、trump 规则开关、log 检查开关 | P1 | |

## 4. 非功能需求

normalize p99 < 5 ms；log 检查（单个 512 KiB）p99 < 100 ms——因此 log 检查不在钩子中同步执行，而是在 `torrent.created` 后异步执行（钩子只检查 log 是否存在与大小）。

## 5. 可配置项与站点术语

`required_mbid`（false）、`formats`、`encodings`、`trump_enabled`（true）、`log_check_enabled`（true）、`title_template`、`dupe_policy`。术语 `type-music.name`、`type-music.field.<field>`、`type-music.release_type.<type>`、`type-music.artist_role.<role>`。

## 6. 外部接口需求概述

同 type-movie；另订阅 `torrent.created`（异步 log 检查）；HTTP 增加 `POST /api/p/type-music/v1/log-check`（上传前预检，user 权限，限流）。
