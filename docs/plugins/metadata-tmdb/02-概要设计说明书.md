## 1. 设计目标

遵循共用设计；用 TMDB 的 `append_to_response` 一次请求获取详情、外部 ID、图片、翻译，减少调用次数。

## 2. 总体结构

模块：`client`（HTTP、鉴权、限速、重试、熔断）、`mapper`（TMDB → 统一模型，类型映射表）、`cache`、`images`（转存）、`api`（HTTP 路由）。

## 3. 对外接口清单

| 类别 | 内容 |
|---|---|
| 导出 | `metadata-provider` |
| 能力 | `sql`、`redis`、`blob`；`http_outbound = ["api.themoviedb.org", "image.tmdb.org"]` |
| 发布事件 | `metadata.fetched` |
| HTTP（`/api/p/metadata-tmdb/v1`） | `GET /lookup?id=movie:603&locale=zh-CN`、`GET /search?q=&type=movie`（user，`user:30/m`）；`POST /admin/refresh/{id}`（`metadata-tmdb.refresh`） |
| cron | `refresh_stale`（`10 3 * * *`） |
| 权限点 | `metadata-tmdb.manage`、`metadata-tmdb.refresh`（已登记） |

## 4. 数据设计概要

`cache`（external_id、locale、data、not_found、fetched_at、last_used_at）。

## 5. 关键流程

```
lookup(id, locale):
  c = cache[(id, locale)]；未过期 → return
  if 熔断中 → return c（stale）或 None
  rl.acquire()（Redis 令牌桶，等待 ≤ 2 s，否则返回 stale / service_unavailable）
  电影：GET /3/movie/{id}?language=<locale>&append_to_response=external_ids,images,translations,credits,release_dates
       include_image_language=<lang>,null
  剧集：GET /3/tv/{id}?…&append_to_response=external_ids,images,translations,credits,content_ratings
  单季：GET /3/tv/{id}/season/{n}?language=<locale>
  imdb：GET /3/find/{tt}?external_source=imdb_id → 取 movie_results / tv_results 第一项 → 递归 lookup
  mapper → data；images 转存；UPSERT cache；数据有变化 → publish metadata.fetched
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-MDTMDB-1 | 外部 ID 编码 | `movie:<id>` / `tv:<id>` / `tv:<id>:s<n>` / `imdb:<tt>`：TMDB 电影与剧集 ID 空间重叠，必须带类型前缀 |
| DD-MDTMDB-2 | 演员数量 | 只取前 20 名演员与导演 / 编剧：控制数据量 |
| DD-MDTMDB-3 | 商业确认 | 静态配置 `commercial_ack` 未设置时插件仍可用，但后台显示条款提示；是否合规由站点负责 |

## 7. 对平台契约的新增

无（`metadata.fetched` 已登记）；前端署名组件 `<Attribution>` 由 web 组件提供（docs/components/web）。
