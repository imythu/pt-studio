## 1. 设计目标与原则

1. **配置即类型**：kind 定义（受限的字段描述语言）编译为 JSON Schema，供上传表单、校验、搜索使用。
2. **单一 type_id**：对 torrent 与搜索而言只有 `generic` 一个类型；`kind` 是种子字段与 Group 字段。这样新增 kind 不需要重启、不需要内核重新登记类型。
3. **字段命名隔离**：搜索字段 `generic_<kind>_<field>`，避免不同 kind 同名字段语义冲突。

## 2. 总体结构

模块：`kinds`（定义 CRUD、预设、编译为 JSON Schema、版本号）、`normalize`（按 kind 校验）、`grouping`、`rules`（文件规则、标题）、`meta`（external-id 绑定的元数据源）、`search`（动态 index-schema）。

## 3. 对外接口清单

同 type-movie（ID / 前缀替换为 `type-generic` / `generic_`）。`info()` 返回的 `field-schema` 为 `oneOf`（按 `kind` 判别）的组合 schema；`group-schema` 同理。

搜索：`index-schemas()` 动态生成（kind 变化后 search 需重新合并 schema——search 的 schema 合并在启动时与 `search.reindex` 时执行；本插件在 kind 变化后调用 `ctx.search.reindex("torrents")`（作用域 `admin`）或提示管理员在 search 后台重建，见 §7）。

## 4. 数据设计概要

`kinds`（kind、definition JSON、version、active）、`group_meta`、`vocab`（选项映射）。

## 5. 关键流程

```
kind 定义 → compile(def) → JSON Schema（含 x-pt-* 扩展）→ 存 kinds.compiled；kv "schema_ver" +1；terms.define 名称与选项
normalize(fields): kind = fields.kind（必填，且为 active kind）→ 用 compiled schema 校验 → 规范化（trim、枚举映射）
group_key: def.group_fields 非空 → "generic:" + kind + ":" + join(规范化字段值, ":")；否则 none
canonical_title: render(def.title_template, fields)
钩子：def.files 规则；标题策略
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-TGEN-1 | 每个 kind 一个 type_id 还是共用 | 共用 `generic`：类型注册在内核启动时完成（D4），动态新增 type_id 需要重启；kind 作为字段可即时生效 |
| DD-TGEN-2 | 字段描述语言 | 受限子集（§1 字段类型）而非任意 JSON Schema：保证可生成表单、筛选、搜索映射，且校验开销有界 |
| DD-TGEN-3 | 索引字段变化 | 新增 kind 或字段需要 search 合并 schema 后重建索引（swap，零停机）；删除字段不触发重建 |

## 7. 对平台契约的新增

共用设计 §9；请 search-meilisearch 支持“贡献者 schema 运行时变化”：提供 `ctx.search.refresh_schema(contributor)`（只在新增字段时更新设置与重建受影响索引），否则本插件只能调用 `reindex`；术语动态键见 SRS §5。
