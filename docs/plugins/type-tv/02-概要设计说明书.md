## 1. 设计目标与原则

与 type-movie 相同；差异：分组粒度为“剧集 + 季”，种子带范围（scope），校验季集与文件一致。

## 2. 总体结构

模块与 type-movie 相同（`schema`、`normalize`、`grouping`、`rules`、`meta`、`search`），另加 `episodes`：从文件名解析集号（`S\d+E\d+`、`E\d+`、`第\d+集`、`\[\d+\]`），计算范围一致性。

## 3. 对外接口清单

与 type-movie 03 §3 相同，插件 ID / 前缀替换为 `type-tv` / `tv_`；scopes `ctx.torrents = ["write:group"]`；权限点 `type-tv.manage`。

## 4. 数据设计概要

`group_meta`（同 type-movie，另存 `episode_count`、`season_name`）、`trumps`、`vocab`。

## 5. 关键流程

```
normalize:
  ids 提取（themoviedb.org/tv/<id>、imdb tt…、douban subject）
  release_name 解析：season、episode、episode_end；"Complete"/"全集" → scope = complete；"S01"（无 E）→ season_pack
  中文：第X季 → season；更新至 EXX / 连载 → ongoing = true
  scope 一致性：episode → 需要 episode；episodes → episode < episode_end；season_pack → episode 为空；complete → season = 0
group_key: "tv:" + scheme + ":" + id + ":s" + pad2(season)
canonical_title: "{title} {season_tag} {resolution} {source} {video_codec} {audio_codecs?}-{release_group?}"
   season_tag = S01 | S01E02 | S01E02-E05 | Complete
rules（钩子）:
  视频文件数 n；episode → n ≥ 1 且文件名集号 ∈ {episode}；episodes → 集号 ⊆ [episode, episode_end]；
  season_pack → 若 group_meta.episode_count 已知：n ≥ ceil(count × min_ratio)（ongoing 时不检查）
  不一致 → pending + episode_mismatch
  去重：同 Group、同 scope、同（season, episode, episode_end）、同规格
  trump：完结季包 vs 单集 / 连载季包；rank 同 type-movie
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-TTV-1 | 分组粒度 | 剧集 + 季：每季作为独立作品页（大多数 PT 站按季发布与浏览）；剧集总览页由前端按 `tmdb_tv_id` 聚合各季 Group |
| DD-TTV-2 | 合集 | season = 0 的独立 Group，避免把多季合集归入某一季 |
| DD-TTV-3 | 集数校验严重程度 | 不拒绝，只转人工：文件命名差异大，误判代价高 |

## 7. 对平台契约的新增

共用设计 §9；术语 `type-tv.scope.<scope>`；建议 torrent 提供按外部 ID 聚合多个 Group 的查询（`GET /v1/groups?type_id=tv&field.tmdb_tv_id=`），或由 search 的 `groups` 索引完成（推荐后者，无需新增）。
