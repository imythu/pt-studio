## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元 | 条目解析、eid 去重、聚合、倍率合并（proptest：favorable 结果单调、override 优先级）、信号规则、窗口/小时划分、Lua 扣减比较函数、重算公式 | `cargo nextest`、`proptest` |
| 集成 | 真实 PG 17 + Redis 7.4（testcontainers）+ pt-testkit 内核宿主：分区 worker、落库 SQL、窗口关闭、快照、swarm、对账、重算、事件发布与订阅 | `pt-testkit` |
| 契约 | 事件载荷符合 `schemas/events/*.json`；WIT 兼容检查；OpenAPI 与清单一致、`oasdiff`；MCP 输入输出 schema | `jsonschema`、`wasm-tools`、`oasdiff` |
| 一致性/混沌 | 参考实现（纯内存模型）与系统输出逐字段比对；随机杀进程、断 Redis、PG 故障切换、租约漂移 | 自研 harness（`xtask chaos-acct`） |
| 性能 | 合成流生成器（按 design/03 §3 的分布生成 3000 万 peer 的 announce）；单副本/多副本吞吐、延迟、PG 写入、事件量 | `xtask loadgen-acct`、Prometheus |
| 安全 | 敏感字段不外泄、权限、输入校验、越权移除规则 | 集成 + 静态扫描 |
| 前端 | 插槽组件、批量列请求合并 | Vitest、Playwright |

参考实现：`tests/model.rs` 以最朴素的方式（逐条、无批处理）计算期望的 snatch、总量、每日、事件，所有集成用例的“预期结果”以它为准。

## 2. 测试环境与数据

| 环境 | 配置 |
|---|---|
| CI 集成 | PG 17、Redis 7.4 单实例（acct 与 main 同实例不同前缀）、N=8、W=300、1～3 个内核副本（同进程多实例模拟） |
| 性能 | PG 17（16 vCPU / 64 GB / NVMe）、Redis acct 独立实例、3 个 pt-server 副本（8 vCPU）、N=64、W=900 |
| 数据 | 种子镜像 100 万（体积对数正态分布 100 MB～100 GB）；用户 30 万；peer 3000 万；传输活动比例 15%；促销规则 2 万条（含全站 1 条、自动促销 1.5 万种子） |

时间控制：pt-testkit 冻结 `ctx.time`；流条目 ID 由测试显式指定（`XADD acct:p <ms>-<seq>`）以构造窗口与小时边界。
