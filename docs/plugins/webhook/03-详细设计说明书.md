## 1. 模块详细设计

### 1.1 sanitize：外发字段白名单

| 事件 | 允许字段 | 附加 |
|---|---|---|
| `torrent.created` | `torrent_id, group_id, type_id, size, status`；`uploader_id` 仅当 `anonymous = false` | `title`、`url`（视图） |
| `torrent.status_changed` | `torrent_id, from, to` | `title`、`url` |
| `request.created` | `request_id, type_id, bounty, currency` | `title`（requests 视图 ⊕ 需含 title）、`url` |
| `request.filled` | `request_id, torrent_id` | `url` |
| `forum.topic_created` | `topic_id, forum_id` | `url`（只在版块为公开可读时外发，否则丢弃整条） |
| `promotion.started` / `ended` | `promotion_id, scope, kind, torrent_ids（≤ 50）, starts_at, ends_at` | — |
| `moderation.decided` | `target, decision` | — |
| `report.created` | `case_id, target_kind, reason_code` | — |
| `user.registered` | 无字段（只计数），可配置附加 `user_id` | — |
| `search.index_rebuilt` | `index, documents, duration_ms` | — |

外发载荷：

```json
{ "id": "<event_id>", "type": "torrent.created", "occurred_at": "…", "site": "<site_url>",
  "data": { "torrent_id": 5501, "type_id": "movie", "size": 53687091200, "status": "approved",
            "title": "…", "url": "https://site/torrents/5501" } }
```

### 1.2 sender

```
send(delivery):
  ep = endpoints[delivery.endpoint_id]；!ep.enabled → cancelled
  body = formats::render(ep.format, payload)
  t = now_unix；sig = hex(HMAC_SHA256(ep.secret, t + "." + body))
  headers: Content-Type: application/json；User-Agent: PT-Studio-Webhook/<ver>；X-PT-Event；X-PT-Delivery（UUIDv7）；X-PT-Signature: t=<t>,v1=<sig>
  http.send(POST ep.url, timeout = timeout_secs)（内核 SSRF 防护；不跟随重定向）
  2xx → delivered；记录耗时与响应前 1 KiB
  其他 / 超时 → attempts+1；attempts ≤ 6 → 按退避表重新调度；否则 failed
  ep.consecutive_failures：成功清零；失败 +1；≥ disable_after_failures → ep.enabled = false；publish webhook.delivery_failed{endpoint_id, event_id, status, attempts}
```

### 1.3 ssrf（内核未提供时的插件内兜底）

URL 校验：scheme = https；主机为域名时不允许 `localhost`、`*.local`、`*.internal`；IP 字面量不允许 RFC 1918、100.64.0.0/10、127.0.0.0/8、169.254.0.0/16、::1、fc00::/7、fe80::/10、0.0.0.0、元数据地址 169.254.169.254；端口 443 或 `allowed_ports`。DNS 重绑定防护需要内核 http-client 支持（插件内无法解析 DNS 后固定连接地址），列入 02 §平台契约新增。

### 1.4 formats

- discord：`{ "content": null, "embeds": [ { "title": data.title ?? type, "url": data.url, "description": 事件摘要（术语渲染，站点默认语言）, "timestamp": occurred_at } ] }`；
- slack：`{ "text": 摘要, "blocks": [ { "type": "section", "text": { "type": "mrkdwn", "text": "<url|title> …" } } ] }`；
- 文本全部转义（Discord Markdown、Slack mrkdwn 特殊字符）。

## 2. 接口详细设计

**POST `/v1/admin/endpoints`** `{ "name": "公告频道", "url": "https://discord.com/api/webhooks/…", "events": ["torrent.created"], "filter": [ { "field": "type_id", "op": "eq", "value": "movie" } ], "format": "discord" }` → 201 `{ "id": 3, "secret": "whsec_…（仅此一次）" }`；校验：事件在白名单、URL 通过 ssrf 校验、`allowed_hosts` 非空时主机在列表中。

**POST `/v1/admin/endpoints/{id}/rotate-secret`**、**POST `/v1/admin/endpoints/{id}/test`**、**GET `/v1/admin/deliveries?endpoint_id=&state=`**。

## 3. 数据库设计（schema `webhook`）

```sql
CREATE TABLE webhook.endpoints (
    id                    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name                  text NOT NULL,
    url                   text NOT NULL,
    secret                bytea NOT NULL,
    events                text[] NOT NULL,
    filter                jsonb NOT NULL DEFAULT '[]',
    format                text NOT NULL DEFAULT 'json' CHECK (format IN ('json', 'discord', 'slack')),
    enabled               boolean NOT NULL DEFAULT true,
    consecutive_failures  integer NOT NULL DEFAULT 0,
    created_at            timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE webhook.deliveries (
    id           bigint GENERATED ALWAYS AS IDENTITY,
    endpoint_id  bigint NOT NULL,
    event_id     text NOT NULL,
    event_type   text NOT NULL,
    payload      jsonb NOT NULL,
    state        text NOT NULL CHECK (state IN ('pending','delivered','failed','cancelled')),
    attempts     integer NOT NULL DEFAULT 0,
    last_status  integer,
    last_error   text,
    response_excerpt text,
    duration_ms  integer,
    created_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (created_at, id),
    UNIQUE (created_at, endpoint_id, event_id)
) PARTITION BY RANGE (created_at);
```

`secret` 以内核 kv 的私有存储为宜；放在表中时用静态配置 `secret_key` 加密（AES-256-GCM）。`deliveries` 按天分区，保留 14 天。去重：同一端点同一事件只投递一次（订阅重复投递时 `ON CONFLICT DO NOTHING`——由于分区键包含 created_at，去重另用 Redis `SET NX dd:<endpoint>:<event_id>`（TTL 7 天））。

## 4. 配置项

见 SRS §5，静态 `secret_key`。清单：订阅白名单事件（每个一条 `[[subscriptions]]`）；`[[jobs]] send`；cron `cleanup`（分区由内核维护）。

## 5. 前端设计

后台端点列表（状态、最近投递成功率）、编辑表单（事件多选、过滤条件构建器、格式）、投递日志与重发按钮、签名验证示例代码（Python / Node / Go）。

## 6. 安全设计

字段白名单脱敏；SSRF 防护；签名与时间戳；密钥只显示一次并加密存储；不跟随重定向；响应体截断且不渲染。
