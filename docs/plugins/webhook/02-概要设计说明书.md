| 类别 | 内容 |
|---|---|
| 原则 | 订阅处理只做“匹配端点 + 脱敏 + 入队”，投递在延迟任务中；出站主机由管理员配置，内核出站能力需支持“运行时主机列表”（⊕）；全程防 SSRF |
| 模块 | `endpoints`（CRUD、密钥）、`filter`（事件白名单、谓词过滤）、`sanitize`（字段白名单与匿名处理）、`queue`（投递队列）、`sender`（签名、HTTP、重试）、`formats`（json / discord / slack）、`ssrf`（地址检查） |
| 依赖 | 只读视图 `torrent.v_torrent_public`（附加标题，匿名时不附加上传者）；无服务依赖 |
| 订阅 | 白名单中的每个事件一个订阅（WASM 订阅需静态声明，见 01 §FR-002 列表） |
| 能力 | `sql`、`kv`；`http_outbound = ["runtime:allowed_hosts"]` ⊕ |
| 发布 | `webhook.delivery_failed` |
| 关键流程 | on_event(evt) → endpoints（订阅该类型且启用）→ filter → sanitize → INSERT deliveries(state = pending) → 调度 send；send：ssrf 检查（DNS 解析结果）→ 签名 → POST → 2xx：delivered；否则重试或 failed；连续失败计数 → 停用 |
| 设计决策 | DD-WHOOK-1：载荷采用字段白名单（每个事件类型定义允许外发的字段），而不是黑名单；DD-WHOOK-2：签名包含时间戳防重放（接收方应拒绝 5 分钟以前的签名）；DD-WHOOK-3：DNS 解析后检查地址，并要求 HTTP 客户端连接到已检查的地址（需内核 http-client 支持“固定解析地址”或在内核出站层统一做 SSRF 防护 ⊕） |
| 平台契约新增 | 内核出站：① `runtime:` 主机列表（由插件设置决定，管理员修改设置时生效）；② 内核 http-client 层的 SSRF 防护（禁止私有地址，所有插件受益）——推荐在内核实现，本插件不重复 |
| 权限点 | `webhook.manage`（已登记） |

需求追溯：FR-001 → endpoints；FR-002、010 → filter；FR-003 → sanitize；FR-004、005、011 → sender、ssrf；FR-006、007 → queue；FR-008 → endpoints；FR-009 → formats。
