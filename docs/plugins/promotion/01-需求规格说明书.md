## 1. 引言

### 1.1 目的

定义促销插件 `promotion` 的需求。促销决定种子的流量倍率（免费、2x 上传等），是 PT 站最核心的运营手段之一。

### 1.2 范围

包含：

- **单种促销**：版主为一个或多个种子设置促销类型与时限；
- **自动促销规则**：按体积、发布时长、资源类型、标签、做种人数等条件自动设置或取消促销（数据驱动）；
- **全站活动**：限时全站免费 / 2x 等，可按资源类型过滤；
- **个人促销卡**：用户对指定种子使用“个人免费卡 / 个人 2x 卡”，只对该用户生效（卡由 shop 售卖或管理员发放）；
- 倍率下发：一律通过 `ctx.accounting.set_rate_rule()` / `remove_rate_rule()`；
- 展示：当前促销状态查询（单种、批量、全站）、前端徽标、搜索字段贡献、下载钩子上下文；
- 促销名称与图标走术语键。

不包含：

- 倍率的结算与存储（accounting）；
- 促销卡的售卖与扣款（shop，本插件提供发放接口）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 促销类型（kind） | 预设：`free`（下载 0x）、`double_up`（上传 2x）、`double_up_free`（2x + 0x）、`half_down`（下载 0.5x）、`thirty_down`（下载 0.3x）、`double_up_half_down`（2x + 0.5x）；以及 `custom`（自定义倍率） |
| 倍率（‰） | 千分比整数，1000 = 1x；与 accounting 的 `up_permille` / `down_permille` 一致 |
| 生效促销 | 某时刻对某（用户，种子）实际生效的倍率，由 accounting 按规则合并计算 |
| 展示促销 | 种子页面显示的促销（不含个人卡），由本插件按优先级选出一个主促销 |

### 1.4 参考资料

- docs/platform/、docs/plugins/accounting/03 §1.3（倍率规则模型）
- NexusPHP：`sp_state`（促销状态枚举）、`promotion_time_type` / `promotion_until`（限时）、后台“自动促销”与“全站促销”设置
- UNIT3D：`free`（0/25/50/75/100%）、`doubleup`、`fl_until` / `du_until`、`featured`（精选种子：免费 + 2x）、freeleech tokens（个人免费令牌）、全站 freeleech / double upload 事件
- Gazelle/OPS：freeleech（全站/单种）、Neutral Leech（上传下载都不计），freeleech token

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM，ID `promotion`，缩写 `PROMO`。
- 提供：`ctx.promotions`（single）。
- 依赖：`ctx.accounting`（`write:rates`、`read`）、`ctx.terms`；只读视图 `torrent.v_torrent_public`。
- **不依赖** `ctx.torrents`：torrent 插件的下载流程会调用 `ctx.promotions.current()`，如果本插件再依赖 `ctx.torrents` 会形成服务依赖环（平台禁止）。种子属性从事件与只读视图获得。
- 搜索贡献者：为 `torrents` 索引提供 `promotion_kind`、`promotion_ends_at`。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 在列表和详情页看到促销徽标与剩余时间；按“免费”筛选；对种子使用个人免费卡；通过 MCP 查询当前促销 |
| 版主 | 对种子设置 / 取消促销 |
| 管理员 | 配置自动促销规则、全站活动、促销类型显示名 |
| 其他插件 | torrent 下载钩子读取促销；search 订阅事件更新文档；shop 发放个人促销卡 |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP | 种子表 `sp_state` 1～7 枚举促销类型，`promotion_until` 限时；后台“自动促销”（新种按体积随机设置促销）、全站促销；tracker 在 announce 时读取 `sp_state` 计算流量 | 类型丰富，运营熟悉；全站促销开关简单 | 促销直接写在种子表，announce 热路径要查数据库；倍率逻辑散落在 announce.php；自动促销“随机”导致用户刷新抢种；促销到期依赖清理脚本，期间状态不一致 | **采纳**促销类型集合与限时；**改进**：倍率只通过 accounting 的规则下发，tracker 不感知；自动促销规则确定性（不随机），并有防抖；到期由 accounting 按规则时间自动失效，不依赖清理任务 |
| UNIT3D | `free` 支持 0～100% 的粒度、`doubleup`，各自独立的到期时间；featured 种子；freeleech tokens 由用户消耗，对单种个人生效；全站事件由配置开启 | 个人令牌提升参与感；上传与下载倍率独立 | 个人令牌使用后不可撤回、无有效期；featured 与促销概念混淆 | **采纳**上下行倍率独立、个人促销卡（带有效期，默认 7 天，可配置）；featured 归入“标签”（torrent 插件）而非促销 |
| Gazelle/OPS | 全站 freeleech、单种 freeleech、Neutral Leech；freeleech token 在下载时选择使用 | Neutral Leech（上传也不计）适合补种活动 | 只有 3 种状态，粒度粗 | **采纳**中性（`neutral`：上传 0x、下载 0x）作为可选 custom 预设，默认不启用 |

### 2.4 约束与假设

1. accounting 的 favorable 规则只允许“对用户更有利”（上传 ≥ 1x、下载 ≤ 1x）；`neutral`（上传 0x）属于不利方向，必须用 override 模式（accounting 03 §1.3）。
2. accounting 限制单条规则的 `torrents` 列表 ≤ 10000；本插件按种子生成独立规则（`external_ref` 每种子唯一），不使用大列表。
3. 规模：种子 100 万级；同时生效的单种 / 自动促销规则预计 ≤ 5 万条；个人卡生效 ≤ 10 万条。
4. 规则生效时间：`starts_at` 早于 now − 5 min 会被 accounting 截断（不允许追溯）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-PROMO-001 | 促销类型 | 支持 6 种预设类型与 custom；每种类型的显示名、短名、图标走术语键 `promotion.<kind>` | P0 | 术语后台改名后前端显示新名称 |
| FR-PROMO-002 | 单种设置 | 有 `promotion.create` 的用户为 1～1000 个种子设置促销（类型、开始时间、结束时间或时长、原因） | P0 | accounting 中出现对应规则；种子页显示徽标 |
| FR-PROMO-003 | 单种取消 | 取消某种子的单种促销 | P0 | accounting 规则被移除；徽标消失 |
| FR-PROMO-004 | 单种覆盖 | 同一种子已有单种促销时再次设置：替换（结束旧的、创建新的） | P0 | 同一时刻每个种子最多一条单种促销 |
| FR-PROMO-005 | 限时到期 | 到期后倍率自动失效（由 accounting 规则时间控制），展示状态在 5 分钟内更新 | P0 | 到期后新的流量按 1x 计 |
| FR-PROMO-006 | 自动促销规则 | 管理员定义规则：条件（体积、发布后时长、类型、标签、状态、做种人数、完成数）+ 促销类型 + 持续方式（固定时长 / 条件满足期间） | P1 | 新种满足“≥ 10 GiB”时自动免费 24 小时 |
| FR-PROMO-007 | 新种触发 | 订阅 `torrent.created` / `torrent.status_changed`，种子通过审核（approved）时评估自动规则 | P1 | 审核通过 1 分钟内生效 |
| FR-PROMO-008 | 做种人数触发 | 订阅 `traffic.swarm_stats_updated`，按做种人数类条件设置 / 取消（如“做种 ≤ 2 人时 2x 上传”） | P1 | 做种人数变化后 10 分钟内生效 |
| FR-PROMO-009 | 防抖 | 条件型自动促销设置“最短持续时间”和“退出阈值”（滞回），避免频繁切换 | P1 | 做种人数在阈值附近波动时，1 小时内状态最多变化 2 次 |
| FR-PROMO-010 | 优先级 | 单种促销 > 自动促销（可配置）；多条自动规则命中时取优先级最高的一条 | P1 | 展示与下发只采用一条 |
| FR-PROMO-011 | 全站活动 | 管理员创建全站活动（类型、时间窗口、可选资源类型过滤、标题术语键、横幅文案） | P0 | 活动期间全站流量按活动倍率计；结束后恢复 |
| FR-PROMO-012 | 全站与单种叠加 | 全站活动与单种促销同时存在时，按 accounting 规则合并（favorable：上传取最大、下载取最小） | P0 | 单种 2x + 全站免费 = 2x 免费 |
| FR-PROMO-013 | 个人促销卡持有 | 记录用户持有的个人卡（类型：个人免费 / 个人 2x），可由服务发放 | P1 | 发放幂等 |
| FR-PROMO-014 | 使用个人卡 | 用户对一个种子使用一张卡，生效期默认 7 天（可配置），只对该用户该种子生效 | P1 | accounting 中出现 user-torrent 规则 |
| FR-PROMO-015 | 个人卡限制 | 已有更优促销（如种子已免费）时使用免费卡提示并要求确认；同一种子同一类型卡不能重复使用；可设体积下限 | P2 | 重复使用返回 `promotion.card_already_applied` |
| FR-PROMO-016 | 当前促销查询 | `current(torrent_id)`、`current_many(ids)`（≤ 500）、`active_global()` | P0 | 结果与数据库一致；批量 p99 < 20 ms |
| FR-PROMO-017 | 我的促销 | 用户查询某种子对自己的生效倍率（含个人卡、全站活动） | P2 | 与 accounting `effective_rate` 一致 |
| FR-PROMO-018 | 搜索字段 | 作为搜索贡献者提供 `promotion_kind`、`promotion_ends_at`；促销开始 / 结束时发布事件以触发重新索引 | P1 | 按“免费”筛选结果正确（延迟 ≤ 5 分钟） |
| FR-PROMO-019 | 下载钩子上下文 | torrent 调用 `current()` 取得 `{up_rate, down_rate}` 填入 `torrent.before_download` 输入 | P0 | 钩子输入中促销字段正确 |
| FR-PROMO-020 | 一致性巡检 | 定期比对本插件的有效促销与 accounting 中自己创建的规则，补建缺失、移除多余 | P0 | 人为删除 accounting 规则后，下一次巡检恢复 |
| FR-PROMO-021 | 种子删除 | 订阅 `torrent.deleted`，结束该种子的全部促销 | P1 | 规则被移除 |
| FR-PROMO-022 | 历史 | 保留促销变更历史（谁、何时、什么类型、原因） | P1 | 后台可查询某种子的促销历史 |
| FR-PROMO-023 | MCP | `list_active_promotions`（读） | P2 | 返回全站活动与即将到期的热门促销 |
| FR-PROMO-024 | 横幅 | 全站活动期间在首页显示横幅（`home.announcements`） | P1 | 活动开始后横幅出现 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-PROMO-001 | 性能 | `current_many` | 500 个种子 p99 < 20 ms（缓存命中） |
| NFR-PROMO-002 | 性能 | 自动规则评估 | 单个 `traffic.swarm_stats_updated` 事件（≤ 1000 项）p99 < 200 ms |
| NFR-PROMO-003 | 一致性 | 与 accounting 的规则一致 | 偏差在一个巡检周期（10 分钟）内消除 |
| NFR-PROMO-004 | 可靠性 | 幂等 | 所有对 accounting 的写入以 `external_ref` 幂等；事件重复投递不产生重复规则 |
| NFR-PROMO-005 | 容量 | 规则数量 | 同时生效 ≤ 15 万条（单种 + 自动 + 个人卡） |
| NFR-PROMO-006 | 安全 | 权限 | 单种设置需 `promotion.create`，自动规则与全站活动需 `promotion.manage`；全部写审计 |
| NFR-PROMO-007 | 可观测 | 指标 | 规则下发成功/失败、巡检修复数、自动规则命中数 |

## 5. 可配置项与站点术语

运行时设置：

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `kinds_enabled` | string[] | 6 种预设 | 可用的促销类型 |
| `custom_enabled` | bool | false | 是否允许自定义倍率 |
| `max_single_days` | integer | 30 | 单种促销最长天数（0 = 允许永久） |
| `manual_over_auto` | bool | true | 单种促销优先于自动促销 |
| `card.duration_days` | integer | 7 | 个人卡生效天数 |
| `card.min_size_bytes` | integer | 0 | 个人卡适用的最小体积 |
| `banner.enabled` | bool | true | 全站活动横幅 |

术语（已登记）：`promotion.free`、`promotion.double_up`、`promotion.double_up_free`、`promotion.half_down`、`promotion.thirty_down`、`promotion.double_up_half_down`、`promotion.global_event`、`promotion.event.<event_id>`；新增：`promotion.neutral`、`promotion.custom`、`promotion.card.free`、`promotion.card.double_up`、`promotion.auto_rule.<rule_id>`。

## 6. 外部接口需求概述

- 服务 `ctx.promotions`：`current`、`current_many`、`active_global`、`create`、`end`、`grant_cards`、`cards_of`。
- 事件：发布 `promotion.started`、`promotion.ended`、`promotion.card_applied`、`promotion.cards_changed`；订阅 `torrent.created`、`torrent.status_changed`、`torrent.tags_changed`、`torrent.deleted`、`traffic.swarm_stats_updated`、`user.deleted`。
- 搜索贡献：`torrents` 索引字段 `promotion_kind`、`promotion_ends_at`。
- HTTP：`/api/p/promotion/v1/*`；插槽 `torrent.list.row_badges`、`torrent.detail.header`、`home.announcements`、`torrent.detail.actions`（使用个人卡）。
- MCP：`list_active_promotions`。
