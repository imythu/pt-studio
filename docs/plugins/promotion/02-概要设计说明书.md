## 1. 设计目标与原则

1. **只下发规则，不结算**：本插件只决定“什么时候、对谁、多少倍率”，通过 `ctx.accounting.set_rate_rule()` 下发；结算与历史重算由 accounting 负责（平台 Q2）。
2. **本插件为事实来源，accounting 为执行面**：促销记录先在本插件落库（`sync_state = pending`），再下发；下发失败由巡检补齐。
3. **确定性**：自动促销不随机（NexusPHP 随机促销引发抢种的教训）；所有 `external_ref` 由促销 ID 确定性生成。
4. **无依赖环**：不依赖 `ctx.torrents`；种子属性通过事件维护本地镜像，必要时读只读视图。
5. **展示与执行分离**：展示状态（`current`）由本插件计算并缓存；实际倍率以 accounting 合并结果为准，二者在“全站 + 单种叠加”时可能不同，展示接口同时返回合并后的倍率。

## 2. 总体结构

### 2.1 在整体架构中的位置

```
版主 / 管理员 ──HTTP──► promotion (WASM) ──set_rate_rule / remove_rate_rule──► accounting
torrent.created / status_changed / tags_changed / deleted ──►│
traffic.swarm_stats_updated ─────────────────────────────►│ 自动规则引擎
shop ──ctx.promotions.grant_cards──────────────────────────►│
torrent（下载钩子输入）──ctx.promotions.current──────────────►│
                                                          │ events: promotion.started / ended
                                                          ▼
                                          search（重新索引 promotion_kind）、notify、webhook
```

| 事件 | key | 说明 |

## 5. 关键流程

### 5.1 设置单种促销

```
POST /torrents/promotions {torrent_ids[], kind, starts_at?, ends_at | duration, reason}
 1. 校验权限、类型启用、时长 ≤ max_single_days；种子存在且 status ∉ {deleted}（查镜像，缺失时查视图）
 2. 对每个种子（同一事务）：
      结束现有 manual 促销（state=replaced）
      INSERT promotions(source=manual, external_ref="m:<id>", sync_state=pending)
 3. 提交前对每条调用 accounting.set_rate_rule（external_ref 幂等）→ 成功则 sync_state=synced, rate_rule_id
    被替换的旧促销调用 remove_rate_rule
    失败的保持 pending（巡检补齐）
 4. 发布 promotion.started / promotion.ended（被替换的）；DEL cur:<tid>
```

### 5.2 自动规则

```
on_swarm_stats(evt.items[]):
  更新 torrent_mirror.seeders/leechers/completed
  rules = 启用的、条件中含 seeders/leechers/completed 的自动规则（按 priority）
  for item in items:
     for r in rules: matched = predicate(r.conditions, mirror[item.torrent_id])
        state = auto_state[(r, tid)]
        进入：matched 且 当前无此规则促销 → create(source=auto, ends_at = r.duration?)
        退出：!matched_exit(r.exit_conditions) 且 已持续 ≥ r.min_hold → end(cause=condition_lost)
  同一种子多条规则命中时只保留优先级最高的一条（其余不创建）
```

### 5.3 全站活动

```
POST /admin/events {kind, starts_at, ends_at, type_ids?, title_zh, title_en, banner}
 → INSERT promotions(source=global, scope=global 或 torrents-by-type)
 → set_rate_rule(scope = Global)；有 type_ids 过滤时：accounting 规则不支持按类型 →
   方案：为满足类型的种子逐个下发（规则数可能很大）——见 DD-PROMO-5
 → terms.define("promotion.event.<id>")；发布 promotion.started(key=global)
```

### 5.4 个人卡

```
POST /me/cards/apply {torrent_id, card_kind}
 1. 余额 ≥ 1；种子满足 min_size；该用户该种子该类型无生效卡
 2. 扣卡；INSERT promotions(source=card, user_id, external_ref="c:<id>", ends_at = now + duration)
 3. set_rate_rule(scope = UserTorrent(uid, tid), favorable)
 4. 发布 promotion.card_applied、promotion.cards_changed
```

### 5.5 巡检

```
reconcile:
  mine = accounting.list_rate_rules(owner = promotion, active_at = now) 分页取全
  want = SELECT … FROM promotions WHERE state='active' AND (ends_at IS NULL OR ends_at > now)
  缺失（want 有、mine 无）→ set_rate_rule；多余（mine 有、want 无）→ remove_rate_rule
  内容不一致（倍率或时间不同）→ set_rate_rule（同一 external_ref 内容不同会 supersede）
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论与理由 |
|---|---|---|---|
| DD-PROMO-1 | 倍率如何生效 | 写种子表字段（NexusPHP） / 下发 accounting 规则 | accounting 规则：tracker 不感知业务，倍率结算集中（平台 Q2） |
| DD-PROMO-2 | 种子属性来源 | 依赖 `ctx.torrents` / 事件镜像 + 视图 | 事件镜像：避免 torrent → promotions → torrents 的服务依赖环 |
| DD-PROMO-3 | 每种子一条规则还是一条规则含多种子 | 列表 / 每种子 | 每种子：accounting 列表上限 10000，且列表变更需 supersede 整条规则；每种子规则的增删互不影响 |
| DD-PROMO-4 | 自动促销是否随机 | 随机（NexusPHP） / 确定性 | 确定性：可预测、可解释、不会因刷新页面抢种 |
| DD-PROMO-5 | 带类型过滤的全站活动 | 逐种子下发 / 请 accounting 支持“按种子类型”的作用域 | 请 accounting 增加 `scope = torrent_types(list<string>)`（§7）；合入前降级为逐种子下发（只对活动开始时已存在的种子，以及活动期间新种的 `on_torrent_created` 补发），并在后台提示规则数量 |
| DD-PROMO-6 | 不利方向倍率（neutral） | 不支持 / override | override 模式、priority 100；默认禁用 |
| DD-PROMO-7 | 展示状态 | 只展示主促销 / 全部 | 主促销（manual > auto，按 `manual_over_auto`）+ 全站活动单独字段；同时返回 accounting 合并后的“全局倍率”（不含个人卡） |
| DD-PROMO-8 | 个人卡是否发布 `promotion.started` | 发布 / 不发布 | 不发布：只影响单个用户，不改变公开展示与搜索 |

## 7. 对平台契约的新增

| 类别 | 内容 |
|---|---|
| 服务方法 | `ctx.promotions.end(id, reason)`（目录原签名无 reason）；新增 `grant_cards(user_id, card_kind, n, reason, idempotency_key) -> u32`、`cards_of(user_id)`；新作用域 `write:cards`（shop 用） |
| accounting | 请 `rate-scope` 增加 `torrent-types(list<string>)`（全站活动按资源类型过滤）；accounting 需在 torrents 镜像中有 `type_id`（其 03 §1.4 已维护种子体积镜像，可一并维护） |
| 事件 | `promotion.started` / `ended` 补字段；新增 `promotion.card_applied`、`promotion.cards_changed` |
| 搜索 | 作为 `torrents` 索引贡献者：`promotion_kind`（string，filterable，label_term `promotion.filter_label`）、`promotion_ends_at`（timestamp，sortable） |
| 术语 | `promotion.neutral`、`promotion.custom`、`promotion.card.free`、`promotion.card.double_up`、`promotion.auto_rule.<rule_id>`、`promotion.filter_label` |
| 共享库 | 自动规则条件采用 `pt-predicate`（同 medals 02 §7 的提案） |
| Redis 子键 | `cur:<torrent_id>`、`global`（目录建议子键 `active` 改为 `global`） |
