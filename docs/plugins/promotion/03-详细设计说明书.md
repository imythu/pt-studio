## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/promotion/`（Rust + `wit-bindgen`），`kind = "wasm"`；状态在 PG schema `promotion` 与 Redis `p:promotion:`。
- 倍率一律千分比整数（`u32`），与 accounting `rate-rule` 一致。
- `external_ref` 规则：单种 `m:<promotion_id>`；自动 `a:<promotion_id>`；全站 `g:<promotion_id>`（逐种子降级时 `g:<promotion_id>:<torrent_id>`）；个人卡 `c:<promotion_id>`。accounting 以 `(owner_plugin, external_ref)` 幂等。
- 所有对 accounting 的写调用均“先落库、后下发”，下发结果写回 `sync_state`；下发失败不回滚本插件事务，由巡检补齐（§1.6）。

### 1.1 kinds：类型与倍率

| kind | up ‰ | down ‰ | 模式 | 术语键 |
|---|---|---|---|---|
| `free` | — | 0 | favorable | `promotion.free` |
| `double_up` | 2000 | — | favorable | `promotion.double_up` |
| `double_up_free` | 2000 | 0 | favorable | `promotion.double_up_free` |
| `half_down` | — | 500 | favorable | `promotion.half_down` |
| `thirty_down` | — | 300 | favorable | `promotion.thirty_down` |
| `double_up_half_down` | 2000 | 500 | favorable | `promotion.double_up_half_down` |
| `neutral` | 0 | 0 | override（priority 100） | `promotion.neutral` |
| `custom` | 1000～`max_up` | 0～1000 | favorable | `promotion.custom` |

“—”表示该维度不设置（`None`，不影响）。`custom` 只允许“更有利”方向；不利方向只能用 `neutral`。`max_up` 取 accounting 的 `rates.max_up_permille`（通过 `list_rate_rules` 无法读取，故本插件静态配置 `max_custom_up_permille`，默认 5000，accounting 会再次截断）。

### 1.2 manual：单种促销

```
set_single(actor, req{torrent_ids[1..=1000], kind, up?, down?, starts_at?, ends_at?, duration_secs?, reason}):
  require rbac(actor, promotion.create)
  validate kind ∈ kinds_enabled；custom 时 custom_enabled 且 up/down 合法
  starts = max(req.starts_at ?? now, now)           // 不允许追溯
  ends = req.ends_at ?? (duration ? starts + duration : None)
  if max_single_days > 0: require ends 非空 且 ends - starts ≤ max_single_days 天
  for tid in torrent_ids (同一事务，按 tid 排序避免死锁):
     m = mirror::get_or_load(tid)                    // 缺失则 SELECT torrent.v_torrent_public；不存在 → 该项错误 torrent_not_found
     if m.status == 'deleted': 该项错误
     old = SELECT … FROM promotions WHERE torrent_id=tid AND source='manual' AND state='active' FOR UPDATE
     if old: end_internal(old, cause='replaced')
     p = INSERT promotions(source='manual', torrent_id=tid, kind, up, down, starts_at, ends_at, reason,
                           created_by=actor.user_id, state='active', sync_state='pending') RETURNING id
     UPDATE external_ref = 'm:'||p.id
     history::record(p, 'start', actor)
  // 下发（同一调用内，提交前；accounting 调用独立提交）
  for p in created: sync::push(p)
  for o in replaced: sync::pull(o)
  for p: events.publish(promotion.started{…, source:'manual'})；cache::invalidate(tid)
  return {items: [{torrent_id, promotion_id | error}]}
```

`end_internal(p, cause)`：`UPDATE state='ended', ended_at=now, end_cause=cause`；`sync::pull(p)`；发布 `promotion.ended`；`cache::invalidate`。

### 1.3 auto：自动规则

**规则定义**（`auto_rules.definition`，`schemas/auto_rule.v1.json`）：

```json
{
  "schema": 1,
  "name_zh": "大体积新种免费",
  "name_en": "Large new torrents freeleech",
  "priority": 50,
  "kind": "free",
  "enter": [
    { "field": "size", "op": "gte", "value": 10737418240 },
    { "field": "age_hours", "op": "lt", "value": 24 },
    { "field": "status", "op": "eq", "value": "approved" }
  ],
  "exit": null,
  "duration": { "mode": "fixed", "hours": 24 },
  "min_hold_minutes": 0,
  "type_ids": ["movie", "tv"]
}
```

```json
{
  "schema": 1, "name_zh": "冷门保种 2x", "name_en": "Low-seed 2x upload", "priority": 30,
  "kind": "double_up",
  "enter": [ { "field": "seeders", "op": "lte", "value": 2 }, { "field": "age_hours", "op": "gte", "value": 720 } ],
  "exit":  [ { "field": "seeders", "op": "gte", "value": 5 } ],
  "duration": { "mode": "while_matched", "max_hours": 168 },
  "min_hold_minutes": 60,
  "type_ids": null
}
```

| 字段 | 约束 |
|---|---|
| 可用 `field` | `size`、`age_hours`（由 `created_at` 计算）、`type_id`、`status`、`tags`（`in`/`nin` 对数组判断交集）、`seeders`、`leechers`、`completed`、`file_count` |
| `enter` | 1～10 个谓词，全部成立才进入 |
| `exit` | null（= `enter` 不成立即退出）或 1～10 个谓词（任意一个成立即退出，形成滞回） |
| `duration.mode` | `fixed`（固定时长，到期结束，不再因条件重新进入同一规则：每个 (rule, torrent) 只触发一次）或 `while_matched`（条件满足期间，最长 `max_hours`，0 = 不限） |
| `min_hold_minutes` | 0～1440；进入后至少持续这么久才评估退出 |
| `priority` | 0～1000，越大越优先 |

**评估**（`auto::evaluate(tid, trigger)`）：

```
m = mirror[tid]；if m.status != 'approved': 结束本种子的所有 auto 促销（cause=condition_lost）；return
rules = active 规则，按 priority DESC, id
current = SELECT … FROM promotions WHERE torrent_id=tid AND source='auto' AND state='active' FOR UPDATE   // 至多一条
for r in rules:
  st = auto_state[(r.id, tid)]                        // {fired_once, entered_at}
  if r.type_ids && m.type_id ∉ r.type_ids: continue
  if r.duration.mode == fixed && st.fired_once: continue
  if predicate::all(r.enter, m):
     best = r；break
if current:
  cr = rule of current
  keep = (now - current.starts_at < cr.min_hold) or
         (cr.exit is null ? predicate::all(cr.enter, m) : !predicate::any(cr.exit, m)) or
         cr.duration.mode == fixed                    // fixed 只按时长结束
  if best is some and best.priority > cr.priority and best.id != cr.id: keep = false   // 更高优先级规则抢占
  if keep: return
  end_internal(current, cause = (best ? 'replaced' : 'condition_lost'))
if best and (current is None or best.id != current.rule_id):
  ends = fixed ? now + hours : (max_hours > 0 ? now + max_hours : None)
  create auto promotion(rule_id = best.id, kind = best.kind, ends_at = ends)；sync::push；事件
  UPSERT auto_state SET fired_once = true, entered_at = now
```

`manual_over_auto = true` 时：种子有生效的 manual 促销则跳过自动评估（已有的 auto 促销保留但展示让位；下发照常，accounting 按 favorable 合并）。为避免倍率叠加超出预期，**manual 存在时结束 auto 促销**（cause=`replaced`），manual 结束时立即重新评估该种子。

**触发点**：

| 触发 | 处理 |
|---|---|
| `on_torrent_created` | 写镜像；status = approved 时 evaluate |
| `on_torrent_status` | 更新镜像；to ∈ {disabled, deleted, rejected} → 结束该种子全部促销（manual 也结束，cause = `torrent_disabled`）；to = approved → evaluate |
| `on_torrent_tags` | 更新镜像 tags；evaluate |
| `on_swarm_stats` | 批量更新镜像 seeders/leechers/completed（一条 `UPDATE … FROM unnest(...)`）；只对“有规则引用做种类字段且该种子数值跨过任一规则阈值”的种子 evaluate（阈值集合预先从规则中提取） |
| cron `reevaluate_age` | 对 `age_hours` 类条件：`SELECT torrent_id FROM torrent_mirror WHERE created_at BETWEEN now - (max_age_threshold + 1h) AND now - (min_age_threshold)` 分批 evaluate（只覆盖阈值附近的种子） |

规则新建 / 修改后：延迟任务 `rule_rollout`（tx manual）按 `torrent_mirror` 分批 1000 评估全部 approved 种子；修改不利于用户的规则（缩小条件）时，已有 auto 促销按新规则退出。

### 1.4 global：全站活动

```
create_event(req{kind, starts_at, ends_at(必填), type_ids?, title_zh, title_en, banner_markdown?}):
  require promotion.manage；ends_at - starts_at ≤ 31 天
  p = INSERT promotions(source='global', torrent_id=NULL, kind, starts_at, ends_at, type_ids, …)
  terms.define([{key: "promotion.event."+p.id, defaults: {zh-CN: {name: title_zh}, en: {name: title_en}}}],
               idempotency_key = "event:"+p.id+":1")
  if type_ids is null:
     sync::push(p)                                    // scope = global
  else if accounting 支持 torrent-types 作用域（启动时以 list_rate_rules 不可探测，改由静态配置 accounting_supports_type_scope）:
     sync::push(p, scope = torrent_types(type_ids))
  else:
     降级：延迟任务 global_fanout(p.id) 按镜像分批为匹配类型的种子逐个 set_rate_rule("g:<pid>:<tid>")；
           活动期间 on_torrent_created（匹配类型）补发；结束时 remove 全部
  events.publish(promotion.started{scope: 'global', torrent_ids: [], kind, starts_at, ends_at})
  redis.DEL("global")
```

全站活动修改：只允许改 `ends_at`（延长或提前结束）与标题；改 kind 需结束后新建。

### 1.5 cards：个人促销卡

| card_kind | 倍率 | 术语 |
|---|---|---|
| `free` | down 0 | `promotion.card.free` |
| `double_up` | up 2000 | `promotion.card.double_up` |

```
apply_card(uid, tid, card_kind, confirm: bool):
  m = mirror::get_or_load(tid)；status 必须 approved；size ≥ card.min_size_bytes
  lock card_balances(uid, card_kind)；balance ≥ 1 否则 promotion.no_card
  dup = SELECT 1 FROM promotions WHERE source='card' AND user_id=uid AND torrent_id=tid AND kind=card_kind AND state='active'
  if dup: err(promotion.card_already_applied)
  eff = accounting.effective_rate(uid, tid, now)
  if !confirm && 卡效果已被当前倍率覆盖（free 卡且 eff.down == 0；2x 卡且 eff.up ≥ 2000）:
     err(promotion.card_redundant, details{current: eff})       // 前端提示后带 confirm=true 重试
  UPDATE card_balances SET balance = balance - 1；INSERT card_log(delta=-1, reason='apply:<tid>')
  p = INSERT promotions(source='card', user_id=uid, torrent_id=tid, kind=card_kind, starts_at=now,
                        ends_at=now + card.duration_days)
  sync::push(p, scope = user_torrent(uid, tid))
  publish promotion.card_applied、promotion.cards_changed
grant_cards(uid, card_kind, n ∈ [1,100], reason, idem)：幂等表；加余额；card_log；事件
```

个人卡促销不进入 `cur:` 展示缓存，只在 `GET /torrents/{id}` 的 `mine` 字段中体现。

### 1.6 sync：下发、移除、巡检

```
push(p, scope_override?):
  rule = { external_ref: p.external_ref, scope: scope_override ?? (p.torrent_id ? torrents([tid]) : global),
           up_permille: p.up, down_permille: p.down, mode: p.kind == neutral ? override : favorable,
           priority: p.kind == neutral ? 100 : 0, starts_at: p.starts_at, ends_at: p.ends_at,
           reason_term: Some("promotion."+p.kind) }
  match accounting.set_rate_rule(rule):
    Ok(id)  → UPDATE promotions SET rate_rule_id = id, sync_state = 'synced', sync_error = NULL
    Err(e)  → UPDATE sync_state = 'pending', sync_error = e.code, sync_attempts + 1；metrics
pull(p):
  if p.rate_rule_id: accounting.remove_rate_rule(p.rate_rule_id, idempotency_key = "rm:"+p.external_ref)
  成功 → sync_state = 'removed'；失败 → sync_state = 'remove_pending'
```

`external_ref` 不变而内容变化（如延长 `ends_at`）时再次 `push`：accounting 结束旧规则并新建（supersedes），返回新 id。

**巡检（cron `reconcile`，tx manual）**：

```
1. 处理 pending / remove_pending（按 sync_attempts 退避：attempts ≤ 3 每轮，之后每 6 轮一次）
2. mine = 分页 accounting.list_rate_rules({owner_plugin: "promotion", active_at: now}) → map external_ref → info
3. want = SELECT … FROM promotions WHERE state='active' AND starts_at <= now + 10min AND (ends_at IS NULL OR ends_at > now)
4. want 中 synced 但 mine 缺失 → push；内容不一致（up/down/ends_at）→ push
5. mine 中 external_ref 不在 want（且非本轮刚创建）→ remove_rate_rule
6. 记录指标 reconcile_fixed_total{kind}
```

`list_rate_rules` 每页 500，5 万条规则约 100 次调用；巡检每 10 分钟一次，可接受。规则数超过 15 万时改为按 `torrent_id` 分段增量巡检（`reconcile_shard = minute/10 % 6`）。

### 1.7 mirror：种子属性镜像

| 字段 | 来源 |
|---|---|
| `torrent_id, type_id, size, status, created_at` | `torrent.created`；`torrent.status_changed`；缺失时 `torrent.v_torrent_public` |
| `tags[]` | `torrent.tags_changed` |
| `file_count` | `torrent.created` 无此字段 → 镜像为 NULL；规则引用 `file_count` 时谓词为 false（文档说明，§7 请 torrent 补字段） |
| `seeders, leechers, completed` | `traffic.swarm_stats_updated` |

冷启动：首次启用时延迟任务 `mirror_bootstrap` 从 `torrent.v_torrent_public` 分批导入（无 tags、无做种数，随后由事件补齐）。

### 1.8 view：展示状态

```
current_many(ids ≤ 500):
  hits = redis.MGET(cur:<id>…)
  miss → SELECT DISTINCT ON (torrent_id) … FROM promotions
         WHERE torrent_id = ANY($1) AND source IN ('manual','auto') AND state='active'
           AND starts_at <= now AND (ends_at IS NULL OR ends_at > now)
         ORDER BY torrent_id, (source='manual') DESC（manual_over_auto 时）, priority DESC
  g = global_snapshot()（redis "global"，TTL 60 s，miss 时查 PG）
  state = { torrent_id, primary: {kind, source, ends_at, name_key}, global: [{event_id, kind, ends_at}],
            combined: {up_permille, down_permille}   // primary ∪ 适用的 global，按 favorable 合并（与 accounting 同算法，不含个人卡）
            ends_at: min(primary.ends_at, global.ends_at) }
  回写 cur:<id>（TTL = min(300 s, 到期剩余秒数)；无促销写 "_none"）
```

`torrent.before_download` 的 `promotion{up_rate, down_rate}` 取 `combined`。

### 1.9 search：贡献者

`index-schema()` 返回 `torrents` 索引字段：

| 字段 | 类型 | 属性 | label_term |
|---|---|---|---|
| `promotion_kind` | string | filterable、facet、exact | `promotion.filter_label` |
| `promotion_ends_at` | timestamp | filterable、sortable | — |

`documents(ids)`：返回 `current_many(ids)` 中 primary 的 kind（无则 `none`）与 `ends_at`。全站活动不进入索引（search 03 §1.5 第 11 行：`scope = global` 不处理）；前端在筛选“免费”时，若有全站免费活动，提示“当前全站免费”。

### 1.10 expire 与 history

- cron `expire`（每分钟，tx manual）：`UPDATE promotions SET state='ended', end_cause='expired', ended_at=ends_at WHERE state='active' AND ends_at <= now RETURNING …`（每批 1000）→ 发布 `promotion.ended`（card 来源不发）、`cache::invalidate`；不调用 `remove_rate_rule`（accounting 规则已按 `ends_at` 失效，由 accounting 的 `rate_rule_gc` 清理）。
- `history`：每次 start / end / replace / extend 写一行（按月分区，保留 24 个月）。

### 1.11 lifecycle

- `on_torrent_deleted`：结束该种子全部促销（含个人卡；个人卡不退回，可配置 `card.refund_on_delete`，默认 true 退回一张）。
- `on_user_deleted`（purge）：删除 `card_balances`、`card_log`；结束该用户生效的个人卡促销。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:promotions@0.1.0`）

```wit
package pt:promotions@0.1.0;

interface promotions {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms};

  enum promo-source { manual, auto, global, card }
  record promo-brief {
    promotion-id: u64, kind: string, source: promo-source, name-key: string,
    up-permille: option<u32>, down-permille: option<u32>,
    starts-at: timestamp-ms, ends-at: option<timestamp-ms>,
  }
  record promotion-state {
    torrent-id: u64,
    primary: option<promo-brief>,
    global: list<promo-brief>,
    combined-up-permille: u32,
    combined-down-permille: u32,
    ends-at: option<timestamp-ms>,
  }
  record promotion-def {
    torrent-id: u64, kind: string, up-permille: option<u32>, down-permille: option<u32>,
    starts-at: option<timestamp-ms>, ends-at: option<timestamp-ms>, reason: string,
    idempotency-key: string,
  }
  record card-balance { card-kind: string, balance: u32 }

  current: func(torrent-id: u64) -> result<option<promotion-state>, plugin-error>;
  current-many: func(ids: list<u64>) -> result<list<promotion-state>, plugin-error>;
  active-global: func() -> result<list<promo-brief>, plugin-error>;
  create: func(def: promotion-def) -> result<u64, plugin-error>;
  end: func(promotion-id: u64, reason: string) -> result<bool, plugin-error>;
  grant-cards: func(user: user-id, card-kind: string, n: u32, reason: string, idempotency-key: string) -> result<u32, plugin-error>;
  cards-of: func(user: user-id) -> result<list<card-balance>, plugin-error>;
}
```

| 方法 | 作用域 | 说明 | 错误码 |
|---|---|---|---|
| `current` | — | 无促销返回 `none`（种子不存在也返回 `none`，不泄露存在性） | |
| `current-many` | — | ≤ 500 | `promotion.too_many_ids` |
| `create` | `write` | 等同单种设置（source = manual，created_by = `plugin:<caller>`）；幂等键 `(caller, key)` | `promotion.kind_disabled`、`promotion.duration_invalid`、`promotion.torrent_not_found` |
| `end` | `write` | 只能结束 `create` 由同一调用方创建的促销 | `promotion.not_found`、`kernel.forbidden` |
| `grant-cards` | `write:cards` | n ∈ [1, 100] | `promotion.card_kind_invalid`、`kernel.idempotency_key_reused` |

### 2.2 事件载荷（版本 1）

| 事件 | 字段 |
|---|---|
| `promotion.started` | `promotion_id, scope(torrent/global), source(manual/auto/global), kind, torrent_ids[], type_ids?, up_rate?, down_rate?, starts_at, ends_at?` |
| `promotion.ended` | `promotion_id, scope, source, torrent_ids[], cause(expired/cancelled/replaced/condition_lost/torrent_disabled/torrent_deleted)` |
| `promotion.card_applied` | `promotion_id, user_id, torrent_id, card_kind, ends_at` |
| `promotion.cards_changed` | `user_id, card_kind, delta, balance, reason` |

`up_rate` / `down_rate` 为千分比整数（与目录字段名一致）。

### 2.3 钩子

无。

### 2.4 HTTP API

**GET `/v1/torrents/{torrent_id}`** →

```json
{ "torrent_id": 5501,
  "primary": { "promotion_id": 77, "kind": "free", "source": "auto", "name": "免费",
               "ends_at": "2026-10-06T08:00:00Z" },
  "global": [ { "promotion_id": 90, "kind": "double_up", "name": "国庆 2x", "ends_at": "2026-10-07T16:00:00Z" } ],
  "combined": { "up_permille": 2000, "down_permille": 0 },
  "mine": { "up_permille": 2000, "down_permille": 0, "cards": [] } }
```

`mine` 来自 `accounting.effective_rate(当前用户, tid)`（含个人卡）。

**GET `/v1/torrents?ids=1,2,3`**（≤ 500）→ `{ "items": [ { "torrent_id": 1, "kind": "free", "ends_at": "…", "global_kind": "double_up" } ] }`（列表徽标精简格式）。

**POST `/v1/torrents/promotions`**（`promotion.create`；`Idempotency-Key` 必填）

```json
{ "torrent_ids": [5501, 5502], "kind": "double_up_free", "duration_secs": 86400, "reason": "官方资源推广" }
```

→ `{ "items": [ { "torrent_id": 5501, "promotion_id": 120 }, { "torrent_id": 5502, "error": "promotion.torrent_not_found" } ] }`

**DELETE `/v1/torrents/{torrent_id}/promotion`** 请求 `{ "reason": "…" }` → 204（无单种促销时 404 `promotion.not_found`）。

**GET `/v1/torrents/{torrent_id}/history?cursor=`** → `{ "items": [ { "at": "…", "action": "start", "kind": "free", "source": "manual", "by": "user:12", "reason": "…" } ], "next_cursor": null }`

**GET `/v1/me/cards`** → `{ "balances": [ { "card_kind": "free", "balance": 2 } ], "active": [ { "torrent_id": 5501, "card_kind": "free", "ends_at": "…" } ] }`

**POST `/v1/me/cards/apply`** 请求 `{ "torrent_id": 5501, "card_kind": "free", "confirm": false }` → 200 `{ "promotion_id": 300, "ends_at": "…", "balance": 1 }`；409 `promotion.card_redundant`（`details.current`）、`promotion.card_already_applied`；403 `promotion.no_card`；422 `promotion.card_not_applicable`（体积不足 / 未审核）。

**POST `/v1/admin/rules`**：请求为 §1.3 规则 JSON → 201 `{ "id": 7, "rollout_job_id": "…" }`。**POST `/v1/admin/rules/preview`**：请求同上 → `{ "matched_now": 1832, "sample": [5501, 5502] }`（只基于镜像，≤ 10 万种子扫描）。

**POST `/v1/admin/events`**

```json
{ "kind": "free", "starts_at": "2026-10-01T00:00:00+08:00", "ends_at": "2026-10-08T00:00:00+08:00",
  "type_ids": null, "title_zh": "国庆全站免费", "title_en": "National Day Freeleech", "banner_markdown": "…" }
```

→ 201 `{ "id": 90 }`；**PATCH `/v1/admin/events/{id}`**：`{ "ends_at": "…" }`；**DELETE**：立即结束。

**POST `/v1/admin/users/{user_id}/cards`**（`Idempotency-Key` 必填）`{ "card_kind": "free", "delta": 2, "reason": "活动奖励" }` → `{ "balance": 4 }`。

**POST `/v1/admin/reconcile`** → 202。

### 2.5 MCP 工具

`list_active_promotions`：入参 `{ "limit": 20 }`；出参 `{ global: [{name, kind, ends_at}], ending_soon: [{torrent_id, title?, kind, ends_at}] }`（`ending_soon` 为 24 小时内到期的单种 / 自动促销，按做种人数降序，标题从 `torrent.v_torrent_public` 取）；write = false。

### 3.1 PostgreSQL（schema `promotion`）

```sql
CREATE TABLE promotion.promotions (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    source          text NOT NULL CHECK (source IN ('manual', 'auto', 'global', 'card')),
    torrent_id      bigint,
    user_id         bigint,

    ends_at         timestamptz,
    reason          text NOT NULL DEFAULT '',
    created_by      text NOT NULL,                 -- 'user:<id>' / 'plugin:<id>' / 'auto:<rule_id>'
    state           text NOT NULL CHECK (state IN ('active', 'ended')),
    end_cause       text,
    ended_at        timestamptz,

    updated_at      timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT promotions_target CHECK (
        (source = 'global' AND torrent_id IS NULL AND user_id IS NULL) OR
        (source IN ('manual', 'auto') AND torrent_id IS NOT NULL AND user_id IS NULL) OR
        (source = 'card' AND torrent_id IS NOT NULL AND user_id IS NOT NULL))
);
CREATE UNIQUE INDEX promotions_one_manual_idx ON promotion.promotions (torrent_id) WHERE source = 'manual' AND state = 'active';
CREATE UNIQUE INDEX promotions_one_auto_idx ON promotion.promotions (torrent_id) WHERE source = 'auto' AND state = 'active';
CREATE UNIQUE INDEX promotions_one_card_idx ON promotion.promotions (user_id, torrent_id, kind) WHERE source = 'card' AND state = 'active';
CREATE INDEX promotions_torrent_active_idx ON promotion.promotions (torrent_id) WHERE state = 'active';
CREATE INDEX promotions_expiry_idx ON promotion.promotions (ends_at) WHERE state = 'active' AND ends_at IS NOT NULL;
CREATE INDEX promotions_sync_idx ON promotion.promotions (sync_state) WHERE sync_state IN ('pending', 'remove_pending');
CREATE INDEX promotions_global_idx ON promotion.promotions (starts_at, ends_at) WHERE source = 'global' AND state = 'active';

CREATE TABLE promotion.auto_rules (

);

    torrent_id  bigint PRIMARY KEY,

    created_at  timestamptz,

    leechers    integer NOT NULL DEFAULT 0,
    completed   integer NOT NULL DEFAULT 0,
    updated_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX torrent_mirror_created_idx ON promotion.torrent_mirror (created_at) WHERE status = 'approved';
CREATE INDEX torrent_mirror_seeders_idx ON promotion.torrent_mirror (seeders) WHERE status = 'approved';

CREATE TABLE promotion.card_balances (
    user_id    bigint NOT NULL,
    card_kind  text NOT NULL CHECK (card_kind IN ('free', 'double_up')),
    balance    integer NOT NULL DEFAULT 0 CHECK (balance >= 0),
    PRIMARY KEY (user_id, card_kind)
);

CREATE TABLE promotion.card_log (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id        bigint NOT NULL,
    card_kind      text NOT NULL,
    delta          integer NOT NULL,
    balance_after  integer NOT NULL,
    reason         text NOT NULL,
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX card_log_user_idx ON promotion.card_log (user_id, id DESC);

CREATE TABLE promotion.history (
    id            bigint GENERATED ALWAYS AS IDENTITY,
    at            timestamptz NOT NULL DEFAULT now(),
    promotion_id  bigint NOT NULL,

    caller text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL,
```

## 5. 前端设计

- `torrent.list.row_badges`：每页一次 `GET /torrents?ids=`（前端 SDK 批量）；徽标颜色按 kind；剩余时间 < 24 h 显示倒计时。
- `torrent.detail.header`：主促销 + 全站活动 + “对你生效：上传 2x / 下载 0x”。
- `torrent.detail.actions`：“使用个人卡”（有余额时显示），`card_redundant` 时弹窗确认；版主“设置促销”对话框（类型、时长快捷项 6h/24h/3d/7d/自定义）。
- `home.announcements`：全站活动横幅（Markdown 经安全渲染器）。
- 后台：规则列表（拖拽调整优先级）、规则编辑器（谓词构建器，共用组件）、预览命中数、活动日历。

## 6. 安全设计

| 点 | 措施 |
|---|---|
| 越权 | 单种设置需 `promotion.create`；规则与活动需 `promotion.manage`；服务 `create`/`end` 需作用域 `write`，`end` 只能结束自己创建的 |
| 滥用 | 单种批量 ≤ 1000；时长上限；custom 方向限制；全部写审计（`ctx.audit`）与 history |
| 横幅 XSS | Markdown 经统一安全渲染器（comments 插件定义的渲染器 crate），禁止原始 HTML |
| 信息泄露 | `current` 对不存在 / 无权查看的种子返回 none |

## 7. 性能设计

- `current_many` 500 项：一次 MGET + 一次 `ANY($1)` 查询（缓存未命中部分）。
- `on_swarm_stats`：每事件 ≤ 1000 项，镜像一条批量 UPDATE；只对跨阈值的种子评估，预计每批 < 50 次评估。
- accounting 规则数：每种子一条；15 万条时 accounting 进程内索引约 15 万 × ~150 B ≈ 22 MiB（每副本），可接受。

## 10. 对平台契约的新增（补充）

- 请 torrent 在 `torrent.created` 载荷中加入 `file_count`、`created_at`（目前镜像只能用事件的 `occurred_at` 近似发布时间）。
- `traffic.swarm_stats_updated` 只含有变化的种子；本插件依赖它维护做种数镜像。accounting 若有“全量刷新”能力（例如每日一次全量发布），可减少镜像漂移（与 accounting 设计确认）。
