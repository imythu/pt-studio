## 1. 设计目标与原则

1. **搜索插件不认识业务**：字段、分组、可见性取值全部来自贡献者；搜索插件只负责合并、同步、查询与安全。
2. **可见性在服务端强制，且只能收紧**：基线过滤由本插件生成，`search.before_query` 只能追加条件，任何入口（HTTP、MCP、服务调用、tenant token）走同一个过滤生成器。
3. **数据库是同步的真相**：事件处理只写 PG 待写表（受 inbox 恰好一次保护）；写 Meilisearch 是可重放的“按主键替换”，失败重来。
4. **写放大最小化**：窗口合并、文档哈希去重、做种数部分更新、向量按正文哈希复用；不把按用户的行为数组写进文档。
5. **零停机**：设置能就地改的就地改，字段集合变化走 swap 重建；查询方只认在线 uid，不感知代数。
6. **只依赖 CE**：默认部署不需要 Meilisearch 商业授权。
7. **遵守平台约束**：Native 插件但不依赖进程内后台线程——所有异步工作由事件订阅、cron、延迟任务驱动，天然支持多副本。

## 2. 总体结构

### 2.1 在整体架构中的位置

```
                       ┌───────────── 内核 ─────────────┐
 前端 / MCP ──HTTP────►│ 网关(鉴权/权限/限流) ─► search 路由 │
 rss / ai-* ──服务调用──►│ 服务注册表 ─► ctx.search          │
                       │ 事件中继 ─► on-event(订阅)       │──► PG: search_meilisearch.*（待写、已索引、重建、实例游标）
                       │ 调度器 ─► on-cron / 延迟任务     │──► Redis: p:search-meilisearch:*（缓存、锁）
                       │ 多实现调用 ─► 贡献者 search-contributor ──► torrent / type-* / accounting / promotion
                       └──────────────┬─────────────────┘          / mediainfo / subtitles / requests / forum / identity
                                      │ HTTPS（reqwest，长连接池）
                                      ▼
                    Meilisearch primary ──(本插件扇出写入)──► replica × N（CE）
                    或 Meilisearch EE network（leader + remotes，可选）
```

### 2.2 内部模块

| 模块 | 职责 |
|---|---|
| `meili_client` | Meilisearch HTTP 客户端：多实例、超时、熔断、版本检查、任务等待；只在本模块出现 API key |
| `schema` | 拉取贡献者 schema、校验命名、合并、生成 Meilisearch 设置与设置哈希；同义词汇总 |
| `registry` | 逻辑索引登记（标准 + 扩展）、拥有者映射、在线 uid / 构建 uid、状态机 |
| `ingest` | 事件 → 标脏（映射表）；`touch`/`remove` 服务入口；做种数暂存 |
| `flusher` | 取待写批次 → 调贡献者生成片段 → 合并 → 标题预处理 → 敏感检查 → 向量 → 写 Meilisearch / oplog；删除优先 |
| `stats` | 做种数部分更新批量写入 |
| `rebuild` | 重建状态机：建索引 → 枚举 → 双写 → 触碰重放 → 校验 → swap → 清理 |
| `query` | 请求校验、可见性基线、钩子、表达式生成、缓存、混合搜索、结果后处理（高亮、游标） |
| `release_parser` | 发布名解析与标题规范化（纯函数，有完整单元测试） |
| `replication` | `replicas` 模式下的 oplog、每实例游标、追赶与健康检查；`network` 模式适配 |
| `tenant` | tenant token 专用 key 管理与签发 |
| `admin` | 后台 API、一致性巡检、失败任务回收 |
| `mcp` | `search_torrents` 工具 |

## 3. 对外接口清单

### 3.1 提供的服务（`ctx.search@0.1.0`）

| 方法 | 说明 | 作用域 |
|---|---|---|
| `query(SearchRequest) -> SearchResult` | 查询，服务端强制可见性（按调用 actor 计算） | 无；`query:all` 可跳过可见性（新增，见 §7） |

| `schema(index) -> IndexSchemaView`（新增） | 合并后的字段视图（筛选面板） | 无 |

## 4. 数据设计概要

| 数据 | 存储 | 说明 |
|---|---|---|
| 逻辑索引登记、合并 schema、设置哈希、代数 | PG `search_meilisearch.indexes` | |
| 待写实体（普通 / 优先） | PG `pending_ops` | 主键 (index, entity_id)，合并 |
| 做种数暂存 | PG `swarm_stats_pending` | 主键 torrent_id |
| 已索引记录 | PG `indexed_docs`（hash 分区 16） | doc_hash、text_hash |
| 重建 | PG `rebuilds`、`rebuild_touched` | |
| 同义词（管理员） | PG `custom_synonyms` | |
| Meilisearch 任务跟踪 | PG `meili_tasks` | 等待、失败回收 |
| 多实例 oplog 与游标 | PG `oplog`、`instances` | 仅 `replicas` 模式写 oplog |

## 5. 关键流程

### 5.1 增量同步（普通通道）

```
事件 torrent.updated(id=5501)
 → on-event（inbox 去重）
 → UPSERT pending_ops(index='torrents', entity_id=5501, op='upsert', lane='normal', seq=nextval)
 → jobs.schedule_once('flush', run_at=ceil(now, 2s), dedupe_key='flush:torrents:normal:<bucket>')
 ... 2 s 后 ...
 flush 任务：取 Redis 锁 lock:flush:torrents
   SELECT … FROM pending_ops WHERE index='torrents' AND lane='normal' ORDER BY seq LIMIT 1000 FOR UPDATE SKIP LOCKED
   → 贡献者批量生成片段（拥有者 torrent 先；返回 none ⇒ 改为删除）
   → 合并、规范化、敏感检查、doc_hash 比较（未变跳过）
   → （需要时）ctx.llm.embed
   → PUT /indexes/pt_torrents/documents（部分更新，缺失字段显式 null）+ 删除批
   → 记录 meili_tasks；更新 indexed_docs；DELETE pending_ops WHERE (index, entity_id, seq) 匹配
   → sql.commit()，循环直到批空
```

### 5.2 删除优先

```
torrent.status_changed(to=disabled) / torrent.deleted
 → UPSERT pending_ops(lane='priority', op = deleted ? 'delete' : 'upsert')
 → jobs.schedule_once('flush', run_at=now, dedupe_key='flush:torrents:priority:<1s bucket>')
 flush(priority)：先于普通批执行；写入后 INCR qcgen:torrents（缓存全部失效）
```

### 5.3 做种数部分更新

```
traffic.swarm_stats_updated{items[…]} ─► UPSERT swarm_stats_pending … WHERE observed_at 更新
cron flush_swarm_stats（每分钟）：
  取 5000 行 → 过滤 indexed_docs 中存在的 torrent → PUT documents [{id, accounting_seeders, accounting_leechers, accounting_completed}]
  → 删除已写行（按 observed_at 匹配）→ commit → 下一批
```

### 5.4 重建（swap）

```
POST admin/indexes/torrents/rebuilds ──► rebuilds(state=preparing)
 rebuild_step:
  preparing   : 删除残留 pt_torrents__next；创建；PATCH 设置；等待任务成功 → building；indexes.dual_write_uid = pt_torrents__next
  building    : 按 id 游标枚举（list-ids 或视图）每步 5000 → 贡献者批量生成 → 写 __next（复用旧向量）→ 存游标 → 重新调度
  replaying   : rebuild_touched 中的实体（双写期间被触碰过的）重新生成写入 __next
  verifying   : 等待 __next 全部任务完成；比对文档数（与拥有者实体数差异 ≤ 0.1%）
  swapping    : POST /swap-indexes [{indexes:[pt_torrents, pt_torrents__next]}]；等待任务 → generation+1；清 dual_write_uid
  cleanup     : 删除 pt_torrents__next（此时是旧数据）→ INCR qcgen → 发布 search.index_rebuilt → done
```

### 5.5 查询

```
HTTP POST /v1/search ─► 内核（鉴权、use 权限、限流）─► query 模块
 1 校验请求（索引、audience、字段、操作符、长度）
 2 调用者画像：user_id、class_id（ctx.users，缓存 30 s）、restricted/admin 权限（ctx.rbac）
 3 基线过滤 + 用户过滤 → 表达式列表
 4 ctx.hooks.run("search.before_query") → 只追加
 5 组装 Meili 请求（q 规范化、locales、facets、sort、distinct、hybrid、高亮标记）
 6 缓存键 = sha256(index | qcgen | 规范化请求)；命中返回
 7 未命中：语义查询先取查询向量（缓存）→ 选实例 → POST /indexes/<uid>/search（超时 2 s，熔断）
 8 后处理：displayed 字段裁剪、高亮标记、游标 → 写缓存 → 返回
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| DD-SRCH-1 | 增量同步驱动方式 | A 轮询 PG 时间戳（Gazelle delta）；B 事件直写 Meili；C 事件 → PG 待写表 → 延迟任务批量写 | **C** | inbox 给出恰好一次的标脏；合并窗口降低写放大；Meili 写失败可整批重来；全部由内核调度驱动，多副本无需额外协调 |
| DD-SRCH-2 | 是否允许前端直连 / 暴露 Meili 内置 MCP 与 chats | 默认直连 / 默认代理 | **默认代理**；tenant token 可选；Meili 的 `/chats`、内置 MCP 端点**禁止**经网关暴露，部署文档要求 Meili 只在内网 | 可见性、限流、术语只能在服务端统一；Meili 内置 MCP 用 master/普通 key 访问，绕过 `search.before_query` |
| DD-SRCH-3 | 可见性如何表达 | A 各索引自定义；B 统一可见性字段 | **B**：每个文档必须有 `vis_level`（`public` / `member` / `staff`）、`vis_min_class`（int）、可选 `vis_owner_id`；由拥有者写入 | 过滤生成器通用；tenant token 同一套；拥有者最清楚业务状态 → 可见性映射（候选、待审、等级限定） |
| DD-SRCH-4 | 已删除资源 | 文档内 `deleted` 标记过滤 / 物理删除 | **物理删除**（优先通道）+ 缓存代数失效 | 避免任何过滤遗漏导致泄露；索引更小 |
| DD-SRCH-5 | 全量重建 | A 原地清空重灌；B 新索引 + swap | **B**，在线 uid 固定为 `<prefix>_<index>`，构建 uid `__next`，swap 后删除旧数据 | swap 原子（Meili 官方保证全部成功或全部失败）；查询方不感知代数；不需要别名功能 |
| DD-SRCH-6 | 按用户行为字段（我在做种、我的收藏） | 写入文档（UNIT3D）/ 不写 | **不写**；“只看我在做种”由前端先取 `ctx.accounting.seeding_now` 的 ID 列表，作为 `id IN [...]` 过滤（≤ 1000 个，超出分批或降级） | 避免每个用户行为触发文档重写；用户 ID 不进公共索引更利于隐私 |
| DD-SRCH-7 | 贡献者字段命名 | 自由命名 / 前缀 | 拥有者可无前缀；其他贡献者必须以 `<schema>_`（type-* 用 `<type_id>_`）开头；保留 `vis_`、`rel_`、`_` | 防止插件间字段冲突；与 plugin-api 示例 `movie_imdb_id` 一致 |
| DD-SRCH-8 | 术语改名后可搜 | 把术语名称写进文档 / 同义词 | **同义词**：可搜索的术语键型字段（如 `tags = ["official"]`）的每个值，派生同义词组 `[official, 官方, Official, …]` | 术语改名只需就地更新 synonyms 设置，不重写千万文档 |
| DD-SRCH-9 | 向量来源 | Meili 内置 embedder / `ctx.llm` | **两种都支持**，默认 `none`；`llm` 模式用 `userProvided` embedder + `_vectors.regenerate=false` | `ctx.llm` 统一计费与审计（`llm.usage_recorded`）；内置 embedder 适合不配 LLM 插件的站点，但 API key 存在 Meili 设置中、Meili 需出站 |
| DD-SRCH-10 | 内容更新用全量替换还是部分更新 | `POST documents`（替换）/ `PUT documents`（合并） | **PUT 合并**，合并 schema 中本次缺失的字段显式置 `null`，`_vectors` 仅在正文哈希变化时携带 | 替换会丢失未携带的 `_vectors`；显式 null 防止旧字段残留 |
| DD-SRCH-11 | 访问 Meilisearch 的网络通道 | 经内核 `http-client`（禁止内网地址）/ Native 直连 | **Native 直连**（reqwest，地址仅来自 site.toml 静态配置，不接受运行时输入） | `http-client` 的 SSRF 防护禁止内网地址，而 Meili 必须在内网；Native 插件已与内核同信任级别（security.md §5） |
| DD-SRCH-12 | 多实例 | 等待 Meili CE 复制 / 自建扇出 / EE network | **默认 single；可选 replicas（自建 oplog 扇出）；可选 network（EE）** | CE 无复制（已核实：复制与分片仅 EE v1.37+）；自建扇出逻辑简单可控；EE 留给有商业授权的站点 |
| DD-SRCH-13 | 部分更新造成残缺文档 | 依赖 Meili 行为 / 写前过滤 | 写前按 `indexed_docs` 过滤；可见性字段缺失的文档天然被基线过滤排除（双保险） | Meili 部分更新对不存在的主键会新建文档 |
| DD-SRCH-14 | 贡献者失败 | 整批失败 / 跳过该贡献者 | 拥有者失败 → 整个实体重试；非拥有者失败 → 该实体本次缺这些字段并标记 `partial`，延迟 60 s 再标脏一次 | 不因一个类型插件故障阻塞全站同步 |
| DD-SRCH-15 | 过滤输入 | 允许原始表达式 / 只允许结构化 | 只允许结构化；钩子处理者（受信插件）可追加原始表达式，本插件用解析器校验其只引用可筛选字段 | 杜绝表达式注入（NexusPHP 教训） |

## 7. 对平台契约的新增

| 类别 | 新增项 | 说明 |
