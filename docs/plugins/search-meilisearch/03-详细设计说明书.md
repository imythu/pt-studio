### 1.2 schema 模块：贡献者发现与合并

**输入**：`ctx.plugins.search_contributors()` → `[plugin_id]`；对每个贡献者调用 `index-schemas()`（超时 2 s）。

**内部结构**：

```rust
pub struct MergedField {
    pub name: String, pub ty: FieldType,          // String | Int | Float | Bool | Timestamp | StringArray
    pub searchable: bool, pub filterable: bool, pub sortable: bool,
    pub rank: u8, pub exact: bool, pub label_term: String,
    pub source_plugin: String, pub is_owner_field: bool,
}
pub struct MergedIndex {
    pub index: String, pub owner: String, pub audience: Audience,   // User | Admin
    pub fields: BTreeMap<String, MergedField>,
    pub title_fields: Vec<String>, pub embed_fields: Vec<String>,
    pub contributor_versions: BTreeMap<String, String>,              // plugin_id -> schema version
    pub synonyms: Vec<Vec<String>>,                                   // 贡献者提供
    pub conflicts: Vec<SchemaConflict>,
}
```

**合并算法**：

```
fn merge(index, decls: Vec<(plugin_id, IndexSchema)>) -> MergedIndex:
    owner = registry.owner_of(index)        // 标准索引见 §1.4；扩展索引为 register_index 的调用方
    require decls 中存在 owner 的声明，否则索引状态 = waiting_owner（不建 Meili 索引）
    按 (plugin_id == owner ? 0 : 1, plugin_id) 排序 decls          // 拥有者优先，其余字典序，结果确定
    fields = {} ; conflicts = []
    加入保留字段：id(Int, filterable, sortable)、vis_level(String, filterable equality)、
                  vis_min_class(Int, filterable comparison)、vis_owner_id(Int, filterable equality)、
                  created_at(Timestamp, sortable, filterable comparison)
    for (pid, s) in decls:
        for f in s.fields:
            err = validate_name(pid, owner, f.name)               // 见下
            if err: conflicts.push(err); continue
            if f.name in fields:
                if fields[f.name].source_plugin != pid: conflicts.push(Duplicate{f.name, pid}); continue
            if f.field_type ∉ 类型表: conflicts.push(BadType); continue
            fields[f.name] = from(f, pid)
        synonyms += s.synonyms（每组 2～20 个词，每词 ≤ 64 字符，非法丢弃）
    加入 rel_* 字段（若 title_fields 非空，且无同名字段）：rel_resolution, rel_source, rel_video_codec,
        rel_audio_codec(StringArray), rel_hdr(StringArray), rel_group, rel_year(Int)；全部 filterable、exact
    对每个 title_field t 加入 t + "_norm"（String, searchable, rank = rank(t)）
    return MergedIndex{…}
```

**字段命名校验 `validate_name`**：

| 规则 | 说明 |
|---|---|
| 正则 `^[a-z][a-z0-9_]{0,62}$` | 不允许点号（Meili 用点号表示嵌套路径）与大写 |
| 保留前缀 `vis_`、`rel_`、`_`、保留名 `id`、`created_at` | 只有本插件（及拥有者对 `vis_*`、`id`、`created_at` 提供值）可用 |
| 非拥有者前缀 | `type-<x>` 插件须以 `<x>_` 开头（如 `movie_`）；其他插件须以 schema 名 + `_` 开头（如 `accounting_`、`promotion_`） |
| 敏感黑名单 | 名称中任何 `_` 分段等于 `passkey`、`email`、`ip`、`password`、`token`、`secret`、`totp`、`webauthn` → 拒绝（`email_hash` 例外：仅允许 audience = admin 的索引） |

**设置哈希**：对生成的设置 JSON 做规范化（键排序）后 `sha256`。**文档形状哈希**：对 `{fields 名称与类型, title_fields, embed_fields, contributor_versions}` 做 `sha256`。

### 1.3 Meilisearch 设置生成

```
fn build_settings(m: &MergedIndex, synonyms: Synonyms, cfg) -> Json:
  searchable = m.fields.filter(searchable).sort_by(rank, name).names()
  filterable = [
     { attributePatterns: [字符串型 & filterable & label_term 非空 的字段],     features: {facetSearch: true,  filter: {equality: true, comparison: false}} },
     { attributePatterns: [字符串型 & filterable & label_term 为空],             features: {facetSearch: false, filter: {equality: true, comparison: false}} },
     { attributePatterns: [数值/时间/布尔 & filterable],                         features: {facetSearch: false, filter: {equality: true, comparison: true}} },
  ]  （空组省略）
  sortable = m.fields.filter(sortable).names()
  typo = { enabled: true,
           minWordSizeForTypos: {oneTypo: cfg.typo_min_word_one, twoTypos: cfg.typo_min_word_two},
           disableOnAttributes: m.fields.filter(exact).names() ∪ {所有 rel_*},
           disableOnWords: 词包 disable_on_words,
           disableOnNumbers: true }
  localized = [
     { attributePatterns: m.fields.filter(searchable && name 以 _zh 或 _cn 结尾).names(), locales: ["cmn"] },
     { attributePatterns: m.fields.filter(searchable && name 以 _en 或 _original 结尾 或 为 *_norm).names(), locales: ["eng"] },
  ]  （其他字段交给 Meili 自动检测）
  ranking = ["words","typo","proximity","attribute","sort","exactness"] + 拥有者声明的自定义规则（如 "created_at:desc"，仅允许 sortable 字段）
  displayed = m.fields.names() − {embed 正文辅助字段}（audience = user 的索引不得含 email_hash 等）
  return {
    searchableAttributes, filterableAttributes, sortableAttributes, displayedAttributes,
    typoTolerance, localizedAttributes, rankingRules,
    synonyms: synonyms.to_meili_map(),          // 见 §1.8
    dictionary: 词包 dictionary（如 "WEB-DL","Blu-ray","DTS-HD","DD+","Atmos","HDR10+"）,
    separatorTokens: [], nonSeparatorTokens: ["+"]   // 保留 DD+、HDR10+
    pagination: {maxTotalHits: cfg.max_total_hits},
    faceting: {maxValuesPerFacet: 100, sortFacetValuesBy: {"*": "count"}},
    proximityPrecision: "byAttribute",
    embedders: embedder_settings(cfg)           // §1.9；mode=none 时为 null（删除）
  }
```

**就地 vs 重建判定（启动与同义词变更时）**：

| 变化 | 处理 |
|---|---|
| 仅设置哈希变化，文档形状哈希不变 | `settings_apply`：`PATCH /indexes/<live>/settings`（Meili 异步重建内部结构，期间旧设置继续可查） |
| 文档形状哈希变化（新增/删除字段、贡献者 schema `version` 变化、title/embed 字段变化） | `auto_rebuild = true` → 创建重建（trigger = `auto`）；否则索引标记 `stale`，后台提示 |
| embedder 维度或来源变化 | 必须重建（向量不可复用） |

多副本并发：`init` 中对 `indexes` 行 `SELECT … FOR UPDATE` 后比较哈希，只有拿到行锁且哈希不同的副本写入新哈希并调度任务（延迟任务 `dedupe_key = settings:<index>:<hash>`）。

### 1.4 registry：逻辑索引与状态

| 逻辑索引 | 拥有者 | audience | 在线 uid | 主键 | 默认 distinct |
|---|---|---|---|---|---|
| `torrents` | torrent | user | `<prefix>_torrents` | `id` | 可选 `group_id` |
| `groups` | torrent | user | `<prefix>_groups` | `id` | — |
| `requests` | requests | user | `<prefix>_requests` | `id` | — |
| `forum` | forum | user | `<prefix>_forum` | `id`（post_id） | 可选 `forum_topic_id` |
| `users_admin` | identity | admin | `<prefix>_users_admin` | `id` | — |
| 扩展索引 | `register_index` 调用方 | 调用方声明 | `<prefix>_<index>` | `id` | 声明 |

扩展索引名规则：`^<schema>_[a-z0-9_]{1,40}$`（`schema` 为调用方插件 schema 名），如 `subtitles_files`。

索引状态：`waiting_owner` → `creating` → `ready` ⇄ `rebuilding`；`stale`（形状变化未重建）；`disabled`（拥有者未启用）；`degraded`（存在 schema 冲突或贡献者故障，仍可查询）。

**标脏 SQL**：

```sql
INSERT INTO pending_ops (index_name, entity_id, op, lane, enqueued_at, first_enqueued_at, source_event_id)
VALUES ($1, $2, $3, $4, now(), now(), $5)
ON CONFLICT (index_name, entity_id) DO UPDATE
   SET op = EXCLUDED.op,
       lane = CASE WHEN pending_ops.lane = 'priority' OR EXCLUDED.lane = 'priority' THEN 'priority' ELSE 'normal' END,
       seq = nextval('pending_ops_seq'),
       enqueued_at = now(),
       source_event_id = EXCLUDED.source_event_id;
```

`op` 以最后一次为准（先删后建的实体最终为 upsert；拥有者在 `to-document` 返回 none 时 flusher 自动转删除，所以“最后一次为准”是安全的）。

**调度 flush**：

```
bucket_ms = lane == priority ? 1000 : settings.flush_window_ms
run_at = lane == priority ? now : (floor(now / bucket_ms) + 1) * bucket_ms
ctx.jobs.schedule_once("flush", run_at, {"index": idx, "lane": lane}, dedupe_key = "flush:<idx>:<lane>:<run_at>")
```

延迟任务与业务写入同事务（kernel/03 §9.2），因此“标脏成功但没调度”的情况不存在；`flush_sweeper` 仍兜底处理 `enqueued_at < now - 10s` 的行。

**重建期间**：若 `indexes.dual_write_uid` 非空，标脏同时 `INSERT INTO rebuild_touched(rebuild_id, entity_id) ON CONFLICT DO NOTHING`。

### 1.6 flusher：批量写入

```
on_cron(job "flush", payload {index, lane}):           // tx = manual
  lock = redis SET lock:flush:<index>:<lane> <run_id> NX PX 60000；失败 → 返回 ok（另一副本在处理，行仍在表中）
  loop（直到批空或已运行 25 s）:
    rows = SELECT index_name, entity_id, op, seq FROM pending_ops
           WHERE index_name=$1 AND lane=$2 [AND enqueued_at <= now() - window（normal 时）]
           ORDER BY seq LIMIT settings.batch_size FOR UPDATE SKIP LOCKED
    if rows 为空: break
    upserts = rows.filter(op=upsert).ids; deletes = rows.filter(op=delete).ids
    frags = contributors_batch(index, upserts)        // §1.6.1
    docs = []; for id in upserts:
        if frags.owner[id] is None: deletes.push(id); continue
        doc = merge_fragments(frags, id)                // 拥有者先，后者不覆盖已存在键
        doc = normalize(doc)                            // §1.7 标题预处理、rel_* 解析、NFC
        sensitive_check(doc) ?: { metric; deletes.push(id)?? 否 → 记录 failed，跳过该实体并告警 }
        fill_nulls(doc, merged.fields)                  // 合并 schema 中缺失的字段 = null
        h = blake3(canonical(doc)); th = blake3(embed_text(doc))
        if indexed_docs[id].doc_hash == h: skip（仍删除 pending 行）
        if embedder.mode == llm && indexed_docs[id].text_hash != th: need_embed.push(id)
        docs.push(doc)
    vectors = embed_batch(need_embed)                  // ctx.llm.embed，每批 ≤ 64 条，失败 → 不带 _vectors 写入并标记 text_hash = NULL（下次重试）
    targets = [live_uid] + (dual_write_uid ? [dual_write_uid] : [])
    for uid in targets:
        if docs: t1 = meili.update_documents(uid, docs, primaryKey="id")     // PUT /indexes/{uid}/documents
        if deletes: t2 = meili.delete_batch(uid, deletes)                  // POST /indexes/{uid}/documents/delete-batch
        record meili_tasks(t1,t2)
    if mode == replicas: INSERT oplog(index, op, ids, docs_zstd)          // §1.10
    UPSERT indexed_docs（docs）；DELETE indexed_docs（deletes）
    DELETE FROM pending_ops p USING unnest($ids,$seqs) AS x(id,seq) WHERE p.index_name=$1 AND p.entity_id=x.id AND p.seq=x.seq
    if lane == priority: redis INCR qcgen:<index>
    sql.commit()
  release lock（Lua 不可用 → 仅当 GET == run_id 时 DEL；非原子窗口可接受，锁 60 s 自然过期）
```

- **顺序保证**：同一索引同一通道同一时刻只有一个 flush 在运行（锁），读取（贡献者调用）与入队 Meili 任务的顺序一致；Meili 对同一索引按入队顺序执行任务，因此后读到的状态一定后生效。优先通道与普通通道可能并发：两者都“读取当前状态”，若优先通道先读到“已下架”、普通通道后读到“已下架后又恢复”也是正确的最终状态；反向（普通先读旧状态、优先后写删除，然后普通再写入旧状态）通过“普通通道写入前再次检查该实体是否存在 lane=priority 的待写行或 `priority_epoch` 是否变化”避免：普通批在调用 Meili 前执行 `SELECT entity_id FROM pending_ops WHERE lane='priority' AND entity_id = ANY($ids)`，命中的实体从本批剔除（留给优先通道）。
- **幂等**：Meili 写是按主键的合并/删除，重复执行结果相同；`pending_ops` 行只在 Meili 接受任务（返回 `taskUid`）后删除。Meili 接受后任务失败由 `task_reaper` 回收（§1.11）。
- **超时**：job `timeout_secs = 60`；单次 Meili 写超时 10 s；超时视为失败，事务回滚，行保留。

#### 1.6.1 贡献者批量调用

```
contributors_batch(index, ids):
    for c in contributors(index):                     // 拥有者先
        if c 实现 to-documents: r = c.to_documents(index, ids)（每次最多 500 个 id，超时 5 s）
        else: r = 并发 8 个调用 c.to_document(index, id)（每个超时 2 s）
        失败处理：c == owner → 整批返回错误（事务回滚，下次重试）；
                  非拥有者 → 该贡献者字段缺失，metric contributor_failures{plugin}，
                  对这些 id 调度一次延迟 60 s 的 touch（dedupe_key = retry:<index>:<plugin>:<minute>）
        片段校验：必须是 JSON 对象；键必须是该贡献者在 schema 中声明的字段（拥有者还可写保留字段）；
                  未声明的键丢弃并计数（防止贡献者把未声明字段塞进文档）
```

#### 1.6.2 拥有者必须提供的字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 实体 ID |
| `vis_level` | string | `public`（游客也可见，预留）、`member`（登录用户）、`staff`（需 `restricted.read`） |
| `vis_min_class` | int | 等级下限，默认 0 |
| `vis_owner_id` | int? | 所有者用户 ID：所有者总能看到自己的 staff 级文档（如自己的待审种子）。**匿名发布时必须省略** |
| `created_at` | int | Unix 秒（Meili 按数字比较） |

torrent 的建议映射（由 torrent 插件最终决定，写入其 LLD）：`approved → member`；`candidate → settings.candidate_visibility`；`pending → staff`；`rejected/disabled → 删除（优先通道）`；等级限定资源写 `vis_min_class`。

### 1.7 release_parser：标题预处理

纯函数 `normalize_title(s) -> String` 与 `parse_release(s) -> ReleaseInfo`。

**规范化步骤**：

1. Unicode NFKC 仅作用于全角 ASCII（U+FF01～U+FF5E → ASCII），其余字符 NFC；去控制字符。
2. 保护片段（不拆）：`\d+\.\d+`（如 `5.1`、`7.1`、`2.0`）、`[HhXx]\.26[45]`、`DD[P+]?\d\.\d`、`AAC\d\.\d`、`DTS-HD(\.MA)?`、`WEB-DL`、`Blu-ray`、`HDR10\+?`。
3. 把未受保护的 `.`、`_`、`[`、`]`、`【`、`】`、`(`、`)` 替换为空格；合并连续空格。
4. 中文与拉丁字母、数字之间插入空格（`流浪地球2.2023` → `流浪地球 2 2023`；帮助分词边界），但数字与 `p`/`i` 相连的分辨率保持（`2160p`）。

**解析**（词典驱动，`data/release_dict.toml`）：

| 字段 | 规则（大小写不敏感，取最后出现者） | 规范值 |
|---|---|---|
| `rel_resolution` | `4320p`、`2160p`/`4K`/`UHD`、`1080p`、`1080i`、`720p`、`576p`、`480p` | `2160p` 等 |
| `rel_source` | `Remux`、`Blu-ray`/`BluRay`/`BD`、`WEB-DL`/`WEBDL`、`WEBRip`、`HDTV`、`DVD`、`UHD BluRay` | `bluray`、`remux`、`web_dl`、`webrip`、`hdtv`、`dvd` |
| `rel_video_codec` | `x265`/`H.265`/`H265`/`HEVC` → `hevc`；`x264`/`H.264`/`AVC` → `avc`；`AV1`；`VC-1`；`MPEG-2` | 规范小写 |
| `rel_audio_codec` | `TrueHD`、`Atmos`、`DTS-HD MA`、`DTS:X`、`DTS`、`DDP`/`DD+`/`EAC3`、`DD`/`AC3`、`AAC`、`FLAC`、`LPCM`、`Opus` | 数组 |
| `rel_hdr` | `DV`/`DoVi`/`Dolby Vision`、`HDR10+`、`HDR10`/`HDR`、`HLG` | 数组 |
| `rel_group` | 末尾 `-Group` 或 `@Group`（`[A-Za-z0-9]{2,20}`），排除词典中的已知非组名（`DL`、`HD`、`MA`） | 原样 |
| `rel_year` | `(19|20)\d{2}`，且不紧邻分辨率数字 | int |

贡献者已提供同名语义字段（如 `movie_resolution`）时，`rel_*` 仍写入（供跨类型统一筛选），但筛选面板对同一资源类型优先展示类型字段（schema 接口中 `rel_*` 标记 `generic = true`）。

**查询规范化**：查询串经步骤 1～4 处理；若用户输入的是整段发布名（含 ≥ 3 个 `.` 分隔片段），附加 `matchingStrategy = "all"`。

### 1.8 同义词汇总

来源（按优先级合并，每个索引独立）：

1. 内置 PT 词包 `data/synonyms_pt.toml`（组）：`[2160p, 4K, UHD]`、`[hevc, h265, x265, h.265]`、`[avc, h264, x264, h.264]`、`[bluray, blu-ray, bd]`、`[web-dl, webdl]`、`[ddp, dd+, eac3, e-ac-3]`、`[dovi, dv, dolby vision]`、`[remux, 原盘remux]`、`[国语, 普通话, mandarin]`、`[粤语, cantonese]`、`[中字, 中文字幕, chs]`……
2. 贡献者 `index-schema.synonyms`（如 type-movie 的中英文片名对）。
3. **术语派生**：对 schema 中 `label_term` 指向术语族、且值为术语键后缀的可搜索字段（约定：字段声明 `label_term` 形如 `torrent.tag` 族，值 `official` 对应术语键 `torrent.tag.official`），对每个值 v 生成组 `[v, name(zh-CN), name(en), short(各语言)…]`（经 `ctx.terms.get_many` 取全部 `site.locales`）。
4. 管理员 `custom_synonyms`（可限定索引，`kind` = `group` 双向 / `oneway` 单向 `input → synonyms`）。
5. 简繁：Meili 分词器自带中文归一化；另提供可选的“简繁对照”导入（管理员上传对照表，生成单向同义词），默认不启用。

**展开为 Meili 格式**：Meili `synonyms` 为 `{词: [同义词…]}` 的单向映射。组 `[a,b,c]` 展开为 `a:[b,c]`、`b:[a,c]`、`c:[a,b]`；单向 `x → [y,z]` 只写 `x:[y,z]`。全部小写、去重；单个索引同义词条目上限 20,000（超过拒绝新增并告警）。

### 1.9 混合搜索

**embedder 设置**（名称固定 `pt_semantic`）：

| mode | 设置 | 文档 | 查询 |
|---|---|---|---|
| `none` | `embedders: null` | 不带 `_vectors` | 拒绝 `semantic` 请求（`search-meilisearch.semantic_unavailable`） |
| `llm` | `{"pt_semantic": {"source": "userProvided", "dimensions": <cfg>}}`（可加 `binaryQuantized: true`） | `_vectors: {"pt_semantic": {"embeddings": [...], "regenerate": false}}`；正文 = `embed_fields` 按声明顺序拼接，≤ 2000 字符 | `ctx.llm.embed([q], profile)` → `hybrid: {embedder: "pt_semantic", semanticRatio}` + `vector` |
| `meili` | 透传 `cfg.embedder.meili`（`source` ∈ `openAi`/`rest`/`huggingFace`/`ollama`…，`documentTemplate` 由本插件按 `embed_fields` 生成，`documentTemplateMaxBytes: 2000`） | Meili 自行生成 | `hybrid: {embedder: "pt_semantic", semanticRatio}`（无需 `vector`） |

- 查询向量缓存：Redis `qv:<sha256(model|q)>`，值为 f32 小端字节，TTL 24 h。
- 重建时复用：`building` 阶段对每批 id 先 `POST /indexes/<live>/documents/fetch {"ids": [...], "fields": ["id"], "retrieveVectors": true}` 取回向量，`text_hash` 未变（`indexed_docs`）即直接附带；只有变化或缺失的才调用 `ctx.llm.embed`。
- 预算：`llm` 模式每分钟 embed 文本数上限 `embed_rate_per_min`（默认 3000），超出的实体以无向量写入并 `text_hash = NULL`，由 `housekeeping` 逐步回填（向量缺失的文档在语义检索中排在最后，Meili 已说明）。

### 1.10 多实例

**mode = single**：一个实例，读写同一 URL。

**mode = replicas（CE）**：

- `instances` 中一个 `primary`、若干 `replica`。flusher 只写 PG `oplog`（不直接写任何实例）+ 立即调度 `apply:<instance>` 延迟任务；每个实例一个游标 `instances.applied_seq`。
- `apply` 任务：取 `oplog WHERE seq > applied_seq ORDER BY seq LIMIT 50` → 按序对该实例执行（docs 解压后 `PUT documents`、delete-batch、settings、swap）→ 记录任务 → `applied_seq = max(seq)` → commit。单实例串行（锁 `lock:apply:<instance>`）。
- **重建在 replicas 模式**：`preparing/swapping/cleanup` 的管理操作也写入 oplog（`op = create_index | settings | swap | delete_index`），保证各实例同序执行；`building` 阶段写入的文档同样走 oplog（文档量大时 oplog 体积 ≈ 文档 zstd 压缩后约 300 B/条，1000 万 ≈ 3 GB，保留到所有实例应用后再删除）。
- 读路由：健康（`/health` 200）且 `head_seq - applied_seq ≤ lag_max_ops`（默认 5000）且最近一次 apply 不早于 60 s 的实例进入轮询池；池为空时退化为 primary。
- 宕机实例恢复后从游标继续；若游标已落后于 oplog 保留下限（默认保留 48 h），标记 `needs_resync`，管理员对该实例触发“实例重建”（以 primary 为源用 `/export` 或重放全量重建）。

**mode = network（EE，可选）**：写入只发往 `role = leader` 的实例；查询带 `useNetwork: true` 发往任意实例；拓扑由运维用 Meili `/network` 配置，本插件只检测 `not_leader` 错误并告警。启动时检查 `/version` 的 edition 信息与配置一致，否则拒绝写入。

### 1.11 失败任务回收与巡检

- `task_reaper`（每 2 分钟）：`SELECT … FROM meili_tasks WHERE status = 'enqueued' AND enqueued_at < now() - 30s LIMIT 500` → `GET /tasks?uids=…` → 成功则删除记录；失败则把该任务涉及的实体（记录中的 `entity_ids`）重新标脏（lane 同原任务），`failed_count + 1`；同一实体连续失败 5 次进入 `poison` 列表（后台可见）并停止自动重试。
- `consistency_check`（每日）：对每个 user 级索引，按 id 区间 10,000 分段：拥有者 `list-ids`（或视图）与 `indexed_docs` 做集合差，缺失 → touch，多余 → remove；另抽样 1000 个 id `documents/fetch` 比对 `doc_hash`。每段一次 `sql.commit()`。

### 1.12 query 模块

```
fn query(req: SearchRequest, inv: InvocationInfo) -> PResult<SearchResult>:
    idx = registry.get(req.index) ?: index_not_found
    viewer = viewer_of(inv)                     // §1.12.1
    if idx.audience == Admin && !viewer.admin_index: kernel.forbidden
    validate(req, idx.schema)                    // 长度、字段、操作符、limit、cursor
    user_exprs = req.filters.map(|f| filter::to_expr(f, idx.schema))     // §1.12.2
    base = visibility_expr(viewer, idx)
    hook_in = {version:1, actor, index, query: req.query, filters: [base] + user_exprs, sort: req.sort, user_id, class_id}
    out = ctx.hooks.run("search.before_query", hook_in)?
    match out: Denied(d) → 返回 d.code（HTTP 403/422 由内核映射）；Allowed(final) →
    appended = final.filters[len(hook_in.filters)..]; for e in appended: filter::validate_raw(e, idx.schema)?   // 只引用可筛选字段
    filters = final.filters
    meili_req = {
       q: normalize_query(req.query), filter: filters（数组 = AND）, sort: req.sort.map(to_meili),
       offset, limit, facets: req.facets ∩ facetable, distinct: req.collapse ? idx.distinct_attr : null,
       attributesToRetrieve: idx.displayed_for(viewer), attributesToHighlight: idx.title_fields + "*_norm",
       highlightPreTag: "\u{E000}", highlightPostTag: "\u{E001}", attributesToCrop: [], showRankingScore: req.semantic,
       locales: infer_locales(req.query, inv.locale), matchingStrategy: …,
       hybrid: req.semantic ? {embedder: "pt_semantic", semanticRatio: req.semantic_ratio ?? settings.semantic_ratio} : null,
       vector: (mode == llm && req.semantic) ? query_vector(req.query)? : null }
    key = "qc:" + idx.name + ":" + GET qcgen:<idx> + ":" + sha256(canonical(meili_req))
    if cached = redis GET key: return decode(cached)
    inst = replication.pick_read_instance()
    resp = meili.search(inst, idx.live_uid, meili_req)（超时 request_timeout_ms；熔断 §1.12.4）
    result = postprocess(resp)                   // hits、facetDistribution、estimatedTotalHits、next_cursor
    redis SET key result EX cache_ttl_secs（结果 > 256 KiB 不缓存）
    return result
```

#### 1.12.1 调用者画像与可见性

```
viewer_of(inv):
   if "query:all" ∈ inv.caller_scopes: return Viewer::System          // 已获站点授权的系统查询
   user_id = inv.actor.user_id（kind ∈ user/mcp）；无 → Viewer::Anonymous（只看 public）
   u = cache uc:<uid> 30s || ctx.users.get(uid)；status ∈ {banned, deleted, pending} → Anonymous 视角
   restricted = ctx.rbac.check(uid, "search-meilisearch.restricted.read")（随 uc 缓存）
   admin_index = ctx.rbac.check(uid, "search-meilisearch.admin_index.read")
visibility_expr(v, idx):
   System     → "id >= 0"（恒真，占位以保持钩子输入结构一致）
   Anonymous  → "vis_level = 'public'"
   User(u)    → "(vis_level IN ['public','member'] AND vis_min_class <= {u.class_id}) OR vis_owner_id = {u.id}"
                 + restricted ? " OR vis_level = 'staff'" : ""
   admin 索引 → "id >= 0"（audience 检查已在前面完成）
```

服务调用（非 HTTP）时 actor 由内核传递：rss 以用户身份调用时按用户可见性；`system` actor 且无 `query:all` 作用域按 Anonymous 处理。

#### 1.12.2 结构化过滤

`Filter { field, op, values: Vec<Json> }`，`op` ∈ `eq`、`ne`、`in`、`not_in`、`gt`、`gte`、`lt`、`lte`、`between`、`exists`、`is_null`、`is_empty`。

- 字段必须 `filterable`；比较类操作符要求字段类型为数值/时间；`in`/`not_in` 最多 1000 个值。
- 值按字段类型校验：string ≤ 256 字符、去控制字符；int 为 i64；timestamp 接受 RFC 3339 转 Unix 秒。
- 字符串字面量生成：用单引号包裹，`\` → `\\`、`'` → `\'`（Meili 过滤语法支持反斜杠转义）。字段名只来自 schema，不来自用户原文。
- `filter::validate_raw`：用本模块的过滤表达式解析器（递归下降，覆盖 Meili 过滤语法子集：比较、`IN`、`TO`、`EXISTS`、`IS NULL`、`IS EMPTY`、`AND`/`OR`/`NOT`、括号）解析钩子追加的表达式，遍历标识符，全部必须为可筛选字段；解析失败 → 视为钩子处理者错误，返回 `kernel.hook_failed`（fail-closed）。

#### 1.12.3 游标与高亮

- 游标：`base64url(json{o: offset, h: sha256(请求去掉 offset 后)[0..8]})`；`offset + limit > max_total_hits` 或哈希不匹配 → 400 `kernel.bad_request`。
- 高亮：Meili `_formatted` 中的 `\u{E000}…\u{E001}` 原样返回为 `highlights.{field}: string`；前端按私用区字符切分并用 `<mark>` 组件渲染，文本节点由 React 转义。返回前删除原文中本就存在的 U+E000/U+E001（防伪造高亮）。

#### 1.12.4 熔断

每实例滑动窗口 30 s：失败率 > 50% 且请求 ≥ 20 → 打开 15 s；打开期间直接返回 `search-meilisearch.unavailable`（503，retryable），半开时放行 1 个请求。状态存进程内存（各副本独立，可接受）。

### 1.16 stats：做种数部分更新

订阅处理（Native `batch = 64`，整批一个工作单元）：

```sql
INSERT INTO swarm_stats_pending (torrent_id, seeders, leechers, completed, observed_at, event_id)
SELECT * FROM unnest($1::bigint[], $2::int[], $3::int[], $4::bigint[], $5::timestamptz[], $6::uuid[])
ON CONFLICT (torrent_id) DO UPDATE
   SET seeders = EXCLUDED.seeders, leechers = EXCLUDED.leechers, completed = EXCLUDED.completed,
       observed_at = EXCLUDED.observed_at, event_id = EXCLUDED.event_id
 WHERE swarm_stats_pending.observed_at < EXCLUDED.observed_at;   -- 乱序 / 回放的旧事件不覆盖新值
```

同一批内同一 torrent 出现多次时，先在内存按 `observed_at` 取最大再写入。

`flush_swarm_stats`（cron 每分钟，`tx = manual`，`timeout_secs = 55`）：

```
loop（≤ 50 s）:
  rows = SELECT s.* FROM swarm_stats_pending s
         JOIN indexed_docs d ON d.index_name='torrents' AND d.entity_id = s.torrent_id
         ORDER BY s.observed_at LIMIT stats_batch_size FOR UPDATE OF s SKIP LOCKED
  orphans = DELETE FROM swarm_stats_pending s WHERE NOT EXISTS (indexed_docs …) AND s.observed_at < now() - interval '1 hour'
            （未索引的种子：保留 1 小时等待其文档写入，之后丢弃——文档首次写入时由 accounting 贡献者提供当时值）
  if rows 空: break
  docs = rows.map(|r| {"id": r.torrent_id, "accounting_seeders": r.seeders, "accounting_leechers": r.leechers, "accounting_completed": r.completed})
  for uid in [live_uid] + dual_write_uid: task = meili.update_documents(uid, docs)；记录 meili_tasks(kind='stats')
  DELETE FROM swarm_stats_pending s USING unnest($ids, $observed) x(id, o) WHERE s.torrent_id = x.id AND s.observed_at = x.o
  sql.commit()
```

- 不更新 `indexed_docs.doc_hash`（统计字段不参与 doc_hash 计算：`canonical(doc)` 排除 `accounting_*` 统计字段），从而普通通道不会因统计变化重写文档；普通通道写入时贡献者给出的统计值是“当时值”，之后被部分更新覆盖，两者都是单调最新，偶发回退在下一次统计事件后自愈（可接受，≤ 5 分钟）。
- 不使缓存失效（统计字段允许 ≤ 缓存 TTL 的陈旧）。

### 1.17 rebuild：重建状态机

`rebuild_step` 延迟任务（`tx = manual`，`timeout_secs = 300`，payload `{rebuild_id, shard?}`），每次推进一步并在末尾重新调度自己（`dedupe_key = rebuild:<id>:<state>:<cursor>`）：

```
step(r):
  match r.state:
  preparing:
    meili.delete_index(r.target_uid)（不存在忽略）→ wait
    meili.create_index(r.target_uid, primaryKey="id") → wait
    meili.patch_settings(r.target_uid, build_settings(merged, synonyms)) → wait（失败 → failed）
    UPDATE indexes SET dual_write_uid = r.target_uid, status='rebuilding'
    r.expected_total = owner_count(index)（list-ids 计数或视图 count）；state = building；commit
  building:
    ids = owner.list_ids(index, after = r.cursor_id, limit = 5000)（无实现 → 视图 SELECT id … WHERE id > $1 ORDER BY id LIMIT 5000）
    if ids 空: state = replaying; commit; reschedule; return
    frags = contributors_batch(index, ids)；docs = merge/normalize/check
    if reuse_vectors && embedder 未变: vectors = meili.fetch_vectors(live_uid, ids)，text_hash 相同者复用
    meili.update_documents(r.target_uid, docs)；记录 meili_tasks
    UPSERT indexed_docs（hash 写入；向量复用状态）
    r.cursor_id = max(ids); r.done_count += len(ids); commit; reschedule(run_at = now)
  replaying:
    batch = SELECT entity_id FROM rebuild_touched WHERE rebuild_id = r.id ORDER BY entity_id LIMIT 5000
    对 batch 重新生成文档写入 target（实体已不存在 → 删除）；DELETE 已处理行；commit；为空则 state = verifying
  verifying:
    等待 meili_tasks(target_uid) 全部 succeeded（未完成 → reschedule(now + 10s)，最长 2 h）
    n = meili.stats(r.target_uid).numberOfDocuments
    if |n − r.expected_total| / max(1, expected) > 0.001: state = failed（保留 target 供排查，dual_write 关闭）
    else state = swapping
  swapping:
    task = POST /swap-indexes [{"indexes": [live_uid, target_uid]}] → wait（swap 原子）
    UPDATE indexes SET generation = generation + 1, dual_write_uid = NULL, status='ready', applied_settings_hash = settings_hash
    INCR qcgen:<index>；state = cleanup；commit
  cleanup:
    meili.delete_index(target_uid)（此时内容为旧代）；DELETE rebuild_touched；
    publish search.index_rebuilt{index, documents: n, duration_ms, generation, trigger}；state = done；commit
```

- **取消**：`preparing`～`verifying` 可取消：关闭 `dual_write_uid`，删除 target，状态 `cancelled`。
- **失败**：任一步连续失败 5 次 → `failed`，关闭双写，在线索引不受影响。
- **并发**：同一索引最多一个活动重建（部分唯一索引）。`building` 可按 id 区间切成 4 个分片并行（payload.shard），各自游标存于 `kv rebuild:<id>:shard:<n>`。
- **swap 与 replicas 模式**：`swapping` 写入 oplog，由各实例按序执行；全部实例 `applied_seq` 越过该条后才进入 cleanup。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:search@0.1.0`）

```wit
package pt:search@0.1.0;

interface search {
  use pt:plugin/types@1.0.0.{plugin-error, json};

  enum filter-op { eq, ne, in, not-in, gt, gte, lt, lte, between, exists, is-null, is-empty }

  record filter {
    field: string,
    op: filter-op,
    /// JSON 数组文本，元素类型须与字段类型一致；exists/is-null/is-empty 时为 "[]"
    values: json,
  }

  record sort-spec { field: string, descending: bool }

  record search-request {
    /// 逻辑索引名，如 "torrents"
    index: string,
    /// 关键词，≤ 256 字符；可为空串（纯筛选）
    query: string,
    filters: list<filter>,
    sort: list<sort-spec>,
    /// 需要分布统计的 facet 字段
    facets: list<string>,
    /// 按索引的 distinct 属性折叠（torrents → group_id）
    collapse: bool,
    /// 语义 / 混合查询
    semantic: bool,
    /// 0.0～1.0；none 用站点默认
    semantic-ratio: option<f64>,
    /// 1～100，默认 20
    limit: u32,
    cursor: option<string>,
  }

  record facet-bucket { value: string, count: u64 }
  record facet-result { field: string, buckets: list<facet-bucket> }

  record hit {
    id: u64,
    /// 文档字段（JSON 对象，已按调用者裁剪）
    document: json,
    /// 字段名 → 带 U+E000/U+E001 标记的文本（JSON 对象）
    highlights: json,
    ranking-score: option<f64>,
  }

  record search-result {
    hits: list<hit>,
    facets: list<facet-result>,
    estimated-total: u64,
    next-cursor: option<string>,
    processing-ms: u32,
    /// 结果来自缓存
    cached: bool,
  }

  record suggestion { id: u64, text: string, highlight: string }

  enum audience { user, admin }

  record index-def {
    /// ^<schema>_[a-z0-9_]{1,40}$
    index: string,
    audience: audience,
    /// 折叠属性（可选），须为拥有者声明的 filterable 字段
    distinct-attribute: option<string>,
    /// 追加排序规则，如 ["created_at:desc"]
    custom-ranking: list<string>,
  }

  record field-view {
    name: string,
    field-type: string,
    searchable: bool,
    filterable: bool,
    sortable: bool,
    facetable: bool,
    /// 支持的过滤操作符
    ops: list<filter-op>,
    label-term: string,
    source-plugin: string,
    /// rel_* 等跨类型通用字段
    generic: bool,
  }

  record index-schema-view {
    index: string,
    audience: audience,
    status: string,
    fields: list<field-view>,
    distinct-attribute: option<string>,
    semantic-available: bool,
  }

  /// 查询；按 invocation 的 actor 强制可见性；caller-scopes 含 "query:all" 时跳过可见性
  query: func(req: search-request) -> result<search-result, plugin-error>;
  /// 联想；prefix ≤ 64 字符，limit ≤ 10
  suggest: func(index: string, prefix: string, limit: u32) -> result<list<suggestion>, plugin-error>;
  /// 注册扩展索引；调用方成为拥有者；重复调用相同定义幂等
  register-index: func(def: index-def) -> result<_, plugin-error>;
  /// 触发重建，返回 rebuild id（UUIDv7）；已有进行中的重建时返回其 id
  reindex: func(index: string) -> result<string, plugin-error>;
  /// 高优先级删除
  remove: func(index: string, id: u64, idempotency-key: string) -> result<_, plugin-error>;
  /// 标脏重写（≤ 10,000 个 id）
  touch: func(index: string, ids: list<u64>, idempotency-key: string) -> result<_, plugin-error>;
  /// 合并后的字段视图
  schema: func(index: string) -> result<index-schema-view, plugin-error>;
}
```

Rust trait 由 `service!` 宏生成 `SearchService`（每个方法首参 `&Ctx`）。

| 方法 | 权限 / 作用域 | 错误码 |
|---|---|---|
| `query` | 无；`users_admin` 需调用用户有 `admin_index.read`（system 调用需 `query:all`） | `search-meilisearch.index_not_found`、`.invalid_filter`、`.invalid_sort`、`.field_not_filterable`、`.query_too_long`、`.semantic_unavailable`、`.unavailable`、`kernel.forbidden`、`kernel.bad_request`、钩子拒绝码、`kernel.hook_failed` |
| `suggest` | 同上 | 同上子集 |
| `register_index` | 名称前缀须为调用方 schema | `.index_name_invalid`、`.index_owner_mismatch` |
| `reindex` | `admin` 作用域或拥有者 | `.index_not_found`、`.index_owner_mismatch` |
| `remove` / `touch` | 调用方为该索引贡献者，或 `admin` 作用域 | `.index_not_found`、`.index_owner_mismatch`、`kernel.validation_failed` |
| `schema` | 无（admin 索引需权限） | `.index_not_found` |

`remove`/`touch` 的幂等：`kv` 键 `idem:<caller>:<key>`（TTL 24 h，`compare_and_set`）；重复调用直接返回 ok。

```sql
    terms       text[] NOT NULL CHECK (cardinality(terms) BETWEEN 1 AND 20),
    created_by  bigint,
    updated_by  bigint,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now(),
    version     integer NOT NULL DEFAULT 1,
    CONSTRAINT custom_synonyms_oneway_check CHECK (kind = 'group' OR input IS NOT NULL)
);

CREATE TABLE meili_tasks (
    instance_id  text NOT NULL,
    task_uid     bigint NOT NULL,
    index_uid    text NOT NULL,
    kind         text NOT NULL CHECK (kind IN ('docs','delete','stats','settings','swap','create','drop')),
    lane         text,
    index_name   text,
    entity_ids   bigint[] NOT NULL DEFAULT '{}',
    status       text NOT NULL DEFAULT 'enqueued' CHECK (status IN ('enqueued','succeeded','failed')),
    error_code   text,
    enqueued_at  timestamptz NOT NULL DEFAULT now(),
    finished_at  timestamptz,
    PRIMARY KEY (instance_id, task_uid)
);
CREATE INDEX meili_tasks_status_idx ON meili_tasks (status, enqueued_at);

CREATE TABLE poison_entities (
    index_name   text NOT NULL,
    entity_id    bigint NOT NULL,
    failed_count integer NOT NULL,
    last_error   text,
    updated_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (index_name, entity_id)
);

CREATE TABLE instances (
    id            text PRIMARY KEY,
    role          text NOT NULL CHECK (role IN ('primary','replica','leader','remote')),
    applied_seq   bigint NOT NULL DEFAULT 0,
    healthy       boolean NOT NULL DEFAULT false,
    version       text,
    needs_resync  boolean NOT NULL DEFAULT false,
    last_check_at timestamptz,
    last_apply_at timestamptz,
    updated_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE oplog (
    seq         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    index_uid   text NOT NULL,
    op          text NOT NULL CHECK (op IN ('docs','stats','delete','settings','create_index','swap','delete_index')),
    payload     bytea NOT NULL,              -- zstd(JSON)
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX oplog_created_at_idx ON oplog (created_at);
```

**数据量估算**：`indexed_docs` ≈ 文档总数（1000 万 + 300 万 + 2000 万 ≈ 3300 万行，约 100 B/行 ≈ 3.3 GB 含索引）；`pending_ops` 稳态 < 1 万行，Meili 宕机 1 h 约 30 万行；`swarm_stats_pending` ≤ 活跃种子数（≈ 50 万）；`meili_tasks` 保留 7 天约 50 万行；`oplog` 仅 replicas 模式。

### 3.2 Redis（插件代码写法，实际前缀 `p:search-meilisearch:`）

| 键 | 类型 | TTL | 说明 | 内存估算 |
|---|---|---|---|---|
| `qc:<index>:<gen>:<sha256>` | STRING（zstd JSON） | `cache_ttl_secs` | 结果缓存 | 热门 5 万条 × 4 KB ≈ 200 MB 上限（配额 256 MB，LRU 由 TTL 控制） |
| `qcgen:<index>` | STRING(INCR) | 无（每索引一个键） | 缓存代数 | 可忽略 |
| `sug:<index>:<gen>:<sha256>` | STRING | 60 s | 联想缓存 | ≤ 20 MB |
| `qv:<sha256>` | STRING（f32 字节） | 24 h | 查询向量 | 1 万 × 4 KB = 40 MB |
| `uc:<user_id>` | HASH `class_id,status,restricted,admin_index` | 30 s | 调用者画像 | 活跃 3 万 × 100 B |
| `lock:flush:<index>:<lane>` | STRING | 60 s | flush 互斥 | — |
| `lock:apply:<instance>` | STRING | 60 s | 副本应用互斥 | — |
| `schema_ver` | STRING | 无 | 合并 schema 版本（副本缓存校验） | — |

缓存一致性：优先通道写入后 `INCR qcgen:<index>`，旧代数键自然过期。

### 3.3 搜索索引贡献

本插件不导出 `search-contributor`；它是消费方。贡献者须满足 §1.6.2 与 §1.2 的约定。

校验规则（`init` 中额外执行）：`single` 模式只能有 1 个实例；`replicas` 恰有 1 个 `primary`；`network` 恰有 1 个 `leader`；`embedder.mode = llm` 时 `ctx.llm` 必须可用，否则降为 `none` 并告警；`/version` 低于 `min_version` → 索引状态 `degraded`，拒绝写入。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 可见性 | 基线过滤由服务端生成，钩子只能追加（内核校验）；追加表达式经解析校验只引用可筛选字段；`users_admin` 双重检查（路由权限 + 服务内权限）；system 调用跳过可见性需 `query:all` 且站点授权 |
| 过滤注入 | 只接受结构化过滤；字段名来自 schema 白名单；字符串值转义；排序字段白名单 |
| 敏感数据 | 字段名黑名单（schema 合并时）+ 文档键黑名单（写入前）；拥有者不得在匿名文档中写 `vis_owner_id`/上传者字段（本插件检查：文档含 `anonymous = true` 时删除 `vis_owner_id` 与 `uploader_id` 并计数告警）；日志只记查询词前 64 字符与索引名，不记 user_id 组合 |
| 密钥 | master key / admin key 只在静态配置（`x-pt-secret`，加密存储）；运行时只在 `meili_client` 中使用；tenant token 用专用仅 `search` 动作的 key 签名并定期轮换；Meili 部署在内网，`/chats`、`/mcp`、`/keys` 等不经任何代理暴露 |
| XSS | 高亮不返回 HTML；返回前剥离原文中的标记字符 |
| 限流 | 路由级限流（§HLD 3.6）；MCP 由 mcp 插件按 token 限流 |
| 审计 | 重建、取消重建、同义词变更、一致性巡检触发写 `audit.write`（`search-meilisearch.rebuild`、`search-meilisearch.synonym_change`…）；tenant token 签发计数指标（不审计每次签发） |
| 用户清除 | `user.deleted` purge → `users_admin` 删除；作者字段由贡献者在重新生成时匿名化 |
| 资源滥用 | `query` ≤ 256 字符、过滤 ≤ 20 条、`in` ≤ 1000 值、facets ≤ 10；超出 422 |

## 7. 性能设计

| 热点 | 设计 |
|---|---|
| 查询 | Redis 结果缓存（键含最终请求哈希 → 自带权限范围）；调用者画像缓存 30 s；Meili 连接池（reqwest keep-alive，每实例 64 连接）；只取 `displayedAttributes` 子集；不开 `showMatchesPosition` |
| 钩子 | 50 ms 预算；处理者应只读本地缓存（moderation/levels 文档约束） |
| 写入 | 2 s 窗口合并；批量 1000；doc_hash 去重；贡献者批量接口；部分更新只传变化字段 |
| 做种数 | 只写 3 个字段；每分钟一次；5000/批；对未索引 id 过滤 |
| 重建 | 并行：`rebuild_step` 每步 5000 id，同一重建最多 4 个步进任务并发（按 id 区间切分）；复用向量；Meili 侧使用默认 `indexing` 线程；重建期间普通通道照常 |
| 容量 | 单 Meili 实例（8C/32G/NVMe）承载 1000 万种子文档的估算：每文档约 2 KB 原文、索引放大约 5～8 倍 → 100～160 GB 磁盘；需 P0 实测（design/09） |
