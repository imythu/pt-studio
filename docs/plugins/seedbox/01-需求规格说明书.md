## 1. 引言

### 1.1 目的

定义盒子（seedbox，数据中心中的做种服务器）插件 `seedbox` 的需求：用户申报盒子、管理员审核、按 IP 段判定某用户在某种子上的 peer 是否来自盒子，供 anticheat、hnr、bonus 等插件差异化处理；可选自动识别未申报的盒子。

### 1.2 范围

包含：盒子申报（IP / CIDR、提供商、说明）、审核、`is_seedbox(user, torrent)` 判定与缓存、批量判定、未申报盒子的自动识别（可选，基于 ASN 数据中心列表）、盒子规则开关（供其他插件读取的策略标志）、统计、隐私保护。

不包含：按 IP 区分的流量倍率（accounting 没有 IP 维度，见 02 §7 的远期提案）；具体的奖励或处罚（由使用方插件决定）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 申报 | 用户登记自己的盒子 IP 段 |
| 盒子 peer | IP 落在该用户已批准盒子 IP 段内的 peer |
| 数据中心 ASN | 属于云 / 托管服务商的自治系统号 |

### 1.4 参考资料

- docs/platform/conventions/security.md（IP 为敏感数据）、docs/plugins/tracker-bridge/（`peers`，需 `peer.ip` 授权）、docs/plugins/anticheat/（`ctx.is_seedbox` 上下文、A-12 批量方法）
- NexusPHP 1.7+：盒子（seedbox）规则——用户申报盒子 IP，盒子做种按单独规则计算魔力值，未申报盒子可能被处罚
- 国内 PT 站常见做法：盒子上传量计入但魔力值打折、盒子不计入 H&R 豁免等

## 2. 总体描述

### 2.1 插件定位

- WASM，ID `seedbox`，缩写 `SBOX`；提供 `ctx.seedbox`。
- 依赖：`ctx.tracker`（`peers`，需要站点授予 `peer.ip`）、`ctx.users`；可选 `ctx.notify`。
- 敏感数据：`peer.ip`（必需，未授权时插件以“只记录申报、判定恒为 false”的降级模式运行——因此声明为 `sensitive_optional`）。

### 2.2 用户角色与使用场景

普通用户：申报 / 修改 / 删除自己的盒子，查看审核状态。管理员：审核申报、查看疑似盒子、配置规则。其他插件：查询 `is_seedbox`。

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP（seedbox） | 用户在设置中填写盒子 IP；announce 时根据 IP 判断是否盒子，魔力值按盒子规则；管理员可查看 | 申报简单 | IP 判断放在 announce 热路径；IP 以明文长期存储；无审核 | **采纳**申报 + 差异化规则；**改进**：判定不在热路径（按需查询 + 缓存）；申报需审核；IP 只对管理员可见，事件与日志中不出现 |

### 2.4 约束与假设

判定依赖 tracker-bridge 的 `peers(torrent_id)` 返回 IP（需授权）；结果有 1 小时缓存，属于近似判定。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-SBOX-001 | 申报 | 用户提交盒子：CIDR（IPv4 ≥ /24、IPv6 ≥ /48，最多 5 条）、提供商、说明 | P0 | 记录为 pending |
| FR-SBOX-002 | 审核 | 管理员批准 / 拒绝（原因）；可设有效期 | P0 | 批准后生效 |
| FR-SBOX-003 | 修改与删除 | 用户修改（重新进入审核）或删除自己的申报 | P1 | |
| FR-SBOX-004 | 判定 | `is_seedbox(user, torrent)`：该用户在该种子上存在 IP 属于已批准盒子的 peer | P0 | 正确 |
| FR-SBOX-005 | 批量判定 | `is_seedbox_many(pairs)`（≤ 500 对） | P1 | 供 anticheat、hnr |
| FR-SBOX-006 | 用户级标志 | `registered(user)` 返回已批准的盒子记录（不含 IP，只含 ID、提供商、状态） | P0 | |
| FR-SBOX-007 | 自动识别 | 可选：定期抽样活跃 peer，IP 属于数据中心 ASN 且该用户无已批准盒子 → 发布 `seedbox.detected`（供管理员复核，不自动处罚） | P2 | 默认关闭 |
| FR-SBOX-008 | 规则标志 | 站点配置供其他插件读取的策略：`hnr_exempt`、`bonus_factor`、`anticheat_speed_relax` | P1 | 使用方通过 `policy()` 读取 |
| FR-SBOX-009 | 冲突检测 | 两个用户申报重叠的 IP 段 → 审核时提示 | P2 | |
| FR-SBOX-010 | 隐私 | IP 段只对申报者本人与 `seedbox.manage` 可见；事件不含 IP；删除申报后 IP 立即删除 | P0 | |
| FR-SBOX-011 | 用户删除 | 清理 | P1 | |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-SBOX-001 | 性能 | `is_seedbox` 缓存命中 | p99 < 5 ms；未命中 p99 < 100 ms |
| NFR-SBOX-002 | 隐私 | IP 数据最小化 | 判定结果缓存只存布尔值；自动识别不落库 IP，只存 ASN 与 HMAC(/24) |
| NFR-SBOX-003 | 降级 | 未授予 `peer.ip` | 插件正常启动，判定恒为 false，后台提示 |

## 5. 可配置项与站点术语

运行时设置：`max_ranges_per_user`（5）、`require_review`（true）、`policy.hnr_exempt`（true）、`policy.bonus_factor`（1.0）、`policy.anticheat_speed_relax`（true）、`detect.enabled`（false）、`detect.sample_per_hour`（2000）。静态配置：`asn_db_path`（DB-IP ASN Lite MMDB 路径，自动识别用；不随仓库分发）、`hmac_key`。

术语：`seedbox.name`（已登记）。

## 6. 外部接口需求概述

服务 `ctx.seedbox`（`is_seedbox`、`is_seedbox_many`、`registered`、`policy`）；事件 `seedbox.registered`、`seedbox.detected`（已登记），新增 `seedbox.reviewed`、`seedbox.removed`；HTTP `/api/p/seedbox/v1/*`；插槽 `user.settings.tabs`、`admin.user.tabs`。
