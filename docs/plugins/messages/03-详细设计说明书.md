## 1. 模块详细设计

### 1.1 conversations

```
create(sender, recipients[1..=max], subject, body, markup, idem):
  幂等（sender, idem）
  rs = 去重(recipients) − {sender}；每个 r：users.get(r) 存在且 status ≠ deleted
  for r: if blocks[(r, sender)] && !is_staff(sender): err messages.blocked（不区分哪个收件人：返回 details.recipient_index）
         settings[r].accept == staff_only && !is_staff(sender): err messages.recipient_not_accepting
  antispam(sender)；hooks.run(message.before_send, {sender_id, recipient_ids: rs, subject, body_length})
  r = pt_markup::render(body, markup)
  c = INSERT conversations(subject, kind = 'user', created_by = sender)
  INSERT participants(c, sender, in_sent = true, last_read_message_id = m.id) + (c, r, in_inbox = true, last_read_message_id = 0) for r in rs
  m = INSERT messages(c, sender, source, rendered, render_version)
  UPDATE conversations SET last_message_id = m.id, last_message_at = now
  for r: redis.INCR("unread:<r>")；publish message.sent{message_id: m.id, conversation_id: c, sender_id, recipient_id: r}
reply(u, c, body)：u 为参与者且未 left；对每个其他参与者：若其 in_inbox = false 则重新置 true（会话重新出现在收件箱）；未读计数 +1（只对之前已读到最新的参与者 +1，避免重复：维护 participants.unread_count）
read(u, c)：UPDATE participants SET last_read_message_id = c.last_message_id, unread_count = 0；redis.DECRBY("unread:<u>", 旧 unread_count)（下限 0）
remove(u, c)：participants.in_inbox = in_sent = false, removed_at = now；全部参与者 removed 后 purge_deleted 30 天后物理删除
```

### 1.2 system

```
send_system(uid, subject_term, body_template, args, idem):
  幂等（caller_plugin, idem）
  lang = 用户语言（ctx.users 的 locale；缺省站点默认）
  subject = terms.get(subject_term, lang).name；body = terms.render(body_template, args, lang)
  c = INSERT conversations(kind = 'system', subject, created_by_plugin = caller)
  INSERT participants(c, uid, in_inbox = true, folder = 'system')；INSERT messages(c, sender = NULL, …)
  unread +1；publish message.sent{sender_id: null}
send_system_many(uids ≤ 1000, …)：同上批量插入（单事务），每用户一个会话
```

`body_template` 为 terms 的 MessageFormat 子集模板（terms 03），渲染结果再经 `pt-markup`（markdown）渲染与净化。

### 1.3 broadcasts

```
broadcast(filter{all | min_class_rank | roles[] | class_ids[]}, subject, body, starts_at?, expires_at?, idem)：
  require 作用域 broadcast 或 HTTP 权限 messages.broadcast
  INSERT broadcasts；publish message.broadcast_sent{broadcast_id, filter_summary}
用户视图：
  active = SELECT … FROM broadcasts WHERE starts_at ≤ now AND (expires_at IS NULL OR expires_at > now) ORDER BY id（缓存 60 s，条数 ≤ 50）
  visible(u) = active.filter(b => matches(b.filter, u) && b.id ∉ hidden(u) && b.created_at ≥ u.created_at)
  unread_broadcasts(u) = visible(u).count(b => b.id > cursor(u))
  系统文件夹列表 = 系统会话 ∪ visible(u)（按时间合并）
read_broadcast(u, b)：cursor(u) = max(cursor, b.id)
```

`matches` 需要用户的等级与角色：`users.get(u).class_id` + `rbac.roles_of(u)`（已在请求上下文中，无额外开销）；等级 rank 比较经 `levels.classes()`（缓存）。

### 1.4 unread

Redis `unread:<uid>`（私信）为热计数；`reconcile_unread`（每小时）对最近 1 小时有变化的用户（Redis SET `dirty_unread`）用 PG `SUM(participants.unread_count)` 校正。`GET /unread` 返回 `{private: n, broadcast: m}`。

### 1.5 blocks 与 settings

`blocks(user_id, blocked_id)`；员工（`rbac.check(sender, "messages.broadcast")` 或角色 ≥ moderator）不受拉黑影响。`settings(user_id, accept: all | staff_only)`。

### 1.6 report_bridge

```
report(u, message_id, reason_code, note, consent: true):
  u 必须是该消息所在会话的参与者；consent 必须为 true（前端提示“内容将提交给管理员”）
  snapshot = {conversation_id, message_id, sender_id, sent_at, rendered_text 前 5000 字, 上下文前后各 2 条（同样只取文本）}
  reports.create(reporter_id = u, target = "message:<id>", reason_code, note, snapshot)（⊕ snapshot 参数）
```

### 1.7 lifecycle

`user.deleted{purge}`：其发送的消息 `source = '', rendered = '', purged = true`；其参与者行删除；作为唯一剩余参与者的会话删除。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:messages@0.1.0`）

```wit
package pt:messages@0.1.0;

interface messages {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, json, timestamp-ms};

  record broadcast-filter { min-class-rank: option<s32>, roles: list<string>, class-ids: list<u32> }

  send-system: func(user: user-id, subject-term: string, body-template: string, args: json, idempotency-key: string) -> result<u64, plugin-error>;
  send-system-many: func(users: list<user-id>, subject-term: string, body-template: string, args: json, idempotency-key: string) -> result<u32, plugin-error>;
  broadcast: func(filter: broadcast-filter, subject: string, body: string, expires-at: option<timestamp-ms>, idempotency-key: string) -> result<u64, plugin-error>;
  unread-count: func(user: user-id) -> result<u32, plugin-error>;
}
```

作用域：`send-system*` 需 `send`；`broadcast` 需 `broadcast`。

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `message.sent` | `message_id, conversation_id, sender_id?, recipient_id, kind(user/system)` |
| `message.broadcast_sent` | `broadcast_id, created_by, filter_summary` |

### 2.3 钩子 `message.before_send`

输入：`version, actor, sender_id, recipient_ids[], subject, body_length`（不含正文）；allow / deny；200 ms；失败策略 allow。

### 2.4 HTTP API（摘要）

**POST `/v1/conversations`**（Idempotency-Key）`{ "recipients": ["bob"], "subject": "你好", "body": "…", "markup": "markdown" }` → 201 `{ "conversation_id": 77, "message_id": 901 }`；错误：403 `messages.blocked` / `messages.recipient_not_accepting`、404 `messages.recipient_not_found`、429 `messages.rate_limited`。

**GET `/v1/conversations?folder=inbox&cursor=`** → `{ "items": [ { "id": 77, "subject": "你好", "participants": [ {"id": 2, "username": "bob"} ], "last_message_at": "…", "unread": 1, "starred": false, "kind": "user" } ], "next_cursor": "…" }`

**GET `/v1/conversations/{id}`** → 会话与消息（分页，按时间正序；渲染 HTML）。

**POST `/v1/admin/broadcasts`**（`messages.broadcast`）`{ "filter": { "min_class_rank": null, "roles": [], "class_ids": [] }, "subject": "…", "body": "…", "expires_at": null }` → 201。

### 2.5 MCP

| 工具 | 说明 |
|---|---|
| `list_my_messages` | 入参 `{folder?, unread_only?}`；出参 `[ {conversation_id, subject, from, last_message_at, unread} ]`——**不含正文** |
| `send_message` | 入参 `{to: [username], subject, body}`；write，confirm（确认页展示收件人与正文） |

## 3. 数据库设计（schema `messages`）

```sql
CREATE TABLE messages.conversations (
    id                 bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind               text NOT NULL CHECK (kind IN ('user', 'system', 'staff')),
    subject            text NOT NULL,
    created_by         bigint,
    created_by_plugin  text,
    last_message_id    bigint,
    last_message_at    timestamptz NOT NULL DEFAULT now(),
    created_at         timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE messages.participants (
    conversation_id       bigint NOT NULL REFERENCES messages.conversations (id) ON DELETE CASCADE,
    user_id               bigint NOT NULL,
    in_inbox              boolean NOT NULL DEFAULT false,
    in_sent               boolean NOT NULL DEFAULT false,
    folder                text NOT NULL DEFAULT 'normal' CHECK (folder IN ('normal', 'system')),
    starred               boolean NOT NULL DEFAULT false,
    last_read_message_id  bigint NOT NULL DEFAULT 0,
    unread_count          integer NOT NULL DEFAULT 0,
    removed_at            timestamptz,
    PRIMARY KEY (conversation_id, user_id)
);
CREATE INDEX participants_inbox_idx ON messages.participants (user_id, conversation_id DESC) WHERE in_inbox;
CREATE INDEX participants_sent_idx ON messages.participants (user_id, conversation_id DESC) WHERE in_sent;

CREATE TABLE messages.messages (
    id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    conversation_id  bigint NOT NULL REFERENCES messages.conversations (id) ON DELETE CASCADE,
    sender_id        bigint,
    markup           text NOT NULL DEFAULT 'markdown',
    source           text NOT NULL,
    rendered         text NOT NULL,
    render_version   integer NOT NULL,
    purged           boolean NOT NULL DEFAULT false,
    created_at       timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX messages_conv_idx ON messages.messages (conversation_id, id);

CREATE TABLE messages.broadcasts (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    filter      jsonb NOT NULL,
    subject     text NOT NULL,
    rendered    text NOT NULL,
    created_by  text NOT NULL,
    starts_at   timestamptz NOT NULL DEFAULT now(),
    expires_at  timestamptz,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE messages.broadcast_cursors (user_id bigint PRIMARY KEY, last_read_id bigint NOT NULL);
CREATE TABLE messages.broadcast_hidden (user_id bigint NOT NULL, broadcast_id bigint NOT NULL, PRIMARY KEY (user_id, broadcast_id));

CREATE TABLE messages.blocks (user_id bigint NOT NULL, blocked_id bigint NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (user_id, blocked_id));
CREATE TABLE messages.settings (user_id bigint PRIMARY KEY, accept text NOT NULL DEFAULT 'all' CHECK (accept IN ('all', 'staff_only')));
CREATE TABLE messages.idempotency (owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (owner, key));
```

Redis（`p:messages:`）：`unread:<uid>`（无 TTL，校正任务维护）、`dirty_unread`（SET）、`bc_active`（60 s）、频率计数。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.users@^0.1", "ctx.terms@^0.1", "ctx.rbac@^0.1"]`、`optional_requires = ["ctx.levels@^0.1", "ctx.reports@^0.1"]`；`[[hook_points]] message.before_send`；订阅 `user.deleted`；cron 两项。

## 5. 前端设计

收件箱（文件夹标签、未读加粗、星标）、会话页（气泡或邮件式列表）、写信（用户名自动补全、多收件人）、拉黑列表、隐私设置；导航未读徽标（轮询 `/v1/unread`，60 秒）。

## 6. 安全设计

正文只对参与者可见；无员工读取接口；举报需参与者同意并只提交快照；渲染器同 comments；拉黑与隐私设置；频率限制；事件与日志不含正文。

## 7. 性能设计

未读走 Redis；收件箱列表走部分索引；广播 O(1) 写入，读取时过滤 ≤ 50 条活跃广播。

## 8. 可观测性

`pt_plugin_messages_sent_total{kind}`、`pt_plugin_messages_rejected_total{reason}`、`pt_plugin_messages_unread_reconciled_total`。
