## 1. 引言

### 1.1 目的

定义站内信插件 `messages` 的需求：用户之间的私信会话、系统通知信（供其他插件发送）、管理员群发、收件箱管理。

### 1.2 范围

包含：会话（两人或多人，≤ 10 人）、消息发送与回复、已读状态、未读计数、收件箱 / 已发送 / 系统 / 星标、删除（各自删除，不影响对方）、收件箱容量、拉黑、举报、系统消息（模板 + 术语）、群发（按条件：全体、等级、角色）、发送钩子、MCP（只读摘要与发送）。

不包含：邮件 / Telegram 等外部通知（notify）；实时推送通道（由 web 轮询或内核 SSE，若提供）。

### 1.3 参考资料

- Gazelle：pm_conversations / pm_conversations_users（每个参与者的 InInbox、InSentbox、UnRead、Sticky）、pm_messages
- UNIT3D：private_messages 与 conversations、系统消息（`SystemBot`）
- NexusPHP：短讯（messages 表，sender = 0 为系统），收件箱 / 发件箱、群发

## 2. 总体描述

WASM，ID `messages`，缩写 `MSG`；提供 `ctx.messages`；拥有钩子 `message.before_send`；渲染使用 `pt-markup`。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle | 会话 + 参与者状态表 | 删除互不影响，状态清晰 | — | **采纳**会话 + 参与者状态模型 |
| NexusPHP | 每条消息一行，群发时为每个收件人复制一行 | 简单 | 30 万用户群发产生 30 万行与长事务 | **改进**：群发为“广播”记录 + 每用户已读游标，惰性显示 |
| UNIT3D | 系统机器人账号发信 | 统一 | 系统账号可被误用 | 系统消息 sender 为空，不使用真实账号 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-MSG-001 | 发起会话 | 向 1～9 个收件人发送（标题 ≤ 100、正文 ≤ 20000） | P0 | |
| FR-MSG-002 | 回复 | 在会话中回复 | P0 | |
| FR-MSG-003 | 已读 / 未读 | 每个参与者的已读游标；未读计数（全局与按会话） | P0 | |
| FR-MSG-004 | 文件夹 | 收件箱、已发送、系统、星标；搜索标题 | P1 | |
| FR-MSG-005 | 删除 | 参与者把会话移出自己的视图（对方不受影响）；所有参与者删除后物理删除（延迟 30 天） | P0 | |
| FR-MSG-006 | 容量 | 收件箱会话数上限（按等级配置，默认 500）；超限时新消息仍送达但提示清理（不拒收系统消息） | P2 | |
| FR-MSG-007 | 拉黑 | 用户拉黑他人后，对方无法向其发送私信（员工除外） | P1 | |
| FR-MSG-008 | 隐私设置 | 只接收好友（不在本期）/ 只接收员工 / 所有人 | P2 | |
| FR-MSG-009 | 系统消息 | `send_system(user_id, subject_term, body_template, args)`：模板经 terms 渲染；无发件人；不可回复（可配置为回复给员工收件箱） | P0 | |
| FR-MSG-010 | 群发 | 管理员按条件（全体、等级 ≥ X、角色）发送广播；收件人登录后在系统文件夹中看到 | P1 | 30 万用户群发 < 1 秒完成写入 |
| FR-MSG-011 | 发送钩子 | `message.before_send`（moderation、levels：新用户每日私信上限） | P0 | |
| FR-MSG-012 | 反垃圾 | 频率（每分钟 5 条、每日 100 条）、新用户限制、相同正文群发检测 | P0 | |
| FR-MSG-013 | 举报 | 举报某条消息（reports；举报时把该消息内容快照交给 reports，需举报者同意） | P1 | |
| FR-MSG-014 | 员工查看 | 正文默认不可被员工查看；只有被举报的消息可被 `reports.moderate` 查看快照 | P0 | |
| FR-MSG-015 | 事件 | `message.sent`（不含正文） | P0 | |
| FR-MSG-016 | MCP | `list_my_messages`（标题、发件人，不含正文）、`send_message`（需确认） | P2 | |
| FR-MSG-017 | 用户删除 | purge：删除其发送的正文（对方看到“已删除用户的消息”占位）、参与者状态 | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-MSG-001 | 未读计数 | p99 < 10 ms（Redis 计数） |
| NFR-MSG-002 | 收件箱列表 | p99 < 50 ms |
| NFR-MSG-003 | 群发 | O(1) 写入 |
| NFR-MSG-004 | 隐私 | 正文不进事件、日志、搜索、AI（除非用户举报或主动发给 AI 助手） |

## 5. 可配置项与站点术语

`max_recipients`（9）、`inbox_limit_by_class`（`{默认: 500}`）、`rate.per_min`（5）、`rate.per_day`（100）、`new_user_days`（7）、`new_user_daily_limit`（10）、`system_reply_to_staff`（false）。术语：`messages.name`（已登记）、`messages.system`（系统消息）。

## 6. 外部接口需求概述

服务 `ctx.messages`（`send_system`、`unread_count`；⊕ `send_system_many`、`broadcast`）；事件 `message.sent`；钩子 `message.before_send`；HTTP `/api/p/messages/v1/*`；插槽 `nav.user_menu`（未读数）；MCP 两项。
