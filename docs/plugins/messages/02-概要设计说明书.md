## 1. 设计目标与原则

1. **会话 + 参与者状态**（Gazelle 模型）：删除、已读、星标都是参与者自己的状态。
2. **群发不复制**：广播存一行，每个用户维护 `broadcast_cursor`；未读广播数 = 生效广播中 id > cursor 且满足条件的数量（条件按用户属性在读取时判断）。
3. **正文隐私**：员工默认无法读取私信正文；举报时由举报者提交快照。

## 2. 总体结构

| 模块 | 职责 |
|---|---|
| `conversations` | 会话创建、参与者、回复、文件夹、删除 |
| `system` | 系统消息（模板渲染）、批量系统消息 |
| `broadcasts` | 群发与用户游标 |
| `unread` | 未读计数（Redis + PG 校正） |
| `blocks` | 拉黑与隐私设置 |
| `antispam` | 频率、重复（`pt-antispam`） |
| `report_bridge` | 举报快照 |

| 类别 | 内容 |

## 4. 数据设计概要

`conversations`、`participants`（会话 × 用户：folder 标记、last_read_message_id、starred、left_at）、`messages`、`broadcasts`（条件 JSON、标题、正文、生效时间、过期时间）、`broadcast_cursors`、`broadcast_hidden`（用户隐藏某广播）、`blocks`、`settings`、Redis 未读计数。

## 5. 关键流程

```
send(u, recipients, subject, body):
  校验收件人数、存在性、拉黑与隐私设置、频率；hooks.run(message.before_send, {sender_id, recipient_ids, subject, body_length})
  INSERT conversations、participants（发件人 + 收件人）、messages；渲染正文
  unread：收件人 INCR u:<rid>（Redis）；publish message.sent（每个收件人一条，不含正文）
broadcast(filter, …)：INSERT broadcasts（1 行）；publish message.broadcast_sent
unread_count(u) = Redis 私信未读 + 广播未读（缓存 60 s：生效广播中 id > cursor 且 filter 匹配用户）
```

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-MSG-1 | 群发存储 | 广播 + 游标：避免 30 万行写入（NexusPHP 改进） |
| DD-MSG-2 | 员工读取私信 | 默认不可读；站点规则需要时由举报快照获得——隐私优先 |
| DD-MSG-3 | 系统消息回复 | 默认不可回复；`system_reply_to_staff` 开启时回复进入“员工收件箱”会话（参与者为具有 `reports.moderate` 的员工组，用虚拟参与者 `staff`） |
| DD-MSG-4 | 正文加密 | 不做应用层加密（服务端需要渲染与举报快照）；依赖数据库与磁盘加密，并通过 schema 隔离、无视图、无事件来降低暴露面 |

## 7. 对平台契约的新增

服务方法补充（见 §3）；事件 `message.broadcast_sent`；作用域：`send`（已登记）用于 `send_system`；新作用域 `broadcast`（只给管理类插件）；reports 需要接收“举报者提交的内容快照”（`ctx.reports.create` 增加 `snapshot` 参数）。

## 实现说明（2026-10-17，开站计划 M4.3：群发公告）

- 表 `broadcasts`（一行一条，Markdown 渲染后存 `body_html`）、`broadcast_cursors`（用户已读游标 = 最大已读公告 ID）、`broadcast_hidden`（用户隐藏）。不为每个用户复制消息（DD-MSG-1）。
- 投放条件只实现最低等级 `min_class`（与 `identity.v_user_public.class_id` 比较，读取时判断）与到期时间；撤回后对所有人不可见。
- 接口：`GET /broadcasts`（对我可见的公告与未读标记）、`POST /broadcasts/read`（游标移到最新）、`DELETE /broadcasts/{id}`（隐藏）、`GET/POST /admin/broadcasts`、`POST /admin/broadcasts/{id}/revoke`（权限 `messages.broadcast`，发布与撤回写审计）；`GET /unread` 增加 `broadcasts` 计数。
- 服务 `ctx.messages.broadcast(subject, body, min_class?, expires_at?, idempotency_key)`，作用域 `broadcast`，按（调用方, 幂等键）去重。事件 `message.broadcast_sent`。
- 前端：站内信“公告”页签（打开即全部已读、可隐藏）、首页 `home.announcements` 未读公告横幅（“知道了”）、用户菜单未读数含公告、后台 `/admin/p/messages/` 发布与撤回（显示已读人数）。
- 未实现：按角色 / 注册时间等更多条件、定时发布、系统消息回复进入员工收件箱（“联系管理组”由 tickets 插件提供）。
