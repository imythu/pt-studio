## 1. 引言

### 1.1 目的

定义 `terms` 插件（`ctx.terms` 的唯一实现，决策 D7）的需求：站点术语键的登记、多语言默认值、管理员覆盖、单位 / 图标 / 复数、取值与渲染、缓存与失效、导入导出。

### 1.2 范围

**包含**：

- 术语键登记：启动时由内核汇总各插件清单 `[terms]` 后调用 `ctx.terms.register()`；运行时由属主插件登记动态键（如新建的等级、商品、勋章）；
- 多语言默认值（至少 `zh-CN`、`en`）与语言回退；
- 管理员覆盖：名称、短名、单位、图标、复数形式；重置、历史、审计；
- 取值接口：`get`、`get_many`、`render`（`{term:…}` 占位 + ICU MessageFormat）、快照（供内核本地缓存、前端 `/api/kernel/v1/terms`）；
- 缓存与失效：版本号、`terms.updated` 事件、Redis 快照缓存；
- 面向前端（`t('term:…')`）、MCP（`get_term` 工具与工具输出渲染）、通知模板（notify 调用 `render`）的取值约定；
- 导入导出（JSON / TOML / CSV），站点预设的引导覆盖；
- 后台管理页面。

**不包含**：

- 界面文案、错误信息等普通 i18n（由前端 i18n 资源与各插件 `message` 处理；判断标准见 catalog/terms.md §1）；
- 各插件的术语键清单本身（属于各插件，登记在 catalog/terms.md）；
- 术语的业务含义（如等级规则、币种精度）；
- 内核侧的快照缓存与 `GET /api/kernel/v1/terms` 路由（内核实现，本插件提供数据接口）。

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| 术语键 | `<plugin_id>.<path>`，如 `bonus.currency`；正则 `^[a-z][a-z0-9-]*(\.[a-z0-9_]+)+$` |
| 默认值 | 插件提供的各语言值（清单 `[terms]` 或运行时 `define`） |
| 覆盖值 | 管理员在后台为某键某语言设置的值，优先于默认值 |
| 术语值 | `{name, short?, unit?, icon?, plural?}` |
| 有效值 | 按回退链合并默认值与覆盖值后对外提供的值 |
| 快照 | 某语言全部有效值的集合，带全局版本号 |
| 退役 | 键不再被任何启用插件声明；覆盖值保留，不进快照 |
| 孤儿覆盖 | 导入时针对尚未登记的键保存的覆盖值，键登记后自动生效 |

## 2. 总体描述

### 2.1 插件定位

| 项 | 内容 |
|---|---|
| 类型 | **Native**（内核启动依赖它；所有插件、前端、MCP、通知都读术语，属基础服务） |
| 提供的服务 | `ctx.terms@0.1.0`（single） |
| 依赖 | 无业务服务依赖（内核要求 terms 最先激活，kernel/02 §3.2）；使用内核宿主能力 kv、sql、redis、blob、events |
| 消费方 | 内核（登记、快照、渲染宿主接口）、全部插件（经内核 `terms` 宿主接口）、notify（模板渲染）、mcp / 各 MCP 工具（输出渲染）、search-meilisearch（同义词派生）、前端（经内核快照路由） |

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 站点管理员（`terms.manage`） | 把“魔力值”改成“猫粮”、单位“颗”；把等级名改成“府丞 / 府尹”；给促销“免费”换图标；为英文界面补复数形式；导出给其他站参考、导入预设；查看修改历史；重置 |
| 普通用户 | 在界面、邮件、站内信、MCP 回答中看到本站叫法 |
| 插件开发者 | 在清单中声明键与默认值；运行时为动态实体登记键；在代码中 `ctx.terms.get()` / 模板中 `{term:bonus.currency}` |
| 内核 | 启动登记；维护每语言快照；为前端提供快照路由 |
| AI 客户端 | `get_term` 查询本站叫法以便正确称呼 |

### 2.3 现有开源 PT 程序的做法调研

| 项目 | 做法 | 优点 | 缺点 | 我们采纳 / 改进 |
|---|---|---|---|---|
| **NexusPHP** | 多语言靠 `lang/chs|cht|en/lang_<页面>.php` 语言文件，按页面拆分；站点特有叫法（魔力值、等级名、促销名）直接写在语言文件或代码常量里（如用户等级常量与 `get_user_class_name`）；各站要改名只能直接编辑语言文件 | 简单直接；简繁英三语齐全，社区站点普遍沿用 | 站点改名 = 修改源码文件，升级时与上游冲突，导致大量站点停留在旧版本；同一叫法分散在多个语言文件中，改漏常见；没有“站点叫法”与“界面文案”的区分 | 采纳“多语言并存、按语言回退”；改进：**站点叫法独立为术语表**，存数据库，后台修改，升级不冲突；一个概念只有一个键，全站引用 |
| **UNIT3D** | Laravel 本地化 `lang/<locale>/*.php` / JSON，社区翻译多语言；用户组名称存数据库可后台编辑；货币名（BON）等写在语言文件 | 用户组名称数据驱动；多语言覆盖广 | 其余站点叫法仍在语言文件，站长通过发布 vendor 文件覆盖，升级需手动合并；无复数 / 单位 / 图标的统一结构 | 采纳“等级名数据驱动”；改进：等级名作为 `levels.class.<id>.name` 动态术语键，与货币、促销等统一管理；值结构内置单位、图标、ICU 复数 |
| **Gazelle（OPS/RED）** | 仅英文；用户等级名在 `permissions` 表（后台可改）；货币、促销名硬编码在模板 | 等级名后台可改 | 无多语言；大多数叫法硬编码 | 同上 |
| **Luminance** | 继承 Gazelle，加入部分站点设置项（站名等） | 站点设置集中 | 叫法覆盖面小 | 站名作为术语 `kernel.site_name`（catalog 已列） |
| **TorrentPier** | 语言包 + 站点配置中少量可改名称 | — | 同 NexusPHP | — |

结论：DD-TERMS-1（术语与 i18n 分离、数据库存覆盖）、DD-TERMS-3（字段级覆盖 + 语言级回退）、DD-TERMS-5（导入导出用于站点间分享“叫法包”，替代 fork 改文件）。

### 2.4 约束与假设

1. 术语键前缀必须等于声明插件的 ID（内核清单校验，kernel/03 §2.1）；本插件再次校验。
2. 内核在 terms 插件 `init` 之后、其他插件 `init` 之前调用 `register(all)`；每个副本启动时都会调用一次（多副本、滚动升级时会出现新旧版本交替调用）。
3. 读路径（每次页面渲染、每个插件取值）由内核进程内快照承担；本插件的服务调用只发生在快照构建、管理操作与少量服务端渲染。
4. 规模：键 ≤ 2 万（含动态键，如 5000 个商品 / 勋章），语言 ≤ 8 种。
5. 渲染引擎必须与内核宿主接口 `terms.render` 的行为一致（同一 crate，见 HLD §7）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-TERMS-001 | 启动登记 | `register(defs)` 只接受内核调用；写入/更新默认值，绝不覆盖管理员覆盖值 | P0 | 重启后已覆盖的值保留，默认值更新（与 TC-KRN-110 一致） |
| FR-TERMS-002 | 登记校验 | 键正则、前缀与属主一致、值结构合法、长度上限；缺少 `zh-CN` 或 `en` 时告警（不拒绝） | P0 | 非法键被拒并在报告中列出；缺语言计入指标 |
| FR-TERMS-003 | 登记幂等与版本保护 | 相同定义重复登记无副作用；旧版本插件（滚动升级中的旧副本）登记不得回退新版本默认值 | P0 | 新旧副本交替重启，默认值保持新版本 |
| FR-TERMS-004 | 退役 | 插件升级后不再声明的键立即退役；插件被移除（24 h 内无任何副本登记）后其键退役；退役键不进快照，覆盖值保留，键重新出现时恢复 | P1 | 禁用插件 24 h 后快照不含其键；重新启用后覆盖值仍在 |
| FR-TERMS-005 | 动态键 | 属主插件运行时 `define(defs)` 登记 / 更新动态键默认值（如 `levels.class.7.name`、`shop.item.42`），`retire(keys)` 退役 | P0 | 非属主前缀被拒；幂等 |
| FR-TERMS-006 | 多语言与回退 | 有效值按回退链 `请求语言 → 语言基码（zh-TW→zh）→ site.default_locale → en → 键名` 解析；先确定首个有 `name` 的语言，再在该语言内取其他字段；`icon` 与语言无关，沿链回退 | P0 | 回退用例表全部通过 |
| FR-TERMS-007 | 管理员覆盖 | 对任一键、任一站点语言设置 `name`、`short`、`unit`、`icon`、`plural` 中任意字段；未设置的字段继承默认值；空串表示显式清空 | P0 | 只改单位时名称仍随默认值变化 |
| FR-TERMS-008 | 乐观锁 | 覆盖写入支持 `If-Match` 版本；冲突返回 409 | P1 | 两人同时编辑后者收到冲突 |
| FR-TERMS-009 | 重置 | 删除某键某语言的覆盖，恢复默认 | P0 | 重置后快照为默认值 |
| FR-TERMS-010 | 值校验 | `name` 1～64 字符、`short` ≤ 32、`unit` ≤ 16；NFC；禁止控制字符与 `<`、`>`；`plural` 须为合法 ICU 片段（唯一参数 `count`，含 `other` 分支，≤ 512 字符）；`icon` 须为内置图标名或已上传图标 | P0 | 非法输入 422，`errors[]` 指出字段 |
| FR-TERMS-011 | 图标上传 | 上传 PNG / JPEG / WebP（≤ 256 KiB），服务端解码、缩放至 ≤ 128×128、重新编码为 WebP、去除元数据，按内容哈希存储；公开路由提供，长期缓存 | P1 | SVG、伪造扩展名被拒；输出无 EXIF |
| FR-TERMS-012 | 取值服务 | `get(key, locale)`、`get_many(keys, locale)` 返回有效值；未知键返回空 | P0 | 与快照一致 |
| FR-TERMS-013 | 渲染 | `render(template, args, locale)`：先展开 `{term:<key>}`、`{term:<key>|short}`、`{term:<key>|unit}`、`{term:<key>|plural(<arg>)}`，再按 ICU MessageFormat 用 `args` 渲染；术语值中的 ICU 特殊字符被转义 | P0 | 渲染样例全部正确；术语名含 `{`、`'` 时不破坏模板 |
| FR-TERMS-014 | 快照 | `snapshot(locale)` 返回该语言全部有效值与全局版本号；`version()` 返回当前版本 | P0 | 5000 键快照构建 p95 ≤ 50 ms（缓存未命中）|
| FR-TERMS-015 | 变更事件 | 任何改变有效值的操作在同一事务发布 `terms.updated{keys[], locale, version}`；变更键超过 500 个时 `keys = ["*"]` | P0 | 事件与数据库变更原子 |
| FR-TERMS-016 | 缓存 | 快照按 `(locale, version)` 缓存在 Redis；版本变化即失效 | P0 | 修改后 2 s 内另一副本内核取到新值（配合内核） |
| FR-TERMS-017 | 前端取值约定 | 快照 JSON 结构可被内核原样输出给前端：含 `name/short/unit/icon/icon_url/plural`；前端 `t('term:k')`、`t('term:k|unit')`、`tp('term:k', n)` 的语义在本文档定义 | P0 | 前端 SDK 契约测试通过 |
| FR-TERMS-018 | MCP 工具 | `get_term`：按键或关键词查询本站叫法（当前用户语言） | P1 | 输出符合 schema |
| FR-TERMS-019 | 通知模板约定 | notify 等插件用 `render` 渲染模板，模板中只用 `{term:…}` 引用叫法；输出为纯文本，HTML 转义由使用方负责 | P0 | 与 notify 契约测试 |
| FR-TERMS-020 | 导出 | 按格式（JSON / TOML / CSV）、范围（仅覆盖 / 有效值 / 默认 + 覆盖）、前缀、语言导出 | P1 | 导出再导入（仅覆盖）结果不变（往返一致） |
| FR-TERMS-021 | 导入 | 上传文件 → 预览差异（新增 / 修改 / 未知键 / 无效项）→ 确认应用；模式 `merge` / `replace`（限定前缀）/ `fill`（只填未覆盖的）；未知键 `skip` 或保留为孤儿覆盖；同一导入重复应用幂等 | P1 | 预览不改数据；应用后一次版本递增、一次事件 |
| FR-TERMS-022 | 历史与审计 | 每次覆盖设置、重置、导入、动态登记、退役记录历史（前后值、操作者、原因）；管理操作写审计 | P0 | 后台可按键查看历史 |
| FR-TERMS-023 | 分类 | 按 catalog/terms.md 的分类（虚拟货币、用户等级、身份标识、促销、考核、种子状态、社区、内容、其他）展示；权限说明键（`*.perm.*`）单独归为“权限说明” | P1 | 新插件的键按前缀规则自动归类 |
| FR-TERMS-024 | 引导覆盖 | 站点静态配置（含预设）中的 `bootstrap` 覆盖值在首次启动时以 `fill` 模式导入一次 | P2 | 再次启动不重复导入、不覆盖管理员修改 |
| FR-TERMS-025 | 后台管理 | 列表（搜索、分类、属主插件、仅已覆盖、缺翻译、已退役）、编辑（各语言并排、预览复数与模板）、历史、导入导出、图标上传 | P1 | 端到端用例通过 |
| FR-TERMS-026 | 覆盖率巡检 | 每日统计各语言缺失的键，输出指标与后台报表 | P2 | 指标 `missing_translations{locale}` |
| FR-TERMS-027 | 语言限制 | 只允许为 `site.locales` 中的语言设置覆盖；默认值可含其他语言（忽略不入快照） | P0 | 不支持的语言 422 |
| FR-TERMS-028 | 服务端覆盖写入 | `set_override` 服务方法供持有 `manage` 作用域的插件（如后台批量工具、AI 助手的确认后操作）调用，行为与 HTTP 接口一致 | P2 | 无作用域 403 |
| FR-TERMS-029 | 用户清除 | 订阅 `user.deleted`（purge）：历史、覆盖、导入记录中的操作者 ID 置空 | P1 | purge 后无该用户 ID |
| FR-TERMS-030 | 退役扫描 | 定时退役长期未登记插件的键（FR-TERMS-004） | P1 | 重复执行无副作用 |

## 5. 可配置项与站点术语

静态配置（`site.toml [plugin.terms]`）：

| 配置键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `bootstrap` | map<key, map<locale, value>> | {} | 引导覆盖（通常来自预设），首次启动以 `fill` 模式导入 |
| `retire_after_hours` | int | 24 | 插件缺席多久后退役其键 |
| `max_import_bytes` | int | 2097152 | 导入文件上限 |
| `icon_max_bytes` | int | 262144 | 图标上传上限 |

运行时设置（后台可改）：

| 配置键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `snapshot_cache_ttl_secs` | int | 3600 | Redis 快照缓存 TTL |
| `wildcard_threshold` | int | 500 | 事件 `keys` 超过此数量时改发 `["*"]` |
| `history_page_size` | int | 50 | 后台历史分页 |

站点术语：本插件不拥有业务术语。权限说明键 `terms.perm.manage`（catalog 规则允许，不逐一登记）。后台界面文案走 i18n。

## 6. 外部接口需求概述
