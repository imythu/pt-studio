## 1. 模块详细设计

### 1.0 公共约定

- crate `pt-plugin-terms`（`plugins/native/terms/`），`pub fn plugin() -> NativePlugin`。Native 插件，可以使用进程内缓存（WASM 的“无跨调用状态”约束不适用），但**进程内缓存只是加速**，真相永远是 PG，任何缓存条目都以全局版本号为键。
- 每次服务调用 / HTTP 请求 / 事件处理 / cron 批次是一个 PG 事务（内核工作单元）。所有改变有效值的写操作都遵循同一模板（下称“写模板”）：

```
BEGIN（内核开启）
  SELECT version, default_locale, locales FROM registry_state WHERE id = 1 FOR UPDATE   -- 全局写锁
  … 读取当前行（FOR UPDATE）、计算差异、校验 …
  若无任何变化 → 直接返回（不递增版本、不发事件、不写历史）
  v := UPDATE registry_state SET version = version + 1, updated_at = now() WHERE id = 1 RETURNING version
  批量写数据行（rev / registry_version = v）
  INSERT term_history（registry_version = v）
  ctx.events.publish(terms.updated{keys, locale, version: v})        -- outbox，与数据同事务
  ctx.audit.write(...)（管理操作）
COMMIT（内核提交）
提交后：清理本进程缓存中 version < v 的条目（可选，失败无影响）
```

- `registry_state` 行锁把所有写者串行化。术语写入频率极低（管理员操作、启动登记、动态键登记），串行化不构成瓶颈；它同时消除了“并发登记 / 并发导入”产生交错版本的可能。
- 时间一律 `ctx.time.now()`；UUID 一律 `ctx.random.uuid_v7()`。
- 语言标签统一规范化：按 BCP 47 规则大小写（`zh-cn` → `zh-CN`，`EN` → `en`），正则 `^[a-z]{2,3}(-[A-Z][a-z]{3})?(-([A-Z]{2}|[0-9]{3}))?$`，长度 ≤ 35。
- 字符串值进入任何处理前先做 Unicode NFC 规范化并去除首尾空白（§1.5）。
- 日志中可以记录术语键与语言（非敏感），不记录导入文件原文。

### 1.1 site：站点语言信息

| 项 | 内容 |
|---|---|
| 来源 | ★ 内核在 `register` 请求中附带 `site{default_locale, locales}`（site.toml `[site]`）；每个副本启动都会带一次，写入 `registry_state` |
| 退化方案 | ★ 未合入前：`[plugin.terms]` 静态配置 `default_locale`、`locales` 必填，内核登记时不带 site 信息 |
| 变化处理 | `default_locale` 或 `locales` 与 `registry_state` 不同 → 更新并递增版本，事件 `keys = ["*"], locale = "*"`（全部快照的回退链都变了） |
| 多副本不一致 | 滚动修改 site.toml 期间新旧副本交替登记会使 locales 来回切换：为此 site 信息也按“最高内核版本优先”保护（`registry_state.site_kernel_version`，比较规则同 §1.2 的 semver 保护） |

回退链（`chain(req)`，FR-TERMS-006）：

```
fn chain(req: Option<&str>, st: &SiteState) -> Vec<Locale>:
    out = []
    if let Some(r) = req.map(normalize):
        if st.locales.contains(r): out.push(r)
        b = language_subtag(r)                       // "zh-TW" → "zh"
        if b != r && st.locales.contains(b): out.push(b)
    out.push(st.default_locale)
    out.push("en")                                   // en 总是最后一级回退（即使站点未启用 en，插件默认值中的 en 仍可用）
    dedupe(out)
```

- 请求语言未启用（如 `ja`）时不进入链，直接从 `default_locale` 开始；快照缓存按“链的首元素”归一（`ja` 与 `zh-CN` 共用 `zh-CN` 快照）。
- 只有 `locales` 中的语言可以设置覆盖（FR-TERMS-027）；`en` 未启用时只用其默认值。

### 1.2 registry：启动登记（`register`）

**输入**：`RegisterRequest{site, plugins: [{plugin_id, plugin_version, terms: [{key, values: [{locale, value}]}]}]}`。★ 内核必须为**每个启用的插件**（包括没有 `[terms]` 的插件，`terms = []`）各传一项，另加 `plugin_id = "kernel"` 一项（`kernel.site_name`，默认值来自 `site.name`）；否则“插件删掉全部术语”与“插件未传”无法区分。

**校验**（`validate_def`，每条定义）：

| 检查 | 级别 | 问题码 |
|---|---|---|
| 键正则 `^[a-z][a-z0-9-]*(\.[a-z0-9_]+)+$`，长度 ≤ 160 | error（丢弃该键） | `terms.invalid_key` |
| 键首段 = `plugin_id` | error（丢弃） | `terms.not_owner` |
| 同一插件内键重复 | error（丢弃后者） | `terms.invalid_key` |
| 语言标签合法 | error（丢弃该语言） | `terms.invalid_locale` |
| 值校验（§1.5，默认值规则） | error（丢弃该语言） | 对应字段问题码 |
| 校验后该键没有任何语言 | error（丢弃该键） | `terms.name_required` |
| 缺 `zh-CN` 或 `en` | warning（保留） | `terms.missing_required_locale` |
| 单插件键数 > 5000 | error（整个插件拒绝） | `terms.too_many_keys` |

**版本保护**（DD-TERMS-6）：`defs_hash = sha256(canonical_json(valid_defs))`，canonical = 键按字典序、语言按字典序、字段按固定顺序、紧凑 JSON、NFC。

```
register(req):
    inv = ctx.invocation
    if inv.caller_plugin != "kernel": return Err(terms.kernel_only)
    st = lock_registry_state()                                      // 写模板
    changes = ChangeSet::new()
    apply_site_info(req.site, &mut st, &mut changes)                // §1.1
    report = []
    for p in req.plugins.sorted_by(plugin_id):
        (defs, issues) = validate_plugin(p)
        h = defs_hash(defs)
        reg = SELECT * FROM plugin_registrations WHERE plugin_id = p.id FOR UPDATE
        outcome = match reg:
            None                                   => apply_plugin(p, defs, &mut changes); Applied
            Some(r) if semver(p.v) > semver(r.v)   => apply_plugin(...); Applied
            Some(r) if p.v == r.v && h != r.hash   => apply_plugin(...); Applied        // 同版本重新打包（开发环境）
            Some(r) if p.v == r.v && h == r.hash   => restore_absent(p.id, &mut changes); Unchanged
            Some(r) /* p.v < r.v */                => record_stale(p, defs, h); StaleVersion  // 不改默认值
        upsert plugin_registrations(last_registered_at = now, last_seen_at = now,
                                    absent_retired_at = NULL [Applied/Unchanged], last_report = issues)
        report.push(PluginReport{…})
        metrics: pt_terms_register_issues_total{plugin, level}
    if changes.is_empty(): return Ok(RegisterReport{version: st.version, changed: false, plugins: report})
    v = bump_version()
    flush(changes, v)              // 批量写 term_keys / term_defaults / term_history（UNNEST，每批 1000 行）
    publish_updated(changes, v)    // §1.9
    Ok(RegisterReport{version: v, changed: true, plugins: report})
```

`apply_plugin(p, defs)`：

```
existing_keys     = SELECT key, source, is_retired, retired_reason FROM term_keys WHERE plugin_id = p.id
existing_defaults = SELECT key, locale, name, short, unit, icon, plural FROM term_defaults
                    WHERE key IN (existing_keys)
for d in defs:
    k = existing_keys.get(d.key)
    if k is None:          insert term_keys(source='manifest', category=classify(d.key)); changes.add(d.key)
    elif k.source == 'dynamic': update source='manifest'；issue warning terms.dynamic_key_promoted
    if k.is_retired:        unretire(d.key)；history 'unretire'；changes.add(d.key)
    for each locale in union(d.values.locales, existing_defaults[d.key].locales):
        new = d.values.get(locale); old = existing_defaults.get(d.key, locale)
        if new != old: upsert / delete term_defaults；history 'default_set'(before=old, after=new)；changes.add(d.key, locale)
for k in existing_keys where k.source == 'manifest' && !k.is_retired && k.key ∉ defs:
    retire(k.key, 'undeclared')；history 'retire'；changes.add(k.key)
restore_absent(p.id)        // 见下
```

- 管理员覆盖表 `term_overrides` 在登记路径中**只读不写**（FR-TERMS-001）。
- `restore_absent(p)`：把 `plugin_id = p` 且 `retired_reason = 'plugin_absent'` 的键恢复（manifest 键只恢复仍在声明中的；dynamic 键全部恢复）。
- `record_stale`：把旧版本的 `(version, hash, defs)` 写入 `plugin_registrations.stale_*` 列，后台“插件登记”页显示“插件 X 以较低版本 1.1.0 登记，已忽略（当前记录 1.2.0）”。确属有意降级时，管理员在该页点击“以此版本为准”（⊕ `accept_downgrade` 路由，§2.4），以存储的 stale 定义执行 `apply_plugin`。**不做自动降级**：内核只在启动时登记，仅凭时间无法判断高版本副本是否仍在运行。
- 启动风暴：N 个副本同时启动，`registry_state FOR UPDATE` 让它们串行；第一个之后的副本全部命中“hash 相同”分支，单次耗时为若干条主键查询（< 20 ms）。
- 首次安装（约 2 万键）：一次事务、约 20 批 UNNEST，每条语句远低于 `statement_timeout_ms = 5000`；事件 `keys = ["*"]`。

### 1.3 registry：动态键（`define` / `retire`）与退役扫描

**define(defs, idempotency_key)**（FR-TERMS-005）：

```
caller = inv.caller_plugin
idem = idempotency_check(caller, "define", idempotency_key, sha256(canonical(defs)))   // §1.10
if idem.hit: return idem.result
require 1 ≤ len(defs) ≤ 1000                                       else kernel.validation_failed
for d in defs: require first_segment(d.key) == caller               else Err(terms.not_owner)（整次拒绝）
校验同 §1.2；任一 error 级问题 → Err(kernel.validation_failed, details.issues)（全有或全无）
st = lock_registry_state()
for d in defs:
    k = SELECT … FROM term_keys WHERE key = d.key FOR UPDATE
    if k.source == 'manifest' → Err(terms.static_key)（整次拒绝）
count = SELECT count(*) FROM term_keys WHERE plugin_id = caller AND source = 'dynamic' AND NOT is_retired
if count + 新键数 > max_dynamic_keys_per_plugin → Err(kernel.quota_exceeded)
逐键：新建 / 恢复（已退役则 unretire）/ 默认值整体替换（未给出的语言删除）；比较后只记录有变化的
有变化 → 写模板（history action = 'define'，actor = plugin:caller）
保存幂等结果；返回 DefineResult{created, updated, unchanged, restored, issues(warnings), registry_version}
```

**retire(keys, idempotency_key)**：键必须是调用方的 dynamic 键；manifest 键 → `terms.static_key`；不存在 → 计入 `unchanged` 并给 warning `terms.key_not_found`；已退役 → `unchanged`。退役原因 `owner_retired`，覆盖值保留。

**动态键使用约定**（给属主插件）：

- 属主在“新建实体”时调用一次 `define`，默认值取自管理员在属主界面填写的名称；幂等键 `<entity_kind>:<entity_id>:<revision>`，事件驱动场景用 `<event_id>:terms`。
- 之后的改名推荐深链到 `/admin/p/terms/edit/<key>`（覆盖值），不要在属主界面再维护一份名称；若属主仍再次 `define` 改默认值，已有覆盖值继续生效（编辑页会提示“默认值已变化”）。
- 实体删除时 `retire`；实体恢复时再次 `define`。

**retire_sweep（cron，`15 * * * *`，FR-TERMS-004 / 030）**：

```
run(job):                                   // tx = manual
    plugins = ctx.service::<dyn PluginsService>("ctx.plugins").list()      // 当前副本启用的插件
    UPDATE plugin_registrations SET last_seen_at = now()
        WHERE plugin_id = ANY($enabled_ids)；commit
    absent = SELECT plugin_id FROM plugin_registrations
             WHERE plugin_id <> 'kernel' AND absent_retired_at IS NULL
               AND last_seen_at < now() - make_interval(hours => $retire_after_hours)
    for p in absent:                         // 每个插件一个事务
        keys = SELECT key FROM term_keys WHERE plugin_id = p AND NOT is_retired FOR UPDATE
        写模板：retire(keys, 'plugin_absent')，history 'retire'，事件（keys 或 ["*"]）
        UPDATE plugin_registrations SET absent_retired_at = now() WHERE plugin_id = p
        commit
```

- 心跳来源：`last_seen_at` 由两处刷新：启动登记、本 cron 读取 `ctx.plugins.list()`。cron 每小时在任意一个副本运行，所以只要集群中**任一副本**仍启用该插件且该副本跑过 cron，插件就不会被判缺席。★ 假定 `PluginInfo` 含 `id`、`version`、`enabled`（catalog/services.md 未给出字段，见 §10）。
- 重复执行：已退役的键被 `NOT is_retired` 过滤，`absent_retired_at` 已设置的插件被跳过；第二次执行不递增版本、不发事件。
- `kernel` 的键永不因缺席而退役。

### 1.4 resolve：有效值合并

输入：某键在链上各语言的默认值行 `D[l]` 与覆盖行 `O[l]`（字段 `NULL` = 继承，`''` = 显式清空，仅 `short/unit/icon/plural` 可清空）。

```
fn effective(key, chain, D, O) -> Effective:
    // 1. 名称：首个“有名称”的语言
    picked = None
    for l in chain:
        name = O[l]?.name.or(D[l]?.name)
        if name.is_some(): picked = Some(l); break
    if picked is None:
        return Effective{name: key, resolved_locale: "und", short/unit/plural: None, icon: icon_walk()}
    l = picked
    // 2. 同一语言内取其他字段（不跨语言，避免“猫粮 + pts”混搭，DD-TERMS-3）
    field(f) = match O[l]?.f { Some("") => None, Some(v) => Some(v), None => D[l]?.f }
    // 3. 图标与语言无关，沿整条链回退
    icon_walk() = for l in chain: match O[l]?.icon { Some("") => return None, Some(v) => return Some(v), None => {} }
                                  if let Some(v) = D[l]?.icon { return Some(v) }
                  None
    Effective{name, short: field(short), unit: field(unit), plural: field(plural), icon: icon_walk(),
              icon_url: icon_url(icon), resolved_locale: l}
```

- `icon_url(icon)`：`blob:icons/<sha>.webp` → `/api/p/terms/v1/icons/<sha>.webp`；`icon:<name>` → 无（前端用内置图标集渲染）。
- 编辑页设置图标时默认写入 `default_locale` 的覆盖（其余语言沿链继承），“仅此语言”复选框可改为写入当前语言。
- 回退用例表见 TP §3.2（TC-TERMS-020～029）。

### 1.5 validate：值校验

公共规则（默认值与覆盖值相同，FR-TERMS-010 / NFR-TERMS-007）：

1. NFC 规范化，去除首尾空白；长度按 Unicode 标量计。
2. 拒绝：`Cc` 类控制字符（含换行、制表）、`<`、`>`、双向控制符（U+202A～U+202E、U+2066～U+2069）、U+FEFF、U+200B；允许 U+200D（emoji 组合）。
3. 字段上限：`name` 1～64、`short` ≤ 32、`unit` ≤ 16、`icon` ≤ 128、`plural` ≤ 512。
4. `name` 不能只由空白组成；覆盖值中 `name` 只能为 NULL（继承）或非空。
5. `{`、`}`、`'`、`#` 允许出现在 `name/short/unit` 中：渲染时在 AST 层作为文本节点替换（§1.6），不会被解释为 ICU 语法。

`icon`：

| 形式 | 规则 |
|---|---|
| `icon:<name>` | `<name>` 匹配 `^[a-z0-9-]{1,40}$` 且在内置图标清单中。清单 `builtin_icons.txt` 由 `xtask gen-icons` 从 `web/ui-kit` 的图标集生成并编译进插件 |
| `blob:icons/<sha256hex>.webp` | `icons` 表中存在该哈希 |
| 其他（URL、`data:`、SVG） | 拒绝 `terms.icon_invalid` |

`plural`（DD-TERMS-8）：用 §1.6 的解析器解析，要求：

- 整个字符串恰好是一个顶层占位 `{count, plural, …}`（前后不得有文本），参数名必须是 `count`；
- 必须含 `other` 分支；选择器只能是 `=<非负整数>` 或该语言 CLDR 复数类别（`icu_plurals` 查询；如 `zh` 只有 `other`，`en` 有 `one/other`，`ru` 有 `one/few/many/other`）；
- 分支内容只能是文本与 `#`，不得嵌套参数、`select`、`{term:…}`；
- `offset:` 不允许。

覆盖值的额外规则：

- 设置覆盖后若该语言 `O.name` 为 NULL 且该键在该语言没有默认值 → `terms.name_required`（否则该覆盖永远不会被选中，见 §1.4 第 1 步）。
- 语言 ∉ `registry_state.locales` → `terms.locale_not_enabled`。

错误输出：HTTP 422 `kernel.validation_failed`，`errors[] = [{path: "/plural", code: "terms.plural_invalid", message, details?}]`；服务调用返回同一错误码与 `details.errors`。

### 1.6 render：共享渲染 crate `pt-term-render`

位置 `crates/term-render`（MIT OR Apache-2.0），★ 内核宿主接口 `terms.render` 与本插件 `render` 共用（NFR-TERMS-011）。依赖 `icu_plurals`、`icu_decimal`、`icu_locale`（ICU4X，Unicode-3.0 许可证，★ 加入 cargo-deny 允许列表）。ICU4X 目前没有稳定的 MessageFormat 实现，因此 crate 自带 **MessageFormat 1 子集**解析器与格式化器。

**语法（EBNF）**：

```
message      = { text | placeholder } ;
placeholder  = "{" ws ( termref | argument ) ws "}" ;
termref      = "term:" key [ "|" form ] ;
form         = "short" | "unit" | "plural(" ident ")" ;
argument     = ident [ ws "," ws argtype ] ;
argtype      = "number" [ ws "," ws ( "integer" | "percent" ) ]
             | "plural" ws "," ws plural_body
             | "select" ws "," ws select_body ;
plural_body  = { ws selector ws "{" message "}" } ;          (* 必须含 other *)
selector     = "=" digits | "zero" | "one" | "two" | "few" | "many" | "other" ;
select_body  = { ws ident ws "{" message "}" } ;             (* 必须含 other *)
ident        = ( letter | "_" ) { letter | digit | "_" } ;
key          = 术语键正则 ;
text         = 普通字符；"''" 表示一个单引号；"'{"…"'" 引号内为字面量；plural 分支内 "#" 表示当前数值
```

**限制**：模板 ≤ 16 KiB；嵌套深度 ≤ 4；`{term:…}` ≤ 64 个；输出 ≤ 64 KiB；不支持日期 / 时间 / 货币参数（调用方先格式化为字符串）。

**算法**：

```
render(template, args, locale, lookup) -> Result<String>:
    ast = parse(template)?                                   // terms.template_invalid{offset, reason}
    ast = expand_terms(ast, |key, form| {
        t = lookup(key, locale)                              // 未知键：name = key，计数 pt_terms_unknown_keys_total
        match form:
            Name   => [Text(t.name)]                         // 文本节点：值中的 { } ' # 不会被解释
            Short  => [Text(t.short ?: t.name)]
            Unit   => [Text(t.unit ?: "")]
            Plural(arg) => match t.plural:
                Some(p) => parse(p).rename_arg("count", arg)  // 写入时已校验，只含文本与 #
                None    => [Number(arg), Text(" "), Text(t.unit ?: t.name)]
    })
    args = parse_args(args)?          // JSON 对象；值只能是 number / string / bool；否则 terms.render_arg_invalid
    out = format(ast, args, PluralRules::cardinal(locale), DecimalFormatter(locale))?
          // 缺参数 → terms.render_arg_missing{arg}；plural/number 参数非数字 → terms.render_arg_invalid
    require len(out) ≤ 64 KiB           else terms.template_invalid{reason: "output_too_large"}
    Ok(out)
```

- 输出是**纯文本**：渲染器不做 HTML 转义，也不产生标记；嵌入 HTML 的使用方（notify 邮件、前端）负责转义（FR-TERMS-019）。
- 渲染结果不得再次作为模板输入（避免二次解释），调用方文档中写明。
- 例：`zh-CN`，`bonus.currency = {name: 猫粮, unit: 颗, plural: "{count, plural, other {# 颗猫粮}}"}`：
  - `"你获得了 {term:bonus.currency|plural(n)}"`，`{n: 120}` → `你获得了 120 颗猫粮`
  - `"{term:bonus.currency}不足"` → `猫粮不足`
  - `en`，`plural = "{count, plural, one {# Cat Treat} other {# Cat Treats}}"`，`{n: 1}` → `1 Cat Treat`
  - 术语名为 `{x}'s`：`"{term:k}"` → `{x}'s`（字面输出）

### 1.7 snapshot：快照构建与缓存

**快照体**（`snapshot.body`，内核原样输出给前端，FR-TERMS-017）：

```json
{
  "locale": "zh-CN",
  "version": 1287,
  "chain": ["zh-CN", "en"],
  "terms": {
    "bonus.currency": { "name": "猫粮", "short": "猫粮", "unit": "颗", "icon": "icon:coin",
                        "plural": "{count, plural, other {# 颗猫粮}}" },
    "promotion.free": { "name": "免费", "icon": "blob:icons/9f86d081884c7d65….webp",
                        "icon_url": "/api/p/terms/v1/icons/9f86d081884c7d65….webp" },
    "hnr.rule_summary": { "name": "H&R Rules", "from": "en" }
  }
}
```

- 省略为空的字段；`from` 仅在实际取值语言 ≠ `locale` 时出现（前端可据此设置 `lang` 属性）；名称回退到键名的条目 `from = "und"`。
- 只含未退役键；按键排序（稳定输出，便于 ETag 与 diff）。

**构建**：

```
snapshot(locale, if_version):
    st = SELECT version, default_locale, locales FROM registry_state WHERE id = 1
    c = chain(locale, st); head = c[0]
    if if_version == Some(st.version): return None
    if let Some(s) = local_cache.get((head, st.version)): return Some(s)          // moka，最多 16 条
    if let Some(bytes) = redis GET snap:<head>:<version>: s = unzstd(bytes); local_cache.put; return Some(s)
    got = redis SET snaplock:<head>:<version> <node> NX EX 10
    if !got: 轮询 GET snap:… 4 次（间隔 50 ms），命中则返回；否则自行构建（防止锁持有者崩溃）
    s = build(c, st.version)?；redis SET snap:<head>:<version> zstd(s) EX snapshot_cache_ttl_secs
    local_cache.put；return Some(s)

build(c, v0):
    for attempt in 1..=3:
        rows = keyset 分页（每页 5000，受 database.max_rows = 10000 限制）:
            SELECT k.key,
                   (SELECT jsonb_object_agg(d.locale, jsonb_build_object('n',d.name,'s',d.short,'u',d.unit,'i',d.icon,'p',d.plural))
                      FROM term_defaults d WHERE d.key = k.key AND d.locale = ANY($chain)) AS defaults,
                   (SELECT jsonb_object_agg(o.locale, jsonb_build_object('n',o.name,'s',o.short,'u',o.unit,'i',o.icon,'p',o.plural))
                      FROM term_overrides o WHERE o.key = k.key AND o.locale = ANY($chain)) AS overrides
              FROM term_keys k
             WHERE NOT k.is_retired AND k.key > $after
             ORDER BY k.key LIMIT 5000
        v1 = SELECT version FROM registry_state WHERE id = 1
        if v1 == v0: return serialize(resolve_all(rows, c), v0)
        v0 = v1                                         // 构建期间有写入：以新版本重建
    Err(kernel.service_unavailable)                    // 连续 3 次被并发写入打断（实际不会发生）
```

- 页间一致性：写入方总会递增版本，构建结束时比对版本即可发现“跨页读到两个版本”的情况。
- 键数 2 万时快照体约 2.4 MiB，zstd(3) 后约 0.5 MiB；服务调用参数 + 返回 ≤ 4 MiB 的限制只对跨 WASM 调用适用，内核（Native 进程内）调用不受限，但仍记录指标 `pt_terms_snapshot_bytes{locale}`，> 3 MiB 告警。

**version()**：`SELECT version FROM registry_state WHERE id = 1`（主键单行，< 1 ms）。不缓存在 Redis：它是失效判断的唯一依据，不能有陈旧副本。

**get / get_many**：通过 `snapshot(locale)` 的进程内结构取值（先读版本，再查本地缓存）；`get_many` ≤ 1000 键（超出 → `kernel.validation_failed`）；未知或已退役键：`get` 返回 None，`get_many` 省略该项；`pt_terms_unknown_keys_total{caller}` 计数。

### 1.8 store：覆盖写入、重置、历史

**set_override**（HTTP `put_override` 与服务 `set_override` 共用 `overrides::set(actor, key, locale, patch, expected_rev, reason)`）：

```
locale = normalize(locale)；require locale ∈ st.locales            else terms.locale_not_enabled
k = SELECT * FROM term_keys WHERE key = $key                       None → terms.key_not_found；retired → terms.key_retired
st = lock_registry_state()
cur = SELECT * FROM term_overrides WHERE key = $1 AND locale = $2 FOR UPDATE
if expected_rev.is_some() && expected_rev != cur.map(rev).unwrap_or(0): Err(kernel.conflict, details{current_rev, current})
new = cur.unwrap_or_default().apply(patch)        // Keep / Inherit(NULL) / Set(v)
validate(new, has_default(key, locale))?
if new.all_null(): 等同 reset（删除行）
if new == cur: return Ok{changed: false, state: cur, registry_version: st.version}
v = bump_version()
UPSERT term_overrides(…, rev = v, updated_by = actor.user_id, import_id = NULL)
INSERT term_history(action='override_set', before=cur, after=new, actor, reason, registry_version=v)
publish terms.updated{keys:[key], locale, version: v}
audit.write{action:"terms.override_set", target:"term:<key>", details:{locale, before, after, reason}}
```

- `rev` 取自全局版本（单调、永不复用），因此“删除后重建”的覆盖不会与旧 ETag 冲突。HTTP ETag = `"r<rev>"`；无覆盖时 rev 视为 0。
- `reason` ≤ 500 字符，可选（后台界面默认要求填写，可在设置中关闭）。
- **reset_override**：删除行；不存在时返回 `removed = false`（幂等，不递增版本）；`expected_rev` 规则同上；history `override_reset`；audit `terms.override_reset`。
- 服务调用方必须在 `caller_scopes` 中有 `manage`（`[capabilities.scopes] "ctx.terms" = ["manage"]`），否则 `kernel.forbidden`；actor 记为 `plugin:<caller>`，若调用链携带用户（如 AI 助手确认后的操作），`actor.user_id` 一并记录。

**历史查询**：`term_history` 按 `(key, id DESC)` 索引键集分页；`before/after` 为 `{name?, short?, unit?, icon?, plural?}`，JSON 中 `null` 表示继承。后台“恢复到此版本”= 以该条 `after`（或 `before`）为请求体发起一次普通 PUT。

### 1.9 事件发布与缓存失效

```
publish_updated(changes, v):
    keys = changes.keys()（去重排序）
    locales = changes.locales()        // 默认值变化、退役、site 变化 → "*"
    payload = {
        keys:   if keys.len() > wildcard_threshold || changes.is_global() { ["*"] } else { keys },
        locale: if locales.len() == 1 && !changes.is_global() { locales[0] } else { "*" },
        version: v,
    }
    ctx.events.publish(NewEvent{event_type: "terms.updated", version: 1, key: "global", payload})
```

- 载荷大小：500 个键 × ≤ 160 字节 ≈ 80 KiB 上限，实际术语键平均约 25 字节（≈ 13 KiB）；`wildcard_threshold` 最大可设 2000。
- 失效链路：PG 提交 → outbox → `terms.updated` → 内核刷新快照（★ 广播方式见 §10 第 5 项）→ 前端下次请求快照时 ETag 变化。本插件自身的 Redis 快照键带版本号，**不需要显式删除**，旧版本按 TTL 过期。
- 本插件**不订阅**自己的事件；进程内缓存同样以版本为键，下一次调用读取到新版本即自然失效。

```
upload_icon(multipart file):
```

### 1.12 transfer：导出与导入

**统一数据模型**（三种格式互相等价）：`terms: {<key>: {<locale>: {name?, short?, unit?, icon?, plural?}}}`；字段缺省 = 不涉及 / 继承，`""` = 显式清空。

**JSON**：

```json
{
  "format": "pt-studio.terms",
  "format_version": 1,
  "exported_at": "2026-10-05T08:00:00.000Z",
  "scope": "overrides",
  "locales": ["zh-CN", "en"],
  "terms": {
    "bonus.currency": { "zh-CN": { "name": "猫粮", "unit": "颗" }, "en": { "name": "Cat Treats", "unit": "" } },
    "levels.class.5.name": { "zh-CN": { "name": "府尹" } }
  }
}
```

**TOML**（与 `site.toml [plugin.terms.bootstrap]` 结构相同，预设可直接复用）：

```toml
format = "pt-studio.terms"
format_version = 1
scope = "overrides"

[terms."bonus.currency".zh-CN]
name = "猫粮"
unit = "颗"

[terms."bonus.currency".en]
name = "Cat Treats"
unit = ""
```

**CSV**（UTF-8 带 BOM，RFC 4180，宽表）：表头 `key,locale,name,short,unit,icon,plural`；空单元格 = 不涉及 / 继承；`<empty>` = 显式清空（`<` 是禁用字符，不会与真实值冲突）。

**导出**（`export_terms`）：参数 `format`、`scope ∈ {overrides, effective, full}`、`prefix?`、`locales?`（默认全部启用语言）、`include_retired`（默认 false）。

| scope | 内容 |
|---|---|
| `overrides` | 只有覆盖行（含孤儿覆盖与退役键的覆盖，`include_retired` 控制）；用于站点间分享“叫法包”，再导入后往返一致（FR-TERMS-020） |
| `effective` | 每键每语言的有效值（只读参考，导入时作为 merge 处理） |
| `full` | `{default, override, effective}` 三层；仅 JSON 支持，CSV/TOML 返回 422 |

- CSV 防公式注入：单元格以 `=`、`+`、`-`、`@`、`\t`、`\r` 开头时在前面加 `'`；导入时若首字符为 `'` 且第二个字符属于上述集合，则去掉 `'`。
- 流式输出（每次读取 2000 键），`Content-Disposition: attachment; filename="terms-<scope>-<yyyyMMdd>.<ext>"`，`Cache-Control: no-store`。

**导入**：

```
create_import(file, mode, unknown, prefix?, dry_run = true):
    size ≤ max_import_bytes；格式按扩展名 + 内容判定（JSON 首个非空白字符为 "{"；TOML 可解析；CSV 表头匹配）
    parse（JSON 深度 ≤ 6；条目 ≤ max_import_items = 50000）  失败 → terms.import_parse_failed{line, column}
    if mode == replace && prefix 为空 → kernel.validation_failed（/prefix）
    st = SELECT version, locales …；cur = 读取范围内（文件涉及的键 ∪ replace 前缀下的键）的覆盖与键状态
    plan = diff(file, cur, mode, unknown)：每项 {key, locale, op, before, after, class, issues}
        op    ∈ set | reset | none
        class ∈ add（新覆盖）| change | reset | unchanged | unknown_skip | unknown_keep（孤儿）| retired（键已退役，覆盖保存）| invalid
        merge：文件给出的字段覆盖当前字段，未给出的字段保持
        fill：只处理当前没有覆盖行的 (key, locale)
        replace：前缀下、文件语言范围内的覆盖整体替换为文件内容；文件未出现的 (key, locale) → reset
        语言未启用 / 值不合法 → invalid
    blob.put("imports/<id>.<ext>", 原文件)        // 留档，随记录清理
    INSERT imports(status='previewed', base_version = st.version, plan, summary, expires_at = now + 24 h)
    if !dry_run: 直接执行 apply（skip_invalid = false）
    201 + Location
```

```
apply_import(id, skip_invalid, reason):
    imp = SELECT … FROM imports WHERE id = $1 FOR UPDATE
    status == applied  → 200 返回 imp.result（幂等）
    status == expired / failed 或 now > expires_at → terms.import_state_invalid
    st = lock_registry_state()
    if st.version != imp.base_version:
        plan2 = 重新计算 diff
        if plan2 != imp.plan: UPDATE imports SET plan = plan2, base_version = st.version, summary …
                              → 409 terms.import_stale（响应带新 summary，前端要求再次确认）
    invalid > 0 && !skip_invalid → kernel.validation_failed（details.invalid_count）
    v = bump_version()
    分批（每批 1000）UPSERT / DELETE term_overrides（rev = v, import_id = id）；history action='import'
    publish terms.updated{keys（> 阈值 → ["*"]）, locale（多语言 → "*"）, version: v}     // 一次事件
    audit terms.import_applied{import_id, mode, summary, reason}
    UPDATE imports SET status='applied', applied_by, applied_at, result
```

- 单次导入 ≤ 5 万项，整体是一个事务（每条语句 ≤ 1000 行，远低于 5 s 语句超时；整体通常 < 3 s）。这是有意的：导入必须原子，且只产生一次版本递增与一次事件（FR-TERMS-021）。
- HTTP 层 `create_import`、`apply_import` 声明 `idempotent = true`，客户端带 `Idempotency-Key`；业务层状态机本身也保证重复 apply 无副作用。

**引导覆盖 bootstrap（FR-TERMS-024）**，在 `lifecycle.init` 中执行（早于内核的 `register` 调用）：

```
init():
    b = config.static.bootstrap；if b 为空 → return
    h = sha256(canonical(b))
    st = lock_registry_state()
    if st.bootstrap_hash == h → return
    items = 对每个 (key, locale)：仅当 term_history 中从未有过该 (key, locale) 的 override_set / override_reset / import / bootstrap 记录
            且当前无覆盖行时才写入（“从未被人动过”才填，管理员改过或重置过的永不回填）
    unknown 一律 keep（此时插件键可能尚未登记，成为孤儿覆盖，登记后自动生效）
    有写入 → 写模板（history action='bootstrap'，actor = system）
    UPDATE registry_state SET bootstrap_hash = h, bootstrap_applied_at = now()
```

- 多副本同时启动：行锁串行，第二个副本看到 hash 相同直接返回。
- 预设升级后 `bootstrap` 内容变化 → hash 变化 → 只补填新增且从未被动过的项。

```
        （“魔力值”能匹配到已被改名为“猫粮”的 bonus.currency —— 帮助模型把通用叫法映射到本站叫法）
        排序：精确匹配 > 前缀 > 子串；同级按键名
    输出（§2.5）
```

### 1.16 内核接入（本插件提供的支持）

| 内核行为（kernel/03 §13） | 本插件提供 |
|---|---|
| 启动登记 | `register`；返回 `RegisterReport`，内核把 error 级问题写入启动日志（不阻止启动） |
| 进程内快照 | `snapshot(locale, if_version)`：版本未变返回 None，避免重复传输 |
| 刷新 | ★ 推荐（§10 第 5 项）：收到 `terms.updated` 的副本 `PUBLISH k:bus terms:<version>`，各副本比较本地版本后调用 `snapshot`。退化方案：各副本每 2 s 调用一次 `version()`（一条主键查询），版本变化即拉取。两种方式本插件都无需改动 |
| 宿主接口 `terms.get/get-many/render` | 内核用本地快照 + `pt-term-render`；★ `term` 记录增加 `plural`、`icon-url` |
| `GET /api/kernel/v1/terms?locale=` | 返回 `snapshot.body`，`ETag: "<version>-<head>"`（W/ 不需要），`Cache-Control: no-cache`（每次带 If-None-Match 校验） |
| terms 故障 | 内核继续使用最后一份快照；冷启动且 terms 不可用时使用清单默认值（NFR-TERMS-005） |

```wit
package pt:terms@0.1.0;

interface terms {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms, json};

  /// 一种语言的术语值（默认值、覆盖合并前的原始值）
  record term-value {
    name: string,
    short: option<string>,
    unit: option<string>,
    icon: option<string>,
    plural: option<string>,
  }

  record localized-value {
    locale: string,
    value: term-value,
  }

  /// 有效值（按回退链合并后）
  record term {
    key: string,
    name: string,
    short-name: option<string>,
    unit: option<string>,
    /// "icon:<name>" 或 "blob:icons/<sha>.webp"
    icon: option<string>,
    /// 可直接用于 <img src> 的站内地址（仅 blob 图标）
    icon-url: option<string>,
    /// ICU 复数片段，参数名 count
    plural: option<string>,
    /// 实际取到名称的语言；名称回退为键名时为 "und"
    resolved-locale: string,
  }

  // ---------- 登记 ----------
  record site-info {
    default-locale: string,
    locales: list<string>,
    /// 内核版本（semver），用于多副本 site 信息的版本保护
    kernel-version: string,
  }

  record term-def {
    key: string,
    values: list<localized-value>,
  }

  record plugin-terms {
    plugin-id: string,
    plugin-version: string,
    terms: list<term-def>,
  }

  record register-request {
    site: site-info,
    /// 每个启用的插件一项（含没有 [terms] 的插件），另加 plugin-id = "kernel"
    plugins: list<plugin-terms>,
  }

  enum issue-level { warning, error }

  record def-issue {
    key: string,
    locale: option<string>,
    level: issue-level,
    /// 问题码，如 "terms.invalid_key"
    code: string,
    message: string,
  }

  enum plugin-outcome { applied, unchanged, stale-version, rejected }

  record plugin-report {
    plugin-id: string,
    outcome: plugin-outcome,
    upserted: u32,
    retired: u32,
    restored: u32,
    issues: list<def-issue>,
  }

  record register-report {
    registry-version: u64,
    changed: bool,
    plugins: list<plugin-report>,
  }

  record define-result {
    created: u32,
    updated: u32,
    unchanged: u32,
    restored: u32,
    issues: list<def-issue>,
    registry-version: u64,
  }

    retired: u32,
    unchanged: u32,
    issues: list<def-issue>,
    registry-version: u64,

  variant field-patch {
    keep,
    inherit,
    set(string),
  }

    name: field-patch,
    short: field-patch,
    unit: field-patch,
    icon: field-patch,
    plural: field-patch,
  }

  record override-state {
    key: string,
    locale: string,
    name: option<string>,
    short: option<string>,
    unit: option<string>,
    icon: option<string>,
    plural: option<string>,
    /// 覆盖行版本（取自全局版本，单调）；0 = 无覆盖
    rev: u64,
    updated-at: option<timestamp-ms>,
    updated-by: option<user-id>,
  }

  record set-override-request {
    key: string,
    locale: string,
    patch: override-patch,
    /// 乐观锁：期望的当前 rev（0 = 期望当前无覆盖）；none = 不检查
    expected-rev: option<u64>,
    reason: option<string>,
    idempotency-key: string,
  }

  record set-override-result {
    state: override-state,
    changed: bool,
    registry-version: u64,
  }

  record reset-override-request {
    key: string,
    locale: string,
    expected-rev: option<u64>,
    reason: option<string>,
    idempotency-key: string,
  }

  record reset-override-result {
    removed: bool,
    registry-version: u64,
  }

  // ---------- 快照 ----------
  record snapshot {
    locale: string,
    version: u64,
    chain: list<string>,
    /// 快照体 JSON（LLD §1.7）
    body: json,
  }

  /// 有效值；未知或已退役键返回 none。locale 为空时用调用上下文 locale
  get: func(key: string, locale: option<string>) -> result<option<term>, plugin-error>;
  /// ≤ 1000 键；结果顺序与输入一致，未知键省略
  get-many: func(keys: list<string>, locale: option<string>) -> result<list<term>, plugin-error>;
  /// 展开 {term:…} 后按 MessageFormat 子集渲染；args 为 JSON 对象；输出纯文本
  render: func(template: string, args: json, locale: option<string>) -> result<string, plugin-error>;
  /// 需要作用域 manage
  set-override: func(req: set-override-request) -> result<set-override-result, plugin-error>;
  /// 需要作用域 manage
  reset-override: func(req: reset-override-request) -> result<reset-override-result, plugin-error>;
  /// 仅内核
  register: func(req: register-request) -> result<register-report, plugin-error>;
  /// 键前缀必须等于调用方插件 ID；≤ 1000 条；全有或全无
  define: func(defs: list<term-def>, idempotency-key: string) -> result<define-result, plugin-error>;

  retire: func(keys: list<string>, idempotency-key: string) -> result<retire-result, plugin-error>;

  snapshot: func(locale: string, if-version: option<u64>) -> result<option<snapshot>, plugin-error>;
```

| 触发 | keys | locale |
|---|---|---|

#### `PUT /terms/{key}/overrides/{locale}`

```http

X-CSRF-Token: …
Content-Type: application/json
```

- 整体替换：缺省或 `null` 字段 = 继承；`""` = 清空（`name` 不能为 `""`）。全部字段继承 = 等同 DELETE。

- 200：返回该语言的 `{default, override, effective, rev, updated_at, updated_by}`，`ETag: "r<新 rev>"`。内容无变化时同样返回 200，rev 不变。

### 2.6 前端 / 通知取值约定（FR-TERMS-017、019）

**前端 SDK**（`@pt-studio/slots` 的 `PluginApi`，数据来自内核快照）：

```ts
type TermValue = { name: string; short?: string; unit?: string; icon?: string; icon_url?: string;
                   plural?: string; from?: string };

t('term:bonus.currency')            // → name；未知键 → 键名（开发模式 console.warn）
t('term:bonus.currency|short')      // → short ?? name
t('term:bonus.currency|unit')       // → unit ?? ''
tp('term:bonus.currency', 120)      // plural 存在：format(plural, {count: 120})；否则 `${fmt(120)} ${unit ?? name}`
useTerm('bonus.currency')           // → TermValue | undefined（React hook，快照更新时重渲染）
useTermFamily('torrent.category.')  // → Array<[key, TermValue]>（按键排序；用于动态族下拉框）
<TermIcon k="promotion.free" size={16} />   // icon: 内置图标；blob: <img src={icon_url} alt={name}>
```

- 快照加载：应用启动时 `GET /api/kernel/v1/terms?locale=<当前语言>`（带 `If-None-Match`），结果按 `(locale, version)` 存 `localStorage`（读写包在 try/catch 中，失败只影响首屏）；★ 若内核在 API 响应中附带 `X-PT-Terms-Version` 头（§10 第 6 项），SDK 发现版本变大即后台刷新；退化方案：每 5 分钟及页面可见性恢复时校验一次。
- 前端复数格式化与后端使用同一组测试夹具（`crates/term-render/tests/fixtures/*.json`，前端 vitest 读取同一文件），保证语义一致；前端实现为 `@pt-studio/slots` 内的 MF 子集 + `Intl.PluralRules`。
- 渲染结果作为 React 文本节点输出（自动转义），禁止 `dangerouslySetInnerHTML`。

**通知模板**（notify 及其他发送文本的插件）：

- 模板中只用 `{term:<key>}` 系列占位引用叫法，不得写死“魔力值”；参数用 ICU 参数（`{n, number}`、`{n, plural, …}`）。
- 调用 `ctx.terms.render(template, args, recipient_locale)`（或宿主接口 `terms.render`）。标题与正文分别渲染。
- 输出是纯文本：HTML 邮件由 notify 在渲染**之后**做 HTML 转义再嵌入；渲染结果不得再次作为模板。
- 渲染失败（`terms.render_arg_missing` 等）属于调用方缺陷，notify 应记录并回退到不含该参数的兜底文案，不应重试。

| `term_overrides` | 通常 < 1000，上限 16 万 | 键 × 启用语言 |
| `term_history` | ≤ 100 万行（NFR-TERMS-010） | 不分区（远低于 5000 万阈值）；永久保留 |
| `imports` | 数百行 | 90 天清理；`plan` 最大约 10 MiB（TOAST） |
| `icons` | 数百行 | |
| `service_idempotency` | 数千行 | 7 天清理 |

### 3.2 Redis（实例 `main`，私有前缀 `p:terms:`，下表为插件代码中的写法）

| 键 | 类型 | TTL | 内容 | 内存估算 |
|---|---|---|---|---|
| `snap:<locale>:<version>` | STRING | `snapshot_cache_ttl_secs`（默认 3600） | 快照体 JSON，zstd(3) 压缩 | 5000 键约 120 KiB；2 万键约 0.5 MiB；× 8 语言 × ≤ 2 个版本 ≈ 8 MiB |
| `snaplock:<locale>:<version>` | STRING（NX） | 10 s | 构建者 node_id，防止击穿 | 可忽略 |

- 两类键都带版本号，写入后不再修改；失效靠版本变化与 TTL，不需要显式删除。
- 清单：`[redis] quota_mb = 32`（默认值即可）、`max_keys = 1000`。
- Redis 不可用：`snapshot` 直接从 PG 构建（进程内缓存仍生效），记录 `pt_terms_snapshot_cache_total{result="redis_error"}`；所有写操作不依赖 Redis。

### 3.3 搜索索引贡献

无（`search_contributor = false`）。search-meilisearch 订阅 `terms.updated` 自行派生同义词（其 LLD §1.5），本插件只保证 `keys` 可能为 `["*"]`、`version` 可用于去重。

### 5.2 编辑页 `TermEditPage`

```
┌ bonus.currency  [currency] [bonus · manifest]                       历史 ▸ ┐
│            │ zh-CN（默认语言）              │ en                          │
│ 名称       │ 默认：魔力值                   │ 默认：Bonus Points          │
│            │ [猫粮          ] (继承 ○)      │ [              ] (继承 ●)   │
│ 短名       │ 默认：魔力   [ ] (继承●/清空○) │ …                           │
│ 单位       │ 默认：点     [颗]              │ …                           │
│ 图标       │ [🪙 icon:coin ▾] □仅此语言     │ （沿链继承：icon:coin）     │
│ 复数       │ 结构化编辑器：other [# 颗猫粮] │ one [# Cat Treat] other […] │
│            │ ⟳ 原始 ICU 模式                │                             │
│ 预览       │ 0 → 0 颗猫粮 · 1 → 1 颗猫粮 …  │ 1 → 1 Cat Treat · 5 → …     │
│ 模板试算   │ [你获得了 {term:bonus.currency|plural(n)}]  n=[120] → 你获得了 120 颗猫粮 │
│ 原因       │ [站点改名                    ]                                │
│            │                        [重置此语言]  [保存]                    │
└────────────────────────────────────────────────────────────────────────────┘
```

- 每个字段三态：继承（显示默认值，灰色）/ 设置 / 清空（仅 short、unit、icon、plural）；三列“默认 / 覆盖 / 有效”可切换为紧凑模式。
- 复数编辑器：按该语言 `plural_categories` 生成分支行（另可加 `=0` 等精确分支），`#` 以徽标显示；可切换原始 ICU 文本；输入时调用 `POST /previews`（防抖 300 ms）显示样例与错误。
- 图标选择器：内置图标网格（来自 `GET /icons` 的 `builtin`）、已上传图标、上传按钮（客户端先检查 ≤ 256 KiB 与类型，服务端为准）。
- 保存：`PUT …/overrides/{locale}`，携带 `If-Match: "r<rev>"`（无覆盖时 `If-None-Match: *`）；412 时弹出“他人已修改”对话框，显示对方的值与本地草稿的差异，提供“载入最新后重新编辑”。
- 每种语言独立保存；有未保存修改时离开页面提示。
- `default_changed_since_override = true` 时在该语言列顶部提示“插件默认值已更新：旧 → 新”。
- 历史抽屉：时间线（操作、语言、前后差异、操作者、原因、导入链接），每条可“以此值填入草稿”。
- 退役键只读显示（可查看历史与覆盖值，可重置覆盖）；孤儿覆盖显示“键尚未登记”。

## 6. 安全设计

| 方面 | 措施 |
|---|---|
| 权限 | 后台路由全部 `terms.manage`（内核网关校验）；`get_icon` public 但只读、内容为重新编码的位图；`set_override` / `reset_override` 服务调用校验 `caller_scopes ∋ manage`；`register` 只接受 `caller_plugin = kernel`；`define` / `retire` 校验键首段 = 调用方 |
| 注入 | 值禁止 `<`、`>`、控制字符、双向控制符；渲染在 AST 层替换术语值（文本节点），ICU 结构无法被术语值注入；复数片段受限语法（只含文本与 `#`）；输出纯文本，HTML 转义由使用方负责；前端只以文本节点渲染 |
| SQL | 全部参数化（sqlx 编译期检查）；列表排序固定，无动态 ORDER BY；`q` 的 `%`/`_` 转义 |
| 文件 | 图标：魔数判定、尺寸与内存上限、超时、重新编码、去元数据、内容哈希命名、`nosniff` + `CSP default-src 'none'`；SVG 一律拒绝。导入：大小、条目数、JSON 深度上限；TOML/CSV 解析器有界；原文件只存 blob，不回显 |
| CSV | 导出防公式注入（`'` 前缀），导入对称还原 |
| 敏感数据 | 本插件不处理 passkey、邮箱、IP；历史与导入记录只含操作者用户 ID（purge 时置空）；审计 details 只含键、语言、前后值、原因 |
| 审计 | `terms.override_set`、`terms.override_reset`、`terms.import_applied`、`terms.icon_uploaded`、`terms.downgrade_accepted`（管理操作）；系统操作（登记、退役、bootstrap）写 `term_history`，不写审计 |
| 拒绝服务 | 写接口限流（§2.4）；`get_many` ≤ 1000；`render` 模板 / 输出 / 嵌套上限；快照构建防击穿锁；图标解码在阻塞线程池并限时 |
| 一致性攻击 | 旧版本副本无法回写旧默认值（semver 保护）；导入基线版本检查防止“预览后被他人改动”的静默覆盖 |

## 7. 性能设计

| 热点 | 设计 | 指标 |
|---|---|---|
| 页面渲染 / 插件取值 | 不经本插件：内核进程内快照 | — |
| `get_many`（100 键） | 版本主键查询 + 进程内快照（moka）；未命中 → Redis（zstd 解压约 1 ms）→ PG 构建 | p95 ≤ 5 ms（NFR-TERMS-001） |
| 快照构建 5000 键 | 1 页 5000 行，相关子查询走主键 / `(key, locale)` 主键；Rust 侧合并 | p95 ≤ 50 ms，体积 ≤ 1 MiB（NFR-TERMS-002） |
| `render` | 解析 + 格式化纯 CPU；模板 AST 进程内 LRU 缓存（键 = sha256(template)，1024 条） | p95 ≤ 1 ms（NFR-TERMS-003） |
| 启动登记 | hash 短路；变化时 UNNEST 批量写 | 无变化 < 20 ms；首次 2 万键 < 3 s |
| 多副本刷新 | 每次版本变化每语言构建一次（防击穿锁 + Redis 共享） | N 副本 × L 语言只构建 L 次 |
| 导入应用 5 万项 | 单事务，每批 1000 行 | < 5 s |

容量（NFR-TERMS-010）：2 万键 × 8 语言快照全部缓存约 8 MiB Redis；`term_history` 100 万行时按键查询走 `(key, id DESC)` 索引，< 5 ms。

## 9. 错误码表

| 错误码 | HTTP | 说明 |
|---|---|---|
| `terms.key_not_found` | 404 | 术语键不存在（未登记且无孤儿覆盖） |

| `terms.render_arg_invalid` | 422 | 参数类型不符（如 plural 参数不是数字） |

| `terms.import_parse_failed` | 422 | 导入文件无法解析（`details.line`、`details.column`） |

| 问题码 | 说明 |
|---|---|
| `terms.invalid_key` | 键格式错误或重复 |
| `terms.invalid_locale` | 语言标签不合法 |
| `terms.name_required` | 缺少名称（定义没有任何语言，或覆盖所在语言无默认名称且未给名称） |

| 2 | 登记数据 | 内核为**每个启用插件**传一项（含无 `[terms]` 的插件，`terms = []`），另加 `plugin_id = "kernel"` 一项承载 `kernel.site_name` | 否则无法区分“删除了全部术语”与“未传”；`kernel.site_name` 的默认值来自 `site.name` |
| 3 | 内核服务 | `ctx.plugins.list()` 的 `PluginInfo` 至少含 `id`、`version`、`enabled` | retire_sweep 的心跳来源 |
| 4 | 服务签名 | `ctx.terms` 正式签名见 §2.1；catalog 中 `set_override(key, locale, value)` 改为 `set_override(req)` | 语义不变（设置覆盖），参数扩展为 patch + 乐观锁 + 幂等 |
| 5 | 内核刷新 | 内核收到 `terms.updated` 后 `PUBLISH k:bus terms:<version>`（或各副本每 2 s 调 `version()`） | 同 HLD §7 风险项；内核 `GET /terms` 的 ETag 建议为 `"<version>-<locale>"` |
| 6 | 内核网关 | 所有 API 响应附带 `X-PT-Terms-Version: <version>` | 前端无需轮询即可发现术语变化；退化：前端 5 分钟校验 |
| 7 | 共享 crate | `crates/term-render` 的语法为 MF1 子集（§1.6），kernel/03 §13 “ICU MessageFormat”的描述需同步为该子集 | ICU4X 无稳定 MessageFormat |
| 8 | 清单规则 | plugin-api §4.2 `[frontend].routes` “须以 `/p/<plugin_id>/` 开头”应放宽为“`/p/<id>/` 或 `/admin/p/<id>/`” | 与 api.md §1 前端页面路径一致；search-meilisearch 已有同样用法 |
| 9 | 约定冲突 | api.md §11 写 `If-Match` 不匹配返回 412，而 error-codes.md 中 `kernel.conflict` 为 409 | 本插件按 409（与 SRS FR-TERMS-008 一致）；建议 api.md 统一 |
| 10 | 前端 SDK | `@pt-studio/slots` 的 `PluginApi` 增加 `tp()`、`useTermFamily()`、`<TermIcon>`，`t()` 支持 `|short`、`|unit` 后缀 | 由 web/slots 实现；行为见 §2.6 |
| 11 | 构建 | `xtask gen-icons`：从 `web/ui-kit` 图标集生成 `builtin_icons.txt` | 内置图标名校验 |
