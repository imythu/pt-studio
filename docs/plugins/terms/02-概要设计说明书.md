## 1. 设计目标与原则

1. **叫法与文案分离**：术语表只管“换一个站会改叫法”的概念；其余走 i18n（catalog/terms.md §1）。
2. **默认值属于插件，覆盖值属于站点**：插件升级只改默认值；管理员覆盖永不被登记覆盖。
3. **读路径不经过本插件**：高频取值由内核进程内快照完成；本插件负责数据真相、校验、版本、通知。
4. **一个版本号统治全部缓存**：任何改变有效值的写操作在同一事务内递增全局版本并发布 `terms.updated`。
5. **渲染只有一份实现**：内核与本插件共享渲染 crate，保证宿主接口与服务行为一致。
6. **安全默认**：术语值是纯文本；图标重新编码；ICU 片段结构受限。

## 2. 总体结构

### 2.1 位置

```
 plugin.toml [terms] ──► 内核加载器 ──register(all)──► terms 插件 ──► PG terms.*（默认、覆盖、历史、版本）
                                                       │    └──► Redis p:terms:snap:<locale>:<ver>
                                                       └── terms.updated（outbox）──► 内核各副本快照刷新
 前端 ──GET /api/kernel/v1/terms──► 内核快照 ◄──snapshot(locale)── terms 插件
 插件 ──宿主 terms.get/render──► 内核快照 + 共享渲染 crate
 notify / mcp ──ctx.terms.render──► terms 插件（或内核宿主接口）
 管理员 ──/api/p/terms/v1/…──► terms 插件（覆盖、导入导出、图标）
```

| 模块 | 职责 |
|---|---|
| `registry` | `register`（内核）、`define` / `retire`（属主插件）；校验、版本保护、退役 |
| `store` | 默认值、覆盖值、历史的读写；全局版本；事件发布 |
| `resolve` | 回退链与字段合并，生成有效值 |

## 4. 数据设计概要

| 实体 | 存储 |
|---|---|
| 键登记（属主、来源、分类、退役） | PG `terms.term_keys` |

## 5. 关键流程

### 5.1 启动登记

```
内核：加载全部清单 → terms.init() → ctx.terms.register(defs[全部启用插件]) → 其他插件 init
terms.register：
  require caller == kernel
  逐插件：比较 plugin_registrations（版本、定义哈希）
     新版本 ≥ 已记录版本 且 哈希不同 → upsert 默认值；本插件旧声明中有、新声明中没有的键 → 退役
     版本低于已记录 → 只刷新 last_registered_at（不改默认值）
     哈希相同 → 只刷新 last_registered_at
  有效值有变化 → registry_state.version += 1 → 发布 terms.updated → 提交
```

### 5.2 管理员覆盖

```
PUT /v1/terms/bonus.currency/overrides/zh-CN {name:"猫粮", unit:"颗"}  (If-Match: 3)
 → 校验（键存在且未退役、语言 ∈ site.locales、值合法）
 → UPSERT term_overrides（version 检查）→ INSERT term_history → version += 1
 → 发布 terms.updated{keys:["bonus.currency"], locale:"zh-CN", version}
 → audit.write(terms.override_set) → 提交
内核各副本：收到 terms.updated → ctx.terms.snapshot(zh-CN) → 替换本地快照
前端：下次请求 /api/kernel/v1/terms 时 ETag 变化 → 拉取新快照
```

### 5.3 快照

```
snapshot(locale): v = version()；GET snap:<locale>:<v> → 命中返回
  未命中：一条 SQL 取全部未退役键的默认值与覆盖值（chain 中的语言）→ resolve → 序列化 → SET EX ttl → 返回
```

### 5.4 导入

```
POST /v1/imports (file, mode, unknown, dry_run 默认 true)
 → 解析 → 逐项校验 → 与当前覆盖求差 → 保存 imports(status=previewed, plan) → 返回差异
POST /v1/imports/{id}/applications → 状态为 previewed 且当前版本仍等于预览时版本（否则重新计算差异）→ 单事务应用 → version += 1 → 一次事件 → status = applied
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| DD-TERMS-1 | 站点叫法存哪里 | 语言文件（NexusPHP/UNIT3D）/ 数据库 | **数据库**：默认值来自清单、覆盖值来自后台 | 升级不冲突；后台可改；可导入导出 |
| DD-TERMS-2 | 读路径 | 每次调用服务 / 内核快照 | **内核快照**（kernel/03 §13），本插件只提供 `snapshot` 与版本 | 每页渲染、每个插件取值都不跨服务调用 |
| DD-TERMS-3 | 回退粒度 | 整值回退 / 字段逐级回退 / “首个有名称的语言”内取字段 | **首个有名称的语言内取字段，图标独立回退** | 避免中文名配英文单位的混搭；图标与语言无关 |
| DD-TERMS-4 | 覆盖粒度 | 整值覆盖 / 字段级覆盖 | **字段级**，NULL = 继承，空串 = 显式清空 | 只改单位时名称仍随插件默认值改进 |
| DD-TERMS-5 | 站点间分享 | 无 / 导出导入 | **导出导入**（JSON/TOML/CSV）+ 静态配置 `bootstrap` | 预设“叫法包”（如古风等级名）可复用，替代 fork |
| DD-TERMS-6 | 滚动升级时旧副本回写旧默认值 | 后写者胜 / 按插件版本保护 | **按插件 semver 保护**：只接受 ≥ 已记录版本的定义 | 防止默认值在新旧副本间来回抖动 |
| DD-TERMS-7 | 插件移除后的键 | 立即删除 / 立即退役 / 延迟退役 | **延迟退役**（缺席 24 h），覆盖值永久保留 | 滚动升级期间短暂缺席不应抖动；重新启用无需重配 |
| DD-TERMS-8 | 复数表达 | 自定义语法 / ICU MessageFormat 片段 | **ICU 片段**，限定唯一参数 `count`、必须含 `other` | 与 catalog 约定一致；CLDR 复数类别覆盖各语言 |
| DD-TERMS-9 | 模板占位扩展 | 只支持 `{term:key}` / 扩展字段与复数 | 扩展 `|short`、`|unit`、`|plural(arg)`（需内核同步，§7） | 邮件、通知常需“120 颗猫粮”这类复数与单位 |
| DD-TERMS-10 | 图标存储与访问 | 外链 URL / SVG / 位图重新编码 | **位图重新编码为 WebP，内容哈希命名，本插件公开路由提供** | 外链有隐私与可用性问题；SVG 有 XSS 风险（kernel/03 §6.7 强制下载）；公开路由可长期缓存且同源满足 CSP |
| DD-TERMS-11 | 事件大小 | 总列全部键 / 通配 | 超过 500 键发 `["*"]` | 事件载荷 ≤ 64 KiB |
| DD-TERMS-12 | 动态键归属 | 管理员任意新建 / 只能由属主插件登记 | **只能由属主插件 `define`**；管理员只覆盖已登记键 | 键与实体生命周期一致（删除商品即退役其键） |

## 7. 对平台契约的新增

| 类别 | 新增项 | 说明 |
|---|---|---|
| 服务方法 | `ctx.terms.reset_override`、`define`、`retire`、`snapshot`、`version` | 见 LLD §2.1；`snapshot` 是内核“从 ctx.terms 拉取”快照（kernel/03 §13）的正式接口 |
| 宿主接口 | `pt:plugin/terms` 的 `term` 记录增加 `plural: option<string>`、`icon-url: option<string>` | 插件侧渲染复数、展示图标需要（plugin-api §2 当前只有 key/name/short-name/unit/icon） |
| 内核渲染语法 | kernel/03 §13 的模板占位扩展为 `{term:<key>}`、`{term:<key>|short}`、`{term:<key>|unit}`、`{term:<key>|plural(<arg>)}` | 与本插件 `render` 一致 |
| 共享 crate | `crates/term-render`（`pt-term-render`，MIT OR Apache-2.0）：占位展开 + ICU MessageFormat，由内核与 terms 共用 | 保证宿主接口与服务渲染一致（NFR-TERMS-011）；ICU 实现的许可证（ICU4X 为 Unicode-3.0）需加入 cargo-deny 允许列表 |
| 内核刷新机制（风险） | 内核订阅 `terms.updated` 使用单个消费组 `kernel.terms_cache`，按 Redis Streams 语义**每条消息只投递给一个副本**，其他副本不会刷新 | 建议内核改为：收到事件的副本再 `PUBLISH k:bus terms:<version>` 广播；或每个副本定期（2 s）调用 `ctx.terms.version()` 比较。本插件两种方式都支持 |
| 事件载荷 | `terms.updated` v1 增加 `version`（u64）；`keys` 允许 `["*"]`、`locale` 允许 `"*"` | 只增字段；需在 catalog/events.md 注明 |
| 清单 `[terms]` | 值结构支持 `plural` 字段（catalog/terms.md 已列，plugin-api §4.2 字段表只写了 name/short/unit/icon） | plugin-api §4.2 补 `plural` |
| 登记数据 | 内核调用 `register(defs)` 时每条定义附带 `plugin_id` 与 `plugin_version` | 版本保护（DD-TERMS-6） |
| MCP | `get_term` 已登记，无新增 | |
| Redis | `p:terms:` 下子键 `snap:<locale>:<version>` | 建议补入 redis-keys.md §4 |
| 错误码 | LLD §9 的 `terms.*` | |
