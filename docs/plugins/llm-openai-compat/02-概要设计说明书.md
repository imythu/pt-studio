| 类别 | 内容 |
|---|---|
| 原则 | 能力显式声明（兼容服务能力差异大，不靠猜测）；结构化输出逐级降级 + 本地校验；与 llm-claude 共用 quota / scrub / idem / usage 模块（共享 crate `pt-llm-common`） |
| 模块 | `mapper`（接口 ↔ Chat Completions）、`structured`（三级降级）、`embed`（批处理）、`client`、`probe`（能力探测：发送最小请求测试 tools 与 response_format 是否被接受）、共享模块 |
| 服务 | `ctx.llm`：`complete`、`embed`、`models` |
| 能力 | Native；`http_outbound = ["config:profiles.*.base_url"]`（⊕ `config:` 声明，同 metadata-douban 02 §7；允许内网主机，因为由站点显式配置） |
| 历史回放 | Chat Completions 无思考块绑定；`provider_blob` 保存原始 `message`（含 `tool_calls`），回放时原样使用 |
| 设计决策 | DD-LLMO-1：不自动探测能力于每次调用（成本高），只在启动与管理员触发时探测，结果与声明不一致时告警；DD-LLMO-2：嵌入与对话分 profile（常见部署是不同服务）；DD-LLMO-3：本地模型的 token 统计可能缺失，估算值标记 estimated，不计入严格配额（配额按估算执行） |
| 平台契约新增 | `config:` 出站主机声明；共享 crate `pt-llm-common` |
| 权限点 | `llm-openai-compat.manage`（已登记） |

需求追溯：FR-001～003、006 → mapper；FR-004 → structured；FR-005 → embed；FR-007 → client；FR-008、009 → 共享模块；FR-010 → 能力声明。
