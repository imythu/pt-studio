## 1. 模块详细设计

### 1.1 mapper：请求

```json
POST {base_url}/v1/chat/completions
Authorization: Bearer <api_key>（为空时不发送）
{ "model": "<profile.model>",
  "max_tokens": <min(req, profile)>,
  "temperature": <effort 映射>,
  "messages": [ { "role": "system", "content": "<system + UNTRUSTED_NOTE>" },
                { "role": "user", "content": "<text 与 <user_content> 包裹的 untrusted 拼接>" },
                { "role": "assistant", "content": null, "tool_calls": [ … ] },     // 来自 provider_blob 原样回放
                { "role": "tool", "tool_call_id": "call_1", "content": "…" } ],
  "tools": [ { "type": "function", "function": { "name": "…", "description": "…", "parameters": { … } } } ],
  "tool_choice": "auto",
  "response_format": { "type": "json_schema", "json_schema": { "name": "output", "schema": { … }, "strict": true } } }
```

每个 `tool-result` 映射为一条 `role: tool` 消息。

### 1.2 mapper：响应

`choices[0].message`：`content` → text；`tool_calls[]` → tool-calls（`function.arguments` 为 JSON 字符串，解析失败 → 视为空并记录 warning）；`finish_reason`：`stop` → end-turn、`tool_calls` → tool-use、`length` → max-tokens、`content_filter` → refusal、其他 → other；`provider_blob = json(choices[0].message)`；`usage.prompt_tokens / completion_tokens`（缺失时估算：字符数 / 3，标记 estimated）。

### 1.3 structured

```
caps 含 json_schema → response_format json_schema（strict）
否则 caps 含 json_object → response_format {type: json_object}；system 末尾附加 “只输出符合以下 JSON Schema 的 JSON：<schema>”
否则 → 只附加提示词
解析：去除 ``` 代码围栏 → serde_json → jsonschema 校验
失败 → 追加一条 user 消息（“上一次输出不符合 schema：<错误摘要>，请只输出合法 JSON”）重试 1 次 → 仍失败 structured_invalid
```

### 1.4 embed

```
POST {embed_profile.base_url}/v1/embeddings  { "model": "<model>", "input": [ "query: …" | "…" ] }
分批 128；响应 data[].embedding（按 index 排序）；校验每个向量长度 = profile.dims，不一致 → upstream_error（防止配置错误污染索引）
```

### 1.5 probe

`POST /v1/admin/probe {profile}`：① 最小对话；② 带一个 dummy 工具请求；③ 带 json_schema 的请求；记录哪些被接受（HTTP 400 视为不支持）；结果与声明对比，返回建议的 `caps`。

## 2. 接口详细设计

实现 `pt:llm@0.1.0`；`models()` 返回各 profile（`context_tokens` 来自配置 `context_tokens`，缺省 32768）。

## 4. 配置项

见 SRS §4；额外：`temperature_map`、`query_prefix`（嵌入）、`allow_extra_body`（false）。

## 6. 安全设计

内网 base_url 只能由 site.toml 声明；key 不进日志；其余同 llm-claude。

## 8. 可观测性

`pt_plugin_llm_openai_compat_requests_total{profile,status}`、`…_tokens_total{profile,kind,estimated}`、`…_structured_retries_total`。
