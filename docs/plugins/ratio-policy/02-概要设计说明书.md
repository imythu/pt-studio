## 1. 设计目标与原则

1. **只管自己的限制**：通过 identity 的带来源限制施加 / 解除，绝不触碰其他来源（NexusPHP 共用字段的改进）。
2. **状态机清晰**：`ok → warned → restricted → (banned)`，恢复时逆向解除。
3. **钩子极简**：钩子只读本插件的状态表，不计算分享率。
4. **增量 + 全量**：与 levels 相同的脏用户机制。

## 2. 总体结构

```
traffic.settled ─► dirty ─► incr_evaluate(15 min) ─┐
cron daily_evaluate ───────────────────────────────┤► evaluator ─► users.apply/lift_restriction
                                                    │             events ratio.*、notify
torrent.before_download / invite.before_issue ─► 读 states 表
```

| 模块 | 职责 |
|---|---|
| `policy` | 要求表、减免、豁免判定（纯函数） |
| `metrics` | 读视图：uploaded、downloaded、完成数、做种中完成数 |
| `evaluator` | 状态机 |
| `hooks` | 钩子处理 |

## 4. 数据设计概要

`states`（每用户：状态、警告开始与截止、限制开始、手动标记、豁免截止）、`dirty_users`、`history`（按月分区）。

## 5. 关键流程

```
eval(u, m):
  required = policy::required(m.downloaded, m.seeding_ratio)
  exempt = policy::exempt(u, m, state.exempt_until)
  ok = exempt || m.ratio >= required
  match state:
    ok        & !ok → warned(deadline = now + warning_days)；publish ratio.warned；通知
    warned    & ok  → ok；publish ratio.warning_lifted
    warned    & !ok & now ≥ deadline → apply_restriction(leech_disabled)；restricted；publish ratio.restricted
    restricted & ok → lift_restriction(leech_disabled)；ok；publish ratio.restriction_lifted
    restricted & !ok & ban_after_days > 0 & now ≥ restricted_at + ban_after_days → apply_restriction(banned)；banned
    banned    & ok  → lift_restriction(None)（两种都解除）；ok
  手动警告（manual = true）：不因 ok 自动解除，到期按普通警告处理（期满时若 ok 则解除）
```

增量评估只处理状态为 warned / restricted / banned 的脏用户及新增下载量跨过档位的脏用户——实现上对所有脏用户执行 `eval`，计算量小。

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-RATIO-1 | 用计入量还是原始量 | 计入量（含促销倍率）：与站点公示的分享率一致 |
| DD-RATIO-2 | 做种减免数据 | 用 `v_snatch`（`completed_at IS NOT NULL` 为完成数；“做种中”需要 accounting 提供 `is_seeding`，视图目前无此列 → §7） |
| DD-RATIO-3 | 下载限制方式 | identity 限制（同时作用于 tracker 与 .torrent 下载）；钩子只用于警告期的可选限制 |
| DD-RATIO-4 | 员工 | identity 拒绝插件限制员工；本插件对员工只记录状态、不施加限制 |
