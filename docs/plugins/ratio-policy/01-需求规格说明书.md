## 1. 引言

### 1.1 目的

定义分享率策略插件 `ratio-policy` 的需求：按下载量分档的最低分享率、分享率警告（Ratio Watch）、禁止下载、后续封禁，以及新用户豁免。

### 1.2 范围

包含：要求分享率表、做种减免（Gazelle 风格）、新用户豁免、警告与期限、限制下载（经 identity 限制机制）、可选的进一步封禁、恢复后自动解除、管理员手动警告 / 解除 / 豁免、状态查询、MCP。

不包含：H&R（hnr）、等级（levels）、作弊（anticheat）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 要求分享率（required） | 按下载量所在档位查表得到的最低分享率 |
| 做种减免 | 按“当前做种的已完成种子比例”降低要求分享率（Gazelle `required ratio × (1 − seeding%)`） |
| 警告期 | 低于要求后给予的补救时间（默认 14 天） |
| 限制 | 期满仍不达标时由本插件施加的 `leech_disabled` 限制 |

### 1.4 参考资料

- docs/platform/、docs/plugins/identity/（`apply_restriction` / `lift_restriction`）、docs/plugins/accounting/（`v_user_totals`、`v_snatch`）
- Gazelle/OPS：Required Ratio 表（按下载量 0～5 GB、5～10 GB … > 100 GB 递增）、按做种比例减免、Ratio Watch（2 周）、到期禁止下载
- NexusPHP：低分享率警告与自动禁止下载（`leechwarn`、`leechwarnuntil`），连续警告封号
- UNIT3D：`min_ratio` 配置与 `ratio watch` 类命令

## 2. 总体描述

### 2.1 插件定位

- WASM，ID `ratio-policy`，缩写 `RATIO`；提供 `ctx.ratio`。
- 依赖：`ctx.users`（`apply_restriction`、`lift_restriction`、`get`）；可选 `ctx.levels`（豁免等级）、`ctx.notify`。
- 只读视图：`accounting.v_user_totals`、`accounting.v_snatch`、`identity.v_user_public`。
- 处理钩子：`torrent.before_download`（警告期内可选限制）、`invite.before_issue`（警告中不能发邀）、`shop.before_purchase`（可选）。

### 2.2 用户角色与使用场景

普通用户：查看自己的分享率、要求、距离要求还差多少上传量、警告期限。管理员：配置要求表、豁免、手动警告 / 解除 / 豁免。

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle/OPS | Required Ratio 按下载量分档（0～5 GB 为 0，之后 0.15～0.60），按“做种的已完成种子比例”减免；低于要求进入 2 周 Ratio Watch，期满禁止下载 | 公平、对保种者友好 | 表格写死；计算依赖每日脚本 | **采纳**分档 + 做种减免 + 警告期；**改进**：表格可配置、增量评估 |
| NexusPHP | 分享率低于阈值发警告、设置 `leechwarnuntil`，到期禁止下载；多次警告封号 | 操作简单 | 直接改用户字段，与其他禁止来源冲突（自动任务可能解除管理员的限制）；豁免逻辑写死在等级比较中 | **采纳**多级处置；**改进**：通过 identity 的“带来源的限制”，本插件只解除自己施加的限制 |

### 2.4 约束与假设

分享率按 accounting 的计入量（含倍率）计算；数据分钟级最终一致。规模 30 万用户。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-RATIO-001 | 要求表 | 管理员配置按下载量分档的要求分享率（档位 ≤ 20），默认 Gazelle 风格表 | P0 | 查表结果正确 |
| FR-RATIO-002 | 做种减免 | 可选：`required = table × (1 − seeding_ratio × reduction)`，`seeding_ratio` = 当前做种的已完成种子 / 已完成种子总数 | P1 | 减免计算与公式一致 |
| FR-RATIO-003 | 豁免 | 下载量 < `exempt_below_bytes`、注册天数 < `grace_days`、指定等级、管理员单独豁免（可设期限）不受约束 | P0 | 豁免用户不会被警告 |
| FR-RATIO-004 | 警告 | 分享率 < 要求且无豁免 → 进入警告，期限 `warning_days`（默认 14）；发布 `ratio.warned`；通知 | P0 | 警告记录与事件 |
| FR-RATIO-005 | 解除警告 | 警告期内分享率恢复到 ≥ 要求 → 解除；发布 `ratio.warning_lifted` | P0 | 恢复后 15 分钟内解除 |
| FR-RATIO-006 | 限制下载 | 期满仍不达标 → `apply_restriction(kind = leech_disabled, reason_code = "ratio.below_required")` | P0 | identity 状态变为 leech_disabled |
| FR-RATIO-007 | 自动恢复 | 被限制后分享率恢复 ≥ 要求 → `lift_restriction`（只解除本插件来源） | P0 | 管理员施加的其他限制不受影响 |
| FR-RATIO-008 | 进一步处置 | 可选：限制持续 `ban_after_days` 仍未恢复 → `apply_restriction(kind = banned)`；默认关闭 | P2 | 默认不封禁 |
| FR-RATIO-009 | 警告期下载限制 | 可选：警告期内 `torrent.before_download` 拒绝下载新种子（已下载过的除外） | P2 | 开启后警告用户下载新种子被拒 |
| FR-RATIO-010 | 发邀限制 | 警告或限制中的用户 `invite.before_issue` 被拒 | P1 | 错误码 `ratio-policy.restricted` |
| FR-RATIO-011 | 状态查询 | `status(user)`：ratio、required、差额上传量、警告期限、can_download | P0 | 与计算一致 |
| FR-RATIO-012 | 评估调度 | 订阅 `traffic.settled` 标记脏用户，每 15 分钟评估；每日全量 | P0 | 恢复与警告及时 |
| FR-RATIO-013 | 管理操作 | 手动警告（自定义期限）、解除警告、豁免、解除本插件限制 | P1 | 审计记录 |
| FR-RATIO-014 | 历史 | 警告 / 限制 / 解除历史 | P1 | 可查询 |
| FR-RATIO-015 | MCP | `get_my_ratio_status`（已登记） | P2 | |
| FR-RATIO-016 | 用户删除 | 清理数据 | P1 | |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-RATIO-001 | 性能 | 全量评估 30 万用户 | ≤ 10 分钟 |
| NFR-RATIO-002 | 性能 | 钩子 `torrent.before_download` | p99 < 10 ms（只读本插件表 + kv） |
| NFR-RATIO-003 | 可靠性 | 幂等 | 重复评估不重复施加 / 解除限制、不重复通知 |
| NFR-RATIO-004 | 正确性 | 限制来源隔离 | 只解除本插件施加的限制 |

## 5. 可配置项与站点术语

运行时设置：`table`（档位数组 `[{min_downloaded_bytes, required}]`）、`seeding_reduction`（0～1，默认 1.0 = Gazelle 全额减免；0 = 关闭）、`exempt_below_bytes`（5 GiB）、`grace_days`（7）、`exempt_class_ids`（[]）、`warning_days`（14）、`ban_after_days`（0 = 关闭）、`block_new_downloads_during_warning`（false）、`notify`（true）。

默认表（Gazelle 风格，GiB）：0～5: 0.00；5～10: 0.15；10～20: 0.20；20～30: 0.30；30～40: 0.40；40～50: 0.50；50～60: 0.60；≥ 60: 0.60。

术语：`ratio-policy.warning`（已登记）；新增 `ratio-policy.required`（要求分享率）、`ratio-policy.restricted`（因分享率被限制）。

## 6. 外部接口需求概述

服务 `ctx.ratio.status`；事件 `ratio.warned`、`ratio.warning_lifted`、`ratio.restricted`、`ratio.restriction_lifted`；订阅 `traffic.settled`、`user.deleted`；钩子处理 `torrent.before_download`、`invite.before_issue`；HTTP `/api/p/ratio-policy/v1/*`；插槽 `user.profile.stats`、`home.announcements`（自己的警告横幅）；MCP `get_my_ratio_status`。
