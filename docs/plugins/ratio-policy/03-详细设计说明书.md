## 1. 模块详细设计

### 1.1 policy（纯函数）

```rust
fn required(downloaded: u64, seeding_ratio: f64, s: &Settings) -> f64 {
    let base = s.table.iter().rev().find(|t| downloaded >= t.min_downloaded_bytes).map(|t| t.required).unwrap_or(0.0);
    let r = base * (1.0 - s.seeding_reduction * seeding_ratio.clamp(0.0, 1.0));
    (r * 1000.0).round() / 1000.0                      // 保留 3 位，避免浮点抖动
}
fn ratio(up: u64, down: u64) -> f64 { if down == 0 { f64::INFINITY } else { up as f64 / down as f64 } }
fn exempt(u, m, st, s) -> Option<&'static str> {
    if st.exempt_until > now { return Some("manual") }
    if m.downloaded < s.exempt_below_bytes { return Some("low_download") }
    if now - u.created_at < s.grace_days days { return Some("grace") }
    if s.exempt_class_ids.contains(u.class_id) { return Some("class") }
    None
}
fn upload_needed(up, down, required) -> u64 = max(0, ceil(required × down) − up)
```

`seeding_ratio = seeding_completed_count / completed_count`（completed_count = 0 时为 0）。

校验：`table` 按 `min_downloaded_bytes` 严格递增、第一档为 0、`required ∈ [0, 10]`、档位 ≤ 20；`seeding_reduction ∈ [0, 1]`。

### 1.2 metrics

```sql
SELECT u.id, u.class_id, u.created_at, t.uploaded, t.downloaded,
       t.completed_count, t.seeding_completed_count            -- 依赖 02 §7 的视图扩展
FROM identity.v_user_public u LEFT JOIN accounting.v_user_totals t ON t.user_id = u.id
WHERE u.id = ANY($1);
```

视图扩展合入前的降级：`seeding_reduction` 视为 0（不减免），后台提示“做种减免需要 accounting 视图支持”。

### 1.3 evaluator

见 HLD §5。实现细节：

- 每用户 `SELECT … FROM states WHERE user_id FOR UPDATE`（不存在则插入 ok）。
- `apply_restriction` 幂等键：`ratio:r:<uid>:<restricted_seq>`（每次进入 restricted 时 `restricted_seq + 1`）；`lift_restriction` 幂等键 `ratio:l:<uid>:<restricted_seq>`。
- identity 返回 `kernel.forbidden`（员工）→ 状态记为 `restricted_skipped`（展示用），不重试。
- 通知幂等键：`ratio:n:<uid>:<event_type>:<seq>`。
- 每次状态变化写 `history`。

**全量评估** `daily_evaluate`（tx manual）：键集分页 2000；同时处理警告到期。**增量** `incr_evaluate`：同 levels 03 §1.4 的 `dirty_users` 出队。

### 1.4 hooks

```
torrent.before_download(input{user_id, torrent_id, …}):
  if !settings.block_new_downloads_during_warning: allow
  st = states[user_id]；if st.state != warned: allow
  if kv.get("dl:<uid>:<tid>")（已下载过，见下）: allow
  deny("ratio-policy.download_restricted", "分享率警告期间不能下载新种子")
```

“已下载过”的判断需要知道用户是否下载过该种子：订阅 `torrent.downloaded` 会产生大量写入。改为查询 `accounting.v_snatch`（`user_id, torrent_id` 主键查询）——视图查询在钩子中允许（只读 SQL），p99 < 5 ms。kv 不使用。

```
invite.before_issue(input{inviter_id}):
  st = states[inviter_id]；st.state ∈ {warned, restricted, banned} → deny("ratio-policy.restricted", …)
```

### 1.5 admin

| 操作 | 实现 |
|---|---|
| 手动警告 | `state = warned, manual = true, deadline = 请求值`；通知 |
| 解除 | warned → ok；restricted / banned → lift_restriction + ok；写审计 |
| 豁免 | `exempt_until = 请求值`；若当前 warned / restricted 则立即解除 |

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:ratio@0.1.0`）

```wit
package pt:ratio@0.1.0;

interface ratio {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  enum ratio-state { ok, warned, restricted, banned }
  record ratio-status {
    ratio: option<f64>,            // none = 无限（未下载）
    required: f64,
    upload-needed: u64,
    state: ratio-state,
    warned-until: option<timestamp-ms>,
    exempt-reason: option<string>,
    can-download: bool,
  }

  status: func(user: user-id) -> result<ratio-status, plugin-error>;
  exempt: func(user: user-id, until: timestamp-ms, reason: string, idempotency-key: string) -> result<_, plugin-error>;
}
```

目录概要签名 `{ratio, required, warned_until, can_download}` 保留，新增字段只增不删。`can_download = state ∉ {restricted, banned}`（不反映其他来源的限制；完整判断请查询 identity）。

### 2.2 事件载荷（版本 1）

| 事件 | 字段 |
|---|---|
| `ratio.warned` | `user_id, ratio, required, deadline, manual` |
| `ratio.warning_lifted` | `user_id, ratio, cause(recovered/manual/exempt)` |
| `ratio.restricted` | `user_id, ratio, required, kind(leech_disabled/banned)` |
| `ratio.restriction_lifted` | `user_id, ratio, cause` |

`ratio` 为数值（未下载时为 null）。

### 2.3 HTTP API

**GET `/v1/me`** → `{ "ratio": 0.42, "required": 0.3, "upload_needed": 0, "state": "ok", "warned_until": null, "exempt_reason": null, "can_download": true, "table": [...], "seeding_reduction_applied": 0.35 }`

**POST `/v1/admin/users/{id}/warn`** `{ "deadline": "2026-10-20T00:00:00Z", "reason": "…" }` → 204；**POST `/lift`** `{ "reason": "…" }` → 204；**POST `/exempt`** `{ "until": "…", "reason": "…" }` → 204。均需 `ratio-policy.warnings.moderate`，写审计。

**GET `/v1/admin/warned?state=warned&cursor=`** → 列表（用户、分享率、要求、截止时间）。

### 2.4 MCP 工具

`get_my_ratio_status`：出参同 GET /me（不含 table）。

## 3. 数据库设计（schema `ratio_policy`）

```sql
CREATE TABLE ratio_policy.states (
    user_id          bigint PRIMARY KEY,
    state            text NOT NULL DEFAULT 'ok' CHECK (state IN ('ok','warned','restricted','banned','restricted_skipped')),
    manual           boolean NOT NULL DEFAULT false,
    warned_at        timestamptz,
    deadline         timestamptz,
    restricted_at    timestamptz,
    restricted_seq   integer NOT NULL DEFAULT 0,
    exempt_until     timestamptz,
    exempt_reason    text,
    last_ratio       double precision,
    last_required    double precision,
    evaluated_at     timestamptz,
    updated_at       timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX states_active_idx ON ratio_policy.states (state) WHERE state <> 'ok';
CREATE INDEX states_deadline_idx ON ratio_policy.states (deadline) WHERE state = 'warned';

CREATE TABLE ratio_policy.dirty_users (user_id bigint PRIMARY KEY, since timestamptz NOT NULL);

CREATE TABLE ratio_policy.history (
    id        bigint GENERATED ALWAYS AS IDENTITY,
    at        timestamptz NOT NULL DEFAULT now(),
    user_id   bigint NOT NULL,
    from_state text NOT NULL,
    to_state  text NOT NULL,
    ratio     double precision,
    required  double precision,
    actor     text NOT NULL,
    reason    text NOT NULL DEFAULT '',
    PRIMARY KEY (at, id)
) PARTITION BY RANGE (at);
CREATE INDEX history_user_idx ON ratio_policy.history (user_id, at DESC);
```

## 4. 配置项

见 SRS §5。清单要点：`requires = ["ctx.users@^0.1"]`、`optional_requires = ["ctx.notify@^0.1"]`、`publishes = ["ratio.warned","ratio.warning_lifted","ratio.restricted","ratio.restriction_lifted"]`、`[[hooks]] torrent.before_download priority 30`、`invite.before_issue priority 30`、订阅 `on_traffic_settled`、`on_user_deleted`、cron 三项、`history` 按月分区保留 24 个月。

## 5. 前端设计

个人页显示分享率、要求、差额；警告期间首页横幅（倒计时 + “还需上传 X”）；后台：要求表编辑器（档位表格）、警告列表、用户详情（状态历史）。

## 6. 安全设计

只解除自己来源的限制；管理操作需权限并写审计；钩子只读，不泄露他人信息。

## 7. 性能设计

全量 150 批 × 2000；钩子一次主键查询（必要时再一次 `v_snatch` 主键查询）。

## 8. 可观测性

`pt_plugin_ratio_policy_transitions_total{from,to}`、`pt_plugin_ratio_policy_warned`（gauge）、`pt_plugin_ratio_policy_restricted`（gauge）、`pt_plugin_ratio_policy_hook_denied_total{hook}`、`pt_plugin_ratio_policy_evaluate_seconds{mode}`。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `ratio-policy.download_restricted` | 403 | 分享率不足禁止下载（已登记） |
| `ratio-policy.restricted` | 403 | 处于警告或限制中，不能执行该操作 |
| `ratio-policy.table_invalid` | 422 | 要求表校验失败 |
| `ratio-policy.not_warned` | 409 | 解除操作时用户不在警告 / 限制中 |
