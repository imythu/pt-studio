## 1. 引言

### 1.1 目的

定义求种 / 悬赏插件 `requests` 的需求：用户发布求种并附悬赏，其他用户追加悬赏、应求（提交已发布的种子），求种者确认后悬赏发放给应求者。

### 1.2 范围

包含：发布求种（资源类型、字段要求、描述）、悬赏（币种、最低额、托管）、追加悬赏、应求、确认 / 驳回、自动确认、过期退款、撤回、投票（“我也想要”）、与资源类型字段对接（结构化要求）、搜索贡献、评论（comments 目标 `request`）、通知。

不包含：保种任务（`requests.keep_seeding_task` 术语已登记，本期不实现，见 02 §6）。

### 1.3 参考资料

- Gazelle/OPS：requests（bounty 以上传量计、多人追加、填充时校验格式要求、填充者获得全部悬赏、可被撤销填充）
- UNIT3D：requests（BON 悬赏、claim 认领、approve / reject fill）
- NexusPHP：求种（魔力值悬赏、应求、确认）

## 2. 总体描述

WASM，ID `requests`，缩写 `REQ`；提供 `ctx.requests`；拥有钩子 `request.before_create`；处理 `torrent.before_delete`（应求种子被删除前的提示）与 `comment.before_create`（已关闭求种的评论策略）；搜索贡献者（`requests` 索引）。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| Gazelle | 悬赏为上传量；投票即追加悬赏；填充时校验格式与介质要求；填充可被撤销（悬赏退回给填充者之前的状态） | 结构化要求、激励强 | 悬赏用上传量会扰乱分享率体系 | **采纳**结构化要求、多人追加、撤销填充；**改进**：悬赏用虚拟货币（ledger），不影响分享率 |
| UNIT3D | 认领（claim）防止重复工作；BON 悬赏；求种者批准填充 | 认领机制 | 认领后长期不完成会占位 | **采纳**认领（带过期） |
| NexusPHP | 魔力值悬赏、应求、确认 | 简单 | 求种者不确认则悬赏悬而未决 | **改进**：自动确认期限 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-REQ-001 | 发布 | 资源类型、标题、描述、结构化要求（按类型插件字段，如分辨率 ≥ 1080p、片源 ∈ {BluRay, Remux}）、外部 ID（可选）、初始悬赏 | P0 | |
| FR-REQ-002 | 悬赏托管 | 悬赏从用户转入系统托管（ledger，原因 `requests.bounty_escrow`）；最低悬赏可配置 | P0 | |
| FR-REQ-003 | 追加悬赏 | 其他用户追加（每人每求种可多次），记录每笔贡献 | P0 | |
| FR-REQ-004 | 投票 | “我也想要”（不出钱）计数 | P2 | |
| FR-REQ-005 | 认领 | 用户认领求种（声明正在制作），认领有效期默认 72 小时，期间其他人仍可应求 | P2 | |
| FR-REQ-006 | 应求 | 提交已发布且已审核的种子 ID；校验类型与结构化要求；同一时刻只有一个待确认的应求 | P0 | |
| FR-REQ-007 | 确认 | 求种者确认 → 悬赏全额发放给应求者（ledger 系统发行，原因 `requests.bounty_payout`）；状态 filled | P0 | |
| FR-REQ-008 | 驳回 | 求种者或版主驳回应求（原因）→ 回到 open | P0 | |
| FR-REQ-009 | 自动确认 | 应求后 `auto_confirm_days`（默认 7）内无操作 → 自动确认 | P1 | |
| FR-REQ-010 | 撤销填充 | 版主在填充后 `revoke_days`（默认 14）内撤销（种子不符或被删除）→ 收回发放（ledger 冲正，余额不足则记录欠款）→ 回到 open | P2 | |
| FR-REQ-011 | 过期 | 求种 `expire_days`（默认 90）无人应求 → closed（expired），全部悬赏退回贡献者 | P0 | |
| FR-REQ-012 | 撤回 | 求种者在无待确认应求时撤回求种 → 全部退回；贡献者撤回自己的追加（同条件）→ 退回本人那部分 | P1 | |
| FR-REQ-013 | 抽成 | 可选：发放时抽成 `fee_permille`（默认 0），回收不发行 | P2 | |
| FR-REQ-014 | 发布钩子 | `request.before_create`（levels：等级要求；type-*：要求合法性） | P0 | |
| FR-REQ-015 | 搜索 | requests 索引：标题、类型、状态、悬赏总额、要求字段 | P1 | |
| FR-REQ-016 | 列表 | 按状态、类型、悬赏排序、最新 | P0 | |
| FR-REQ-017 | 通知 | 应求、确认、驳回、过期、撤销时通知相关方 | P1 | |
| FR-REQ-018 | 评论策略 | 已关闭求种是否允许评论（默认不允许） | P2 | |
| FR-REQ-019 | 种子删除 | 订阅 `torrent.deleted`：待确认的应求自动驳回；已填充的进入“待复核”（版主决定是否撤销） | P1 | |
| FR-REQ-020 | MCP | `list_requests`（读）、`create_request`（写，确认） | P2 | |
| FR-REQ-021 | 用户删除 | 求种者被删除：open 的求种保留（悬赏仍有效），确认权转给版主；贡献者被删除：其贡献保留 | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-REQ-001 | 资金一致 | 托管余额 = Σ 有效贡献 − 已发放 − 已退回；每日对账，偏差告警 |
| NFR-REQ-002 | 幂等 | 所有 ledger 调用使用确定性幂等键 |
| NFR-REQ-003 | 列表性能 | p99 < 50 ms |

## 5. 可配置项与站点术语

`currency`（bonus）、`min_bounty`（1000）、`min_contribution`（100）、`auto_confirm_days`（7）、`expire_days`（90）、`revoke_days`（14）、`fee_permille`（0）、`claim_hours`（72）、`comment_on_closed`（false）。术语：`requests.name`、`requests.bounty`（已登记）；新增 `requests.status.<status>`、`requests.claim`。

## 6. 外部接口需求概述

服务 `ctx.requests`（`get`、`fill`；⊕ `list_open_by_type`）；事件 `request.created`、`request.bounty_added`、`request.filled`、`request.closed`（已登记），新增 `request.fill_submitted`、`request.fill_rejected`、`request.fill_revoked`；钩子 `request.before_create`；HTTP `/api/p/requests/v1/*`；插槽 `nav.main`、`home.widgets`、`request.detail.sidebar`、`torrent.detail.sidebar`（“此种子满足了求种 X”）；MCP 两项。
