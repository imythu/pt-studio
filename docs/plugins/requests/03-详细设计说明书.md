## 1. 模块详细设计

### 1.1 发布

```
create(u, req{type_id, title, description_md, external_ids{}, requirements: [predicate], initial_bounty}, idem):
  rbac requests.create；initial_bounty ≥ min_bounty
  requirements：每个谓词的 field 必须是该类型 field_schema 中的字段（经 GET /api/p/torrent/v1/content-types 缓存的 schema，kv 缓存 10 分钟）
  hooks.run("request.before_create", {user_id, type_id, title, bounty: initial_bounty, currency}) → modify.title
  INSERT requests(state = 'open', expires_at = now + expire_days)
  contribute(u, request, initial_bounty, idem + ":c0")    // 同一事务内插入 pending 贡献并调度
  publish request.created
  // 初始贡献在 bounty_step 中失败（余额不足、钩子拒绝）时：求种自动关闭（closed, reason = withdrawn），
  // 不发布 request.bounty_added；前端在“发布中”状态轮询后提示失败原因
  // 为减少这种情况，发布前先做一次 ledger.balance 预检（不保证），不足直接返回 422 ledger.insufficient_balance
```

描述经 `pt-markup` 渲染。外部 ID（如 IMDb）可用于“已有种子”提示：发布前查询 search 的 torrents 索引（`movie_imdb_id = …`），在前端提示“可能已有资源”。

### 1.2 bounty

```
contribute(u, r, amount, idem):
  r.state == open（或 fill_pending）；amount ≥ min_contribution
  c = INSERT contributions(request_id, user_id, amount, state = 'pending') ；jobs.schedule_once("bounty_step", now, {op: "escrow", id: c.id}, dedupe = "c:" + c.id)
  return c.id（前端轮询贡献状态，或 Prefer: wait=3）

bounty_step（tx manual）:
  match op:
    escrow(c):  c.state == pending → ledger.transfer({currency, from: c.user, to: None, amount, reason: "requests.bounty_escrow",
                                                      memo: "request:<rid>", idempotency_key: "req:c:<c.id>"})
                ok → c.state = escrowed；UPDATE requests SET bounty_total += amount；publish request.bounty_added
                insufficient / hook deny → c.state = failed（error_code）
    payout(f):  total = Σ escrowed of r；fee = total × fee_permille / 1000；pay = total − fee
                ledger.transfer({from: None, to: f.filler, amount: pay, reason: "requests.bounty_payout", idempotency_key: "req:p:<f.id>"})
                ok → contributions(escrowed) → paid（paid_fill_id = f.id）；f.payout_entry = entry；r.state = filled
                fee 部分不发行（已在托管时回收）
    refund(c):  ledger.transfer({from: None, to: c.user, amount: c.amount, reason: "requests.bounty_refund", idempotency_key: "req:r:<c.id>"})
                ok → c.state = refunded；全部贡献终态 → r.state = closed
    revoke(f):  ledger.reverse(f.payout_entry, "requests.fill_revoked")
                ok → contributions(paid by f) → escrowed；r.state = open；f.state = revoked
                insufficient → f.state = revoke_debt（版主后台处理：手工调整或放弃）
  可重试错误 → 重新调度（退避，≤ 10 次）
```

### 1.3 fills

```
submit_fill(u, r, torrent_id, idem):
  r.state == open；rbac requests.fill；u ≠ r.user_id（可配置是否允许自己应求，默认否）
  t = ctx.torrents.get(torrent_id)；status == approved；type_id == r.type_id
  f = v_torrent_fields[torrent_id].fields；ok = pt_predicate::all(r.requirements, f)
  !ok && !rbac(u, requests.moderate) → requests.requirements_not_met{failed: [...]}
  INSERT fills(state = 'pending', auto_confirm_at = now + auto_confirm_days)；r.state = fill_pending
  publish request.fill_submitted；notify 求种者
confirm(by, f)：by == r.user_id 或 requests.moderate；f.state = confirmed；调度 payout
reject(by, f, reason)：f.state = rejected；r.state = open；publish request.fill_rejected；notify 应求者
auto_confirm（cron）：f.state = pending 且 auto_confirm_at ≤ now → confirm(by = system)
revoke(mod, f, reason)：f.state == paid_out 且 now − confirmed_at ≤ revoke_days；调度 revoke；publish request.fill_revoked
服务 fill(request_id, torrent_id, filler_id, idem)：等同 submit_fill（作用域 write，供“上传时选择应求”的前端流程经 torrent 插件调用）
```

### 1.4 lifecycle

- `expire`（cron）：`state = open AND expires_at ≤ now` → `closing`（reason expired），为每笔 escrowed 贡献调度 refund；publish `request.closed{reason: expired}`。
- 撤回：求种者在 `open` 状态撤回 → `closing`（reason withdrawn）；贡献者撤回自己的贡献（`open` 状态、非求种者的初始贡献）→ 只退该用户的贡献。
- `torrent.deleted` / `status_changed(to ∈ {disabled, deleted})`：该种子的 pending 应求 → reject（reason torrent_removed）；paid_out 的应求 → `needs_review` 标记（版主决定是否 revoke）。
- `user.deleted`：求种者被删除 → `requests.owner_deleted = true`（确认权转给版主，自动确认照常）；贡献者被删除 → 退款时 ledger 对已删除用户的发行会失败（`ledger.recipient_invalid`）→ 该笔标记 `forfeited`（不发行）。

### 1.5 认领与投票

`claims(request_id, user_id, expires_at)`：同一用户同一求种一条；过期自动失效（读时过滤）。`votes(request_id, user_id)` 主键；`requests.votes` 冗余计数。

### 1.6 对账（`reconcile`，每日）

`escrow_balance = Σ contributions.amount WHERE state = 'escrowed'`；与 ledger 中本插件原因码的流水汇总比较：`Σ escrow − Σ payout − Σ refund − fee`（通过 `ctx.ledger.history` 按原因码汇总——需 ledger 提供按原因码与调用方的汇总查询 ⊕），偏差 ≠ 0 告警。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:requests@0.1.0`）

```wit
package pt:requests@0.1.0;

interface requests {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms, json};

  record request-info {
    id: u64, type-id: string, title: string, user-id: option<user-id>, status: string,
    bounty-total: s64, currency: string, votes: u32, requirements: json, created-at: timestamp-ms,
  }
  record request-page { items: list<request-info>, next-cursor: option<string> }

  get: func(id: u64) -> result<option<request-info>, plugin-error>;
  fill: func(request-id: u64, torrent-id: u64, filler-id: user-id, idempotency-key: string) -> result<u64, plugin-error>;
  list-open-by-type: func(type-id: string, cursor: option<string>) -> result<request-page, plugin-error>;
}
```

### 2.2 事件

| 事件 | 字段 |
|---|---|
| `request.created` | `request_id, user_id, type_id, bounty, currency` |
| `request.bounty_added` | `request_id, user_id, amount, currency, total` |
| `request.fill_submitted` | `request_id, fill_id, torrent_id, filler_id` |
| `request.fill_rejected` | `request_id, fill_id, by, reason` |
| `request.filled` | `request_id, torrent_id, filler_id, payout, currency` |
| `request.fill_revoked` | `request_id, fill_id, by, reason` |
| `request.closed` | `request_id, reason(confirmed/expired/withdrawn)`（confirmed 指填充完成后归档——本实现中 filled 即终态，`closed{confirmed}` 不单独发布，保留枚举以兼容目录） |

### 2.3 钩子

- 拥有 `request.before_create`：输入 `version, actor, user_id, type_id, title, bounty, currency`；allow / deny / modify(`title`)；300 ms；deny。
- 处理 `comment.before_create`（target 以 `request:` 开头）：求种 `closed` / `filled` 且 `!comment_on_closed` → deny(`requests.closed`)。

### 2.4 HTTP API（前缀 `/api/p/requests/v1`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/requests?status=open&type_id=&sort=bounty|new|votes&cursor=` | 列表 |
| POST | `/requests` | 发布（Idempotency-Key）`{type_id, title, description_md, external_ids, requirements, bounty}` |
| GET | `/requests/{id}` | 详情（贡献者列表、应求、认领） |
| PATCH | `/requests/{id}` | 编辑（求种者：无应求时；版主随时） |
| POST | `/requests/{id}/bounty` | 追加 `{amount}` |
| POST / DELETE | `/requests/{id}/vote` | 投票 |
| POST / DELETE | `/requests/{id}/claim` | 认领 |
| POST | `/requests/{id}/fills` | 应求 `{torrent_id}` |
| POST | `/fills/{id}/confirm`、`/fills/{id}/reject`、`/fills/{id}/revoke` | 确认 / 驳回 / 撤销 |
| POST | `/requests/{id}/withdraw`、`/contributions/{id}/withdraw` | 撤回 |
| GET | `/admin/review` | 待复核（应求种子被删除）列表（`requests.moderate`） |

`requirements` 示例：`[{ "field": "resolution", "op": "in", "value": ["2160p", "1080p"] }, { "field": "release_type", "op": "in", "value": ["remux", "disc"] }]`。

### 2.5 MCP

`list_requests`（入参 `{type_id?, status?, sort?}`）；`create_request`（入参 `{type_id, title, description, bounty}`，write，确认页显示悬赏金额与币种）。

## 3. 数据库设计（schema `requests`）

```sql
CREATE TABLE requests.requests (
    id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id         bigint,
    owner_deleted   boolean NOT NULL DEFAULT false,
    type_id         text NOT NULL,
    title           text NOT NULL,
    description_src text NOT NULL,
    description_html text NOT NULL,
    external_ids    jsonb NOT NULL DEFAULT '{}',
    requirements    jsonb NOT NULL DEFAULT '[]',
    currency        text NOT NULL,
    bounty_total    bigint NOT NULL DEFAULT 0,
    votes           integer NOT NULL DEFAULT 0,
    state           text NOT NULL CHECK (state IN ('open','fill_pending','filled','closing','closed')),
    close_reason    text,
    expires_at      timestamptz NOT NULL,
    filled_torrent_id bigint,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX requests_open_idx ON requests.requests (type_id, bounty_total DESC) WHERE state IN ('open', 'fill_pending');
CREATE INDEX requests_expire_idx ON requests.requests (expires_at) WHERE state = 'open';

CREATE TABLE requests.contributions (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    request_id     bigint NOT NULL REFERENCES requests.requests (id),
    user_id        bigint NOT NULL,
    amount         bigint NOT NULL CHECK (amount > 0),
    state          text NOT NULL CHECK (state IN ('pending','escrowed','failed','refunding','refunded','paid','forfeited')),
    error_code     text,
    paid_fill_id   bigint,
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX contributions_request_idx ON requests.contributions (request_id, state);

CREATE TABLE requests.fills (
    id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    request_id       bigint NOT NULL REFERENCES requests.requests (id),
    torrent_id       bigint NOT NULL,
    filler_id        bigint NOT NULL,
    state            text NOT NULL CHECK (state IN ('pending','rejected','confirmed','paid_out','revoking','revoked','revoke_debt')),
    reason           text,
    auto_confirm_at  timestamptz NOT NULL,
    confirmed_at     timestamptz,
    confirmed_by     text,
    payout_amount    bigint,
    payout_entry     text,
    needs_review     boolean NOT NULL DEFAULT false,
    created_at       timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX fills_one_pending_idx ON requests.fills (request_id) WHERE state = 'pending';
CREATE INDEX fills_auto_idx ON requests.fills (auto_confirm_at) WHERE state = 'pending';
CREATE INDEX fills_torrent_idx ON requests.fills (torrent_id);

CREATE TABLE requests.votes (request_id bigint NOT NULL, user_id bigint NOT NULL, PRIMARY KEY (request_id, user_id));
CREATE TABLE requests.claims (request_id bigint NOT NULL, user_id bigint NOT NULL, expires_at timestamptz NOT NULL, PRIMARY KEY (request_id, user_id));
CREATE TABLE requests.idempotency (owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL, response jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (owner, key));

CREATE VIEW requests.v_request_public WITH (security_barrier = true) AS
SELECT id, type_id, state AS status, user_id, created_at FROM requests.requests;
```

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.ledger@^0.1", "ctx.torrents@^0.1", "ctx.users@^0.1"]`、`optional_requires = ["ctx.notify@^0.1"]`；`views = ["torrent.v_torrent_fields", "torrent.v_torrent_public"]`；`[database] views = ["v_request_public"]`；`search_contributor = true`；`[[hook_points]] request.before_create`；`[[hooks]] comment.before_create priority 30`；订阅三项；cron 三项；`[[jobs]] bounty_step`。

## 5. 前端设计

列表（悬赏排序、类型筛选）；详情（要求列表以人类可读形式显示、贡献者、应求区：提交种子 ID 或从“我的种子”选择、确认 / 驳回按钮）；上传页 `torrent.upload.extra` 插槽：“此种子是否满足某求种”（选择后上传完成自动应求）。

## 6. 安全设计

资金动作只在延迟任务中执行；确定性幂等键；确认权限校验；要求校验在服务端；版主强制接受写审计。

## 7. 性能设计

列表走部分索引；资金动作异步。

## 8. 可观测性

`pt_plugin_requests_state{state}`、`pt_plugin_requests_bounty_escrowed`（gauge）、`pt_plugin_requests_ledger_failures_total{op}`、`pt_plugin_requests_reconcile_diff`。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `requests.not_found` | 404 | |
| `requests.bounty_too_low` | 422 | 低于最低悬赏 / 最低追加 |
| `requests.not_open` | 409 | 状态不允许该操作 |
| `requests.fill_pending` | 409 | 已有待确认应求 |
| `requests.requirements_not_met` | 422 | 应求种子不满足要求（`details.failed`） |
| `requests.torrent_invalid` | 422 | 种子未审核或类型不符 |
| `requests.self_fill_not_allowed` | 403 | 不允许自己应求 |
| `requests.not_owner` | 403 | 非求种者 |
| `requests.revoke_window_expired` | 409 | 超过撤销期限 |
| `requests.closed` | 403 | 已关闭的求种不允许评论（钩子返回） |
| `requests.requirements_invalid` | 422 | 要求字段不属于该类型 |
