| 类别 | 内容 |
|---|---|
| 原则 | 搜索复用 `ctx.search`（以 feed key 对应用户的身份查询，可见性与网站一致）；下载复用 `ctx.torrents.build_download`（钩子与 passkey 注入由 torrent 完成）；本插件不存储种子数据，只存订阅定义 |
| 模块 | `keys`（feed key 鉴权）、`feeds`（订阅 CRUD、条件编译为 SearchRequest）、`rss_xml`（RSS 2.0 渲染）、`torznab`（参数解析、caps、结果 XML）、`catmap`（分类映射）、`download`、`limits`（限流与缓存） |
| 依赖 | `ctx.auth`（`authenticate(Credential::FeedKey)` → Principal）、`ctx.search`（`query`）、`ctx.torrents`（`get_many`、`build_download`；作用域 `download`）、optional `ctx.promotions`（`current_many`）、`ctx.hnr`（规则参数）、`ctx.accounting`（`swarm_stats`）、`ctx.identity` 的 feed key 签发（`ctx.auth.issue_token(kind = feed)`） |
| HTTP 路由鉴权 | 订阅与下载路由 `auth = public`（由本插件以 feed key 自行鉴权，内核网关不做会话鉴权）；管理路由 `auth = user` |
| 关键流程 | feed：`k` → `auth.authenticate(feed_key)` → principal（scope 必须含 `rss`）→ 读订阅定义 → `search.query(req, as = principal)` → 补充促销、做种数 → 渲染 XML（缓存 `fc:<feed_id>` 60 s）；download：`k` → principal → `torrents.build_download(id, principal.user_id)`（触发 `torrent.before_download`）→ 返回字节，`Content-Disposition: attachment; filename="<title>.torrent"` |
| 设计决策 | DD-RSS-1：不在 URL 中使用 passkey（NexusPHP 的改进）；DD-RSS-2：服务调用的 actor 必须是 feed key 对应用户——需要内核支持“以指定 principal 发起服务调用”（rss 通过 `ctx.auth.authenticate` 得到的 principal 作为后续服务调用的 actor）⊕；DD-RSS-3：Torznab `infohash` 返回 v1 hash（hybrid 种子同理）；DD-RSS-4：Torznab 的 `downloadvolumefactor` 取 `promotions.current_many` 的 combined 倍率（不含个人卡） |
| 平台契约新增 | ① 内核：插件在处理 public 路由时，用 `ctx.auth.authenticate` 获得的 principal 发起后续服务调用（“降权调用”，`invocation.as_principal(p)`），否则 search 与 torrent 无法按该用户的权限过滤；② identity：feed key 的作用域 `rss`、`download`（identity 文档已有 `ptf_` 前缀）；③ search：`query` 支持 `as_principal`（或由 ① 统一解决）；④ torrent：`build_download` 接受 `via = "rss"` 标记（下载事件中记录来源） |
| 权限点 | `rss.use`（已登记） |

需求追溯：FR-001 → feeds；FR-002 → keys；FR-003 → rss_xml；FR-004 → download；FR-005～008 → torznab、catmap；FR-009 → DD-RSS-2；FR-010、011 → limits；FR-012 → keys（identity 鉴权结果）；FR-013 → keys（使用记录）。
