## 1. 模块详细设计

### 1.1 keys

- 生成：`POST /v1/me/key` → `ctx.auth.issue_token(user_id, kind = feed, scopes = ["rss", "download"], ttl = None, name = "RSS", idempotency_key)`；返回明文一次（之后只显示前 8 位）；重置 = 吊销旧 key + 签发新 key。
- 鉴权：`p = auth.authenticate(Credential::FeedKey(k))`；None → 401 `rss.key_invalid`（统一错误，不区分不存在 / 吊销 / 用户被封）；`p.scopes` 必须含所需作用域。
- 使用记录：`HSET use:<token_id> at <now> ua <UA 前 100 字符>`（Redis，TTL 30 天），`GET /v1/me/key` 显示最近使用时间与 UA。

### 1.2 feeds

订阅定义：

```json
{ "name": "4K 电影免费", "type_ids": ["movie"], "category_ids": [], "q": "",
  "filters": [ { "field": "rel_resolution", "op": "eq", "value": "2160p" } ],
  "promotion": ["free", "double_up_free"], "min_size": 0, "max_size": 0, "exclude": ["CAM", "TS"] }
```

编译为 `SearchRequest{index: torrents, q, filters: [type_id IN …, … , promotion_kind IN …, size >= …], sort: [created_at:desc], limit: items_per_feed}`；`filters` 字段必须是 torrents 索引的 filterable 字段（`ctx.search` 的 schema 查询结果，缓存 10 分钟），`exclude` 转为对标题的 `NOT` 关键词（Meilisearch 查询中的 `-word` 语法）。

### 1.3 rss_xml

```xml
<rss version="2.0" xmlns:torznab="http://torznab.com/schemas/2015/feed">
<channel>
  <title>{site_name} - {feed_name}</title><link>{site_url}</link><ttl>5</ttl>
  <item>
    <title>{torrent.title}</title>
    <link>{site_url}/torrents/{id}</link>
    <guid isPermaLink="false">{site_host}-{id}</guid>
    <pubDate>{RFC 2822}</pubDate>
    <enclosure url="{site_url}/api/p/rss/v1/dl/{id}?k={feed_key}" length="{size}" type="application/x-bittorrent"/>
    <description>{规格摘要 · 促销 · 做种数}（纯文本，XML 转义）</description>
    <torznab:attr name="seeders" value="…"/> …（与 Torznab 相同的属性，便于工具复用）
  </item>
</channel></rss>
```

所有文本 XML 转义；描述不含 HTML。`Cache-Control: private, max-age=60`；`ETag = hash(item ids + 更新时间)`。

### 1.4 torznab

| 参数 | 处理 |
|---|---|
| `t` | `caps`、`search`、`tvsearch`、`movie`、`music`、`book`；其他 → 错误码 202（Newznab 错误：No such function） |
| `apikey` | feed key |
| `q` | 关键词 |
| `cat` | 逗号分隔的 Newznab 分类 → 反向映射为 type_id / category_id |
| `imdbid` | `tt` 前缀可有可无 → filter `movie_imdb_id` / `tv_imdb_id` |
| `tmdbid`、`tvdbid` | filter 对应字段 |
| `season`、`ep` | `tv_season`、`tv_episode`（或 anime 字段） |
| `artist`、`album` | 加入 q（音乐字段为 searchable） |
| `author`、`title` | 加入 q |
| `limit`（≤ 100）、`offset` | 分页（search 游标不支持偏移 → 本插件使用 search 的 `offset` 模式（≤ 1000）⊕） |

`t=caps` 响应：

```xml
<caps>
  <server title="{site_name}"/>
  <limits max="100" default="50"/>
  <searching>
    <search available="yes" supportedParams="q"/>
    <tv-search available="yes" supportedParams="q,season,ep,imdbid,tvdbid,tmdbid"/>
    <movie-search available="yes" supportedParams="q,imdbid,tmdbid"/>
    <music-search available="yes" supportedParams="q,artist,album"/>
    <book-search available="yes" supportedParams="q,author,title"/>
  </searching>
  <categories> <category id="2000" name="Movies"><subcat id="2040" name="Movies/HD"/>…</category> … </categories>
</caps>
```

条目属性（`torznab:attr`）：`category`（每个映射分类一条）、`size`、`seeders`、`peers`（seeders + leechers）、`grabs`（completed）、`infohash`（v1 hex）、`downloadvolumefactor`（down_permille / 1000）、`uploadvolumefactor`、`minimumratio`（hnr 的 `min_torrent_ratio`，未启用 hnr 时省略）、`minimumseedtime`（hnr `min_seed_hours × 3600`）、`imdb`（7 位数字）、`tmdbid`、`tvdbid`、`season`、`episode`。

错误：Newznab 错误 XML `<error code="100" description="Incorrect user credentials"/>`（100 鉴权、201 参数错误、202 不支持、500 内部错误、429 不在规范中 → 使用 HTTP 429 + `<error code="500" description="Request limit reached"/>`）。

### 1.5 catmap

默认映射（`category_map` 设置）：

| type_id / 条件 | Newznab |
|---|---|
| movie + resolution ∈ {2160p, 4320p} | 2045（Movies/UHD） |
| movie + resolution ∈ {1080p, 1080i, 720p} | 2040（Movies/HD） |
| movie + release_type = disc | 2050（Movies/BluRay） |
| movie 其他 | 2000 |
| tv + 2160p | 5045；tv + HD | 5040；tv 其他 | 5000 |
| anime | 5070（TV/Anime） |
| music + format 无损 | 3040（Audio/Lossless）；music 其他 | 3010（Audio/MP3）或 3000 |
| generic.game | 4050（PC/Games）；generic.software | 4000；generic.ebook | 7020（Books/EBook）；generic.course | 7000 |

### 1.6 download

```
GET /v1/dl/{id}?k=：
  p = keys::auth(k, scope = download)；rl(p.token_id)
  bytes = torrents.build_download(id, p.user_id, via = "rss")   // 内部触发 torrent.before_download 钩子
  错误映射：钩子拒绝 → 403 + 纯文本说明（BT 客户端显示）；not_found → 404
  响应 Content-Type: application/x-bittorrent；Content-Disposition: attachment
```

## 2. 接口详细设计

无服务 WIT、无事件、无钩子。HTTP 见 SRS §6。管理接口：

**POST `/v1/me/feeds`** 请求为 §1.2 定义 → 201 `{ "id": 5, "url": "https://site/api/p/rss/v1/feeds/5.xml?k=ptf_…" }`（只在 key 刚生成且仍在前端会话中时拼接完整 URL；之后返回不含 key 的模板，由前端提示用户使用已保存的 key）。

## 3. 数据库设计（schema `rss`）

```sql
CREATE TABLE rss.feeds (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id     bigint NOT NULL,
    name        text NOT NULL,
    definition  jsonb NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX feeds_user_idx ON rss.feeds (user_id);
```

Redis（`p:rss:`）：`fc:<feed_id>`（XML 缓存 60 s）、`tz:<hash(query,user_class)>`（Torznab 缓存 60 s；键含用户等级与角色摘要，保证可见性一致）、`rl:<token_id>:<kind>:<min>`、`use:<token_id>`。

## 4. 配置项

见 SRS §5。清单：`requires = ["ctx.auth@^0.1", "ctx.search@^0.1", "ctx.torrents@^0.1"]`、`optional_requires = ["ctx.promotions@^0.1", "ctx.hnr@^0.1", "ctx.accounting@^0.1"]`；scopes `ctx.torrents = ["download"]`、`ctx.accounting = ["read"]`、`ctx.auth = ["tokens:issue"]`（签发 feed key ⊕ 需 identity 支持 kind = feed）；路由 `auth = "public"`（feed、dl、torznab）与 `user`（管理）。

## 5. 前端设计

设置页“RSS”：生成 / 重置 key（醒目提示“不要分享”）、最近使用记录、订阅列表与编辑器（复用搜索筛选面板组件）、复制订阅 URL 与 Torznab 地址（Prowlarr 配置说明）。

## 6. 安全设计

URL 中只有 feed key（可吊销、作用域受限）；鉴权失败统一错误；限流；XML 转义；下载经过 torrent 钩子；缓存键包含权限摘要。

## 7. 性能设计

搜索走 Meilisearch；60 秒缓存吸收客户端轮询（BT 客户端常见 5～15 分钟轮询）。

## 8. 可观测性

`pt_plugin_rss_requests_total{kind,result}`、`pt_plugin_rss_cache_hit_ratio`、`pt_plugin_rss_downloads_total{result}`。
