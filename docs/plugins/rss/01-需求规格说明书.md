## 1. 引言

### 1.1 目的

定义 RSS 与 Torznab 插件 `rss` 的需求：个人 RSS 订阅（按条件）供 BT 客户端自动下载；Torznab 兼容接口供 Prowlarr / Jackett / Sonarr / Radarr 等工具搜索与下载。

### 1.2 范围

包含：个人订阅密钥（identity 的 feed key）、订阅定义（分类、资源类型、搜索词、筛选条件、促销条件，如“只要免费”）、RSS 2.0 输出、下载链接（不在 URL 中暴露 tracker passkey）、Torznab（`t=caps`、`search`、`tvsearch`、`movie`、`music`、`book`）、分类映射到 Newznab 标准分类、促销与 H&R 属性（`downloadvolumefactor`、`uploadvolumefactor`、`minimumratio`、`minimumseedtime`）、缓存与限流、权限过滤（与网站搜索一致）。

不包含：Atom 与 JSON Feed（P2 可加）；“书签 RSS”（依赖书签功能，不在本期）。

### 1.3 参考资料

- Torznab 规范（Newznab 扩展；`t=caps` 必须实现；`supportedParams`；torznab:attr 如 seeders、peers、infohash、downloadvolumefactor、uploadvolumefactor、minimumratio、minimumseedtime）
- UNIT3D：RSS（用户自建 feed，按分类、类型、分辨率、freeleech 过滤）与 Torznab API
- NexusPHP：RSS（passkey 放在 URL 中，`torrentrss.php?passkey=…`）

## 2. 总体描述

WASM，ID `rss`，缩写 `RSS`；无服务；依赖 `ctx.auth`（`authenticate(feed_key)`）、`ctx.search`（查询，按用户权限过滤）、`ctx.torrents`（`build_download`，作用域 `download`）、optional `ctx.promotions`、`ctx.hnr`、`ctx.accounting`（swarm 统计）。

### 2.1 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP | RSS URL 带 passkey；下载链接同样带 passkey | 简单 | passkey 泄露面大（RSS URL 常被分享、截图、记录到第三方工具日志），泄露后他人可冒用流量 | **改进**：URL 只带可独立吊销的 feed key（identity 的 `ptf_` key，作用域仅限 RSS / 下载），不带 passkey；下载接口凭 feed key 生成注入 passkey 的 .torrent |
| UNIT3D | 用户自定义 RSS 条件；Torznab | 灵活、工具兼容 | — | **采纳**自定义条件与 Torznab |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-RSS-001 | 订阅定义 | 用户创建最多 20 个订阅：名称、资源类型、分类、关键词、筛选（索引 facet 字段）、只要促销（free / 2x）、最小 / 最大体积、排除词 | P0 | |
| FR-RSS-002 | feed key | 使用 identity 签发的 feed key（`ptf_` 前缀）；用户在 RSS 页面生成 / 重置 | P0 | 重置后旧 URL 失效 |
| FR-RSS-003 | RSS 输出 | RSS 2.0：标题、链接（详情页）、enclosure（下载链接，`type = application/x-bittorrent`、`length`）、pubDate、guid（种子 ID）、描述（规格摘要、促销） | P0 | 主流 BT 客户端可解析 |
| FR-RSS-004 | 下载 | `GET /v1/dl/{torrent_id}?k=<feed_key>` → 注入 passkey 的 .torrent；同样经过 `torrent.before_download` 钩子（分享率、H&R 等限制生效） | P0 | URL 中无 passkey |
| FR-RSS-005 | Torznab caps | `t=caps`：server、limits（max 100、default 50）、searching（search / tv-search / movie-search / music-search / book-search 及 supportedParams）、categories | P0 | Prowlarr 能识别 |
| FR-RSS-006 | Torznab 搜索 | `t=search`（q、cat、limit、offset）、`tvsearch`（q、season、ep、tvdbid、imdbid、tmdbid）、`movie`（q、imdbid、tmdbid）、`music`（q、artist、album）、`book`（q、author、title） | P0 | |
| FR-RSS-007 | Torznab 属性 | seeders、peers、grabs、size、infohash（v1）、downloadvolumefactor、uploadvolumefactor、minimumratio、minimumseedtime、imdb / tmdbid / tvdbid 等 | P0 | 工具能读取免费状态 |
| FR-RSS-008 | 分类映射 | 资源类型 / 分类 → Newznab 标准分类（2000 电影、5000 电视、3000 音频、4000 PC、7000 书籍、5070 动漫）；站点可调整 | P0 | |
| FR-RSS-009 | 权限 | 结果与网站搜索一致（候选 / 待审不出现；等级限定资源按用户等级） | P0 | |
| FR-RSS-010 | 缓存 | 同一订阅 60 秒内重复请求返回缓存；`If-Modified-Since` / ETag | P1 | |
| FR-RSS-011 | 限流 | 每 feed key 每分钟 30 次（RSS）、60 次（Torznab）；下载每分钟 30 次 | P0 | |
| FR-RSS-012 | 被封禁用户 | feed key 对 banned / deleted 用户失效；leech_disabled 用户可读 RSS 但下载被拒 | P0 | |
| FR-RSS-013 | 访问记录 | 记录 feed key 最近使用时间与客户端 UA（供用户发现泄露） | P2 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-RSS-001 | RSS 响应 | 缓存命中 p99 < 30 ms；未命中 p99 < 300 ms |
| NFR-RSS-002 | 下载 | p99 < 200 ms |
| NFR-RSS-003 | 安全 | URL 中不出现 tracker passkey；feed key 可单独吊销 |

## 5. 可配置项与站点术语

`max_feeds_per_user`（20）、`items_per_feed`（50）、`cache_secs`（60）、`rate.rss_per_min`（30）、`rate.torznab_per_min`（60）、`rate.download_per_min`（30）、`category_map`（资源类型 / 分类 → Newznab 分类）。术语：无新增（标题等来自种子数据）。

## 6. 外部接口需求概述

HTTP：`GET /api/p/rss/v1/feeds/{feed_id}.xml?k=`、`GET /v1/dl/{id}?k=`、`GET /v1/torznab/api?t=…&apikey=`；用户管理：`GET/POST/PATCH/DELETE /v1/me/feeds`、`POST /v1/me/key`（生成 / 重置 feed key）。插槽 `user.settings.tabs`（RSS 设置）。
