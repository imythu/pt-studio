## 1. 模块详细设计

### 1.1 rules（确定性检查）

| code | 条件 | severity |
|---|---|---|
| `spec_mismatch.<field>` | `mediainfo.compare(summary, fields)` 每个差异一条 | high |
| `mediainfo_missing` | 影视类型且无 MediaInfo | medium |
| `archive_only` | 文件列表只有 rar / zip / 7z（影视、音乐类型） | high |
| `title_nonstandard` | 标题与规范标题相似度 < 0.5 | low |
| `nfo_missing` | 站点要求 NFO 的类型且 `nfo_present = false` | low |
| `sample_only` | 所有视频文件 < 200 MiB 且路径含 sample | high |

### 1.2 llm_review

系统提示（固定，便于提示缓存）：

```
你是 PT 站的上传预审助手。根据给出的种子技术信息，找出不符合常见发布规范的问题。
只依据给出的信息判断，不要猜测；不确定时给出 warn 而不是 fail。
输出 JSON：verdict（pass / warn / fail）、findings（code、severity、message，message 用简体中文）、confidence（0~1）。
可用的 code：title_format、spec_inconsistent、description_low_quality、suspicious_files、wrong_type、other。
```

用户消息：`text`（结构化事实：类型、规范标题、字段、MediaInfo 摘要、文件样本、确定性检查结果）+ `untrusted`（上传者填写的标题与描述前 2000 字）。

请求：`ctx.llm.complete({profile: "cheap", system, messages, output_schema, effort: "low", max_output_tokens: 1500, idempotency_key: "aiur:<torrent_id>:<revision>"})`。`stop = refusal` 或 `structured_invalid` → 报告标注 `model_failed`，只保留确定性结果。

输出 schema：

```json
{ "type": "object", "additionalProperties": false, "required": ["verdict", "findings", "confidence"],
  "properties": {
    "verdict": { "type": "string", "enum": ["pass", "warn", "fail"] },
    "confidence": { "type": "number" },
    "findings": { "type": "array", "items": { "type": "object", "additionalProperties": false,
      "required": ["code", "severity", "message"],
      "properties": { "code": { "type": "string", "enum": ["title_format", "spec_inconsistent", "description_low_quality", "suspicious_files", "wrong_type", "other"] },
                      "severity": { "type": "string", "enum": ["low", "medium", "high"] },
                      "message": { "type": "string" } } } } } }
```

合并：`verdict = max(确定性结论（任一 high → fail，medium → warn）, 模型结论)`；确定性 high 与模型 pass 矛盾 → 取 fail 并记录 `model_disagreed`。

### 1.3 dupes

若 Group 有外部 ID：`search.query(torrents, filters: [<type>_imdb_id = …（或对应 ID 字段）, rel_resolution = …, vis_status = approved], limit 5)`（以系统身份查询）；结果作为 finding `possible_dupe`（severity medium，附种子 ID）。

### 1.4 budget

`INCR budget:<yyyymmdd>`（Redis）> `daily_model_budget` → 跳过模型（`model_skipped: budget`）。

## 2. 接口详细设计

### 2.1 服务（WIT `pt:ai-upload-review@0.1.0`）

```wit
package pt:ai-upload-review@0.1.0;

interface ai-upload-review {
  use pt:plugin/types@0.1.0.{plugin-error, json, timestamp-ms};
  record finding { code: string, severity: string, message: string, source: string /* rule | model | dupe */ }
  record review-report { report-id: u64, torrent-id: u64, verdict: string, confidence: option<f64>, findings: list<finding>,
                         model-skipped: option<string>, created-at: timestamp-ms }
  review: func(torrent-id: u64) -> result<option<review-report>, plugin-error>;
}
```

调用方需原始 actor 拥有 `ai-upload-review.read`（moderation 以审核员身份读取）。

### 2.2 事件

`ai.upload_reviewed`：`torrent_id, report_id, verdict, findings[]（只含 code 与 severity）, model_skipped?`。

### 2.3 HTTP

`GET /v1/torrents/{id}` → 最新报告；`POST /v1/torrents/{id}/rerun`（`ai-upload-review.read`）；`POST /v1/reports/{id}/feedback {useful: bool}`；`GET /v1/admin/stats`（准确率、调用量）。

## 3. 数据库设计（schema `ai_upload_review`）

```sql
CREATE TABLE ai_upload_review.reports (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    torrent_id     bigint NOT NULL,
    revision       integer NOT NULL,
    verdict        text NOT NULL,
    confidence     double precision,
    findings       jsonb NOT NULL,
    model          text,
    model_skipped  text,
    usage          jsonb,
    feedback       text CHECK (feedback IN ('useful', 'false_positive')),
    feedback_by    bigint,
    created_at     timestamptz NOT NULL DEFAULT now(),
    UNIQUE (torrent_id, revision)
);
```
