## 1. 模块详细设计

### 1.1 ids

```
normalize(s): m = regex(r"(?:imdb\.com/title/)?(tt\d{7,9})").captures(trim(s))；m 为空 → Err(id_invalid)；return m[1]
info(): {source: "imdb", type-ids: ["movie", "tv"], id-pattern: "tt\\d{7,9}"}
link(tt) = "https://www.imdb.com/title/" + tt + "/"
```

### 1.2 delegate

见 HLD §3；委托结果不在本插件缓存（metadata-tmdb 已缓存）；`ctx.metadata` 不可用或 TMDB 返回 none 时退回最小数据。

### 1.3 licensed（可选）

同 metadata-douban 03 §1 的代理约定（`GET {endpoint}/title/{tt}`），映射到统一模型；需风险 / 授权确认（`POST /v1/admin/licensed/enable`，`metadata-imdb.manage`），结果缓存 30 天（schema `metadata_imdb.cache`，结构同 metadata-tmdb）。

## 2. 接口详细设计

`search()` 返回空列表（IMDb 不支持搜索，前端改用 TMDB 搜索）。

**GET `/v1/lookup?id=https://www.imdb.com/title/tt0111161/`** → `{ "source": "tmdb", "external_id": "movie:278", "data": { … , "ids": { "imdb": "tt0111161", "tmdb": 278 } } }` 或最小数据。

## 3. 数据库设计

仅在启用 licensed 时使用 `metadata_imdb.cache`（同 metadata-tmdb 结构）。
