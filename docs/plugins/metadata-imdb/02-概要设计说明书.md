## 1. 设计目标

合规优先：不访问 IMDb；以 ID 校验、外链与委托为主。

## 2. 结构与接口

| 类别 | 内容 |
|---|---|
| 模块 | `ids`（提取与校验）、`delegate`（经 `ctx.metadata.lookup("tmdb", "imdb:<tt>", locale)`）、`licensed`（可选端点客户端） |
| 导出 | `metadata-provider` |
| 依赖 | `ctx.metadata`（内核聚合服务，optional：未启用 metadata-tmdb 时返回最小数据） |
| 能力 | `kv`；`http_outbound = ["config:licensed_endpoint"]`（仅可选端点） |
| HTTP | `GET /api/p/metadata-imdb/v1/lookup?id=` |

## 3. 关键流程

```
lookup(tt, locale):
  tt = normalize(tt)；非法 → id_invalid
  if licensed_enabled: 调用授权端点（同 douban 代理约定）
  elif delegate_to == tmdb 且 ctx.metadata.sources() 含 tmdb:
     r = ctx.metadata.lookup("tmdb", "imdb:" + tt, locale)；r.data.ids.imdb = tt；return r（source 字段保留 "tmdb"）
  else return {source: "imdb", external_id: tt, data: {kind: null, ids: {imdb: tt}, attribution: {source: "imdb", url}}}
```

## 4. 设计决策

| 编号 | 问题 | 结论 |
|---|---|---|
| DD-MDIMDB-1 | 是否导入 Non-Commercial Datasets | 否：条款禁止用其建立电影信息数据库，PT 站的作品库正属于此类 |
| DD-MDIMDB-2 | 委托调用是否构成依赖环 | metadata-imdb → 内核 `ctx.metadata` → metadata-tmdb，单向，不成环；metadata-tmdb 不调用 metadata-imdb |

## 5. 对平台契约的新增

确认 WASM 插件可以 `requires ctx.metadata`（内核聚合服务）并被路由到其他 metadata 插件；`config:<key>` 形式的出站主机声明（与 metadata-douban 02 §7 相同）。

## 6. 需求追溯

FR-001、002 → ids；FR-003、004 → delegate；FR-005 → licensed；FR-006 → 前端。
