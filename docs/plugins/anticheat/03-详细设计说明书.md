## 0. 实现说明（0.2）

与本文的差异（其余按本文实现；需要补的能力与做法见 [05-后续工作.md](05-后续工作.md)）：

| 项 | 实现 | 原因 |
|---|---|---|
| swarm 快照（§1.11） | 读 accounting 新增视图 `v_swarm_peers`（活跃 peer + 该用户在种子上的累计原始流量，不含 IP / 端口 / peer_id） | 平台没有 `ctx.tracker` 服务 |
| 盒子识别、同 IP 对端（FR-ACH-041）、种子视角（FR-ACH-042）、passkey 重置 | 未提供：`ctx.is_seedbox` 恒为 false；`reset_passkey` 决定返回 `anticheat.action_unavailable` | 依赖的 seedbox 插件与 identity 方法尚不存在 |
| 运行时设置 | 扁平键（如 `breaker_max_auto_per_hour`、`appeal_window_days`），见清单 `[settings_schema]` | 后台设置编辑器（设计 D21）按扁平 schema 生成表单 |
| 申诉令牌密钥 | `[plugin.anticheat] appeal_token_secret`（≥ 32 字节）；未配置时用插件 kv 中首次生成的随机密钥，不拒绝启动 | 现有部署无需改配置即可启用 |
| 近期重新验证 | 未声明 `reauth_secs` | 平台还没有重新验证接口与前端流程，声明后会话超过时限的管理员将无法操作 |
| 默认规则集 | 首次加载时写入 v1（`src/default_ruleset.json`），`counter_jump` 规则另匹配 pt-tracker 的 `started_nonzero`（首报 started 携带非零累计值） | 迁移文件无法引用 JSON 文件；伪造 started 是已出现的作弊手法 |
| 证据分区 | 内核只预建上月起的分区：信号时间早于 28 天前的按入库时间记 | 避免写入不存在的分区 |
| 结论性规则开案 | `on_score` 在 band ≥ high **或** 有自动策略命中时开案（§1.7 的“即使 band < high 也开案”） | 同左 |
| 申诉四眼 | 原决定人与本案处置的批准人都不能复核（sysop 例外） | 同 §1.10 |
| MCP `admin_resolve_anticheat_case` | 确认整体锁定（`confirm_locked`） | 清单只能按工具锁定确认，不能按参数 |

约定：伪代码中 `tx` 指当前调用的工作单元；`commit()` 指 `sql.commit()`（仅 `tx = "manual"` 入口）；`now` 取 `ctx.time.now()`；所有跨插件调用都带幂等键（键规则见 §1.9）。

## 1. 模块详细设计

### 1.1 ingest：证据入库

**证据来源与种类**：

| 来源 `source` | 种类 `kind` | 外部引用 `external_ref` | 写入者 |
|---|---|---|---|
| `accounting` | 6 种信号名（`speed_exceeded` 等） | `signal:<signal_id>` | `on_signal` 订阅 |
| `anticheat` | `anticheat.daily_upload_spike`、`anticheat.shared_ip_counterparty` | `spike:<user>:<yyyy-mm-dd>`、`sip:<case_id>:<torrent_id>` | cron / `enrich_case` |
| `plugin:<id>` | `<id>.<kind>`（如 `seedbox.shared_account`） | 调用方幂等键 | `report()` |
| `manual` | `anticheat.manual` | `manual:<Idempotency-Key>` | 后台 |

**on_signal**（`traffic.signal_raised` v1，ordered，tx auto）：

```
handle(evt):
    p = evt.payload                                   -- {signal_id, user_id, torrent_id?, signal, severity, hits, details, first_at}
    validate p（schema；signal ∈ 6 种；severity ∈ low/medium/high） ?: 记录 rejected 指标并返回 ok（不重试坏数据）
    INSERT INTO evidence(user_id, torrent_id, source, kind, severity, hits, details, occurred_at, external_ref)
        VALUES (p.user_id, p.torrent_id, 'accounting', p.signal, p.severity, p.hits, p.details, p.first_at, 'signal:'||p.signal_id)
        ON CONFLICT (source, external_ref, occurred_at) DO UPDATE SET hits = greatest(evidence.hits, EXCLUDED.hits),
                                                                     severity = greatest_sev(evidence.severity, EXCLUDED.severity)
    -- accounting 在严重度升级时以新的 signal_id 再次发布，因此冲突只来自重放
    scoring.rescore_user(p.user_id, trigger = 'evidence', auto_policies = true)
```

- 内核 inbox 已保证本事务对同一事件恰好一次；`ON CONFLICT` 兜底回放（`--force`）与 `report()` 重试。
- `details` 只保留白名单字段（按信号种类：`kind, bytes, interval_secs, speed_bps, limit_bps, client, reported_up, reported_down, seeders, leechers, hour_start, swarm_uploaded, swarm_downloaded, user_uploaded, user_share_pct, uploaders, peer_id_prefix, ua_family`），其余丢弃，大小 ≤ 4 KiB。

**report(req)**：

```
report(req{user, torrent_id?, kind, severity, details(json ≤ 4 KiB), occurred_at, note?, idempotency_key}):
    require "report" ∈ caller_scopes                           ?: anticheat.scope_required
    require kind 以 caller + "." 开头且匹配 ^[a-z][a-z0-9-]*\.[a-z][a-z0-9_]{1,47}$   ?: anticheat.report_invalid
    require occurred_at ∈ [now − 30 d, now + 5 min]            ?: anticheat.report_invalid
    require ctx.users.get(user) 存在                          ?: anticheat.user_not_found
    INSERT evidence(source = 'plugin:'||caller, external_ref = idempotency_key, …) ON CONFLICT DO NOTHING RETURNING id
       冲突 → 读取已有行，details 哈希不同 → kernel.idempotency_key_reused；相同 → 返回原 id
    scoring.rescore_user(user, 'evidence', auto_policies = true)
```

**daily_upload_spike**（cron `20 5 * * *`，tx manual）：

```
d = 站点时区的昨天
cursor = kv.get("spike:<d>") ?: 0
loop:
    rows = SELECT user_id, uploaded_raw FROM accounting.v_user_daily
           WHERE day = $d AND uploaded_raw >= $min AND user_id > $cursor ORDER BY user_id LIMIT 500
    for r in rows:
        hist = SELECT uploaded_raw FROM accounting.v_user_daily WHERE user_id = $u AND day BETWEEN d−30 AND d−1
        n = len(hist)；p95 = n ≥ 7 ? percentile(hist, 95) : 0
        if r.uploaded_raw >= max(min, factor × p95):
            INSERT evidence(kind = 'anticheat.daily_upload_spike', source = 'anticheat', severity = r ≥ 3×max(min, factor×p95) ? 'high' : 'medium',
                            details = {day, uploaded_raw, p95, history_days: n, factor}, occurred_at = d 末,
                            external_ref = 'spike:<u>:<d>') ON CONFLICT DO NOTHING
            若插入：scoring.rescore_user(u, 'evidence', auto_policies = true)
    kv.set("spike:<d>", last_user_id)；commit()
    if len(rows) < 500: break
```

视图缺失（A-8 未合入）时启动日志告警并让该 cron 直接返回（`anticheat.dependency_missing` 指标）。

### 1.2 rules：规则集 DSL

规则集是一个 JSON 对象（≤ 64 KiB），保存在 `rulesets.definition`。JSON Schema 文件 `schemas/ruleset.v1.json`，要点如下：

```json
{
  "schema": 1,
  "defaults": { "window_days": 90, "half_life_days": 14, "hits_fn": "log2", "hits_cap": 4, "max_evidence": 2000 },
  "thresholds": { "low": 10, "watch": 30, "case": 60, "critical": 80, "transfer_block": 60 },
  "rules": [ /* evidence | aggregate | multiplier */ ],
  "policies": [ /* 处置策略 */ ]
}
```

**证据规则**（`type = "evidence"`）：

| 字段 | 类型 | 约束 / 默认 | 说明 |
|---|---|---|---|
| `id` | string | `^[a-z][a-z0-9_]{1,47}$`，全集唯一 | 规则 ID（规则统计、案件主规则、原因码 `anticheat.<id>`） |
| `mode` | enum | `enforce` / `shadow` / `off` | |
| `match.kinds` | string[] | 1～10 个 | 证据种类 |
| `match.severity_gte` | enum? | low / medium / high | |
| `match.where` | predicate[] | ≤ 10 个，全部成立 | 见下方谓词 |
| `weight` | number | 0～100 | 基础分 |
| `severity_mult` | object | 每项 0～5，默认 `{low: 0.5, medium: 1, high: 2}` | 无严重度的证据按 medium |
| `hits_fn` / `hits_cap` | enum / number | `log2`（1 + log₂h）/ `linear`（h）/ `none`（1）；cap 1～20 | |
| `half_life_days` | number | 1～365，缺省取 defaults | |
| `context_mult` | `{when: predicate[], mult}`[] | ≤ 5 项，mult 0～3 | 全部满足的项连乘 |
| `per_torrent_cap` | number | 0～100，缺省 = cap | 同一 (规则, 种子) 的上限；无种子的证据视为种子 0 |
| `cap` | number | 0～100 | 该规则总上限 |
| `tags` | string[] | ≤ 5，`^[a-z_]{2,32}$` | `conclusive` 为保留标签 |

**聚合规则**（`type = "aggregate"`）：`id, mode, match{kinds, severity_gte?, where?}, window_days(1～180), measure, steps[{gte, score}]（≤ 10，gte 递增，score 0～100）, tags`。`measure`：`count`、`distinct_torrents`、`distinct_kinds`、`sum:<path>`、`max:<path>`（path 为 `details.<key>` 或 `hits`）。取达到的最高阶梯分；聚合规则不做时间衰减（窗口即边界）。

**乘数规则**（`type = "multiplier"`）：`id, mode, when: predicate[], factor(0.1～3), applies_to_tags: string[]`（空 = 全部规则）。

**谓词**：`{ "field": <path>, "op": <op>, "value": <v> }` 或 `{ "measure": {fn, window_days, match}, "op", "value" }`。

| path | 含义 |
|---|---|
| `hits`、`severity`、`torrent_id` | 证据字段（仅证据规则可用） |
| `details.<key>` | 证据详情字段（key 为 `^[a-z_]{1,32}$`） |
| `ctx.account_age_days`、`ctx.class_id`、`ctx.is_protected`、`ctx.confirmed_cases_365d`、`ctx.warnings_90d` | 用户上下文 |
| `ctx.is_seedbox` | 证据所在种子是否为该用户登记的盒子（仅证据规则；seedbox 未启用恒 false） |

`op`：`eq`、`ne`、`gt`、`gte`、`lt`、`lte`、`in`、`nin`、`exists`。`value` 为数值 / 字符串 / 布尔 / 数组，或引用 `{ "ref": "details.limit_bps", "mul": 5 }`（与同一证据的另一个数值字段比较）。类型不匹配、字段缺失时谓词为 false（`exists` 除外）。无正则、无循环，单条证据的计算量 ≤ O(规则数 × 谓词数)。

**处置策略**（`policies[]`）：

| 字段 | 说明 |
|---|---|
| `id` | 策略 ID |
| `when` | `{ band_gte?, score_gte?, rules_any?[], tags_any?[] }`，全部成立 |
| `actions` | `[{kind, days?}]`，kind ∈ `warn`、`freeze_traffic`、`lock_wallet`、`disable_download`、`ban`、`adjust_traffic`（自动策略不允许 adjust_traffic、reset_passkey） |
| `auto` | 是否自动执行；含 `ban` / `disable_download` 时要求 `auto_ban_enabled = true`，否则校验报错 |

**语义校验**（`validate(def) -> errors[]`）：ID 唯一；`thresholds` 满足 `0 < low < watch < case ≤ critical ≤ 100` 且 `transfer_block ≥ watch`；`rules_any` 引用存在；聚合 `steps` 递增；`auto = true` 的策略必须带 `rules_any` 或 `tags_any`，且所引用规则至少一条带 `conclusive` 标签；`ref` 目标为数值 path；总规则数 ≤ 200。错误项 `{path: JSON Pointer, code, message}`。

### 1.3 context：评分上下文

```
context.get(user, need_seedbox_torrents: set<u64>) -> Ctx:
    c = SELECT * FROM user_context WHERE user_id = $1
    if c 为空 或 c.refreshed_at < now − 24h:
        u = ctx.users.get(user)；roles = ctx.rbac.roles_of(user)
        confirmed = SELECT count(*) FROM cases WHERE user_id=$1 AND resolution='sanctioned' AND resolved_at > now−365d
        warnings  = SELECT count(*) FROM sanctions WHERE user_id=$1 AND kind='warn' AND created_at > now−90d AND state <> 'overturned'
        UPSERT user_context(user_id, account_created_at=u.created_at, class_id=u.class_id,
                            is_protected = max_builtin_rank(roles) ≥ rank(protected_min_role),
                            confirmed_cases_365d = confirmed, warnings_90d = warnings, refreshed_at = now)
    if ctx.seedbox 可用 且 need_seedbox_torrents 非空:
        missing = need − SELECT torrent_id FROM seedbox_flags WHERE user_id=$1 AND torrent_id = ANY($2) AND refreshed_at > now−24h
        对 missing 调 ctx.seedbox.is_seedbox(user, t)（A-12 合入后改为 is_seedbox_many，一次 ≤ 500）→ UPSERT seedbox_flags
    return Ctx{account_age_days = floor((now − account_created_at)/1d), …, seedbox: map}
```

在钩子以外的入口调用（事件、cron、延迟任务、HTTP），外部服务失败时使用旧缓存并记 `context_stale_total`；无缓存时以保守默认（`is_protected = true`、`is_seedbox = false`）计算——保守默认使该用户不会被自动处置。

### 1.4 scoring：评分

```
compute(user, rs, now, include_shadow = true) -> Score:
    W = max(rs.defaults.window_days, 所有聚合 / measure 的 window_days)
    ev = SELECT id, kind, severity, hits, torrent_id, details, occurred_at FROM evidence
         WHERE user_id = $1 AND occurred_at >= now − W AND occurred_at <= now
           AND (verdict IS NULL OR verdict <> 'false_positive')
         ORDER BY occurred_at DESC LIMIT rs.defaults.max_evidence
    ctx = context.get(user, torrents_needing_seedbox(rs, ev))
    contrib = map<rule_id, f64>;  per_t = map<(rule_id, torrent), f64>;  matched = map<rule_id, list<ev>>
    for e in ev where e.occurred_at >= now − rs.defaults.window_days:
        for r in rs.evidence_rules where r.mode != off and match(r, e, ctx):
            age_d = (now − e.occurred_at) / 86400000
            c = r.weight × r.severity_mult[e.severity ?: medium] × hitsf(r, e.hits)
                × 2^(−age_d / r.half_life) × Π{cm.mult | cm ∈ r.context_mult, all(cm.when, e, ctx)}
            k = (r.id, e.torrent_id ?: 0)
            c = min(c, r.per_torrent_cap − per_t[k], r.cap − contrib[r.id])；c = max(c, 0)
            per_t[k] += c；contrib[r.id] += c；matched[r.id].push(e)
    for a in rs.aggregate_rules where a.mode != off:
        sel = ev where occurred_at >= now − a.window_days and match(a.match, e, ctx)
        v = measure(a.measure, sel)；contrib[a.id] = max{s.score | s ∈ a.steps, v ≥ s.gte} ?: 0
    for m in rs.multiplier_rules where m.mode != off and all(m.when, ctx, ev):
        for r in contrib.keys where m.applies_to_tags 为空 或 tags(r) ∩ m.applies_to_tags ≠ ∅:
            factor[m.mode][r] ×= m.factor                   -- shadow 乘数只作用于影子分
    enforce = Σ{contrib[r] × factor[enforce][r] | mode(r) = enforce}
    shadow  = Σ{contrib[r] × factor[enforce][r] × factor[shadow][r] | mode(r) ∈ {enforce, shadow}}
    score = min(100, round_half_even(enforce))；shadow_score = min(100, round_half_even(shadow))
    band = 按 thresholds：score ≥ critical → critical；≥ case → high；≥ watch → watch；≥ low → low；否则 none
    tags = ∪ tags(r) for r with contrib > 0 and mode = enforce
    breakdown = [{rule, type, mode, score: round2(contrib×factor), evidence: len(matched[r]), top_torrents: 3}]（按分值降序）
    return Score{score, shadow_score, band, tags, breakdown, rules_hit: keys(contrib>0), evidence_used: len(ev), truncated: len(ev)=max}
```

- **确定性**：输入固定（证据、规则集、上下文快照、now），浮点运算顺序固定（按 rule 在规则集中的顺序、证据按 `occurred_at DESC, id DESC`），最终四舍六入五成双取整。同一 WASM 构建在不同副本结果相同。
- `truncated = true`（窗口内证据超过 2000 条）时按最近证据计算，并在案件中提示“证据过多”。

**rescore_user**（在调用方事务内）：

```
rescore_user(user, trigger, auto_policies):
    rs = rules.active()                                    -- SELECT version, definition FROM rulesets WHERE status='active'
    s = compute(user, rs, now)
    old = SELECT … FROM user_risk WHERE user_id = $1 FOR UPDATE
    blocked = (open_case(user) 且 s.score ≥ rs.thresholds.transfer_block) 或 exists sanction(user, kind ∈ {freeze_traffic, lock_wallet}, state ∈ {pending, active})
    UPSERT user_risk(score, shadow_score, band, tags, breakdown, ruleset_version = rs.version, transfer_blocked = blocked,
                     computed_at = now, peak_score = greatest(old.peak_score, s.score))
    if old.band != s.band: INSERT case_events(若有进行中案件) 或 risk_history(user, from, to, at)
    cases.on_score(user, s, rs, trigger)                   -- §1.5
    if auto_policies: policies.evaluate(user, s, rs)       -- §1.7
```

`trigger ∈ {evidence, decay, activation, manual}`；`activation` 与 `decay` 时 `auto_policies = false`。

**rescore_decay**（cron `30 3 * * *`，tx manual）：按 `user_id` 键集分页 `SELECT user_id FROM user_risk WHERE score > 0 OR shadow_score > 0 OR open_case_id IS NOT NULL`，每批 500：对有进行中案件或 watch 及以上的用户先 `enrich.refresh_hits(user)`，再 `rescore_user(user, 'decay', false)`；`commit()`；游标存 kv `decay:<scheduled_at>`，同一 `scheduled_at` 重跑从游标续跑。

**rescore_batch**（延迟任务，规则集激活后）：payload `{ruleset_version, cursor}`；用户集合 = `SELECT DISTINCT user_id FROM evidence WHERE occurred_at >= now − W`（键集分页 500）；若生效版本已不是 payload 中的版本则停止；每批后 `commit()` 并 `schedule_once(rescore_batch, now, {version, cursor}, dedupe = "rs:<v>:<cursor>")`。

### 1.5 cases：案件与队列

**状态机**：

```
            on_score(band≥high) / 手动开案
   (无) ───────────────────────────────► open ──resolve(sanction)──► resolved ──appeal overturned──► overturned
                                          │  ──resolve(no_action)──► resolved
                                          │  ──resolve(dismiss)────► dismissed
                                          │  ──30 天无活动且 band < watch──► closed_stale
                                          └──user.deleted──► closed_user_deleted
```

- 进行中 = `open`。部分唯一索引 `cases_user_open_key ON cases(user_id) WHERE state = 'open'` 保证每用户至多一个。
- 认领字段：`assigned_to`、`claim_expires_at`；认领不改变状态。

**on_score**：

```
on_score(user, s, rs, trigger):
    c = SELECT … FROM cases WHERE user_id=$1 AND state='open' FOR UPDATE
    if c 为空 and s.band ∈ {high, critical}:
        c = INSERT INTO cases(user_id, state='open', opened_reason='score', score_at_open=s.score, score=s.score,
                              peak_score=s.score, band=s.band, primary_rule=s.breakdown[0].rule, ruleset_version=rs.version,
                              prior_case_id = 最近一个已关闭案件, priority = priority(s, 0))
            ON CONFLICT ON CONSTRAINT（部分唯一索引）DO NOTHING RETURNING *
        if c 为空: c = SELECT …（并发者已开案）
        else: publish anticheat.case_opened{case_id, user_id, rule=primary_rule, score, band, opened_reason, ruleset_version, evidence_count}
              schedule_once(enrich_case, now, {case_id}, dedupe = "enrich:<case_id>")
              stats.bump(rs.version, s.rules_hit, cases_opened = 1)
    if c 存在:
        INSERT case_evidence(case_id, evidence_id, snapshot) SELECT … FROM 本次 matched 证据 ON CONFLICT DO NOTHING
        UPDATE cases SET score = s.score, peak_score = greatest(peak_score, s.score), band = s.band,
                         primary_rule = s.breakdown[0].rule, priority = priority(s, opened_at), updated_at = now
        UPDATE user_risk SET open_case_id = c.id
```

`priority(s, opened_at) = s.score + (band = critical ? 20 : 0) + min(30, floor(等待小时 / 4))`；`queue_maintenance` 每 10 分钟刷新等待项。

**认领**：

```
claim(case_id, me):
    r = UPDATE cases SET assigned_to = me, claim_expires_at = now + claim_ttl, version = version + 1
        WHERE id = $1 AND state = 'open' AND (assigned_to IS NULL OR claim_expires_at < now OR assigned_to = me)
        RETURNING version
    空 → 存在且 open → anticheat.case_claimed（details: assigned_to, claim_expires_at）；否则 anticheat.case_state_invalid / not_found
release(case_id, me)：UPDATE … SET assigned_to = NULL WHERE id AND assigned_to = me
```

**queue_maintenance**（cron `*/10 * * * *`）：① `UPDATE cases SET assigned_to = NULL WHERE claim_expires_at < now`；② 刷新 priority；③ `state='open' AND band < watch AND updated_at < now − 30d` → `closed_stale`（时间线、`case_resolved{resolution: no_action}` 不发——stale 不是决定，发 `case_events` 即可）；④ `proposed` 处置超过 7 天未批准 → `lifted(lift_reason='proposal_expired')`；⑤ 指标 `queue_oldest_age_seconds`、`queue_over_sla`。每项更新幂等（条件 UPDATE），重复运行无副作用。

### 1.6 decisions：复核决定

**处置权限矩阵**：

| 处置 | 所需权限 | 受保护用户 | four_eyes |
|---|---|---|---|
| `warn`、`freeze_traffic`、`lock_wallet`、`adjust_traffic` | `anticheat.cases.moderate` | 需 `anticheat.sanctions.manage` | — |
| `disable_download`、`ban`、`reset_passkey` | `anticheat.sanctions.manage` | 不允许（identity 会拒绝插件来源；提示由 sysop 在 identity 后台处理） | `ban` 在 `four_eyes_for_ban` 时先为 `proposed` |

```
resolve(case_id, decision, note, key, actor):
    require note 1..=2000 字符（NFC、去控制字符）                       ?: kernel.validation_failed
    幂等：INSERT decision_requests(actor_key, key, request_hash) ON CONFLICT → 同哈希返回首次结果 / 不同 kernel.idempotency_key_reused
    c = SELECT … FROM cases WHERE id=$1 FOR UPDATE                       ?: anticheat.case_not_found
    c.state != 'open' → anticheat.case_state_invalid
    c.assigned_to != actor.user：未认领则自动认领（同 claim 条件），被他人认领 → anticheat.claim_required
    ctx = context.get(c.user_id)
    match decision:
      dismiss{false_positive_evidence_ids}:
          UPDATE evidence SET verdict='false_positive' WHERE id = ANY($ids) AND user_id = c.user_id（ids 必须属于 case_evidence）
          c.state='dismissed', resolution='dismissed'
      no_action: c.state='resolved', resolution='no_action'
      sanction{actions}:
          require 1 ≤ len(actions) ≤ 6，同 kind 不重复
          for a in actions:
              perm = 矩阵(a.kind, ctx.is_protected)；require rbac.check(actor.user, perm)   ?: anticheat.action_not_allowed
              ctx.is_protected 且 a.kind ∈ {ban, disable_download, reset_passkey} → anticheat.target_protected
              a.kind = lock_wallet 且 ctx.ledger 不可用 → anticheat.action_unavailable
              a.kind = adjust_traffic：require 0 < a.up_bytes ≤ user_totals(c.user_id).uploaded   ?: anticheat.adjust_invalid
              until = a.days ? now + a.days×1d : (a.kind = warn ? warn_chain_until(user, warn.default_days) : null)
              state = (a.kind = ban 且 four_eyes_for_ban) ? 'proposed' : 'pending'
              INSERT sanctions(user_id, case_id, kind, state, until, params{up_bytes?}, decided_by = actor.user, decided_at = now)
              if a.kind ∈ {warn, adjust_traffic, reset_passkey}: ops.enqueue(...)（§1.9）
          c.state='resolved', resolution='sanctioned'
    c.resolved_at = now, resolved_by = actor.user, resolution_note = note, appeal_deadline = now + appeal.window_days
    UPDATE user_risk SET open_case_id = NULL；重算 transfer_blocked
    stats.on_resolution(c, contributing_rules(c))；INSERT case_events；audit("anticheat.resolve", "user:<u>", {case_id, decision, actions})
    publish anticheat.case_resolved{case_id, user_id, action = most_severe(actions) ?: none, actions[], resolution,
                                    false_positive = (decision = dismiss), by}
    effects.bump(c.user_id)
```

`warn_chain_until(user, days)`：`max(now, 现有生效警告的最晚 until) + days`（Gazelle 顺延语义）。

`most_severe` 顺序：`ban > disable_download > freeze_traffic > lock_wallet > adjust_traffic > reset_passkey > warn > none`。`contributing_rules(c)` = 决定时分数构成中贡献 ≥ 10% 的 enforce 规则。

**批准**（`approve(sanction_id, actor)`）：`s.state = 'proposed'`；`actor ≠ s.decided_by`（sysop 也不能自批，四眼不例外；站点关闭 `four_eyes_for_ban` 时不会出现 proposed）；需 `anticheat.sanctions.manage`；`UPDATE sanctions SET state='pending', approved_by, approved_at` → `effects.bump`。

**手动解除处置**（`lift(sanction_id, reason, actor)`）：权限同施加；`state ∈ {proposed, pending, active}` → `lifted`；`effects.bump`；发布 `sanction_changed{op: lifted}`；审计。

### 1.7 policies：自动处置与熔断

```
evaluate(user, s, rs):
    if not settings.auto_actions_enabled or settings.breaker.tripped: return
    ctx = context.get(user)；if ctx.is_protected: 记录 suggestion；return
    c = 进行中案件（on_score 已在 band ≥ high 时开案；结论性规则即使 band < high 也开案：opened_reason='score'）
    for p in rs.policies where p.auto and cond(p.when, s):
        if exists sanctions WHERE case_id = c.id AND policy_id = p.id: continue          -- 同案件同策略只执行一次
        n = SELECT count(*) FROM auto_action_log WHERE at > now − 1h
        if n + len(p.actions) > breaker.max_auto_per_hour:
            config 无法在 WASM 中写设置 → 写 kv "breaker" = {tripped_at, n}；metric；log error；记录 suggestion；return
        for a in p.actions: INSERT sanctions(…, state='pending', decided_by=NULL, policy_id = p.id, case_id = c.id, until = now + a.days)
        INSERT auto_action_log(user_id, case_id, policy_id, at = now, count = len(p.actions))
        case_events(kind='auto_action')；effects.bump(user)
```

- 熔断状态以 kv 键 `breaker` 为准（WASM 插件不能改自己的运行时设置）；`settings.breaker.tripped` 作为管理员手动熔断开关；两者任一为真即熔断。`POST /admin/breaker/resets` 删除 kv 键并审计。
- 自动处置不会关闭案件：案件仍为 `open` 等待复核；复核员可以维持（把自动处置纳入决定）或解除。`resolve` 时已有的自动处置保留，除非决定为 `dismiss`——此时该案件全部自动处置置 `lifted(lift_reason='dismissed')`。

### 1.8 sanctions 与 effects：期望状态协调

**效果映射**：

| 处置 kind | 效果 effect | 合成规则 |
|---|---|---|
| `ban` | `ban` | 任一永久 → 永久；否则最晚 until |
| `disable_download` | `leech` | 同上 |
| `freeze_traffic` | `freeze` | 最晚 until（必须有期限，默认 `freeze.default_days`） |
| `lock_wallet` | `wallet` | 存在即锁定 |
| `warn`、`adjust_traffic`、`reset_passkey` | 一次性操作（`effect_ops`） | — |

```
bump(user):                                           -- 在调用方事务内
    for eff in [ban, leech, freeze, wallet]:
        live = SELECT id, case_id, until, created_at FROM sanctions WHERE user_id=$1 AND kind = map⁻¹(eff) AND state IN ('pending','active')
        desired = live 为空 ? {active: false} : {active: true, until: 合成, case_id: 最新, reason_code: 'anticheat.'||case.primary_rule, since: min(created_at)}
        e = SELECT … FROM effects WHERE user_id=$1 AND effect=eff FOR UPDATE
        if e 为空 and not desired.active: continue
        if e.state = 'overridden' and 没有晚于 e.overridden_at 创建的 live 处置: continue     -- 尊重管理员的外部解除
        if e.desired == desired and e.state != 'overridden': continue
        UPSERT effects SET desired = desired, rev = rev + 1, state = 'pending', attempts = 0, next_attempt_at = now
    if 有任何 rev 变化或待执行 ops: schedule_once(run_effects, now, {user}, dedupe = "eff:<user>:<Σrev>:<ops 数>")
```

**run_effects**（延迟任务，tx manual）：

```
run_effects(user):
    for e in SELECT … FROM effects WHERE user_id=$1 AND applied_rev < rev AND state IN ('pending','retrying') AND next_attempt_at <= now ORDER BY effect:
        key = "ach:eff:<user>:<effect>:<rev>"
        r = match (e.effect, e.desired.active):
            (ban|leech, true)  → ctx.users.apply_restriction{user, kind, reason_code, note: "case:<case_id>", until, idempotency_key: key} → restriction_id
            (ban|leech, false) → ctx.users.lift_restriction(user, Some(kind), "anticheat.lifted", key)
            (freeze, true)     → ctx.accounting.set_rate_rule{external_ref: "freeze:<user>", scope: users([user]), up_permille: Some(0),
                                    down_permille: settings.freeze.down_permille, mode: override, priority: 1000000,
                                    starts_at: desired.since, ends_at: Some(desired.until), reason_term: Some("anticheat.freeze_traffic")} → rule_id
            (freeze, false)    → e.ext_ref 存在 ? ctx.accounting.remove_rate_rule(e.ext_ref, key) : ok
            (wallet, true)     → e.ext_ref 存在且未解锁 ? ok : ctx.ledger.lock_account{user, currency: None, reason: "anticheat.case",
                                    ref: "case:<case_id>", idempotency_key: key} → lock_id
            (wallet, false)    → ctx.ledger.unlock_account(e.ext_ref, key)
        match r:
            Ok(ext) → UPDATE effects SET applied_rev = rev, applied = desired, ext_ref = coalesce(ext, ext_ref), state = 'synced', last_error = NULL
                      UPDATE sanctions SET state='active', activated_at = now WHERE user_id AND kind = map⁻¹(effect) AND state='pending'
                      publish anticheat.sanction_changed{op: applied|lifted|expired} 对每个状态改变的处置
                      若 effect = ban 且 desired.active 且新施加：ops.enqueue(ban_notice)（§1.9，含申诉令牌）
            Err(e) if e.retryable 或 e.code ∈ {kernel.timeout, kernel.service_unavailable, kernel.resource_exhausted}
                    → attempts += 1；state = 'retrying'；next_attempt_at = now + min(2^attempts × 30 s, 1 h)；
                      schedule_once(run_effects, next_attempt_at, {user}, dedupe = "eff:<user>:<effect>:<rev>:<attempts>")
            Err(e)  → state = 'failed'；last_error = e.code；相关 pending 处置 → failed；publish sanction_changed{op: failed}
                      audit("anticheat.effect_failed", …)；metric effect_failures_total{effect, code}
        commit()
    ops.run(user)；commit()
```

- 服务未合入（A-8）时：`apply_restriction` 不存在 → 使用 `ctx.users.set_status(user, banned|leech_disabled, reason)` / `set_status(user, active, reason)`（catalog 方法，同来源同类型 upsert，天然幂等）；到期由本插件 `sanction_expire` 触发 `bump` 解除。
- `wallet` 只持有一个锁：`ext_ref` = lock_id；解锁后清空。
- 永久错误典型值：`identity.target_protected`、`identity.user_not_found`、`accounting.rate_rule_invalid`、`*.scope_denied` / `*.scope_required`（配置错误）。

**到期**：处置带 until 时在插入事务内 `schedule_once(sanction_expire, until, {sanction_id}, dedupe = "sx:<id>:<until_ms>")`；执行：`UPDATE sanctions SET state='expired' WHERE id=$1 AND state IN ('active','pending') AND until <= now RETURNING user_id` → 有行则 `bump`。`sanction_sweep`（cron `*/5`）以 `FOR UPDATE SKIP LOCKED LIMIT 500` 处理遗漏者；二者并发也只会有一个 UPDATE 生效。

**外部覆盖检测**：

```
on_restriction_changed(evt{user_id, restriction_id, kind, source, op}):
    if source != 'anticheat' or op != 'lifted': return
    e = effects(user_id, kind→ban|leech)
    if e.state = 'synced' and e.applied.active and e.ext_ref = restriction_id:    -- 本插件只在 desired 为 false 时解除
        UPDATE effects SET state='overridden', overridden_at = now
        UPDATE sanctions SET state='lifted', lift_reason='external_override' WHERE … state='active' AND kind 对应
        case_events(kind='external_override')；publish sanction_changed{op: lifted}；metric
```

`effect_reconcile`（cron `*/15`）：① 重新调度 `state='retrying' AND next_attempt_at <= now` 且无待执行任务的效果；② 抽样 200 个 `synced` 且 `applied.active` 的 ban/leech 效果调 `ctx.users.restrictions(user)`，缺失 anticheat 来源限制而本插件未解除 → 按外部覆盖处理（事件丢失的兜底）；③ `state='pending' AND updated_at < now − 10 min` → 重新调度。

### 1.9 ops：一次性外部操作与幂等键

| op | 触发 | 调用 | 幂等键 |
|---|---|---|---|
| `warn_notice` | warn 处置写入 | `ctx.messages.send_system(user, "anticheat.notice.warn_subject", "anticheat.notice.warn_body", {until, case_id, reason_term})`；messages 不可用时 `ctx.notify.send(user, "anticheat.warn", args, None)` | `ach:op:<op_id>`（A-11 合入前不传） |
| `sanction_notice` | freeze / wallet / leech 生效 | 同上，模板按 kind | 同上 |
| `ban_notice` | ban 生效 | 生成申诉令牌 → `ctx.notify.send(user, "anticheat.ban_notice", {appeal_link, until?}, Some(["email"]))` | 同上 |
| `adjust` | adjust_traffic 生效 | `ctx.accounting.adjust(user, −up_bytes, 0, "anticheat.fraud_revert", "ach:op:<op_id>")` | 同左 |
| `adjust_revert` | 申诉撤销 | `ctx.accounting.adjust(user, +applied_up, 0, "anticheat.fraud_revert_undo", "ach:op:<op_id>")` | 同左 |
| `compensate` | 申诉撤销且选择补偿 | `ctx.accounting.adjust(user, +bytes, 0, "anticheat.freeze_compensation", "ach:op:<op_id>")`，bytes 由复核员确认（建议值 = 冻结期内 `v_user_daily.uploaded_raw` 之和） | 同左 |
| `passkey_reset` | reset_passkey 生效 | `ctx.users.reset_passkey(user)` | 无（A-11）；op 成功后不再重试 |
| `appeal_result_notice` | 申诉决定 | messages / notify | `ach:op:<op_id>` |

```
ops.run(user):
    for o in SELECT … FROM effect_ops WHERE user_id=$1 AND state IN ('pending','retrying') AND next_attempt_at <= now ORDER BY id FOR UPDATE SKIP LOCKED:
        r = call(o)
        Ok(v)  → state='done', result=v, done_at=now（adjust 记录 applied_up = −adjust_result.applied_up）
        可重试 → attempts+1，退避（同 effects），≥ 8 次 → failed
        永久   → state='failed'（如 accounting.adjust_would_be_negative：用户已无足够上传，记录并提示复核员）
        commit()
```

**申诉令牌**：`token = base64url(HMAC-SHA256(static.appeal_token_secret, "appeal:" || op_id))`（43 字符），重试得到同一令牌；`appeal_tokens(token_hash = sha256(token), case_id, user_id, expires_at = now + token_ttl)` 与 op 同事务写入（`ON CONFLICT DO NOTHING`）；链接 `https://<site>/p/anticheat/appeal#t=<token>`（fragment 不发往服务器、不进 Referer）。`appeal_token_secret` 为 site.toml 静态配置（`x-pt-secret`），未配置时插件拒绝启动。

**幂等键汇总**：效果 `ach:eff:<user>:<effect>:<rev>`；一次性操作 `ach:op:<op_id>`；HTTP 写接口由内核 `Idempotency-Key` 处理，服务 `resolve` 由调用方传入键（MCP 网关使用 `mcp:<confirmation_id>`）。

### 1.10 appeals：申诉

```
submit(case_id, user, body, via):
    c = case(case_id)；c.user_id = user（session 方式）或令牌对应用户  ?: kernel.not_found
    c.resolution ∉ {sanctioned} → anticheat.appeal_not_allowed（no_action / dismissed 无需申诉）
    now > c.appeal_deadline → anticheat.appeal_window_closed
    count(appeals WHERE case_id AND state <> 'withdrawn') ≥ appeal.max_per_case → anticheat.appeal_limit_reached
    exists appeals WHERE case_id AND state IN ('submitted','in_review') → anticheat.appeal_exists
    body：1..=4000 字符，NFC、去控制字符（保留换行）
    INSERT appeals(case_id, user_id, state='submitted', body, via, created_at)
    publish anticheat.appeal_submitted{appeal_id, case_id, user_id, via}
    if appeal.suspend_sanctions: 案件全部 active / pending 处置（ban 除外）置 suspended → bump

submit_by_token(token, body):
    t = SELECT … FROM appeal_tokens WHERE token_hash = sha256(token) FOR UPDATE
    t 为空 或 t.used_at 非空 或 t.expires_at < now → anticheat.appeal_token_invalid（一律同一错误码与响应时间）
    UPDATE appeal_tokens SET used_at = now；submit(t.case_id, t.user_id, body, 'token')（窗口检查以令牌有效期为准）

decide(appeal_id, outcome, note, params, actor):
    a FOR UPDATE；a.state ∈ {submitted, in_review} ?: anticheat.appeal_state_invalid
    four_eyes_for_appeal 且 actor ∈ {case.resolved_by, 案件处置的 approved_by}（sysop 例外）→ anticheat.four_eyes_required
    require rbac(actor, anticheat.appeals.moderate)；撤销含 ban 的案件另需 anticheat.sanctions.manage
    match outcome:
      upheld   → 无变化
      reduced  → params.changes[{sanction_id, until? | lift: true}]：只能缩短或解除，不能加重   ?: anticheat.appeal_change_invalid
      overturned →
          sanctions WHERE case_id AND state IN (proposed, pending, active, suspended) → 'overturned'
          对已完成的 adjust op：ops.enqueue(adjust_revert, applied_up)
          params.compensate_bytes > 0：ops.enqueue(compensate)
          UPDATE evidence SET verdict='false_positive' WHERE id IN (case_evidence)；case.state='overturned', resolution='overturned'
          stats.on_overturn(case)；publish anticheat.case_resolved{resolution: overturned, false_positive: true, action: none, actions: []}
    a.state = outcome，decided_by，decided_at，decision_note
    effects.bump(user)；ops.enqueue(appeal_result_notice)；publish anticheat.appeal_decided；audit
```

申诉认领与案件认领相同（`appeals.assigned_to`、`claim_expires_at`）。

### 1.11 enrich：证据补全

`enrich_case`（延迟任务，payload `{case_id}`，dedupe `enrich:<case_id>`）：

```
c = case(case_id)；c.state != 'open' → return
refresh_hits(c.user_id)：
    page = ctx.accounting.signals(user, now − window, now, cursor)，最多 5 页
    UPDATE evidence SET hits = greatest(hits, $h), severity = greatest_sev(severity, $s)
        WHERE source='accounting' AND external_ref = 'signal:'||$id AND user_id = $u
    commit()
swarm 快照（ctx.tracker 可用时）：
    ts = 案件证据中按 details.bytes / user_uploaded 降序的前 enrich.top_torrents 个不同 torrent_id
    for t in ts:
        pl = ctx.tracker.peers(t, include_ip = 授权 peer.ip 且启用 FR-ACH-041)
        snap = pl.peers[:200].map(p → {user_id, client, seeder, uploaded, downloaded, left, last_announce_at})  -- 不含 ip、port、peer_id
        INSERT case_events(case_id, kind='swarm_snapshot', data={torrent_id, taken_at, peers: snap, truncated})
        if include_ip: shared_ip(c, t, pl)                                                            -- P2
    commit()
rescore_user(c.user_id, 'manual', auto_policies = false)
```

`shared_ip(c, t, pl)`（P2）：取该用户的 peer IP 集合 `A`，其他用户 peer 的 IP 集合按 `prefix(ip)`（IPv4 /24、IPv6 /48）分组；与 `prefix(A)` 相交的对端用户 ID 列表 `X`（排除自己）。`X` 非空时写证据 `anticheat.shared_ip_counterparty`，`details = {torrent_id, counterparty_user_ids: X[:20], prefix_len}`，`external_ref = sip:<case_id>:<t>`。IP 只存在于本次调用的内存中，不写日志、不进 details。

### 1.12 simulate：回测

```
create_simulation(version, params{window_days ≤ 90, as_of = now}):
    rs 必须为 draft 或 retired；同一版本已有 running 模拟 → anticheat.simulation_in_progress
    INSERT simulations(id = uuid_v7, ruleset_version, baseline_version = active.version, status='running', params, totals = {})
    schedule_once(simulate_batch, now, {sim_id, cursor: 0}, dedupe = "sim:<id>:0")
simulate_batch({sim_id, cursor}):
    sim = SELECT … FOR UPDATE；status != 'running' → return
    users = SELECT DISTINCT user_id FROM evidence WHERE occurred_at >= as_of − W AND user_id > cursor ORDER BY user_id LIMIT 300
    for u in users:
        a = compute(u, draft, as_of)；b = compute(u, baseline, as_of)          -- 上下文用当前缓存（近似，结果页注明）
        totals.bands_draft[a.band]++；totals.bands_base[b.band]++
        if a.band ≥ high > b.band: totals.would_open++；sample_open.push(u)（≤ 100）
        if b.band ≥ high > a.band: totals.would_close++；sample_close.push(u)（≤ 100）
        h = 该用户窗口内已决案件结论（sanctioned / dismissed / overturned）
        totals.confusion[h][a.band ≥ high]++                                    -- 估计准确率与召回
        for r in a.rules_hit: totals.rule_hits[r]++
        auto = draft.policies 中 auto 策略会触发的用户数 → totals.auto_actions++
    UPDATE simulations SET totals, cursor = last(users)；commit()
    if len(users) = 300: schedule_once(simulate_batch, now, {sim_id, cursor}, dedupe = "sim:<id>:<cursor>")
    else: status = 'done', finished_at = now, result = finalize(totals)        -- 估计准确率 = TP / (TP + FP)
```

单批 300 用户 × 2 次计算，每次 ≤ 2000 条证据，单批 < 20 s（NFR-ACH-014）。

### 1.13 stats：规则统计

- `stats.bump(version, rules, field)` / `on_resolution` / `on_overturn`：在决定事务内 `INSERT INTO rule_stats(version, rule_id, day, …) VALUES … ON CONFLICT DO UPDATE SET x = x + 1`。
- cron `rule_stats`（`5 * * * *`）：对上一小时新增证据按生效规则集做“仅匹配”计算，`hits = hits + n`，以 kv `rule_stats:<hour>` 标记已处理小时（重复运行跳过）；然后计算近 90 天每规则准确率 = confirmed / (confirmed + dismissed + overturned)，样本 ≥ 20 且低于 `stats.min_precision` 时 gauge `rule_precision` 低于阈值并告警。

### 1.14 hooks

```
handle(call):
    match call.hook:
      "ledger.before_transfer":
          i = call.input；op = i.operation ?: "transfer"
          if op ∉ settings.hooks.block_operations: return allow
          r = SELECT transfer_blocked FROM user_risk WHERE user_id = $1        -- 主键，只读
          r 为真 → deny{code: "anticheat.transfer_blocked", message: i18n("anticheat.hook.transfer_blocked")}
          否则 allow
      "checkin.before_check_in":
          if not settings.hooks.block_checkin_when_frozen: return allow
          r = SELECT EXISTS(SELECT 1 FROM effects WHERE user_id=$1 AND effect='freeze' AND (applied->>'active')::boolean)
          r → deny{code: "anticheat.checkin_blocked"}；否则 allow
```

- 不写任何表（钩子写入独立提交，但这里不需要）；不调用其他服务；不读取设置以外的配置。`config.get-settings()` 每次调用读取（内核缓存）。
- 拒绝消息不包含分数、案件号等细节（避免向付款方以外泄露调查信息：钩子 deny 会返回给发起转账的用户本人，消息为“账户正在接受审核，暂时无法转出”）。

### 1.15 privacy：用户删除与保留

`on_user_deleted`（`user.deleted`，tx manual）：

```
purge:
    schedule_once(purge_user_step, now, {user, step: 0}, dedupe = "purge:<event_id>")；return   -- 事件处理只登记
purge_user_step({user, step}):
    分批（每批 1000）：DELETE FROM evidence WHERE user_id = $1；DELETE FROM case_evidence WHERE case_id IN (该用户案件)
    DELETE FROM user_risk / user_context / seedbox_flags / risk_history / effects WHERE user_id = $1
    UPDATE appeals SET body = NULL WHERE user_id = $1；DELETE FROM appeal_tokens WHERE user_id = $1
    DELETE FROM case_notes WHERE case_id IN (该用户案件)
    UPDATE cases SET resolution_note = NULL, purged_at = now WHERE user_id = $1
    UPDATE case_events SET data = '{}' WHERE case_id IN (该用户案件)
    UPDATE effect_ops SET state = 'cancelled' WHERE user_id = $1 AND state IN ('pending','retrying')
    -- accounting 冻结规则：若 effects.freeze 已落地，调用 remove_rate_rule（键 "ach:purge:<user>:freeze"）清理
    每批 commit()；未完成则 schedule_once(purge_user_step, now, {user, step+1}, dedupe = "purge:<user>:<step+1>")
soft:
    UPDATE cases SET state='closed_user_deleted' WHERE user_id AND state='open'
    UPDATE sanctions SET state='lifted', lift_reason='user_deleted' WHERE user_id AND state IN ('proposed','pending')
    UPDATE effect_ops SET state='cancelled' WHERE user_id AND state IN ('pending','retrying')
    （active 处置保留：账号恢复时仍然有效）
```

其他用户案件的 swarm 快照中出现被删除用户 ID：快照随 `retention` 在 90 天后清空（`case_events.kind='swarm_snapshot'` 的 data 置空），不逐条回溯。

`retention`（cron `40 4 * * *`）：① `cases` 关闭超过 `retention.case_months` → 清空 `resolution_note`、删除 `case_notes`、`case_evidence.snapshot` 只保留 `{kind, severity, occurred_at}`；② swarm 快照 > 90 天置空；③ `appeal_tokens.expires_at < now − 7 d` 删除；④ `simulations.finished_at < now − 30 d` 删除；⑤ `explanations.created_at < now − 90 d` 删除。全部条件 UPDATE / DELETE 分批，重复运行幂等。证据表分区由内核按 `retention_months = 13` 删除。

### 2.1 服务接口（WIT）

```wit
package pt:anticheat@0.1.0;

interface anticheat {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms};

  enum risk-band { none, low, watch, high, critical }
  enum severity { low, medium, high }
  enum case-state { open, resolved, dismissed, overturned, closed-stale, closed-user-deleted }
  enum resolution { sanctioned, no-action, dismissed, overturned }
  enum sanction-kind { warn, freeze-traffic, lock-wallet, disable-download, ban, adjust-traffic, reset-passkey }
  enum sanction-state { proposed, pending, active, suspended, expired, lifted, overturned, failed }

  record risk-summary {
    user-id: user-id,
    score: u32,                       // 0..=100
    band: risk-band,
    under-review: bool,               // 存在进行中案件
    open-case-id: option<u64>,
    transfer-blocked: bool,
    active-sanctions: list<sanction-kind>,
    ruleset-version: u32,
    computed-at: option<timestamp-ms>, // 从未计算过为 none（此时 score = 0）
  }

  record case-filter {
    states: list<case-state>,         // 空 = 全部
    user: option<user-id>,
    bands: list<risk-band>,
    primary-rule: option<string>,
    assigned-to: option<user-id>,
    opened-from: option<timestamp-ms>,
    opened-to: option<timestamp-ms>,
  }

  record case-summary {
    id: u64, user-id: user-id, state: case-state, score: u32, peak-score: u32, band: risk-band,
    primary-rule: string, priority: u32, assigned-to: option<user-id>,
    opened-at: timestamp-ms, updated-at: timestamp-ms, resolution: option<resolution>,
  }
  record case-page { items: list<case-summary>, next-cursor: option<string> }

  record evidence-item {
    id: u64, kind: string, source: string, severity: option<severity>, hits: u32,
    torrent-id: option<u64>, details: string /* JSON */, occurred-at: timestamp-ms, false-positive: bool,
  }
  record sanction-info {
    id: u64, kind: sanction-kind, state: sanction-state, case-id: option<u64>,
    until: option<timestamp-ms>, decided-by: option<user-id>, approved-by: option<user-id>,
    policy-id: option<string>, created-at: timestamp-ms,
  }
  record case-detail {
    summary: case-summary,
    ruleset-version: u32,
    breakdown: string,                // JSON：[{rule, type, mode, score, evidence, top_torrents}]
    evidence: list<evidence-item>,    // ≤ 200，按时间降序
    sanctions: list<sanction-info>,
    timeline: string,                 // JSON：[{at, kind, actor?, data}]
    appeal-deadline: option<timestamp-ms>,
  }

  record action-spec {
    kind: sanction-kind,
    days: option<u32>,                // 1..=3650；ban / disable_download 为 none 表示永久
    up-bytes: option<u64>,            // 仅 adjust-traffic
  }
  variant decision {
    dismiss(list<u64>),               // 标记为误判的证据 ID（可为空）
    no-action,
    sanction(list<action-spec>),
  }
  record resolve-result { case-id: u64, state: case-state, sanctions: list<sanction-info>, duplicate: bool }

  record report-request {
    user: user-id,
    torrent-id: option<u64>,
    kind: string,                     // <caller>.<kind>
    severity: severity,
    details: string,                  // JSON 对象 ≤ 4 KiB
    occurred-at: timestamp-ms,
    idempotency-key: string,          // 1..=128 可见 ASCII
  }

  risk: func(user: user-id) -> result<risk-summary, plugin-error>;
  cases: func(filter: case-filter, cursor: option<string>, limit: u32) -> result<case-page, plugin-error>;
  %case: func(id: u64) -> result<case-detail, plugin-error>;
  resolve: func(case-id: u64, d: decision, note: string, idempotency-key: string) -> result<resolve-result, plugin-error>;
  report: func(req: report-request) -> result<u64, plugin-error>;
}
```

| 方法 | 作用域 | 说明 | 错误码 |
|---|---|---|---|
| `risk` | `read` | 用户不存在或无记录返回 score 0、band none | `anticheat.scope_required` |
| `cases` | `read` | limit ≤ 100；排序 `priority DESC, opened_at, id` | `kernel.bad_request`（游标） |
| `case` | `read` | 员工备注不返回（仅 HTTP 后台可见） | `anticheat.case_not_found` |

| `report` | `report` | §1.1 | `anticheat.report_invalid`、`anticheat.user_not_found`、`kernel.idempotency_key_reused` |

**POST `/v1/appeals:by-token`**（public，`ip:5/h`） `{ "token": "Qm9n…", "body": "…" }` → 201 `{ "appeal_id": 52 }`；无效 → 422 `anticheat.appeal_token_invalid`。**POST `/v1/appeals:lookup`** `{ "token": "…" }` → `{ "case": {同用户视图}, "appeal": {state, decided_at?} }`（令牌已用后仍可查看结果，直到过期）。

**POST `/v1/admin/appeals/51/decisions`**

```json

```

→ 200 `{ "appeal_id": 51, "state": "overturned", "case_state": "overturned" }`。`outcome = reduced` 时 `changes: [{ "sanction_id": 3302, "until": "…" }, { "sanction_id": 3303, "lift": true }]`。

**POST `/v1/admin/rulesets`**（idempotent） `{ "based_on": 1, "definition": { … }, "note": "提高交叉校验权重" }` → 201 `{ "version": 2, "status": "draft", "checksum": "sha256:…" }`；非法 → 422 `anticheat.ruleset_invalid`：

```json
  "errors": [ { "path": "/rules/3/match/where/0/op", "code": "anticheat.unknown_operator", "message": "未知运算符 regex" },
              { "path": "/thresholds/case", "code": "anticheat.threshold_order", "message": "case 必须大于 watch" } ] }
```

**POST `/v1/admin/rulesets/2/simulations`** `{ "window_days": 30 }` → 202 `Location: /api/p/anticheat/v1/admin/simulations/01928c…`；**GET** 结果：

```json

  "result": { "users": 41233, "bands": { "draft": { "none": 39010, "low": 1500, "watch": 512, "high": 160, "critical": 51 },
                                         "baseline": { "none": 39120, "low": 1450, "watch": 470, "high": 150, "critical": 43 } },

              "history": { "confirmed_flagged": 61, "confirmed_missed": 3, "false_positive_flagged": 9, "false_positive_cleared": 14 },
              "estimated_precision": 0.871, "rule_hits": { "cross_check": 9120, "cross_swarm": 233 },
              "samples": { "would_open": [10086, 20001], "would_close": [30010] } },
  "note": "上下文按当前缓存计算，可能与历史时点略有差异" }
```

**POST `/v1/admin/rulesets/2/activations`**（idempotent） `{ "note": "…" }` → 200 `{ "active_version": 2, "rescore": "scheduled" }`；`require_simulation_before_activate` 且无完成模拟（或模拟后草案被修改）→ 409 `anticheat.simulation_required`。

**GET `/v1/admin/rule-stats?version=1&days=90`** → `{ "items": [{rule_id, hits, cases_opened, confirmed, dismissed, overturned, precision, low_precision: bool}] }`。

**GET `/v1/admin/dashboard`** → `{open_cases, over_sla, oldest_waiting_hours, opened_24h, resolved_24h, auto_actions_1h, breaker: {tripped, since?}, appeals_pending, effects_failed}`。

**POST `/v1/admin/cases/{id}/explanations`** → 202 `{ "status": "queued" }`（llm 未启用 503 `anticheat.llm_unavailable`）；**GET `…/explanations/latest`** → `{ text, model, created_at, case_version, stale: bool }`。

其他：`POST /v1/admin/cases`（`{user_id, reason_note}` → 201 案件）；`POST /v1/admin/cases/{id}/notes`（`{text ≤ 2000}`）；`POST /v1/admin/users/{id}/evidence`（`{kind: "anticheat.manual", severity, torrent_id?, note}`）；`POST /v1/admin/sanctions/{id}/lifts`（`{reason_note}`）；`GET /v1/admin/watchlist`（band = watch，按分数降序）；`POST /v1/admin/breaker/resets`（`{note}`）。

鉴权：后台路由 `auth = "admin"` + 权限点；用户路由 `auth = "user"`；令牌路由 `auth = "public"`。所有写接口要求 CSRF（cookie 会话），决定、批准、规则集激活要求近期重新验证（security.md §3）。

## 3. 数据库设计

### 3.1 PostgreSQL（schema `anticheat`）

```sql
CREATE TABLE rulesets (
    version        integer PRIMARY KEY CHECK (version > 0),
    status         text NOT NULL CHECK (status IN ('draft','active','retired')),
    definition     jsonb NOT NULL CHECK (octet_length(definition::text) <= 65536),
    checksum       bytea NOT NULL,
    based_on       integer,
    note           text CHECK (char_length(note) <= 500),
    created_by     bigint,
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now(),
    activated_at   timestamptz,
    activated_by   bigint
);
CREATE UNIQUE INDEX rulesets_active_key ON rulesets ((true)) WHERE status = 'active';

CREATE TABLE evidence (
    id            bigint GENERATED BY DEFAULT AS IDENTITY,
    occurred_at   timestamptz NOT NULL,
    user_id       bigint NOT NULL,
    torrent_id    bigint,
    source        text NOT NULL CHECK (source ~ '^(accounting|anticheat|manual|plugin:[a-z][a-z0-9-]{1,31})$'),
    kind          text NOT NULL CHECK (char_length(kind) <= 64),
    severity      text CHECK (severity IN ('low','medium','high')),
    hits          integer NOT NULL DEFAULT 1 CHECK (hits >= 1),
    details       jsonb NOT NULL DEFAULT '{}' CHECK (octet_length(details::text) <= 4096),
    external_ref  text NOT NULL CHECK (char_length(external_ref) <= 160),
    verdict       text CHECK (verdict IN ('confirmed','false_positive')),
    note          text CHECK (char_length(note) <= 1000),
    created_by    bigint,
    created_at    timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (occurred_at, id)
) PARTITION BY RANGE (occurred_at);
CREATE UNIQUE INDEX evidence_source_ref_key ON evidence (source, external_ref, occurred_at);
CREATE INDEX evidence_user_time_idx ON evidence (user_id, occurred_at DESC, id DESC);
CREATE INDEX evidence_torrent_kind_idx ON evidence (torrent_id, kind, occurred_at DESC) WHERE torrent_id IS NOT NULL;
CREATE INDEX evidence_created_at_idx ON evidence (created_at);           -- rule_stats 按小时扫描

CREATE TABLE user_risk (
    user_id           bigint PRIMARY KEY,
    score             smallint NOT NULL DEFAULT 0 CHECK (score BETWEEN 0 AND 100),
    shadow_score      smallint NOT NULL DEFAULT 0 CHECK (shadow_score BETWEEN 0 AND 100),
    peak_score        smallint NOT NULL DEFAULT 0,
    band              text NOT NULL DEFAULT 'none' CHECK (band IN ('none','low','watch','high','critical')),
    tags              text[] NOT NULL DEFAULT '{}',
    breakdown         jsonb NOT NULL DEFAULT '[]',
    ruleset_version   integer NOT NULL,
    open_case_id      bigint,
    transfer_blocked  boolean NOT NULL DEFAULT false,
    evidence_truncated boolean NOT NULL DEFAULT false,
    computed_at       timestamptz NOT NULL,
    created_at        timestamptz NOT NULL DEFAULT now(),
    updated_at        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX user_risk_band_score_idx ON user_risk (band, score DESC) WHERE band <> 'none';
CREATE INDEX user_risk_positive_idx ON user_risk (user_id) WHERE score > 0 OR shadow_score > 0 OR open_case_id IS NOT NULL;

CREATE TABLE risk_history (
    user_id     bigint NOT NULL,
    at          timestamptz NOT NULL,
    from_band   text NOT NULL,
    to_band     text NOT NULL,
    score       smallint NOT NULL,
    ruleset_version integer NOT NULL,
    PRIMARY KEY (user_id, at)
);

CREATE TABLE user_context (
    user_id               bigint PRIMARY KEY,
    account_created_at    timestamptz NOT NULL,
    class_id              integer NOT NULL,
    is_protected          boolean NOT NULL,
    confirmed_cases_365d  integer NOT NULL DEFAULT 0,
    warnings_90d          integer NOT NULL DEFAULT 0,
    refreshed_at          timestamptz NOT NULL
);

CREATE TABLE seedbox_flags (
    user_id       bigint NOT NULL,
    torrent_id    bigint NOT NULL,
    is_seedbox    boolean NOT NULL,
    refreshed_at  timestamptz NOT NULL,
    PRIMARY KEY (user_id, torrent_id)
);

CREATE TABLE cases (
    id               bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id          bigint NOT NULL,
    state            text NOT NULL CHECK (state IN ('open','resolved','dismissed','overturned','closed_stale','closed_user_deleted')),
    opened_reason    text NOT NULL CHECK (opened_reason IN ('score','manual','report')),
    score_at_open    smallint NOT NULL,
    score            smallint NOT NULL,
    peak_score       smallint NOT NULL,
    band             text NOT NULL,
    primary_rule     text NOT NULL,
    ruleset_version  integer NOT NULL,
    priority         integer NOT NULL DEFAULT 0,
    prior_case_id    bigint REFERENCES cases (id),
    assigned_to      bigint,
    claim_expires_at timestamptz,
    resolution       text CHECK (resolution IN ('sanctioned','no_action','dismissed','overturned')),
    resolution_note  text CHECK (char_length(resolution_note) <= 2000),
    contributing_rules text[] NOT NULL DEFAULT '{}',
    resolved_by      bigint,
    resolved_at      timestamptz,
    appeal_deadline  timestamptz,
    purged_at        timestamptz,
    opened_by        bigint,
    opened_at        timestamptz NOT NULL DEFAULT now(),
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now(),
    version          integer NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX cases_user_open_key ON cases (user_id) WHERE state = 'open';
CREATE INDEX cases_queue_idx ON cases (priority DESC, opened_at, id) WHERE state = 'open';
CREATE INDEX cases_user_idx ON cases (user_id, opened_at DESC);
CREATE INDEX cases_resolved_idx ON cases (resolved_at) WHERE resolved_at IS NOT NULL;

CREATE TABLE case_evidence (
    case_id      bigint NOT NULL REFERENCES cases (id),
    evidence_id  bigint NOT NULL,
    snapshot     jsonb NOT NULL,                -- {kind, source, severity, hits, torrent_id, details, occurred_at}
    added_at     timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (case_id, evidence_id)
);

CREATE TABLE case_events (
    id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    case_id    bigint NOT NULL REFERENCES cases (id),
    at         timestamptz NOT NULL DEFAULT now(),
    kind       text NOT NULL CHECK (kind IN ('opened','evidence_added','band_changed','claimed','released','resolved','auto_action',
                                             'suggestion','sanction_changed','external_override','swarm_snapshot','appeal','explained','closed')),
    actor_user_id bigint,
    actor_plugin  text,
    data       jsonb NOT NULL DEFAULT '{}'
);
CREATE INDEX case_events_case_idx ON case_events (case_id, at);

CREATE TABLE case_notes (
    id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    case_id    bigint NOT NULL REFERENCES cases (id),
    author_id  bigint NOT NULL,
    text       text NOT NULL CHECK (char_length(text) BETWEEN 1 AND 2000),
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX case_notes_case_idx ON case_notes (case_id, created_at);

CREATE TABLE decision_requests (                -- 服务 resolve / 批准 / 申诉决定的幂等
    actor_key     text NOT NULL,                -- "<caller_plugin>:<actor_user_id>"
    key           text NOT NULL CHECK (char_length(key) BETWEEN 1 AND 128),
    request_hash  bytea NOT NULL,
    result        jsonb,
    created_at    timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (actor_key, key)
);

CREATE TABLE sanctions (
    id           bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id      bigint NOT NULL,
    case_id      bigint REFERENCES cases (id),
    kind         text NOT NULL CHECK (kind IN ('warn','freeze_traffic','lock_wallet','disable_download','ban','adjust_traffic','reset_passkey')),
    state        text NOT NULL CHECK (state IN ('proposed','pending','active','suspended','expired','lifted','overturned','failed')),
    until        timestamptz,
    params       jsonb NOT NULL DEFAULT '{}',   -- {up_bytes?}
    policy_id    text,
    decided_by   bigint,
    decided_at   timestamptz NOT NULL DEFAULT now(),
    approved_by  bigint,
    approved_at  timestamptz,
    activated_at timestamptz,
    lifted_by    bigint,
    lifted_at    timestamptz,
    lift_reason  text CHECK (char_length(lift_reason) <= 64),
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT sanctions_freeze_until_check CHECK (kind <> 'freeze_traffic' OR until IS NOT NULL)
);
CREATE INDEX sanctions_user_live_idx ON sanctions (user_id, kind) WHERE state IN ('proposed','pending','active','suspended');
CREATE INDEX sanctions_due_idx ON sanctions (until) WHERE state IN ('pending','active') AND until IS NOT NULL;
CREATE INDEX sanctions_case_idx ON sanctions (case_id);
CREATE UNIQUE INDEX sanctions_case_policy_key ON sanctions (case_id, policy_id, kind) WHERE policy_id IS NOT NULL;

CREATE TABLE effects (
    user_id          bigint NOT NULL,
    effect           text NOT NULL CHECK (effect IN ('ban','leech','freeze','wallet')),
    desired          jsonb NOT NULL,             -- {active, until?, case_id?, reason_code?, since?}
    rev              integer NOT NULL DEFAULT 0,
    applied          jsonb,
    applied_rev      integer NOT NULL DEFAULT 0,
    ext_ref          text,                        -- restriction_id / rate_rule_id / lock_id
    state            text NOT NULL CHECK (state IN ('synced','pending','retrying','failed','overridden')),
    attempts         integer NOT NULL DEFAULT 0,
    next_attempt_at  timestamptz NOT NULL DEFAULT now(),
    last_error       text,
    overridden_at    timestamptz,
    updated_at       timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, effect)
);
CREATE INDEX effects_unsynced_idx ON effects (next_attempt_at) WHERE state IN ('pending','retrying');

CREATE TABLE effect_ops (
    id               bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id          bigint NOT NULL,
    sanction_id      bigint REFERENCES sanctions (id),
    appeal_id        bigint,
    op               text NOT NULL CHECK (op IN ('warn_notice','sanction_notice','ban_notice','adjust','adjust_revert',
                                                 'compensate','passkey_reset','appeal_result_notice')),
    payload          jsonb NOT NULL DEFAULT '{}',
    state            text NOT NULL CHECK (state IN ('pending','retrying','done','failed','cancelled')),
    attempts         integer NOT NULL DEFAULT 0,
    next_attempt_at  timestamptz NOT NULL DEFAULT now(),
    result           jsonb,
    last_error       text,
    created_at       timestamptz NOT NULL DEFAULT now(),
    done_at          timestamptz
);
CREATE INDEX effect_ops_user_pending_idx ON effect_ops (user_id, id) WHERE state IN ('pending','retrying');
CREATE UNIQUE INDEX effect_ops_revert_key ON effect_ops (sanction_id, op) WHERE op IN ('adjust','adjust_revert','passkey_reset');

CREATE TABLE auto_action_log (
    id         bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id    bigint NOT NULL,
    case_id    bigint NOT NULL,
    policy_id  text NOT NULL,
    count      smallint NOT NULL,
    at         timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX auto_action_log_at_idx ON auto_action_log (at);

CREATE TABLE appeals (
    id               bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    case_id          bigint NOT NULL REFERENCES cases (id),
    user_id          bigint NOT NULL,
    state            text NOT NULL CHECK (state IN ('submitted','in_review','upheld','reduced','overturned','withdrawn')),
    via              text NOT NULL CHECK (via IN ('session','token')),
    body             text CHECK (char_length(body) <= 4000),
    assigned_to      bigint,
    claim_expires_at timestamptz,
    decided_by       bigint,
    decided_at       timestamptz,
    decision_note    text CHECK (char_length(decision_note) <= 2000),
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now(),
    version          integer NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX appeals_case_active_key ON appeals (case_id) WHERE state IN ('submitted','in_review');
CREATE INDEX appeals_queue_idx ON appeals (created_at) WHERE state IN ('submitted','in_review');

CREATE TABLE appeal_tokens (
    token_hash  bytea PRIMARY KEY CHECK (octet_length(token_hash) = 32),
    op_id       bigint NOT NULL UNIQUE,
    case_id     bigint NOT NULL REFERENCES cases (id),
    user_id     bigint NOT NULL,
    expires_at  timestamptz NOT NULL,
    used_at     timestamptz,
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE rule_stats (
    ruleset_version integer NOT NULL,
    rule_id         text NOT NULL,
    day             date NOT NULL,
    hits            integer NOT NULL DEFAULT 0,
    cases_opened    integer NOT NULL DEFAULT 0,
    confirmed       integer NOT NULL DEFAULT 0,
    dismissed       integer NOT NULL DEFAULT 0,
    overturned      integer NOT NULL DEFAULT 0,
    PRIMARY KEY (ruleset_version, rule_id, day)
);

CREATE TABLE simulations (
    id                uuid PRIMARY KEY,
    ruleset_version   integer NOT NULL REFERENCES rulesets (version),
    ruleset_checksum  bytea NOT NULL,             -- 激活检查：模拟后草案未修改
    baseline_version  integer NOT NULL,
    status            text NOT NULL CHECK (status IN ('running','done','failed','cancelled')),
    params            jsonb NOT NULL,
    cursor            bigint NOT NULL DEFAULT 0,
    totals            jsonb NOT NULL DEFAULT '{}',
    result            jsonb,
    created_by        bigint NOT NULL,
    created_at        timestamptz NOT NULL DEFAULT now(),
    finished_at       timestamptz
);
CREATE UNIQUE INDEX simulations_running_key ON simulations (ruleset_version) WHERE status = 'running';

CREATE TABLE explanations (
    id            bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    case_id       bigint NOT NULL REFERENCES cases (id),
    case_version  integer NOT NULL,
    model         text NOT NULL,
    text          text NOT NULL CHECK (char_length(text) <= 8000),
    created_by    bigint,
    created_at    timestamptz NOT NULL DEFAULT now(),
    UNIQUE (case_id, case_version)
);

CREATE TABLE torrent_baselines (                  -- P2：种子视角
    torrent_id    bigint PRIMARY KEY,
    confirmed_at  timestamptz NOT NULL,
    confirmed_by  bigint NOT NULL,
    note          text CHECK (char_length(note) <= 500)
);
```

清单分区声明：

```toml
[[database.partitions]]
table = "evidence"
by = "range_month"
premake = 2
retention_months = 13
```

**数据量估算**：证据日常 ≤ 5 万 / 天 → 13 个月 ≤ 2000 万行 × ~400 B（含索引约 2 倍）≈ 16 GB；异常洪峰（50 万 / 天）持续一周额外 350 万行。`user_risk` ≤ 有证据的用户数（估 5 万～10 万行）。`cases` ≤ 每日数十～数百。其余表很小。

### 3.2 Redis

不使用（DD-ACH-11）。批量任务游标与熔断状态存 kv：`spike:<yyyy-mm-dd>`、`decay:<scheduled_at>`、`rule_stats:<hour>`、`breaker`（JSON `{tripped_at, count}`）。

### 3.3 搜索索引贡献

无。

## 6. 安全设计

| 项 | 措施 |
|---|---|
| 权限 | 路由级权限由网关检查；处置种类、受保护用户、四眼在服务端 `decisions` 中再次用 `ctx.rbac.check` 检查（MCP 与服务调用同样适用） |
| 四眼 | 封禁批准人 ≠ 提议人；申诉复核人 ≠ 原决定人 / 批准人；sysop 不豁免封禁四眼（防止单人滥权），只豁免申诉四眼（小站可能只有一名 sysop，可在设置关闭） |
| 作用域 | `ctx.anticheat`：`read` / `write` / `report` 分离；`report` 种类前缀强制为调用方 ID，防止伪造 accounting 证据 |
| 规则集 | 只接受 schema 内的运算符与路径；无正则、无代码执行；激活需近期重新验证并审计前后校验和 |
| 申诉令牌 | 128 位以上熵（HMAC-SHA256），只存 SHA-256；一次性；fragment 传递；公开接口 `ip:5/h` 限流，失败统一错误码与固定延迟，防止枚举 |
| 用户可见信息 | 不暴露分数、阈值、规则 ID、员工备注、其他用户的 ID（swarm 快照只在后台） |
| 敏感数据 | 不申请 `user.email`；IP 只在 P2 关联的单次调用内存中使用；事件、日志、审计、指标、MCP、LLM 输入均不含 IP / passkey / 邮箱 / 申诉正文 |
| 输入 | 备注、申诉、note：NFC、去控制字符、长度限制；`details` 白名单字段与 4 KiB 上限；JSON 规则集 64 KiB |
| LLM | 只输入数值证据与规则构成，用户内容以“数据段”隔离；输出只作参考，不触发动作 |
| 审计 | `anticheat.resolve`、`anticheat.approve`、`anticheat.lift`、`anticheat.appeal_decide`、`anticheat.ruleset_create`、`anticheat.ruleset_activate`、`anticheat.breaker_reset`、`anticheat.evidence_manual`、`anticheat.effect_failed`；details 含案件、处置、前后状态，不含申诉正文 |
| 钩子 | 只读、无外部调用；拒绝消息不泄露调查细节 |

## 7. 性能设计

| 路径 | 设计 | 预期 |
|---|---|---|
| `on_signal` | 1 次证据 INSERT + 1 次窗口证据查询（索引 `evidence_user_time_idx`，≤ 2000 行）+ 上下文（缓存命中时 1 次主键查询）+ 规则计算 + `user_risk` upsert + 可能的案件写入 | p99 ≤ 200 ms；WASM 解析规则集 < 1 ms，计算 2000 条 × 20 规则 < 20 ms |
| `ledger.before_transfer` | 1 次主键查询；WASM 实例化（实例池） | p99 ≤ 20 ms |
| `rescore_decay` | 5 万用户 × ≤ 50 ms，分批 500 | ≤ 45 分钟（单副本串行；cron timeout 3600 s） |
| `rescore_batch`（激活） | 同上，延迟任务链式执行 | 5 万用户 ≤ 30 分钟 |
| `simulate_batch` | 300 用户 / 批，2 次计算 | 10 万条证据（约 2 万用户）≤ 10 分钟 |
| 队列列表 | `cases_queue_idx` 部分索引 | < 10 ms |
| 洪峰 | 订阅按 `user:<id>` 有序（同用户串行，跨用户并行，内核默认并发 8 / 分区）；若规则错误导致开案洪峰，熔断器只限制自动处置，评分照常 | 200 条 / 秒 |

容量见 §3.1。WASM 内存 64 MiB：单次最多加载 2000 条证据（每条 ≤ 4 KiB details → 上限约 8 MiB）。

| `sanctions_active` | gauge | `kind` |

日志：信号入库 debug（user_id、kind、signal_id）；决定与处置 info（case_id、kind、actor）；外部调用失败 warn（code，不含参数原文）；不记录申诉正文、备注、details 中的大字段。
