## 1. 种子视角（FR-ACH-042，P2）

**目标**：参照 UNIT3D 的 cheated torrents——按种子列出交叉校验超额最多的种子与被归因用户；复核后“确认基线”，之后重新计数。

**改动**（只在 anticheat）：

- 表 `torrent_baselines` 已在设计中（LLD §3.1），尚未建：新迁移 `0002_torrent_baselines.sql`。
- 查询：`evidence WHERE kind = 'cross_check_mismatch' AND occurred_at > coalesce(baseline.confirmed_at, now() - N days)` 按 `torrent_id` 汇总次数、`details.swarm_uploaded - swarm_downloaded` 之和、被归因用户（`user_id` 去重）。
- HTTP：`GET /v1/admin/torrents/suspicious?days=`、`POST /v1/admin/torrents/{id}/baselines`（`anticheat.cases.moderate`，审计）。
- 前端：后台增加“种子”标签页；种子标题经 `torrent.v_torrent_public`。

## 2. 处置：重置 passkey（FR-ACH-025，P2）

**目标**：怀疑 passkey 外泄或共用账号时由复核员重置。

**改动**：

- identity：新增服务方法 `ctx.users.reset_passkey(user, idempotency_key)`，作用域 `write:passkey`；复用用户自助重置的逻辑（已发布 `user.passkey_reset`，tracker-bridge 已处理换 passkey 删旧键）。幂等：同一键只重置一次，重放返回首次结果。
- anticheat：
  - 清单 `[capabilities.scopes] "ctx.users"` 加 `write:passkey`；
  - `decisions::resolve` 去掉 `reset_passkey` 的 `anticheat.action_unavailable` 分支；
  - `effects::exec_op` 的 `passkey_reset` 改为调用上述方法（幂等键 `ach:op:<op_id>`），`enqueue_for` 为 `reset_passkey` 登记操作；
  - 前端决定对话框的处置列表加入 `reset_passkey`。
- 文档：services.md `ctx.users` 增加方法与作用域。

## 3. 近期重新验证（security.md §3）

**目标**：封禁批准、复核决定、规则集激活、申诉决定要求近 15 分钟内验证过密码。

**现状**：内核已支持路由的 `reauth_secs`（检查会话的 `reauth_at`，不满足返回 `identity.reauth_required`）；登录时会写 `reauth_at`。缺少重新验证的接口与前端流程，因此 anticheat 暂未声明 `reauth_secs`（否则登录超过时限的管理员无法操作）。

**改动**：

- identity：`POST /v1/sessions/current/reauth`（`auth = "user"`，限流 `user:10/m`），请求 `{password, totp?}`；校验成功后 `UPDATE sessions SET reauth_at = now()`；失败计入登录失败限流；审计。
- web：在 SDK 的请求封装（`packages/sdk`）中统一处理 `identity.reauth_required`：弹出密码（与 2FA）对话框 → 调用上述接口 → 自动重试原请求；用户取消则把原错误抛给调用方。
- anticheat 清单：以下路由加回 `reauth_secs = 900`：`admin_resolve_case`、`admin_approve_sanction`、`admin_decide_appeal`、`admin_activate_ruleset`。
- 其他插件的敏感接口（identity 管理员改用户状态、修改密码等）可同时接入。
- 测试：e2e 中构造 `reauth_at` 过期的会话，验证 403 → 重新验证 → 成功。

## 4. 客户端指纹信号（FR-ACC-019，`client_not_allowed`）

**目标**：识别伪造客户端（peer_id 前缀与 User-Agent 不一致）与同一会话中途更换客户端。

**现状**：记账流已有 `pid`、`ua` 字段；accounting 的 `peers.client_prefix` 已保存 peer_id 前 8 字节；anticheat 默认规则已有 `client_spoof`（fingerprint_mismatch，权重 25）与 `client_changed`（fingerprint_changed，权重 8）。

**改动**（accounting）：

- 配置 `[plugin.accounting.signals]` 增加 `client_fingerprint_check`（默认 false）与 `client_families = [{family, peer_id_prefixes = ["-qB"], ua_regex = "^qBittorrent/"}]`（正则用 `regex` crate 编译，长度 ≤ 200）；内置 qBittorrent、Transmission、Deluge、libtorrent/rTorrent、µTorrent/BitComet 的默认映射。
- `ingest::parse` 保留 `ua`（截断 128，不入信号 details 原文，只记 `ua_family`）。
- `signals::evaluate`：
  - 前缀所属族 ≠ UA 所属族 → `client_not_allowed`，`details.kind = fingerprint_mismatch`，medium；
  - 同一 (uid, tid, pid) 的 `client_prefix` 与 `peers` 表已有记录不同 → `fingerprint_changed`，medium（需在 peers upsert 前读出旧前缀）。
- 上线建议：先把 anticheat 的 `client_spoof` 规则设为 `mode = shadow` 观察误判（客户端更新、改版 UA）后再改为 enforce。

## 5. 盒子识别（seedbox 插件）

**目标**：盒子（独服 / 托管 BT 机）上传速度天然高，超速类证据应降权（默认规则中 `ctx.is_seedbox` 时 ×0.5），H&R 也可据此豁免。参照 NexusPHP 的 seed_box 规则（登记 IP 段，非盒子限速）。

**设计**：见 `docs/plugins/seedbox/`（已有需求与设计文档）。要点：

- 登记：用户申请 / 管理员审核盒子的 IP 段（CIDR）或 ASN；后台管理。
- 判定数据：需要 peer IP。记账流的每条记录已有 `ip`，但 accounting 不保存。两种做法（实现时二选一，写入 seedbox HLD）：
  - A：seedbox 插件申请敏感能力 `peer.ip`，读取 accounting 新增的受限视图（如 `v_peer_ip`，仅对获授 `peer.ip` 的插件开放），按 (用户, 种子) 记录最近 IP 是否命中登记网段；
  - B：通过下文第 6 项的 `ctx.tracker.peers(include_ip = true)` 按需查询。
- 服务：`ctx.seedbox.is_seedbox(user, torrent)` 与批量 `is_seedbox_many(user, torrent_ids) -> list<u64>`（≤ 500，anticheat HLD §7 A-12）。

**anticheat 侧改动**：

- 清单 `optional_requires` 加 `ctx.seedbox@^0.1`；
- 迁移新增 `seedbox_flags(user_id, torrent_id, is_seedbox, refreshed_at)`（LLD §3.1 已定义）；
- `core::context` 按 LLD §1.3 对证据中的种子批量查询并缓存 24 h，填充 `Ctx.seedbox`；seedbox 未安装时保持空集合（现状）。

## 6. 同 IP 对端关联（FR-ACH-041，P2）

**目标**：识别小号互刷——上传方与下载方在同一网段。

**现状**：swarm 的 peer IP 只在 pt-tracker 的 Redis（`ps:{<info_hash>}` 中每个会话的 `ip` / `alt`）中，没有服务可读。anticheat 的 swarm 快照目前读 accounting 的 `v_swarm_peers`（不含 IP）。

**改动**：

- tracker-bridge（Native，已连接 tracker 的 Redis）：提供服务 `ctx.tracker@0.1.0`：
  - `peers(torrent_id, include_ip) -> {peers: [{user_id, peer_id_prefix, seeder, uploaded, downloaded, left, last_announce_at, ip?}], truncated}`，按种子 ID 查 info_hash 后读 `ps:{H}`；
  - `include_ip = true` 时要求调用方获授敏感能力 `peer.ip`（站点在 site.toml `[grants.<plugin>]` 授权），否则 `kernel.forbidden`。
- anticheat：
  - 清单 `optional_requires` 加 `ctx.tracker@^0.1`，`sensitive_optional = ["peer.ip"]`；
  - `jobs::enrich_case`：swarm 快照改用 `ctx.tracker.peers`（不可用时回退 `v_swarm_peers`）；
  - 获授 `peer.ip` 时实现 LLD §1.11 `shared_ip`：IPv4 按 /24、IPv6 按 /48 比较该用户与对端，命中则写证据 `anticheat.shared_ip_counterparty`（`details = {torrent_id, counterparty_user_ids[≤20], prefix_len}`，`external_ref = sip:<case_id>:<torrent_id>`）。**IP 只在本次调用的内存中使用**，不写日志、不入 details（DD-ACH-14）。
  - 默认规则 `shared_ip` 目前为 shadow，观察准确率后再改为 enforce。
- 本项完成后可进一步做多账号关联（design/09 中 anticheat 剩余项）。

## 不需要单独处理的项

- **申诉令牌密钥**：未配置时使用插件 kv 中生成的随机密钥，功能完整；需要固定密钥（多环境一致、可轮换）时在 site.toml `[plugin.anticheat] appeal_token_secret` 配置 ≥ 32 字节的随机值。轮换后已发出的申诉链接失效。
- **MCP 按参数锁定确认**：现为 `admin_resolve_anticheat_case` 整体锁定确认，比设计（仅含封禁 / 禁止下载时锁定）更严格；如需按参数锁定，要在内核 MCP 网关增加“工具按参数声明是否必须确认”的能力。
