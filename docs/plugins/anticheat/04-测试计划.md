## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元 | DSL 解析与校验（schema + 语义）、谓词求值（各运算符、`ref` 引用、类型不匹配）、命中函数、衰减、上限、聚合度量、乘数作用标签、分段、优先级、`warn_chain_until`、`most_severe`、期望效果合成、令牌生成 | `cargo test`（`wasm32-wasip2` 目标与原生目标各跑一次）、`proptest` |
| 参考模型 | `tests/model.py`（独立实现的评分参考）：对随机证据集与规则集计算分数与构成，与插件输出逐字段比对（确定性与正确性） | proptest + 差分测试 |
| 集成 | pt-testkit 内核宿主 + PG 17；identity、accounting、ledger 使用**契约桩**（`stub-identity`、`stub-accounting`、`stub-ledger`、`stub-messages`、`stub-notify`、`stub-seedbox`、`stub-tracker`、`stub-llm`），桩记录每次调用与幂等键，可注入超时 / 可重试错误 / 永久错误；端到端阶段替换为真实 accounting、identity、ledger | `pt-testkit` |
| 契约 | WIT `pt:anticheat@0.1.0` 可被 `wasm-tools` 解析、消费方桩可链接；事件载荷符合 `schemas/events/anticheat.*.v1.json`；`traffic.signal_raised`、`user.restriction_changed`、`user.deleted` 输入 schema；OpenAPI 与清单一致、`oasdiff`；MCP 输入输出 schema；规则集 schema | `jsonschema`、`wasm-tools`、`oasdiff` |
| 混沌 | 处置执行中随机让外部调用超时、在调用成功后提交前杀实例、延迟任务重复投递 | `xtask chaos-ach` |
| 性能 | 信号处理延迟、钩子延迟、洪峰吞吐、全量重算、模拟耗时 | `xtask loadgen-ach`、Prometheus |
| 安全 | 权限矩阵、四眼、作用域、令牌枚举、用户视图信息泄露、敏感字段扫描、LLM 输入审查、输入注入 | 集成 + 静态扫描 |
| 前端 | 队列、工作台、规则集编辑器、用户案件与令牌申诉页 | Vitest、Playwright |

## 2. 测试环境与数据

| 环境 | 配置 |
|---|---|
| CI 集成 | PG 17；1～3 个 pt-server 副本；默认规则集 v1（LLD §1.2）；`breaker.max_auto_per_hour = 5`（便于触发）；冻结 `ctx.time` |
| 端到端 | 真实 accounting + pt-tracker 原型 + identity + ledger；合成 announce 流注入作弊行为（RatioMaster 式虚报、无对端上传、指纹不符客户端） |
| 性能 | 3 副本（8 vCPU）；PG 17（16 vCPU）；预灌 2000 万条证据（13 个月）、10 万个 `user_risk`、1 万个历史案件 |

测试用户：`U1`（普通，账号 200 天）、`U2`（新号 5 天）、`UB`（登记盒子，`stub-seedbox` 对其种子返回 true）、`UM`（moderator 角色，受保护）；员工：版主 `M1`、`M2`（`anticheat.cases.moderate`、`anticheat.appeals.moderate`），管理员 `A1`、`A2`（另有 `anticheat.sanctions.manage`、`anticheat.rules.manage`），sysop `S`。测试插件作用域：`t-seedbox`：`ctx.anticheat` `report`；`t-reader`：`read`；`t-noscope`：无。

信号构造器：`signal(kind, severity, hits, torrent, details, first_at)` 生成 `traffic.signal_raised` 信封（`signal_id` 递增）。
