## 1. 引言

### 1.1 目的

定义签到插件 `checkin` 的功能与非功能需求，作为概要设计、详细设计和测试的依据。

### 1.2 范围

包含：

- 每日签到、连续签到（连签）统计、断签处理；
- 奖励曲线（基础奖励、连签递增、上限、里程碑奖励、可选随机奖励），数据驱动配置；
- 补签卡：持有、使用规则、发放接口（由 shop 售卖时调用）；
- 奖励经 `ctx.ledger` 发放，币种可配置；
- 签到排行（今日签到名次、连签榜），MCP 签到工具；
- 时区与日界线处理。

不包含：

- 商城售卖补签卡的流程（shop 负责，本插件只提供发放补签卡的服务方法）；
- 魔力值币种本身的注册与公式（bonus 负责）；
- 基于签到的勋章（medals 订阅 `checkin.checked_in` 自行实现）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 签到日 | 按站点时区划分的自然日，用 `YYYY-MM-DD` 表示 |
| 连签 | 截至某签到日，连续签到（含补签）的天数 |
| 补签 | 用补签卡为过去某个未签到的签到日补记签到 |
| 里程碑 | 连签达到特定天数（如 7、30、100、365）时的额外奖励 |

### 1.4 参考资料

- docs/platform/（平台契约，权威）、docs/design/、docs/process/plugin-doc-brief.md
- docs/plugins/ledger/、docs/plugins/terms/
- NexusPHP 1.7+ 签到（attendance）功能、各 NexusPHP 系站点的签到插件
- UNIT3D：无原生签到，社区以每日登录奖励（BON）替代

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM 插件，ID `checkin`，缩写 `CHKIN`。
- 提供：`ctx.checkin`（single）。
- 依赖：`ctx.ledger`（发奖励）、`ctx.users`（用户状态）、`ctx.terms`（奖励文案）。
- 拥有钩子点 `checkin.before_check_in`（anticheat 等处理）。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 每天点击签到领取奖励；查看连签天数、本月日历；用补签卡补签；通过 MCP 让 AI 助手代为签到 |
| 管理员 | 配置奖励曲线、里程碑、补签规则、币种；查看签到统计；为用户手动补发补签卡 |
| 其他插件 | shop 发放补签卡；medals 订阅签到事件颁发“全勤”勋章；anticheat 拦截可疑签到 |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP（1.7+ attendance） | 每日签到写 `attendance` 表，奖励 = 初始值 + 连签天数 × 增量，封顶；连签按“昨天是否签到”判断；补签卡（v1.7.x 起）可补回断签；奖励直接加到用户魔力值字段 | 规则简单、用户熟悉；补签卡增加商城消耗 | 奖励直接改用户表字段，无流水，难以对账；按服务器时区判断日界线，夜间跨日时并发重复签到靠唯一索引兜底；配置写死在设置项中，扩展里程碑需改代码 | **采纳**“初始值 + 连签递增 + 封顶”的曲线和补签卡；**改进**：奖励经 ledger 记账有流水；曲线、里程碑数据驱动；日界线固定按站点时区并在接口中返回 |
| NexusPHP 系第三方签到插件 | 随机奖励、签到排名奖励（前 N 名额外奖励）、签到附言 | 趣味性强 | 排名奖励引发“抢签到”脚本，夜间 0 点压力集中 | **采纳**随机奖励（可关闭）；**排名奖励默认关闭**，开启时只按名次展示、不额外加奖励，避免脚本抢签（可配置） |
| UNIT3D | 无签到；BON 按做种时长发放 | 鼓励做种而不是刷签到 | 缺少轻量日活手段 | 签到奖励默认较小，站点自行权衡；签到与做种奖励由不同插件负责，互不影响 |
| Gazelle | 无签到 | — | — | — |

### 2.4 约束与假设

1. 签到日按站点时区（`ctx.time.site_timezone()`）划分，不支持按用户个人时区（保证全站公平、排行可比）。
2. 奖励币种默认 `bonus`（由 bonus 插件注册）；本插件需要在清单中申请 `ctx.ledger` 的 `currency:<code>` 作用域。站点更换币种时需同步修改清单作用域并重启（D4）。
3. 每次调用新实例（WASM），状态全部在 PostgreSQL 与 Redis。
4. 规模：30 万用户，日签到率按 30% 估算，日签到约 9 万次；高峰集中在 0:00～0:10（按 20% 估算，约 30 次/秒）。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-CHKIN-001 | 每日签到 | 已登录且状态为 active / leech_disabled 的用户每个签到日可签到一次 | P0 | 同一签到日第二次签到返回 `checkin.already_checked_in`，不重复发奖励 |
| FR-CHKIN-002 | 连签计算 | 昨天（签到日 − 1）有签到记录则连签 + 1，否则连签重置为 1 | P0 | 构造连续/断开的签到序列，连签数正确 |
| FR-CHKIN-003 | 奖励曲线 | 奖励 = min(base + step × (streak − 1), cap)；参数后台可配置 | P0 | 配置变化后下一次签到按新参数计算 |
| FR-CHKIN-004 | 里程碑奖励 | 连签达到配置的天数（如 7/30/100/365）时额外发放奖励；同一用户同一连签周期内每个里程碑只发一次 | P1 | 达到 7 天时额外到账一次；断签后重新达到 7 天可再次获得 |
| FR-CHKIN-005 | 随机奖励 | 可选：在曲线奖励之外按配置概率加发随机额外奖励；默认关闭 | P2 | 开启后统计 1 万次签到，命中率与配置相差 < 2 个百分点 |
| FR-CHKIN-006 | 奖励记账 | 奖励通过 `ctx.ledger.transfer`（系统发行）发放，原因码 `checkin.daily` / `checkin.milestone` / `checkin.random` | P0 | ledger 流水可查到对应分录，幂等键重放不重复入账 |
| FR-CHKIN-007 | 签到钩子 | 签到前触发 `checkin.before_check_in`，被拒绝时不记录签到 | P1 | anticheat 拒绝时返回其错误码，数据库无记录 |
| FR-CHKIN-008 | 签到事件 | 签到成功后发布 `checkin.checked_in` | P0 | 订阅方收到 `user_id, date, streak, reward` |
| FR-CHKIN-009 | 补签卡持有 | 记录每个用户的补签卡数量；可由服务方法发放、管理员调整 | P1 | 发放与扣减有流水，余额不为负 |
| FR-CHKIN-010 | 补签 | 用户可对过去 `makeup_window_days`（默认 7）天内未签到的某一天使用一张补签卡补签；补签日不能早于用户注册日 | P1 | 补签后该日有记录，连签按新序列重算；超窗口返回 `checkin.makeup_out_of_window` |
| FR-CHKIN-011 | 补签奖励 | 补签是否发放当日基础奖励可配置（默认不发，只恢复连签） | P2 | 配置为不发时补签不产生 `checkin.daily` 分录 |
| FR-CHKIN-012 | 补签重算连签 | 补签填补断点后，从补签日起向后重算连签，当前连签更新；里程碑按重算后的结果补发（未发过的） | P1 | 断一天后补签，当前连签恢复为两段之和 |
| FR-CHKIN-013 | 状态查询 | 查询自己今日是否已签到、当前连签、最长连签、累计签到天数、补签卡数量、下一次奖励预估 | P0 | 接口返回值与数据库一致 |
| FR-CHKIN-014 | 签到日历 | 查询自己某月每天的签到情况（签到 / 补签 / 未签） | P1 | 返回该月全部日期 |
| FR-CHKIN-015 | 排行 | 今日签到名次（第几个签到）、连签榜前 100 | P2 | 名次与签到顺序一致；榜单每 5 分钟刷新 |
| FR-CHKIN-016 | 管理配置 | 管理员在后台配置曲线、里程碑、随机奖励、补签规则、币种显示 | P0 | 设置页由 settings_schema 生成，校验失败拒绝保存 |
| FR-CHKIN-017 | 管理统计 | 管理员查看每日签到人数、发放总额、补签次数 | P2 | 与数据库聚合结果一致 |
| FR-CHKIN-018 | 发放补签卡服务 | `grant_makeup_cards(user_id, n, reason, idempotency_key)`，供 shop 履约与管理员使用 | P1 | 同一幂等键重复调用只发放一次 |
| FR-CHKIN-019 | MCP 签到 | 提供 MCP 工具 `check_in`（写操作，站点可免确认） | P2 | 通过 MCP 调用签到成功，审计可见 credential |
| FR-CHKIN-020 | 用户删除 | 订阅 `user.deleted`，purge 模式下删除该用户签到数据 | P1 | purge 后查询不到该用户记录 |
| FR-CHKIN-021 | 被封禁用户 | `banned`、`pending`、`deleted` 用户不能签到 | P0 | 返回 `checkin.not_allowed` |
| FR-CHKIN-022 | 断签提醒 | 可选：用户当天未签到且连签 ≥ N 天时，在 20:00 通过 notify 提醒（默认关闭） | P2 | 开启后只提醒满足条件的用户，每人每天最多一次 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-CHKIN-001 | 性能 | 签到接口延迟 | p99 < 150 ms（不含钩子处理者耗时） |
| NFR-CHKIN-002 | 性能 | 状态查询（含首页小部件） | p99 < 30 ms；命中 Redis 位图 |
| NFR-CHKIN-003 | 容量 | 签到记录 | 每年约 1.1 亿行，按月分区，保留 13 个月 |
| NFR-CHKIN-004 | 可靠性 | 幂等 | 同一用户同一签到日只产生一条记录、一笔奖励；网络重试不重复发放 |
| NFR-CHKIN-005 | 可靠性 | 奖励与记录一致 | 签到记录与 ledger 分录最终一致；ledger 调用失败时签到失败或由补偿任务补发，不出现“有奖励无记录” |
| NFR-CHKIN-006 | 并发 | 0 点高峰 | 30 次/秒持续 10 分钟无错误 |
| NFR-CHKIN-007 | 安全 | 防脚本 | 签到接口按用户限流 10 次/分钟；可选验证码交给钩子处理者 |
| NFR-CHKIN-008 | 可观测性 | 指标 | 签到次数、奖励总额、钩子拒绝次数、ledger 失败次数 |
| NFR-CHKIN-009 | 可配置性 | 曲线与里程碑 | 后台修改即时生效，无需重启 |

## 5. 可配置项与站点术语

运行时设置（后台可改）：

| 配置键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | true | 关闭后签到接口返回 `checkin.disabled` |
| `currency` | string | `"bonus"` | 奖励币种（必须在清单作用域内） |
| `reward.base` | integer | 10 | 第 1 天奖励（最小单位） |
| `reward.step` | integer | 2 | 每多连签一天增加 |
| `reward.cap` | integer | 100 | 单日曲线奖励上限 |
| `milestones` | array<{days, amount}> | `[{7,50},{30,300},{100,1000},{365,5000}]` | 里程碑 |
| `random.enabled` | bool | false | 随机奖励 |
| `random.probability_permille` | integer | 50 | 命中概率（‰） |
| `random.min` / `random.max` | integer | 10 / 100 | 随机额外奖励范围 |
| `makeup.enabled` | bool | true | 补签开关 |
| `makeup.window_days` | integer | 7 | 可补签的最大回溯天数 |
| `makeup.grant_daily_reward` | bool | false | 补签是否发当日基础奖励 |
| `makeup.max_per_month` | integer | 3 | 每月最多补签次数 |
| `ranking.enabled` | bool | true | 显示今日名次与连签榜 |
| `reminder.enabled` | bool | false | 断签提醒 |
| `reminder.min_streak` | integer | 7 | 连签达到多少天才提醒 |

静态配置（site.toml `[plugin.checkin]`）：无必填项；`ranking_top_n`（默认 100）。

术语：

| 术语键 | 默认中文 | 默认英文 |
|---|---|---|
| `checkin.name` | 签到 | Check-in |
| `checkin.streak` | 连续签到 | Streak |
| `checkin.makeup_card` | 补签卡 | Make-up Card |
| `checkin.makeup` | 补签 | Make-up Check-in |

## 6. 外部接口需求概述

- 用户界面：首页小部件（签到按钮、连签、奖励预估）、`/p/checkin/` 页面（日历、补签、排行）、后台设置页。
- HTTP API：`/api/p/checkin/v1/*`（签到、状态、日历、补签、排行、管理统计、管理补签卡调整）。
- 服务：`ctx.checkin`（`status`、`check_in`、`grant_makeup_cards`、`makeup_cards`）。
- 事件：发布 `checkin.checked_in`、`checkin.made_up`、`checkin.makeup_cards_changed`；订阅 `user.deleted`。
- MCP：`check_in`、`get_my_checkin`。
