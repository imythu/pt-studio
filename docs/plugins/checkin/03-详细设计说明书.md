## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/checkin/`（Rust + `wit-bindgen`），`kind = "wasm"`；每次调用新实例，状态全部在 PG schema `checkin` 与 Redis 前缀 `p:checkin:`。
- 时间：`time.now()`（毫秒）；站点时区 `time.site_timezone()`（IANA 名）。日期类型在 PG 中为 `date`，在接口中为 `YYYY-MM-DD` 字符串。
- 所有 SQL 参数化；所有金额为 ledger 最小单位的整数（`i64`）。
- 设置读取：`config.get_settings()` 每次调用读取（内核缓存），解析失败时使用默认值并记 `warn`。
- 幂等表：服务方法与 HTTP `Idempotency-Key` 以 `(scope, key)` 为主键写 `idempotency`，与业务同事务。

### 1.1 calendar

```
fn today(now_ms, tz) -> Date          // 用 chrono-tz 把 now 转为站点时区本地日期
fn day_bounds(day, tz) -> (start_ms, end_ms)   // 夏令时切换日仍按本地 00:00 计算
fn month_days(yyyy_mm) -> Vec<Date>
```

时区数据随 `chrono-tz` 编译进组件（MIT/Apache）；时区变更（site.toml 改时区）只影响之后的签到，历史记录保留原日期。

### 1.2 checkin（签到主流程）

```
fn check_in(uid, idem_key, via) -> Result<CheckinResult>:
  s = settings()
  if !s.enabled: err(checkin.disabled)
  user = users.get(uid)? ; if user.status ∉ {active, leech_disabled}: err(checkin.not_allowed)
  day = calendar::today(now, tz)

  if idem_key: if let Some(r) = idempotency.get("check_in", uid, idem_key): return r

  // 快速路径（仅优化）：位图已置位且 PG 有记录 → already
  if redis.GETBIT("day:"+day, uid) == 1 && records.exists(uid, day): err(checkin.already_checked_in)

  outcome = hooks.run("checkin.before_check_in", {version:1, actor, user_id: uid, kind:"daily", date: day})
  if Denied(code,msg): err(code,msg)

  st = lock_state(uid)                                  // §1.6 的 SQL
  if st.last_day == day: err(checkin.already_checked_in)
  streak = if st.last_day == day - 1 { st.streak + 1 } else { 1 }
  cycle_start = if streak == 1 { day } else { st.cycle_start }

  r = reward::compute(s, streak, cycle_start, awarded = milestones_awarded(uid, cycle_start))
  // r = {daily, milestone: Option<(days, amount)>, random: Option<amount>, total}

  INSERT INTO records(user_id, day, kind, streak_after, reward_daily, reward_milestone, milestone_days,
                      reward_random, currency, payout_status, created_at, via)
       VALUES (..., 'daily', streak, ..., 'pending', now, via)
       ON CONFLICT (user_id, day) DO NOTHING RETURNING id
  if no row: err(checkin.already_checked_in)

  UPDATE user_state SET streak=streak, longest=max(longest,streak), total_days=total_days+1,
         last_day=day, cycle_start=cycle_start, updated_at=now WHERE user_id=uid
  if r.milestone: INSERT INTO milestones_awarded(user_id, cycle_start, days, day_awarded) ON CONFLICT DO NOTHING

  if r.total > 0:
     jobs.schedule_once("pay_reward", now + 30s, {record_id, user_id: uid, day}, dedupe_key = uid+":"+day)
     payout::try_pay(record) → 成功则 UPDATE records SET payout_status='paid', entry_ids=…
  else: UPDATE records SET payout_status='none'

  rank = redis.INCR("rank:"+day)（失败忽略，rank = None）；EXPIRE 172800
  events.publish({type:"checkin.checked_in", key:"user:"+uid,
                  payload:{user_id, date: day, streak, reward: r.total, currency, milestone_days, made_up:false}})
  result = {date, streak, rank, reward: {total, daily, milestone, random, currency, status}}
  if idem_key: idempotency.put(...)
  // 提交由内核在返回 ok 时完成；提交后缓存操作在下一次读取时自愈（见 §1.7）
  redis.SETBIT("day:"+day, uid, 1); EXPIRE 172800; redis.DEL("st:"+uid)
  return result
```

注意：Redis 写在事务提交之前执行（WASM 无提交后回调）。若事务随后回滚，位图可能误置位；快速路径因此必须同时确认 PG 记录（见上），位图仅用于首页展示，误差在下一次 `status` 查询时由 PG 修正（§1.7）。

### 1.3 reward（纯函数）

```
fn compute(s, streak, cycle_start, awarded: Set<u32>) -> Reward:
  daily = min(s.reward.base + s.reward.step * (streak - 1), s.reward.cap)   // i64 饱和运算
  milestone = s.milestones.iter().find(|m| m.days == streak && !awarded.contains(m.days))
  random = if s.random.enabled && rand_permille() < s.random.probability_permille
              { Some(uniform(s.random.min ..= s.random.max)) } else { None }
  total = daily + milestone.amount + random
```

- `rand_permille()`：`random.bytes(4)` 转 u32 后 `% 1000`；`uniform` 用拒绝采样避免取模偏差。
- 设置校验（settings_schema）：`base ≥ 0`、`step ≥ 0`、`cap ≥ base`、里程碑 `days` 唯一且 ∈ [2, 3650]、`amount ≥ 0`、`random.min ≤ random.max`、所有金额 ≤ 10^12。

### 1.4 payout

```
fn try_pay(rec) -> Result<()>:
  parts = [("checkin.daily", rec.reward_daily), ("checkin.milestone", rec.reward_milestone), ("checkin.random", rec.reward_random)]
  for (reason, amt) in parts where amt > 0:
     ledger.transfer({currency: rec.currency, from_user: None, to_user: Some(rec.user_id), amount: amt,
                      reason, memo: rec.day, idempotency_key: "checkin:" + reason_suffix + ":" + uid + ":" + day})
  // 任一失败 → 返回 Err，记录保持 pending

job pay_reward(payload):
  rec = SELECT … FROM records WHERE id = payload.record_id FOR UPDATE
  if rec is None or rec.payout_status != 'pending': return ok      // 已支付或事务已回滚
  match try_pay(rec):
    Ok  → UPDATE payout_status='paid'
    Err(retryable) → attempts+1；attempts < 12 时 jobs.schedule_once("pay_reward", now + backoff(attempts), …)
                    否则 UPDATE payout_status='failed'；metrics；审计
    Err(non-retryable：currency_not_allowed / currency_disabled) → payout_status='failed'
```

`backoff(n) = min(30s × 2^n, 6h)`。`failed` 的记录在管理统计页显示，管理员可点“重试发放”（`POST /admin/records/{id}/retry`），沿用同一幂等键。

### 1.5 makeup（补签卡与补签）

**补签卡变更**（`grant` / `use` / `admin_adjust`）：

```
fn change_cards(uid, delta, reason, idem_scope, idem_key) -> u32:
  if idempotency hit: return 首次结果
  st = lock_state(uid)
  new = st.makeup_cards + delta ; if new < 0: err(checkin.no_makeup_card)
  if new > 9999: err(checkin.makeup_cards_limit)
  UPDATE user_state SET makeup_cards = new
  INSERT card_log(user_id, delta, balance_after, reason, created_at)
  events.publish(checkin.makeup_cards_changed {user_id, delta, balance: new, reason})
  return new
```

**补签**：

```
fn make_up(uid, date) -> MakeupResult:
  s = settings(); if !s.makeup.enabled: err(checkin.makeup_disabled)
  today = calendar::today()
  if !(today - s.makeup.window_days <= date <= today - 1): err(checkin.makeup_out_of_window)
  if date < local_date(user.created_at): err(checkin.makeup_before_registration)
  hooks.run(checkin.before_check_in, {kind:"makeup", date})
  st = lock_state(uid)
  if st.makeups_this_month(today) >= s.makeup.max_per_month: err(checkin.makeup_monthly_limit)
  INSERT records(kind='makeup', day=date, payout_status=…) ON CONFLICT DO NOTHING → 无行则 err(checkin.already_checked_in)
  change_cards(uid, -1, "checkin.makeup:"+date, …)        // 同一事务
  (streak_now, new_cycle_start, segment) = recompute_streak(uid, date)  // §1.6
  UPDATE user_state SET streak=streak_now, longest=max(longest, segment.len), cycle_start=new_cycle_start,
                        total_days+1, makeup_month=…, makeup_count_month=…
  补发：对 segment 内每个里程碑 m（m.days ≤ segment.len）若 (cycle_start = segment.start, m.days) 未发 → 记入 milestones_awarded，金额并入本次 reward_milestone
  if s.makeup.grant_daily_reward: reward_daily = 曲线(该日在 segment 中的序号)
  调度 pay_reward（dedupe_key = uid+":"+date），try_pay
  events.publish(checkin.made_up {user_id, date, streak_after: streak_now})
```

### 1.6 连签重算与锁

**锁定用户状态**：

```sql
INSERT INTO checkin.user_state (user_id) VALUES ($1) ON CONFLICT (user_id) DO NOTHING;
SELECT user_id, streak, longest, total_days, last_day, cycle_start, makeup_cards,
       makeup_month, makeup_count_month
  FROM checkin.user_state WHERE user_id = $1 FOR UPDATE;
```

**recompute_streak(uid, date)**：补签填入 `date` 后，找出包含 `date` 的连续段：

```sql
-- 向前：从 date-1 往回找连续存在的日期（最多回看 window + 3650 天，实际受 segment 长度限制）
WITH RECURSIVE back(d) AS (
  SELECT $2::date - 1 WHERE EXISTS (SELECT 1 FROM checkin.records WHERE user_id=$1 AND day=$2::date - 1)
  UNION ALL
  SELECT d - 1 FROM back WHERE EXISTS (SELECT 1 FROM checkin.records WHERE user_id=$1 AND day=d - 1)
) SELECT min(d) FROM back;
-- 向后：同理找到 max(d)
```

- `segment = [start, end]`；若 `end == last_day`（段延伸到最近一次签到），则 `streak_now = end - start + 1`、`cycle_start = start`；否则当前连签不变（补的是更早的断点），只更新 `longest`。
- 递归查询使用 `records_user_day_idx`；最长连签 3650 天时约 3650 次索引探测，补签频率低，可接受。

### 1.7 stats 与 cache

**status(uid)**：

```
c = redis.HGETALL("st:"+uid)
if c 非空 且 c.day == today: return c
st = SELECT … FROM user_state WHERE user_id = uid
checked_today = st.last_day == today
next_reward = if checked_today { 预估明天：compute(streak+1) 的 daily } else { compute(streak_if_today) 的 daily }
redis.HSET("st:"+uid, …, "day", today); EXPIRE 600
if checked_today != GETBIT(day:today, uid): SETBIT 修正
```

**日历**：`SELECT day, kind FROM records WHERE user_id=$1 AND day BETWEEN $2 AND $3`（月份 ≤ 31 行）。

**排行**：
- 今日名次：签到时 `INCR rank:<day>` 得到；查询时从 `records` 当日 `ORDER BY created_at` 计算不必要，直接返回签到时保存的 `rank`（存入 `records.rank`）。
- 连签榜：`refresh_ranking` 每 5 分钟执行
  `SELECT user_id, streak FROM user_state WHERE last_day >= $today - 1 ORDER BY streak DESC, user_id LIMIT $n`，
  结果连同用户名（`identity.v_user_public`）写入 `streak_top`（JSON，TTL 15 min）。

### 1.8 lifecycle

- `on_user_deleted`：`mode = purge` → `DELETE FROM records WHERE user_id`（逐分区）、`user_state`、`milestones_awarded`、`card_log`；`soft` → 只 `DEL st:<uid>`。幂等：重复删除无影响。
- `daily_rollup`（tx manual）：`INSERT INTO daily_stats SELECT day, count(*), sum(...), count(*) FILTER (kind='makeup') FROM records WHERE day = $yesterday GROUP BY day ON CONFLICT (day) DO UPDATE`。
- `remind_streak`（tx manual，分批 1000）：查询 `last_day = today - 1 AND streak >= min_streak`，排除今日已签到；对每个用户 `notify.send(uid, "checkin.reminder", {streak}, None)`，幂等键 `checkin.remind:<uid>:<today>`。
- 分区：`records` 由内核按月预建 3 个分区、保留 13 个月（清单 `[[database.partitions]]`）。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:checkin@0.1.0`）

文件 `plugins/wasm/checkin/wit/checkin.wit`：

```wit
package pt:checkin@0.1.0;

interface checkin {
  use pt:plugin/types@0.1.0.{plugin-error, user-id, timestamp-ms};

  record reward {
    total: s64, daily: s64, milestone: s64, milestone-days: option<u32>, random: s64,
    currency: string,
    /// "paid" | "pending" | "none"
    status: string,
  }
  record checkin-status {
    checked-today: bool, today: string, streak: u32, longest: u32, total-days: u32,
    makeup-cards: u32, next-reward: s64, currency: string, today-rank: option<u32>,
  }
  record checkin-result { date: string, streak: u32, rank: option<u32>, reward: reward }

  status: func(user: user-id) -> result<checkin-status, plugin-error>;
  check-in: func(user: user-id, idempotency-key: string) -> result<checkin-result, plugin-error>;
  makeup-cards: func(user: user-id) -> result<u32, plugin-error>;
  grant-makeup-cards: func(user: user-id, n: u32, reason: string, idempotency-key: string) -> result<u32, plugin-error>;
}
```

| 方法 | 作用域 | 说明 | 错误码 |
|---|---|---|---|
| `status` | — | 对任意用户可查（调用方自行做权限判断） | `kernel.not_found` |
| `check-in` | `write` | 代 `user` 签到；actor 原样传入钩子 | 同 HTTP `check_in` |
| `makeup-cards` | — | | |
| `grant-makeup-cards` | `grant` | n ∈ [1, 100]；`reason` 为原因码；幂等键在 `(caller_plugin, key)` 范围内唯一 | `checkin.makeup_cards_limit`、`kernel.idempotency_key_reused` |

所有响应遵循 conventions/api.md；错误为 problem+json。

## 3. 数据库设计

### 3.1 PostgreSQL（schema `checkin`）

```sql
CREATE TABLE checkin.user_state (
    user_id             bigint PRIMARY KEY,
    streak              integer NOT NULL DEFAULT 0,
    longest             integer NOT NULL DEFAULT 0,
    total_days          integer NOT NULL DEFAULT 0,
    last_day            date,
    cycle_start         date,
    makeup_cards        integer NOT NULL DEFAULT 0 CHECK (makeup_cards >= 0),
    makeup_month        char(7),             -- 'YYYY-MM'，makeup_count_month 所属月份
    makeup_count_month  integer NOT NULL DEFAULT 0,
    updated_at          timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX user_state_streak_idx ON checkin.user_state (streak DESC, user_id) WHERE last_day IS NOT NULL;

CREATE TABLE checkin.records (
    id                bigint GENERATED ALWAYS AS IDENTITY,
    user_id           bigint NOT NULL,
    day               date NOT NULL,
    kind              text NOT NULL CHECK (kind IN ('daily', 'makeup')),
    streak_after      integer NOT NULL,
    rank              integer,
    reward_daily      bigint NOT NULL DEFAULT 0,
    reward_milestone  bigint NOT NULL DEFAULT 0,
    milestone_days    integer,
    reward_random     bigint NOT NULL DEFAULT 0,
    currency          text NOT NULL,
    payout_status     text NOT NULL CHECK (payout_status IN ('none', 'pending', 'paid', 'failed')),
    payout_attempts   integer NOT NULL DEFAULT 0,
    via               text NOT NULL DEFAULT 'web',   -- web / mcp / service
    created_at        timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (day, id),
    UNIQUE (day, user_id)          -- 分区表的唯一约束须包含分区键；(user_id, day) 唯一由此保证
) PARTITION BY RANGE (day);
CREATE INDEX records_user_day_idx ON checkin.records (user_id, day);
CREATE INDEX records_pending_idx ON checkin.records (payout_status) WHERE payout_status IN ('pending', 'failed');

CREATE TABLE checkin.milestones_awarded (
    user_id      bigint NOT NULL,
    cycle_start  date NOT NULL,
    days         integer NOT NULL,
    day_awarded  date NOT NULL,
    PRIMARY KEY (user_id, cycle_start, days)
);

CREATE TABLE checkin.card_log (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id        bigint NOT NULL,
    delta          integer NOT NULL,
    balance_after  integer NOT NULL,
    reason         text NOT NULL,
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX card_log_user_idx ON checkin.card_log (user_id, id DESC);

CREATE TABLE checkin.daily_stats (
    day             date PRIMARY KEY,
    users           integer NOT NULL,
    makeups         integer NOT NULL,
    amount          bigint NOT NULL,
    failed_payouts  integer NOT NULL
);

CREATE TABLE checkin.idempotency (
    scope       text NOT NULL,          -- 'check_in' / 'grant' / 'admin_cards'
    owner       text NOT NULL,          -- user_id 或 caller_plugin
    key         text NOT NULL,
    request_hash bytea NOT NULL,
    response    jsonb NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (scope, owner, key)
);
CREATE INDEX idempotency_created_idx ON checkin.idempotency (created_at);   -- 每日清理 > 7 天
```

数据量：`records` 每年约 1.1 亿行（约 120 B/行，约 13 GB/年，含索引约 25 GB），按月分区、保留 13 个月；`user_state` ≤ 30 万行。

### 3.2 Redis（前缀 `p:checkin:`，插件代码中省略前缀）

| 键 | 类型 | TTL | 说明 | 内存估算 |
|---|---|---|---|---|
| `day:<yyyymmdd>` | BITMAP | 48 h | 位偏移 = user_id | user_id 上限 2^24 时约 2 MiB/天 |
| `rank:<yyyymmdd>` | STRING(INCR) | 48 h | 当日名次计数 | 可忽略 |
| `st:<uid>` | HASH | 10 min | 状态缓存 | 9 万活跃 × ~150 B ≈ 13 MiB |
| `streak_top` | STRING(JSON) | 15 min | 连签榜 | < 20 KiB |

user_id 超过 2^26 时位图单键 8 MiB，仍可接受；超过 2^28 时改为按 `uid >> 20` 分片键（实现时预留 `day:<yyyymmdd>:<shard>` 形式，默认 shard 恒为 0）。

### 3.3 搜索索引贡献

无。

## 5. 前端设计

- `home.widgets`：卡片显示“今日已签到 / 签到”按钮、连签天数、明日奖励预估、今日名次；点击按钮调用 POST `/check-in`（自动生成 `Idempotency-Key`，防双击）；里程碑命中时展示动画提示。
- `/p/checkin/`：月历（签到、补签、未签三种状态，可补签的日期带“补签”按钮并显示剩余补签卡）、连签榜、规则说明（由设置渲染，币种名用 `t('term:ledger.currency.<code>')`）。
- `user.profile.stats`：连签 / 累计签到两项（设置 `show_on_profile`）。
- 后台：设置页由 schema 生成；统计页为自定义组件（折线图：每日签到人数与发放额）。

## 6. 安全设计

| 点 | 措施 |
|---|---|
| 重复签到 | PG 唯一约束 `(day, user_id)`；HTTP 幂等键 |
| 脚本抢签 | 限流 `user:10/m`；默认不发名次奖励；钩子点留给 anticheat / 验证码 |
| 越权 | HTTP 只操作当前用户；管理接口需 `checkin.manage`；服务 `check-in` 需作用域 `write` |
| 奖励滥发 | 金额上限校验；ledger 幂等键确定性；管理员调整写审计 |
| 隐私 | 排行只显示用户名与连签；不涉及敏感数据 |

## 7. 性能设计

- 签到写路径：1 次钩子 + 2 条 upsert/update + 1～2 条 insert + 1 次 ledger 调用 + 1 次事件；预计 p50 20 ms、p99 < 150 ms。
- 0 点高峰 30 次/秒：`user_state` 行锁只锁单用户，无热点；`rank:<day>` INCR 为单键热点，Redis 单键 INCR 远高于需求。
- `status` 命中 `st:<uid>` 缓存；首页按 10 min TTL。

## 8. 可观测性

## 10. 对平台契约的新增（补充）

- `ctx.notify.send` 的 `idempotency-key` 为必填参数（notify 03 §2），`remind_streak` 重跑不会重复提醒；不需要 kv 去重（评审 R1 F-08）。
- `ctx.ledger` 作用域与设置 `currency` 绑定：站点更换币种必须同时修改清单并重启；后台保存设置时校验 `currency` 是否在已授予作用域内，不在则拒绝保存（`kernel.validation_failed`）。
