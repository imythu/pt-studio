## 1. 引言

### 1.1 目的

定义商城插件 `shop` 的需求。商城是虚拟货币（魔力值等）的主要消耗出口：用户用币种兑换上传量、邀请、改名、头衔、勋章、VIP、补签卡、个人促销卡等。

### 1.2 范围

包含：

- 商品目录：商品定义（类型、价格、币种、数量规则、库存、限购、上架时间、等级要求、参数表单）；
- 下单与支付：冻结（hold）→ 履约 → 扣款（capture）或解冻（release）；
- **履约适配器**：每种商品类型调用对应插件的服务完成发货；
- 订单状态机、失败补偿、崩溃恢复；
- 退款（管理员）：冲正扣款并尽可能撤销履约；
- 购买钩子 `shop.before_purchase`（等级、分享率等插件可拦截）；
- 改名卡对 `user.before_rename` 的处理（站点要求改名必须通过商城时）；
- 购买记录、统计、MCP 工具。

不包含：

- 币种注册与余额（ledger / bonus）；
- 各商品的业务逻辑本身（由被调用插件实现）；
- 真实货币支付（捐赠由独立插件处理，不在本期范围）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 商品（item） | 可购买的条目，带类型（kind）与价格 |
| 履约（fulfillment） | 支付后实际发放商品，例如调用 `ctx.accounting.adjust` 增加上传量 |
| 冻结（hold） | ledger 中暂时锁定用户余额，履约成功后扣款，失败后解冻 |
| 适配器（adapter） | 某种商品类型对应的履约 / 撤销实现 |

### 1.4 参考资料

- docs/platform/、docs/plugins/ledger/03（hold / capture / release）、docs/plugins/invite/03（grant_quota / deduct_quota）、docs/plugins/medals/、docs/plugins/checkin/、docs/plugins/promotion/
- NexusPHP `mybonus.php`：魔力值兑换上传量、邀请名额、自定义头衔、VIP、改名卡、彩虹 ID、赠送他人等
- UNIT3D BON Store：兑换上传量、邀请、个人 freeleech、VIP 时长；`bon_exchange` 表定义商品
- Gazelle/OPS：Bonus Store（上传量、邀请、自定义头衔、令牌、徽章“收藏品”）

## 2. 总体描述

### 2.1 插件定位

- 类型：WASM，ID `shop`，缩写 `SHOP`。
- 提供：`ctx.shop`（single）。
- 依赖（按商品类型启用，均为 optional）：`ctx.ledger`（必需）、`ctx.accounting`、`ctx.invites`、`ctx.users`、`ctx.medals`、`ctx.checkin`、`ctx.promotions`、`ctx.rbac`、`ctx.hnr`。
- 拥有钩子点 `shop.before_purchase`；处理 `user.before_rename`（可选）。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 普通用户 | 浏览商品、查看价格与余额、购买（含参数，如新用户名、头衔文本、目标种子）、查看订单 |
| 管理员 | 管理商品、查看订单与统计、退款、手动重试失败订单 |
| 其他插件 | levels / ratio-policy 处理 `shop.before_purchase`；MCP 购买 |

### 2.3 现有开源 PT 程序的做法调研

| 程序 | 做法 | 优点 | 缺点 | 我们的取舍 |
|---|---|---|---|---|
| NexusPHP（mybonus） | 商品硬编码在页面与配置中：上传量 1/5/10 GB、邀请、头衔、VIP、改名、彩虹 ID；直接 `UPDATE users SET seedbonus = seedbonus - X, uploaded = uploaded + Y` | 商品丰富，用户熟悉 | 扣款与发货在同一张表同一语句，扩展新商品必须改代码；无订单记录或只有日志文本；并发时可能超扣 | **采纳**商品类型集合；**改进**：商品数据驱动、订单有完整状态机；扣款经 ledger 冻结 / 扣款，发货经各插件服务，失败自动解冻 |
| UNIT3D（BON Store） | `bon_exchange` 表定义商品（value、cost、类型标志），控制器按类型分支处理；交易写 `bon_transactions` | 商品可后台配置 | 新类型仍需改控制器；交易与发货不是原子，失败需人工处理 | **采纳**商品表 + 类型；**改进**：类型由适配器实现，统一的冻结 → 履约 → 扣款流程与恢复任务 |
| Gazelle/OPS（Bonus Store） | 商品包括上传量、邀请、自定义头衔、徽章收藏品；价格可随购买次数递增（部分商品） | 递增价格抑制囤积 | — | **采纳**可选的递增价格（`price_step`） |

### 2.4 约束与假设

1. 跨插件调用不共享事务（平台约定），因此支付与履约必须用幂等键 + 补偿实现最终一致。
2. 币种作用域在清单中静态声明，站点新增可用币种需修改清单并重启。
3. 规模：日订单量 ≤ 5 万；活动高峰 50 单/秒。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-SHOP-001 | 商品定义 | 管理员创建 / 编辑 / 下架商品：kind、名称（术语键 `shop.item.<id>`）、描述、价格、币种、数量范围、库存、限购、上架时间窗口、最低等级、参数 schema、排序、分类 | P0 | 后台创建后前台可见 |
| FR-SHOP-002 | 商品类型 | 支持：`upload_credit`、`invite_quota`、`rename`、`custom_title`、`medal`、`vip`、`makeup_card`、`promo_card`、`hnr_removal` | P0 | 每种类型有适配器与集成测试 |
| FR-SHOP-003 | 类型可用性 | 依赖的服务未启用时，该类型商品自动显示为“不可用”，不可购买 | P0 | 停用 checkin 后补签卡不可购买 |
| FR-SHOP-004 | 商品列表 | 用户查看可购买商品、价格（含递增后的价格）、剩余库存、个人限购剩余 | P0 | 与数据库一致 |
| FR-SHOP-005 | 购买 | 用户选择商品、数量与参数下单；系统冻结金额 → 履约 → 扣款 | P0 | 成功后余额减少、商品到账；订单 completed |
| FR-SHOP-006 | 履约失败 | 履约失败时解冻金额，订单 failed，向用户展示原因 | P0 | 余额恢复；无部分发货 |
| FR-SHOP-007 | 幂等购买 | 购买接口支持 Idempotency-Key；服务 `purchase` 必须带幂等键 | P0 | 重复提交只产生一个订单 |
| FR-SHOP-008 | 崩溃恢复 | 订单停留在中间状态（已冻结 / 履约中）超过 2 分钟时由恢复任务继续推进 | P0 | 注入崩溃后订单最终完成或失败，不出现“扣款未发货”或“发货未扣款” |
| FR-SHOP-009 | 库存 | 商品可设总库存；并发购买不超卖 | P1 | 并发测试库存不为负 |
| FR-SHOP-010 | 限购 | 每用户每日 / 每周 / 总计限购 | P1 | 超出返回 `shop.limit_reached` |
| FR-SHOP-011 | 递增价格 | 可选：价格随用户已购次数递增（`price_step`、`price_max`），可按周期重置 | P2 | 第 N 次价格 = min(base + step × (N−1), max) |
| FR-SHOP-012 | 等级要求 | 商品可设 `min_class_id`；另触发 `shop.before_purchase` 钩子供其他插件拦截 | P1 | 等级不足 `shop.class_required`；钩子拒绝返回其错误码 |
| FR-SHOP-013 | 参数校验 | 带参数的商品（新用户名、头衔文本、目标种子 / H&R 记录）按参数 schema 校验 | P0 | 非法参数 422，不冻结金额 |
| FR-SHOP-014 | 改名卡 | `rename` 商品：参数为新用户名，履约调用 `ctx.users.rename` | P1 | 改名成功；用户名冲突时订单失败并解冻 |
| FR-SHOP-015 | 强制经商城改名 | 可选：开启后 shop 处理 `user.before_rename`，拒绝非商城发起的用户自助改名（管理员改名不受限） | P2 | 用户在资料页改名被拒绝，提示去商城 |
| FR-SHOP-016 | 退款 | 管理员对 completed 订单退款：先尝试撤销履约（支持撤销的类型），再冲正扣款；不可撤销的类型需管理员确认“仅退款” | P1 | 退款后余额恢复；邀请额度被扣回 |
| FR-SHOP-017 | 订单查询 | 用户查看自己的订单；管理员按用户、商品、状态、时间查询 | P0 | 分页正确 |
| FR-SHOP-018 | 统计 | 每商品销量、消耗币种总额（每日汇总） | P2 | 与订单聚合一致 |
| FR-SHOP-019 | 事件 | 订单完成发布 `shop.item_purchased`；失败、退款发布对应事件 | P0 | 订阅方收到 |
| FR-SHOP-020 | MCP | `list_shop_items`（读）、`buy_shop_item`（写，需确认） | P2 | 确认后下单成功 |
| FR-SHOP-021 | 赠送 | 可选：购买时指定受赠用户（`gift_to`），由购买者付款、受赠者收货；部分类型不允许赠送 | P2 | 受赠者收到商品；事件含两者 |
| FR-SHOP-022 | 用户删除 | 订阅 `user.deleted`，purge 时匿名化订单（保留金额统计，去除参数中的个人文本） | P1 | purge 后订单无用户名等文本 |

## 4. 非功能需求

| 编号 | 类别 | 描述 | 指标 |
|---|---|---|---|
| NFR-SHOP-001 | 性能 | 下单受理与完成 | 受理（返回订单号）p99 < 100 ms；订单完成 p95 < 2 s、p99 < 5 s |
| NFR-SHOP-002 | 性能 | 商品列表 | p99 < 50 ms |
| NFR-SHOP-003 | 一致性 | 支付与履约 | 任一时刻崩溃，最终状态只能是“扣款 + 发货”或“未扣款 + 未发货”；恢复时间 ≤ 5 分钟 |
| NFR-SHOP-004 | 一致性 | 库存与限购 | 并发下不超卖、不超限 |
| NFR-SHOP-005 | 安全 | 权限与审计 | 商品管理需 `shop.items.manage`；退款需 `shop.orders.refund` ⊕；全部写审计 |
| NFR-SHOP-006 | 可扩展 | 新商品类型 | 新增类型只需新增适配器模块与清单依赖，不改动订单流程 |
| NFR-SHOP-007 | 可观测 | 指标 | 下单数、成功率、失败原因、恢复次数、退款数 |

## 5. 可配置项与站点术语

运行时设置：

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | true | 商城开关 |
| `gift_enabled` | bool | false | 是否允许赠送 |
| `require_rename_via_shop` | bool | false | 强制经商城改名 |
| `hold_ttl_minutes` | integer | 1440 | 冻结有效期（恢复任务的安全边界） |
| `max_qty_per_order` | integer | 100 | 单次购买数量上限 |

术语：`shop.name`（已登记）、`shop.item.<item_id>`（动态）、`shop.category.<slug>`（动态，商品分类）、`shop.kind.<kind>`（类型名）。

## 6. 外部接口需求概述

- 服务 `ctx.shop`：`items`、`purchase`、`order`。
- 事件：发布 `shop.item_purchased`、`shop.order_failed`、`shop.order_refunded`；订阅 `user.deleted`。
- 钩子：拥有 `shop.before_purchase`；处理 `user.before_rename`（可选）。
- HTTP：`/api/p/shop/v1/*`；插槽 `nav.main`、`nav.user_menu`；页面 `/p/shop/`。
- MCP：`list_shop_items`、`buy_shop_item`。
