## 1. 模块详细设计

### 1.0 公共约定

- 源码 `plugins/wasm/shop/`（Rust + `wit-bindgen`），`kind = "wasm"`；状态在 PG schema `shop`。
- 金额：ledger 最小单位的 `i64`；价格计算全部用饱和 / 检查运算，溢出返回 `shop.price_overflow`。
- 订单 ID：`bigint identity`；所有外部调用的幂等键形如 `shop:<order_id>:<step>[:<n>]`。
- 每个适配器实现 trait：

```rust
trait Adapter {
    fn kind(&self) -> &'static str;
    fn required_service(&self) -> Option<&'static str>;          // 如 "ctx.invites"
    fn params_schema(&self) -> serde_json::Value;                 // 合并到商品参数 schema
    fn gift_allowed(&self) -> bool;
    fn validate(&self, item: &Item, qty: u32, params: &Json, recipient: UserId) -> Result<(), PluginError>; // 无副作用
    fn fulfill(&self, o: &Order) -> FulfillOutcome;              // Done(ref) | Retry(err) | Fail(err)
    fn revert(&self, o: &Order) -> RevertOutcome;                // Done | Unsupported | Retry(err) | Fail(err)
}
```

### 1.1 catalog

**商品字段**（`items`）：`kind`、`slug`、名称（术语键 `shop.item.<id>`，创建时 `terms.define`）、`description_md`、`category`、`currency`、`base_price`、`price_step`、`price_max`、`price_reset`（none/daily/weekly/monthly）、`unit_value`（类型相关，见 §1.3）、`qty_min`/`qty_max`、`stock`（null = 无限）、`limit_per_day`/`limit_per_week`/`limit_total`、`min_class_id`、`available_from`/`available_until`、`config`（类型配置 JSON，如勋章 ID、VIP 天数）、`gift_allowed`、`active`、`sort`。

**可用性**（`available(item)`）：`active` ∧ 时间窗口内 ∧ 适配器的 `required_service` 已启用（`ctx.plugins.list()` 检查，结果 kv 缓存 60 s）∧ 币种在清单作用域内 ∧ 库存 > 0（或无限）。不可用的商品在列表中带 `unavailable_reason`（`service_disabled` / `sold_out` / `not_started` / `ended`）。

### 1.2 pricing 与 limits

```
period_key(reset, now) = none → "all"; daily → yyyymmdd; weekly → ISO 年-周; monthly → yyyymm（站点时区）
price(item, uid, qty):
  n0 = purchase_counters[(uid, item, period_key(item.price_reset))].count       // 已购件数
  if price_step == 0: return base_price × qty
  Σ_{i=0..qty-1} min(base_price + price_step × (n0 + i), price_max ?? ∞)       // 闭式计算，避免循环
limits(item, uid, qty):
  day = counters[(uid,item,yyyymmdd)].count；week = …；total = counters[(uid,item,"all")].count
  任一 + qty > 对应上限 → shop.limit_reached{scope}
```

预扣（下单事务内）：

```sql
SELECT id, stock FROM shop.items WHERE id = $1 FOR UPDATE;           -- 仅 stock 非空时
UPDATE shop.items SET stock = stock - $2, sold = sold + $2 WHERE id = $1 AND stock >= $2;   -- 0 行 → shop.sold_out
INSERT INTO shop.purchase_counters (user_id, item_id, period, count) VALUES ($u, $i, $p, $q)
  ON CONFLICT (user_id, item_id, period) DO UPDATE SET count = purchase_counters.count + EXCLUDED.count;
-- 对 'all'、当日、当周、price_reset 周期四个 period 各执行一次（去重）
```

回补（失败 / 退款）为相反操作；`purchase_counters` 在退款时回补（退款后可再次购买）。

### 1.3 adapters

| kind | 参数（params） | unit_value / config | fulfill | revert | 可赠送 |
|---|---|---|---|---|---|
| `upload_credit` | — | `unit_value` = 每件增加的字节数 | `accounting.adjust(recipient, +unit×qty, 0, "shop.upload_credit", key)` | `accounting.adjust(recipient, −unit×qty, 0, "shop.refund", key:revert)`；`adjust_would_be_negative` → Fail（管理员可选仅退款） | 是 |
| `invite_quota` | — | `unit_value` = 每件邀请数；`config.expires_days?` | `invites.grant_quota({user, amount, reason: "shop.order", expires_at, idempotency_key})` | `invites.deduct_quota({…, ref_idempotency_key: fulfill key})`；`shortfall > 0` → 部分撤销，记录 | 是 |
| `rename` | `new_username` | qty 固定 1 | `users.rename(recipient, new_username)`；`identity.username_taken` → Fail | Unsupported | 否 |
| `custom_title` | `title` | qty 固定 1 | `medals.set_custom_title(recipient, title, key)` | Unsupported | 否 |
| `medal` | — | `config.medal_id`、`config.days?` | `medals.grant({user, medal_id, reason: "shop.order:<oid>", expires_at, idempotency_key})`；`already_held`（reject 型）→ Fail | `medals.revoke(…, key:revert)` | 由 item 配置 |
| `vip` | — | `config.days`（每件天数） | `rbac.grant_role(recipient, "shop:vip", expires_at = max(现有到期, now) + days×qty)`（先 `roles_of` 读取现有到期） | `rbac.revoke_role`（仅当到期时间等于本订单写入值时撤销；否则 Unsupported） | 是 |
| `makeup_card` | — | `unit_value` = 每件张数 | `checkin.grant_makeup_cards(recipient, unit×qty, "shop.order:<oid>", key)` | Unsupported（checkin 无扣减接口） | 是 |
| `promo_card` | — | `config.card_kind`，`unit_value` | `promotions.grant_cards(recipient, kind, unit×qty, reason, key)` | Unsupported | 是 |
| `hnr_removal` | `record_id` | qty 固定 1 | 先 `hnr.records(recipient)` 校验记录属于本人且状态为 failed/active；`hnr.forgive(record_id, reason = "shop.order:<oid>", idempotency_key = "shop:<oid>")`（与 hnr 03 §1.5 签名一致） | Unsupported | 否 |

**错误归类**：适配器把下游错误映射为 `Retry`（`kernel.timeout`、`kernel.service_unavailable`、`kernel.hook_failed`、`*.idempotency_in_progress`、其他 `retryable = true`）或 `Fail`（业务错误）。

`validate` 在下单前执行：检查参数 schema、`rename` 的用户名格式（不查重，查重在 fulfill 时由 identity 完成，避免竞态）、`hnr_removal` 记录归属、`medal` 是否已持有（reject 型提前提示）。

### 1.4 orders：状态机

```
状态                 进入条件                                  下一步
created              下单事务提交                              hold
held                 ledger.hold 成功                          fulfill
fulfilled            适配器 Done                               capture
completed            capture 成功                              —
failed               hold 余额不足 / 适配器 Fail / 超过重试上限   —（已 release 且回补库存）
refunding            管理员退款开始                            revert → reverse
refunded             reverse 成功                              —
needs_attention      异常需人工（hold 过期但已发货且无法补扣） —
```

**下单（HTTP / 服务）**：

```
create_order(req, actor):
  s = settings；enabled 检查；user = users.get(req.user_id)；status ∈ {active, leech_disabled}
  recipient = req.gift_to ?? req.user_id；gift_to 时 gift_enabled ∧ item.gift_allowed ∧ 受赠者 active ∧ ≠ 自己
  item = catalog::get(req.item_id)；available(item) 否则 shop.item_unavailable{reason}
  qty ∈ [item.qty_min, min(item.qty_max, s.max_qty_per_order)]
  adapter.validate(item, qty, params, recipient)
  if item.min_class_id: users.get(uid).class_id ≥ min_class_id 否则 shop.class_required
  hooks.run("shop.before_purchase", {user_id, item_id, kind, qty, price(估算), currency, gift_to, params_keys})
  idem 命中 → 返回已有订单
  limits::check + reserve；amount = pricing::price(...)
  o = INSERT orders(state='created', user_id, recipient_id, item_id, kind, qty, params, amount, currency, …)
  jobs.schedule_once("advance_order", now, {order_id: o.id}, dedupe_key = o.id)
  idempotency.put；return {order_id, state: "created"}
```

**推进（延迟任务 `advance_order`，tx manual）**：

```
advance(oid):
  loop（最多 6 步）:
    o = SELECT … FROM orders WHERE id = oid FOR UPDATE
    match o.state:
      created:
        r = ledger.hold({currency, user: o.user_id, amount, reason: "shop.order", expires_at: now + hold_ttl,
                         idempotency_key: "shop:<oid>:hold"})
        Ok(hold_id)        → state=held, hold_id；step_log；commit
        Err(insufficient)  → fail(o, "ledger.insufficient_balance", release=false)；commit；return
        Err(retryable)     → reschedule(oid, backoff)；commit；return
        Err(other)         → fail(o, code, release=false)；return
      held:
        match adapter.fulfill(o):
          Done(ref)  → state=fulfilled, fulfill_ref=ref；commit
          Retry(e)   → attempts+1；attempts < 10 → reschedule；否则 fail(o, e, release=true)；commit；return
          Fail(e)    → fail(o, e, release=true)；commit；return
      fulfilled:
        r = ledger.capture_hold({hold_id, to_user: None, amount: o.amount, reason: "shop.order",
                                 memo: "order:<oid>", idempotency_key: "shop:<oid>:capture"})
        Ok(res)                       → state=completed, capture_entry_id；publish shop.item_purchased；commit；return
        Err(hold_not_active/expired)  → 补扣：ledger.transfer({from: user, to: None, amount, reason: "shop.order",
                                         idempotency_key: "shop:<oid>:charge"})
                                        成功 → completed；余额不足 → state=needs_attention；告警；commit；return
        Err(retryable)                → reschedule；return
      其他终态 → return
fail(o, code, release):
  if release && o.hold_id: ledger.release_hold(o.hold_id, "shop:<oid>:release")（失败则 reschedule，保持当前状态不变）
  limits::unreserve(o)；state=failed, error_code=code；publish shop.order_failed
reschedule(oid, n) = jobs.schedule_once("advance_order", now + min(5s × 2^n, 10 min), {oid}, dedupe_key = oid + ":" + n)
```

**恢复（cron `recover_orders`，每分钟）**：`SELECT id FROM orders WHERE state IN ('created','held','fulfilled','refunding') AND updated_at < now() - interval '2 minutes' LIMIT 200` → 对每个调度 `advance_order`（dedupe_key = `recover:<oid>:<minute>`）。

### 1.5 refunds

```
refund(oid, actor, refund_only: bool, reason):
  o = FOR UPDATE；state == completed 否则 shop.not_refundable
  state = refunding；commit
  r = adapter.revert(o)
  Done → ok
  Unsupported / Fail → if !refund_only: state = completed（回退）；return shop.revert_unsupported / 下游错误码
  Retry → 保持 refunding，由 recover 继续（refund_only 标记保存在订单上）
  ledger.reverse(o.capture_entry_id, reason = "shop.refund")（幂等键由 ledger 以 entry 维度保证；needs_attention 订单走 charge entry）
  limits::unreserve(o)；state = refunded, refunded_by, refund_reason；publish shop.order_refunded；audit
```

### 1.6 rename_guard（处理 `user.before_rename`）

```
on hook user.before_rename(input):
  if !settings.require_rename_via_shop: allow
  if input.actor.kind == "plugin" && input.actor.plugin_id == "shop": allow
  if input.actor 是管理员（actor.user_id ≠ input.user_id）: allow
  deny("shop.rename_requires_purchase", "请在商城购买改名卡")
```

### 1.7 stats 与 lifecycle

- `daily_stats`：按 (day, item_id, currency) 汇总 completed 订单数、件数、金额，以及 failed、refunded 数。
- `on_user_deleted`（purge）：`UPDATE orders SET params = '{}'::jsonb, params_redacted = true WHERE user_id = $1 OR recipient_id = $1`；保留金额与商品（统计用）；`purchase_counters` 删除。
- `cleanup`：删除 7 天前的幂等记录、30 天前的已过期限购周期计数（`period` 为日 / 周 / 月且已过）。

## 2. 接口详细设计

### 2.1 服务接口（WIT `pt:shop@0.1.0`）

```wit
package pt:shop@0.1.0;

interface shop {
  use pt:plugin/types@1.0.0.{plugin-error, user-id, timestamp-ms, json};

  record item-view {
    id: u64, kind: string, slug: string, name-key: string, category: option<string>,
    currency: string, unit-price: s64, next-price: s64, qty-min: u32, qty-max: u32,
    stock-left: option<u64>, limit-left: option<u32>, gift-allowed: bool,
    params-schema: json, available: bool, unavailable-reason: option<string>,
  }
  record purchase-request {
    user-id: user-id, item-id: u64, qty: u32, params: json,
    gift-to: option<user-id>, idempotency-key: string,
  }
  record order-result { order-id: u64, state: string }
  record order {
    id: u64, user-id: user-id, recipient-id: user-id, item-id: u64, kind: string, qty: u32,
    amount: s64, currency: string, state: string, error-code: option<string>,
    created-at: timestamp-ms, updated-at: timestamp-ms,
  }

  items: func(user: user-id, locale: string) -> result<list<item-view>, plugin-error>;
  purchase: func(req: purchase-request) -> result<order-result, plugin-error>;
  order: func(order-id: u64) -> result<option<order>, plugin-error>;
}
```

目录原签名 `items(locale)` 增加 `user` 参数（计算个人价格与限购）。

|---|---|---|
| `items` | — | |
| `purchase` | `purchase` | 同 HTTP 下单 |
| `order` | — | 调用方只能读取 `user_id` 等于原始 actor 的订单（或拥有 `shop.orders.read`） |

```json
                         "properties": { "new_username": { "type": "string", "minLength": 3, "maxLength": 20 } } } }

```

**POST `/v1/orders`**（`Idempotency-Key` 必填；限流 `user:30/m`）

```json
{ "item_id": 3, "qty": 2, "params": {}, "gift_to": null }
```

→ 202 `{ "order_id": 7001, "state": "created" }`。支持 `Prefer: wait=3`：服务端最多等待 3 秒（每 200 ms 读取一次订单状态），到达终态则返回 200 与订单详情。

错误（422 / 403 / 409，均不创建订单）：`shop.item_unavailable`、`shop.qty_invalid`、`shop.params_invalid`、`shop.limit_reached`、`shop.sold_out`、`shop.class_required`、`shop.gift_not_allowed`、`shop.recipient_invalid`、钩子处理者错误码。余额不足在异步阶段发现，订单 `failed`，`error_code = ledger.insufficient_balance`；为减少这种情况，下单时先做一次 `ledger.balance` 预检（不保证），不足直接返回 422 `ledger.insufficient_balance`。

**GET `/v1/orders/{id}`** → `{ "id": 7001, "item_id": 3, "kind": "upload_credit", "qty": 2, "amount": 20000, "currency": "bonus", "state": "completed", "error_code": null, "created_at": "…", "updated_at": "…" }`

**POST `/v1/admin/orders/{id}/refund`** `{ "refund_only": false, "reason": "误购" }` → 200 `{ "state": "refunded", "reverted": true }`；409 `shop.not_refundable`；422 `shop.revert_unsupported`。

**POST `/v1/admin/orders/{id}/retry`**：仅 `failed` 且错误可重试类（下游暂时故障超过重试上限）的订单；重新进入 `created`（新的幂等键后缀 `:r<n>`）→ 202。

**POST `/v1/admin/items`**：请求体为 §1.1 字段（`name_zh`、`name_en` 用于 define）→ 201 `{ "id": 9 }`；校验：`kind` 已知、`config` 符合适配器 schema、`currency` 在作用域内、价格 ≥ 0。

## 3. 数据库设计

### 3.1 PostgreSQL（schema `shop`）

```sql
CREATE TABLE shop.items (
    id               bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind             text NOT NULL,
    slug             text NOT NULL UNIQUE,
    category         text,
    description_md   text NOT NULL DEFAULT '',
    currency         text NOT NULL,
    base_price       bigint NOT NULL CHECK (base_price >= 0),
    price_step       bigint NOT NULL DEFAULT 0 CHECK (price_step >= 0),
    price_max        bigint,
    price_reset      text NOT NULL DEFAULT 'none' CHECK (price_reset IN ('none','daily','weekly','monthly')),
    unit_value       bigint NOT NULL DEFAULT 1,
    qty_min          integer NOT NULL DEFAULT 1,
    qty_max          integer NOT NULL DEFAULT 1,
    stock            bigint CHECK (stock >= 0),
    sold             bigint NOT NULL DEFAULT 0,
    limit_per_day    integer,
    limit_per_week   integer,
    limit_total      integer,
    min_class_id     integer,
    available_from   timestamptz,
    available_until  timestamptz,
    config           jsonb NOT NULL DEFAULT '{}',
    gift_allowed     boolean NOT NULL DEFAULT false,
    active           boolean NOT NULL DEFAULT true,
    sort             integer NOT NULL DEFAULT 100,
    created_at       timestamptz NOT NULL DEFAULT now(),
    updated_at       timestamptz NOT NULL DEFAULT now(),
    CHECK (qty_min >= 1 AND qty_max >= qty_min AND qty_max <= 1000)
);

CREATE TABLE shop.orders (
    id                bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id           bigint NOT NULL,
    recipient_id      bigint NOT NULL,
    item_id           bigint NOT NULL REFERENCES shop.items (id),
    kind              text NOT NULL,
    qty               integer NOT NULL,
    params            jsonb NOT NULL DEFAULT '{}',
    params_redacted   boolean NOT NULL DEFAULT false,
    amount            bigint NOT NULL,
    currency          text NOT NULL,
    state             text NOT NULL CHECK (state IN ('created','held','fulfilled','completed','failed',
                                                     'refunding','refunded','needs_attention')),
    hold_id           text,
    fulfill_ref       text,
    capture_entry_id  text,
    error_code        text,
    attempts          integer NOT NULL DEFAULT 0,
    refund_only       boolean NOT NULL DEFAULT false,
    refunded_by       bigint,
    refund_reason     text,
    via               text NOT NULL DEFAULT 'web',
    periods           text[] NOT NULL,        -- 预扣过的 purchase_counters 周期，回补时使用
    created_at        timestamptz NOT NULL DEFAULT now(),
    updated_at        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX orders_user_idx ON shop.orders (user_id, id DESC);
CREATE INDEX orders_pending_idx ON shop.orders (updated_at) WHERE state IN ('created','held','fulfilled','refunding');
CREATE INDEX orders_item_idx ON shop.orders (item_id, created_at DESC);

CREATE TABLE shop.order_steps (
    order_id   bigint NOT NULL REFERENCES shop.orders (id) ON DELETE CASCADE,
    seq        integer NOT NULL,
    at         timestamptz NOT NULL DEFAULT now(),
    from_state text NOT NULL,
    to_state   text NOT NULL,
    detail     text NOT NULL DEFAULT '',
    PRIMARY KEY (order_id, seq)
);

CREATE TABLE shop.purchase_counters (
    user_id  bigint NOT NULL,
    item_id  bigint NOT NULL,
    period   text NOT NULL,             -- 'all' / 'd:20261005' / 'w:2026-40' / 'm:202610'
    count    integer NOT NULL DEFAULT 0 CHECK (count >= 0),
    PRIMARY KEY (user_id, item_id, period)
);

CREATE TABLE shop.daily_stats (
    day        date NOT NULL,
    item_id    bigint NOT NULL,
    currency   text NOT NULL,
    orders     integer NOT NULL,
    units      bigint NOT NULL,
    amount     bigint NOT NULL,
    failed     integer NOT NULL,
    refunded   integer NOT NULL,
    PRIMARY KEY (day, item_id, currency)
);

CREATE TABLE shop.idempotency (
    owner text NOT NULL, key text NOT NULL, request_hash bytea NOT NULL,
    order_id bigint NOT NULL, created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (owner, key)
);
```

数据量：`orders` 每年约 1800 万行（日 5 万），建议 v0.2 起按年分区；`order_steps` 约 4 倍，保留 180 天（`cleanup`）。

## 5. 前端设计

- `/p/shop/`：分类标签、商品卡片（名称、价格、余额对比、限购剩余、库存）、不可用商品灰显并显示原因。
- 购买对话框：数量选择（实时显示总价，按递增价格公式计算）、参数表单（JSON Schema 自动生成）、可选赠送对象（用户名自动补全）、确认后提交（`Idempotency-Key` 由前端生成并在重试时复用），提交后用 `Prefer: wait=3` 等待结果，超时则显示“处理中”并轮询。
- “我的订单”：状态徽标；失败订单显示错误说明（错误码映射为本地化文案）。
- 后台：商品编辑（kind 选择后显示该类型的 config 表单）、订单查询与退款对话框（不可撤销类型显示“仅退款”勾选与警告）、统计图表。

## 6. 安全设计

| 点 | 措施 |
|---|---|
| 超扣 / 超卖 | ledger hold 原子扣冻；库存行锁 + 条件更新 |
| 重复下单 | Idempotency-Key 必填；订单幂等表 |
| 参数注入 | 参数按 schema 校验；用户名、头衔由下游插件再次校验；参数不进事件与日志 |
| 越权 | 服务 `purchase` 需作用域；订单只能本人或有权限者查看；退款需 `shop.orders.refund` 并写审计 |
| 赠送滥用（洗钱 / 刷号） | 默认关闭；开启后受 ledger 钩子（anticheat）与限购约束 |

## 7. 性能设计

- 下单受理：1 次钩子 + 1 个事务（≤ 6 条 SQL）+ 调度任务，p99 < 100 ms。
- 推进：每订单 3 次跨插件调用；内核任务唤醒 200 ms。
- 热门限量商品：`items` 行锁串行化，单商品 ~500 单/秒上限，满足活动需求（50 单/秒）。

## 8. 可观测性

| 指标 | 类型 |
|---|---|
| `pt_plugin_shop_orders_total{kind,result}` | counter（result = completed/failed/refunded） |
| `pt_plugin_shop_order_latency_seconds{kind}` | histogram（created → 终态） |
| `pt_plugin_shop_fulfill_errors_total{kind,code}` | counter |
| `pt_plugin_shop_recovered_total` | counter |
| `pt_plugin_shop_needs_attention` | gauge |

告警：`needs_attention > 0`；`pending` 订单（中间状态 > 10 分钟）> 20。

## 9. 错误码表

| 错误码 | HTTP 状态 | 说明 |
|---|---|---|
| `shop.disabled` | 403 | 商城关闭 |
| `shop.item_not_found` | 404 | 商品不存在 |
| `shop.item_unavailable` | 409 | 商品不可用（`details.reason`） |
| `shop.qty_invalid` | 422 | 数量不合法 |
| `shop.params_invalid` | 422 | 参数不合法（`details.errors[]`） |
| `shop.limit_reached` | 403 | 超出限购（`details.scope`） |
| `shop.sold_out` | 409 | 库存不足 |
| `shop.class_required` | 403 | 等级不足 |
| `shop.gift_not_allowed` | 403 | 该商品不允许赠送或赠送已关闭 |
| `shop.recipient_invalid` | 422 | 受赠者不存在、不可用或为自己 |
| `shop.price_overflow` | 422 | 金额溢出 |
| `shop.not_refundable` | 409 | 订单状态不允许退款 |
| `shop.revert_unsupported` | 422 | 该类型无法撤销履约（需勾选仅退款） |
| `shop.rename_requires_purchase` | 403 | 站点要求通过商城改名（`user.before_rename` 钩子返回） |
| `shop.order_not_found` | 404 | 订单不存在 |
