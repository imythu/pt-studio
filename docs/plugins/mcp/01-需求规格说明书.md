## 1. 引言

### 1.1 目的

定义 MCP 网关插件 `mcp` 的需求：把各插件在清单中声明的 MCP 工具以 Model Context Protocol 服务暴露给用户的 AI 客户端，并负责授权、写操作人工确认、限流、审计与输出过滤。

### 1.2 范围

包含：

- MCP 服务端（Streamable HTTP 传输），协议版本 **2026-07-28**（无状态：无 `initialize` 握手、无 `Mcp-Session-Id`），并兼容 **2025-11-25** 客户端（有握手与会话）；
- 授权：OAuth 2.1（站点作为授权服务器，MCP 端点作为受保护资源；受保护资源元数据 RFC 9728；授权服务器元数据；PKCE；动态客户端注册），以及个人 MCP token（简化模式，供不支持 OAuth 的客户端）；
- scope：`mcp:user`（用户侧工具）、`mcp:admin`（管理员侧工具，需近期二次验证）；
- 工具目录：从内核 MCP 注册表（`ctx.mcp_registry.tools()`）读取，按调用者权限过滤；
- 写操作确认：`write && confirm` 的工具首次调用返回待确认，用户在站内（或经 `ctx.mcp.confirm`）确认后执行；
- 输出过滤（敏感字段黑名单兜底）、限流、审计（`mcp.tool_called`）、用户查看与吊销已授权客户端。

不包含：MCP 客户端（站内 AI 助手调用外部 MCP 服务器不在本期）；Resources 与 Prompts（v0.1 只提供 Tools；Roots、Sampling、Logging 在 2026-07-28 中已标记弃用，不实现）。

### 1.3 参考资料

- MCP 规范 2026-07-28（无状态传输、`Mcp-Method` 路由头、授权加固：`iss` 校验 RFC 9207、客户端注册声明 `application_type`、工具 schema 支持完整 JSON Schema 2020-12）与 2025-11-25（Streamable HTTP、OAuth 2.1、`outputSchema`、工具注解）
- docs/platform/catalog/mcp-tools.md、kernel/03 §10（MCP 注册表）、docs/plugins/identity/（`issue_token`、二次验证）

## 2. 总体描述

Native 插件，ID `mcp`，缩写 `MCP`；提供 `ctx.mcp`（确认流程）；依赖 `ctx.auth`、`ctx.users`、`ctx.rbac`、内核 `ctx.mcp_registry`。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-MCP-001 | 端点 | `POST /mcp`（JSON-RPC 2.0；`Accept: application/json, text/event-stream`）；2026-07-28：每个请求独立，可路由到任意副本 | P0 | 主流 MCP 客户端可连接 |
| FR-MCP-002 | 版本协商 | 读取 `MCP-Protocol-Version` 头；支持 2026-07-28 与 2025-11-25；后者的 `initialize` 与会话 ID 由网关以无状态方式模拟（会话 ID 为签名令牌，不需共享存储） | P0 | |
| FR-MCP-003 | tools/list | 返回调用者可用的工具：`name`、`description`、`inputSchema`、`outputSchema`、`annotations`（`readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint`） | P0 | |
| FR-MCP-004 | tools/call | 校验输入 schema → 内核注册表执行（以用户 principal 身份）→ 返回 `structuredContent` 与 `content`（JSON 文本） | P0 | |
| FR-MCP-005 | OAuth | 受保护资源元数据（`/.well-known/oauth-protected-resource`）、授权服务器元数据（`/.well-known/oauth-authorization-server` 与 OpenID 发现）、授权端点（站内同意页）、令牌端点（授权码 + PKCE S256、刷新令牌）、动态客户端注册（RFC 7591，要求声明 `application_type`）、响应中携带 `iss`（RFC 9207） | P0 | |
| FR-MCP-006 | 个人 token | 用户在设置页签发 MCP token（`ctx.auth.issue_token(kind = mcp)`，选择 scope 与有效期），以 `Authorization: Bearer` 使用 | P0 | |
| FR-MCP-007 | scope | `mcp:user` 只能看到 `audience = user` 的工具；`mcp:admin` 需要用户拥有 `mcp.admin_tools.use`，且授权时 30 分钟内通过二次验证；admin 访问令牌有效期 ≤ 1 小时 | P0 | |
| FR-MCP-008 | 写操作确认 | `write && confirm` 工具：首次调用创建确认项（参数快照、摘要），返回工具结果 `isError: false` 的“待确认”说明（含确认链接与确认 ID）；用户在站内确认后，客户端以同一参数再次调用并带上 `confirmation_id`（或站内确认后由网关执行并保存结果，客户端用 `get_confirmation_result` 读取） | P0 | |
| FR-MCP-009 | 确认管理 | 站内“待确认操作”列表：查看参数摘要、确认 / 拒绝；确认项 10 分钟过期 | P0 | |
| FR-MCP-010 | 不可关闭确认 | 目录标注“不可关闭”的工具（如 `admin_set_user_status`）忽略 site.toml 的关闭设置 | P0 | |
| FR-MCP-011 | 输出过滤 | 返回前递归移除字段名在黑名单中的值（passkey、email、ip、password、token、secret、totp、webauthn），并扫描 32 位 hex 与邮箱模式（兜底） | P0 | |
| FR-MCP-012 | 限流 | 每 token：读工具 60 次/分钟、写工具 10 次/分钟；全站并发上限 | P0 | |
| FR-MCP-013 | 钩子 | 调用前 `mcp.before_tool_call`（anticheat 等可拒绝） | P1 | |
| FR-MCP-014 | 审计 | 每次调用发布 `mcp.tool_called`（不含参数值，只含工具名与结果分类）；写操作额外写 `ctx.audit`（含参数摘要） | P0 | |
| FR-MCP-015 | 客户端管理 | 用户查看已授权的 OAuth 客户端与 token（名称、scope、最近使用），可吊销 | P0 | |
| FR-MCP-016 | 术语 | 工具结果中的站点叫法已由各工具渲染；网关在 tools/list 的描述中不额外处理 | P2 | |
| FR-MCP-017 | 提示注入防护 | 工具结果中来自用户的内容标注为数据（`_meta.pt/userContent: true` 与描述约定，见 03） | P1 | |

## 4. 非功能需求

| 编号 | 描述 | 指标 |
|---|---|---|
| NFR-MCP-001 | 网关开销 | p99 < 20 ms（不含工具执行） |
| NFR-MCP-002 | 水平扩展 | 无会话共享存储（2026-07-28 无状态；2025-11-25 会话 ID 为签名令牌） |
| NFR-MCP-003 | 安全 | 令牌只存哈希；admin 令牌短期；所有写操作可追溯 |

## 5. 可配置项

`enabled`（true）、`issuer`（站点 URL）、`access_token_ttl`（user 1 h、admin 1 h）、`refresh_token_ttl`（30 天，admin 不发放刷新令牌）、`dcr.enabled`（true）、`rate.*`、`confirm_ttl_minutes`（10）、`disabled_confirm_tools`（站点可关闭确认的工具列表，不可关闭者除外）。

## 6. 外部接口需求概述

HTTP：`/mcp`、`/.well-known/oauth-protected-resource`、`/.well-known/oauth-authorization-server`、`/.well-known/openid-configuration`（只含 OAuth 所需字段）、`/oauth/authorize`（前端同意页）、`/oauth/token`、`/oauth/register`、`/oauth/revoke`；管理：`/api/p/mcp/v1/me/clients`、`/me/confirmations`；服务 `ctx.mcp`；事件 `mcp.tool_called`、`mcp.confirmation_resolved`；钩子 `mcp.before_tool_call`（拥有者）；插槽 `user.settings.tabs`（AI 客户端与 token）、`nav.user_menu`（待确认徽标）。
