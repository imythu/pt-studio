## 1. 设计目标与原则

1. **网关只做协议、授权、确认、过滤**；工具实现在各插件，注册与执行由内核 MCP 注册表完成（kernel/03 §10）。
2. **无状态**：按 2026-07-28 规范，每个请求自带鉴权与协议版本，可路由到任意副本；旧版本会话以签名令牌模拟。
3. **以用户身份执行**：工具调用的 actor 是令牌对应的用户（credential = mcp_token），权限检查与 HTTP 接口一致。
4. **写操作默认确认**：确认状态在 PG（多副本一致），确认在站内完成（用户在网页上看到真实参数），防止 AI 客户端被提示注入后静默执行写操作。

## 2. 总体结构

```
AI 客户端 ─HTTPS─► /mcp（mcp 插件路由，auth = public，自行鉴权）
   ├─ Bearer 令牌 → ctx.auth.authenticate（OAuth 访问令牌或个人 MCP token）→ principal
   ├─ tools/list → mcp_registry.tools() → 按 scope / audience / permission 过滤
   └─ tools/call → schema 校验 → hooks(mcp.before_tool_call) → 写且需确认？→ 确认项 / 执行
                    → mcp_registry.call(tool, args, principal) → 输出过滤 → 结果
OAuth：/.well-known/*、/oauth/*（同意页在前端 /oauth/consent）
站内确认：/api/p/mcp/v1/me/confirmations → confirm → 执行（以用户身份，actor credential = session）→ 保存结果
```

| 模块 | 职责 |
|---|---|
| `jsonrpc` | JSON-RPC 2.0 编解码、批处理拒绝（MCP 不支持批量）、错误码 |
| `transport` | Streamable HTTP（JSON 响应；SSE 只在工具执行超过 5 秒时用于进度通知——v0.1 只返回 JSON） |
| `version` | 协议版本协商与旧版本兼容 |
| `oauth` | 授权服务器（元数据、授权码、令牌、刷新、动态注册、吊销），令牌签发委托 identity |
| `catalog` | 工具目录过滤与转换（目录 → MCP Tool 对象） |
| `confirm` | 确认项生命周期 |
| `filter` | 输出过滤 |
| `limits` | 限流与并发 |
| `audit` | 事件与审计 |

## 4. 数据设计概要

`oauth_clients`（动态注册的客户端）、`auth_codes`（授权码，10 分钟）、`grants`（用户对客户端的授权：scope、最近使用）、`confirmations`（确认项：工具、参数快照、摘要、状态、结果）；访问令牌与刷新令牌由 identity 的 token 存储（kind 区分），本插件只保存 grant 关联。

## 6. 设计决策

| 编号 | 问题 | 结论与理由 |
|---|---|---|
| DD-MCP-1 | 协议版本 | 主支持 2026-07-28（无状态，适合多副本）；兼容 2025-11-25（会话 ID 为 HMAC 签名令牌，网关不存会话） |
| DD-MCP-2 | 授权服务器 | 站点自建（identity 签发令牌）：用户只需站点账号；令牌受 identity 的吊销与封禁控制 |
| DD-MCP-3 | 确认交互 | 在站内网页确认（而不是 MCP 客户端内确认）：AI 客户端可能被注入，站内页面展示真实参数，用户独立判断 |
| DD-MCP-4 | Resources / Prompts | v0.1 不提供：工具已覆盖需求；减少攻击面 |
| DD-MCP-5 | 进度与长任务 | v0.1 不使用 SSE 与 Tasks 扩展；工具执行超时 30 秒 |

## 7. 对平台契约的新增

identity：token kind `mcp`、`oauth_access`、`oauth_refresh`、`oauth_client_secret`（或由本插件存储客户端密钥哈希）；`ctx.auth.authenticate` 返回 principal 的 `scopes` 与 `client_id`；内核 MCP 注册表：`call` 支持 `principal` 参数（已在目录中）、工具定义需包含 `annotations` 与“确认不可关闭”标志（catalog/mcp-tools.md 增加列 `confirm_locked`）；内核网关：插件路由在根路径（`/mcp`、`/.well-known/*`、`/oauth/*`）——需内核允许 mcp 插件注册这些保留路径 ⊕。
