# 数据库规范（PostgreSQL）

> 版本 0.1 · 2026-10-04 · 数据库已确定为 PostgreSQL（D18），最低版本 16，推荐 17。

## 1. schema 与角色

| 对象 | 规则 | 例子 |
|---|---|---|
| 插件 schema | 插件 ID 的 `-` 换成 `_` | `tracker_bridge` |
| 插件角色 | `<role_prefix>plugin_<schema>`，`role_prefix` 默认 `pt_` | `pt_plugin_tracker_bridge` |
| 内核 schema | `kernel` | |
| 扩展 schema | `ext`（内核安装 `site.toml [database].extensions` 中的扩展） | `ext.gin_trgm_ops` |
| 保留表名 | 以 `_` 开头的表名保留给内核（`_inbox`、`_kv`） | |

- 插件**只能**在自己的 schema 中建对象；跨插件读取只能通过已授权的只读视图（§9）或服务调用。
- 插件 SQL 中**不写 schema 前缀**访问自己的表（`search_path` 已设为本 schema）；访问视图写全名 `identity.v_user_public`。
- 角色、GRANT、扩展、schema 都由内核管理，迁移中不得出现。

## 2. 命名

| 对象 | 规则 | 例子 |
|---|---|---|
| 表 | snake_case，复数名词 | `torrents`、`rate_rules` |
| 关联表 | 两个实体名 | `torrent_tags` |
| 列 | snake_case；外键 `<实体单数>_id`；布尔 `is_` / `has_` 前缀；时间 `_at`；日期 `_on`；时长秒 `_secs`；字节 `_bytes` 或语义名（`size`、`uploaded`） | `user_id`、`is_anonymous`、`created_at`、`seed_secs` |
| 主键 | `id` | |
| 索引 | `<表>_<列>_idx`；唯一 `<表>_<列>_key` | `torrents_uploader_id_idx` |
| 约束 | 外键 `<表>_<列>_fkey`；检查 `<表>_<含义>_check` | |
| 视图 | `v_<名>`；版本化 `v_<名>_v2` | `v_user_public` |
| 枚举 | **不用 PG ENUM 类型**（改值需要 DDL 且不能在事务中回滚），用 `text` + `CHECK` 或查表 | `status text NOT NULL CHECK (status IN ('candidate','pending','approved'))` |

## 3. 主键（结论）

| 场景 | 类型 | 生成 |
|---|---|---|
| 业务实体（用户、种子、Group、帖子、订单、流水……） | `bigint` | `GENERATED BY DEFAULT AS IDENTITY` |
| 事件 ID、幂等键、对外不可枚举的标识（分享链接、确认单） | `uuid` | 应用生成 **UUIDv7**（Rust `uuid` crate `Uuid::now_v7()`；PG 18 起可用 `uuidv7()`） |
| 自然键表（配置、映射） | 自然键 | |

**理由**：

1. design 中的契约与 pt-tracker 已使用 `u64` 用户 ID 和种子 ID（`uid`、`tid`、`user_id % N` 分区），BIGINT 与之一致，索引小、连接快。
2. 单主 PostgreSQL 下 identity 序列足够，不需要雪花 ID 的节点号分配；雪花 ID 会超过 JavaScript 安全整数（2^53），前端必须改用字符串，得不偿失。
3. UUIDv7 有时间序、全局唯一，适合跨进程生成的事件与幂等键；但 16 字节且不便人读，不作为业务主键。
4. 担心 ID 可枚举的接口（如私密分享）额外加 `uuid` 列或签名令牌，而不是换主键。

所有 BIGINT ID 保证小于 2^53（identity 列不会在可预见的规模下逼近此值）。

## 4. 类型

| 数据 | 类型 |
|---|---|
| 时间点 | `timestamptz`（**禁止** `timestamp without time zone`），存 UTC |
| 日期 | `date`（按站点时区的自然日，如签到日） |
| 时长 | `bigint` 秒（列名 `_secs`）或 `interval`（仅配置类） |
| 字节数、流量 | `bigint` |
| 货币金额 | `bigint` 最小单位（scale 由 ledger 币种定义）；**禁止** `float`/`double`/`money` |
| 比率（分享率） | 不存储，按需计算；必须存储时用 `numeric(12,4)` |
| 字符串 | `text` + `CHECK (char_length(x) <= N)`，不用 `varchar(n)` |
| 不区分大小写 | 用户名、邮箱：`text` + 小写规范化列或 `citext`（需启用扩展） |
| JSON | `jsonb`；只放真正半结构化的数据（资源类型字段、设置）；会被过滤/连接的字段要提为列 |
| 二进制哈希 | info_hash：`bytea`（20/32 字节）+ `CHECK (octet_length(..) = 20)`；对外以 hex 表示 |
| IP | `inet`（敏感数据，见 security.md） |
| 布尔 | `boolean NOT NULL DEFAULT false` |

## 5. 审计字段

所有可变业务表必须有：

```sql
created_at  timestamptz NOT NULL DEFAULT now(),
updated_at  timestamptz NOT NULL DEFAULT now(),
```

按需增加：

```sql
created_by  bigint,          -- 操作者用户 ID；系统操作为 NULL
updated_by  bigint,
version     integer NOT NULL DEFAULT 1   -- 乐观锁：UPDATE … SET version = version + 1 WHERE id = $1 AND version = $2
```

- `updated_at` 由应用在 UPDATE 中显式设置（WASM 插件不能写 plpgsql 触发器）。
- 只追加表（流水、日志）只需 `created_at`（或业务时间列）。
- 谁在什么时候做了什么的完整记录在 `kernel.audit_log`，表中审计字段只记最近一次。

## 6. 软删除

- **默认不软删除**。只有“删除后仍需要被引用或恢复”的实体才软删除：用户、种子、Group、帖子、评论、求种。
- 软删除列：`deleted_at timestamptz`（NULL 表示未删除），可加 `deleted_by bigint`、`delete_reason text`。
- 唯一约束与常用索引改为部分索引：`CREATE UNIQUE INDEX … ON torrents (info_hash_v1) WHERE deleted_at IS NULL;`
- 对外视图默认过滤已删除行。
- 只追加表（账本流水、事件、审计）**永不删除**，更正用冲正记录。
- 个人数据清除（用户要求删除账号）由 identity 发出 `user.deleted{mode: purge}`，各插件订阅后匿名化或删除自己的个人数据；这是插件文档必须描述的流程。

## 7. 分区

- 预计超过 5000 万行或需要按时间清理的表使用声明式分区。
- **按时间**：日志、流水、快照类表，`PARTITION BY RANGE (<时间列>)`，月分区（高写入可日分区）。
- **按用户**：按用户查询为主的大表（如 snatch），`PARTITION BY HASH (user_id)`，分区数 16 或 32，部署后不改。
- 分区维护：在清单 `[[database.partitions]]` 声明，由内核任务 `kernel.partition_maintenance` 预建未来分区并按保留期删除旧分区（插件运行期不能执行 DDL）：

```toml
[[database.partitions]]
table = "traffic_log"
by = "range_month"          # range_day | range_month | hash（hash 只在迁移中一次性建好）
premake = 3                 # 预建未来 3 个分区
retention_months = 24       # 0 = 永久
```

- 分区命名：`<表>_y2026m10`、`<表>_y2026m10d04`、`<表>_p07`。
- 分区表主键必须包含分区键。

## 8. 迁移

- 位置：插件目录 `migrations/`；文件 `NNNN_<snake_desc>.sql`，从 `0001` 连续编号。
- **只进不退**，已发布的迁移不得修改（内核校验 sha256）。
- 每个文件默认在一个事务中执行；需要 `CREATE INDEX CONCURRENTLY` 的文件首行写 `-- pt:no-transaction`，且该文件只能包含这类语句。
- 允许的语句与禁止事项见 kernel/03 §6.3（迁移模式）。
- **兼容滚动升级（expand / contract）**：
  1. 新增列：可空或带默认值（PG 11+ 带常量默认值不重写表）；
  2. 删除/重命名列：先发布“不再使用”的代码，再在下一个版本的迁移中删除；
  3. 改类型：新列 + 回填 + 切换 + 删除旧列，分版本进行；
  4. 大表回填不放在迁移中，改为 cron 任务分批执行；
  5. 加 `NOT NULL`：先加 `CHECK (col IS NOT NULL) NOT VALID` → `VALIDATE CONSTRAINT` → 再 `SET NOT NULL`。
- 迁移中设置了 `lock_timeout = 5s`；会长时间持锁的操作必须拆分。
- 种子数据（默认配置、内置等级）可以在迁移中 `INSERT … ON CONFLICT DO NOTHING`。

## 9. 只读视图

- 提供方在自己的 schema 中创建，名字 `v_` 开头，在清单 `[database].views` 列出，并在 [../catalog/services.md](../catalog/services.md) §3 登记（含敏感级别）。
- 写法：

```sql
CREATE VIEW v_user_public WITH (security_barrier = true) AS
SELECT id, username, class_id, status, created_at
FROM users
WHERE deleted_at IS NULL;
```

- **不得**设置 `security_invoker = true`（视图须以提供方权限读取底表）。
- 只暴露稳定、必要的列；视图是提供方 API 的一部分，遵守 [../plugin-api.md](../plugin-api.md) §6 的版本规则。
- 视图中不得包含敏感列，除非整个视图标记为敏感（需要站点授权，例：`identity.v_user_email`）。
- 消费方只能 `SELECT`；写入一律调用服务。
- 视图适合“批量读取、连接过滤”（如 bonus 按用户批量读取做种数据）；单条读取优先用服务调用。

## 10. 查询规范

- 全部参数化（WASM 的 `sql` 接口只接受参数化语句；Native 用 `sqlx::query!` / `query_as!` 编译期检查）。**禁止字符串拼接 SQL**（包括拼接 ORDER BY 字段：用白名单映射）。
- 每个查询必须能走索引；列表接口用键集分页（`WHERE (created_at, id) < ($1, $2) ORDER BY created_at DESC, id DESC LIMIT $3`），不用大 OFFSET。
- 批量写入：WASM 用 `execute_batch`；Native 用 `UNNEST` 批量插入或 `copy_in`。
- 长事务禁止：cron 任务分批提交（`sql.commit()`）。
- `SELECT *` 只允许在迁移和测试中出现。
- 外键：同 schema 内使用外键；**跨插件不使用外键**（无法跨 schema 引用他人表），以 ID + 事件维护一致性（如订阅 `user.deleted`、`torrent.deleted`）。
