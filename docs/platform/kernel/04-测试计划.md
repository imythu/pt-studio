## 1. 测试范围与策略

| 层次 | 内容 | 工具 |
|---|---|---|
| 单元测试 | 清单解析、拓扑排序、钩子管线算法、补丁越界检查、语句检查、Redis 命令改写、限流算法、cron 计算 | `cargo nextest`，`proptest`（排序、改写、补丁） |
| 集成测试 | 真实 PostgreSQL 16/17 + Redis 7.4 + MinIO（testcontainers）；使用测试插件集（见 §2.2） | `testcontainers`、`cargo nextest` |
| 契约测试 | WIT：`wasm-tools component wit` 解析 `pt:plugin`；四种调用组合一致性；OpenAPI 聚合结果通过 `openapi-typescript` 生成且 `tsc --noEmit` 通过；catalog.json 与 docs/platform/catalog 一致 | `wasm-tools`、`xtask` |
| 安全测试 | SQL 隔离逃逸、Redis 越界、WASM 资源滥用、CSRF、敏感字段泄漏、出站 HTTP SSRF | 恶意测试插件 + 专项用例 |
| 性能测试 | 网关开销、WASM 调用开销、事件吞吐与延迟、冷启动 | `criterion`、`oha`、自写事件压测工具 |
| 可靠性测试 | 多副本下的 cron 唯一性、事件不丢不重、副本崩溃与再平衡、Redis/PG 抖动 | 3 副本 docker compose + `toxiproxy` |

## 2. 测试环境与数据

### 2.1 环境

| 环境 | 组成 |
|---|---|
| CI | GitHub Actions（或同类）Linux x86_64；testcontainers 拉起 PG 16、PG 17、Redis 7.4、MinIO |
| 性能 | 8 核 32 GB × 3（内核副本）；PG 17 独立 16 核；Redis 7.4 独立 |
| 混沌 | docker compose：3 × pt-server、PG、Redis、toxiproxy |

### 2.2 测试插件集（`crates/kernel/tests/plugins/`）

| 插件 | 类型 | 用途 |
|---|---|---|
| `t-echo-native` / `t-echo-wasm` | Native / WASM | 提供 `ctx.t_echo`，用于四种调用组合 |
| `t-hooks-a`、`t-hooks-b` | WASM | 可配置 allow/deny/modify/超时/trap 的钩子处理者 |
| `t-events` | WASM | 发布/订阅，可配置失败次数，记录处理次数 |
| `t-cron` | WASM | 记录每次执行的节点与时间 |
| `t-evil` | WASM | 恶意行为：死循环、内存爆炸、`RESET ROLE`、`set_config`、读他人 schema、越界 Redis、SSRF、伪造事件 source |
| `t-evil-migration` | WASM | 迁移中尝试 GRANT、建 SECURITY DEFINER 函数、plpgsql、跨 schema DDL |
| `t-http` | WASM | 带各种 auth/permission/rate_limit/idempotent 声明的路由 |
| `t-mcp` | WASM | 读写 MCP 工具，输出含 `email`、`passkey` 字段 |
| `t-identity-stub` / `t-terms-stub` | Native | 可编程的 `ctx.auth`、`ctx.rbac`、`ctx.terms` |
