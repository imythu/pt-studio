## 2. 插件加载器

### 2.1 发现与清单解析

1. Native：遍历 `pt_server::NATIVE_PLUGINS`（由 `native_plugins!` 宏按 cargo feature 生成），读取 `NativePlugin.manifest`。
2. WASM：遍历 `plugins.dir` 的一级子目录，目录名必须等于清单 `id`；忽略以 `.` 开头的目录。
3. 同一 ID 出现两次（Native 与 WASM 同名、目录重复）→ 错误 `E-LOAD-DUPLICATE`。
4. 解析 TOML → `serde_json::Value` → 用 `plugin-manifest.schema.json` 校验 → 反序列化为 `Manifest`。
5. **catalog 校验**：内核内置一份由 `docs/platform/catalog/*.md` 生成的 `catalog.json`（构建时由 `xtask gen-catalog` 解析表格生成）。校验：`id` 已登记、`provides` 的服务归属本插件、`publishes` 的事件归属本插件、`[[hook_points]]` 归属本插件、`[[hooks]].hook` 存在、`[[permissions]]`、`[terms]` 键前缀、`[frontend].slots` 已登记、`[[mcp.tools]]` 归属本插件。
   - 第三方插件（ID 以 `x-` 开头）不在 catalog 中：只校验名字前缀为 `<id>.`（事件 domain 例外：必须以 `x_<vendor>_` 开头），并在后台标注“未登记”。
   - `site.toml [kernel] strict_catalog = false` 可把官方插件的 catalog 不一致降级为警告（仅开发用）。
6. 读取 `schemas/` 中引用的 JSON Schema，全部编译（`jsonschema` crate，draft 2020-12），编译失败为错误。

### 2.2 签名与版本校验

**包签名**（仅 WASM 插件；Native 插件随二进制构建可信）：

- `checksums.txt`：每行 `<sha256 hex>  <相对路径>`，按路径字典序，覆盖包内除 `plugin.sig`、`checksums.txt` 外的**全部文件**；多出或缺少文件都算失败。
- `plugin.sig`：对 `checksums.txt` 的 minisign（Ed25519）签名。
- 可信公钥：`site.toml [plugins.trust] keys = ["RWQ…"]`。任一公钥验证通过即可。
- `plugins.allow_unsigned = true` 只在 `kernel.mode = "dev"` 时被接受，否则启动报错。

**版本校验**：

| 检查 | 规则 | 失败错误 |
|---|---|---|
| `api` | 内核支持集合 `{pt:plugin@0.1}`（0.2 发布后为 `{0.2, 0.1}`）中有一个与之相等 | `E-LOAD-API` |
| `kernel` | 内核版本满足 semver 要求 | `E-LOAD-KERNEL` |
| `requires` | 所选提供方 `provides` 中的版本满足要求 | `E-LOAD-REQUIRES` |
| WIT 一致性 | WASM 组件的导入/导出与清单一致：导出接口集合 = 清单声明推导出的集合；导入的服务包版本与 `requires` 一致 | `E-LOAD-WORLD` |
| `kind` | 与实际加载方式一致 | `E-LOAD-KIND` |

### 2.3 依赖解析与拓扑排序

```
输入：启用的插件集合 P，site.toml [services] 选择 S
1. 对每个 single 服务 s：
     候选 = {p ∈ P | s ∈ p.provides}
     若 S[s] 存在：必须 ∈ 候选，否则 E-DEP-SELECT
     否则若 |候选| = 1：选中它
     否则若 |候选| > 1：E-DEP-AMBIGUOUS（列出候选）
     |候选| = 0：保留为空（只有被 requires 时才报错）
2. multi 服务：全部候选生效
3. 建图：对每个 p，对每个 r ∈ p.requires：
     single：边 p → provider(r)；无提供方 → E-DEP-MISSING
     multi：边 p → 每个提供方（无提供方允许，消费方须能处理空集合）
   对每个 r ∈ p.optional_requires：有提供方才连边
4. 内核隐式依赖：provider(ctx.auth)、provider(ctx.rbac)、provider(ctx.terms) 的出边先排序
5. Kahn 算法；同一层按插件 ID 字典序，保证各副本顺序一致
6. 若有剩余节点：用 DFS 找出一个环，报 E-DEP-CYCLE "a → b → c → a"
输出：激活顺序 order[]
```

`requires` 未声明却在 WASM 组件中导入了某服务包 → `E-LOAD-WORLD`。

### 2.4 迁移执行

迁移在**管理连接**（`database.admin_url`，角色 `pt_admin`，需 `CREATEROLE`）上执行，运行期连接池（`database.url`，角色 `pt_gateway`）不具备建角色权限。

```
pg_advisory_lock(hashtext('pt-studio:migrate'))         -- 多副本串行
确保扩展：对 site.toml [database].extensions 中每项 CREATE EXTENSION IF NOT EXISTS … SCHEMA ext
确保 kernel schema 及其迁移（内核自带 migrations，同样记录在 kernel.plugin_migration，plugin_id='kernel'）
for p in order:
    确保角色 <prefix>plugin_<schema>（NOLOGIN NOINHERIT）
    GRANT 该角色 TO pt_gateway WITH INHERIT FALSE, SET TRUE      -- PG16+
    确保 schema <schema> AUTHORIZATION 该角色；REVOKE ALL ON SCHEMA FROM PUBLIC
    确保内核管理的表：<schema>._inbox、<schema>._kv（见 §16.2）
    GRANT USAGE ON SCHEMA ext TO 该角色
    for f in p.migrations（按文件名序号升序）:
        已记录且 checksum 相同 → 跳过；checksum 不同 → E-MIG-CHANGED
        语句检查（迁移模式，§6.3）
        若首行为 "-- pt:no-transaction"：逐语句执行（用于 CREATE INDEX CONCURRENTLY）
        否则：BEGIN; SET LOCAL ROLE 该角色; SET LOCAL search_path = <schema>, ext, pg_catalog;
              SET LOCAL lock_timeout = '5s'; SET LOCAL statement_timeout = '15min';
              执行文件; INSERT kernel.plugin_migration; COMMIT
        失败 → 回滚该文件，E-MIG-FAILED（含文件名、行号、PG 错误码），停止
同步只读视图授权（§6.4）
pg_advisory_unlock(...)
```

- 文件名：`NNNN_<snake_desc>.sql`，`NNNN` 从 0001 连续递增；跳号或重复 → `E-MIG-NAME`。
- 校验和：sha256（统一换行为 `\n`）。
- **只进不退**：没有 down 迁移；需要回退时写新的前进迁移。
- `pt-server migrate` 可单独执行迁移（部署流水线先迁移再滚动发布）；`serve` 启动时默认也会执行（`database.migrate_on_start = true`）。

### 2.5 实例化与登记

按拓扑顺序：

1. WASM：加载预编译组件（§4.3），用 `Linker` 链接宿主接口（按有效能力决定链接真实实现或拒绝桩）和服务导入（§4.6），得到 `InstancePre`。
2. 登记服务（§3）、钩子处理者（§5）、路由（§8）、订阅（§7.4）、cron 与延迟任务名（§9）、MCP 工具（§10）、前端条目。
3. 收集权限点 → 待 identity 激活后调用 `ctx.rbac.register_permissions(all)`；收集术语 → 待 terms 激活后调用 `ctx.terms.register(all)`。这两个调用在 identity / terms 的 `init` 之后、其他插件 `init` 之前执行。
4. 调用 `lifecycle.init`（若导出）；超时 30 s。

**副作用登记表**：每个插件的全部登记项记录在 `PluginTable[id].effects`，后台“插件详情”展示；进程退出时按逆拓扑顺序释放（停止消费者、释放锁、关闭连接）。由于 D4，不存在运行时撤销登记。

同时写入 `kernel.plugin_registry`（每个副本启动时 upsert：id、version、kind、manifest 摘要、checksum、first_seen_at、last_seen_at），供“曾经安装过、现已移除”的检测与 `plugin purge` 使用。

### 2.6 启动失败策略

| 类别 | 例子 | 处理 | 退出码 |
|---|---|---|---|
| 配置 / 清单 / 依赖 / 能力错误 | 清单非法、签名失败、依赖缺失、环、敏感能力未授权 | **收集全部错误后统一输出**，退出 | 2 |
| 迁移错误 | SQL 失败、已执行迁移被改 | 立即退出（已提交的迁移保留） | 3 |
| 基础设施不可达 | PG / Redis / S3 连接失败 | 指数退避重试至 `kernel.startup_timeout`（默认 120 s），仍失败则退出 | 4 |
| 插件 init 失败 | `lifecycle.init` 返回错误或超时 | 退出 | 5 |

错误输出格式（stderr，同时以 JSON 写日志）：

```
error[E-DEP-MISSING] plugin `shop`: requires `ctx.bonus@^0.1` but no enabled plugin provides it
  hint: enable plugin `bonus`, or remove `shop` via [plugins] disabled = ["shop"]
```

`pt-server check` 执行到 §2.4 之前的全部检查（不连数据库也可运行 `--offline`），用于 CI 与部署前检查。

**运行期**：任何插件错误（trap、超时、内存超限）只影响那一次调用，不会让进程退出；同一插件 1 分钟内 trap 超过阈值（默认 100 次）时告警，不自动停用（D4）。

## 3. 服务注册表

### 3.1 数据结构

```rust
pub enum Cardinality { Single, Multi }

pub struct ServiceEntry {
    pub name: &'static str,             // "ctx.ledger"
    pub version: semver::Version,
    pub cardinality: Cardinality,
    pub providers: Vec<ProviderRef>,    // Single 时长度为 1（已选定）
}

pub struct ProviderRef {
    pub plugin_id: PluginId,
    pub imp: ServiceImpl,
}

pub enum ServiceImpl {
    /// Native 实现：Arc<dyn XxxService>（类型擦除），以及暴露给 WASM 的适配器
    Native { obj: Arc<dyn Any + Send + Sync>, adapter: Option<Arc<ServiceAdapter>> },
    /// WASM 实现：组件导出的接口实例名，如 "pt:ledger/ledger@0.1.0"
    Wasm { plugin: Arc<WasmPlugin>, export: String },
}

pub struct ServiceRegistry {
    by_name: HashMap<&'static str, ServiceEntry>,
    /// 每个消费方被允许调用的服务集合（requires ∪ optional_requires ∪ 内核服务）
    allowed: HashMap<PluginId, HashSet<&'static str>>,
}
```

服务基数来自 [../catalog/services.md](../catalog/services.md)（catalog.json），不由插件声明。

### 3.2 实现选择

见 §2.3 第 1 步。`site.toml` 示例：

```toml
[services]
"ctx.auth" = "identity"
"ctx.search" = "search-meilisearch"
"ctx.llm" = "llm-claude"
```

### 3.3 调用约束

- **只能沿依赖边调用**：调用方插件不在 `allowed` 中的服务 → `kernel.capability_denied`。依赖图（只由 `requires` / `optional_requires` 构成）无环，因此纯服务调用不会出现 A→B→A 的重入。
- **导出接口不计入依赖图**：hooks、content-type、search-contributor、metadata-provider、mcp-tool、on-event、on-cron 等导出由内核调用，不形成依赖边（评审 B-01）。代价是导出实现可能回调触发它的插件：例如 torrent 调用 type-movie 的 `content-type.normalize`，而 type-movie `requires ctx.torrents`。
- **重入检测**：`InvocationInfo.chain` 记录本调用链上“正在执行服务方法或发起导出调用的插件”集合。导出实现（或其嵌套服务调用）调用的服务提供方已在 `chain` 中 → `kernel.reentrant_call`（500，记录插件与链路）。导出实现只应读取只读视图，不应回调触发方。事件消费与延迟任务开启新链，不受此限制。
- **深度**：`InvocationInfo.depth` 每次服务调用 +1，> 8 → `kernel.call_depth_exceeded`。
- **截止时间**：嵌套调用的截止时间 = min(调用方剩余时间, 被调方法默认超时 1 s)。
- **作用域**：内核把调用方在该服务上的有效作用域（清单 `[capabilities.scopes]` ∩ site.toml 授权）放进 `caller_scopes`，**由提供方检查**；内核只保证调用方无法伪造。
- **事务**：被调方在自己的工作单元中执行，独立提交（§6.2）。

---

### 3.4 以用户身份调用（`invocation.with_principal`）

供自行鉴权的 public 路由使用（rss 的 feed key、crossseed-api 的 API token、mcp 的 OAuth token、ai-assistant 的会话）（评审 B-03）：

1. 插件调用 `ctx.auth.authenticate(credential)`；内核在当前 `InvocationInfo` 中记录返回的 principal（`authenticated: Vec<PrincipalId>`）。
2. 插件调用 `invocation.with_principal(principal_id)`：内核只接受第 1 步记录过的 principal，否则 `kernel.capability_denied`；成功后本次调用后续所有服务调用的 `actor` 为该用户，`caller_scopes` 再与该 principal 的 token 作用域求交。
3. 不能切回原 actor；不能嵌套切换为另一个用户。审计记录同时写入插件 ID 与用户 ID。
4. WIT：`pt:plugin/invocation.with-principal: func(id: principal-id) -> result<_, error>`；Native：`ctx.with_principal(id)` 返回新的 `Ctx`。

## 4. 统一调用与 WASM 运行时

### 4.1 四种调用组合

| 调用方 → 提供方 | 路径 | 开销 |
|---|---|---|
| Native → Native | `ctx.service::<dyn LedgerService>()` 直接得到 `Arc<dyn LedgerService>`，虚函数调用 | 约 1 次动态分发 |
| Native → WASM | `service!` 宏生成的 `LedgerClient` 实现 `LedgerService`：Rust 值 → `component::Val` → 在提供方新实例上 `Func::call_async` → `Val` → Rust 值 | 一次实例化 + 编解码 |
| WASM → Native | 调用方组件的导入函数由内核用 `func_new_async` 动态定义：`Val` → `ServiceAdapter::call(fn, args)` → Rust 实现 → `Val` | 编解码 |
| WASM → WASM | 导入函数动态定义：在提供方新实例上调用对应导出，`Val` 原样转发 | 一次实例化，无 Rust 编解码 |

因为服务接口禁止 `resource`（[../plugin-api.md](../plugin-api.md) §1.2），`Val` 只含值类型，可以安全地在不同 `Store` 之间移动。

### 4.2 Engine 配置

```rust
let mut cfg = wasmtime::Config::new();
cfg.wasm_component_model(true)
   .async_support(true)
   .epoch_interruption(true)
   .consume_fuel(site.wasm.fuel_enabled)        // 默认 false；测试与基准时可开，用于确定性计量
   .cranelift_opt_level(OptLevel::Speed)
   .parallel_compilation(true)
   .allocation_strategy(InstanceAllocationStrategy::Pooling(pool));
// 64 位主机上使用静态内存预留 + guard 页，消除边界检查
cfg.memory_reservation(4 << 30).memory_guard_size(2 << 30);
```

Pooling 配置（`site.toml [wasm.pool]`，括号内为默认值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `total_component_instances` | 1000 | 所有插件并发实例总数上限；≥ Σ 插件 `max_concurrency` 时不会因池满失败 |
| `total_memories` / `total_tables` | 1000 / 1000 | |
| `max_memory_size` | `wasm.max_memory_mb`（256 MiB） | 单个线性内存上限（池槽大小） |
| `max_core_instances_per_component` | 50 | JS/Python 组件内含多个核心模块 |
| `max_memories_per_component` | 4 | |
| `max_tables_per_component` | 16 | |
| `max_component_instance_size` | 1 MiB | |

每个 `Store` 另设 `StoreLimits`：`memory_size = 插件 [wasm].memory_mb`（默认 64 MiB，不得超过 `wasm.max_memory_mb`），`instances = 50`，`tables = 16`，`table_elements = 100_000`。超限 → trap → `kernel.resource_exhausted`。

### 4.3 组件编译与缓存

- 启动时对每个 `plugin.wasm` 计算 sha256；缓存路径 `cache_dir/wasm/<sha256>-<engine_fingerprint>.cwasm`，`engine_fingerprint` 取 `Engine::precompile_compatibility_hash()`。
- 命中则 `Component::deserialize_file`（`unsafe`，因此缓存目录须为 0700、仅 pt-server 用户可写）；未命中则 `Engine::precompile_component` 后写入（先写临时文件再 rename）。
- 多个插件并行编译（rayon），受 `wasm.compile_threads` 限制。

### 4.4 每次调用的执行

```rust
async fn invoke_wasm<R>(plugin: &WasmPlugin, inv: InvocationInfo, f: impl FnOnce(&mut Store<HostState>, &Instance) -> BoxFuture<R>) -> PResult<R> {
    let _permit = plugin.semaphore.acquire_timeout(Duration::from_millis(100)).await
        .map_err(|_| kernel_err("kernel.resource_exhausted"))?;   // 并发上限：[wasm].max_concurrency
    let mut store = Store::new(&ENGINE, HostState::new(plugin, inv.clone()));
    store.limiter(|s| &mut s.limits);
    let deadline = inv.deadline;
    store.set_epoch_deadline(1);
    store.epoch_deadline_callback(move |_| {
        if now_ms() >= deadline { Err(Trap::Interrupt.into()) }    // 超时：中断
        else { Ok(UpdateDeadline::Yield(1)) }                       // 每个节拍让出一次，避免长计算占住 tokio 线程
    });
    let instance = plugin.pre.instantiate_async(&mut store).await?;
    let out = tokio::time::timeout_at(to_instant(deadline), f(&mut store, &instance)).await
        .map_err(|_| kernel_err("kernel.timeout"))?;               // 宿主侧异步等待（SQL 等）也计入
    // store 在此 drop：实例归还池；HostState drop 时结束工作单元（提交或回滚，见 §6.2）
    out
}
```

- epoch 节拍：后台线程每 `wasm.epoch_tick_ms`（默认 10 ms）调用一次 `engine.increment_epoch()`。
- 默认超时：hook 见钩子目录；HTTP 5 s；on-event 30 s；on-cron 按清单 `timeout_secs`；服务调用 1 s；search-contributor 2 s；mcp-tool 10 s；init 30 s。均可由清单 `[wasm].default_timeout_ms` 或站点配置收紧。
- trap 转换：`Trap::Interrupt` → `kernel.timeout`；内存/表增长失败 → `kernel.resource_exhausted`；其他 → `kernel.plugin_trapped`（日志记录 trap 信息与 wasm 回溯）。

### 4.5 宿主接口实现

- 用 `wasmtime::component::bindgen!` 对 `pt:plugin/host` world 生成宿主 trait（async），`HostState` 实现之。
- 每个宿主函数入口先检查有效能力（双保险：未授权接口本已链接拒绝桩），再执行；所有宿主调用都有指标 `pt_kernel_host_calls_total{plugin, iface, fn, outcome}`。
- **出站 HTTP 与 SSRF 防护**（评审 B-04）：`http-client.send` 的目标主机必须匹配清单 `http_outbound`（字面主机、`config:` 解析结果、`runtime:` 当前设置值）；内核自行解析 DNS 并对**每个**解析地址检查：拒绝回环、私有（RFC 1918、ULA）、链路本地、CGNAT、组播、未指定地址与元数据地址（169.254.169.254 等），`allow_private = true` 的 `config:` 主机除外；连接时固定使用检查过的地址（防 DNS rebinding）；重定向最多 3 次且每跳重新检查；只允许 `https`（`allow_private` 主机可用 `http`）；响应体上限默认 8 MiB、超时 ≤ 调用剩余时间。
- **钩子调用中的限制**：`InvocationInfo.kind = hook` 时，`http-client.send` 与对 `ctx.llm` 的服务调用直接返回 `kernel.capability_denied`。
- **WASI**：链接 `wasmtime-wasi` p2，`WasiCtxBuilder` 不提供预打开目录、环境变量、参数；禁止 socket（`allow_tcp(false)`、`allow_udp(false)`、`allow_ip_name_lookup(false)`）；stdout/stderr 接到日志（debug 级，每次调用最多 4 KiB）；时钟与随机数照常提供。不提供 `wasi:http`（出站 HTTP 只走 `pt:plugin/http-client`）。

### 4.6 服务导入的动态桥接

启动时对每个 WASM 插件：

```
for (import_name, item) in component.component_type().imports(&ENGINE):
    if import_name 以 "pt:plugin/" 开头 → 宿主接口，已由 bindgen 链接
    else if import_name 以 "wasi:" 开头 → WASI
    else:  // 业务服务包，如 "pt:ledger/ledger@0.1.0"
        svc = registry.by_wit_package(import_name)  ?: E-LOAD-WORLD
        检查 svc ∈ allowed[plugin]                     ?: E-LOAD-WORLD
        检查类型一致：用 wit-parser 解析调用方组件内嵌 WIT 与提供方 wit/ 目录，逐函数比较签名  ?: E-LOAD-WORLD
        let mut inst = linker.instance(import_name)
        for func in item.functions():
            inst.func_new_async(func.name, move |store, params, results| {
                let caller_inv = store.data().invocation.child(caller=plugin, depth+1, scopes=…)
                match svc.provider.imp {
                    Native{adapter,..} => adapter.call(func.name, caller_inv, params) → results
                    Wasm{plugin: p, export} => invoke_wasm(p, caller_inv, |st, inst| {
                         let f = inst.get_func(st, (export, func.name)); f.call_async(st, params, results); f.post_return_async(st)
                    })
                }
            })
```

`ServiceAdapter` 与 `XxxClient` 由 `pt_plugin_api::service!` 宏根据 WIT 生成，负责 `Val` ↔ Rust 类型转换（record ↔ struct、variant ↔ enum、option、result、list 等）。

### 4.7 多实现扩展点的调用

`search-contributor`、`content-type`、`metadata-provider` 由内核按提供方枚举调用，调用方（search、torrent、`metadata` 宿主接口）得到 `Vec<(plugin_id, handle)>`。每个提供方调用相互独立，单个失败不影响其他提供方（调用方决定是否忽略）。

## 5. Hook 管线

### 5.1 数据结构

```rust
pub struct HookPoint {
    pub name: String,                     // "torrent.before_upload"
    pub owner: PluginId,
    pub input_schema: jsonschema::Validator,
    pub modifiable: Vec<JsonPointer>,     // 可修改字段前缀，如 "/title", "/fields"
    pub append_only: Vec<JsonPointer>,    // 只能追加的数组，如 "/filters"
    pub default_timeout: Duration,
    pub on_error: OnError,                // Deny | Allow
    pub locked: bool,                     // 锁定：站点不可改为 Allow
    pub total_budget: Duration,           // 默认 3 × 处理者超时上限
    pub handlers: Vec<HookHandler>,       // 启动时排好序
}
pub struct HookHandler { pub plugin: PluginId, pub priority: i32, pub timeout: Duration }
```

钩子点属性（可修改字段、超时、失败策略、锁定）来自 [../catalog/hooks.md](../catalog/hooks.md)（catalog.json），拥有者清单只提供输入 schema。

### 5.2 执行算法

```
fn run(hook, input, inv) -> Result<HookOutcome>:
    point = hooks[hook]  ?: kernel.internal
    require inv.caller_plugin == point.owner            // 只有拥有者能触发
    validate(point.input_schema, input) ?: kernel.validation_failed
    cur = input; started = now()
    for h in point.handlers where h.plugin ∉ site.hooks[hook].disabled_handlers:
        view = redact(cur, sensitive_caps(h.plugin))   // 评审 B-05：无 user.email 删 email，无 user.ip 删 ip
        remaining = min(h.timeout, point.total_budget - (now() - started), inv.deadline - now())
        if remaining <= 0: return fail(point, h, "budget_exhausted")
        r = invoke(h.plugin, kind=hook, deadline=now()+remaining, hooks.handle({hook, input: view}))
        match r:
            Ok(Allow)            => metrics(allow)
            Ok(Deny(info))       => metrics(deny); return Ok(Denied{info.code, info.message, by=h.plugin})
            Ok(Modify(patch))    =>
                 check_patch(patch, point.modifiable, point.append_only, view) ?: treat_as_error(h)   // 补丁不能触及被删除的字段
                 cur = json_merge_patch(cur, patch)
                 validate(point.input_schema, cur) ?: treat_as_error(h)
            Err(e) / timeout     => treat_as_error(h)
        treat_as_error(h):
            metrics(failure); log warn
            if effective_on_error(point, h) == Deny: return Err(kernel.hook_failed{hook, plugin=h.plugin})
            else continue
    return Ok(Allowed(cur))
```

- `check_patch`：补丁中每个被修改的路径都必须以某个 `modifiable` 前缀开头；`append_only` 路径上的新数组必须以旧数组为前缀（只能在末尾追加）。
- 处理者的 `deny.code` 必须以处理者自己的插件 ID 为前缀，否则替换为 `kernel.hook_denied`。
- **每个处理者在自己的工作单元中执行并独立提交**，即使管线后续被拒绝也不回滚。处理者如需“预留”（如邀请码），应写带 TTL 的预留记录，并在拥有者随后发布的事件（如 `user.registered`）中确认。插件文档作者必须注意这一点。
- 优先级覆盖：`site.toml [hooks."<name>".priority] <plugin> = <int>`；失败策略覆盖：`[hooks."<name>"] on_error = "allow"`（锁定钩子忽略并告警）。

## 6. 存储网关

### 6.1 PostgreSQL 角色与 schema

| 角色 | 属性 | 用途 |
|---|---|---|
| `pt_admin` | LOGIN, CREATEROLE；拥有数据库 | 仅启动阶段迁移与授权（`database.admin_url`） |
| `pt_gateway` | LOGIN, NOINHERIT | 运行期连接池（`database.url`）；拥有 `kernel` schema；是各插件角色的成员（`INHERIT FALSE, SET TRUE`） |
| `pt_plugin_<schema>` | NOLOGIN, NOINHERIT | 插件角色；拥有自己的 schema |
| `pt_readonly`（可选） | LOGIN | 运维/报表只读 |

数据库级加固（内核迁移 `kernel/0001` 中执行，需要 `pt_admin`）：

```sql
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
REVOKE ALL ON DATABASE pt FROM PUBLIC;
GRANT CONNECT ON DATABASE pt TO pt_gateway;
CREATE SCHEMA IF NOT EXISTS ext;                          -- 扩展安装位置
-- 阻断经由函数的角色切换与文件访问
REVOKE EXECUTE ON FUNCTION pg_catalog.set_config(text, text, boolean) FROM PUBLIC;
GRANT  EXECUTE ON FUNCTION pg_catalog.set_config(text, text, boolean) TO pt_gateway, pt_admin;
REVOKE USAGE ON LANGUAGE plpgsql FROM PUBLIC;             -- 插件默认不能写 plpgsql
GRANT  USAGE ON LANGUAGE plpgsql TO pt_gateway, pt_admin;
```

需要触发器等 plpgsql 的 **Native** 插件在清单中设 `database.plpgsql = true`，内核为其角色单独 `GRANT USAGE ON LANGUAGE plpgsql`，并在迁移检查中用 `pg_query::parse_plpgsql` 拒绝函数体内的 `EXECUTE`（动态 SQL）与 `SET`/`RESET`。WASM 插件只能创建 `LANGUAGE sql` 函数。

### 6.2 工作单元（事务）

```
首次 sql 调用（或工作单元结束时有待写事件）时：
    conn = pool.acquire()                     // 超时 database.acquire_timeout_ms（默认 2000）
    BEGIN
    SET LOCAL ROLE pt_plugin_<schema>
    SET LOCAL search_path = <schema>, ext, pg_catalog
    SET LOCAL statement_timeout = <database.statement_timeout_ms>
    SET LOCAL idle_in_transaction_session_timeout = <调用截止时间 + 5s>
    （事件订阅调用）INSERT INTO <schema>._inbox … ON CONFLICT DO NOTHING；0 行 → 已处理，结束并标记跳过
插件语句：经语句检查（§6.3）后以扩展协议执行（参数绑定）
sql.commit()（仅 tx = "manual"）：执行“提交流程”，然后重新 BEGIN 并重复上面的 SET LOCAL
调用成功返回：提交流程
    RESET ROLE                                -- 恢复为 pt_gateway（内核语句，插件不可达）
    INSERT INTO kernel.event_log …；INSERT INTO kernel.event_outbox …（本单元缓存的事件）
    COMMIT；若有事件则 NOTIFY pt_outbox（在 COMMIT 前执行，随事务生效）
调用失败 / trap / 超时：ROLLBACK（事件随之丢弃）
```

- 插件 `kv` 存在本插件 schema 的 `_kv` 表中，同样在工作单元事务内，与业务数据原子一致。
- 结果行数上限：内核用游标分批读取，超过 `database.max_rows`（默认 10,000，插件清单可调低）即停止并置 `truncated = true`。
- 值映射：`int` ↔ int2/int4/int8；`numeric` ↔ numeric（文本）；`timestamp` ↔ timestamptz（Unix µs）；`json` ↔ json/jsonb；`uuid` ↔ uuid；`int-array` ↔ int8[]；`text-array` ↔ text[]；其他类型以文本返回（`type-name` 给出 PG 类型名）。
- 连接池：sqlx `PgPool`，`max_connections = database.pool_size`（默认 32/副本）；与 pgbouncer 事务模式兼容（全部使用 `SET LOCAL`）。

### 6.3 语句检查

用 `pg_query`（libpg_query 的 Rust 绑定）解析。**这是纵深防御，主隔离仍是角色与 GRANT。**

| 模式 | 允许的顶层语句 | 一律拒绝 |
|---|---|---|
| 运行期 | 单条 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`MERGE`（含 `WITH`） | 多条语句；`SET`/`RESET`/`SHOW`；`SET ROLE`/`SET SESSION AUTHORIZATION`；事务控制（`BEGIN`/`COMMIT`/`SAVEPOINT`…）；`COPY`；`DO`；`CALL`；`LISTEN`/`NOTIFY`/`UNLISTEN`；`LOCK`；`PREPARE`/`EXECUTE`/`DEALLOCATE`；`DECLARE CURSOR`；`VACUUM`/`ANALYZE`；全部 DDL；`GRANT`/`REVOKE` |
| 迁移 | 上述 + `CREATE/ALTER/DROP` 表、索引、视图、序列、类型、`LANGUAGE sql` 函数、触发器（仅 Native 且 plpgsql 授权）、`COMMENT`、`CREATE TABLE … PARTITION OF` | 角色与权限语句；`CREATE EXTENSION`；`CREATE SCHEMA`；对 `<schema>.` 以外对象的任何 DDL（检查限定名）；`SECURITY DEFINER` 函数；`ALTER … OWNER`；视图上的 `security_invoker = true` |

两种模式下都拒绝调用以下函数（遍历解析树中所有 `FuncCall` 节点）：`set_config`、`pg_read_file`、`pg_read_binary_file`、`pg_ls_dir`、`pg_stat_file`、`lo_import`、`lo_export`、`lo_*`、`dblink*`、`pg_terminate_backend`、`pg_cancel_backend`、`pg_reload_conf`、`pg_rotate_logfile`、`pg_advisory_*`、`pg_try_advisory_*`、`pg_notify`、`pg_sleep*`（迁移模式除外）、`current_setting` 带 `missing_ok` 以外的写形式（无）、`txid_current`（允许）。拒绝时返回 `kernel.sql_rejected`，`details.reason` 给出原因。

解析结果按语句文本哈希缓存（LRU 10,000 条），避免重复解析。

### 6.4 只读视图授权

- 提供方在迁移中创建视图（名字须以 `v_` 开头，列入清单 `[database].views`），视图**不得**设置 `security_invoker`，因而以提供方角色的权限读取底表；应设 `WITH (security_barrier = true)`。
- 视图敏感级别来自 [../catalog/services.md](../catalog/services.md) §3。
- 启动时（§2.4 末尾）计算期望授权集合：对每个消费方 `capabilities.views` 中的 `<schema>.<view>`：视图存在于提供方清单 → 敏感视图须有站点授权 → `GRANT USAGE ON SCHEMA <schema> TO <consumer_role>; GRANT SELECT ON <schema>.<view> TO <consumer_role>;`。
- 与 `kernel.view_grant` 记录的现有授权比较，撤销多余的授权（插件被移除或能力被收回）。
- 消费方读视图仍然受 `SET LOCAL ROLE`，因此无法读到未授权视图与底表。

### 6.5 Redis 网关

**实例与连接**：`site.toml [redis.<role>] url = …`，每个角色一个 `redis::aio::ConnectionManager`（多路复用）；Cluster 模式用 `ClusterConnection`。

**键改写**：内核维护命令表（命令 → 键参数位置规则，参照 Redis `COMMAND INFO` 的 key specs，硬编码于 `kernel::storage::redis::commands`）。对插件命令：

1. 命令名大写化，查白名单（下表），不在表中 → `kernel.redis_command_denied`。
2. 按键规则把每个键参数改写为 `p:<plugin_id>:<原键>`；原键不得为空，长度 ≤ 512 字节。
3. `SCAN cursor [MATCH pat] [COUNT n] [TYPE t]`：强制 `MATCH p:<id>:<pat 或 *>`；返回的键去掉前缀。`HSCAN`/`SSCAN`/`ZSCAN` 只改写键参数。
4. 限制：参数个数 ≤ 1024，单个参数 ≤ 1 MiB，`pipeline` ≤ 1000 条；超出 → `kernel.bad_request`。
5. 配额超限期间（§6.6），写命令返回 `kernel.quota_exceeded`，删除类命令仍允许。

| 类别 | 白名单命令 |
|---|---|
| 通用 | `DEL`、`UNLINK`、`EXISTS`、`EXPIRE`、`PEXPIRE`、`EXPIREAT`、`PEXPIREAT`、`EXPIRETIME`、`TTL`、`PTTL`、`PERSIST`、`TYPE`、`RENAME`、`RENAMENX`、`COPY`（不带 DB 参数）、`SCAN`、`TOUCH` |
| 字符串 | `GET`、`SET`（含 NX/XX/EX/PX/KEEPTTL/GET）、`SETNX`、`SETEX`、`PSETEX`、`GETSET`、`GETDEL`、`GETEX`、`MGET`、`MSET`、`MSETNX`、`INCR`、`INCRBY`、`INCRBYFLOAT`、`DECR`、`DECRBY`、`APPEND`、`STRLEN`、`GETRANGE`、`SETRANGE` |
| 位图 / HLL | `SETBIT`、`GETBIT`、`BITCOUNT`、`BITPOS`、`BITFIELD`、`BITFIELD_RO`、`BITOP`、`PFADD`、`PFCOUNT`、`PFMERGE` |
| 哈希 | `HGET`、`HSET`、`HSETNX`、`HMGET`、`HMSET`、`HDEL`、`HEXISTS`、`HGETALL`、`HKEYS`、`HVALS`、`HLEN`、`HINCRBY`、`HINCRBYFLOAT`、`HSCAN`、`HSTRLEN`、`HRANDFIELD`、`HEXPIRE`、`HPEXPIRE`、`HTTL`、`HPERSIST` |
| 列表 | `LPUSH`、`RPUSH`、`LPUSHX`、`RPUSHX`、`LPOP`、`RPOP`、`LLEN`、`LRANGE`、`LINDEX`、`LSET`、`LREM`、`LTRIM`、`LINSERT`、`LPOS`、`LMOVE` |

| 有序集合 | `ZADD`、`ZREM`、`ZSCORE`、`ZMSCORE`、`ZINCRBY`、`ZCARD`、`ZCOUNT`、`ZRANGE`（全部形式）、`ZRANGESTORE`、`ZRANK`、`ZREVRANK`、`ZREVRANGE`、`ZRANGEBYSCORE`、`ZREVRANGEBYSCORE`、`ZREMRANGEBYSCORE`、`ZREMRANGEBYRANK`、`ZPOPMIN`、`ZPOPMAX`、`ZUNIONSTORE`、`ZINTERSTORE`、`ZSCAN` |

### 6.6 配额

| 资源 | 计量 | 超限行为 |
|---|---|---|
| Redis | `kernel.redis_quota_scan` 每 10 分钟：`SCAN MATCH p:<id>:* COUNT 1000` 计数键；对 1% 抽样键执行 `MEMORY USAGE` 估算字节数；结果写 `k:quota:<id>` | 超过 `[redis].quota_mb` 或 `max_keys`：写命令拒绝，直到下次扫描低于 90% |
| KV | `_kv` 表行数与 `pg_total_relation_size` | 超过 `kv.quota_mb`（默认 64）：`set` 拒绝 |
| Blob | `kernel.blob_usage` 在 put/delete 时增减 | 超过 `blob.quota_mb`（默认 1024）：`put` 拒绝 |
| SQL | 不限总量；`statement_timeout`、`max_rows`；schema 大小纳入监控指标 | 告警 |
| WASM | 并发、内存、超时（§4） | 调用失败 |

### 6.7 对象存储

- S3 兼容（`aws-sdk-s3` 或 `object_store`）；配置 `[object_storage] endpoint, bucket, region, access_key, secret_key`。
- 插件键改写为 `plugins/<id>/<key>`；`key` 须匹配 `^[A-Za-z0-9!_.*'()/-]{1,512}$`，不得含 `..`、不得以 `/` 开头。
- `presign_get` TTL ≤ 3600 s；内容类型由插件给出，内核对 `text/html`、`image/svg+xml`、`application/javascript` 强制 `Content-Disposition: attachment`（防 XSS）。
- 内核自用前缀：`kernel/`。torrent 插件文件、图片等都在各自插件前缀下。

## 7. 事件日志

### 7.1 存储

- `kernel.event_log`：只追加，按 `occurred_at` **日分区**（评审 B-08），默认保留期 `events.log_retention_days`（默认 730，0 = 永久）。
- 按事件类型覆盖（`site.toml [events.retention]`）：`"traffic.*" = 30`、`"ledger.entry_posted" = 90`（流水由 ledger 永久保存）为内置默认；分区维护任务对超过最短保留期的分区按类型 `DELETE`，全部类型都过期后 `DROP` 分区。
- Redis Streams 长度：`[events.stream_maxlen]` 按事件类型配置（默认 `~1,000,000`，`traffic.settled` 为 `~5,000,000`）。
- `kernel.event_outbox`：待投递，投递成功即删除。
- DDL 见 §16.1。

### 7.2 发布

```
events.publish(evt) 宿主实现：
    require evt.event_type ∈ manifest.publishes                    ?: kernel.capability_denied
    require evt.version ∈ catalog 中该事件已登记的版本（发布方 schemas/events/<type>.v<n>.json 存在） ?: kernel.validation_failed
    validate(schema[type][version], evt.payload)                    ?: kernel.validation_failed
    require len(payload) ≤ 64 KiB                                    ?: kernel.payload_too_large
    require evt.key 匹配 ^[a-z_]+:[A-Za-z0-9_.:-]{1,128}$ 或 "global"
    id = uuid_v7(); envelope = {id, type, version, occurred_at=now, actor=inv.actor, source=plugin_id, key, payload, trace=当前 span}
    工作单元.pending_events.push(envelope)                          // 提交时写库（§6.2）
    return id
```

Native 插件的 `ctx.events.publish` 行为完全相同。

### 7.3 中继（outbox → Redis Streams）

- 只有持有租约 `k:lock:outbox-relay`（30 s，每 10 s 续约）的一个副本运行中继。
- 唤醒：`LISTEN pt_outbox` + 兜底轮询 200 ms。
- 每轮：

```sql
BEGIN;
DELETE FROM kernel.event_outbox
 WHERE seq IN (SELECT seq FROM kernel.event_outbox ORDER BY seq LIMIT 500 FOR UPDATE SKIP LOCKED)
RETURNING seq, event_id, event_type, partition, envelope;
-- 按 seq 顺序 pipeline：XADD ev:<event_type>:<partition> MAXLEN ~ <maxlen> * env <envelope JSON>
-- Redis 全部成功 → COMMIT；任一失败 → ROLLBACK 并退避重试
COMMIT;
```

- `partition` 在写 outbox 时计算：`xxh3_64(key) % partitions(type)`。
- 顺序保证：同一事务内的事件按发布顺序；跨事务按提交的因果顺序（后开始的事务看到先提交事务的事件，因而 seq 更大且一定后投递）。
- 至少一次：XADD 成功但 COMMIT 失败时会重复投递，由消费端 inbox 去重。
- 积压指标 `pt_kernel_outbox_backlog`；中继延迟 `pt_kernel_event_relay_lag_seconds`。

### 7.4 消费

**消费组**：每个订阅一个消费组，组名 `<plugin_id>.<subscription>`，启动时对其每个分区执行 `XGROUP CREATE ev:<type>:<p> <group> $ MKSTREAM`（已存在则忽略）。订阅可声明 `start = "earliest"`（从流中现存最早条目开始），否则从创建时刻开始；需要更早的历史用回放（§7.7）。

**分区分配**：每个（订阅, 分区）是一个工作项，副本通过租约 `k:lock:evc:<group>:<type>:<p>`（30 s）认领；每个副本最多认领 `ceil(工作项数 / 存活副本数) + 1` 个，未被认领的工作项每 5 s 重试认领，从而在副本增减时自动再平衡。

**处理循环**（持有租约期间）：

```
loop:
    msgs = XREADGROUP GROUP <group> <node_id> COUNT 64 BLOCK 1000 STREAMS ev:<type>:<p> >
    （首次接管时先处理本消费者名下及过期的 pending：XAUTOCLAIM min-idle=60s）
    for m in msgs（ordered=true 时串行；否则最多 subscription.concurrency 个并发，默认 8）:
        env = parse(m.env)
        if env.version ∉ subscription.versions: XACK; metric(skipped_version); continue
        attempt = 1 + XPENDING 中的投递次数 - 1
        loop:
            r = invoke(plugin, kind=event, on-event.handle(env, {subscription, attempt, replay=false}))
                // 工作单元首条语句写 _inbox（§6.2），已处理则直接成功
            if ok: XACK; break
            if attempt >= max_attempts: 写死信（§7.8）; XACK; break
            sleep(backoff(attempt))   // 1s, 2s, 4s … 上限 300s，加 ±20% 抖动
            attempt += 1
```

- `ordered = true` 时失败的消息会阻塞该分区直到成功或进入死信——这是有意的，保证同 key 顺序。
- Native 插件可声明 `batch = N`：一次把最多 N 条交给 `on_event` 批处理接口（`OnEventBatch` trait），整批一个工作单元。
- 流修剪：`MAXLEN ~` 默认 1,000,000 条/分区。消费者落后于修剪点（`XINFO GROUPS` 的 lag 无法计算或 entries-read 落后）时告警 `pt_kernel_event_consumer_gap`，需要用回放补齐。

### 7.5 幂等约定（inbox）

- 内核为每个插件 schema 创建 `_inbox(subscription, event_id, processed_at)`；事件处理的工作单元**第一条语句**插入 inbox，冲突即说明已处理过，内核直接 XACK。
- 因此：**插件的数据库副作用对同一事件恰好一次**；插件**之外**的副作用（Redis 写入、出站 HTTP、调用其他服务）仍可能重复，插件必须自行幂等：
  - 调用其他服务时传入由事件 ID 派生的幂等键，如 `ledger.transfer(idempotency_key = "<event_id>:<user_id>")`；
  - Redis 计数用“写入集合标记 + 计数”或在 PG 中计算后覆盖写；
  - 出站 HTTP 带 `Idempotency-Key: <event_id>`（webhook 插件）。
- inbox 保留 `events.inbox_retention_days`（默认 14 天），由 `kernel.inbox_cleanup` 清理。

### 7.6 分区数调整

1. 维护模式：停止全部副本（或设置 `events.paused = true` 后滚动重启使消费暂停）。
2. 等待 outbox 清空、所有消费组 pending 为 0。
3. 修改 `site.toml [events.partitions]`，启动；内核检测到分区数变化，为新分区建组。旧分区流保留 7 天后由清理任务删除。

### 7.7 回放

- 创建：`POST /api/kernel/v1/events/replays` 或 `pt-server events replay --subscription <plugin>.<sub> --type <t> --from <ts> --to <ts> [--force] [--rate 2000]`，写 `kernel.event_replay`。
- 执行：持有 `k:lock:replay:<id>` 的副本按 `(occurred_at, seq)` 顺序从 `event_log` 读取，XADD 到 `evr:<replay_id>`（单分区），专用消费者只投递给目标订阅，`delivery.replay = true`。
- `--force`：跳过 inbox 去重检查（但仍写 inbox），用于“重建”类订阅（如搜索索引重建）。不带 `--force` 时已处理过的事件被跳过。
- 回放与实时消费并行；订阅方必须能处理“回放事件晚于实时事件到达”的乱序（以载荷中的版本号/时间戳或重新读取当前状态为准）。

### 7.8 死信

- 写入 `kernel.event_dead_letter`（含信封、最后错误、尝试次数）并 XADD `evdlq:<plugin_id>:<subscription>`。
- 后台可查看、重投（单条或按过滤条件批量，走回放通道）、标记忽略。
- 指标 `pt_kernel_event_dead_letters_total{subscription}`，> 0 即告警。

## 8. HTTP 网关

### 8.1 路由注册

- 插件路由前缀：`/api/p/<plugin_id>`；清单 `path` 必须以 `/v<N>/` 开头；路径参数语法 `{name}`，末尾通配 `{*rest}`。
- WASM 插件：内核为每条路由生成 axum handler，转换为 `http-handler.request` 后调用插件导出。
- Native 插件：`HttpRoutes::router()` 返回的 Router 挂在前缀下；内核用清单中的路由表**包一层**中间件，未在清单中声明的路径返回 404（防止绕过权限声明）。
- 启动时检查：同一插件内方法+路径重复、与 OpenAPI 片段不一致 → `E-HTTP-ROUTE`。

### 8.2 中间件顺序

```
1. request_id（X-Request-Id，无则生成 UUIDv7）+ trace（traceparent）
2. 请求体限制（route.max_body_kb，默认 http.max_body_kb）与超时
3. 鉴权：
     Cookie "__Host-pt_session" → Credential::Session
     Authorization: Bearer <token> → Credential::Token（token 前缀 pts_ = 个人 API token，ptm_ = MCP token）
     都没有 → Principal::anonymous()
     有凭据 → principal_cache(sha256(cred), ttl=5s) 或 ctx.auth.authenticate(cred)
              无效 → 401 kernel.unauthenticated（仅当路由 auth ≠ public；public 路由按匿名继续）
4. auth 级别：public（任何人）/ user（需登录）/ admin（需登录且 permission 必填）
5. CSRF：Credential::Session 且方法 ∉ {GET, HEAD, OPTIONS} 时，要求 Header X-CSRF-Token == Cookie __Host-pt_csrf，
         且 Sec-Fetch-Site ∈ {same-origin, none} 或 Origin == site.base_url 的源；否则 403 kernel.csrf_failed
6. 权限：ctx.rbac.check_principal(principal, route.permission?)（评审 B-06；无 permission 的路由也调用，用于执行 token 作用域与只读 token 的方法限制；结果随 principal 缓存 5 s）；
   route.reauth_secs 存在 → 检查 principal.reauth_at，过期 → 403 identity.reauth_required
7. 限流（§8.3）
8. 幂等（§8.4，仅 route.idempotent 且方法为 POST/PATCH）
9. 构造 InvocationInfo{actor, locale(Accept-Language→用户偏好→site.default_locale), deadline=now+route.timeout}
10. 调用插件；错误映射为 problem+json（conventions/api.md §7）
11. 审计（非 GET/HEAD，§12.2）；访问日志与指标
```

凭据撤销：principal 缓存只有 5 s，内核接受最多 5 s 的撤销延迟。封禁、登出、token 撤销都由 identity 在 `authenticate` 内部判定，缓存过期后即生效，内核不需要额外的撤销通知。

### 8.3 限流

- 规则语法（清单 `rate_limit`、site.toml 覆盖）：`<subject>:<count>/<period>[,<subject>:<count>/<period>…]`，`subject ∈ ip|user|token|global`，`period ∈ s|m|h`，例 `"ip:30/m,user:120/m"`；`user` 对匿名请求退化为 `ip`。
- 算法：GCRA，Redis 键 `k:rl:<route_id>:<subject>`，内核自带 Lua 脚本（插件不可用 EVAL，内核可以）。
- 全站默认：`[http.rate_limit] default = "ip:600/m"`，对所有路由叠加。
- 响应头：`RateLimit-Policy`、`RateLimit`（IETF draft-ietf-httpapi-ratelimit-headers 的结构化字段格式），超限时 `429` + `Retry-After`。
- IP 来源：`http.trusted_proxies`（CIDR 列表）内的代理才信任 `X-Forwarded-For`。

### 8.4 幂等键

- 请求头 `Idempotency-Key`：1～64 个可见 ASCII 字符（建议 UUID）。
- 键 `k:idem:<principal_id>:<key>`（匿名不支持），HASH：`fp`（sha256(method + path + body)）、`state`（processing/done）、`status`、`headers`、`body`（≤ 64 KiB，超过只存 status）。TTL 24 h。
- 流程：`HSETNX state processing`（同时设 fp）→ 成功则执行并写入结果；已存在且 fp 不同 → 422 `kernel.idempotency_key_reused`；`processing` → 409 `kernel.idempotency_in_progress`；`done` → 原样返回缓存结果并加 `Idempotent-Replayed: true`。

### 8.5 OpenAPI 聚合

- 内核自身路由用 utoipa 生成；Native 插件用 utoipa 生成片段（构建时输出 `openapi.json`）；WASM 插件随包提供 `openapi.json`。片段中 `paths` 为插件内相对路径（`/v1/summary`）。
- 合并规则：路径加前缀 `/api/p/<id>`；`operationId` 加前缀 `<schema>_`；`components.schemas` 中的名字加前缀 `<PluginPascal>`（如 `Bonus`）并改写全部 `$ref`；`tags = [<plugin_id>]`；安全方案统一为 `cookieAuth`、`bearerAuth`；错误响应统一引用内核的 `Problem` schema。
- 输出 `GET /api/kernel/v1/openapi.json`（OpenAPI 3.1），带 ETag；构建流水线用它生成 `web/sdk`（openapi-typescript）。
- 清单路由与片段不一致 → 启动错误。路由 `validate_request = true` 时，网关按片段中的 requestBody schema 校验请求体（422 `kernel.validation_failed`）。

### 8.6 前端清单与静态文件

返回 `index.html` 时，内核为每个响应生成 CSP nonce，注入 `<script type="importmap" nonce>` 与入口脚本，并在 `Content-Security-Policy` 头中使用同一 nonce（`index.html` 本身 `Cache-Control: no-store`）。

```json
{
  "version": "<所有插件前端条目的哈希>",
  "import_map": { "imports": { "react": "/static/vendor/react-19.x.js", "@pt-studio/slots": "/static/vendor/slots-0.1.js" } },
  "plugins": [
    { "id": "bonus", "version": "1.2.0", "entry": "/static/plugins/bonus/3f9a…/index.js",
      "slots": ["user.profile.stats", "nav.user_menu"], "routes": ["/p/bonus/*"], "settings_ui": "schema" }
  ]
}
```

- 插件 `ui/` 目录以内容哈希路径提供：`/static/plugins/<id>/<sha256前12位>/…`，`Cache-Control: public, max-age=31536000, immutable`。
- 按登录态裁剪：只返回当前用户有权访问的插件路由（后台路由仅管理员可见）。

### 8.7 保留的根路径

一般插件路由只能在 `/api/p/<id>/` 下。以下根路径保留给 mcp 插件（清单 `[[http.root_routes]]`，只有 `id = "mcp"` 的官方插件可声明）：`/mcp`、`/.well-known/oauth-protected-resource`、`/.well-known/oauth-authorization-server`、`/.well-known/openid-configuration`、`/oauth/*`。其他插件声明 → `E-HTTP-ROUTE`。

## 9. 调度器

### 9.1 cron

- 表达式：5 段（分 时 日 月 周），按 `site.timezone` 解释（`croner` crate）；不支持秒级。
- 每个副本独立计算每个任务的下次触发时间 `fire_ts`；到点时：

```
if SET k:cron:<plugin>:<job>:<fire_ts> <node_id> NX EX 86400 失败: return          // 其他副本已触发
if 获取 k:lock:cron:<plugin>:<job> 失败（上一次仍在运行）: 记录 skipped; return     // 禁止重叠
run_id = uuid_v7(); 写 kernel.cron_run(running)
invoke on-cron.run({name, kind: cron, scheduled_at: fire_ts, payload: "{}", run_id})，超时 timeout_secs，期间续约锁
更新 kernel.cron_run(ok/failed/timeout, duration, error)；释放锁
```

- `catch_up = "once"`：启动时若最近一次成功运行早于“上一次应触发时间”，立即补跑一次（同样经过 NX 去重）。
- 手动运行：`POST /api/kernel/v1/jobs/{plugin}/{name}/run`（`kind = manual`）。
- 默认 `tx = "manual"`：长任务应分批 `sql.commit()`，避免长事务锁表（design/08 教训）。

### 9.2 延迟任务

- `ctx.jobs.schedule_once(name, run_at, payload, dedupe_key)`：在当前工作单元中 `INSERT kernel.delayed_job`（与业务同事务）；`dedupe_key` 非空时对 `(plugin_id, name, dedupe_key)` 中未完成的记录做唯一约束，冲突则返回已有 job_id。
- 调度：持有 `k:lock:delayed-jobs` 的副本每 1 s：`SELECT … WHERE state='pending' AND run_at <= now() ORDER BY run_at LIMIT 100 FOR UPDATE SKIP LOCKED` → 置 `running` → 分发到 `on-cron.run(kind = delayed)`；失败最多重试 3 次（退避 30 s、2 min、10 min），之后 `failed`。
- 运行时间精度：秒级。

### 9.3 分布式锁

```
acquire(name, lease):
    token = INCR k:fence:<name>
    ok = SET k:lock:<name> "<node_id>:<token>" NX PX lease
    return ok ? Lock{name, token} : None
renew: Lua：GET == 自己的值 → PEXPIRE lease
release: Lua：GET == 自己的值 → DEL
```

- 续约间隔 lease/3；续约失败视为**锁丢失**：立即取消当前任务（取消令牌），指标 `pt_kernel_lock_lost_total`。
- fencing token 通过 `run_id`/日志暴露；对数据库有强一致要求的任务可把 token 写入自己的表做单调检查。
- 单 Redis 主节点上的锁在主从切换时可能失效；cron 任务因此仍须对 `scheduled_at` 幂等（插件约定）。

### 9.4 分区 worker（仅 Native）

清单 `[[workers]]`（评审 B-09）：内核读取 `partitions_from` 指向的 Redis 键（如 `acct:_meta` 的 `partitions` 字段）得到分区数 N，以租约 `k:lock:worker:<plugin>:<name>:<p>`（30 s，续约 10 s）把分区分配给各副本（每个副本最多持有 ⌈N / 活跃副本数⌉ 个，每 30 s 再平衡）；对每个持有的分区调用插件实现的 trait：

```rust
#[async_trait]
pub trait PartitionWorker: Send + Sync {
    async fn run(&self, ctx: Ctx, partition: u32, cancel: CancellationToken) -> Result<(), PluginError>;
}
```

`run` 返回或租约丢失时取消；异常退出后 5 s 重启。worker 的 exactly-once 语义由插件自己保证（accounting 把流 ID 与聚合结果在同一事务中提交）。

## 10. MCP 工具注册入口

```rust
pub struct McpToolDef {
    pub name: String, pub plugin: PluginId, pub description: String,
    pub input_schema: Json, pub output_schema: Json,
    pub permission: Option<String>, pub write: bool, pub confirm: bool,
    pub audience: Audience,          // User | Admin
}

#[async_trait]
pub trait McpRegistry {
    fn tools(&self) -> Vec<McpToolDef>;
    /// confirmed：mcp 插件已完成用户确认（write && confirm 的工具必须为 true）
    async fn call(&self, tool: &str, args: Json, principal: &Principal, confirmed: bool) -> PResult<Json>;
}
```

`call` 的步骤：

1. 查工具；`audience = admin` 时要求 `mcp.admin_tools.use`；`permission` 存在时 `ctx.rbac.check`。
2. 输入 schema 校验（422）。
3. `write && confirm && !confirmed` → 返回 `mcp.confirmation_required`（由 mcp 插件负责保存待确认项与确认流程）。
4. 以 `actor.kind = mcp`、`credential_id = token_id` 调用插件 `mcp-tool.call`，超时 10 s。
5. 输出 schema 校验（不合法 → `kernel.internal` 并告警）；**敏感字段过滤**：递归删除名为 `passkey`、`email`、`ip`、`ip_address`、`password`、`password_hash`、`totp_secret`、`webauthn*`、`token`、`secret` 的字段，并记录指标（出现即说明插件有缺陷）。
6. `write = true` 的调用写审计。

`mcp.before_tool_call` 钩子由 mcp 插件在调用 `call` 之前触发。MCP 协议、OAuth 授权、token 签发、确认流程、按 token 限流全部在 mcp 插件中实现。

**资源合并**：`presets/<preset>.toml` 先加载，`site.toml` 深度合并覆盖（表合并、数组替换）。
**环境变量**：任意字符串值中的 `${VAR}` / `${VAR:-默认}` 在解析后展开；未定义且无默认 → 启动错误。`kernel.mode = "prod"` 时，`database.url`、`*_key`、`*password*` 等键若含字面密钥（不含 `${`）则告警。

### 11.3 授权合并规则

插件的**有效能力** = 清单申请 ∩ 站点授权，其中：

| 能力 | 是否需要站点授权 |
|---|---|
| `kv`、`sql`、`redis`、`blob`、`http_outbound`、非敏感 `views`、`publishes`、订阅、钩子 | 否（清单声明即生效；站点可通过 `[grants.<id>]` 中的同名字段**收紧**） |
| `sensitive`、敏感视图、`redis_global` | **是**：必须在 `[grants.<id>]` 中列出 |
| `scopes` | 由服务目录标注：标为“需授权”的作用域（`ctx.ledger` 的 `currency:*`、`ctx.users` 的 `write:*`、`ctx.accounting` 的 `write:*`、`ctx.auth` 的 `tokens:issue`、`ctx.rbac` 的 `write:roles`）必须在 `[grants.<id>.scopes]` 中列出；其余清单声明即生效 |

**预设**（presets/*.toml）应为官方插件预填这些授权，管理员在 site.toml 中只需处理差异。

### 11.4 插件配置与设置

- 静态配置：`site.toml [plugin.<id>]`，按 `config.static_schema` 校验（填充 schema `default`），启动后不变，`config.get-static()` 读取。
- 运行时设置：存 `kernel.plugin_settings`，按 `config.settings_schema` 校验；后台 `PATCH`（JSON Merge Patch）→ 校验 → 乐观锁（`version`）写入 → `PUBLISH k:bus settings:<id>` 使各副本缓存失效 → 发布 `kernel.settings_changed`。`config.get-settings()` 读本地缓存（失效后从 PG 重载）。
- schema 中标注 `"x-pt-secret": true` 的字段：写入后在 API 中只返回 `"********"`；存储时用 `kernel.secret_key`（环境变量 `PT_SECRET_KEY`）以 AES-256-GCM 加密。

## 12. 能力校验与审计

### 12.1 运行时检查点

| 检查点 | 位置 | 失败 |
|---|---|---|
| 宿主接口可用性 | 链接时（拒绝桩）+ 宿主函数入口 | `kernel.capability_denied` |
| 服务调用 | 服务桥接 / `ctx.service()` | `kernel.capability_denied` |
| 事件发布类型 | `events.publish` | `kernel.capability_denied` |
| 钩子触发 | `hook-runner.run`（只能触发自己的钩子点） | `kernel.capability_denied` |
| 出站 HTTP 主机 | `http-client.send`：解析 URL，主机须匹配 `http_outbound`（精确或 `*.` 后缀），只允许 `https`（dev 模式允许 http），禁止 IP 字面量与内网地址（解析后检查 RFC 1918、回环、链路本地、元数据地址 169.254.169.254） | `kernel.capability_denied` |
| SQL | 角色 + GRANT（主），语句检查（辅） | PG 权限错误 → `kernel.capability_denied`；`kernel.sql_rejected` |
| Redis | 键改写 + 命令白名单 | `kernel.redis_command_denied` |
| 敏感数据 | 由提供方服务（identity、accounting、tracker-bridge）检查 `invocation.caller-plugin` 的有效敏感能力；内核通过 `ctx.plugins` 提供查询 `has_sensitive(plugin, cap)` | 提供方错误码 |

### 12.2 审计

- 自动审计：非 GET/HEAD 的 HTTP 请求（路由 ID、principal、状态码、路径参数、耗时，**不记请求体**）、`write` MCP 调用、后台设置修改、事件回放与死信操作、手动任务、CLI 管理命令。
- 插件补充：`audit.write({action, target, details})`，`action` 须以插件 ID 为前缀；`details` ≤ 8 KiB，不得含敏感数据（内核按字段名黑名单过滤）。
- 存储：`kernel.audit_log`（按月分区，保留 `audit.retention_months` 默认 24）。只追加：`pt_gateway` 对该表只有 INSERT/SELECT 权限（表属主为 `pt_admin`）。

## 13. 术语服务接入

- 启动：收集全部清单的 `[terms]`（键须以 `<plugin_id>.` 开头），在 terms 插件 `init` 之后调用 `ctx.terms.register(defs)`；terms 插件只写入默认值，不覆盖管理员的覆盖值。
- 宿主接口 `terms.get/get-many/render`：内核维护每语言的进程内快照（`HashMap<key, Term>`），首次使用时从 `ctx.terms` 拉取；内核内部订阅 `terms.updated`（不占用插件订阅名额）后重新拉取。
- `GET /api/kernel/v1/terms?locale=zh-CN`：返回快照，ETag = 快照版本，前端缓存。
- 未启用 terms 插件（不推荐）：内核以清单默认值提供只读术语，启动告警。
- 渲染：ICU MessageFormat（`icu` / `icu_messageformat` 系列 crate），模板中 `{term:<key>}` 先替换为术语名再按参数渲染。

## 15. 多副本部署

| 后台职责 | 分配方式 |
|---|---|
| HTTP 请求 | 负载均衡到任意副本 |
| outbox 中继 | 单租约 `k:lock:outbox-relay` |
| 事件消费 | 按（订阅, 分区）租约分摊 |
| cron | 每次触发 `SET NX` 去重 + 任务锁防重叠 |
| 延迟任务 | 单租约 `k:lock:delayed-jobs` |
| 回放 | 每个回放一个租约 |
| 迁移 | PG advisory lock |
| 分区维护、配额扫描 | 作为内核 cron 任务 |

- **缓存失效广播**（评审 B-07）：内核自身对 `terms.updated`、`plugin.settings_changed` 等缓存失效事件的订阅只有一个副本收到；该副本处理后 `PUBLISH k:bus {kind, version}`，所有副本订阅 `k:bus` 并刷新本地缓存。兜底：各副本每 2 秒比较 `ctx.terms.version()` 等版本号。
- **心跳**：每 10 s 写 `k:node:<node_id>`（TTL 30 s）：版本、`plugin_set_hash`（所有插件 id@version 排序后的 sha256）、启动时间。后台显示集群视图；不同 `plugin_set_hash` 共存时显示警告（滚动升级期间正常）。
- **滚动升级约束**：
  1. 迁移必须对上一版本代码兼容（expand → 发布 → contract 分两次发布）；
  2. 事件载荷不兼容变更须双发过渡（plugin-api §6）；
  3. 新增订阅在新副本上建组，旧副本不消费，无冲突；
  4. 删除路由/工具时，旧副本仍可能短暂提供。
- **优雅关闭**（SIGTERM）：`/readyz` 返回 503 → 等待 `http.drain_secs`（默认 10 s）让负载均衡摘除 → 停止接受新连接，等待在途请求（最长 30 s）→ 停止拉取新事件，等待当前消息处理完 → 释放所有租约 → 关闭连接池 → 退出。
- **Kubernetes 参考**：Deployment（无状态）+ HPA；`terminationGracePeriodSeconds: 60`；迁移以 Job 运行 `pt-server migrate` 后再滚动发布（此时 `migrate_on_start = false`）。
- **连接数估算**：副本数 × `pool_size`；超过 PG `max_connections` 的 70% 时应使用 pgbouncer（事务模式；prepared statement 需 pgbouncer ≥ 1.21 并开启 `max_prepared_statements`）。

```sql
);
CREATE INDEX ON <schema>._kv (expires_at) WHERE expires_at IS NOT NULL;
-- 两表属主为插件角色；以 "_" 开头的表名保留给内核，插件迁移不得创建
```

过期 KV 由读取时惰性判断 + `kernel.inbox_cleanup` 同一任务定期删除。

## 17. CLI

| 命令 | 说明 |
|---|---|
| `pt-server serve` | 启动（默认） |
| `pt-server check [--offline]` | 执行全部启动前检查，不启动服务 |
| `pt-server migrate` | 只执行迁移与授权同步 |
| `pt-server plugins list [--json]` | 列出插件、版本、服务、能力、登记项 |
| `pt-server events replay …` | 创建回放（§7.7） |
| `pt-server events dlq list|retry|ignore` | 死信操作 |
| `pt-server jobs run <plugin> <job>` | 手动触发任务 |
| `pt-server plugin purge <id> [--yes]` | 删除已移除插件的 schema、角色、Redis 前缀、对象存储前缀（插件仍在目录中时拒绝） |
| `pt-server dev` | 开发模式：`allow_unsigned`、pretty 日志、监视 `plugins/` 变化后**整体重启**（仍不支持热插拔） |
| `pt-server gen-openapi` | 输出聚合 OpenAPI，供前端 SDK 生成 |

## 18. 错误码表

内核错误码见 [../catalog/error-codes.md](../catalog/error-codes.md) §2。启动错误（只出现在 CLI 输出与日志，不出现在 API 中）：

| 错误 | 说明 |
|---|---|
| `E-LOAD-DUPLICATE` | 插件 ID 重复 |
| `E-LOAD-MANIFEST` | 清单解析或 schema 校验失败 |
| `E-LOAD-CATALOG` | 名字未在 catalog 中归属本插件 |
| `E-LOAD-SIGNATURE` | 签名或校验和失败 |
| `E-LOAD-API` / `E-LOAD-KERNEL` / `E-LOAD-REQUIRES` | 版本不兼容 |
| `E-LOAD-WORLD` | 组件导入/导出与清单不一致、服务类型不一致 |
| `E-LOAD-KIND` | kind 不符 |
| `E-DEP-SELECT` / `E-DEP-AMBIGUOUS` / `E-DEP-MISSING` / `E-DEP-CYCLE` | 依赖问题 |
| `E-CAP-SENSITIVE` / `E-CAP-SCOPE` / `E-CAP-GLOBAL` | 能力未授权 |
| `E-MIG-NAME` / `E-MIG-CHANGED` / `E-MIG-REJECTED` / `E-MIG-FAILED` | 迁移问题 |
| `E-HTTP-ROUTE` | 路由冲突或与 OpenAPI 不一致 |
| `E-CONFIG` | site.toml 或插件配置校验失败 |
| `E-INFRA` | 基础设施不可达 |
| `E-INIT` | 插件 init 失败 |
