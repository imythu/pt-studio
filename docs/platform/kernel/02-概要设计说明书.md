## 1. 设计目标与原则

1. **机制而非策略**：内核不含 PT 业务，鉴权、术语存储、MCP 协议都由插件实现，内核只调用。
2. **启动即定型**（D4）：所有登记发生在启动阶段，运行时注册表只读（`Arc` 共享，无锁）。这让多副本一致性、依赖检查和资源清理都变得简单。
3. **Native 与 WASM 契约一致**：插件作者面对同一份 WIT；Native 只是“编译进来的、可信的、更快的”插件。
4. **隔离靠底层机制**：SQL 隔离靠 PostgreSQL 角色与 GRANT，Redis 隔离靠键改写 + 白名单，WASM 隔离靠组件沙箱 + 资源限制；字符串解析只做纵深防御。
5. **状态外置**：WASM 实例每次调用新建，内核副本无状态，所有状态在 PostgreSQL / Redis。
6. **至少一次 + 幂等**：异步链路一律至少一次投递，内核提供 inbox 去重帮助插件实现幂等。

## 2. 总体结构

### 2.1 位置

```
              ┌──────────────── pt-server（单个进程，可多副本）────────────────┐
 HTTP/MCP ──► │ gateway(axum) ─► auth 中间件 ─► 路由表 ─► 插件 http-handler       │
              │       │                 │ ctx.auth / ctx.rbac (identity)        │
              │       ▼                                                          │
              │  ┌─────────────── kernel 核心 ───────────────┐                    │
              │  │ loader │ registry │ hooks │ events │ sched │ ◄── site.toml     │
              │  │ storage(pg/redis/blob) │ caps/audit │ obs │                    │
              │  └──────┬──────────────────────┬────────────┘                    │
              │   Native 插件(Arc<dyn …>)   wasm-host(wasmtime, InstancePre 池)   │
              └─────────┼──────────────────────┼─────────────────────────────────┘
                        ▼                      ▼
                PostgreSQL（kernel schema + 每插件 schema）   Redis（main/acct/…）   S3
```

## 3. 对外接口清单

### 3.1 提供的服务

见 [../catalog/services.md](../catalog/services.md) §1（provider = kernel）：`ctx.invocation`、`ctx.log`、`ctx.config`、`ctx.kv`、`ctx.sql`、`ctx.redis`、`ctx.events`、`ctx.http`、`ctx.blob`、`ctx.time`、`ctx.random`、`ctx.audit`、`ctx.jobs`、`ctx.metrics`、`ctx.hooks`、`ctx.metadata`（聚合）、`ctx.content_types`（聚合）、`ctx.plugins`、`ctx.mcp_registry`。

### 3.2 依赖的服务

| 服务 | 用途 | 缺失时 |
|---|---|---|
| `ctx.auth` | 网关鉴权 | 拒绝启动（除非 `kernel.allow_no_auth = true`，仅开发） |
| `ctx.rbac` | 网关权限检查、权限点登记 | 同上 |
| `ctx.terms` | 术语登记与查询 | 降级：返回清单默认值，启动告警 |

内核对这三个服务的依赖也进入依赖图：identity、terms 总是最先激活。

### 3.3 发布的事件

`kernel.settings_changed`、`kernel.node_started`（[../catalog/events.md](../catalog/events.md) §4.1）。

### 3.4 订阅的事件

内核内部订阅 `terms.updated`，用于刷新术语快照（不占用插件订阅名，消费组名 `kernel.terms_cache`）。其他缓存失效（设置变更）通过 `k:bus` 广播，不使用领域事件。

### 3.5 注册的钩子

无。内核提供管线，自身不注册处理者。

## 5. 关键流程

### 5.1 启动

```
读取 site.toml → JSON Schema 校验 → 连接 PG / Redis
→ 发现插件（Native 静态表 + plugins/ 目录）
→ 逐个：解析清单 → schema 校验 → catalog 名字校验 → 签名 → 版本
→ 选择服务实现 → 依赖图 → 拓扑排序（环检测）
→ 能力合并（清单 ∩ 站点授权）→ 敏感能力检查
→ [汇总错误；有错误则退出码 2]
→ 获取 PG advisory lock "pt-migrate"
   → 确保 schema / 角色 / GRANT / 视图授权 → 按拓扑顺序执行迁移 → 释放锁
→ 编译 / 加载 WASM 组件（预编译缓存）→ 链接宿主接口与服务桥接 → InstancePre
→ 登记：服务、钩子、路由、订阅、cron、MCP 工具、权限点（→ ctx.rbac）、术语（→ ctx.terms）
→ 按拓扑顺序调用 lifecycle.init
→ 启动后台工作者：outbox 中继、事件消费者、调度器、心跳
→ 打开 HTTP 监听，/readyz 返回 200，发布 kernel.node_started
```

### 5.2 一次 HTTP 请求

```
axum → 请求 ID / trace → 路由匹配（插件路由表）→ 请求体限制
→ 鉴权：cookie 会话或 Bearer → ctx.auth.authenticate → Principal
→ CSRF（cookie + 非安全方法）→ 权限：ctx.rbac.check(principal, route.permission)
→ 限流（k:rl:*）→ 幂等键（k:idem:*）
→ 构造 InvocationInfo（actor、locale、deadline）→ 调用插件 http-handler（工作单元：事务 + outbox）
→ 提交 → 审计（非 GET）→ 响应（错误统一为 problem+json）
```

### 5.3 事件

```
插件调用 events.publish → 缓存于工作单元 → 提交时 INSERT event_log + event_outbox（同一事务）
→ 中继（持有 k:lock:outbox-relay 的副本）DELETE … RETURNING 一批 → XADD ev:<type>:<p> → 提交
→ 消费者（每个 订阅×分区 一个租约）XREADGROUP → 调用插件 on-event（工作单元中先插 _inbox，冲突则跳过）
→ 成功 XACK；失败按退避重投；超过次数进入死信
```

## 6. 设计决策

| 编号 | 问题 | 备选 | 结论 | 理由 |
|---|---|---|---|---|
| DD-KRN-1 | WASM 实例模型 | A 每插件长驻实例；B 每次调用新实例 | B | 隔离与并发简单、无状态泄漏；pooling allocator 使实例化在微秒级 |
| DD-KRN-2 | 跨插件服务调用的实现 | A 全部 JSON 序列化；B 编译期绑定 + 动态 `Val` 桥接 | B | Native↔Native 零开销；涉及 WASM 时用 `component::Val` 动态转发，无需内核编译期知道第三方 WIT |
| DD-KRN-3 | 服务接口能否用 resource | 允许 / 禁止 | 禁止 | 跨组件 resource 句柄无法通用桥接；用 ID 代替 |
| DD-KRN-4 | 钩子与事件载荷编码 | A 每个钩子一个类型化 WIT 函数；B 通用函数 + JSON + JSON Schema | B | 钩子/事件由插件自行扩展，类型化 WIT 会导致 `pt:plugin` 频繁变更；SDK 从 schema 生成类型 |
| DD-KRN-5 | SQL 隔离 | A 每插件登录角色 + 独立连接池；B 共享池 + `SET LOCAL ROLE` | B（按 design/02），并加语句检查与 `set_config` 撤权 | 连接数可控；`RESET ROLE` 逃逸由语句检查阻断。A 作为备选（README Q1） |
| DD-KRN-6 | 事件存储 | A 只有 outbox；B outbox + 只追加 event_log | B | outbox 投递后即删，保持小表；event_log 按月分区，用于回放与 AI 分析 |
| DD-KRN-7 | 事件流组织 | A 单一大流；B 每事件类型一条流；C 每类型多分区 | C | 订阅方只读自己关心的类型；分区提供横向扩展且保持同 key 有序 |
| DD-KRN-8 | 消费端幂等 | 插件自理 / 内核 inbox | 内核 inbox（同事务）+ 插件对非数据库副作用自理 | 对数据库副作用做到恰好一次，大幅降低插件出错概率 |
| DD-KRN-9 | 主键 | 雪花 / UUIDv7 / 序列 | 业务实体 BIGINT identity；事件与幂等键 UUIDv7 | 见 conventions/database.md §3 |
| DD-KRN-10 | 插件路由版本 | 全局 `/api/v1/p/<id>` / 插件内 `/api/p/<id>/v1` | 插件内 | 各插件 API 独立演进 |
| DD-KRN-11 | 钩子中是否允许出站 HTTP | 允许 / 禁止 | 禁止 | 同步路径的延迟与可用性不受外部服务影响 |
| DD-KRN-12 | 导入了未授权接口 | 拒绝启动 / 链接拒绝桩 | 拒绝桩 | 部分语言工具链会导入全部接口；运行时调用时报错，启动日志提示 |
