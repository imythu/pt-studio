## 1. 引言

### 1.1 目的

定义 PT Studio 微内核（`crates/kernel`）必须提供的能力，作为内核实现和所有插件设计的共同依据。

### 1.2 范围

**包含**：插件加载器、服务注册表、Hook 管线、事件日志、存储网关（PostgreSQL / Redis / 对象存储）、HTTP 网关、MCP 工具注册入口、调度器、能力校验与审计、术语服务接入、配置、可观测性、多副本部署、WASM 运行时（wasmtime）。

**不包含**（全部由插件实现）：任何 PT 业务（用户、种子、记账、账本、搜索……）、身份认证的具体实现（`ctx.auth` 由 identity 提供，内核只调用）、MCP 协议网关（由 `mcp` 插件实现）、术语表存储（由 `terms` 插件实现）、前端。pt-tracker 是独立进程，不属于内核（D16）。

### 1.3 术语与缩写

| 术语 | 含义 |
|---|---|
| 内核 | `crates/kernel`，平台机制的集合，不含 PT 业务 |
| 插件 | Native 插件（编译进二进制的 Rust crate）或 WASM 插件（Component Model 组件） |
| 服务 | 插件之间以名字调用的接口，名为 `ctx.<name>` |
| 钩子（Hook） | 同步拦截点，处理者可放行、拒绝或修改 |
| 事件 | 只追加的领域事实，异步、至少一次投递 |
| 能力（capability） | 插件在清单中申请、由内核在启动时校验并在运行时强制的访问权限 |
| outbox | 与业务写入同一事务的事件暂存表 |
| 工作单元 | 一次插件调用对应的数据库事务边界 |
| passkey | **tracker passkey**（announce URL 中的 32 位十六进制密钥）。WebAuthn 凭据一律称“WebAuthn 凭据”，避免混淆 |

### 1.4 参考资料

- docs/design/01～10（总体设计与决策 D1～D17）
- DeepSeek Harness / Cordis：服务目录（`ctx.xxx`）、声明依赖后自动按依赖激活、副作用登记与自动清理、只追加事件日志。本项目只在启动时加载插件（D4），不需要运行时动态注册与卸载
- wasmtime Component Model、WIT 规范
- Spin / wasmCloud：每请求一实例（instance-per-request）的 WASM 宿主模型
- PostgreSQL 16 角色成员关系的 `INHERIT` / `SET` 选项

## 2. 总体描述

### 2.1 定位

内核是唯一的宿主进程（二进制 `pt-server`），可多副本部署。它不提供任何业务服务，只提供 [../catalog/services.md](../catalog/services.md) §1 列出的内核服务，并负责把插件连起来。

### 2.2 用户角色与使用场景

| 角色 | 场景 |
|---|---|
| 站点运维 | 准备 `site.toml` 与 `plugins/` 目录，启动/滚动升级多副本；查看插件、事件、任务状态；回放事件 |
| 插件开发者 | 按 plugin-api 契约开发 Native / WASM 插件，本地用 `pt-server dev` 运行 |
| 站点管理员 | 在后台查看插件（只读）、修改插件运行时设置、管理术语、查看审计 |
| 终端用户 / AI 客户端 | 通过 HTTP / MCP 间接使用内核网关 |

### 2.3 现有方案调研

| 方案 | 做法 | 采纳 / 改进 |
|---|---|---|
| Cordis / DeepSeek Harness | 运行时动态加载插件；`ctx` 服务注入；副作用随插件 dispose 自动清理 | 采纳服务目录与依赖排序；**不采纳**运行时加载（D4），副作用只需在启动时登记，停机时统一清理 |
| NexusPHP / UNIT3D | 插件机制弱，站点规则硬编码，fork 魔改后无法升级 | 规则全部插件化；契约版本化 |
| Spin / wasmCloud | 每请求新实例 + pooling allocator，状态外置 | 采纳：插件不在内存中跨调用保存状态 |
| Debezium / 事务 outbox 模式 | 业务写与事件写同事务 | 采纳：outbox + 中继到 Redis Streams |

### 2.4 约束与假设

- 数据库为 PostgreSQL ≥ 16（依赖角色成员关系的 `SET` 选项；推荐 17）；Redis ≥ 7.2（Streams、`XAUTOCLAIM`）。数据库已确定为 PostgreSQL（D18）。
- 插件只在启动时加载（D4）；所有副本的插件集合在稳态时一致。
- 热路径（announce）不经过内核（design/01 原则 2）。
- 内核与插件采用 `MIT OR Apache-2.0` 双许可证（D19），不得链接 pt-tracker 或任何 AGPL/GPL 代码（D16，见 [../conventions/licensing.md](../conventions/licensing.md)）。

## 6. 外部接口需求概述

- **插件接口**：WIT `pt:plugin@1.0.0` 与 Rust trait（[../plugin-api.md](../plugin-api.md)）。
- **HTTP**：`/api/kernel/v1/*`（内核自身）与 `/api/p/<id>/v<N>/*`（插件）。
- **运维 CLI**：`pt-server serve | check | migrate | plugins list | events replay | events dlq | jobs run | plugin purge`。
- **外部系统**：PostgreSQL、Redis、S3 兼容存储、OTLP 收集器、Prometheus。
